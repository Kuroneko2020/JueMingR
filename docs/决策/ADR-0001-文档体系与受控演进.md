# ADR-0001：文档体系与受控演进

- 状态：Accepted
- 日期：2026-08-28

## 背景

2026-08-28 对本地 Legacy 快照的代表性调查显示，旧体系存在以下主要问题：

- 正式规则和文档没有与代码共同进入 Git；
- 当前事实分散在多个计划、索引、状态和记录中；
- 更新记录、文档更改历史和归档计划持续膨胀；
- Agent 冷启动需要经过过长的文档链条；
- 文档审计和自然语言字符串审计反过来成为工程负担。

本 ADR 不复制上一轮的完整调查报告。由于 Legacy 正式文档未随代码进入 Git，普通克隆不能完整复现该本地调查范围。

## 决策

1. JueMingR 第一版文档体系按权威性和生命周期组织，具体规则见 [文档治理规则](../规范/文档治理规则.md)。
2. 当前只建立 `规范/` 和 `决策/`，每个目录都有真实职责和实际文档。
3. `设计/`、`计划/`、`验证/` 只在出现真实职责后，通过专门任务和项目所有者批准建立；不为未来用途预建目录。
4. 当前分类不是永久结构。新增、删除、合并或重命名一级目录必须由新的 ADR 记录并由项目所有者批准。
5. GitHub Issues 是动态任务状态的唯一权威载体；当前不建立 GitHub Project。复杂度确实需要时再单独评估。
6. 已批准的复杂任务未来可以建立活动实施计划，但计划只引用 Issue，不复制其动态状态；完成后先提炼长期结论，再删除失效计划。
7. 不继承 Legacy 的全局状态账本、更新记录目录、文档更改历史目录或全量计划归档。
8. 当前合同保存在规范和设计中；历史分别由 Git、已关闭 Issue、Release 和必要的 ADR 承担。
9. 脱敏后的精选实机验收摘要可以进入 Git；原始日志、ZIP、截图、录屏、完整机器信息和个人路径不进入正式文档。
10. 不使用源码字符串锚点或自然语言精确文本审计证明文档治理合规。

## 结果

优点：

- 当前规则、重要决定和代码可以共同追溯；
- 动态状态只有一个权威载体，减少人工同步和状态冲突；
- 默认 Agent 路由更短，历史材料不再自动污染当前事实；
- 目录可以在出现真实职责时演进，而不被首版结构永久锁定。

代价：

- 同一主题的规范、设计、决策和证据可能分处不同分类，需要通过入口和相对链接查找；
- 团队必须正确使用 GitHub Issues、Git、Release 和 ADR，不能只浏览 `docs/` 获得全部历史；
- 完成计划默认删除后，详细过程需要通过 Git 和关闭的 Issue 追溯；
- 一级结构调整需要专门任务和 ADR，会产生少量决策成本。

## 被替代方式

本 ADR 生效后，仓库 Bootstrap 阶段的英文候选分类不再作为当前目录依据，Legacy 的多套状态和历史文档机制也不作为 JueMingR 的治理模型。

若未来事实证明其他组织方式更合适，应创建新的 Accepted ADR，明确写出替代本 ADR 的范围、迁移方式和链接更新。本 ADR 的状态随后改为 `Superseded` 并链接到新 ADR；不得静默改写原决策或依靠重定向占位文件维持旧结构。
