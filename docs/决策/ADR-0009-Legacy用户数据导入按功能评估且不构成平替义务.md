# ADR-0009：Legacy 用户数据导入按功能评估且不构成平替义务

- 状态：Proposed
- 日期：2026-09-01
- 对应任务：[Phase 0-P Issue #18](https://github.com/Kuroneko2020/JueMingR/issues/18)
- 对应规则：[Legacy 平替与行为契约规则](../规范/Legacy平替与行为契约规则.md)
- 对应路线图：[稳定起步路线图](../计划/稳定起步路线图.md)

## 背景

JueMingR 是独立重写。对用户有意义的 Legacy 功能仍应按功能逐项平替；但功能平替、JueMingR 的内部实现与旧版用户数据导入是三个不同问题。完整平替衡量可用功能、可观察行为和安全边界，并以风险相称的证据验证，不自动承诺读取、转换或保留所有旧格式。

旧版路径和数据形状可以是恢复行为或评估导入的证据，却不能决定 JueMingR 的架构。新功能必须先恢复行为合同，再遵循获准的 JueMingR 架构和状态所有权，自行设计数据模型与存储；导入旧数据只在该功能设计或实现时评估。

PR #19 曾以 0/0/0 审查证明其被拒绝提案内部自洽，但项目所有者已拒绝该方向，且该 PR 已关闭、未合并。其被忽略的本地报告只保留为历史证据，不是产品合同。本次 `main` 尚无 ADR-0009，因此本记录使用下一个主线编号；不复制该报告的数据类别清单。

## 决策草案

1. JueMingR 继续按功能替代有意义的 JueMingZ 功能。完整平替只包括可用功能、可观察行为和安全边界，以及风险相称的验证；旧数据导入不是其默认组成部分。
2. 每项功能先恢复其行为合同，再按获准的 JueMingR 架构、状态所有权与自身需要设计新模型和存储，并在该功能设计或实现中评估旧数据导入。
3. 新数据形状可以在有理由时接近 Legacy，也可以在有理由时不同；相同或刻意不同都不是目标。Legacy 可以作为证据或导入输入，不能反向规定新架构。
4. 设置、快捷键、笔记、蓝图、足迹、死亡或游玩历史、地图标记、行为记忆及类似数据，不因 Legacy 存在而形成全局导入承诺。
5. 单项功能可以选择自动支持、用户触发的手动支持、部分或旧版本限定支持、延期、不支持，或当前尚无法证明是否支持。
6. 评估至少考虑用户价值、创造性或难以重建的程度、语义兼容性、身份和所有权能否可靠确定、重复/覆盖/丢失风险、实现与维护成本、旧 schema 对架构的压力，以及可获得的自动和游戏内验证。
7. 用户创建或难以重建的数据应获得更高的评估优先级，但不因此自动成为导入义务。
8. 导入不是单项功能、功能平替、总体架构或稳定起步的默认完成门。只有项目所有者在该功能合同中明确列入时，才成为该功能的完成要求。
9. 不建立首次启动的全局 Legacy 扫描、迁移中心、全局批次或 manifest、预制通用导入接口，或为全部数据预设默认选择。
10. 只有多个真实功能的导入已证明职责、生命周期和安全语义稳定且相同，才可在后续独立任务中提取共享导入能力。
11. 若功能选择导入，最低边界为：Legacy 原件保持只读；由用户明确触发，或在执行前取得用户明确确认；不得静默覆盖 JueMingR 数据；成功后不得自动删除旧数据；失败不得损害任一侧；身份或语义不清时不得猜测。
12. 格式、幂等性、增量、冲突、恢复、验证和 UI 均保留给对应功能的合同与任务；不得由本 ADR 预先统一规定。
13. 本决定只建立长期边界，不增加必需工具、角色或批准层。它可由 Git revert 或新的 Accepted ADR 替代。
14. 本任务不授权任何导入实现、schema、生产代码、项目骨架或下一阶段。

## 被拒绝的方案

### 在稳定起步前逐项决定全部数据类型

拒绝。脱离真实功能语义逐项决定设置、笔记、蓝图、足迹或其他数据，会把未知的用户价值、身份与冲突处理伪装成已完成的产品承诺。

### 建立全局迁移中心或预制共享框架

拒绝。尚无多个真实导入证明共同职责、生命周期和安全语义；预建会形成推测性系统与错误的全局所有权。

### 将导入视为强制平替

拒绝。功能可用、行为可观察且边界安全，不自动等于所有旧文件或格式必须可导入。

### 用旧 schema 约束或刻意反对新架构

拒绝。旧形状既不天然正确，也不天然有害；新模型应由新功能和架构决定。

### 现在承诺所有具名数据都导入，或永远禁止任何导入

拒绝。这两种全局结论都跳过了每项功能的真实价值、兼容性、风险与验证条件。

### 仅为验证本 ADR 制作原型

拒绝。本 ADR 是边界决定，不需要以导入器、schema 或测试项目来证明；原型会越出本次授权。

## 结果

### 优点

- 新架构保有自由，不被旧 schema 锁定；
- 功能平替与旧数据导入拥有独立、可如实记录的完成状态；
- 未来仍可针对有价值的数据作出每功能导入选择；
- 不会在真实需求出现前维护推测性的全局系统；
- 被选择的导入从一开始保留只读和防覆盖的最低安全边界。

### 代价

- 不保证每一份旧数据都能进入 JueMingR；
- 未来功能需要单独评估导入价值、兼容性与风险；
- 一些用户可能需要以新的数据开始；
- 多个实际导入收敛后，仍可能需要后续共享基础设施。

## 后续验证门

本 ADR 仍为 Proposed，在独立审查和机械最终化前不生效。未来功能 Issue 应记录导入决定及其合同范围；未选择导入也应保持为该功能的明确状态。总体架构不等待旧格式、具体 schema 或导入器先行确定。

本决定不要求为自身建立原型。若功能后来选择导入，应在该功能任务中验证适用的身份、语义、冲突、恢复和用户可见结果，而不是以本 ADR 的文字替代实现或游戏内证据。

## 接受与替代方式

项目所有者已在本任务接受本 ADR 的实质方向。独立审查通过后，可仅作不改变实质语义的机械最终化；只有合并进入 `main` 后，它才成为当前有效决定。

若未来需要全局迁移、强制旧格式兼容，或完全禁止任何旧数据导入，必须创建新的 Accepted ADR 明确替代范围。可以通过 Git revert 恢复本决定的提交，但不得静默改写其历史。
