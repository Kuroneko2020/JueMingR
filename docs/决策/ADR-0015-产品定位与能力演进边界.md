# ADR-0015：产品定位与能力演进边界

- 状态：Proposed
- 日期：2026-09-26
- 对应任务：[项目定位澄清与文档一致性修订 #103](https://github.com/Kuroneko2020/JueMingR/issues/103)
- 对应说明：[根 README](../../README.md)、[Legacy 规则的目的与适用范围](../规范/Legacy平替与行为契约规则.md#一目的与适用范围)
- 生效边界：所有者已明确确认定位方向；本 ADR 与关联文档修订仍是候选，待独立语义审查、所有者对完整候选的最终接受、获授权的机械最终化及复核，并合并进入 `main` 后正式生效。现有未修改规范继续有效。

## 背景

[ADR-0003](ADR-0003-原版同进程加载路线与兼容策略.md) 已确立原版 Terraria 客户端辅助工具、不依赖 tModLoader 的产品身份。根 README 以“独立完整重写”定义项目、以完整覆盖旧功能表述唯一最终目标，容易将工程关系和建设目标误读为全部产品定义及功能上限。[ADR-0002](ADR-0002-Legacy平替策略与行为契约方法.md) 和 Legacy 规则中的“先平替、后改进”“独立阶段”，也可能形成全部恢复完成之前禁止任何已批准改进或新能力的全局门槛。

所有者明确要求澄清这些层级：延续 Z 的使用初衷，吸收有价值功能、有效交互、游戏机制知识和失败教训，独立建立可持续维护发展的实现。完整恢复有意义旧能力仍是重要目标，同时围绕实际游玩需求持续演进。这不是新设平台、改变运行路线、宣布能力已实现或重新启动项目。

## 候选决定与有限替代

1. 产品定位由根 README 集中说明；根入口和文档导航短述并链接，Legacy 规则承载恢复、改进与新需求的适用边界，不另建一套定位总纲。
2. 保留有意义旧能力的完整覆盖目标，不授权删减为任意少量功能；旧清单不是产品上限，完整平替不是产品终点。
3. 所有者可以在恢复期间批准改进、新功能及批次调整，实际技术依赖、具体任务和必要验证仍适用。“旧版没有”既不是拒绝已批准需求的充分理由，也不是 Agent 自行追加功能的依据。
4. “先平替、后改进”保留为恢复任务不得擅改已确认正常体验的边界。原样恢复按单项合同执行；已批准差异有明确合同与验收依据，区分等价恢复、有意改进和回归。旧能力继续考古与差异验收；新需求按所有者目标形成合同，不伪造 Legacy 对应项。
5. 仅替代 ADR-0002 决策第 1 项、备选方案第 5 项及相应代价中把“独立阶段／平替基线之后”解释为全产品改进前置门的限制；其背景中的重写关系不再承担完整产品定义。保留禁止“顺手重新设计”的理由及其余四层模型、证据来源、验收轴、风险合同、数据自然归属、资源安全、多人权威和性能验证方法。旧 ADR 保留历史正文并链接本后继；本候选尚不将旧 ADR 标为已替代，最终化时仅标明上述部分的替代关系，不废止整套方法。

## 保持不变的边界

Legacy 永久只读，R 不在编译或运行时依赖 Z，不要求继承错误行为、耦合或技术债。ADR-0003 的加载路线、运行环境、依赖与多人目标，总体架构的职责和状态所有权，各项具体功能合同，以及正确性、安全、性能、测试、独立审查、安装和用户数据保护责任均不变。

稳定起步路线图只补适用范围说明，不改阶段顺序、退出条件、里程碑或开发组合。持续演进不授权任何具体功能、代码、安装、发布或后续任务。网页 Chat 只补理解提醒，不增加本地必读链、工具、角色、审批层或常驻台账。

## 理由、代价与后续维护

只改 README 会留下正常入口及 Legacy 规则中的全局阶段歧义；静默改写 Accepted ADR 会丢失历史决定。本次选择现行说明的定向修订与一份有限后继 ADR，代价是维护少量关联入口及准确的候选／生效状态。保留恢复目标、逐项合同与授权边界，避免把持续演进误作任意扩张，也避免把恢复路线当作产品上限。

最终接受、机械最终化、复核与合并继续遵守[工程治理的正式化闭环](../规范/工程治理规则.md#九长期规则与-adr-的正式化闭环)，独立审查不替代所有者接受。本 ADR 不自行授予合并、关闭任务、发布或版本推进权限；后续实质变化按既有文档与 ADR 演进规则处理。
