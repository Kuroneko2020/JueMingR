# ADR-0019：受控并行协作与模型分工

- 状态：Proposed，正式文本待独立审查，未合并。
- 日期：2026-10-10。
- 对应任务：[#114](https://github.com/Kuroneko2020/JueMingR/issues/114)，[Draft PR #115](https://github.com/Kuroneko2020/JueMingR/pull/115)。
- 授权事实：所有者本轮已明确裁决下列模型分工和并行语义，当前实施直接按该裁决执行，不重复索取同一授权；本文的未合并状态不表示该裁决需要等待才能使用，也不表示稳定主线已改变。

## 问题

ADR-0013 第 3 项的“单主工作区、单实施者”和持续实施／集中独审的文字，可能被扩大解释成一个任务只能使用一个实施子 Agent。这会串行化本可独立的调查、实现与验证。真正需要互斥的是冲突文件、Git 状态、共享产物与共享运行资源。

## 所有者已明确的协作语义

1. 主调度、综合核查与整合使用 GPT-6 Astra / Max；全部子 Agent，包括调查、实施、测试、文档和独立审查，使用 GPT-6.1 Sol / High。开始实质工作及创建／恢复子会话时核实际模型和档位；已核且未变化的不重复核验。无法设置或证实的，说明具体限制并只暂停受该条件约束的工作。
2. 保持一个主工作区、一个主调度及普通任务分支。主调度按实际依赖分工，允许多个子 Agent 同时读和修改互不冲突的文件；不设永久单子 Agent 限制，也不为数量而拆分。
3. 同一文件同时只有一个写入者，修改前复读，接口和共享文件明确交接。Git 索引、分支、提交、公共构建输出、正式证据汇总由主调度串行管理。固定产物的独立验证可以在隔离输出和会话状态下并行，共享运行资源另行互斥。
4. 独立审查者不参与被审内容的实现和期待起草。集中独审针对完整约定增量，可以分领域并行；主调度核完整覆盖及跨领域接缝，不将多个局部通过直接升级为整体通过。返修按真实新增影响窄复核。
5. 分工和当前依赖放原任务或阶段入口，复用现有工具，不新增长期角色数据库、模型监控平台或逐文件审批仪式。

## 有限替代与保留边界

本裁决有限替代 ADR-0013 第 3 项中禁止同任务多个受控实施者的解释，并澄清 ADR-0017 的持续实施／集中独审不限制有依据的并行分工。历史 ADR 保留原文；单工作区、Legacy 只读、保留资产、输入与数据安全、证据层级和实际独立性继续有效。

模型配置属于所有者的项目协作要求，不是 Terraria 产品、编译或 CI 依赖；不授权修改全局技能、插件、账户或其它项目。安装、合并、关闭任务和发布权限未增加。ADR-0018 分层冷启动候选的状态及其单独接受／合并边界不变。

## 落点与代价

正常入口为根 AGENTS.md 及工程规则的角色职责、单工作区和第十二章。共享文件冲突仍需串行交接，主调度承担整合成本；并行数量由独立性和现场资源决定，不承诺固定速度提升。后续调整仍由所有者明确决定，并保持可追溯的普通 Git 变更。
