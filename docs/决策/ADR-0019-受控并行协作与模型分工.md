## 问题

ADR-0013 第 3 项的“单主工作区、单实施者”和持续实施／集中独审的文字，可能被扩大解释成一个任务只能使用一个实施子 Agent。这会串行化本可独立的调查、实现与验证。真正需要互斥的是冲突文件、Git 状态、共享产物与共享运行资源。

## 所有者已明确的协作语义

本节保留 2026-10-10／2026-10-11 原决定的历史语义；下方[2026-10-25 补充](#2026-10-25-所有者当前补充裁决)记录后来改档原因，执行时直接读工程现行配置。

1. 按所有者 2026-10-11 追加决定，主会话使用 GPT-6 Astra / Max，仅负责需求与权限核对、只读审查、任务拆分调度、接口与冲突裁决、结果综合及交付判断；具体调查、实施、测试、文档、构建打包、Git/GitHub 写入和独立审查由全部使用 GPT-6.1 Sol / High 的受控子 Agent 完成。主会话不修改文件、不运行构建、测试、打包或 Git 写入，自身审查不替代独立审查。开始实质工作及创建／恢复子会话时核实际模型和档位；已核且未变化的不重复核验。无法设置或证实的，说明具体限制并只暂停受该条件约束的工作。
2. 保持一个主工作区、一个主调度及普通任务分支。主调度按实际依赖分工，允许多个子 Agent 同时读和修改互不冲突的文件；不设永久单子 Agent 限制，也不为数量而拆分。
3. 同一文件同时只有一个写入者，修改前复读，接口和共享文件明确交接。主调度指定一个子 Agent 串行操作 Git 索引、分支、提交和公共构建输出，并承担正式证据整合；主会话只读核查，不以整合为由接回具体写入。固定产物的独立验证可以在隔离输出和会话状态下并行，共享运行资源另行互斥。
4. 独立审查者不参与被审内容的实现和期待起草。集中独审针对完整约定增量，可以分领域并行；主调度核完整覆盖及跨领域接缝，不将多个局部通过直接升级为整体通过。返修按真实新增影响窄复核。
5. 分工和当前依赖放原任务或阶段入口，复用现有工具，不新增长期角色数据库、模型监控平台或逐文件审批仪式。

## 2026-10-14 所有者补充裁决

所有者当时指出，Astra 随 Sol 每一步重复分析不能实现采用两类模型协作以节省消耗的目的；复杂指令应在压缩后保留原件，网页承担能在线完成的审查和技术指导。下列为 2026-10-14 有限补充的原语义与当时边界；其合并及现行适用关系依文件头核实：

1. 主调度交付具有完整结果和验收边界的工作包，Sol 自主完成必要定位、实现、测试、自查及证据摘要，再集中审核关键差异与结果。真实阻塞和接口冲突可以中途处理；普通内部技术选择不逐步请示。审查问题成组返回，原作者返修、原独审上下文核修复及新增影响，独审不得参与被审实现、测试期待或交付结论的起草。工作包与审查次数依真实依赖决定，不固定某几轮或角色数量。
2. 复杂任务按复杂度和依赖交付多文件原件包及明确的启动委托；短任务不机械拆分。原始目标、执行状态与技术证据分开，压缩后回读相关原件；用户变更保留可追溯补充或新版本，原件清单／哈希只作轻量完整性帮助。指定任务原件的委托不使整个参考目录的历史指令获得执行权限，也不改变 ADR-0004 的现行冷启动顺序。
3. 网页 Chat 直接读取已有在线源码、差异、合同和记录，完成可在线进行的审查；能提供指导时写清真实调用链、状态归属、首选修法、复用／失效边界和关键反例。源码事实、推断、执行证据与未知分开，不能编造本机实测或私有原件结论；建议允许被实际证据推翻。网页不新增本地永久审批依赖。

实施落点为[工程主流程](../规范/工程治理规则.md#十二新会话交接与沟通)及[网页指令交付](../网页Chat协作约定.md#4-开发-prompt-的起草与交付前核对)。本补充不接受 ADR-0018，不自动接受或合并其他文档候选；同文件的候选重叠在获授权合并时按具体语义处理，不能以整文件覆盖消除。协作成本是否减少以实际避免的重复工作判断；无真实计量不承诺额度节省比例。

## 2026-10-25 所有者当前补充裁决

来源为所有者 2026-10-25 的直接执行委托，以及其明确指定的 `references/JMR_AIM_SEMANTICS_REPAIR_20261025_v1/00_冷启动与协作落地.md` 第 2 节和 `06_证据索引与旧条款替代.md` 的档位替代表；当时沿 [#136](https://github.com/Kuroneko2020/JueMingR/issues/136)／[PR #137](https://github.com/Kuroneko2020/JueMingR/pull/137) 落实。所有者要求实际修改规则，不能只在聊天或 Issue 宣布。以下保存该次已授权语义，原件只读、不入 Git 或产品，不使整个参考目录获得权限；现在的执行入口见文件头。

1. 主会话使用 **GPT-6 Astra / Max**，负责需求与权限核对、只读审查、拆分调度、接口与冲突裁决、结果综合及完整交付后的最终整体审核；子 Agent 使用 **GPT-6.1 Sol / Max**，在已授权范围内自主完成包含必要定位、实现、检查、自查、同任务文档和证据的完整工作包，承担具体实施、测试、文档、构建打包、Git/GitHub 写入和独立审查。主会话不接回产品编辑、测试构建、打包或 Git/GitHub 写入，不以整合为由逐工具、逐文件或逐步骤审批。真实阻塞和无法自行解决的接口冲突及时交主调度，其余工作持续推进。
2. 子 Agent 数量按真实依赖、冲突和风险动态决定，不固定数量。同一文件同时只有一个作者；指定一个子 Agent 串行操作 Git、公共构建输出和正式证据整合。共享 GPU、游戏会话和缓存按真实资源互斥，固定产物可在隔离输出中独立检查，不改变单主工作区及保留资产边界。
3. 作者完整交付后集中审核，必要独立子审在同一最终阶段按风险安排，由未参与对应实现或期待起草的上下文承担。主调度核整体覆盖、跨领域接缝和最终结论，不拼局部 PASS 冒充整体通过。确定问题成组返回原作者；增量返修只复核具体问题、必要传播和新增风险，复用仍有效的既有证据，不重启已完成的整套调查。
4. 模型与档位从实际会话元数据或等效现场事实核实，请求参数和自称不能作为确认；已核且未变不重复核验。无法设置或证实时只暂停受影响职责并说明缺口，不修改全局配置，不让无关工作停摆。
5. 该决定覆盖当时规则中的子 Agent **High** 档位及冲突的集中审核要求。2026-10-11／2026-10-14 原决定与历史执行、审查记录保留原义，不批量改为 Max。本文原 Proposed 未整体 Accepted；当时的未合并边界已由文件头所列真实合并接续，不再作为现行事实断言，也不自动接受其他候选。

该次决定的理由与历史保留在此，现行配置和协作要求直接读文件头链接的工程正文，根 AGENTS 只路由；任务恢复回原 Issue 和必要阶段索引，不另建规则中心或进度库。该补充不是 Terraria、构建或 CI 依赖，不增加合并、关闭、安装或发布权限。

## 有限替代与保留边界

本裁决有限替代 ADR-0013 第 3 项中禁止同任务多个受控实施者的解释，并澄清 ADR-0017 的持续实施／集中独审不限制有依据的并行分工。历史 ADR 保留原文；单工作区、Legacy 只读、保留资产、输入与数据安全、证据层级和实际独立性继续有效。

模型配置属于所有者在相应平台的协作决定，不是 Terraria、编译或 CI 依赖；不授权全局设置或其他项目修改。安装、合并、关闭和发布权限未增加。ADR-0018 的有限授权及实际合并事实由该记录单独说明，不因本 ADR 的原候选状态退回未生效。

## 落点与代价
