# ADR-0009：Legacy 数据迁移采用只读复制、幂等导入与显式冲突处理

- 状态：Proposed
- 日期：2026-08-31
- 对应任务：[Phase 0-P Issue #18](https://github.com/Kuroneko2020/JueMingR/issues/18)
- 对应规则：[Legacy 数据迁移规则](../规范/Legacy数据迁移规则.md)

## 背景

JueMingR 是对 JueMingZ 的独立重写，不在编译期或运行时引用 Legacy。Legacy 仍包含用户设置、快捷键、笔记、蓝图、玩家与世界身份线索、角色×世界历史、行为记忆，以及日志、诊断和维护产物。它们在用户意义、自然归属、schema、身份稳定性、隐私、事实价值和失败边界上并不相同，不能把整个目录当作一个统一数据源复制。

源码调查确认，Legacy 的持久化采用多套独立格式和版本。全局配置之间存在重复或派生来源；笔记由索引和正文组成；蓝图模板与玩家×世界实例分离且依赖 Terraria/内容环境；玩家、世界和 pair 身份混用路径 hash、GUID、world ID、cloud flag、map 文件名与显示名 fallback；死亡事件与摘要分别写入；游玩时间、探索和足迹具有各自聚合或裁剪语义；行为记忆采用另一套 key。多处实现具有单文件临时替换，却没有可由静态证据证明的跨文件原子提交或跨进程条件式提交。

这些事实只来自源码、测试源码和既有调查，没有读取项目所有者真实笔记、蓝图、角色、世界、日志、诊断包或导出文件，也没有运行 Terraria、测试或迁移。静态证据足以建立安全合同，但不能证明真实文件现状、实机、多人与云同步结果。

错误迁移可能把全局习惯绑到单一角色、串联不同角色或世界、重复累计历史、覆盖 JueMingR 新数据、把部分迁移写成成功、泄露私人内容，甚至修改或删除 Legacy 原件。因此该策略是高风险长期规则，需要独立语义审查和项目所有者对产品结果的最终接受。

本 ADR 记录选择理由。具体长期合同由[Legacy 数据迁移规则](../规范/Legacy数据迁移规则.md)承载；当前两者仍是 Proposed/草案，均未生效。

## 决策草案

若本 ADR 被项目所有者接受并随对应规则完成最终化、复核且合并到 `main`，采用以下决策：

1. Legacy 永久只读。迁移只复制必要来源到隔离候选并转换，不在 Legacy 原目录修改、标记、重命名、移动、整理或删除任何数据。
2. 导入完成、失败、来源指纹、批次和重试状态只保存在 JueMingR 自有数据中，不能写入 Legacy 或用旧文件时间戳充当标记。
3. 数据先按全局、角色、世界、角色×世界、服务器和会话等自然归属分类，再设计目标 schema；旧目录结构、文件名或 hash 不替代归属判断。
4. 全局习惯与实体事实分开。功能开关、快捷键和普通 UI 偏好默认全局；角色、世界和角色×世界事实只写入可证明的对应目标实体。
5. 用户创作和难以重建的长期内容优先获得保留/导入能力；笔记、蓝图和明确的用户历史不能与缓存、派生摘要或内部学习状态混为一谈。
6. 只有 JueMingR 对应功能、自然归属、批准的目标 schema、来源映射、冲突/恢复合同和获授权验证均已就绪时，才真正导入该类数据；否则报告 `deferred` 或 `not applicable`。
7. 写入前使用只读预检、面向可理解数据类别的明确用户确认，以及逐类 `imported`、`skipped`、`conflict`、`failed`、`deferred`、`not applicable` 结果。
8. 不采用静默自动迁移。当前推荐候选是在标准 Legacy 根首次被检测到时只显示预览，由用户确认后导入，并在设置中保留可重新进入的入口；产品入口仍等待项目所有者接受。
9. 不扫描整块磁盘、用户主目录或云盘寻找 Legacy exports。自动发现只检查明确标准根；其它根和外部导出只由用户主动选择。
10. 导入必须幂等、可安全重试并能识别增量。相同来源不得重复创建笔记/蓝图/标记、重复追加事件/足迹或重复累加游玩时间；文件时间变化不能触发无条件全量重导。
11. 默认不静默覆盖已有 JueMingR 数据。目标存在、目标变化或来源与目标共同变化时，必须重新核对身份、基线和结果。
12. 只有数据类别存在确定、可验证且不丢失任何一方用户结果的规则时才自动合并，并在结果中报告；纯名称相同、计数相近或 hash 可计算不是安全合并证明。
13. 身份歧义保持 `conflict`，不猜测。Legacy 路径、hash、GUID、world ID、cloud flag、显示名和 fallback 只作为组合来源证据，不自动成为 JueMingR 永久身份。
14. 多文件数据使用一致性单元。笔记索引与正文、蓝图模板与实例、原始事实与派生摘要、identity 与对应事实、批次记录与实际目标候选必须整体校验，半完成不得报告成功。
15. 来源和目标在预检后可能并发变化；提交前必须重新验证两侧条件，无法建立条件式提交或安全排他窗口时不得覆盖，候选保留并报告 `conflict`。
16. 失败不得损坏 Legacy，也不得把未提交或部分完成写成成功。已完整提交单元保持可识别，未完成单元可安全重试，对目标原有数据的变更必须先有经验证的恢复策略。
17. 日志、诊断包、运行/性能快照、缓存、临时文件、测试输出、构建输出和 TestPackage 默认不进入运行数据迁移，也不由迁移流程自动扫描、上传或删除。
18. Legacy 数据清理是与导入分离、显式、默认不执行的用户操作，需要独立合同、范围展示、单独确认和恢复说明；导入成功不构成删除授权。
19. 具体存储、类、接口、数据库/JSON、hash、manifest、锁、事务与迁移实现等待总体架构、目标 schema 和迁移器任务，不在本 ADR 提前固定。
20. 本 ADR 不授权实现或运行迁移器、读取项目所有者真实数据正文、执行真实迁移、建立目标 schema、创建项目骨架或生产代码，也不授权启动 Terraria、修改 Legacy、合并当前 PR 或进入下一阶段。

### 待项目所有者接受的产品结果

上述安全底线中，Legacy 只读、禁止静默迁移、禁止全盘扫描、禁止静默覆盖和目标功能/schema 前置门不应被实现细节弱化。独立审查通过后，项目所有者只需用普通语言接受、调整或拒绝以下推荐包：

- 入口：首次检测标准根时显示只读预览，明确确认后才导入；设置中可重开，也可手动选择其它根，不全盘扫描；
- 默认范围：安全映射的全局设置/开关/快捷键默认勾选；笔记和蓝图提供保留能力；实体事实只在身份与目标功能/schema 就绪时导入；旅行和行为记忆默认可选；日志、诊断、缓存、测试和构建产物排除；
- 冲突结果：完全相同跳过，可证明安全时合并并报告，其余保持现有 JueMingR 数据、隔离 Legacy 候选，并让用户另存、跳过或明确替换；Legacy 原件始终不变。

该决定不要求项目所有者选择字段映射、类、schema 类、hash、数据库、锁、事务、manifest 或 Git 操作。

## 被拒绝的方案

### 原地升级 Legacy 文件

拒绝。它会改变永久只读证据源，把跨产品导入与 Legacy 自身 schema 写回混为一谈，并让失败直接威胁用户唯一旧数据。

### 移动或删除旧目录

拒绝。复制成功、测试通过或用户暂时不再使用 Legacy 都不能证明数据可安全删除。清理必须是未来独立且默认不执行的用户操作。

### 首次启动无提示全量迁移

拒绝。它无法让用户理解范围和行为影响，不能处理目标已有数据、身份歧义、私人内容与尚未实现的目标功能，也会把“检测到”错误升级为写入授权。

### 只按文件名或目录 hash 识别实体

拒绝。Legacy 身份可能受路径、cloud/local、GUID、world ID、map 文件名、显示名和 fallback 影响；重命名、移动、复制、删除重建和碰撞都会使单一旧标识产生分裂或误合并。

### 所有文件统一使用一个 schema

拒绝。全局设置、笔记、蓝图、identity、事件、聚合与行为记忆具有不同生命周期、事实来源、兼容门和一致性单元。统一 schema 会掩盖自然归属和独立演进边界。

### 解析失败时使用空默认值覆盖

拒绝。空默认值不能证明来源本来为空；它会把损坏、权限、未知 schema 或部分读取伪装成有效空数据，可能覆盖现有目标内容。

### 目标已存在时一律覆盖

拒绝。JueMingR 数据可能是用户迁移后新建或修改的事实；无条件覆盖会静默丢失新数据，也无法处理同名异源和双方新增。

### 每次运行重复导入全部数据

拒绝。它会重复笔记、蓝图、地图标记和事件，重复累加游玩时间或足迹，也不能从中断恢复与真正增量更新中区分重复。

### 用单文件原子替换冒充多文件整体安全

拒绝。临时文件和 replace 只能降低单个文件写到一半的风险，不能保证笔记索引/正文、identity/事实、事件/摘要或批次记录/目标数据共同提交。

### 扫描整块磁盘寻找 exports

拒绝。用户导出可位于任意位置；全盘发现扩大隐私读取与误识别范围，且不符合明确选择的授权边界。

### 把日志和诊断包导入新版运行数据

拒绝。它们是支持与派生产物，可能含路径、名称、环境和运行内容；可解析不等于具有产品事实价值。需要支持证据时应走独立选择和脱敏流程。

### 在当前阶段实现完整迁移器

拒绝。JueMingR 的总体架构、目标功能和目标 schema 尚未获准；提前实现会把未批准产品选择固化成代码，并越过当前 Phase 0 边界。

### 让项目所有者逐字段判断技术映射

拒绝。执行和审查 Agent 应依据正式合同处理字段、schema、hash、幂等、锁与事务等工程问题；项目所有者只决定用户看到的入口、默认范围、冲突结果和重大风险。

## 优点

- Legacy 原件始终可作为恢复、核对和放弃迁移的独立来源。
- 按自然归属和目标身份隔离，可降低全局习惯误绑角色、角色/世界串档和服务器猜测的风险。
- 预检与明确确认让用户先看到范围、排除项和冲突，而不是在首次启动被动接受写入。
- 幂等、增量与批次状态使重复执行和中断重试可以被区分，避免历史事实重复累计。
- 显式冲突和“目标默认不变”保护迁移后新产生的 JueMingR 数据。
- 多文件一致性单元把单文件安全与整体成功分开，避免半完成被报告为成功。
- 目标功能/schema 前置门阻止为未设计功能建立临时数据债。
- 默认排除日志、诊断与维护产物，并禁止全盘扫描，缩小隐私与误导入范围。
- 具体实现延期，使长期用户结果和安全合同不依赖某一种数据库、文件 API 或锁技术。

## 代价

- 实现需要分类预检、来源/目标身份、批次账本或等价能力、隔离候选、条件式提交和分类结果，复杂度高于直接复制目录。
- 某些历史数据会因身份、目标功能、schema 或兼容证据不足而延迟，不能承诺一次全量完成。
- 用户可能需要对少量真正无法安全合并的候选作选择；产品界面必须把技术冲突翻译成普通语言。
- 保持 Legacy 不变意味着迁移后会同时占用旧、新存储，清理须另行设计和授权。
- 多文件、并发、中断与恢复需要故障注入和受控验证；静态审查或普通成功路径不足以证明安全。
- 来源模型的已知缺口与真实文件未知状态意味着实现期仍需最小、脱敏的格式样本或由项目所有者执行的受控验证。

## 后续验证门

本 ADR 被接受也只确定长期策略，不自动授权实现。未来迁移器任务开始前至少需要：

1. 总体架构和相关目标功能获得独立授权；
2. 每类目标自然归属与目标 schema 已批准，并与来源 schema、Terraria/内容环境分层；
3. 字段/语义映射、不可映射项、废弃来源和配置源优先级经过定向审查；
4. 玩家、世界、pair 和可能的服务器身份合同处理重名、重命名、移动、云本地、复制、重建、fallback 与碰撞；
5. 幂等和增量测试证明笔记、蓝图、事件、时间、足迹和地图数据不会重复；
6. 冲突测试证明目标已有数据不会被静默覆盖，只有确定规则自动合并；
7. 多文件中断、并发修改、掉电/写失败、候选校验和恢复测试覆盖每个一致性单元；
8. 未知较新 schema、损坏、截断、缺失、孤立与重复 ID 均安全失败并保留来源；
9. 隐私审计证明不全盘扫描、不上传正文、报告脱敏、外部导出只由用户选择；
10. 项目所有者在获授权的独立任务中亲自执行所有需要 Terraria 的实机与多人场景，并确认用户可见入口、范围和冲突结果。

自动测试、审计、静态证据、实机、多人、性能和项目所有者验收分别记录，任一轴不能冒充另一轴。没有目标实现时，本阶段不创建占位测试或运行真实迁移。

## 接受与替代方式

本 ADR 当前为 `Proposed`。只有其完整语义经过独立审查、项目所有者接受被审查的产品结果、对应规则与路由在同一获授权收口中最终化、最终 head 再次复核通过，并合并进入 `main` 后，才成为 Accepted 决策。PR、审查通过或讨论本身不使它生效。

项目所有者接受本 ADR 只授权后续按[工程治理规则](../规范/工程治理规则.md)完成草案时态、路由、复核和合并收口；不自动授权生产代码、目标 schema、迁移器、真实数据读取、Terraria、真实迁移、清理 Legacy 或下一阶段。

在合并前，本 ADR 和对应规则可以直接放弃。生效后，如需改变 Legacy 只读、迁移入口、默认范围、身份/冲突结果、清理权限或隐私边界，应由新的 Accepted ADR 与对应规则明确替代；不得借实现细节静默弱化本决策。
