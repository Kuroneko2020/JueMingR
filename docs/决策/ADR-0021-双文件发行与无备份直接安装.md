# ADR-0021：双文件发行与无备份直接安装

- 状态：所有者已批准决定；实现与文档候选待任务 PR 合并生效
- 决定来源：[Issue #151](https://github.com/Kuroneko2020/JueMingR/issues/151) 所载所有者 2026-11-02 双文件统一发行与安装委托
- 生效边界：本任务已授权实施和一次确认目标换装；本 ADR 的长期仓库规则随任务 PR 合并生效。不授权自动合并、Tag 或公开发行。

## 决定

正常开发候选、后续打包和另行获准的诊断候选统一为 `JueMingR.dll`＋`Terraria.exe.config`。手动 ZIP 根目录严格只有这两文件；单独 Setup EXE 内嵌同一构建的同一对原始字节。内部组件在受控的 `JueMingR.Runtime/<payloadId>` 展开，源码项目和职责边界保持。

安装/更新直接替换选定并验证目标的两个同名普通文件，已有第三方加载配置不构成拒绝条件。不保存被替换旧 config/DLL，不以旧 Restore 为前置；卸载不恢复小助手/Z。界面与 CLI 共用进程外安装服务。无备份不是跨两文件原子提交承诺；部分失败报告真实步骤，通过重装修复。

## 有限替代

替代技术平台§11、工程安装偏好、版本规则开发包及架构 Setup 职责中与本路线冲突的“旧多载荷正常发行、已有 config 拒绝、每次备份、旧 Restore 前置、卸载恢复第三方”要求。旧实验布局、旧包和原始验证结果保留为历史事实，不改签为本方案证据。

保留合法目标、普通文件/路径/占用检查、自有对象删除、单一 Host/Harmony、一次 Runtime 交接、预测独立进程及全部源码/测试/审查/发布资格要求。世界、角色、笔记、蓝图库、设置的存储和业务 schema 迁移原件保护保持；已有历史备份和回执不删除。实际游戏由所有者启动操作。

## 结果与代价

玩家获得两种同源交付方式；加载器只绑定本容器确定的完整组件目录，不扫描最新版本或回退旧 Validation。安装覆盖后不提供此前第三方工具的恢复保证。机制实现、局部验证、包验证、实际换装和本人体验分别记录于任务，不由本 ADR 宣称通过。
