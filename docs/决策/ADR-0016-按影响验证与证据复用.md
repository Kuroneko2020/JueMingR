# ADR-0016：按影响验证与证据复用

- 状态：Accepted
- 对应任务：[G10 及本轮治理完善 #107](https://github.com/Kuroneko2020/JueMingR/issues/107)，[PR #108](https://github.com/Kuroneko2020/JueMingR/pull/108)
- 生效边界：所有者明确批准本任务方向及条件；完整候选已通过独立语义／工程审查，按预授权完成机械最终化与窄复核后，合并进入 `main` 才正式生效。现有有效条款继续适用，本次受控实施与验证不等于提前全仓生效。

## 原因与决定

风险触发原则已经有效，但逐次架构默认业务、工作量 runner 和开发包重复执行，历史 profile 的双构建措辞又与最窄相关原则竞争。本决定将原则落到现有入口，不改变产品玩法或独立批准制度。

1. 验证与复审跟随实际影响及多层消费者；开发反馈、整批覆盖、专项构建比较分别处理。完整覆盖允许由本次执行和核验后的原证据组成，不设固定检查数量或审查轮次。
2. 结构检查与业务登记分离，同有效输入下每个断言 ID 执行一次；独立配置／场景保留。失败、未知、缺项、未选和复用不能混记。
3. 证据绑定真实输入、参数、产物及环境，保留原执行身份。默认只在可靠边界复用，当前工具以少量明确叶子职责投影相关输入，共享和未知依赖保守处理，原执行产物有界留存；文档／提交身份另记，避免建设语义分析平台。旧格式不能凭 PASS 迁为可信记录。
4. 双构建由确定性输入、工具链、构建／打包方式及明确交付要求触发。独立输出必须重新生成，适用检测结果不因此重复。Release 实产物、包和安装安全要求保留。
5. 网页 Chat 仅作为可选辅助，核对最新目标与授权、合法使用、安全边界、实际入口成本及独立依据；不成为本地 Agent 第二规范或常驻门。

- 细化 [ADR-0006](ADR-0006-测试与审计采用分层验证与独立判定.md) 的按风险、分层、独立判定与成本原则，保留全部数据隔离及实机边界；不重写该历史决定。
- 有限替代 #67/PR #68 在测试／性能规则及工作量设计中的“每次核心、选中检测重新执行”接线；原高频断言维护责任保留。
- 有限替代[构建设计](../设计/可重复构建与项目骨架.md)中历史 profile 的无条件重复构建安排；[ADR-0011](ADR-0011-可重复构建与项目骨架.md)的可信本地威胁模型、固定输入／依赖边界与 [ADR-0013](ADR-0013-单工作区操作偏好与项目知识分层.md) 的单工作区独立输出比较方法保持。
- 路由需随真实职责维护，未知显式阻止合格交付；保守指纹仍可能多测，但避免推断任意代码语义和维护大型缓存。普通业务改动可先局部反馈，最终补足整批义务。
- 无新 SDK、依赖、服务、平台、常驻角色或审批要求。通过正常 Git／PR 可修订或撤销；所有者不需要选择内部测试技术，日常判断由实施者负责。数据保护、只读 Legacy、独立判断和未验证结果保持。
