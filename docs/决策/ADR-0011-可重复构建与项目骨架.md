# ADR-0011：可重复构建与项目骨架

- 状态：Proposed
- 日期：2026-09-01
- 对应任务：[Phase 0-R Issue #23](https://github.com/Kuroneko2020/JueMingR/issues/23)
- 对应设计：[可重复构建与项目骨架](../设计/可重复构建与项目骨架.md)
- 上位决定：[ADR-0010：总体架构与状态所有权](ADR-0010-总体架构与状态所有权.md)

## 背景

总体架构已经批准六个候选生产物理边界，但任务开始时仓库没有解决方案、项目、生产源码、测试项目、构建入口或可复核游戏引用输入。本轮是第一项真实生产工程任务；此前的文档与治理试运行不能证明生产代码可以在当前宿主条件下构建，也不能证明项目引用门会在真实违规时失败。

JueMingR 必须面向原版 Terraria 的 32 位 .NET Framework 同进程宿主，同时保持 Early Bootstrap BCL-only、Host-neutral Platform、唯一游戏程序集引用边界和 Legacy 零依赖。Terraria、ReLogic 和 XNA 是合法本地编译输入，不能提交到 Git 或复制进 JueMingR 输出；源码、工具链、引用和产物身份必须分离。

当前不需要 Harmony、AppDomainManager 或加载链。若为“以后可能需要”预建 Coordinator、Feature、安装器、全局 Manager 或测试基础设施，会扩大尚未有运行证据的长期承诺。

## 决策草案

本节记录待独立工程审查的选择。项目所有者已预授权审查通过后的机械最终化；只有随本任务合并进入 `main` 后，本 ADR 和对应设计才生效。

1. 使用经当前机器实际验证的 Microsoft .NET SDK `10.0.203` 及其 MSBuild `18.3.3.22005`/Roslyn，`global.json` 精确锁定且不 roll forward、不允许 preview。
2. 七个当前项目使用 SDK 风格 `net472`、C# `7.3`、显式 `x86`，依赖已安装的 .NET Framework 4.7.2 Developer Pack / Targeting Pack；不使用任何 PackageReference、NuGet reference assemblies 包、Source Link 包或第三方构建工具。
3. 建立六个生产 class library：Bootstrap、Platform、Features、TerrariaHost、Infrastructure、Setup；另建一个无第三方框架的 ArchitectureTests console executable，不增加其它项目。
4. ProjectReference 固定为：Bootstrap/Platform/Setup 无引用；Features/Infrastructure 各只引用 Platform；TerrariaHost 只引用 Platform、Features、Infrastructure；ArchitectureTests 只引用 Platform。
5. Bootstrap 只有无行为 marker，保持 BCL-only；Platform 只有 marker 与最小 typed operation request/result seam，不实现 Runtime、Session、Coordinator、队列、线程、重试或工作流。
6. 只有 TerrariaHost 直接引用 Terraria、ReLogic 和最小必需 XNA Game，全部 `Private=false`；当前只含 marker 和无副作用 `typeof(...)` 编译探针，不创建 Composition Root 或游戏对象。
7. Setup 当前只是无行为 class library 边界，用于证明它不依赖游戏内项目/程序集；不实现最终进程外 executable、CLI、UI、安装或恢复，也不锁定其未来运行时。
8. 合法游戏引用由 Windows PowerShell 5.1 兼容脚本从 Steam/显式 Terraria 安装、Terraria.exe 精确嵌入资源和 Microsoft XNA 安装/GAC_32 准备到 Git 忽略目录；不下载、不扫描整盘、不把 Legacy 当作输入、不修改源安装。三个正式入口都必须先确认规定的同级 Legacy 仓库存在并解析其 Windows 最终物理根；复现入口把同一根作为“只用于禁止写入的受保护路径”显式传给系统 TEMP 中没有 Legacy sibling 的 clean clones，副本不得读取其内容。显式例外只接受 system TEMP 直接子目录中名称为 `JueMingR-Repro-<32 hex>` 的 verifier root，以及其两个精确 clone leaf；普通无 sibling checkout 即使传入同名目录也必须失败。当 repository 自己已有 sibling 时，显式参数不能把它替换为其它目录。准备目标、构建/复现输出、调用者 TEMP 派生 scratch、staging、backup 和临时 clone 等一切可能写入或递归清理的根，都必须在首次写入前与 repository、destination、合法来源和 Legacy 中相应的受保护根双向不重叠。准备目录、构建输出、refs 和 marker 记录的 Terraria/XNA 来源也必须在任何写入前解析为 Windows 最终物理路径并通过双向不重叠门；marker 来源文件还必须继续匹配正式 baseline。`-Force` 只能替换结构、marker schema、来源身份和文件元数据都能证明由当前脚本完整拥有的引用目录。
9. 仓库跟踪 schema 1 reference baseline，记录三项逻辑文件的程序集/文件版本、public key token、PE/CLR、Requires32Bit、SHA-256、来源、不可由 JueMingR 再分发和不 Copy Local；仓库不保存游戏文件。
10. 正式 Windows PowerShell build entry 在任何外部工具或输出写入前，先解析并验证精确 `dotnet.exe`/`git.exe` 的绝对、非 reparse 路径，再完整快照当前进程环境、清空全部继承变量，只重建受控 Windows 基础目录、固定工具 PATH、与 repository/refs/output/合法来源/Legacy 物理隔离的 owned TEMP 用户状态，以及锁定的 .NET CLI/NuGet/Git/MSBuild 变量；任何普通环境变量都不能再作为隐式 MSBuild 属性、import、构建事件或旁路输出路径进入子进程。入口在创建 owned scratch 前，用未绑定的 Git discovery 探针要求 `show-toplevel` 的最终物理路径等于当前 repository，保存当前 worktree 私有 git-dir/common-dir，并先要求 prospective scratch 与两项 metadata、refs、output/configuration、合法来源和 Legacy 双向不重叠；创建 scratch 后立即复核同一 binding，随后所有身份调用都显式使用该 git-dir/work-tree，并在记录前再次发现和比对绑定。local `core.worktree` 不能把 clean/dirty 判断重定向到另一目录，自定义 separate git-dir 也不能落入会写入或清理的树。入口同时关闭外部 Git 全局/系统配置与 hooks，Git 调用禁用 pager/replacement objects，dirty identity 的 diff 还明确禁用 external diff/textconv；所有 recorded source path 的索引必须是普通 stage-0 `100644/100755`，不接受 conflict、assume-unchanged、skip-worktree、symlink 或 gitlink，且 `filter`、`ident`、`working-tree-encoding` 和 textconv 等内容转换/外部处理属性必须未设置。clean 身份还要求每个 tracked path 的原始 working-tree blob、index blob 和固定 commit blob/mode 三方一致；每个 recorded path 的 ordinal 路径、mode、存在性、长度和物理 SHA-256 形成独立内容 digest，构建前后必须完全相同。入口显式关闭 Git source-control 查询、SourceLink、untracked source embedding、repository URL 发布和 RepositoryUrl assembly metadata；`DeterministicSourcePaths=false`，但保留 `Deterministic=true` 与受检查的显式 PathMap，使 Git remote/provider 不进入 DLL/PDB。入口锁死 compiler side output、build event、pack/deploy、restore graph 与 `OutDir` 边界，并对每次 MSBuild 调用禁用 node reuse。随后验证精确 SDK、由 Windows SpecialFolder 取得的 Targeting Pack、refs/baseline 与来源文件身份、来源/refs/仓库 `artifacts` 下专用输出的最终物理路径隔离、既有输出的完整 owned 结构、Git 二进制边界、clean/dirty 身份、原始 solution/project/shared build 定义，以及正式参数下的有效项目属性、构建时依赖项和全部输出/中间目录。入口还把 tracked 与 non-ignored untracked 路径组成 recorded source inventory，拒绝 `eng/src/tests` 和根正式输入中任何 ignored、reparse 或未记录物理文件，并审计五类 pre-target 求值项只来自 recorded repository、当前项目精确 guarded intermediate 或 locked SDK；repository input 同时记录实际 SHA-256。该求值项记录不冒充 target 执行期由 locked SDK 生成的完整 Csc 输入闭包。入口再 fresh restore/build、运行 ArchitectureTests，按精确 26 项声明输出扫描产物，并在写 ignored build record 前复核来源哈希、Legacy 只读边界、Git 索引/属性、物理 Git 绑定、原始内容盘点和完整 Git source identity 未变化。成功或失败都必须分别尝试完整恢复调用者环境和清理 owned scratch；任一步失败都不写 build record 或 PASS。
11. build record 分开记录 commit、含原始内容 digest 的 dirty identity、全量 recorded source 物理 SHA-256 盘点、物理 Git/正式输入策略、configuration、`closed-allowlist-v1` 环境策略、七个项目的实际求值构建属性、关闭的 Git/SourceLink 元数据属性、compiler/build side-effect 有效值、五类有效输出/中间路径、ProjectReference/direct Reference/PackageReference、批准的 SDK Analyzer 与空 COM/native references，以及五类 pre-target 求值项的相对路径/来源/repository SHA-256、逐项目 input-set SHA-256 和 ignored count 0；同时记录由一致结果派生的 TFM/x86/C# 版本、SDK/MSBuild/compiler/PowerShell/Developer Pack、参数、baseline、refs、精确声明输出哈希、架构结果、外部时间和未验证轴。二进制只使用非发布占位版本和显式 SourceRevisionId，不嵌入当前时间。
12. 可重复构建的声明范围为全部正式 DLL、EXE 和 portable PDB；两个路径不同、不继承 refs、各自拥有 obj/bin 的 clean clone 必须在相同 commit、工具链、引用和参数下得到相同 raw source content digest 与 pre-target evaluated item/content set，再逐文件 SHA-256 一致，差异为 0。clone 持久锁定 `core.autocrlf=false`/`core.eol=lf`，checkout 再次显式锁定，并由两个独立 `powershell.exe` 进程构建；verifier 不信任 record 中的 digest，而从两个 clone 的物理文件重算并与调用者三方比较。带时间的 build record 不参与比较。复现入口与 build entry 使用相同的 Legacy、物理 Git、正式输入、索引/属性和环境恢复约束；最终 summary 不在既有路径上原地截断，而是在同目录用随机 `CreateNew` 普通文件写入并 flush，删除旧目录项后原子 move，避免既有 hardlink/symlink 把摘要写入重定向到受保护文件。
13. ArchitectureTests 只接受正式 build entry 传入的 repository/configuration、两项锁定工具链根和 owned tool-state root，并先断言自身恰好继承 `closed-allowlist-v1` 环境；它用机器可读 solution/csproj/XML/MSBuild 实际求值/文件系统/Git/程序集元数据检查精确 C# 项目集、图、循环、所有 direct Reference、批准的 SDK Analyzer、空 COM/native/PackageReference、游戏/Legacy/TerrariaHelper 边界、Copy Local、项目 SDK、TFM/x86/C# 7.3、全部输出路径、compiler/build side-effect、关键确定性属性、operation 完整 public API 面和正式输入。其 Git 与 dotnet 子进程使用已验证绝对可执行文件，并从零构造各自最小环境。根 `Directory.Build.targets` 必须为空，嵌套共享 build 文件、附加 SDK/import/hook、未批准 XML 元素、条件化关键属性、项目引用 metadata 和外部 XML namespace 均 fail closed，Git 二进制边界同时按文件名、baseline 内容哈希和程序集身份检查，不审核自然语言，也不以生产类名存在冒充运行行为。
14. 最小 operation contract 只有 typed request marker、底层类型为 `int` 且数值固定为 `0..6` 的七种互异终态 outcome，以及以一个必需、不可选构造参数接收已定义 outcome 并只读返回它的 sealed result；不预建字符串业务分派、执行器、Host port、Feature 目标、线程、重试、持久化、诊断或全局错误框架。
15. 当前不创建 CI、加载链、安装器、Feature、Tag、Release、安装包或用户测试包；当前证据只覆盖本机工具链、合法编译输入、结构、构建身份和声明范围内的字节复现。

上述 content inventory 覆盖全部 tracked/non-ignored recorded path。会影响正式二进制的根 build/config 文件及 `eng/src/tests` 使用原始物理字节；Markdown、PowerShell 与 `.gitignore` 使用显式 `normalizedTextLf` 内容模式，使 Windows CRLF checkout 与规范 LF clone 在 Git 文本内容相同时得到同一身份。第 10 项的“物理长度/SHA-256”和 raw blob 三方一致只适用于 `contentMode=raw`；规范文本项记录 UTF-8/LF 长度/SHA-256，并以 Git 正常文本转换结果与 index/commit 比较。两类均记录 SHA-256 并进入总 digest。第 12 项的 `raw source content digest` 术语按本段校正为 recorded-source content-mode digest。

## 候选方案和拒绝理由

### 采用：锁定 SDK 的六边界最小骨架

该方案把 ADR-0010 已批准的职责映射为最少物理项目，用 `ProjectReference` 和直接 assembly reference 形成可执行边界；合法专有输入只保存在本机，身份由 Git baseline 约束；自有测试 runner 足以检查当前结构，不引入长期包或 CI。统一 x86 与当前宿主/refs 的实际 PE/CLR 证据一致，也避免本轮维护混合 solution platform。

### 已安装 SDK 6.0.428（未采用）

该 SDK 能作为候选 Microsoft 工具链，但本机已经用稳定 `10.0.203` 完成 net472/x86、无 PackageReference 的 class library 与 executable 探针。再维护第二套正式 SDK 只会增加恢复与输出身份，不提供本轮需要的额外能力。

### Visual Studio MSBuild 18.5.4.18101（未采用）

本机 Visual Studio 安装包含该 MSBuild，但 `msbuild` 不在 PATH，使用它需要发现私有 VS 安装位置。SDK `10.0.203` 内置 MSBuild 已完成全部目标探针，因此不引入第二个、依赖 IDE 安装布局的正式入口。

### AnyCPU 或混合 solution platform（未采用）

AnyCPU 最小探针能够构建，但其输出不带 `Requires32Bit`，不能直接表达当前 Terraria 同进程的 32 位约束。所有当前项目统一 x86 能以最小配置保证被 32 位 CLR 加载；这不锁定未来进程外 Setup/Recovery 的最终运行时。

### 直接复制 JueMingZ 项目（拒绝）

Legacy 只能提供行为和风险证据。复制其项目、refs 或 schema 会违反独立重写和永久只读边界，并把历史依赖/架构迁就带入新版。

### 一个大项目（拒绝）

一个程序集无法用编译边界保持 Bootstrap BCL-only、Platform Host-neutral、Setup 进程外职责和 Host 唯一游戏引用，单靠命名空间不足。

### 一个 Feature 一个项目（拒绝）

当前没有任何真实具体 Feature，也没有证据需要为每个具体 Feature 分别建立物理程序集。预建“一项具体功能一个项目”会膨胀解决方案和长期维护面；已批准的单一 Feature Collection 边界只用 marker 证明程序集边界。

### 所有项目直接引用 Terraria（拒绝）

这会让游戏 ABI、线程和对象生命周期扩散到 Bootstrap、Platform、Features、Infrastructure 和 Setup，破坏 Host 适配边界。

### 直接提交游戏 DLL（拒绝）

专有 Terraria/ReLogic/XNA 文件不属于 JueMingR 可再分发资产；提交会违反法律/隐私边界，也把本地输入错误地当作源码。

### 从 Legacy 复制 refs（拒绝）

Legacy refs 不能证明当前合法安装、当前 Steam build 或当前 XNA 来源，也会产生编译依赖。当前脚本只从合法本地安装和 Microsoft XNA 安装取得。

### 私人绝对 HintPath（拒绝）

绝对路径无法在新 clone、其他用户或独立审查环境恢复，还会泄露本机信息。项目只使用参数化的本地 reference root。

### NuGet reference assemblies 包（拒绝）

本机已经安装官方 .NET Framework 4.7.2 Targeting Pack；引包会增加未授权长期依赖和恢复路径，并掩盖缺失系统前置条件。

### 立即加入 Harmony（拒绝）

本轮不加载、不 Hook，也没有需要 patch 的行为。Harmony 属于后续加载/Host 任务，不能为编译探针提前引入。

### 立即实现完整 Operation 框架（拒绝）

当前只需证明 typed、Host-neutral seam 和终态分类。Coordinator、执行器、线程交接、冲突域与失败原因必须由加载链和真实 Feature 校准。

### 本地 build 一次即称可重复（拒绝）

一次成功只能证明一次输入组合可编译，不能发现绝对路径、时间、obj 缓存或 PDB 引入的非确定性。

### 同一目录连续 build 两次（拒绝）

复用同一 obj/bin 会掩盖未声明输入。正式复现使用两个不同路径的独立 clean clone，每个副本重新准备 refs。

### 用 CI 代替本地可恢复构建（拒绝）

当前没有批准 CI，也不能上传专有 refs。先建立仓库原生、本机可恢复脚本；未来 CI 必须另行设计合法输入来源和权限。

### 空功能和万能 Manager（拒绝）

没有真实消费者、状态 owner 或生命周期证据时创建 Manager、Registry、Provider、Dispatcher、Event Bus、全局队列或空 Feature，只会预先固化错误抽象。

## 结果

### 优点

- 六个生产边界和依赖方向由 MSBuild 与 ArchitectureTests 双重表达；
- Bootstrap、Platform、Setup 和游戏 Host 的引用隔离可机器验证；
- 新 clone 能从合法本地安装恢复 refs，而 Git 不保存或输出专有文件；
- source/toolchain/refs/parameters/outputs 身份分开记录；
- DLL/EXE/PDB 的跨路径字节复现已经有正式入口和实际证据；
- 不需要新包、第三方工具、CI 或 Terraria 实机。

### 代价

- 开发者必须安装精确 SDK、4.7.2 Targeting Pack、XNA 4.0 Refresh，并持有与 baseline 匹配的合法 Terraria；
- refs 验证和双 clone 会增加秒级构建/哈希成本；
- baseline 与工具链升级需要显式任务和完整重验；
- 统一 x86 对当前骨架最简单，但未来独立 Setup 工具需要重新作运行时决定；
- build record 含时间和本地执行身份，不是声明可重复输出。

### 当前构建边界

当前只构建 marker、最小 operation contract、无副作用引用探针和架构 runner。编译通过不等于 Terraria 加载、Hook、功能、安装、多人、性能、用户验收或发布。TerrariaHost 是唯一物理游戏引用边界，但具体 Composition Root 尚不存在；Setup 也尚不是最终可执行部署单元。

### 未验证范围

- 原版 Terraria 进程加载、AppDomainManager、config 和固定 handoff；
- Harmony、Host 回调、Runtime/Session/Coordinator；
- 任何 Feature、UI、持久化、Diagnostics、安装恢复；
- Steam/GOG/Windows 渠道运行兼容、多人与重连；
- FPS、热路径和产品性能；
- 项目所有者实机与用户验收；
- Tag、Release、安装资产和正式产品版本。

### 后续工具链升级成本

任何改变 SDK、MSBuild、Developer Pack、TFM、PlatformTarget、PDB/PathMap、refs 来源或可重复声明范围的工作，都要重新跑工具链探针、引用身份/反例、Debug/Release、ArchitectureTests 及三项负向控制、missing refs、clean clone 和双副本字节比较。输出或长期边界改变时需要新的 Accepted ADR。

## 后续验证门

当前只能证明构建和结构。下一候选阶段是“最小原版加载链验证”，但必须由独立 Issue 和项目所有者授权，且 Terraria 实机只能由项目所有者亲自执行。后续真实 Feature 必须校准 operation request payload、执行边界和失败原因，不能把当前最小终态分类扩写成万能框架。

当前不创建下一阶段 Issue、发布资产、安装包或用户测试包。加载、实机、多人、性能和发布仍是未验证轴。

## 接受与替代方式

本 ADR 初始状态为 Proposed。项目所有者已经预授权：当 Phase 0-R PR 的隔离独立工程审查达到 Critical 0、Important 0、所有必需实际检查通过且不需要新依赖、架构变化或 Terraria 实机时，可以机械改为 Accepted；只有合并进入 `main` 后才生效。

以后修改六个项目边界、主工具链、TFM/PlatformTarget、游戏引用来源模型或可重复构建定义，需要新的 Accepted ADR。普通 SDK 补丁更新是否需要新 ADR，取决于它是否改变输出、恢复方式或长期边界；不得静默改写本 ADR 历史。
