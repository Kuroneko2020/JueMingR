# ADR-0011：可重复构建与项目骨架

- 状态：Proposed
- 日期：2026-09-02
- 对应任务：[Phase 0-R Issue #23](https://github.com/Kuroneko2020/JueMingR/issues/23)
- 对应设计：[可重复构建与项目骨架](../设计/可重复构建与项目骨架.md)
- 前置决定：[ADR-0010：总体架构与状态所有权](ADR-0010-总体架构与状态所有权.md)

## 背景

ADR-0010 已提出六个候选物理边界，但未授权建立项目。Phase 0-R 的首个实验实现证明了锁定工具链、合法本地游戏引用和跨 worktree 字节复现可行，也暴露出另一类风险：若把同权限恶意环境、Git 内部状态和构建器自证都纳入当前任务，脚本与测试会远大于骨架本身，普通 Agent 难以维护。

项目所有者因此关闭但保留未合并的实验 PR #24，并在 Issue #23 将范围改为精简替代实现。当前需要保留已经证明必要的核心，同时明确接受一个较窄的本地开发威胁模型。

## 决策

若本 ADR 随精简替代 PR 被项目所有者接受并合并，则采用以下决定：

1. 锁定 .NET SDK `10.0.203`，所有项目使用 `net472`、C# `7.3` 和 `x86`，不引入 `PackageReference`。
2. 建立 Bootstrap、Platform、Features、TerrariaHost、Infrastructure、Setup 六个生产项目，以及一个无第三方包的 ArchitectureTests console 项目。
3. ProjectReference 图固定为：Features→Platform、Infrastructure→Platform、TerrariaHost→Platform+Features+Infrastructure、ArchitectureTests→Platform；其余项目无项目引用。
4. TerrariaHost 是唯一游戏引用边界。Terraria、ReLogic 和 XNA 只从固定、被忽略的本地目录引用，均为 `Private=false`。
5. baseline 记录三项合法编译引用的公开身份与 SHA-256；游戏文件不进入 Git、输出或分发。
6. 保留三个低能力脚本：显式准备引用、固定目录构建、两个系统 TEMP detached worktree 的 Release 字节复现。
7. ArchitectureTests 只执行 Issue #23 列出的 13 类检查；只保留三个指定负向控制。
8. 当前源码只实现 marker、内部 compile probe 和最小 operation contract，不实现加载、安装、运行时协调或用户功能。
9. 威胁模型信任当前仓库所有者、执行 Agent、普通 Git 和本机工具链。敌对 Git/环境变量、链接与 TOCTOU、同权限恶意进程和构建器自证明确不在本决定范围内。
10. 构建证据只支持源码边界、编译引用、声明输出和同 commit 字节复现结论；不支持加载、兼容、实机、多人、性能或玩家验收结论。

## 候选方案

### 精简固定脚本与有限检查（采用）

该方案直接覆盖当前可信本地开发流程中的真实失败：错误 SDK、错误或缺失引用、依赖方向回流、游戏文件误跟踪或 Copy Local，以及非确定声明输出。实现规模与骨架相称，后续 Agent 可以逐文件复核。

### 保留旧实验的敌对环境审计（拒绝）

旧实现包含 Git physical binding、环境隔离、raw blob/index 比较、链接防御、PowerShell 控制流审计和构建器自证。它们处理的是当前未批准的同权限对抗模型，会显著增加误报、维护成本和审查轮次，因此只保留旧实验及其历史证据，不进入替代实现。

### 引入 NuGet reference assemblies 或第三方测试框架（拒绝）

当前机器已经具备已核验的 SDK、targeting pack 和 Windows PowerShell 5.1；BCL console runner 足以检查有限合同。新增依赖没有必要收益，并会扩大恢复与供应链边界。

## 结果

### 优点

- 六项目图和唯一游戏引用边界可以由短小检查器直接验证；
- 合法游戏文件保持本地、被忽略且不 Copy Local；
- 构建输入和输出记录足以复核同 commit 的字节一致性；
- 脚本接口、写入目录和 TEMP worktree 所有权清楚；
- 代码规模受硬预算限制，降低后续维护成本。

### 代价与剩余风险

- 工具链或游戏版本变化需要显式更新 baseline 和决定；
- 检查器信任仓库内容和本机普通执行环境，不提供恶意篡改防护；
- 项目骨架尚未验证任何真实加载、生命周期、功能或安装路径；
- 六个边界仍需后续获得授权的加载链和代表性切片校准。

## 状态边界

本 ADR 保持 Proposed，对应设计保持草案。PR、测试或独立审查通过都不会自动使它 Accepted；只有项目所有者复核、明确接受并合并后，才允许更新正式路由与后续阶段状态。
