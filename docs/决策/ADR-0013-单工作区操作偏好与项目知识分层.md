# ADR-0013：单工作区操作偏好与项目知识分层

- 状态：Proposed
- 对应任务：[Issue #36](https://github.com/Kuroneko2020/JueMingR/issues/36)
- 生效边界：目录与本轮整理方向已获所有者授权；本 ADR 及新增规则是本 PR 候选，待所有者接受、机械最终化与窄审后，获准合并进入 `main` 才成为长期合同。现有有效规则和 #34 已接受的配置、诊断退出条款继续有效。

## 背景

精选历史机制和用户说明需要可追溯的 Git 文档；外部反编译与参考图需要独立版本的持久本地快照。只链接 Legacy 会使日常研究依赖旧目录，全量复制则引入重复内容与许可混淆。另有既存双工作树验证入口、历史验收后恢复步骤，与所有者明确的单工作区和保留可用安装偏好需要协调。

## 候选决定

1. 新增真实分类 `docs/AI经验笔记/` 与 `docs/功能介绍/`，均跟踪。按主题合并旧经验与行为，明确当前 R、历史证据、仅文档声称、待核对；技术合同仍在设计，动态任务仍在 Issues。原文留 Legacy，不另存完整旧文档副本。
2. 根 `/references/` 精确忽略。精选 Terraria、TerrariaHelper 与参考图按身份分开，实际普通复制且一次校验，默认只读、不作缓存、不属用户数据、不随 Git 备份。编译继续用 `external/TerrariaRefs`；研究副本不成为代码、构建、运行、资产或分发输入。
3. 单主工作区、单实施者、普通分支/PR；独立只读上下文审查。已授权开发并交所有者实测的候选在检查/审查及安全预检后安装到已确认目标，免重复确认同一许可；异常安全门停止，不自动操作游戏。保留已测试可用安装，纯文档收口不默认卸载、重建或重测，安装与合并 SHA 分开。诊断退出合同不受削弱。
4. 常规重复构建采用相同 clean commit 与锁定输入的同工作区顺序干净比较；旧工作树脚本保留原实现但退出当前自动/默认路由。此证据不等于独立 checkout/跨环境复现；更强发布证据在对应任务解决。
5. 新知识在产生的同一任务整理，受影响行为说明同步；没有新知识不造文档。被推翻经验更新或退出当前索引，硬边界由适当设计、类型、测试和就地注释承担。入口按当前任务定向路由，不新增服务、角色、审计或定期任务。
6. 已有 docs/精选本地资料足够时，Legacy 缺失不无条件阻塞。需要未选入证据而来源缺失，只停止依赖部分；不猜路径、全盘扫描或自动 clone。

## 替代与保留边界

- 补充 [ADR-0001](ADR-0001-文档体系与受控演进.md) 的分类及精选历史材料路由，保留其受控结构、唯一事实与禁止流水原则。
- 接受后替代 [ADR-0011](ADR-0011-可重复构建与项目骨架.md) 第 6 项中“双 clean worktree”作为本机常规执行方式的部分，保留锁定输入、声明产物比较与不得越级的证据要求。历史 ADR 不被改写，独立工作树机制仍是既存脚本事实。
- [技术平台规则](../规范/技术平台与兼容规则.md) 对 TerrariaHelper 实现不得复制进 R 的生产 clean-room 边界保留。本次所有者明确允许的例外仅为**不进入 Git/产品的本地原件研究快照**；不授权把其反编译代码、二进制或资源复用于 R 实现或分发，不推定第三方许可证。
- 历史加载/F5 验证的恢复步骤仍是当时证据；未来默认交付按[工程偏好](../规范/工程治理规则.md#单工作区与安装交付偏好)，实际安装技术门与已接受诊断退出要求不变。

## 代价与接受点

普通克隆不包含原件，缺资料须按[来源说明](../设计/本地参考资料使用说明.md)补齐或限定结论；历史文档未必由 Git 绑定，整理不能声称重验所有旧结论。同工作区比较不能排除独立环境差异。所有者需要接受上述实际长期语义及窄替代关系；本 ADR 不授权合并、发布、游戏操作或下一功能。
