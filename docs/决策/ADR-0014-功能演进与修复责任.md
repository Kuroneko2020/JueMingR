# ADR-0014：功能演进与修复责任

- 状态：Accepted
- 对应任务：[功能演进、根因修复与临时处置责任补全 #40](https://github.com/Kuroneko2020/JueMingR/issues/40)
- 对应条款：[工程治理规则](../规范/工程治理规则.md#功能演进缺陷修复与临时处置)
- 生效边界：本 ADR、集中条款与新增读取、实施、审查和交付责任已获所有者接受，随本次合并进入 `main` 生效；现有有效规范继续适用。

## 背景

本次补充前，工程治理已有任务授权、角色分工和独立审查，架构已有唯一状态所有者与失败语义，测试和性能规则已有独立判定、合法测试修订及诊断退出。它们尚缺少集中表达，把变化性质、足以支持修复的因果依据、职责落点、必要局部重构与临时止损接到同一任务的实施和交付。

## 已接受的决定

在工程治理中集中补清通用判断与既有角色责任，由根 AGENTS 和文档入口提供短路由。允许功能和体验迭代，但不放松明确合同与安全边界；修复有足够因果依据并落在正确职责，必要重构服务同一结果且遵守授权；被替代内容有去向，临时止损准确说明未解决项和恢复条件。具体含义只由集中条款承载，不在本 ADR 复制全文。

这是对 [ADR-0008](ADR-0008-工程治理采用风险分级与仓库原生流程.md) 既有责任的补充，不建立治理平台，不替代或放宽总体架构、测试、性能、版本、诊断退出、关键注释及同任务知识维护合同，也不改写 Accepted ADR。领域要求继续由原文档承担。

## 代价与替代方案

实施者需在原任务中说明适用的变化性质、依据与结果；审查者需核对因果、职责及复杂度用途。复用既有 Issue、PR、Git、注释和证据限制记录成本，不新增必需工具、角色、审批层、外部咨询、自动审计、修复台账或常驻管理机制；所有者继续只承担产品、体验与风险裁决，日常技术工作由 Agent 负责。

只保留分散原则会留下读取和责任落点缺口；复制各领域合同会增加矛盾与维护成本；要求每次修复做无限根因调查、重构、全量回归或减少代码行数则脱离实际风险，均不采用。必要防御、兼容和过渡实现仍可有依据地保留，不以“禁止补丁”取消安全措施。

## 接受与演进边界

本 ADR 与集中条款的实质语义已经通过独立语义审查，并获项目所有者明确接受及机械最终化、条件式合并授权。按[长期规则与 ADR 的正式化闭环](../规范/工程治理规则.md#九长期规则与-adr-的正式化闭环)完成最终化窄复核，且待合并 head 与被复核 head 一致、无现场阻塞后，随本次合并进入 `main` 生效；独立审查本身不替代所有者接受与合并授权。

后续可通过受控修改或 revert 调整；实质决策变化按既有 ADR 演进规则记录替代关系，不静默改写历史。本补充不授权具体代码修复、笔记产品差异或设计实现、进程/安装/删除/回滚操作、合并、发布或下一任务。
