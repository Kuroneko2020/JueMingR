# 当前群系显示与 F5 配置

这是当前 **JueMingR** 的用户说明。依据 #34 / [PR #35](https://github.com/Kuroneko2020/JueMingR/pull/35) 合并后的 main 实现、[群系设计](../设计/代表性纵向切片一-群系显示.md)、[F5 设计](../设计/F5控制界面样板与UI基础.md)和[配置持久化设计 A 部分](../设计/配置持久化与用户数据布局.md)。当前目标为 Terraria **1.4.5.8**；既有所有者实机/接受证据只覆盖其 Windows Steam 单人场景，不外推多人、其它渠道、全部分辨率或 FPS。

## 查看群系与控制显示

进入普通单人世界后，默认显示绿色 `群系: …`，随所处区域更新；离开世界回菜单不保留旧文字。F5 打开或隐藏控制界面，默认进入“信息”页。点击群系行的“关闭”隐藏群系文字，点击“开启”恢复；绿色/红色短下划线表达实际选择。实际故障显示“不可用”，不能靠重复点击或改配置解除故障。

F5 只控制界面显隐，不导出诊断。界面有两行分类：物品、杂项、地图、查询、笔记、关于，以及蓝图、钓鱼、战斗、信息、增益、移动。**当前真实业务控制只有群系显示**；其它样板行、模式和键盘图标不代表已有蓝图、笔记编辑、快捷键绑定或自动化能力。不要按 Legacy 页面的说明在 R 寻找尚未接入的动作。

## 移动窗口与输入

拖住标题栏移动窗口，正文滚动时标题/导航固定。窗口位置可跨启动恢复；自动适应屏幕/UI scale 的边界夹紧不会覆盖用户原位置，用户再次主动拖动才形成新偏好。F5 是否打开、最后页签、滚动和正在拖动状态不跨启动保存。

失焦、进入全屏地图、原版设置/特殊 UI、拍照等不安全场景会关闭或取消当前交互。标题拖动被关闭、失焦或退出世界打断时，保留最后一个有效且聚焦的拖动位置，不把合成释放坐标当新位置。直接关闭进程前尚未交给保存系统的拖动过程不保证保存；具体输入范围与极小视口行为查 F5 设计。当前 F5 入口限定单人、键鼠和有效游戏焦点。

## 保存在哪里

同一游戏安装目录下：

| 文件 | 保存内容 | 缺文件默认 |
| --- | --- | --- |
| `JueMingRData/config/features/biome-display.json` | 群系显示的用户期望开关 | 开启 |
| `JueMingRData/config/ui.json` | F5 最终窗口位置 | 居中 |

偏好在同一安装内跨角色、世界与回菜单共享，不自动共享到其它游戏副本或电脑。首次缺文件不会立刻生成默认 JSON，真实修改后才保存；目录或锁文件存在不等于偏好已落盘。当前只实施这两份文档，没有笔记/蓝图/足迹存储，也不自动导入 Legacy 设置。精确 schema、备份、锁和后台生命周期只查配置设计，不在这里维护第二套技术合同。

## 正常静默，异常才提醒

合法读取、首次缺失、切换开关、拖动与正常自动保存都静默，不弹“保存中/保存成功”，也不改成成功日志。真正读取/保存失败、损坏、未知字段或版本、超时、占用或外部修改冲突才给必要中文提醒。同一份文档的同一持续异常不会因重复操作、开关 F5 或切世界刷屏；不同文档各自提醒。菜单或原版隐藏 UI 时暂不领取，显示成功才算提醒已交付。

异常时本次内存选择可能仍生效，但磁盘未可靠保存；保护原件，不自动降级、覆盖未知字段、恢复备份、换目录或提权，也不在本进程中自动重试/热重载。按提示退出游戏后处理具体文件原因再启动：格式损坏时先备份并仅移走提示的配置文件；冲突时保留该文件及 `.bak`；不要整体删除 `JueMingRData` 或盲删锁文件。两份配置独立，一份失败不等于另一份保存失败。
