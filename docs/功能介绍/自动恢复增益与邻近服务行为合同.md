# 自动恢复、增益与邻近服务行为合同

G07 的实施候选合同；授权、实际检查、安装与接受状态以 [#97](https://github.com/Kuroneko2020/JueMingR/issues/97) 为准。所有者已决定本节策略，尚未表示实现、实机或多人验收通过。技术依据与分步交付见[实现设计](../设计/自动恢复增益与邻近服务实现设计.md)。历史调查保持原样，不用本合同反写 Z 行为。

## 新旧差异与默认

回血、回蓝、护士、家具增益、自动增益依次放在 F5 增益页；自动收税在杂项页。六项默认关闭，跟随添加和跟随删除独立默认关闭，增益名单为空，两份药品禁用名单为空（默认允许所有当前原版合法药品）。每项有现有公共快捷键入口，初始未绑定；回血开关键在关闭时开快速，任一开启模式变关闭。不改原版 H/J/B。

恢复来源从旧背包实现明确扩为当前原版快速恢复允许的主包 0—57 和**可使用虚空袋**，不含鼠标槽 58、箱子、其它银行或远端物品。收藏不是禁止消费。许可是物品类型许可，真实提供者仍须通过当前会话、容器、槽位、对象、类型、数量与共享占用重验。

智能回血采用本轮明确的单向 50% 门槛与损失公式，快速采用最接近缺血规则；不继承按名称推测的旧策略。本轮不优化冷却，但完整保留真实冷却、特殊效果、实际消费和防重入。回蓝检查下一次实际费用，保持持续施法，不借快捷物品的攻击禁用门。家具采用当前版本完整对象与原版效果，自动调用不打开制作窗口。NPC 失败不循环开聊，不以关窗或短暂空引用证明失败已消失。

## 回血选择

`D=max(0,M-currentLife)`，`M` 为当前有效最大生命，`H` 为截上限前的本次名义恢复量（随机品用真实分布的数学期望，不预抽随机数）。无缺血不使用。

- 智能：`D>=H` 总是通过门槛；只有 `0<D<H` 时要求 `2*D>min(H,M)`，等号拒绝。
- 合格候选最小化 `max(H-D,0)+2*max(D-H,0)`；同分依次选剩余缺血更小、主包、较小槽号、较小类型。
- 快速：不设上述门槛，最小化 `abs(H-D)`，同分选较大 H，再按相同来源次序。
- 先排除禁用品、缺货、非法来源、受占用和当前原版不准使用的候选；选择不能消费、扣蓝或触发随机数。

## 回蓝与两份药品目录

实际持有耗蓝武器且下一次实际使用费用不足时，选恢复量最大的允许药品；同量按主包、槽、类型。费用 20 时蓝 19 触发，20 不触发；无须先按攻击或先失败。费用含耗蓝修正、副用及原版免费/跳过规则；工具、放置物、钓竿、纯弹药/辅助物不误作武器。即使最大蓝仍不够一次费用也不连续喝药。消费后同更新又耗蓝和原版魔力花同时工作时，共享本次真实使用边界防重复，不重置攻击、channel、选择或真实输入。

回血/回蓝目录分别根据已加载的当前原版定义完整生成，按实际 type 去重，按需准备并缓存。禁用按 type 保存，允许从未持有的合法药品；禁用和关闭立即阻止旧资格，重新允许须可靠保存。目录异常明确可见且允许主动重试，不永久缓存假空全集。

## 自动增益与跟随名单

允许名单保存 Item 类型，不保存 Buff 类型。可选项来自当前合法主包与可用虚空袋，要求 `buffType>0 && buffTime>0 && !summon`；不人为加只消费品限制。可刷新可用列表、添加、删除和清空，已选无库存条目仍可删除。

只补缺失，不续期、不提升已有食物等级；近战灌注、照明宠物、宠物、饱食四组互斥，仙灵等原版等价效果也视作已有。拒绝免疫、无空位等已知无效项，单项失败不阻塞其它缺失效果，也不对同一失败实物反复使用。每次操作都绑定一个真实来源，完成后重看下一项。瓶装蜂蜜按原版 QuickBuff 语义只取得增益，不宣称该链同时执行回血。

跟随添加仅在真实手动使用并确认效果成功后学入使用前 Item 类型，包括最后一件。跟随删除仅在真实图标取消入口后确认该效果消失，删除其对应允许项；自然到期、死亡、护士、自动恢复/增益/家具或快捷物品程序调用不学习。两项与自动增益开关独立，普通 AddBuff/DelBuff 不是人工意图。

## 护士与税收

护士需求为缺血或持续超过 60 Tick 的可治 Debuff，与回血门槛无关。报价、付款、治疗和移除负面状态走当前原版，钱包及四个人银行均可按原版付款找零。不能用 BuyItem 试余额，不设预算/费用上限，不伪造扣款回滚。已知无钱或无需求不开聊；报价未知与合法零费分开，当前原版零费用分支只给对白而不治疗，不能虚构免费治疗。

实际开聊前确认当前 NPC 实例、代次、正常距离与交互条件，保护鼠标持物、输入及已有对话。失败或结果未知保留原版对话和文字，保留失败原因；关窗不是重试许可。支付能力从不足到足够、需求/目标真实改变等对应事实才能重新准入；未确认副作用不按普通变化重放。成功仅关闭仍属于本次请求的对话，不能关闭后来的玩家对话。

税款为零不查 NPC。正余额时复核邻近税收官，通过原版生成世界金币/网络请求，保留原版增长和存档。领取调用完成（余额清零）与捡到金币是两件事；满包、延迟未到账不能补领。异常可能已产部分金币，因此当前未确认领取禁止重放，直至看到明确清零再有新税款。税收之后 G06 存钱可正常处理新金币，不能解除主动取出保护，也不把税收制造为普通物品票据。

## 组合、反馈与证据边界

对真实冲突按回血、回蓝、护士、家具、增益、收税排序；前项冷却/无需求不能饿死独立后项。消费来源、付款账户与找零空槽共享实际占用边界；未知结果保护对应资源。治疗之后护士必须观察新需求。关闭/移除、失焦、死亡及真实会话改变使旧资格退休，不能在新世界写回。

配置按本安装内共享自然域保存，复用可靠文件工具；坏格式、未来版本、外部变化或未知提交保护原件。普通开关/加载/保存/等待/无药/无税/已有 Buff 静默，不占状态行或预留高度；用途与持续错误在名称悬停，真实错误复用现有一次反馈，不建立通知中心。

单人、本地开服和普通原版多人客户端是目标，复用原版生命/魔力/Buff/库存与税收产币出口，不造每瓶药 ACK。服务器修改库存权威/规则的特殊情况不冒称支持。隔离原版调用、静态网络路径、所有者实机和真实联网分别报告；所有消费、扣款、领取用隔离数据验证。本任务到完整包安全安装结束，等待实测与外部审查，不自动合并/接受/发布或推进下一组。
