## Legacy 完整使用过程

旧版在游戏中按 F5，选择“笔记”页。没有笔记时只有 `+`；点击后追加一张“新笔记”卡片，不会自动进入编辑。双击标题改标题，Enter 提交；双击正文写多行，Enter 换行；两种编辑都可用 Esc 放弃当前草稿。一次只编辑一个字段。双击另一个字段、点击新增/悬挂/删除、切页或主动关闭 F5，会先尝试提交修改，失败通常阻止这一次后续动作并留住草稿。这里的“点击外部保存”只覆盖内容区的空白命中，不等于任意点击窗口外都会保存。

卡片可点“悬挂”，让**正文**作为独立便签留在游戏画面，F5 关闭后仍能看。鼠标移上去出现箭头、拖动把手和叉号；箭头改背景透明程度，把手移动便签，叉号只取消悬挂。阅读长正文可滚轮滚动；修改内容和删除仍回 F5。删除先点“删除”，再点同一篇的“确认”。已成功保存的内容和悬挂状态从磁盘恢复；未提交草稿没有单独恢复文件，异常退出不能保证保留。

以上是正常链路的静态提取。强制隐藏、正文读失败、跨文件保存和缓存刷新另有明确缺口，详见 NOTE-10、23～25，不能用“自动保存”概括为绝不丢失。

## 入口、列表与编辑

### NOTE-01：进入、可达性与归属（A；模式实效 C）

F5 第一行含“笔记”标签，内部沿用 `hotkeys` 页 ID 和 `note` 图标，实际接入卡片页。F5 记住最近选择的有效页面；默认页是增益，初次打开不保证直接看到笔记。F5 显示状态本身不作为笔记数据保存。

主菜单、全屏地图及部分原版菜单会限制或隐藏 F5；笔记没有另外要求某个功能主开关开启，也未见笔记专属的存活角色门。退出世界不删除笔记。默认存储按本地 OS 用户配置根共享，不按角色、世界或服务器分篇；这不表示多人共享或服务器同步。

注册表仍把笔记标成 `Implemented=false`、隐藏、计划中，测试也保留该断言；与此同时真实标签、绘制、命令、存储和测试均存在。保留冲突，不能只用注册标志断言完全缺失，也不能由静态接入宣称实机完整可用。证据 E01、E20；T01；H01。

### NOTE-02：新建、身份与顺序（A）

点击 `+`，先提交当前编辑；成功才新增。新笔记标题“新笔记”、正文空、未悬挂，追加在索引末尾；不自动选中、聚焦、滚到新卡片或进入编辑。失败不应被理解为新增成功，旧源码通常保持现有列表，但缓存刷新缺口见 NOTE-25。

允许多篇和重名。标题只是显示内容，独立 ID 才决定笔记身份及正文文件；改标题不改 ID。没有“当前选中笔记”的独立集合模型，操作按命中卡片执行。保存和悬挂不重排；删除移除对应条目。卡片按顺序放到当前较短的一列，视觉上不是固定逐行左右排列。

已检查页面、命令路由、模型、存储及对应测试，未发现笔记搜索、手动排序、整篇复制按钮、批量选择/删除入口；编辑中的文本剪贴板另见 NOTE-06。证据 E02、E20、E21；T02、T04。

### NOTE-03：卡片、空内容与布局（A；极端尺寸 C）

内容宽度小于 360 个 F5 布局单位时一列，否则两列。`+` 与卡片一起参加页面滚动。标题在上，右侧是“悬挂/已悬挂”和“删除/确认”；正文在独立视口内。标题显示会省略，正在编辑的长标题也可能被省略，未见标题水平滚动。

正文为空或纯空白时显示灰色“双击进入编辑”；非空正文为浅蓝色，标题偏暖色，编辑正文偏黄色。正文行高 24、绘制尺度 0.76，标题行高 24、尺度 0.86。卡片至少留两行正文；正文很长时卡片不无限增高，通常上限为当前视口高度一半，但最小卡高 119 优先，不能保证极小视口仍满足一半上限。

这是旧版可见布局信息，不是要求 R 复制所有颜色数值。正文内部滚动、整页滚动与光标规则见 NOTE-07。证据 E03；T03；H01、H02。

### NOTE-04：进入编辑、单击和取消（A）

同一标题或正文命中元素，两次左键按下间隔不超过 500 ms，横纵距离各不超过 6 个 F5 基础布局单位，判作双击。单击非当前编辑字段不进入编辑，**也不因此提交另一篇的草稿**。双击不同字段先尝试提交旧编辑，成功才打开新字段；失败留在旧字段。

一次只能编辑一个标题或一篇正文。已在编辑的字段单击可移动光标。Esc 取消当前编辑，回到缓存中的已加载/已保存内容；不是文件回滚，也不能修复已经部分提交的磁盘写入。没有独立的自动草稿文件。证据 E04、E08；T05、T06。

### NOTE-05：文本与基本按键（A 主体；字符边界 B/C）

| 操作或内容 | 旧实现语义 |
| --- | --- |
| 标题 Enter / 正文 Enter | 标题提交，正文在光标插入换行；不是统一的保存键 |
| Esc | 取消当前字段编辑；不等于取消所有删除确认或关闭便签 |
| Left / Right、Delete | 按 .NET UTF-16 单元移动或删除；没有保证按完整 emoji/组合字符处理 |
| Up / Down、Home / End | 以正文的硬换行和列位置计算，不以自动折行后的视觉行计算 |
| Backspace | 借用宿主输入结果识别尾部删除，再尝试作用于自有光标；普通单单元删除有对应处理，多单元删除不能据此保证正确 |
| 按住导航键 | 自有方向/Home/End/Delete 采用按下沿，未实现自身连续重复；Backspace 重复来自宿主 |
| 换行、制表符 | 聚焦/原生输入归一化 CRLF、CR 为 LF，tab 变一个空格；标题输入去掉 LF |
| 标题上限 | 编辑和存储均为 80 个 UTF-16 单元；非 80 字节，也非保证 80 个用户感知字符。超长截掉后缀，在中间插入也可能挤掉尾文 |
| 空标题 | 保存层去首尾空白、换行改空格；空/纯空白回“新笔记”。编辑取消不会写入这个默认值 |
| 正文上限 | 正文接入传入 0 表示不设该输入上限，存储亦未见显式数量/体积上限；不代表任意大文本都可用 |

光标用闪烁的竖线表示，500 ms 切换。中文已提交文本和多行字符串有测试断言；没有选区锚点、拖拽文本选择或自有 Ctrl+A、撤销/重做历史。上述 UTF-16 操作可能拆开代理对、组合字符；本轮是静态风险，未运行复现。证据 E05、E06、E21；T06。

### NOTE-06：剪贴板、原生输入法与文本绘制（C；保留必要输入能力）

旧编辑器把整个草稿传给 Terraria 原生文本输入，再将新增差量尽量插到自有光标。它不是一个具备完整选区的标准记事本控件。

本地 **Terraria 1.4.5.7** 参考中：Ctrl+C/Ctrl+Insert 复制传入整段；Ctrl+X/Shift+Delete 剪切整段；Ctrl+V/Shift+Insert 粘贴；Ctrl+Z 清空整段，**不是撤销**。结合旧编辑器调用可得到该版本宿主下的条件性行为，不能直接宣称当前实际游戏也完全如此。正文允许多行剪贴板。复杂 Unicode、宿主删除多个字符与自有光标的组合还需直接观察或目标版本证据。

有原生 IME 启用、组合文字预览和候选面板调用；组合预览暂不进入草稿，候选框锚点按光标位置提供。旧编辑器自己的 Enter/Esc 处理未再显式检查组合输入状态，依赖宿主标志；高 UI scale 下候选位置、Enter 是否只确认候选、Esc 是否只取消组合输入均未实机验证。原生输入调用失败时本次更新提前返回，不能保证该帧提交/取消仍可用。内部诊断状态不等于页面显示了错误说明。

正文虽然存为纯文本，绘制却可进入 Terraria 的 `ChatManager.DrawColorCodedStringWithShadow` 字符串路径；.7 原件该路径会按内容决定解析聊天标签。因此“没有富文本编辑器”不能扩大为“所有方括号标签一定原样绘制”，也不能反过来承诺 Markdown、附件或完整富文本支持。R 已选择字面纯文本及基本中文/剪贴板能力，具体目标见下文 Q4/Q5；这不改变上述旧版事实和版本限制。证据 E06、E07、R01、R02；T06；H03。

### NOTE-07：换行、正文滚动与光标（A；视觉行导航及手动滚动 C）

正文按宽自动折行，也保留手动换行；自动折行不写入正文文件。预览正文超高时用独立视口和滚轮，没有独立正文滚动条；整页滚动条属于外层页面。F5 中滚轮优先尝试移动命中的正文，量为 `-rawDelta/3`，标准向下 `-120` 对应向下 40 个 F5 基础布局单位，极小非零 delta 用正负 40 回退；正文已经不能继续移动时可交给整页滚动。悬挂便签的滚轮隔离规则不同，见 NOTE-16。

编辑中按光标位置自动调正文滚动，以便看见光标；该检查在绘制时反复执行。因此用户把视口滚离光标后可能被拉回，不应无证据声称能自由停留远处阅读。滚动偏移是进程内状态，未写入笔记文件；重新开始编辑会以当前光标可见性再次调整。上下键按硬换行移动，长段落的视觉行导航不等同普通编辑器。证据 E03～E05；T03、T06。

## 提交、切换、删除与异常

### NOTE-08：草稿、提交成功与失败（A 保护主体；假成功 B）

编辑器记录进入时的标题/正文，与草稿比较。未改动就结束编辑，不写盘；有改动则把当前标题和正文交给保存层，成功后结束编辑，失败保留草稿和焦点。改标题也会带上缓存中的正文一起保存。

新增、悬挂、删除按钮均先尝试提交当前编辑，即使按钮属于另一篇。提交失败便结束**这一次命令**，不会继续原按钮动作；没有替用户保存一条“稍后自动继续新增/删除”的待办动作。用户可重试或 Esc 放弃草稿。原始按键命令队列仍会顺序处理其他已排队命令，失败不是全局停队门。

旧页面没有独立保存按钮、清晰的未保存标识或失败原因绘制；保存错误主要进入内部结果和日志。“留住编辑态”不等于普通用户明白为何不能切换。缓存刷新失败也可能使上层成功与显示不一致，见 NOTE-25。证据 E08、E09、E24；T04～T06。

### NOTE-09：点击外部、切页和主动关 F5（A，限定触发）

| 条件 → 用户动作 | 旧结果及失败边界 |
| --- | --- |
| 正在编辑 → 点内容视口空白 | 空白 fallback 命中尝试提交；卡片/按钮命中优先，不能概括成任意“点外面” |
| 正在编辑 → 点 F5 外、标题栏或滚动条 | 没有通用外部点击提交承诺；标题栏等会被自己的命中规则截走 |
| 正在编辑 → 单击另一个标题/正文 | 忽略该字段的进入编辑请求，不自动提交旧稿；双击才走切换提交 |
| 正在编辑 → 切 F5 页签 | 提交失败保持原页；成功才清理焦点并切页 |
| 正在编辑 → 主动 F5 开关/设置隐藏 | 提交失败保留可见 F5；成功才关闭。再次打开使用已保存内容 |

正在编辑也计入 F5 活动交互，所以鼠标移到窗口外仍可能捕获游戏鼠标，却不触发保存；不能把“外面不保存”误写成“外面必然可操作游戏”。证据 E04、E09、E10；T05。

### NOTE-10：强制隐藏、失焦、退出和连续动作（B/C）

主菜单/全屏地图等强制隐藏路径先把 F5 设为不可见，再重置交互并尝试保存；这里未处理保存失败返回值。若失败，草稿可能仍在内存，但界面已经隐藏；不能将主动关闭的“失败不关窗”保证套用到强制隐藏。失焦输入守卫也会尝试重置/保存，失败可能在后续回调重复尝试。

编辑焦点通过共享输入标志和自己的输入接管标记维持。正常结束会释放自己的标记；共享布尔标志直接写值，并非对所有其他输入者的完整租约。强制隐藏失败、失焦后重新聚焦、同时聊天/其他输入是否残留阻挡，需要目标版本观察。

已搜索笔记相关保存调用及进程退出事件，未见专门的进程退出草稿刷新入口。正常离开世界只有在相关回调执行时才走隐藏/保存；直接退出、崩溃或断电不保证保存未提交草稿。已落盘笔记不随退出世界删除。

命令在游戏线程顺序执行，保存同步发生，未见“正在保存”编辑界面或异步保存队列。输入命令队列容量 32，满时丢最旧项；一次失败并不自动撤销其他已排队命令。不能据此宣称连续快速操作、长 I/O 或进程中断安全。证据 E09～E11、E23；H01 的概括须受此限制。

### NOTE-11：删除及确认期限（A 二段删除；确认生命周期 B）

点击“删除”先将该篇按钮变为“确认”，再次点击同篇才删除。第一次点击前也先提交当前草稿；保存失败不进入确认。删除已悬挂笔记会在成功保存及缓存刷新后移除便签。没有回收站或撤销删除入口。

确认没有超时，也没有独立取消按钮。点击另一篇“删除”会换到另一篇；成功新增、开始不同编辑、成功保存 dirty 草稿、成功删除会清理确认。**切页、关 F5、普通 Esc 并不普遍清理确认**，下次打开可能仍是“确认”。不能把 Esc 取消编辑写成取消删除确认。

删除失败通常保留卡片和确认状态，用户可再试；底层补偿恢复与缓存刷新仍有限制，见 NOTE-24、25。R 已接受二段确认及离开笔记页/关闭 F5/明确取消时失效的差异，见下文 Q3；不把新目标倒写为旧版已经具有该保护。证据 E02、E08、E12、E23；T04、T07。

## 悬挂便签与输入隔离

### NOTE-12：悬挂、更新、取消与再次悬挂（A）

在 F5 点击“悬挂”先提交编辑，再保存悬挂状态；允许多篇同时悬挂。卡片变“已悬挂”，再点仍是维持悬挂，**不是取消开关**。悬挂只读已保存快照的正文，未提交草稿不直接显示；编辑成功后更新，删除成功后消失。

便签右侧 `x` 只取消悬挂，不删除正文/笔记，也不二次确认。取消后再次从 F5 悬挂，会重新选默认位置、尺寸和不透明度；不是恢复上次设置。旧记录明确声称此默认重建，不需要把它误补成“记住上次位置”。证据 E13、E14、E22；T04、T08；H01、H04。

### NOTE-13：便签内容、工具栏与初始位置（A 主体；初始参照 C）

便签只显示正文，**不显示标题**，不提供编辑或删除控件。空白正文是空行，没有 F5 的“双击进入编辑”提示。正文自动折行、视口裁剪，不逐行加省略号；字体尺度 1.20、行高 36，保持与 F5 卡片不同的阅读尺寸。

默认宽 280、高 304（上下各 8 留白加八行正文）。初始算法意图是放在参照矩形右侧间隔 12，放不下改左侧，Y 随参照顶部；无有效参照时从屏幕 `(12,12)` 起。但实际调用直接把 F5 基础布局矩形传给未缩放的便签算法，没有转换，缩放时不能保证位置紧邻可见 F5 或与其顶部齐平；这是静态坐标风险，实效保持 C。恢复时按屏幕夹取，并有限避让其他便签；最多尝试 32 次、每次右下移动 28，不能保证任意数量不重叠。

鼠标在便签或工具栏上时显示 `<`、`>`、中间拖动把手、`x`。工具栏通常在框上方间隔 4，靠屏幕顶端时移入框顶；出现工具栏不改变正文视口或滚动范围。证据 E14、E15；T08；H01、H04。

### NOTE-14：透明度的方向和影响（A）

底层保存的是**不透明度**，默认 0，即用户说的“透明度 100”。`<` 减少不透明度 5，让背景更透明；`>` 增加 5，让背景更明显；范围 0～100，到边界不循环、不保存同值。按下沿触发，不是按住持续调整。

背景、边框及按钮背景随该值变化，正文、按钮文字、拖动把手不随之消失。不透明度 100 表示使用各表面的基准透明程度，不保证每个像素 alpha 都等于 255。旧 toolbar 画面只有箭头和叉号等，未见“透明度 100”的实时数字读数；历史说明中的数字是解释口径。**全透明仍有命中区域，仍可拦截游戏点击。** 证据 E15、E16；T08；H01、H04。

### NOTE-15：移动、尺寸、边缘与重叠（A 主体；生命周期 C）

只有把手能启动拖动，正文不能当整块拖动把手。按住时保留鼠标相对位置，越出便签仍捕获；拖动时不同时执行箭头、叉号或正文滚动。松开提交一次位置，移动中不持续写盘。

未发现用户调整大小的控件；存储有宽高字段不等于提供 resize 功能。恢复宽限制 220～360，高 120～360，并按当前屏幕夹取；极小屏幕仍有最小尺寸，不能保证完整放得下。夹取/避让本身不保存，以后拖动松开、箭头或叉号会连同当前显示矩形提交。

多个便签按笔记快照顺序绘制，逆序判定命中，后画的优先；点击不会自动置顶。可同时出现多个 hover 工具栏。避让不算工具栏占用；当前拖动篇暂不自动避让，拖动期间可重叠，松开后每次普通构帧又会尝试避让，显示位置可能与刚保存的位置不同。因此没有保证可永久手动叠放，有限避让也仍可能无法消除重叠。

拖动松开先释放拖动状态，再保存；失败后下一帧可回旧缓存位置，没有可继续提交的新位置草稿或普通用户错误提示。打开地图/菜单的早退未清旧拖动，恢复后是否继续移动/提交是静态风险，未实机复现。证据 E14～E17；T08。

### NOTE-16：便签滚轮与热栏（A；历史诊断冲突 C）

仅命中正文视口才滚动正文，滚动量为 `-rawDelta/3`；标准向下滚轮 `-120` 对应向下 40 个未缩放屏幕单位，极小非零 delta 用正负 40 回退。到边界夹停；滚动不落盘，没有可拖拽滚动条入口。

命中便签主体、工具栏和拖动范围都会隔离热栏滚轮，即使正文短或已到边界也不能把滚轮交给游戏切热栏。只有正文可移动时才有实际阅读位置变化，这与 F5 内层到边界可交整页不同。

H01 声称长文到边界不记假的 Wheel 成功；当前源码只要正文可滚便设置消费标记，仍可能记录 `Ui.Notes.Wheel / Succeeded`，即使本次位置没动。现有测试只验证 toolbar 和短正文，未覆盖长文边界。此为诊断语义冲突，不作为新版用户能力要求。证据 E16、E18；T08。

### NOTE-17：显示条件、坐标和相邻输入（A 主体；共存 C）

独立便签在非主菜单、非全屏地图时可显示，F5 关闭仍工作；已读入口及上游没有笔记全局 Enabled、聊天或模态统一门。失焦检查只限制新按键/滚轮，不是聊天协调保证。F5 的原版菜单门不能套用到独立便签。

便签内部使用未缩放的游戏客户区屏幕坐标：优先 OS 客户区鼠标，失败才回退 Terraria 原始鼠标；便签绘制、命中、拖动及拖动位置保存按同一未缩放域，不除以 UI scale。F5 本身使用自己的缩放布局域，初次悬挂却直接传入其基础布局矩形，存在 NOTE-13 的参照转换缺口，不能把内部同域扩大为全链路对齐。改变分辨率会重新夹取便签位置；窗口模式、多显示器、所有极端缩放未实机验证。

鼠标命中主体/toolbar 或正在拖动时，便签优先于 F5 主窗，消费游戏鼠标键并压制游戏鼠标提示；拖动保留左键 held，其他鼠标键仍消费。范围外没有便签造成的全屏捕获；但 F5 编辑态另有 NOTE-09 的捕获。便签阅读态不接管文本键盘，不能写成阻断全部游戏操作。

独立图层排在 F5 dispatcher 后，使用 `InterfaceScaleType.None`。普通鼠标按下在前置和后置协调，延后的 toolbar 点击会重新确认同篇同控件并只重放一次；测试 fake 验证了这些路径。真实聊天、其他弹层、死亡、暂停、断线重连、多人及遮挡关系仍 C。证据 E17～E19；T08。

### NOTE-18：哪些状态能恢复（A 持久状态；残留 C）

| 状态 | 旧保存/恢复范围 |
| --- | --- |
| 标题、正文、顺序、ID、创建/更新时间 | 文件保存；重启重新读入，不按世界切换清除 |
| 悬挂开关、位置、尺寸、不透明度 | 索引保存；重新构帧按当前屏幕恢复，存在读写失败限制 |
| 草稿、字段焦点、删除确认、拖动进行中 | 仅进程内；没有恢复文件，不能承诺异常退出后继续 |
| F5 正文/便签正文滚动 | 不落盘；二者是不同内存字典，不保证切换后的清理一致 |

便签滚动字典和拖动状态的整体重置只见测试入口；取消悬挂清理的是另一份 F5 滚动字典。因此同进程重新悬挂可能沿用旧阅读位置，删除后的便签滚动条目也可能残留。主菜单/地图早退清鼠标沿与待重放按钮，却不清拖动。不能把这些残留当成有意的用户状态恢复合同。证据 E13、E17、E22；T08。

## 文件、内容安全与静态成本

### NOTE-19：用户能看到的反馈（A 文案；失败提示 B）

主要文案为“笔记”、`+`、“新笔记”、“双击进入编辑”、“悬挂/已悬挂”、“删除/确认”，便签工具为 `<`、`>`、`x` 和把手。没有独立的已保存通知、保存按钮、dirty 提示、读取失败卡片或便签错误消息绘制。

读写结果、失败原因和内部输入状态可进入诊断；正文读错日志按路径节流 30 秒，绘制异常日志有 10 秒节流。笔记操作诊断不直接记录标题/正文，但异常消息可能带路径，不能承诺日志不含个人路径。必要错误反馈与正常配置自动保存静默是不同语义。证据 E03、E06、E15、E24；T04～T08。

### NOTE-20：真实数据根与共享范围（A 自然归属；R 路径已另行决定）

Legacy 默认从系统 `MyDocuments` 已知文件夹取得用户文档根，再接 `My Games/Terraria/JueMing-Z/config/notes/`；不按当前工作目录推导，也没有角色/世界/服务器/游戏安装 ID。目录构造时转为绝对路径并固定。

索引为 `index.json`，每篇正文为 `<noteId>.txt`。存储构造器可接受别的目录，但已读生产入口用默认构造器，不能据此说有用户选择目录 UI。同 OS 用户的多安装/多进程若用同一默认根会碰到同一批笔记；没有云或网络共享机制。R 已决定使用确认过的 `Terraria.exe` 同级 `JueMingRData`，不继承这个旧根。证据 E20；T02；[配置设计](../设计/配置持久化与用户数据布局.md)。

### NOTE-21：格式与影响行为的字段（A 解释旧事实；非 R schema）

| 旧字段/约束 | 含义、默认与注意点 |
| --- | --- |
| `SchemaVersion`、`Notes` | 写出版本 1；列表本身承载顺序。读取未检查版本；见 NOTE-23 |
| `NoteId` | 新建为 `note-` 加 UTC 毫秒时间及 12 位 GUID 片段；标题不参与。读取允许 trim 后 1～80 个 ASCII 字母/数字/`-`/`_`，大小写无关查找/去重 |
| `Title` | 默认“新笔记”，去首尾空白/处理换行后截为 80 个 UTF-16 单元；允许重名 |
| `CreatedUtc`、`UpdatedUtc`、`BodyUpdatedUtc` | UTC round-trip 字符串；正文/标题保存都更新后两项；悬挂操作只更新 `UpdatedUtc`。坏时间回当下，早于创建的时间抬至创建时间，未保留错误标记 |
| `Pinned`、`PinnedX/Y/Width/Height`、`OpacityPercent` | 开关、矩形、不透明度。新建 false/坐标尺寸 0/不透明度 0；悬挂时另算初始矩形。负宽高夹 0、不透明度夹 0～100，坐标未在存储层夹屏幕，未见专门的有限浮点数校验 |
| `BodyLength` | 正文 UTF-16 `.Length` 元数据；正文实际在独立 txt，读取快照重算长度，不按索引长度截断/校验。不是字节数或内容哈希 |
| 正文编码 | 写 UTF-8 无 BOM，读 UTF-8。没有附件/Markdown 结构字段；显示解析边界另见 NOTE-06 |

正文内容只存在 txt，索引重复保存正文长度/更新时间等摘要；没有跨文件内容哈希验证。缓存 `Revision` 仅进程内递增，磁盘无该版本字段，不能拿它当外部写入冲突保护。证据 E20、E21、E24；T02、T07。

### NOTE-22：正常保存次序（A 意图；可靠性限制 B）

新建/修改先读现有索引，构造候选，再准备正文和索引临时文件，**先提交正文，再提交索引**；仅改标题也重写正文并更新正文时间。改悬挂、位置或透明度只改索引，随后读正文及刷新缓存。创建时间、身份和原顺序不因改标题改变。

删除先移除候选索引条目，备份并删除正文，再提交新索引；索引失败尝试恢复正文。正文原本缺失仍允许删索引。普通失败不会有意移除缓存卡片，但无法承诺底层所有失败都恢复原样。

成功写操作之后同步全量重读索引和全部正文，不能把 store 返回成功直接等同屏幕和磁盘已一致。证据 E22～E24；T02、T04、T07、T08。

### NOTE-23：加载异常、孤立文件和未知版本（B；事故发生 C）

| 输入状态 | 旧实现结果与风险 |
| --- | --- |
| 索引不存在 | 成功空列表，单纯读取不创建文件 |
| 索引读取/JSON 解析抛异常 | 返回读取失败，不覆盖该索引；增删改也先读索引，因此同次读失败阻止写入 |
| 根对象为 null、`Notes=null` | 按成功空索引处理，不等于受保护的坏索引；下次操作可能写出新的列表 |
| ID 无效/为空/重复 | 静默过滤，重复保留第一个，大小写无关；下一次成功写会写回过滤后的整个索引 |
| 未来 `SchemaVersion` / 未知字段 | 未见拒绝门或未知字段保留；后续会写回版本 1 模型，存在降级覆盖风险 |
| 孤立 txt | 不扫描目录恢复，不显示；常规读取也未见自动删除孤立正文 |
| 正文缺失 | 当空正文成功加载，无缺失标记 |
| 正文读异常 | 当空正文成功加载，只记节流日志；整体快照仍成功 |
| 正文长度与索引不同 | 按读到的正文重算，不判定冲突，时间仍来自索引 |

尤其需要保护的静态链：**正文暂时读错 → 缓存变空 → 用户只修改标题 → 保存层把缓存空正文重写到原文件**。这条可达代码链说明存在内容覆盖风险，未证明用户实际发生过该事故。新版“读失败不能用空白覆盖原件”已经是有效要求，不需要再向所有者申请是否保护。

首次刷新失败，UI 仍标成已加载；普通重新显示不自动重试。成功操作会再刷新，不能简单说只有重启才能恢复。缺文件、真空白、读取失败和未知版本必须在后续设计中具有可区分的安全语义，具体 UI 与恢复方式待定。证据 E08、E20、E23、E24；T07 的破损 JSON 断言不覆盖以上所有情况。

### NOTE-24：备份、部分提交与外部修改（B/C）

旧单文件写用同目录随机 `.tmp-<GUID>`，写入后 flush；已有目标先做随机 `.bak-<GUID>` 再 replace，新文件 move。提交遇到 `IOException` 最多四次尝试，中间等 15/30/45 ms；不是整体 I/O 超时保证。

备份是操作内补偿材料，不是用户可依赖的历史版本或回收站。正文已提交而索引失败时尝试回滚；回滚异常会被吞掉，随后仍尝试清理备份。删除补偿也有类似边界。进程在两文件之间中断、回滚本身失败、临时文件准备中途失败，可能留下不一致或残留；未见启动恢复扫描。测试注入正常的提交失败并成功回滚，不能证明这些更深失败安全。

没有文件监视、mtime/hash 比较、跨进程锁或整个读改写事务锁。缓存锁只保护内存交换。外部改文或两个进程可互相覆盖；改标题尤其可能将旧缓存正文写回。新版本应防止静默覆盖、假成功和默认数据污染，但本轮不指定线程模型、文件数量或事务方案。证据 E22～E24；T07。

### NOTE-25：已写入、已刷新与用户看到的成功（B）

新增/保存/删除/悬挂的 store 成功后，cache 会调用刷新，却忽略刷新返回值；刷新失败可保留旧快照，上层仍报告原操作成功。这可能出现“已经写盘但界面还是旧内容/旧便签”；若刷新只是某份正文读错，还会以成功方式放入空正文。

所以普通保存失败的草稿保留测试，不能扩成全链路永不假成功。需要分别表达提交状态、当前内容是否可信、草稿是否仍在、下一步怎样重试，避免自动执行依赖不确定成功的动作。这里是后续设计必须解决的用户结果，不是新增通用状态框架授权。证据 E08、E24；T04～T08 未覆盖刷新失败。

### NOTE-26：生命周期、资源与静态工作量（C 性能实效）

首次取快照可能触发读盘，且不一定等用户进入笔记页；便签输入/绘制路径也取快照。F5 关闭但有悬挂仍读鼠标、构帧、命中、折行和绘制；没有悬挂也会先取快照、扫描笔记后早退。不能写“关闭即零成本”或“Draw 绝不读写”：标题 Enter 等编辑更新发生在绘制调用链，可能同步保存。

缓存 getter 不读盘，但每次复制全部笔记和悬挂对象。成功写操作同步全量重读全部正文。F5 有按状态/视口缓存的布局，但活动正文仍反复折行和保持光标可见；可见卡片反复查找笔记也随总数增长。独立便签在 Update 前置、PlayerInput 后置、Draw、热栏 Hook 等入口都可能重建 frame，未见按正文版本/宽度复用整帧；逐字符增长子串测宽、全部折行列表和有限避让都随长文/数量增加工作。

悬挂命中诊断默认开启，以签名和 250 ms 合并重复调用；签名字典未见生产容量/清理门。合并事件不消除前面的构帧和字符串工作。读取错误与绘制异常日志节流不等于磁盘重试节流。

便签使用共享 renderer，不自行创建独立 SpriteBatch/纹理；资源未就绪可跳过绘制，资源异常可触发共享资源失效。但输入没有同等可绘制门，暂时不可见而仍捕获是待验证风险；共享资源完整退出恢复不在本专项已证明范围。所有这些仅是静态形态，未测帧率、卡顿、内存总量或性能改善，不要求照抄旧缓存。证据 E03、E05、E17～E19、E24～E26；T07、T08；H01 的绘制概括受此纠正。

### Q1～Q7 的正式决定

1. **Q1：完整主体。** 接受上述多篇卡片与悬挂能力，保留再次悬挂重置默认位置、尺寸与背景透明度，以及默认背景全透明等候选初始行为；不增加自由调整尺寸、搜索等未提取能力。新版“全局”限同一 `JueMingRData` 数据根，跨角色/世界使用，不暗示不同安装或电脑自动共享。视觉和操作体验可在后续实机中受控调整，但不能借微调削弱内容安全或删减完整范围。
2. **Q2：保存交互。** 保留 NOTE-08～09 限定的原提交触发，增加明确保存入口、未保存标识和必要失败说明；强制隐藏后保留可恢复的会话草稿，返回页面能够继续处理。正常保存不刷“正在保存/已保存”等成功弹出通知；必要编辑状态、失败反馈和原件保护仍保留。不增加跨崩溃草稿恢复系统，内存留稿不等于可靠持久化。
3. **Q3：删除确认。** 离开笔记页、关闭 F5 或明确取消时确认失效，重新进入须重新确认；同一次删除失败可以保留确认供重试。叉号只取消悬挂，不删除正文；临时隐藏或失败不能变成静默删除。
4. **Q4：编辑语义。** 标题保持 80 个完整用户可见字符的规模，超限明确反馈或阻止新增，不静默截掉既有尾部；移动与删除不拆坏字符，相关上下/Home/End 等导航按视觉阅读行处理。没有撤销能力时 Ctrl+Z 不执行破坏性清空；保留基本整段复制/剪切和光标处粘贴，不承诺标准文本选区、完整撤销或编辑历史。中文输入、候选确认和游戏输入隔离是实现目标，不能把确认/取消组合输入误作整篇提交/取消。正文规模上限由后续设计与证据决定，不任意指定或套用小型配置文件限制。
5. **Q5：字面纯文本。** 中文、标点、方括号及其他正文按输入文本显示，不自动解释 Terraria 聊天颜色或图标标签。这是明确选择的新版行为差异，可能改变依赖旧聊天标签效果的内容显示，不声称历史事实已经证明或无差异平替。本次不做富文本、Markdown 或标签兼容系统。
6. **Q6：便签共存。** 保持独立于 F5 缩放的阅读尺寸，F5 关闭后仍可显示；主菜单/全屏地图隐藏并结束拖动，失焦释放输入，聊天、原版弹层或其他明确输入者拥有输入时便签不抢操作，并保持必要可恢复状态。不可见却继续拦截输入不属于正常结果；背景透明与可操作性分开，按 NOTE-14 的背景语义处理，不使正文与工具文字跟随背景一起消失。目标覆盖单人和多人客户端本地自用，不向其他玩家同步笔记；目标覆盖不等于已验证支持，后续按实际场景建立证据。
7. **Q7：首轮暂缓旧数据导入。** 首轮实现不含导入器、自动迁移、旧索引修复、目录扫描或真实旧正文转换。这不是永久放弃旧笔记内容；以后单独决定是否开发手动导入、优先级和范围，本次不承诺日期或优先级、不新建导入任务、不授权导入，也不让未来导入决定继续阻塞需求确认收口。

在 R 候选中按 F5 → 笔记，用 `+` 新建多篇，允许重名，不自动进入编辑。双击标题或正文编辑；标题 Enter 保存并结束，正文 Enter 换行，Esc 或“取消”放弃当前字段草稿；“保存”保存后仍可编辑。单击另一字段不切换，双击另一字段、内容空白、新建/悬挂/删除、切页或主动 F5 关闭先保存；失败保留草稿且不继续后续动作。删除必须再次点同篇“确认”，也可“取消删除”。

“悬挂”显示已保存正文，关闭 F5 后仍可阅读。悬停工具栏的把手拖动，`<`/`>` 调背景不透明度，`×` 只取消悬挂；默认背景透明，文字仍显示。重复“已悬挂”保留当前位置和透明度，取消后再悬挂才重新采用默认。鼠标滚轮只作用于唯一命中的正文/便签；地图、菜单、聊天和失焦等强制隐藏释放输入，当前会话草稿保留。只接受本地客户端 netMode 0/1，群系仍保留单人门；多人实机未由该门或模拟测试证明。

文件为已验证游戏目录内 `JueMingRData/notes/notes.json`（UTF-8、schema 1），同安装共享，不按角色或服务器分篇，不联网同步。标题 80 个编辑字素，正文每篇最多 1,048,576 UTF-16 单位、最多 1,024 篇、整份编码文件最多 16 MiB；单个异常组合字素另有 1,024 UTF-16 单位保护。超限输入整次拒绝，原文不裁剪；读入不可靠或超限文件时整份保护。长文可能显示“正在排版”，正文和保存不因此被截断。

异常先看 F5 笔记页；便签操作保存失败也显示查看原因的提示。提交未确认时停止写入、显示最后可信内容；退出所有同安装游戏，保留完整 notes 目录中的正式文件及 `.bak` / `.tmp` 后检查恢复，不盲目删掉唯一副本。尚未提交草稿不保证跨强制结束恢复，正常保存不刷成功通知。安装、恢复程序和重置配置均保留 notes。精确职责及恢复保证见[笔记实现设计](../设计/笔记功能实现设计.md)。
