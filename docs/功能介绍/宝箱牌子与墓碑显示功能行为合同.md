## 1. 调查时的一页用户摘要

三项都是把世界物体的文字直接显示出来：宝箱显示容器名称，牌子显示书写内容，墓碑显示墓碑正文。它们不负责打开、编辑、取物、存物或删除物体。

| 旧功能与模式 | 有有效金属探测能力 | 无能力，或旧代码读不到能力 | 需要本玩家开过记录吗 |
| --- | --- | --- | --- |
| 宝箱“始终” `Always` | 扫描屏幕附近容器并显示名称，仍受距离、可读性、原点和绘制限制 | **不取宝箱标签、不扫描该模式目标、不绘制**；即使有记录也不显示 | 不需要；有无记录采用同一查名规则 |
| 宝箱“开过” `Opened` | 按当前角色×世界的记录坐标选候选 | **同样可以显示**，没有金属探测门 | 需要；正在打开的世界箱可能在本次绘制分派前刚登记 |
| 宝箱“关闭” `Off` | 不执行本项标签查询/绘制 | 同左 | 不显示；记录工作是否还跑，取决于共享外层是否被其它世界显示开启 |
| 牌子、墓碑“全部／前几行／前几字” | 读取客户端已有正文 | 同样读取；**两项都没有金属探测门** | 无关，不要求鼠标悬停或打开编辑界面 |

这里的“有效能力”是原版已计算的 `Player.accOreFinder`，不是“是否装备某一个物品”。当前 .8 的携带、合成信息饰品及符合原版条件的队友共享会进入此状态；隐藏原版信息文字不是能力失效。旧帮助方法把 false 和读取失败都返回 false，不能据此解释为“玩家没装备探测器”。见第 3 节及 V8-01。

**显示与记忆是两条不同职责。** 旧记录属于角色×世界，读取本地玩家非负 `chest` 槽及其世界坐标；不是右键意图，也不单独证明用户手动打开或服务端全部数据已就绪。记录入口却挂在共享 Draw：其它显名或五项世界高亮开启，也可能带动箱子导入、记录和保存；所有共享世界显示都关掉时，这个入口不运行。因此旧“关闭仍记”是条件性的，旧记录也不是完整开箱历史。

**已查实的成本包括**：始终模式分步读附近 tile、发布时集中查名；开过模式刷新时整张 `Main.chest` 名称表与当前角色×世界全部记录；逐候选存在性复核、排序、字体度量；记录冷加载、哈希、去重、同步保存及共享 Draw 的附带工作。没有发现本基线为了名称克隆整箱物品；核对的原版 .6/.7/.8 `FindChest` 都是坐标字典查询。所有者“宝箱是性能大户”是明确风险反馈，尚不能归因为某个方法的 FPS 根因。第 5 节逐项列出事实、历史材料和剩余疑点。

**所有者已确认三项同批交付**，复用 R 现有世界层、字体/样式副窗、偏好与公共快捷键，独立补齐宝箱记录/身份。内部可先牌子/墓碑后宝箱，但不停在半批再次等待开发授权。新版采用结果和验收条件见第7节；旧数据不导入。

## 2. 三条真实行为链与操作差异

证据编号在第 8 节固定版本、路径和行段。下表沿真实消费者展开；注册中的 `RequiredActions=None` 不证明整个外围没有文件副作用。

| 功能 | 实际链路 | 独立内容与状态 |
| --- | --- | --- |
| 宝箱显名 | Feature 注册/更多信息页 → 模式 setter 或热键 → `InformationWorldOverlay.DrawInformationInterfaceLayer` → `DrawWorldOverlay` 构造 FullRecord、导入、登记 → `DrawChestLabels` 的 Off/Always 能力门 → `InformationChestLabelService` → tile/名称服务 → 排序、当前坐标过滤 → `InformationWorldLabelRenderer` | 三模式，独立颜色/字号；开过事实由 `PlayerWorldBehaviorStore` 保存。Z01–Z07 |
| 牌子显示 | 注册/更多信息页 → `All/Lines/Characters/Off` 与参数 → 同一外层 → `DrawSignTextLabels` → `GetSignLabels` → 正文布局缓存 → `DrawSignTextBlock`/`UiTextRenderer` | 非墓碑的 `tileSign` 类，独立模式、行数、字数、颜色/字号。Z08–Z10 |
| 墓碑显示 | 注册/更多信息页 → 自己的四模式与参数 → 同一外层 → `DrawTombstoneTextLabels` → `GetTombstoneLabels` → 同一布局服务和最终文本绘制 | `Tombstones=85`，独立于牌子；共享表不代表共享开关或样式。Z08–Z10 |

三项初次默认关闭；旧页面顺序为宝箱、牌子、墓碑。宝箱的 `Known`、`Open` 只是 `Opened` 的旧格式别名，不是额外按钮。旧 enabled 布尔值与模式兼容归一化也会影响异常/旧格式值；正常 UI 关闭同时把 enabled 设 false，不能用人为矛盾字段组合描述普通玩家的第四模式。

牌子与墓碑都实际支持四模式，并非只有墓碑支持按字截取。`Line` 归 `Lines`，`Chars/Character` 归 `Characters`，其它值归 Off。默认前 **3** 行、前 **80** 字；行数 1–10、字数 1–1200，`-/+` 每次调整 1。只有所选模式对应的数量行出现；数量不是源正文编辑限额。

### 2.1 样式窗口与模式恢复

旧三项各自有颜色和字号，不共用值：宝箱 `#FFA500`，牌子 `#E6C16A`，墓碑 `#FF5555`；字号默认 0.70、范围 0.50–1.80、按钮步长 0.10。这些是旧值，不把 R 三实体显名的默认 0.90 或五目标箭头颜色自动套过来。

旧样式窗 HSL 拖动先改局部色块草稿，释放提交；六位 HEX 完整后可自动提交，Enter 也可提交。Esc 可取消当前未完成字段/草稿，却不会撤销先前已提交颜色；不存在统一的“整个窗口确认/取消事务”。恢复默认只针对本项样式，行数/字数是另外的参数。模式/样式写入内存后调用 `ConfigService.SaveAll`，入口忽略保存摘要，不能把成功提示或 `Succeeded` 记录当作磁盘成功。R 已有可靠偏好与失败反馈可以复用，不继承这一缺口。

旧 UI setter 与热键记忆分叉：直接选模式没有同步热键的最后非关闭模式；热键只有在自己从开启转关闭时记住当前模式，关闭状态再按键只恢复其已有记忆，无记忆可能返回 `noLastNonOffMode`。因此“页面选模式→页面关闭→按键开启”不保证恢复刚选模式。新版候选沿 R 的**同一模式命令拥有记忆、按钮与热键共用出口**，保留用户期望的再次开启结果，不复制两份记忆。

### 2.2 外层可达性与退出

F5 是否打开、切到哪一页不是世界标签的运行条件。外层先判断是否存在任一 Information 世界显示需求，再检查 SpriteBatch/原版资源，随后构建上下文；菜单、本地玩家不可取或 inactive 使上下文失败。上下文没有单独的 `dead` 早退，玩家死亡但 active/世界仍可用时可继续经过此链。后续绘制和原版层是否实际执行仍有自己的条件，不能把“死亡”直接推成全部停止。

所有 Information 世界显示都关闭时，最外层 `ShouldDrawWorldOverlay` 在调用服务前返回，连该服务的 Stopwatch 都不创建；只是本批三项关闭、但 NPC 显名或五种高亮之一仍开时，不成立此总早退。只有群系等状态面板开着，也不自动进入世界显示的箱子记录链。世界显示没有因为 F5 关窗而停止；三功能各自 Off 只挡自己的消费者。异常外层 catch 会使后续分派中断，不能声称旧三项已有完整局部失败隔离。

### 3.2 容器类别、位置与名字

| 世界对象 | 旧实际覆盖 | 原点/默认名语义 | 不能推导的结论 |
| --- | --- | --- | --- |
| 普通箱 `Containers=21`、第二套 `Containers2=467` | Always 的 tile 候选；Opened 要适用记录 | 2×2，frame 步长 18，横向样式步长 36；`Lang.chestType/chestType2` | 锁箱仍可默认显名，不表示能够打开 |
| 梳妆台 `Dressers=88` | 覆盖 | 3×2，横向步长 54，独立中心点与 `Lang.dresserType` | 不能当 2×2 箱；梳妆/服装交互不等于打开其储物槽 |
| 假箱 `FakeContainers=441/468` | Always 覆盖，默认名分别同对应箱表 | 2×2；tile 存在不要求有世界 Chest 元数据 | 原版 fake 交互是动画/机关；不能据默认名宣布它有箱内物品或生成正常开过事实 |
| 个人银行/保险箱/护卫熔炉/虚空；钱币槽等便携入口 | 不属于此世界箱标签候选 | 原版当前容器槽 -2…-5 对应 bank…bank4，-1 表示未开；记录入口只接非负槽 | 不能按外形、当前容器对象或“储物空间”一概纳入 |
| 展示人偶、帽架、旧假人、武器架及其它 tile entity | 不属于此功能 | `tileContainer` 同时含展示类，不能拿它当候选集合 | 不读它们的装备/展示内容，不新增标签能力 |

旧 scanner 对单个原点/帧取模与类别作检查，没有核验整件所有组成格的同类型、同样式与正确偏移。相邻合法原点可分别发现，不用连通合组，但残片、异常帧和同址替换不能据此保证完整性或物体连续身份。R 的已有四格目标复核可提供组织方式，不能直接把所有容器硬塞入五目标枚举；梳妆台和牌子挂放变体须按自己的尺寸/帧语义实现。

名字优先级为：**当前可读 Chest 的非空自定义名 → 当前 tile 对应 Lang 类型/样式名 → 宝箱/梳妆台通用名**。开过记录不存名字，不拥有名称真相。Always 与 Opened 取名实现不同，但没有按“是否开过”分配不同名称权限。没同步自定义名、真实未命名、读取失败都可能落到默认名；旧输出没有可靠状态标识，显示默认名不能证明远端确实未命名。

名字缓存使用世界键、坐标、类型/样式、语言及当前 Chest 对象/索引/name 签名；**命中前先查 Chest 并拼签名**。类型默认名先走强类型 Lang 表读取，失败可走反射后备；`Containers2=467` 样式 4 先取物品 3988 的名称，fake 468 没有同一特例。不再使用 `MapHelper.TileToLookup/Lang.GetMapObjectName`，没有循环构造 Item 或为名字读取/克隆物品数组。Opened 刷新另建全表坐标→name 字典。可达链未发现箱内物品快照、容量或交易查询；旧报告若讨论另一条箱内搜索/自动存放路径，不能把成本移植到这里。

外层标签缓存同类型/样式且非空旧名称时直接复用，不主动复核实时改名。Always 来源签名不含语言/name，通常等重扫条件或 300 tick 安全刷新再取新名；Opened 一般等 60 tick/签名失效刷新。名字缓存有语言键，不等于外层标签会立即要求重算。字体变化可刷新度量，却不能自动修正旧语言字符串。

### 3.3 开过事实与保存

记录入口是 `RecordOpenChest` 每次共享世界 Draw 读取本机玩家的 `chest`；非负、对应对象/坐标可读且 X/Y>0，才调用 `TryRecordOpenedChest`。它不读右键、不观察原版请求发出、不看箱内物品、不判断手动/自动来源，也不看其它玩家的槽。正常拒绝/上锁而 local 槽未成功改变不会登记；仅鼠标悬停、自动堆叠接触箱子、fake 触发机关都不由这段代码产生记录。若其它路径确实改变了本机有效打开槽，记录器不能区分其来源。

当前 .8 正常多人开箱是 31 请求，服务端发内容与 33，再由本机 33 消费更新 `player.chest/chestX/chestY`；因此正常链的记录通常在本机收到开箱状态之后，但 Legacy 没有验证整批物品同步完成或请求关联。Host & Play 的本机观察与主机权威必须分开；本轮没有运行三拓扑验证。历史旧键导入本身也可以建立记录，并非所有记录都来自本角色的正常打开事件。

**实际归属不是全局或世界共享。** `InformationWorldContextProvider` 生成 `worldName#worldID`，FullRecord 再读原版 ActivePlayerFileData/ActiveWorldFileData 的 Path/Name。角色、世界分别优先使用规范化路径（Trim、统一分隔符、小写并加 `path:`）；路径缺失才使用 `value:` 加角色名、世界名#数字 ID。文件名是这两个键组合的 SHA-256。这里是代码里的身份来源，未读取任何用户存档正文；不能用项目另一个未被调用的 identity resolver 替它背书。Z02/Z05/Z07。

| 身份变化 | 旧键可以说明什么 | 仍不能保证什么 |
| --- | --- | --- |
| 同路径改角色/世界显示名 | 路径优先可保持同一 pair | 文件被同址替换后仍可能沿用；没有可靠世界内容 generation |
| 同名、不同路径的角色/世界 | 路径均可读时可分开 | 无路径回退时，同名角色、相同世界名与 ID 可能碰撞 |
| 换角色、重连 | 可读 player path 不同则换 pair；重连可能沿用旧 pair | 可用检查只要求键非空，`unknown#…` 也可能进入；不是完整未知身份拒绝 |
| 普通客机、同地址另一存档、Host & Play | 只使用本机上述 file data/回退键 | 没有服务器地址或世界身份协议；未证所有拓扑下 file data 的实际可用性，不能承诺绝不串记录 |
| 同坐标挖掉/换类型/重新放置 | 记录继续保存坐标；显示时读当前位置 | “曾开过此坐标”不证明仍是原物体；新同址物体可能继承候选资格 |

旧 schema 1 文件位于逻辑用户目录 `My Games/Terraria/JueMing-Z/data/behavior/`，按 pair 一份 JSON，保存身份/显示名、创建更新时间及 `(X,Y,FirstOpenedUtc,Source)` 列表。首次访问 pair 会在锁内查文件并反序列化，之后使用进程级字典；本轮定向反向引用没有发现生产退出清理、退出统一 flush 或失败重试入口，只有测试重置。缓存没有发现按世界数淘汰上限，不能因名称缓存有上限就声称所有缓存都有界。

每次新坐标添加后在同一调用中全量序列化并同步 `WriteThrough/Flush(true)`，再 Replace/Move；重复同坐标仍做键计算/锁/线性去重，但不更新首次时间、不再次写文件。写失败只记警告并吞掉，内存已 added，返回可仍为 true；重复开同一箱因此不会触发重试，后续新坐标才可能把整份列表再次保存。加载失败被缓存为空，未知 schema 没有完整保护，未来写入可能覆盖原件；这不是 R 允许继承的恢复规则。

旧 `InformationKnownChestKeys` 导入也从共享 Draw 进入：列表非空且 pair 可用时逐键拆坐标，按完整旧 WorldKey 或末尾数字 worldID 匹配，归到**当前**角色×世界。导入键没有原角色身份，不能证明这些箱是本角色开过。Store 保存失败或本来已存在后，调用者仍可移除匹配旧键并 `SaveAll`，没有跨文件事务，也没有可靠结果反馈。显示开启可能触发文件冷读、导入和写入，不能把“只读标签”推广成全链只读。R 首批已确认不导入旧记录；目录预留不构成迁移授权。

## 4. 牌子与墓碑：完整正文、截取与数据就绪

### 4.1 目标和刷新

旧服务枚举 `Main.sign`，读 X/Y/text，再读对应 tile。墓碑是类型 85；牌子是 `Main.tileSign[type]` 为真且不是 85 的对象。当前 .8 初始化集合为 55、85、425、573，所以非墓碑消费者还包括告示牌 `AnnouncementBox=425`、破旧木牌 `TatteredWoodSign=573`，不是所有外形像箭头牌的 tile；510/511 不在该集合。这是版本绑定的类别说明，不把所有未知 sign tile 自动纳入新需求。

它不调用 `Sign.ReadSign`，不自动打开界面或发网络请求；没有装备、距离交互资格或鼠标悬停门。显示另受候选范围、1600 世界像素距离与绘制裁切影响。空/全空白正文不生成标签。牌子与墓碑各自调用扫描/候选缓存；同时开启会分别遍历同一注册表，布局缓存才是共享的。

60 tick 缓存命中仍复核当前坐标 active、tileSign 与墓碑类别；tile 移除/失活/换类可以提前停显。**正文没有在命中时重新读取**：别人改字、清空正文、sign 槽消失或同址同类重放，可能到下一次扫描才更新；过滤不改写原缓存，同址恢复还能短暂重现旧字。扫描缓存只用 tick，不含世界、角色或连接代次；本轮未见生产退出 reset，时间倒退能触发扫描，但不能承诺重连/换世界的旧文本绝不短暂串用。

### 4.2 截取的真实含义

| 情形 | Legacy 实际处理 | 边界/缺口 |
| --- | --- | --- |
| 全部 | 归一换行后折行，仍最多 10 个显示行、约 `460×字号` 宽，超出追加 `...` | “全部”不是无限全文；不修改源 `Sign.text` |
| 前几行 | 先按同一宽度折行，再取前 N 个**显示行** | 长单行也能占多行，不能理解成原文第 N 个换行前的全部文字 |
| 前几字 | 先 `Substring(0,N)`，再折行/限制最多 10 行 | N 按 UTF-16 code unit，换行也计数；不是 Unicode 字素数或最终可见字数 |
| CRLF/CR/首尾空白 | CRLF、CR 归一成 LF，整体 Trim | 首尾空行/空格被去除；内部空行保留并占显示行 |
| 中文普通字符 | 按逐 char 宽度折行 | 不证明所有字体均含相应字形 |
| 组合附加符、代理对 emoji、ZWJ 序列 | 逐 char/Substring 切分，没有整体字素边界 | 可切坏字符，旧测试没有证明支持；不作为必须保留行为 |
| 颜色/物品标签 | 截取与度量先面对原始字符串；最终走 ChatManager 字符串绘制，可能解析标签 | 可截断标签，原始串宽度可能不等于颜色/图标布局；不是完整富文本支持合同 |

`1200` 是显示“前几字”参数上限，本文不据此声称本功能编辑源正文或把原文截短到 1200。布局缓存键包含文本/哈希、模式、数量、字号和字体缓存身份；相同文字可共用布局。位置改变不应要求正文重写，旧此链也未写正文。缓存命中不代表最终 ChatManager 不再工作：当前 .8 对需解析字符串仍会 ParseMessage、LayoutSnippets/ToList，再绘制阴影与内容（V8-05）；没有测量就不报告这部分毫秒或 FPS。

### 4.3 位置、层级与非交互

旧文字块以登记坐标乘 16 为左上角、固定宽 32 世界像素，顶端对齐，每行按自身测量宽度居中；X 可夹到屏幕 4px 安全边距，后续行向下排，不为标签增加编辑、拖动或点击命中。扫描拒绝 X/Y≤0，未核验牌子各挂放变体的完整格与 frame/origin。每项最多 40 个成功绘制的文字块，布局准备发生在最终可绘检查之前；这既不是完整注册表处理上限，也不保证首个 40 候选全部可见。候选裁出与最终每行像素裁切是不同工作；标签块边缘、长行、底部超出不因“有范围判断”就证明全量正确裁切。

正常信息世界层在原版主要 UI 之下；F5 与 Notes 的后续界面优先。旧注入还存在锚点不可用时的后备分派，不能把正常层级保证外推到所有 fallback。标签代码主要使用世界坐标减 screenPosition，牌子块自身没有完整倒重力变换，原版 Game 层矩阵、相机/世界缩放与 UI 缩放不能重复施加。新版复用 R 已接受世界层及其投影门，倒重力、特殊视图、边缘换行仍列有限验收，不能把实体短名测试直接当作长正文验证。

### 7.3 开过的位置：独立观察、身份与持久确认

本工具生效期间，即使三显示全关/无探测/F5关闭，也低成本观察本机正常成功打开世界容器的状态变化。非负本机槽、当前世界完整合格原点及正常打开状态必须成立；排除银行、失败/拒绝点击、悬停、自动存放接触、其它玩家和原自动化内部临时借用状态。复用已有操作上下文，不重开#48回执研究，不用数帧等待猜成功。

同箱保持打开时只比较必要少量状态，不每Update构造pair/文件SHA、全历史锁或线性去重。新坐标事实才推进revision；重复已有坐标不产生同值写，但此前未确认修订仍须允许有界重试。记录的用户含义是**本角色在此世界曾打开过的位置**，不存名称/物品/全文/永恒物体身份。拆除/暂不可读不删除坐标；同址另一件合格容器可继承资格，只显示新完整物体及当前名字。

持久pair只能使用当前版本证据支持的已加载角色与世界稳定定位，具体身份、文件名/schema在有限实现设计中落定；不能仅按名字、服务器地址或临时对象地址宣称无碰撞。普通客机须核对可用身份。身份未知仅保留当前会话，反馈不能承诺重启恢复，不向公共unknown文件写入；不得把所有Opened永久降为会话模式而不说明。首轮只建R新记录，不导入旧坐标/配置/身份，不扫描旧存档/文档或新建服务器/全项目身份平台。

### 7.4 正文与性能的实际边界

采用可靠普通文字并保留原版常用颜色/物品标签的可见效果；一次解析的结果用于截取、度量和绘制，不每帧ParseMessage/LayoutSnippets，不截坏标记后交回原版猜。“前几字”按完整可见字符单元，图标计1个不可拆单元，颜色控制不计数；换行规范化、内部空行保留，换行本身不扣字数。当前TFM/Unicode工具须用代表组合字符、emoji/ZWJ反例验证能力，不能只凭StringInfo名字保证全部Unicode；未支持/损坏标签非交互字面保留，不偷偷删正文。

## 9. R 开发候选的使用与验证边界

F5「更多信息」页提供三项真实控制：宝箱“始终／开过／关闭”，牌子和墓碑“全部／前几行／前几字／关闭”。首次全部关闭、快捷键未绑定；共用键盘按钮接入既有录制与冲突处理，原有 12 项不重置。热键在关闭和上次非关闭模式间切换；无历史选择时宝箱开启为“开过”，牌墓为“前几行”。F5 关闭或切页不停止已经开启的世界显示。

宝箱“始终”需要原版当前有效金属探测能力，“开过”不需要；牌子、墓碑均不需要，也无需悬停或打开编辑界面。三项各自保存模式、样式与参数；默认字号 0.70，范围 0.50–1.80、每步 0.10，原有实体显名默认 0.90 不变。默认颜色为宝箱 #FFA500、牌子 #E6C16A、墓碑 #FF5555。样式窗只重置该项颜色/字号，不改模式、数量或绑定。

“前几行”默认 3、范围 1–10，按换行后实际排版行计；“前几字”默认 80、范围 1–1200，每次 ±1，仅当前模式显示对应参数行。“全部”也最多显示 10 个排版行，超出有省略标志；显示截取不修改正文。常见颜色/物品标记按完整单元处理，不支持或损坏的标记按字面；原版字体缺少的字形仍可能显示后备符号。
