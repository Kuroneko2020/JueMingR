### 1.1 已确认决定与新版用户流程〔A〕

三项各自保留开关、名单或原有操作入口，不新增取代它们的总开关。出售、丢弃各有独立名单；自动堆叠没有因此新增白名单。首轮最终候选须三项和必要 UI、保存及错误反馈一起可用，涵盖单人、Host & Play、本机加入他人房间或普通服务器，不依赖 R 服务端组件。三项绑定已按本次决定撤除；内部可以分步实现和验证，不能交付时只剩单人或一项后台。

| 当前情况 | 新版应发生什么 |
| --- | --- |
| 早已在包里的物品命中出售/丢弃名单 | 可按当前开关和合法条件处理，不等新获取；取出、购买、卸装备或取消收藏不带永久免处理权 |
| 玩家主动打开有效 NPC 商店 | 当前符合出售条件的物品优先卖；不寻找商人、不打开/重开/切换/关闭商店 |
| 没有有效商店、出售关闭或不在名单 | 出售不适用，继续判断丢弃、存放；在出售名单里不形成永久等店锁 |
| 同一物品同时命中多个规则 | 实际开始前按 **出售＞丢弃＞存放** 重新判断；重叠名单合法 |
| 从箱里取 20 木头 | 此动作本身不触发自动堆叠；卖扔仍按自己的名单判断 |
| 后来从地面拾取 3 木头 | 可触发并处理当前未收藏兼容整栈 23 个，不只新增 3 个；取消 Legacy 前量零要求 |
| 同类另有收藏栈 | 收藏栈不动，也不阻止其它合格未收藏栈；执行前按每个实际栈重核 |
| 买入、卸下、包内整理、只开开关或未知增长 | 不独自建立存放来源；没有可靠取得证据时不能猜成拾取 |
| 原版手动打开可开物品 | 本次真正进入合法主包槽的产物可成为存放来源；不自动打开下一件、不递归开奖 |
| 钱币 | 永远不作为本轮存、扔、卖的主动输入候选；没有自动存钱也不回退给堆叠。出售正常收款仍须完整核验 |

所有规则保护收藏、鼠标拿持、当前使用、正在手动操作的原物品及非法槽位。候选范围沿用主包前 58 槽的有意义能力，含快捷栏和弹药，但排除币类；装备、银行、鼠标槽 58 和垃圾桶不成为这三项的来源。出售/丢弃不套用“可堆叠”门，名单中的非堆叠物也可处理；存放继续按实际兼容性和堆叠资格筛选。用户可自由改包，旧计划不冻结槽位。不新增随身保留额度、保护秒数或逐单位的永久来源账本。

**丢弃的新增裁决已经取得：允许自动丢弃覆盖垃圾桶中的任何原有内容。** 这包括原来由玩家放入的物品；连续替换后，只有最后留在垃圾桶的那一项可按原版方式取回，之前内容可能永久消失。此许可只覆盖原版垃圾桶替换的后果，不能任意清除其它槽位、重复扣物或把丢弃改成抛到地上。钱币候选排除仍有效；原有垃圾桶内容被替换不等于将它作为自动筛选来源。不增加逐件确认或另外的总开关。

### 1.2 操作结果和相邻边界〔A＋必要安全合同〕

规则明确不适用且**尚未开始**时，才直接考虑下一规则。已开始而未确认、部分完成或原因不明失败，不得简单落到下一规则，更不能重复卖、扔、存。完整结果必须说明实际处理量和余量；确认一次操作结束后重新读取剩余物品，再按当时优先级评估，不继续执行旧数量计划。未知只限制真实受影响范围，不无限暂停无关物品，也不自动补一次或回写旧快照。

偏好全局共享，来源事实和待处理状态只属于当前会话。关闭规则、改名单、退出世界、换角色、断线或商店变化使尚未开始的旧计划失效；已经发生的变化不能假称已撤回，旧结果不得作用于新会话。清理安全责任结束前不丢弃未知结果，但不重放旧请求。

未来存鱼边界：可靠的本机**直接钓获**与普通地面拾取分开；鱼落地后再拾取按真实普通拾取，不追踪是谁钓的，也不能仅因缺钓获标记把其它增长认作拾取。专用存鱼与普通存放同时匹配时，专用模式优先决定存放目标，同样允许未收藏兼容整栈；不能绕过卖＞扔＞存，目标不适用时如何回退尚属未来专用功能细节，本轮不发明回退。两种存鱼模式均不在首轮实现。

### 1.3 手动开启来源与真实限制〔C：目标 .8；新版目标见 1.1〕

“开匣”统一指原版正常打开/拆开可开物品，按原版 **OpenableBag 识别与实际开启分支**覆盖，不按中文名称或三个样例建白名单。目标 .8 包括宝藏袋、普通/困难匣、草药袋、蠕虫罐、牡蛎、福袋、Chillet 蛋、两种锁盒、礼物及旧礼物；它不包括世界箱 UI、装备、放置、喝药、制作、提炼或微光。〔V8-01〕

原版先产生结果，再消耗开启原物；多个结果可能合入既有栈、进入多个槽，钱币还可能换面额。主包接收不下时，原版设置允许的产物可能先进入已启用的虚空仓库，余量才请求落地；落地后真正再次拾取是后续独立来源。首轮只处理真正进入约定主包槽的部分，不扩展为从虚空仓库抽取物品，不主动扔旧物腾位、不补生成或删除溢出产物。〔V8-02〕

来源观察须跟随本机真实开启的调用因果，合并其内层 GetItem 事实，等本次调用完成后才评估；不能将同一直接产物既计为开启又计为世界拾取。GetItem 的设置名也被直接发物复用，不能单独当来源证明。无合法开启、缺钥匙、取消、异常或无可证实主包产物时，不制造存放资格；已产生但整体异常的结果保留未知。原物品、必要钥匙和用户当前操作的槽位须让开。〔V8-01/02〕

**原版允许在玩家保持有效商店界面时，手动右键打开背包中的可开物品。** .8 背包入口仍按 context 0 接收输入，商店绘制没有统一禁止这一入口；鼠标路径受真实右键边沿、itemAnimation、待处理原版动作、物品兼容和槽锁约束。手柄另有 ActionOpen 路径，不能把鼠标路径的门直接套到所有输入。F5 正在拥有指针/键位录入时仍须遵守 R 输入隔离；先完成玩家本次输入，再处理产物，不能伪造输入或开关商店来制造兼容。上述为静态可达，不是实机手感或所有输入场景已通过。〔V8-01/03〕

### R 开发候选使用与验证边界

F5 的“物品”页依次提供“自动堆叠、自动出售、自动丢弃”，各行明确“开启/关闭”，三项绑定已撤除。首次全关；出售默认旧鞋、海草、锡罐，丢弃名单为空。F5 隐藏后，已启用功能继续工作。先用少量无价值物品试用，特别是自动丢弃会替换垃圾桶原有内容。

两份名单紧接对应功能行；行上“添加”从当前背包按类型选择，收藏栈也可提供类型，批量勾选后“确定添加”才提交。名单图标悬停显示名称，点击打开明确编辑层：“替换”选定新类型后提交，“移除”删除该名单条目；取消、离页或失焦丢弃未提交草稿。已开启功能会按最新名单处理现有库存。收藏与当前手动操作仍按实际物品保护，不因列入名单失效。

页面没有绑定/录入/清除入口，旧配置中的非零绑定也不再切换三项；F5 固定开关、Notes 既有编辑/输入法/阅读滚轮及名单 Esc/失焦输入保护继续保留。配置独立保存在 `JueMingRData/config/features/item-automation.json`，新写入 version 2；合法旧文件仅在读取边界退休绑定字段，首次真实修改前保留原件。重复点已选开启/关闭不改 revision 或写盘；普通保存成功静默，未可靠保存和实际故障明确提示。

出售需要玩家自己打开有效 NPC 商店；关店会继续判断丢弃和堆叠。堆叠由实际地面拾取或完整成功的普通手动开启产物触发；从箱中取出、购买和包内移动本身不触发。比如先取出20木头，再拾取3木头，可处理未收藏23个整栈。原版同类可开物品依据目标版本集合识别，涵盖匣子、宝藏袋、牡蛎等，不是三个样例的白名单。

后台结果区分执行中、完成、部分完成、未确认与超时，页面只保留必要错误，不常驻普通处理结果。未确认影响范围继续保护，不重发或回填。原版客机没有本功能请求 ID，断线等历史不能保证得到可判定结果。单人、Host & Play、普通客机均有实现接线；隔离网络夹具和本地绘图不等于三拓扑实机接受。实际测试流程见[物品开发候选实机卡](../../scripts/phase0s/Item-Automation-Owner-Test-Card.zh-CN.md)，当前候选和验收只查 #46。

## 2. Legacy 名称与普通用户流程

| 名称 | 实际入口与作用 | 本文边界 |
| --- | --- | --- |
| 自动堆叠 | F5 → 物品 → 第二行；符合来源条件后选择性存放物品 | 主能力；不是全背包整理，也不是按一次键立即存全部 |
| 自动存钱 | 物品页第八行；独立开启，靠近银行入口时处理钱币 | 相邻能力；开启时钱币不再归自动堆叠处理 |
| 自动存放鱼 | 钓鱼页；“所有 / 任务鱼 / 关闭”与独立主开关热键 | 独立钓鱼触发，不把其“所有”模式当本功能的模式 |
| 持续开袋 / 快速开袋 | 物品页显示“持续开袋”；功能注册仍称“快速开袋” | 同一开袋能力的 UI/内部名称差异；受控批次是自动堆叠的一种特殊来源 |

普通使用过程按旧版静态入口恢复：

1. 打开 F5，进入“物品”，在“自动堆叠”行选择“开启”。默认关闭；选择会保存为 Legacy 全局偏好。可以通过行尾键盘入口绑定主开关键，作用仍是开/关。
2. 靠近有相应物品的合适世界容器。无需打开箱子；箱子或银行界面打开时反而会挡住执行。仅有个人银行入口在旁，不表示普通物品能存入银行。
3. 取得合格物品。**普通世界拾取前，背包已有同种、同前缀物品时，旧版不会因此再建立新待存意图。** 功能开启前已有物品也不会仅因开关打开而被全包整理。
4. 受控持续开袋有例外：其产物可以在原先已有同类时形成待存意图，而且可能连同原有合格同类栈参与存放，并非只存刚增加的数量。
5. 鼠标拿物、容器/聊天/NPC冲突或其它使用物品动作期间等待合适时机；执行前再核对来源、玩家世界、设置和槽位。普通背包打开本身不是一律禁止；其它文本/地图情形不能一概说已阻挡。
6. 有空间就可能存入全部或一部分；余量留身上。旧版对一个批次只要观察到来源数量下降，就可能按成功结束整个批次，不承诺把每种余量一直存完。
7. 从容器取出的东西不应因“背包增加”又被识别成拾取；关闭容器不会将这次取出变成新来源。主开关关闭也不意味着已经进入原版调用的动作能够中途回滚。

正常结果主要通过背包/容器变化与原版转移表现感知。以下详细条款分别说明哪些只是意图、哪些有静态执行依据、哪些仍需指定实机证明。

## 3. Legacy 自动堆叠详细行为

### STORE-01 入口、开关和保存

Legacy 行显示“开启 / 关闭”和行尾主开关热键，提示“尝试堆叠刚捡起的物品”。未发现专属配置、范围滑块、名单、保留数量、延时输入框或立即整理按钮。开关为全局布尔偏好，默认关闭；动作一旦切换会通知设置代次并调用保存。没有“打开配置窗再点确定”的步骤。

**选中状态只表示 Legacy 内存设置，不表示正在存放、等待、存妥或保存成功。** UI 改内存后调用保存，没有依据保存结果撤回该选中状态；实际工作还受来源、UI、角色、运行调度与执行门控制。等待、无目标、来源拒绝、重试耗尽等主要在内部诊断，普通行不展示这些状态。R 需要按既有期望/实际/不可用分层与保存失败保护承接，不能继承误导性成功。〔C，UI 与配置交叉；E01–E03〕

### STORE-02 来源是取得依据，不是背包差值本身

| 来源或动作 | 现场静态结论 | 限制 |
| --- | --- | --- |
| 普通世界拾取 | 版本专用入口结合前后背包增量和世界物品余量，形成取得票据；只有满足精确同类前量为零等条件才准入 | 调用了拾取入口、背包增加或物品发光，单独都不够 |
| 已有同种同前缀，再世界拾取 | 只推进基线，不新建该项待存意图 | 不把新增加的部分自动拆出来存放 |
| 受控持续开袋 | 旧开袋执行前后精确采样，正增长可以形成受控批次来源 | 前量不必为零；不是所有打开袋子/匣子的行为都自动等同此路径 |
| 普通手工开袋、合成、购买、直接发背包奖励 | 未发现各自独立可靠来源接入，不能据总量增加判定支持 | 若产物实际落地再走合格世界拾取路径，按后者判断；不是宣称该来源类别全部支持 |
| 世界箱和四类个人银行取出 | 形成容器取出保护事实，不是拾取准入 | 单取、全部取出、拆分和经鼠标转入的识别边界见 STORE-08 |
| 取消收藏、脱装备、背包内拆分/合并/排序、开启前已有物品 | 不因这些动作本身建立新拾取意图 | 原有合格意图之后如何受变化影响，见 STORE-05、STORE-09 |

世界取得的特殊消耗（心、星、星云增益等）若没有主背包正增长，不应占用来源票据。`newAndShiny` 不是可靠依据；界面可清掉它，非世界来源也可能设置它。旧注册描述“检测刚增加的 itemType”过于宽泛，不能代替当前来源合同。〔C+B+D；E04–E06〕

前量统计包含前 58 格内所有同 type/prefix 正数量物品，不排除收藏旧栈；候选基线同组资格又以每槽条件合并，一个不合格同类槽就可能使整组不准入。两次扫描之间连续拾取同兼容物品，后一次前量已经大于零时，整组票据也可能被拒绝，不能承诺连续拾取一定累积存放。

### STORE-03 来源槽位与物品资格

候选读取主 `inventory[0..57]`：包括快捷栏、普通背包、钱币与弹药槽。**没有整栏排除快捷栏或弹药。** 不以鼠标物品、装备栏、杂项装备栏或虚空袋作为本选择性路径的来源；槽 58 不在该扫描内。

物品须非空、数量大于零、未收藏、可堆叠，且不属于被资格检查排除的饰品、翅膀或防御装备。未发现收藏以外可由用户设置的独立“锁定物品”系统或排除名单。取消收藏本身不生成来源。钱币 `71–74` 在自动存钱开启时从自动堆叠来源准入中排除；关闭存钱后也仍需符合可靠来源条件，不成为主动搜遍身上钱币的模式。〔C+B+D；E04–E07〕

### STORE-04 到底允许移动多少

来源准入按精确 `type + prefix` 兼容身份核对票据增量。之后建立执行候选时，选入的是该兼容身份下的**所有当前合格槽位及其整栈数量**，不是每张票据的“新增数量额度”。

- 普通世界拾取要求取得前该兼容同类总量为零，因而不会通常把先前已有同类顺带当成这次取得。
- 受控开袋允许前量非零。例如测试用“原有 5、开袋增加 2、后量 7”验证该来源可准入；实际候选收集整栈，所以不能承诺只存 2。
- 来源、槽位和数量复验是执行资格，**不等于已经证明来源和所有目标的总量守恒**。
- 来自容器的保护数量与后来取得数量混在同一栈时，没有一个可独立减去的普通物品保留额度。以来源判定和保护代次失效处理，不能擅自解释为“永远保留取出的 N 个，其余都存”。

这是完整平替中必须明确的可观察差异，不能把“选择性”误写成“仅新增数量”。〔C+B；E04–E06；测试只断言准入，不是 7 个已真实转移的证据〕

### STORE-05 待处理与变化复验

等待期间没有权利冻结玩家背包。入队意图携带玩家世界身份、来源票据、来源/保护代次、设置代次与精确槽位签名；执行前重新读取。槽位换物、数量消耗、前缀/收藏/资格改变、排序换槽或保护代次漂移，都会影响再次校验；不把旧槽号直接当作仍然属于同一物品。

来源保护的明确拒绝不进入普通失败补执行。仅有客户端显示变化、函数返回或请求已入队，都不能视为物品已经可靠存妥。〔C+B；E04–E08〕

如果已有合法待存，等待中又世界拾取同 type/prefix 且前量大于零，下一次来源扫描会将该身份列为拒绝，并删除对应旧待存、释放票据；这发生在服务的 UI 等待返回和执行校验之前。已发出的旧请求还可能因票据/签名失效被拒绝，但不能追溯取消已经执行的动作。此完整情形来自静态调用链，未见相应完整专测。

### STORE-06 等待、取消和失败不是同一状态

普通背包打开本身允许后台存放；鼠标拿物、世界箱/个人银行/未知负容器状态、聊天、NPC 对话等则阻挡。只有容器字段 `-1` 表示没有容器 UI，不能把任意负数当作关闭。正在自动收获/捕捉等使用物品时，后台待存让路。

无目标、没有增长、资格拒绝、UI 暂时阻挡、队列忙、入队拒绝、来源过期、执行失败和未验证结果，在旧实现中有不同控制分支。部分分支保留待存，部分拒绝或清除；没有一个涵盖全部情况的“安全时执行”保证。F5 本身隐藏不是关闭功能。〔C+B+D；E07–E09〕

| 玩家状态 | 本次定向检查能支持的范围 |
| --- | --- |
| 普通背包打开 | 允许，但等待距最近待存变化满 3 tick；不是打开背包起固定等三帧 |
| 容器、聊天、NPC 对话、鼠标拿物 | 服务/执行器有明确阻挡；读到可靠增长时可能先维护/删除待存，再返回等待 |
| 商店、笔记编辑、其它文本、全屏地图 | 本功能直接门只读取菜单/Chat/NPC/Chest和鼠标，未见每一种专门状态门；主开关键另有较完整文本/模态门，不能替代后台执行门。是否经共享原版字段间接阻挡不在本轮证明范围 |
| 失焦 | 新请求调度依赖 GameInputAvailable；焦点读取失败有回退。已排队请求的执行器没有等价焦点复查，队列仍有独立 Update，不能保证失焦后旧动作一律停住 |
| 原版/自动化正在使用物品 | 共享队列及通道使后台请求让路，但不是所有玩家操作/全部自动化竞争都已验证 |

这里的未知应进入后续输入与资源安全验收，不写成 Legacy 已实现完整的“任何文本或地图打开就暂停”。补充来源见 E09。

### STORE-07 部分完成、有限重试与恢复限制

原版可以只转走有容量的一部分，余量留在背包。Legacy 兼容层以同 type 总量或选中槽数量的减少作为结果信号；一旦据此成功，会结束整个待存批次，不能保证逐项剩余都继续处理。

旧常规重试间隔是 60 tick，无附近目标为 180 tick；初试后最多再安排 3 次重试。600 tick 年龄限制只在登记重试时检查，**不是所有 UI 等待、队列忙或入队拒绝都会在 600 tick 自动取消**。这些是旧内部固定值，不是可调配置，也不是已接受的 R 调度设计。

另有背包打开后的 3 tick 稳定窗、待落槽/等待结果的 120 tick 分支。不能把 120 tick 写成来源票据统一有效期：当前来源票据没有按时间到期，64 个槽位的容量满时拒绝新票据，已为执行保留的票据不会被任意覆盖。

原版正常完成会保留未移动余量，但 AutoStack 没有跨所有来源和目标的原子回滚证明。部分修改后异常、结果不明确或网络迟到，不能据“失败”重新执行就认定安全；也不能要求未来用旧背包快照盲目覆盖游戏的新状态。R 必须保留资源安全和未确认结果底线，具体恢复方案留后续设计。〔C+B+D/U；E07–E10〕

## 4. Legacy 容器、保护、生命周期与多人

### STORE-08 防止取出后又存回

普通物品取出与钱币租约是两套不同语义：

| 事项 | 普通物品自动堆叠 | 自动存钱相邻能力 |
| --- | --- | --- |
| 取出识别 | 世界箱和 `bank/bank2/bank3/bank4`，优先看实际数组归属；UI context 数字仅辅助 | 可靠取钱事实进一步建立当前身份下的钱币保护租约 |
| 鼠标中转 | 鼠标保留同 type/prefix 的来源记录，跨关闭容器仍可延续；转入背包仍按容器取出发布 | 不能靠关 UI 释放钱币租约 |
| 旧请求 | 任意容器取出推进保护代次，可能连带使先前其它品类待存失效 | 执行前复查租约、代次与银行范围三态 |
| 正常保持 | 取出增长推进基线；没有新可靠来源，不会反复回放这次增长 | 仍在任一银行范围内则继续保护，不按枚数建立随身额度 |
| 解除/失效 | 不是“走出银行范围释放普通物品租约”；鼠标空、身份或兼容物品变化等清理鼠标来源，旧取得事实不会因此变成拾取 | 可靠观察无任何银行、玩家世界身份改变或自动存钱关闭后重新开启，才释放 |
| 范围读取失败 | 不能构造新的可信来源 | `Unavailable` 不能当作已经离开全部银行 |

普通物品不承诺把取出量永久绑定到每一个对象，也没有固定延时解除或保留数量规则。反过来，可靠世界拾取后的原栈仍在身上时，再取得同兼容物品也未必准入。取出保护测试中的“五容器矩阵”使用服务输入标签；它不是五类真实容器交互均已实机通过的证据。〔C+B+D；E05–E06、E11〕

具体反例是：先前容器取出增长已经扫描、消费并拒绝，后来新的受控开袋批次获准时，过去取出的同类数量也可能一起进入整栈候选。若两种来源在同次扫描混合，则可能因来源种类/保护代次不一致而全部拒绝。不能既承诺“任何旧取出量永不移动”，又保留不区分数量的受控开袋整栈语义。

### STORE-09 目标容器、范围与多目标顺序

| 条件 | 现场 .7 原版选择性调用证据 |
| --- | --- |
| 实际底层目标 | 附近世界 `Main.chest` 对象。普通箱在内；梳妆台等只要确有世界 Chest 且满足原版条件，也不能因名称被排除。展示物、任意 tileContainer、假箱图块不自动等于可存目标。 |
| 个人银行与移动入口 | 猪猪/钱币槽/Chester 对应的 `bank`、保险箱 `bank2`、熔炉 `bank3`、虚空 `bank4` 不在此普通物品实际目标列表。Legacy 前检却把附近银行算进去，造成仅有银行时仍可能无效尝试；这不是银行存普通物品能力。 |
| 距离 | 欧氏距离，半径 600 游戏像素；从 `player.position` 到 `(chest.x*16+16, chest.y*16+16)`，不是从玩家中心、鼠标或容器 UI 测距。约为 37.5 格只是换算，不是矩形扫描范围。 |
| 顺序 | 附近枚举按世界 Chest 索引顺序，不按距离最近排序；先补兼容未满栈，再按目标的空槽规则放余量。默认传入 smartStack=false。 |
| 同类与新栈 | 目标候选按 type 建立；实际合栈还须可堆叠且 prefix 等兼容。含同 type、不同 prefix 的箱子可能不能合原栈，但有空位时可以新建栈。完全空箱或没有该 type 的箱子不是随意投放目标。 |
| 满箱/无目标 | 没有相应容量就留身上；不承诺自动找所有世界箱或等空间一直重试。 |
| 锁定/他人使用 | 原版会标记锁定或正被玩家使用的世界 Chest 为阻挡。没有单独视线检查；不能据范围内可见推断有权写入。执行会重新枚举范围和容器状态，仍不证明跨网络竞争下的权限与最终结果。 |
| UI 与内容知识 | 无需主动打开；打开容器 UI 会挡住本功能执行。客户端当前知道的箱内容与服务器实际内容不同，数组存在不证明同步完成。 |

本路径传入明确的来源数组，不调用原版另一个默认只取背包部分槽位并可能带虚空袋的包装路径，因此不能把原版“快捷堆叠”的所有默认行为倒灌给本功能。以上 .7 静态结果纠正早期报告仅称“普通箱”、仅以 .6 说明顺序的过窄结论；不证明 R .8 等价。〔C 原版与 Legacy 调用交叉；E08、E10〕

### STORE-10 生命周期

玩家世界身份、来源/保护代次与设置代次变化可以使尚未执行的旧请求失效；死亡/鬼魂有清理和执行拒绝分支。服务收到关闭状态时会清理，但调度的全局 lane 可能先返回，所以不能承诺“点关闭、退世界或聊天时该瞬间所有内部状态都清空”。已经进入原版同步调用的动作没有中途撤销保证。

重新进入世界、换角色、断线重连后的迟到结果不得用于新身份。Legacy 的静态代次门能证明部分拒绝路径，不能替代全部断线/切换竞态与多人同步验证。R 的完整目标仍需退出后不残留旧动作；不能将旧清理调度细节作为必须复刻的架构。〔C+B/U；E07–E09、E11〕

### STORE-11 多人权威

| 场景 | 已知控制路径 | 未证明范围 |
| --- | --- | --- |
| 单人 | 当前客户端原版直接处理来源与世界容器 | 真实 .7/.8 的全部物品属性/容量/异常守恒仍未实测 |
| Host & Play 的本地客户端 | 仍须区分本地客户端请求与主机/服务器角色处理，不能按同一进程合并两者 | 本功能各阶段、远端同步、延迟/拒绝/断线完整链未验收 |
| 加入专用服务器的客户端 | 选择性原版路径涉及来源槽锁定与原版网络请求，由服务器处理 | 请求已发送、客户端数量减少、Legacy 标为成功都不是服务器最终接受凭据 |

Legacy 元数据 `SupportedByOriginalAction` 只是实现路线声明。未发现主功能具有独立的最终服务器接受回执或跨全部目标守恒核验；不能把“无异常返回”升级为多人安全。

R 现行[平台规则](../规范/技术平台与兼容规则.md#九单人与多人拓扑)仍以客户端产品覆盖单人、Host & Play、连接专服为目标，不部署 R 专用服务端组件。普通物品功能不能未经调查全局删去多人，也不能在结果未确认时宣称成功。保留完整目标，未证明安全的具体写路径须明确停住或显示未确认，不能靠盲目重试补执行。〔C/U；E08–E10〕

### STORE-12 其它自动化和运行成本

自动存钱开启时拥有钱币处理；普通物品不归存钱。自动出售、丢弃排在未完成自动堆叠之后；持续开袋为清理批次让出执行窗口；收获和捕捉正在使用物品时，后台存放等待。没有相邻功能并不意味着自动堆叠无法独立工作：世界拾取到存放可以单独成立，开袋受控来源则确有额外用户能力依赖。无需先复制旧 ActionQueue 或实现全部物品页。

来源保护不是禁止出售/丢弃的总保险：自动堆叠拒绝后若已无 pending，出售/丢弃仍按自己的名单继续。钓鱼存放也有独立待处理与钓鱼会话，不自动继承普通物品来源票据；共享执行出口的内部耦合不能把它们合并为一个产品功能。自动存钱的空银行首币补救只覆盖可证明的 `player.bank`；其合法面额转换以总价值而非枚数不变判断，不能把该专用恢复能力写成 AutoStack 跨容器回滚。

旧开启路径有 5-tick 扫描节流，主背包最多 58 槽，包含字典/列表、兼容身份与签名整理；来源观察和执行前复验也有自身工作。关闭后不再正常扫描不等于共享来源 Hook、调度和安全观察成本为零。原版附近枚举上限与容器遍历、候选数量、失败重试都会影响成本；不凭缓存命名或静态调用次数宣称 FPS 良好。

以后真正需要验证的场景是满背包多类型、密集世界箱、只有银行但无真实目标、长期 UI 阻挡、连续开袋、自动化抢占、多人延迟/拒绝与反复失效。无需为每个循环建立一份性能报告，本轮也不创建测量工具。〔C+B+D/U；E06–E10〕

## 5. Legacy 物品页结构与控件映射

### STORE-13 整页结构

Legacy 实际绘制顺序如下，**没有额外分组标题**。这是从布局、控件与命中代码恢复的结构；定向检查功能材料及精选视觉资料未找到可用旧物品页截图，本轮未观察实际画面。行内选择状态取配置，不能把所有行都解释成实时执行状态。〔E01、E12〕

#46 本次 UI 修正已收到并实际查看历史聊天提取的旧 Z 物品页原图；上述“未找到”是此前取证时的事实。新图仅补足三项顺序、行下名单和紧凑图标结构，不能证明该冻结源码的逐像素或点击语义；当前 R 信息页控件规则与本次撤除绑定决定优先。

| 顺序 / 名称 | 行内操作组 | 行下区域或弹层 | 提示与本轮归属 |
| --- | --- | --- | --- |
| 1 快捷物品 | 添加、开启、关闭、主开关键盘 | 条目卡含物品选择、删除、独立使用键；选择面板与录入提示 | “新增一条快捷物品配置。”“启用快捷物品功能。”；本轮只记录结构，独立使用键不是自动堆叠动作键 |

页高度计算包含三处可增长区域和其余行，整体内容滚动；滚动位置按内容/视口夹紧，完全不可见的行不生成相同绘制工作，命中取与 viewport 的交集。捕捉弹层在行锚点可见时注册为 modal overlay，阻止后续行覆盖与抢命中，并优先决定是否阻挡主滚动。源码可追到条目和弹层命令，并非只列 Feature 元数据；小视口下的实际像素、按键手感和全部行的后台可用性未由本次静态几何证明。

### STORE-14 主开关键入口与实际保存

自动堆叠的键盘入口须**双击**打开；单击只记录需要双击，不打开。旧判定为同一控件、500 ms 内、横纵位移各不超过 6。弹窗标题“自动堆叠 快捷键”，显示“当前：未绑定”或当前组合，以及“录入 / 清除 / 关闭”，说明“只切换功能开启/关闭，不执行功能动作。”默认未绑定。〔C+B；E02–E03、E13〕

1. 点录入会清文本焦点、停止其它录入，并记住当前已按键，避免启动点击立即成为绑定。
2. 新按键采到后直接尝试验证并保存，不另点“保存”。成功显示“已保存 …”，未变化、内部冲突、保留键或保存失败有各自消息；无论成功、失败或取消，结束这次录入，弹窗仍留着。
3. 录入时单独 Esc 取消并保留旧绑定；单独 Backspace 清除；带修饰键的这两个键拒绝。普通非录入状态下 Esc 能否关闭整窗，没有找到相同保证。
4. 切页成功时关闭该弹层并取消录入；若笔记提交门阻止切页，不能说切换已经发生。**F5 隐藏或失焦在旧代码中没有清除该录入状态**：隐藏时绘制返回，失焦时录入更新返回；回到窗口后的实际续录表现仍需实测。不能将“暂停采样”写成“取消”。
5. 当前生产绑定来自 `unified-hotkeys.json` 的 `feature.toggle.inventory.auto_stack`。旧 `hotkeys.json` 的开关字典和测试 helper 不是现行运行入口。
6. 运行主开关键在 F5 可见、录入、活动 UI、文本、NPC、失焦/无输入或不在世界等门禁下不切换。它翻转开关并保存，既不直接执行 QuickStack，也不替代原版快捷堆叠键；原版键重合不会一律被绑定策略阻止，不能承诺消费或禁用原版动作。

两处提示/保存冲突须保留：

- 弹层录入 hover 宣称支持鼠标键，但当前功能主开关键策略实际拒绝鼠标主键及多于一个修饰键。通用录入器能识别，不等于该目标能保存。R 提示必须符合真实许可。
- 点“清除”与按 Backspace 的反馈路径不同。按钮忽略保存成功布尔，只看 `Changed`；保存失败可能内存已清但提示“当前未绑定”。不能据此说磁盘已清，不能继承为正确体验。

Legacy 普通按钮**在按下边沿提交**，按住时只改变按下外观；不是松手才改。自动堆叠按钮默认 enabled，没有等待或失败禁用接入。R 按既有“同一控件、同一布局代次释放才执行”和失焦输入尾部保护处理，这属于明确呈现差异，不将 R 规则倒写成旧版原貌。〔C+B/U；E01–E03、E13〕

**出售：只在玩家当前有效商店交易。** Legacy 会选择附近 NPC、改 talkNPC/购物设置并 OpenShop，有时留下界面；这是被取消的旧行为。新版不重建虚构 shop，也不缓存价格文本猜成交价。必须核验当前 NPC、商店实例/类型、购物条件和会话，商店关闭或变化使旧计划失效。无有效商店或明确不可售且尚未调用时属于不适用，可考虑下一规则。〔E16；V8-04〕

.8 原版交易先以当前购物设置和回售记录计算收入，`SellItem` 将钱币放入 0..53，可能跨多个币栈递归换面额；收不下则恢复其备份的前 58 槽并返回 false。它不先清空被卖槽来腾位，也没有“收不下就扔钱到地上”的这条出售后备路径。随后 ItemSlot 才加入回购并清来源。不得只看来源减少或只看 SellItem 的 true；要核对扣除与实际总币值变化及原版允许的回售调整。零 value 物品在原版有零收入接收分支，须明确记为零收入处理，不能伪报金币收入；其它价格无效/拒绝与中途异常未知分开。〔V8-04〕

回购不是无限保险：`AddItemToShop` 先消耗本店回售记录对应量，再尝试与已有 buyOnce 栈合并或用 0..38 的空位；没有空间时可能无法留下全部回购物，但原版仍可完成出售。已接受目标保留原版交易结果，不承诺售出每件都可找回。验证应区分正常原版回购容量限制与中途异常漏步骤。Legacy 收款后加入回购/清源异常时会返回失败，却可能已经收钱；不能重试整笔。〔E16；V8-04〕

**丢弃：送入原版垃圾桶，允许替换其中任何原物。** Legacy 借 ItemSlot 的垃圾桶分支，不是 world Drop；只比较源槽减少、记录垃圾桶 type，不能证明数量/属性或完整结果。.8 该分支复制本次整栈到 trashItem 并清源，连续操作共用同一垃圾桶。在旅行模式还会按原版垃圾桶路径尝试研究（包括被替换旧内容）；这是该原版操作的附带行为，不新增自动研究功能。新版须核对源栈确实转入垃圾桶且之前内容按已接受覆盖语义消失，不能仅以点击返回或类型变化报成功。未知中断停止相同资源的后续替换，已明确处理的其它独立资源再按真实冲突决定。〔E17；V8-05〕

### 6.4 真实冲突、结果和客机等待

来源事实、当前规则选择、提交和结果分开。来源 Hook 可以记录必要事实，不立即在回调里依次执行所有操作；活游戏状态只在游戏主线程按原版时序处理。开始前重新检查卖＞扔＞存，待处理意图不是预先取得物品所有权。

| 实际影响范围 | 必须协调的原因 | 不应扩大的等待 |
| --- | --- | --- |
| 一次开启原物/钥匙与本次产物接收 | 先发物后扣原物；GetItem 多槽合并、钱币换面额及可能虚空/世界余量 | 等本次原版调用结束；不继承未来快速开物品的固定速度窗 |
| 出售源槽＋收款/备份范围＋当前商店/回购 | 收款可能写 0..53，失败恢复前 58 槽；同一主线程调用内不允许嵌套物品 mutation | 不能以“另一来源槽不同”证明同时安全；也不因商店关闭锁住所有待扔/待存 |
| 丢弃源槽＋单个垃圾桶＋实际输入作用域 | 多次操作争同一目标；原版输入借用及旅行研究可能有额外状态 | 可短暂串行垃圾桶操作；不必等待另一无关物品寻找箱子 |
| 一次存放提交的来源槽组＋原版网络锁/目标容器 | 原版合并来源、转移多个栈，客机按这些槽发请求并等待服务器写回 | 不把一个无容量/退避的候选当所有卖扔的全局锁；可能覆盖收款/重排范围时必须先等真实冲突结束 |

.8 客机存放的网络槽锁不同于 `LocalPlayerHasPendingInventoryActions`（后者是 FakeCursorItem/制作请求）；`HasLockedInventory` 汇合原版堆叠锁等条件。不同 UI/操作路径使用的门不同，不能强清原版锁或在整个背包需要保护时绕过。原版 QuickStack 使用共享 scratch/netInv，并且消息没有 R 的请求 ID；后续实现须在这条操作范围内限制未完成批次、核对原版槽回复和会话，不能并发叠发相同资源后假装能准确归属。

旧快速开袋在请求**入队**时，只要清理开关任一开启便设置 24 tick 让路，不核对候选/冲突/结果；卖扔在选自己名单前先等全部 AutoStack pending，另有整个 InputActionQueue busy 门。这是 Legacy 的人为调度策略，不是每种资源必须等待的证据，也没有足够历史证据断定某个版本是体验退化起点。未来固定开启速度方向保留，本轮不制定新 Tick。〔E18〕

| 结果 | 本批的处理责任 |
| --- | --- |
| 未开始且明确不适用 | 按优先级考虑下一规则；保留简明原因，例如商店关闭、名单不含或无合法目标 |
| 已发请求或已调用但结果未确认 | 保留真实受影响范围，等对应观察；超时仍未知，不当失败补一次，不进入替代动作 |
| 部分完成且原版操作已结束 | 记录已证实部分，重新观察剩余资源和当前条件；不宣称整批完成、不继续旧快照数量 |
| 拒绝/失败且可证实无副作用 | 按具体原因重新评估或有限等待条件变化；不能从通用异常/文字消息猜出“完全未动” |
| 原因不明异常、断线或迟到 | 撤销旧会话尚未开始的意图；未知不写回旧备份、不自动重发，有限状态反馈，等待后续明确事实 |

### 6.5 已接受的职责与状态归属方向

这是已接受的后续设计与审查约束，不表示机制已经实现，也不新建类、接口、项目或架构规则。普通拆分由 Agent 负责，最终文件名在后续设计确定。

| 职责 | 输入 → 输出 | 唯一归属与边界 |
| --- | --- | --- |
| 合法来源观察 | 本机原版取得/开启因果、必要前后事实 → 有界来源事实 | Host 读取原始事实；物品业务解释是否可触发存放；不另造所有来源总线 |
| 共同当前观察 | 当前会话和三项真实需求 → 同时点背包/商店/保护事实 | 一个观察提供者；Terraria 仍拥有实际物品，不让三项各养一份事实源 |
| 规则与优先级 | 当前物品、名单、开关、合法来源、商店/目标 → 卖/扔/存意图或不适用 | 物品业务知道名单和卖＞扔＞存；通用层不知道三项业务规则 |
| 有界待处理状态 | 变化/来源/结果 → 待评估身份和受影响范围 | 物品业务会话状态；有限合并、失效和清理，不跨角色保存、不建逐件永久来源账本 |
| 操作与结果 | typed 意图及业务前置/结果要求 → 完成、部分、拒绝、未知 | 业务定义资源/价值与部分结果；通用层仅做有效性、真实冲突、生命周期和传递 |
| 原版宿主适配 | 已准入操作 → 原版最小调用和真实观察 | Host 承担版本能力、线程、槽/商店/网络适配；不在中心 Host 堆名单或优先级 |
| UI 与配置 | 用户选择 → 偏好 revision、业务命令和有限反馈 | 业务/Settings 管语义，F5 管布局、命中、滚动和编辑态；机械 writer 不认识物品 |

仓库真实已有的是 F5/字体材质与输入隔离、偏好后台保存、一个 Feature 的 bool session 生命周期和宿主更新入口。`IGameOperationRequest` 只是空 marker，Outcome/Result 没有接入执行协调；`IGameSessionProbe` 只返回 bool。没有现成背包观察、完整 session generation、冲突租约、去重或权威结果收口。三项需要在这批中接入必要的窄能力，沿用[总体架构操作边界](../设计/总体架构与状态所有权.md#17-唯一游戏操作出口)与[跨功能准入](../设计/总体架构与状态所有权.md#20-跨功能协作准入)，不另建 Runtime、Session、全局工作流、功能名 switch 或反射业务分派。〔E19〕

后续编码前说明职责、状态 owner、输入输出；首条操作链通后立即检查结构，再接完三项。一个功能不是一个巨大类；持续吸收无关职责的中心文件要解释并及时作必要局部重构。文件长度只是线索，“约 600 行”不是硬门；不删注释、压代码或拆 partial 规避，不拆成互写全局变量的小文件。测试和脚本也按职责组织，不堆进巨型 Program 或总审计脚本；AI 业务代码照常审查。必要局部调整随本目标完成，不事后积成大整改，也不机械要求每个小操作一个接口/程序集。本轮不新增行数门禁或代码健康平台。

### 6.6 有针对性的性能输入

- 对应开关关闭后停止它的领域扫描、名单投影、容器查询和新意图；共用 Hook 最小早退。已开始/未知操作只做必要有限收口，不以“关闭零工作”丢掉安全责任。
- 出售先判实际商店，无店立即不适用，不扫描 NPC；启用、名单修改、开/换商店、物品/收藏/使用变化触发评估已有库存，不要求新获取。
- 三项需要同一时点事实时共享一次有限主包观察。可靠入口用于来源；无法可靠捕获的库存/收藏变化可用有界轮询兜底，后续设计说明槽规模、cadence、活动及停止条件，不为每种变化堆 Hook，也不把轮询差值当拾取。
- 没有合法存放候选就不查询目标；按需求查 600px 世界 Chest，不复制旧银行前检。缓存须有位置/会话/箱体变更与内容未知的失效规则，执行前重核锁定、占用、范围、容量；客机本地未知不能先当无目标拒绝合法服务端路径。频率由实际路径与验证确定，不固定全项目预算。
- 连续来源可合并重复“需要评估”信号，但不得丢失开启→直接接收和落地→后续拾取的因果；待处理有界，超容量不能覆盖正在负责的未知结果。等待中不反复提交相同请求或无目标扫描，没有无限重试/积压。
- Draw、输入高频路径和每个物品事件不反复读取配置、序列化、写日志、全世界扫描或建完整快照。配置 I/O 沿用后台机制；执行前的实时复核不能被缓存替代。
- 只留必要结果、原因和有限状态，不存每件物品永久历史，不增常驻高频遥测。按第 7 节验证无变化/持续输入/大名单/多箱/无目标/全关等成本；静态形态不证明 FPS，当前不跑基准或新建测量项目。

### 6.7 后续完整批次与内部顺序

三项整体需求及以下实施顺序方向已获接受，设计与实现尚未开始，等待后续实施任务授权。先确认职责/输入输出与 .8 能力/结果判据，再接共享必要观察及第一条操作链并检查结构，然后补齐三种规则、两个名单、三开关和配置反馈，最后进行三拓扑资源/输入/异常与限定成本验证。第一条可以在单人和纯逻辑中先做，最终交付仍必须三项完整，不以内部步骤缩水范围。

### 8.5 按路径区分本地结果与服务器权威

| 路径 | 前置与实际权限 | 可以观察的结果／仅提交的步骤 | 后续拒绝、部分、延迟和断线责任 |
