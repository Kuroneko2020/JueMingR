## 2. 一页使用摘要与真实入口

Legacy 的三项显示在 F5“更多信息”页，各有开启/关闭、配置及可绑定快捷键；初次均关闭，没有查到专属固定默认按键。位置行是“调整信息窗位置 → 开始”，不是第四个永久开关。三项和群系共用一块信息文字区域；完整/过滤鱼获也是旧同容器消费者，但不进入本轮恢复范围。（Z01–Z06）

| 能力 | 开启后的实际可见内容 | 条件不足时的旧表现 | 默认样式 |
| --- | --- | --- | --- |
| 世界感染 | `感染信息 神圣:X% 腐化:Y% 猩红:Z%`；三项独立，零值保留，无合计/纯净度/详情 | NPC 门失败或三字段全不可读则整行消失；部分失败错误地补成 0 | `#DDA0DD`，字号 0.72 |
| 幸运值 | 最终总值，紧跟十一类来源中的非零贡献及说明；无独立明细开关、展开窗或来源悬停 | NPC 门失败或总值读不到时全部消失；个别来源读不到被省略 | `#FAFAD2`，字号 0.72；正负不自动换色 |
| 渔夫任务 | 任务鱼名、角色累计完成次数、能解析时的地点、已完成时的“今日已交” | NPC 门失败则消失；映射失败存在假正常任务风险 | `#E0FFFF`，字号 0.72 |
| 调整信息窗位置 | 尝试隐藏 F5，等待一次新按下，拖整块信息窗，松手完成并返回 F5；无内容时临时画“信息窗” | 没有完整的取消/强制退出合同；保存失败也可能记录成功 | 全容器一份位置，不属于任何一项文字样式 |

三项实际样式副窗都有 H/S/L、六位 HTML 色、字号加减及恢复默认；旧字号范围 0.50–1.80，步长 0.10，没有透明度或动画设置。颜色/字号按项保存，恢复样式默认不重置信息窗位置。UI 与快捷键都写同一显示设置；旧 UI 同值命令仍会 `SaveAll`，不能继承为 R 的保存要求。（Z02、Z03、Z09）

位置注册器声称支持快捷键，但真实开关目标目录及统一快捷键策略没有位置目标，位置行也没有键盘入口。**本轮未证实旧位置快捷键实际接线**；新版可将其作为一次进入动作接公共系统，不另建绑定机制。（Z01、Z03）

## 3. 三个 NPC 前提：原版标记与当前存在不同

实际 `HasSavedNpc` 先读对应 `NPC.saved*`，为 true 立即通过；否则逐项扫描 `Main.npc`，仅 `active && type == 指定NPC` 通过。typed 数组存在就用它的结果，否则才尝试反射数组。没有自有“本会话曾观察过”集合、永久 NPC 历史或“任意城镇 NPC 即可”条件；没有金属探测器门。（Z05:447–506）

| 能力/NPC | 声明 | 当前 .8 与旧可达门 | 历史语义 |
| --- | --- | --- | --- |
| 感染／树妖 Dryad=20 | 这个世界曾存在，不要求活着 | T8 没有 `NPC.savedDryad`；实际回落为当前活动 20 | 死亡/离开后，下次行重建不显示。**与声明冲突**，不能写成永久解锁 |
| 幸运／巫师 Wizard=108 | 曾存在，不要求活着 | `savedWizard` 为真，或当前活动 108 | 原版世界保存/加载该标记；不是巫医 WitchDoctor=228，也不是受缚巫师 BoundWizard=106 |
| 任务／渔夫 Angler=369 | 曾存在，不要求活着 | `savedAngler` 为真，或当前活动 369 | 原版世界保存/加载该标记；获救/城镇 AI 可设真，不要求当前仍活动 |

T8 的 `AI_007_TownEntities_UpdateSavedStates` 对 108/369 设置标记；`WorldFile` 保存与恢复，`clearWorld` 清零。该原版事实不是旧插件自己的持久记录。当前选读的 `SendData/GetData` 未见这两个 saved 字段直接同步；活动 NPC 正常同步后，其本地 AI 可以设真，**不能由普通客机刚进入时的 false 证明世界从未出现过该 NPC**。（T8-N）

| 场景 | 树妖门 | 巫师/渔夫门及数据含义 |
| --- | --- | --- |
| 从未出现，可靠本地状态已就绪 | 无当前活动树妖就不显示 | saved 为 false 且无对应活动 NPC，不显示；只见受缚巫师不满足108门 |
| 曾出现但死亡/离开 | 没有历史记录，仍不显示 | 原版 saved 已可靠为 true 时继续有资格，不扫描 NPC |
| 单人重新进入旧世界 | 从当前 NPC 表判断 | 世界加载恢复原版标记；不等于信息值也已更新完毕 |
| 普通客机刚进入，NPC 未同步或当前已死 | 未看到20只能说明本地尚未看到活动树妖 | 无可靠历史输入时为未知；旧版把它当失败并隐藏，不能承诺永久历史可读 |
| 换世界/重连/换角色 | 不得沿用前一世界资格 | 原版清世界重置标记；旧行缓存有世界名#ID、玩家对象、tick 倒退失效，但没有完整连接代次合同 |
| 无可读世界/本地玩家不 active | 外层不构造状态窗 | 同左；玩家 dead 但仍 active 没有独立拒绝门，不能保证死态数据仍是完整新样本 |

三项在各次摘要重建中分别查同一 NPC 表；saved 为真有早退，树妖每次需要查活动表。没有先要求共享全部 NPC 状态的理由，但后续三个必要资格可在已有观察边界一次有限取得，不能依赖“NPC 显名已开启”。

## 4. 世界感染：口径、零与新鲜度

旧显示只读 `WorldGen.tGood/tEvil/tBlood`，分别对应神圣/腐化/猩红；格式 `0.##%`、InvariantCulture。T8 三字段实际为 byte，因此正常现成数据是整数，不表示拥有小数统计精度。全零仍显示三项0%；没有按零值隐藏、分色类别、感染总和或“纯净度”。三个读取全失败才隐藏；任意一个读取成功时其它失败的 out=0 会被正常格式化，这是错误降级。（Z05:185–207、521–543）

T8 `CountTiles` 在扫描列 X=0 时公布前一轮累计结果：三种计数各除 `totalSolid`、乘100、`Math.Round(double)`（默认中点取偶）后转 byte；有正计数但舍入0时至少报1。分母是原版可计类别的加权总和：普通类别 `tileCounts[2,477,1,60,53,161]` 加神圣/腐化/猩红计数集合，remix 分支还将474/195计入对应感染。它不是所有地图格数，也不是玩家探索比例或附近群系。

原版按列统计 active tile，y=40 到 `worldSurface+1` 区间权重5，以下到 `maxTilesY-40` 权重1。`LoadWorldTiles` 建立加载累积；`UpdateWorld` 在非客机角色每累计30次该更新计一列，横向循环后再公布。这里的30是原版世界更新调用次数，不是本文给 R 设定的刷新周期或现实等待时间。原版方法会写计数/状态，部分分支创建 Tile、处理 Skyblock 并广播；**不能为了得到“只读统计”而调用它**。（T8-I）

旧显示真实链没有调用全世界计数、树妖对话、主动网络请求或读取 .wld；R 旧摘要“不全世界扫 tile”在本批可达链上成立。状态面板与世界显名 Draw 分开，不经过后者的旧箱子导入/开箱记录。（Z04）

| 拓扑/状态 | 现成输入 | 能作出的结论 |
| --- | --- | --- |
| 单人 | 本地最近公布的三字节 | 可显示该次原版统计；不能承诺每次方块变化后立即准确 |
| 本机房主 | 须按实际客户端/权威角色区分；原版权威统计及对应客户端消息 | 同机不等于本地显示可绕过就绪与同步判断 |
| 普通客机 | 正常加入及原版后续公布时的消息57三字节 | 不在本机重计全世界；显示最近已接收统计，未收到不能解释为纯净世界 |
| 初始化0 | `clearWorld` 会将三字节清零 | 没有独立就绪证明，不能仅凭0判有效零 |
| 陈旧 | 上次统计/消息仍在 | 可标最近结果；不能编造没有来源的更新时间 |
| 部分未知或读取失败 | 有效性不完整 | 新版应明确未知/不可用，不拿默认0拼成完整统计 |

T8 客户端 EXE 内的正常 server 分支在玩家加入时发57，在 `CountTiles` 公布时广播57；客机只收三byte。未核对独立 `TerrariaServer.exe` 二进制，也未运行三拓扑。新版需要可靠区分“已收到/尚未收到”或“本地统计已公布”；目前 R 没有该就绪事实，不能靠延迟固定秒数或强制重扫补齐。（T8-I、T8-N）

## 5. 幸运值：权威总值与解释明细

旧总值直接来自 `LocalPlayer.luck`，不以来源之和替换。最多三位小数，正值带 `+`、负值带 `-`，绝对值<0.0005显示0；没有百分号、掉落倍率或提升概率换算。总值与来源共用一个显示开关和样式。旧读取未检查 NaN/Infinity，来源读失败则省略；两者均须在新版有效性判断中处理。（Z07）

来源按下表固定顺序，仅显示绝对贡献≥0.0005的项。首行前缀“来源:”，后续缩进、中文逗号分隔；按 UTF-16 长度44拆行，随后公共窗宽限制仍可能省略文字。不是鼠标悬停详情或单独副窗。无可见项显示“来源: 无”，但旧代码也把不可读项省略，所以这句话不证明全部来源已确认零。

| 显示项 | 旧读取与解释值 | T8 更新含义与限制 |
| --- | --- | --- |
| 瓢虫 | `ladyBugLuckTimeLeft=t`；正 `t/43200×0.2`，负 `-t/(-10800)×0.2`；附“剩XmYYs” | 原版同式；时间按dayRate向0变化。旧按60tick/秒换算，不是加速世界中的可靠现实倒计时 |
| 火把 | `torchLuck×0.2`，附原值 | 原版已汇总的环境值；普通计算末尾将负 torchLuck 夹0。旧测试中的负火把是假输入，不能当当前正常玩法 |
| 幸运药水 | `luckPotion×0.1`，附等级 | Buff257按剩余时间>36000、>18000、其余赋3/2/1；每正常更新重建，不是显示端再扫Buff |
| 风筝 | `kiteLuckLevel×0.1/3`，附等级 | Buff383按 `Clamp(buffTime/10800,0,3)`；不是直接计风筝实体数；三位显示会舍入 |
| 银河珍珠 | `usedGalaxyPearl` 真为+0.03 | 玩家永久使用事实；显示不使用物品、不读玩家文件 |
| 灯笼夜 | `LanternNight.LanternsUp` 真为+0.3 | 当前 getter 为自然或手动灯笼状态，无扫描；不能只认自然事件 |
| 花园侏儒 | `HasGardenGnomeNearby` 真为+0.2 | 原版 UpdateBiomes 从 SceneMetrics 刷新；旧显示不自行扫描侏儒 |
| 臭味 | `stinky` 真为−0.25 | 正常重置后由Buff120恢复；不能在中间重置态读成稳定0 |
| 装备 | `equipmentBasedLuckBonus` | 原版已汇总装备：LuckyClover +.03、WiltedClover −.1、RavenFeather −.1、LuckyHorseshoe +.05、LuckyCoin +.05；旧只显示合计，没有逐件列表 |
| 钱币 | 读 `coinLuck`，纯分档，附原值及阈值说明 | >249000→.2；>24900→.175；>2490→.15；>249→.125；>24.9→.1；>2.49→.075；>.249→.05；其它非0→.025，0→0。原版每次按 `.9999^dayRate` 衰减，<.25清0 |
| 破镜坏运 | `brokenMirrorBadLuck` 真为−0.25 | 原版按剩余时间更新布尔并扣dayRate；旧未显示这项剩余时间 |

T8 `RecalculateLuck` 依序将这些项累计写入 luck，无最终整体 clamp；旧解释公式与该版本一致，但旧 double 解释、原版 float 累计、显示舍入与省略小项不是位级相同。原版事实需取同次完成更新的样本；不能靠“可读十来个字段”保证组合一致或没有成本。

**旧差额是真实显示，却不是已证实的额外来源。** 旧代码以 `actualLuck-knownTotal` 补“其他/未解析 ±数值（player.luck差异）”，使显示加和接近总值。差额可能包含不可读项、小项省略或采样/舍入差异。新版建议继续把总值当权威、保留全部有依据的明细；部分不可读或不一致时诚实提示，不为凑和创造贡献或用缓存永久冻结变化。

| 方法 | 为什么不能作为普通显示取数 |
| --- | --- |
| `RecalculateLuck` | 逐步写玩家 luck，非只读 |
| `Player.RollLuck → GameContent.Luck.RollLuck` | 消耗 Main.rand，返回一次随机结果，不是当前幸运值 |
| `UpdateLuck` / `UpdateLuckFactors` | 衰减瓢虫/钱币/破镜、推进火把环境汇总；还可能发消息134 |
| `TryRecalculatingTorchLuck` | 普通地下每次最多一行81格、中心±40格，跨81行汇总；改计数/近邻标志，其它分支可 TorchAttack |

旧幸运 builder **没有调用这些方法，也没有自建环境扫描**，只读现成字段并做小型解释。T8 正常 `Player.Update` 中 ResetEffects→UpdateBuffs→UpdateEquips→UpdateLuck；R 宜在已有完成更新边界读取一致事实。位置/环境/装备/Buff/事件与时间变化应更新相应依赖；名称、固定说明、未变的可见数值不应反复排版。钱币原值和瓢虫秒数本来可能变化，不能只因贡献档位相同就删掉旧有意义明细。（T8-L）

## 6. 渔夫：世界任务、累计次数、当天完成分别读取

旧文本是 `渔夫任务: <鱼名或ID> / 完成:<次数>`，可解析时追加 `/ 位置:<地点>`，已交时追加 `/ 今日已交`。没有物品图标、倒计时、奖励预览、导航、自动交付或刷新任务。鱼名来自 `Lang.GetItemNameValue`；“完成”读 `LocalPlayer.anglerQuestsFinished`，是角色累计次数，不是今日布尔，也未用背包有鱼判断完成。（Z05:209–238、546–577）

| 事实 | 正常数据路径 | 旧缺口与新版边界 |
| --- | --- | --- |
| 世界当前任务 | `Main.anglerQuest → anglerQuestItemNetIDs[index]`，T8有41项映射 | 旧忽略读取失败，映射失败将index当itemId，未初始化0也可能取第一条正常鱼；新版必须验证任务输入、下标和正有效物品类型 |
| 个人今日状态 | T8本地 `Main.anglerQuestFinished` bool；旧兼容代码另尝试索引形式 | 客机消息74携带此玩家状态；未就绪false不能写成确定“未交” |
| 个人累计次数 | `LocalPlayer.anglerQuestsFinished` | 与当前任务独立；字段未知不能默认正常0 |
| 地点说明 | 旧先按内部物品名读本地化，抽取中文位置标记、英文Caught in或最后一对括号 | 解析不是完整原版任务对话；没有任意语言保证，失败应明确地点未取得 |

T8 `AnglerQuestSwap` 仅权威角色执行，先清今日名单与布尔，再随机选合法任务；并不排除与前一周期同鱼。正常换日来自 `UpdateTime_StartDay`，不是现实午夜。世界保存包含当前任务与当天已交名单；单人加载按当前玩家名字恢复本地布尔。多人正常加入/换任务由 `SendAnglerQuest` 给每位已连接玩家发消息74（任务index、该名字是否在名单），客机收两值；75向服务器登记交付，76同步累计次数。显示本身不发送这些请求。（T8-Q）

原版名单匹配是 `List<string>.Contains(player.name)` 的默认精确、区分大小写字符串比较，不是稳定 UUID。旧快捷改名兼容逻辑会按同样的名字匹配重算本地今日布尔，这只解释相邻功能为何能改变显示；本批不恢复改名、重置任务或私人任务历史。普通客机显示自己的布尔不需要取得全体名单，不能把其他玩家已交当自己已交。

**地点路径有已确认副作用风险。** 旧首选键是 `AnglerQuestText.<内部名>`，T8实际使用 `AnglerQuestText.Quest_<内部名>`。未核全部资源别名，不能写成所有材质/语言环境必然回退；但首选键与原版规范不匹配，可达 fallback 是 `Lang.AnglerQuestChat(false)`：未交分支写 `Main.npcChatCornerItem`，已交分支随机选 NoQuest 对话，因此已交后地点也可能消失。旧“只读显示”不能推广为整条链无副作用。新版应直接读取正确本地化键及所需地点，不调用聊天、任务选择或奖励流程。（Z05:240–408；T8-Q）

旧摘要每30游戏tick重建时重读鱼、累计次数、今日布尔及地点，不是任务变化才刷新。签名没有任务周期或个人状态；一般会在下次重建更新，但游戏语言不在专用revision中。新版须分别处理同鱼新周期、本人交付、语言、角色/世界/连接代次和正常消息到达；只缓存鱼ID会漏状态，只重建整个信息系统则浪费无关工作。

## 7. 信息窗：完整调整、坐标与保存

### 7.1 容器与正常流程

真实链为 `InformationStatusPanelOverlay → InformationOverlayService.DrawStatusPanel → InformationStatusLineService.GetLines → InformationStatusPanelService.DrawPanel`；冻结 src 中没有 `DrawInfoWindow` 符号。群系、感染、幸运总值及明细、两类鱼获、渔夫顺序加入共享行列表，使用一个左上角位置。（Z04–Z08）

1. “开始”先设置调整状态，再尝试隐藏 F5；若 Notes 离开保存失败，旧 `SetVisible(false)` 可拒绝隐藏，进入动作没有据此回滚调整状态。
2. 进入时 `waitingForFreshPress` 要先看到左键松开；打开按钮那次释放或已按住进入的尾缘不能直接成为真正拖动。
3. 之后新按下须命中整块信息窗，记住鼠标到左上角的偏移；不是只拖句柄。
4. 拖动直接改内存 `AppSettings.InformationPanelX/Y` 和 initialized；没有独立草稿或拖前备份。
5. 真正拖动后的释放结束整个调整模式、同步 SaveAll、记录“已保存”、重开 F5。原文“取消拖动”在这里是完成，不是撤销；原地按下释放也会保存。
6. 正常隐藏/重开未改选页/滚动，因此返回原页和原滚动；没有跨启动恢复这些瞬时状态的保证。

无可见信息时，调整模式临时显示一行“信息窗”及金黄外框/白内框，不开业务、不造默认配置。未发现恢复位置默认、吸附、锚定、各项独立移动、自由尺寸或帮助样例面板。样式恢复默认不是恢复位置。（Z02、Z03、Z08）

### 7.2 退出与失败矩阵

| 触发 | 旧实际行为/缺口 | 推荐 R 候选 |
| --- | --- | --- |
| 新拖动真实释放 | 保存并结束调整，返回 F5；无同值过滤 | 相同工作流；提交独立位置偏好，同值不写 |
| Esc/右键/F5/切页 | 无专用取消信息窗调整入口；F5主窗自身开关不清该静态状态 | 显式取消恢复进入前偏好；正常取消可返回原 F5 页，不以“取消”名义保存草稿 |
| 失焦/输入许可丢失 | 输入适配将LeftDown置false，面板自行推导released；若Draw继续，可能合成完成并SaveAll/重开F5 | 沿R失焦原则取消草稿、不提交、不自动重开；消费已归属尾缘 |
| 菜单、无active玩家、退出世界 | 外层不Draw，但没有清调整字段 | 清交互/旧会话引用；正常关闭/退出的收尾只使用最后有效样本，绝不重新采合成坐标 |
| 地图/特殊UI/视口或字体失效 | 没有完整专用终止合同 | 接现有安全呈现门；失效手势结束，不穿透或在旧几何上继续操作 |
| 保存失败 | 新内存位置仍在；返回值忽略，仍记录“已保存”及重开F5 | 保留当前已提交意图并提示未可靠落盘；旧完成不覆盖新意图，保护原件 |

正常关闭/世界退出是否接受已发生的有效拖动，采用现有 R F5 的最后有效样本收尾原则；失焦和显式取消则恢复拖前位置。其它会导致主窗不可呈现的退出不自动重开 F5。上述完整手势衔接与显式取消是候选，需要第10节工作流裁决，不声称旧版已经具有这些保护。

### 7.3 坐标、尺寸与数据归属

旧配置初值 X=20、Y=320、initialized=false；未初始化的实际显示使用 X=20、Y约为屏高45%，不是固定320。布局宽度从420起，随最长行增加、上限640，内边距6；长行省略，按行高累积总高度，没有窗内滚动。已初始化先按 `0…screenSize-48` 夹紧，再按整块宽高进一步投影。（Z08:212–295）

仅绘制夹紧不写回设置，所以内容变宽或视口暂时缩小时，旧版已经能保留原坐标并在恢复时重新投影；不能说旧版完全没有“偏好/实际位置”区别。但拖动直接写偏好，没有未提交草稿；在临时夹紧处原地释放也可能将投影变成新偏好。配置加载另将坐标限制到0…4096，不能把该历史常数当新版屏幕上限。

信息窗在 UI scale 层直接绘制，位置不减相机或跟随倒重力。鼠标却复用 F5 `LegacyUiInput.ReadMouse`，校正UI矩阵后又除 `LegacyMainUiScale.DrawScale`，信息窗没有同一额外绘制缩放；F5因尺寸收缩时存在显示/命中坐标不一致的静态风险。不能凭“都是屏幕位置”宣称 UI缩放、游戏缩放和全部窗口尺寸组合正确。（Z10）

旧位置/三开关/样式属于全局 `Documents/My Games/Terraria/JueMing-Z/config/appsettings.json`，`ConfigVersion=1`；按该数据根跨角色世界，不天然按游戏安装隔离。没有把感染、幸运或个人任务事实另存为本工具的历史。位置字段为 `InformationPanelX/Y/InformationPanelPositionInitialized`；不是 F5 主窗或 Notes 悬挂位置。（Z09）

拖动不主动逐帧落盘，释放在 Draw 调用内同步 SaveAll，持全局锁写 appsettings/features/hotkeys/unified-hotkeys 四份配置，底层还有同步重试等待。返回 `ConfigSaveSummary` 被位置调用忽略；成功诊断不等于磁盘成功。新版只复用 R 已有后台偏好/原子保存机械能力，独立信息窗位置意图、实际投影、拖动草稿和磁盘结果分责；不决定文件拆分、不迁移旧数据、不借用 F5/Notes 的状态。（Z03、Z08、Z09）

### 7.4 绘制与输入优先必须一起看

旧信息层优先位于 Map/Minimap 前，缺锚点依次尝试 Resource Bars、Inventory、Mouse Text；另有高层 fallback。F5与悬挂笔记是另外的层。历史“物品栏/容器/装备/小地图/生命魔力在上”的基准明确为 Terraria .6，不是当前 .8 完整验收。（Z10、H05）

普通只读显示不捕获输入，但每次处理仍读鼠标；调整中无论指针是否位于信息窗都全局捕获、设置 mouseInterface/blockMouse并清左右键字段。它没有按原版UI、F5、Notes真实遮挡取得唯一最高输入归属，视觉在下不证明输入也在下。R应复用现有输入许可/弹层/手势尾缘与真实绘制层，普通文字不拦输入；调整只对获归属的进入动作、命中与拖动承担捕获，不以遮挡矩形猜整个原版UI。（Z08、Z10；R04）

## 10. 新版候选与少量待确认差异
