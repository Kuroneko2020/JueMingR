# 视距解锁行为合同

本合同来自所有者委托的 `JMR-VIEW-UNLOCK-20261018-v1`。本轮是独立的新能力；任务授权、候选、验证、包和安装身份见 [#124](https://github.com/Kuroneko2020/JueMingR/issues/124)，不把任务合同或自动检查当作所有者体验接受。职责与原版接点见[实现设计](../设计/视距解锁实现设计.md)。

## 入口与操作

F5 地图页提供公开的“视距解锁”标准行，只有“开启”“关闭”两个按钮；名称悬停说明逐字为“可以调整到更大的视野范围”。首次没有设置时关闭，不要求隐藏资格或旅行菜单开启。

开启只放开调节范围，画面不会立即跳到预设倍率。随后使用原版世界缩放的放大、缩小按键，按住可连续调整；使用原版当前映射，重绑后仍有效。没有新的决明快捷键、绑键入口、倍率滑条、额外窗口或“打开”按钮。这是[默认绑键接入](本地短提示与快捷键反馈行为合同.md#后续功能的默认接入)的明确例外：本轮指定只沿原版缩放键，开关从 F5 操作。

原版聊天、文字编辑、录键、失焦及地图／拍照等非世界上下文不接受新的世界缩放动作；已被其它输入所有者消费的按键不会重新出现。UI 和全屏地图使用自己的缩放，世界视野改变不改变它们的大小。

## 关闭保留与生命周期

开关表示是否允许继续向普通范围之外扩大视野，与当前倍率、当前画面所需的外围绘制是三种不同事实。

| 当前条件与操作 | 结果 |
| --- | --- |
| 关闭后开启 | 保持当前倍率，允许之后用原键扩大视野 |
| 已调到超范围后关闭 | 目标倍率与完整画面保持，不自动弹回；标准行显示关闭 |
| 关闭且仍超范围，未按缩放键 | 保持当前选择及必要外围绘制 |
| 关闭且仍超范围，按原版放大键 | 从当前倍率逐步调回普通范围，第一下不跳回边界 |
| 关闭且仍超范围，按原版缩小键 | 不继续向外扩大；重新开启后才可再次扩大 |
| 已回普通范围且关闭 | 按原版普通上下限运行，额外外围工作按实际需要退出 |

开关 F5、暂时切入全屏地图、选项、拍照或失焦不重置已选倍率。特殊画面按自身坐标绘制；返回世界继续使用原版当前目标。倍率优先属于原版 `Main.GameZoomTarget`，本功能不新增跨启动倍率恢复服务，也不把倍率写入角色或世界存档。真正重新启动后的倍率沿原版自己的设置持久规则。

设备或资源故障与普通关闭分别处理：必要原版接点不符时不安装半套解锁；发生实际资源／绘制失败时停止新的不受支持倍率，保留或回退到已确认能正确绘制的安全状态，并通过现有错误通道说明原因。不得无限逐帧重试。

## 可见内容与相邻能力

扩展后的画面应正确显示当前世界中客户端真实掌握的图格、墙、液体、光照、实体与必要世界效果。正常暗区仍然暗，不增加全亮、透视、全地图揭示，也不只缩小中央画面后遗漏外围。

玩家中心辅助瞄准的候选范围按当前真实相机扩展，保留既有距离排序与模式含义；光标中心的世界半径不因缩放自动变大。目标标记、预测、显名、工具选区与原版实际指点沿最终相机对齐。视野扩大不扩大攻击、挖掘、交互或服务端权限，不改变实体生成、AI 或退场规则，不恢复已撤红框和整组未来精算。

单人与普通客机按实际掌握的数据显示；客机未知区继续保持未知，不能当作空气供查询或操作使用。已收到区块不代表远处所有实体都已同步。具体取得的网络范围与限制由本任务实际原版请求链及联网证据说明。

普通客机需要当前视口的未知区块时，复用原版单区块请求，逐次更新最多新增一个请求、最多跟踪16个在途区块。同一区块收到前去重，只有原版实际解码完成才成为已知。视口移开时释放旧区块的本地跟踪，不声称撤回已发送的网络数据。当前仍需要的区块经过300次更新未收到，或请求发送发生异常时，停止额外请求并给出一次必要反馈；调回普通视野后可重试。关闭开关但仍保留宽视野时，当前实际视口仍承担这些必要责任。

## 配置与反馈

开关是当前游戏安装下跨角色、世界共享的普通偏好。唯一文档为 `JueMingRData/config/features/view-unlock.json`，UTF-8、`format="JueMingR.View"`、`version=1`、布尔 `enabled`；缺文件默认关闭且不预写默认 JSON，不含倍率、角色或世界身份字段。只存开关，不增加倍率历史或恢复服务。

复用 [PreferenceDocument 与原子文件合同](../设计/配置持久化与用户数据布局.md)。读取完成前拒绝修改；真实点击改变本次内存选择并按现有后台保存流程请求持久化。损坏、未来版本、未知字段、占用、外部变化及未确认提交保护原文件；保存失败不悄悄重置本次倍率或开关。安装、恢复与卸载保留该文件为用户数据。

普通 F5 成功点击、加载与保存保持静默，不产生开关短提示或新增状态行。真实读取／保存或能力失败使用现有必要错误通道和不可用悬停；普通名称提示保留既定原文。此功能不注册 R 开关快捷键，因此没有快捷键开关回执消费者。

## 有限支持与验证

安全倍率下限必须由锁定 Terraria 版本的完整画面、设备容量和有限成本对照共同决定；未指定“无限视野”，不把参考实现的 30% 或更大放大上限直接当作产品保证。实际支持范围、光照路径、分辨率及设备差异、普通客机证据、成本与未验证边界由 [#124](https://github.com/Kuroneko2020/JueMingR/issues/124) 的固定候选证据承担。

本轮实现以原版目标倍率50%为基础下限；更大的物理视口还受原版强制倍率及现有观察范围容量约束，实际可用下限可提高。50%不是任意分辨率或设备上的保证，也不改变原版普通放大上限。本轮锁定 Windows Steam Terraria1.4.5.8，原版隔离专项覆盖1920×1080、1280×720与实际尺寸切换；1920×1080的50%最终矩阵对应3840×2160世界像素范围。Color、White、Retro、Trippy四条光照路径、外围图格／墙／液体／实体及必要画面效果和关闭保留按实际专项取证；其它设备、4K、30%倍率和所有者体验不因此自动通过。

原版专服与完整初始化客机之间的实际 TCP 专项已覆盖正常握手、当前未知区块请求、原版回执解码、去重、数量和失败边界，并将实际收到的冷区交给原版1920×1080、50%矩阵绘制。它由有限网络泵与真实 Draw 组成，不等于完整客户端模拟、Host & Play、远程网络条件或所有者多人验收；本场景实际收到NPC，掉落物及弹体收包为零，不扩称这些实体的联网生命周期已测。

扩展视野有实际绘制成本。修复前候选的隔离场景原版 Draw 对照中，普通倍率关闭／开启的均值约2.24／2.42毫秒，50%宽视野开启／关闭保留约15.62／14.70毫秒；样本量、设置、失败处置和确切候选由任务固定证据保留。这是受控场景 Draw 计时，不是完整帧时、FPS、普遍性能保证或“零成本”结论。

CPU 行布局／命令／配置检查只证明其实际断言。原版已映射输入、真正外围绘制、实际攻击、联网、帧时和所有者体验分别验证，互不代替；不能用倍率字段或 R 自己的叠加层冒称原版外围已经画出。

75%／50%／30%的隔离参考探点已分别实际绘制；30%探点只存在于测试进程，量化后约29.69%，本机受控洞穴Draw平均约42–43ms，明显高于50%约18–21ms，分配量也增加。因此本候选保留50%基础下限；上述参考不构成30%产品支持或其他设备性能承诺。
集中独审发现并修复普通NPC的外围粗筛、场景filter及水波消费、旧光照额外扩容失败边界。宽视野与关闭保留均继续消费原版活跃场景效果；水波保留质量、重力、真实液体与原生队列规则。必要GPU资源失败属于异常恢复：停止本次owner新的解锁，普通安全倍率继续绘制、现有错误通道反馈一次；与正常关闭保留宽视野的行为区分。原版无关异常不被统一吞掉。

修复后的原版Draw开发对照约为普通关闭返回1.93ms、普通开启2.57ms、宽开启15.69ms、关闭保留13.94ms；活跃水波普通/宽/保留各30次约2.56/21.93/21.87ms，稳定资源没有逐帧重建。新参考75/50/30静止与移动约10.97/11.31、20.21/20.80、41.69/42.02ms，仍支持50%基础下限的选择。上述开发样本入口为`repair-full-09`，准确候选身份和正式检测由任务记录承担；旧样本保留自身身份，不能改签为新执行结果。

连续调节宽视野时，足够的水波容量保持复用：向内缩小或在相邻容量桶来回，不应反复重建资源和清掉已有波纹。只有实际需要超出现有容量，或设备／模式／额外渲染生命周期结束时，才按需准备或释放。水面绘制失败只退休本功能自己的未完成批次，准确归还原版共享引用及进入前的设备绘制状态；实际资源失败仍按既有一次反馈／安全普通倍率处置，未知原版异常保留原传播。
