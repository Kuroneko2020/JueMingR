# 保持收藏与快捷物品使用行为合同

本阶段保持收藏与快捷物品使用实现，以及分装新堆不自动收藏、鼠标快捷手势归属两项追加修订，已获所有者接受，随本次合并进入 `main` 生效。实际状态、接受范围、验证与交付身份查 [G05 #91](https://github.com/Kuroneko2020/JueMingR/issues/91)；源码接受不表示最新修订已经安装，也不补造游戏内实测或真实多人通过记录。实现依据见[实现设计](../设计/保持收藏与快捷物品使用实现设计.md)。

## 默认与三个动作

保持收藏和快捷物品分别默认关闭、独立保存；快捷物品条目为空，所有新动作未绑定。物品页分别提供两个主开关及其公共快捷键入口。每条快捷物品还有独立的“使用键”；总开关键只切能力，不使用物品，能力关闭时仍能用总开关键开启。

条目按稳定 ID 保存，改名、排序或换目标不换身份，删除后新建不用旧身份。条目可添加、编辑、启停、删除；一次新的有效按下只请求一次，不连点、不排宏。使用收藏物品是明确的玩家意图，仍允许原版消耗。

## 收藏保持域

保持的是这件实物或原版有据完整转移/合并结果的收藏意图，不是同类型、同前缀或同名物品的永久偏好。只改必要标记，不补数量、不回滚 Item、不生成物品。

| 情境 | 已接受的范围与边界 |
| --- | --- |
| 快捷栏及主包 0—49 调换、拖动、原版排序 | 跟随实际转移。排序本来跳过收藏物品，不强行改变原版排序规则。 |
| 当前功能装备、社交装备/饰品及 MiscEquips | 意图跟随真实交换；这些槽期间保留意图，不把收藏标记写成装备组共享。返回可收藏背包槽再恢复。 |
| 装备组切换 | 只交接当前已知物品的真实关系，再激活时核验；不扫描和改写所有未知非激活组。 |
| 鼠标拿起再放回 | 仅有来源中转，保持独立实物关系，不强制放回、不污染无关鼠标物品。 |
| 垃圾桶取回 | 原物仍在时保留往返关系；覆盖、真正销毁或来源失效即结束，不恢复已删物。 |
| 合法状态转换 | 按实际转换前后传递，包括水桶和下表状态族；同用途不同物品不是同一实物。 |
| 分堆 | 从收藏堆分出的新堆不自动收藏，原余量继续保持；连续右键取出并放回背包也一样。新堆已有或手动设置的收藏不清除。来源最后一件完整转移、整堆搬动仍保持；正常合入已有栈沿下列合堆规则。 |
| 合堆 | 原版允许合并且任一输入仍有有效意图时，结果栈保持收藏；不建立部分数量收藏。主动取消优先。 |
| 钱币/弹药专用槽、独立染料、未知非激活装备组 | 不主动全量追踪或补标；原版已有标记保持。 |
| 箱子、银行、虚空储物、展示家具、交给别人 | 离开保持域，结束旧补标记资格；不主动清原版 favorite，不扫描外部容器。 |
| 丢地再捡、购买、制作、奖励、死亡掉落后取得 | 新取得关系，不按旧 type/名称补标；尊重当前原版事实。 |
| 主动取消 | 立即撤销该件及相应有据关系的旧资格；后续移动、变形、快捷使用和迟到回调不补回。 |
| 全量消耗、销毁、出售、交出、角色/世界/连接更换 | 退休对应运行记忆，不复活旧实例，不跨会话。短暂不可读不当成空库存或新身份。 |

Terraria 1.4.5.8 的装备 `favorited` 用于“装备组共享”，不等同于背包收藏；共享开关仍由原版控制，不由本功能打开、关闭或解释成背包取消。装备期间独立保留先前可靠收藏意图，避免把“保持收藏”变成改变配装。主包上的真实取消收藏入口决定新意图。

关闭时停止恢复并清运行记忆，已有原版收藏不清除。重新开启只从当前可靠的背包收藏重新观察，不追溯关闭期间的变化。收藏记忆不写跨角色历史文件，不因正常长期持有而计时淘汰。恢复会使现有存/卖/扔重新核验来源资格，不产生一次新拾取，也不解除别人的未确认占用。

## 条目目标、多状态与提供者

每条明确指定一次目标：正常使用、设置形态、先设置形态再使用。实物家族、目标用途和可用提供者分别表示；贝壳电话四个目的地可分别建立条目并绑定，个人出生点和世界出生点始终分开。已切到的目标形态保留；使用失败不谎称形态恢复，后来人工切形态也不被旧收尾覆盖。

以当前原版右键转换表逐项核验旧九族，并补入当前弹药切换四状态和旧式跑酷指南开关；隐藏 dummy 不作为可绑定目的地，真实发现单件时沿原版 5437→5358 的恢复边再到合法目标。详细符号、转换方向、当前中文名、原版条件和同步入口由实现设计中的固定原版证据表承载。工具、武器与被动物品按实际类别分别提供使用或设置状态，不因没有动画判定合法状态设置失败。

| 用途 | 经原版同一效果分支核对的稳定提供者顺序 |
| --- | --- |
| 回个人出生点（不消耗道具） | 魔镜 50 → 冰雪镜 3199 → 手机 3124 → 贝壳电话 5358 |
| 前往海洋 | 魔法海螺 4263 → 贝壳电话海洋 5360 |
| 前往地狱 | 恶魔海螺 4819 → 贝壳电话地狱 5361 |
| 回世界出生点 | 贝壳电话世界出生点 5359；不混入个人出生点组 |
| 其它物品 | 按该物品明确目标使用，不凭 useStyle、名称或图标自动归组 |

首选实物存在且合法可用时优先；其后先取已经处于目标状态的提供者，再取需合法变形者，各层按表顺序。相同种类优先当前合法选槽、快捷栏、主包，再按稳定槽序。“仅此物品”禁止跨实物提供者替代，但仍允许同一实物的合法形态转换。快捷来源仅为 0—49；鼠标拿着物品时拒绝新快捷使用，不借用 58，不从箱子、银行、装备或别人库存取货。收藏功能对有来源鼠标/58镜像的支持是另一项职责。

回忆/返回药水不默认加入无消耗回家组；不混不同代价的传送杖、回复量或副作用不同的药品、普通与特殊捕虫工具。一次最多实际操作一个提供者；只有确定没有变形、使用、消费等副作用时才可有限改选，已执行或结果未知不换第二件重试。

## 归位与快速连续输入

优先直接选择真实背包槽，不造临时物品格、不复制到鼠标。四种责任分开：实际搬动过才归还位置；无人改选时恢复原选择；释放自己的合成输入与目标；保留真实形态、消费和效果。

| 输入或中断 | 预期 |
| --- | --- |
| 持续移动、跳跃、修饰键 | 仍及时归还选择，不等全部键松开。 |
| 数字/滚轮明确改选，或原版明确改变选择 | 保留最新人工选择，同时清完旧借用。 |
| 同键连按、两个条目连按/同时按 | 同时只一个真实使用；已忙明确不受理，不排延迟宏。旧 A 回调不影响 B。 |
| 新物理攻击或持续使用 | 保护玩家后续输入；必要时中止尚未完成快捷操作，不让旧恢复更换新攻击使用的物品。 |
| F5、聊天、地图、模态或失焦 | 阻止新使用，安全收尾已发生动作；恢复焦点不重放旧按下。 |
| 关闭、禁用、删除、旧保存完成 | 退休旧请求并必要收尾；旧回调不复活条目。 |
| 消耗为零或合法变形 | 不还旧数量/旧 type，不阻止选择和输入清理。 |
| 暂停、死亡、换会话、保存退出、异常 | 按真实原版阶段结束，不用现实超时重放已执行效果，不写旧库存。 |

正常完成与设置形态不逐次刷“成功”。请求未执行与异常明确分类：输入／原版接管等正常让路保持静默；找不到合适物品或正忙等必要请求失败给一次本地反馈，按住不重复刷屏。真正异常不能被同次操作的正常收尾擦除。动画、本地调用、效果观察与服务器确认分别解释。

## G06 追加的物品页呈现

本节呈现修订已随 [G06 #93](https://github.com/Kuroneko2020/JueMingR/issues/93) 获所有者接受，随 [PR #94](https://github.com/Kuroneko2020/JueMingR/pull/94) 合并进入 `main` 生效，不改写 G05 历史接受记录。两个开关的正常加载／保存／完成不插入或预留文字行，保存中的控件禁用、执行暂停和可靠生效边界保持。功能行间距沿公共行尺度交接；物品图标、使用键、编辑控件、选择器和必要空结果说明完整保留。

保存失败、提交未确认、能力不可用及旧绑定清理失败沿既有本地出口提醒一次，未解决原因可从对应功能名称悬停再次查看。两个开关、各条目和绑定清理各自保留失败事实；无关保存成功不清错，重试开始不算恢复，新失败仍可提醒。未知提交继续保护文件及执行。名称说明变化不占高度、不触发整页重建，也不因悬停扫描背包或读文件。

软核死亡不清掉仍随身保留的装备意图；真正死亡掉落结束原关系。原版自然使用结束后立即接受新的按下，不因旧操作尚未走到下一次选槽更新而丢掉第一帧输入。普通完整连发先自然结束；只有明确取消/人工接管才缓冲返回，避免截断末发。

## 公共输入与保存

仍使用唯一公共采样、精确左右修饰组合、新主键沿、冲突表和录入小窗。文本/IME、查询、笔记、录入及其它占用场景不使用物品；录入键不穿透攻击。总开关同更新关闭时阻止新操作；开启不重放已经按住的使用键。

Mouse1—Mouse5 及其修饰组合可以作为使用键，包括与原版“使用物品”重合的键盘键或侧键。本次快捷手势对使用物品、使用图格、智能选择的贡献由公共输入层消费；长按只执行一次，即使已经归位也不误用原选中物品。主键和修饰键各自真实释放后恢复正常输入。已有的独立攻击仍阻止快捷使用；后来新发生的独立攻击、数字键、滚轮和另一快捷项继续按上述接管/忙碌规则处理。找不到提供者或正忙也不把已识别的快捷手势转成普通攻击。

键位只在 `config/hotkeys.json`；领域条目与两个开关在安装内独立配置，不另存可执行 chord。条目可靠保存后才注册/绑定；动态删除先阻止执行，成功删除后清理该 ID 的绑定记录。半成功时孤儿绑定不执行，绑定清理失败不删其它未知动作；领域删除失败明确保留受阻状态，不报告成功。损坏、未来版本、外部冲突与未知提交保护原件，不用空列表覆盖，不自动读 Z 配置。容量同时遵守领域条目、核心动作、公共绑定条数和文件字节上限，满时明确拒绝，不截断。

## 验证与多人边界

普通客户端连接原版服务器是目标，不要求服务器安装 R 或新协议；选择、形态、消耗、投射与传送分别复用原版出口。收藏意图主要属于本机；不写远端库存、不批量同步全包弥补归位错误。实际多人体验、Windows IME、全部资源包及帧时由相应实测说明，隔离 `netMode=1` 不是联网验收。

所有技术用例使用独立临时数据和受控原版适配，不访问真实物品/存档，不自动启动游戏/服务器或发送真实聊天。各轮验证、包与安装保留原始身份；本次接受与合并不授权重新打包安装、发布或下一批开发。
