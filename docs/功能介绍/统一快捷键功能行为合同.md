## 1. 给所有者的一页摘要

旧版有四类不同用途，不能合成一张“全部按键都一样”的表：

| 用途 | 玩家怎样设置和使用 | 提取结论 |
| --- | --- | --- |
| 功能主开关、主模式 | F5 功能行最右双击 keyboard → 小窗单击“开始录入” → 按组合立即保存 → 看当前绑定和结果 → 关闭小窗；之后在允许的游戏场景按键切开关 | 63 个登记目标；多模式按历史模式回切。自动回血/回蓝有可绑定但拒绝切换的源码反例，不能称 63 项均可用 |
| 单次动作 | 蓝图七个动作、快捷物品、挖矿采集、快捷宣告各有局部键框；按键进入该功能自己的动作流程 | 已共用底层绑定和查询；入口单双击、允许键、错误显示仍不同。采集按键启动后续持续挖矿，不是按住采集键才挖 |
| 按住、局部编辑和固定入口 | F5 固定开关；战斗左右键手势；Shift+右键持续开袋；笔记编辑、地图选标记等 | 有各自输入 owner 或业务门，未统一为可配置动作；盘点不等于批准全部可重绑定 |
| 退休、开发或接线有问题的项 | 旧 N/直接打开蓝图页已停用；诊断热键仅诊断覆盖层；`hotkeys` 页名实际通向笔记 | 不能按类名、旧字段或图标认定普通可用能力 |

**旧版统一到了公共键目录、解析、录入服务、统一键文件、保存时的内部同组合检查、运行缓存和按下沿查询。没有统一到同一帧只采一次、完整冲突仲裁、跨消费者消费和可靠取消/落盘。** 例如 `K` 与 `LCtrl+K` 可同时满足；两个 ID 不共享消费；一些消费者遇到第一项事件就返回，后项可能下一帧才看见按住。F5 打开本身会阻挡普通统一热键，但固定 F5 与编辑按键独立处理。[Z01–Z08、Z16–Z19]

两个尤其值得避免的旧结果：保存失败前内存已经换成新键，局部键框又可能不显示失败；关闭 F5 或离开局部录入页，没有统一结束所有捕获。旧经验中的“阻挡时更新边沿”是正确的局部修法，但生产物理读键自身也会把输入不许可变成 false，不能据此宣称恢复绝无误触。[Z03–Z05、Z10–Z15]

**已接受首轮：群系显示、自动堆叠、自动出售、自动丢弃共用完整键鼠绑定，默认未绑定。** 零至三个左右修饰键加一个主键，以精确修饰集合和主键新按下沿请求正常设置命令，不绕过业务安全门。四项均从行尾键盘双击进入同一小窗，包含群系入口。原版冲突只在设置时检查，成功后不监控或自动停用；集中页、导入和未实现业务不在首轮，见第 7 节。

## 2. 全部入口与消费者索引

### 2.1 主开关的共用行为

下表每项 binding ID 均为 `feature.toggle.` 加列出的 target ID。共同属性：**可配置、首次未绑定、F5 行尾 keyboard 双击入口、保存 UI 至多一个左右修饰键加键盘主键、组合从未满足到满足时尝试一次**。当前统一 gate 要求在世界且游戏/UI/文本条件允许；F5 可见也阻挡。绑定归 `unified-hotkeys.json`，功能开关仍归原功能设置，模式历史归 `hotkeys.json`。[Z01、Z02、Z06、Z08–Z10]

真实链路为：页面共同行注册 `feature-toggle-hotkey-open:<target>` → UI 命令 → 录入/保存 → `RuntimeAutomationDispatcher` → `FeatureToggleHotkeyService` → `FeatureToggleProfile.Toggle` → 原设置/服务 setter → `SaveAll`。它不提交用物品、挖矿或宣告动作；“开了自动化”之后该功能是否行动仍由自己的规则决定。[Z09、Z16]

**源码反例：自动回血、自动回蓝。** Catalog 把两项登记成 Binary，而实际 switch 调用 `ToggleMulti`；模式规范化明确拒绝非 Multi target。因此当前非 Off 时返回 `invalidCurrentMode`，Off 时返回 `noLastNonOffMode`。这是“有录入、有接线、应用拒绝”，不是完全未接线，也不是新版应继承的模式语义。本轮不修 Legacy。[Z08、Z16]

| 通用 Ctrl/Alt/Shift、AltGr | 公共 parser 明确拒绝；不是“左右任一”的别名 | 旧文字示例的 Ctrl+K/Alt+K 不能当当前合法存储；兼容测试桥映射左侧不等于生产导入 |
| 鼠标 | 左、右、中、X1、X2 有 token/虚拟键 | 主开关/蓝图保存入口禁止；快捷物品/采集/宣告允许 |
| 保留键 | Esc、Backspace、F5 一律不能作为普通绑定主键 | 修饰后也保留；单独 Esc/Backspace 在录入另作取消/清除 |
| 滚轮/手柄/其它 | 滚轮 token 明确 unsupported；没有手柄、OEM 标点、Win、CapsLock、NumLock、媒体键目录 | 不是新增支持清单。未知 token 拒绝，录入轮询未列出的物理键可能没有结果，而非一定出现失败提示 |

token 忽略大小写与首尾空白；修饰键按左 Ctrl、右 Ctrl、左 Alt、右 Alt、左 Shift、右 Shift 排序。要求恰有一个主键，重复修饰、多主键及无主键拒绝。`Del/PgUp/PgDown/Spacebar/Escape`、Numpad 数字、鼠标 Button/Mouse1–5 别名按目录归一。显示 `Num+` 对应存储 `NumPlus`；parser 用 `+` 分割，显示文本不保证可原样写回。[Z01]

**文件路径与 UI 不同。** 加载 `NormalizeBindings` 和运行 `BuildRegistrations` 只 parse，未执行入口 policy。可解析但超修饰数/含被该入口禁止鼠标的文件绑定仍可能进入运行缓存；重复完整组合也不会在加载时裁定赢家。不能把生产 UI 保存检查写成不可绕过的全局合同。[Z02、Z04、Z05]

### 3.2 从点击到结束

主开关双击判定采用同 element ID、500 ms 内、横纵各不超过6单位，未读取 Windows 系统双击偏好。小窗实际锚定被点按钮：优先下方，容不下放上方，再夹视口；只有无 anchor 才居中。标称 368×184，布局带最小宽高300/150；并非已证明任意小窗口可读。[Z10]

| 操作 / 状态 | 当前实际结果 |
| --- | --- |
| 看已有绑定 | 主小窗显示“当前”、提示、“开始录入/清除/关闭”；局部框显示已绑定键或未绑定。主行 keyboard 本身不是完整键名表 |
| 开始录入 | Seed 记住此刻已按住键，启动点击不会立即变新主键；已按住修饰键仍可加入后来的新主键，不要求全部先松手 |
| 普通候选 | 按目录顺序遇到第一个新主键沿就读取当前修饰键、形成结果并立即尝试保存；没有确认按钮、松开后提交或完整未提交草稿 |
| 多个同时新主键 | 第一个目录项胜出，不是整帧组合快照；之后其它键读取还可能发生在另一时刻 |
| Esc / Backspace | 单独按分别取消/清整条绑定；带修饰时报保留键错误。所有有结果的情况都会结束本次捕获 |
| 主小窗结果 | 成功/失败/取消/清空后保留小窗，只退出录入，让玩家看结果；“关闭”才主动关小窗 |

| 重置 | 主小窗有清除；局部 Backspace 清除；物品另有取消录入/删除条目。所查入口没有恢复默认键按钮 |
| 再开另一录入 | 五类开始入口互相停止旧捕获，主小窗打开/开始同样处理；并非多个独立捕获同时生效 |
| 点击外部 | 没有通用外部点击取消；overlay 仅在自己的 Bounds 优先命中。允许鼠标录入的类别，启动点击释放后的新鼠标点击可能成为绑定 |

**可见文案与实际策略不一致的三处**：主小窗称支持鼠标而保存策略禁止；宣告前两格称不支持鼠标，但任一格实际都是整组录入；蓝图局部框沿用“采集按键”文案。保留这些来源差异，不把它们拼成更完整的旧能力。[Z02、Z10、Z13、Z14]

## 4. 触发、冲突与输入所有权

### 4.1 组合怎样匹配

运行只要求绑定列出的修饰键和主键全部按住，**允许额外修饰键**。按住 K 后再按 LCtrl，也可使 `LCtrl+K` 从不满足变满足；只松开/重按该修饰键也可产生下一沿，不要求主键一定先松开。短按/长按没有独立分类；统一查询本身只产生组合按下沿，持续业务属于消费者。[Z05]

每次 `QueryBinding` 即时读键，按 binding ID 保存 WasDown。相同 ID 再查会 idle，不同 ID 不共享输入消费。没有统一帧号、冻结的物理样本或全局赢家；查询返回 Accepted 也不等于业务命令执行成功。[Z05]

### 4.2 冲突防到了哪里

| 冲突类别 | 录入/保存时 | 运行时 |
| --- | --- | --- |
| 决明内完全相同 canonical 组合 | 拒绝，返回冲突功能名；没有强制覆盖；禁用功能/禁用条目的已识别绑定也占用 | 直接文件已有重复不在加载阶段去重；不同 ID 各自可命中 |
| K 与 LCtrl+K、左/右组合重叠 | 不是相同字符串，允许 | 额外修饰不排除，两者可共同满足；不具备“最长组合优先” |
| 不同消费者与场景重用 | 注册表跨主开关/动作类型比同组合，不按场景区分；不证明运行全部路径排他 | 蓝图→主开关有顺序；宣告还在更早 prefix，物品/采集随后。各消费者保留自己的 gate/业务门 |
| Terraria 当前改键 | 没有读取当前玩家键位；无实际警告或 hard fail 路径，Space 有明确允许测试断言 | 公共层不消费原版键；可能并行触发，鼠标宣告另有自己的局部消费 |
| F5 / 诊断固定组合 | F5 主键全局保留；固定 Ctrl+Alt 诊断组未纳入完整组合注册仲裁 | F5/诊断独立读键；不能借旧 FeatureToggleHotkeyConflictRegistry 残留就声称生产已防住 |
| 聊天、笔记、名单、地图、录入 | 不是重绑定覆盖策略，主要是 gate/局部 owner | F5 可见、文本/录入等阻挡统一查询结果，具体时序仍受调用方和物理读键门影响 |
| 系统保留组合 | 仅 Esc/Backspace/F5 主键保留，不是 Windows 保留组合库 | 没有系统级拦截保证；`LAlt+F4`/`RAlt+F4` 等可解析组合不因此受本工具可靠控制 |

证据：[Z01、Z02、Z05、Z06、Z16–Z21、Z27]。只有主小窗实际显示冲突消息，不能把公共 reason catalog 当全部局部框都有提示。[Z10–Z14]

主开关遍历63项，遇首个 PressedEdge（含 blocked）就 return；蓝图按创建→保存→移动→区域→镜像→库→列表尝试，事件后返回；快捷物品成功入队才 break。**推断反例**：重叠键的前项本轮先返回，后项未采样，下一轮仍按住时才首次观察 down，可能延后一轮执行。既非统一优先级，也非同一帧完整仲裁；本轮未运行复现。[Z16–Z20]

### 4.3 前台、物理状态和 UI 所有权

公共 context 中 `Foreground=true` 是常量，但 `GameInputAvailable` 走 `TerrariaMainCompat.AllowsInputProcessing`：它先查 OS 前台进程/owner 链，查询失败回退 FocusHelper，再失败可返回 true；某些主窗句柄为零分支也允许。因此不能只看字段名说“完全没有前台保护”，也不能说所有失败都关闭。[Z06、Z07]

gate 按主菜单/世界、前台与输入可用、NPC对话、Legacy modal、颜色/名称/F5文本、Terraria文本、录入、UI交互/F5可见等条件返回原因。F5“仅可见”本身足以阻挡普通统一键；物品选择、宣告和业务还有额外条件。它不是一份可复用于所有入口的单一 busy bool。[Z06、Z17–Z19]

边沿保护必须区分三种路径：

| 路径 | 实际保存的沿状态与限制 |
| --- | --- |
| 测试字典仍报告 down，仅 context 阻挡 | Query 先记录 true 再 blocked；持续查询不会放开 gate 后补同一沿 |
| 生产 Physical 的 AllowsInputProcessing=false | 原始读键函数先短路为 false；Query 将 WasDown 写 false并 idle，甚至不评估 gate。许可恢复但键仍按住，可形成新沿 |
| 调用方整体跳过 Query | WasDown 不更新。旧值false时恢复可能新沿；旧值true通常继续抑制，直到某次查询看见false |

targeting 输入不允许时整段跳过；快捷物品总开关/条目/前置条件、采集模式/手持镐也可能跳过。宣告 prefix 则可能继续 Query 并清沿。**源码不能证明全局“失焦期间跟踪真实按住、恢复必须松手才触发”保证**；重新激活误触是有路径的条件反例，尚未实机复现。[Z05–Z07、Z16–Z19]

公共层不消费原版输入。鼠标宣告、F5、蓝图选区、地图和文本各自消费/持有自己的状态；OS 重新读取可以绕开已经写成 false 的原版鼠标。因此“消费原版点击”“物理仍按住”“前台许可”“当前 UI owner”“功能愿不愿执行”须分别表达。旧录入未给出整体不触发原版操作的证明，不把已有 seed 断言扩大到这一结论。[Z03、Z05、Z15、Z19、Z21–Z25]

## 5. 配置、性能形态与旧坑

### 5.1 实际保存归属

| 数据 | 旧生产角色与保护 |
| --- | --- |
| `unified-hotkeys.json` | ConfigVersion=1、BindingsById。默认只含宣告组合；已有空表不补默认。空绑定清除对应键。已识别 ID 决定可运行项，不以角色/世界分档 |
| `hotkeys.json`（version4） | 仍读取/保存快捷物品行、启用/物品集合、旧键字段、旧开关表与 LastNonOffMode；旧键文本不自动成为统一运行绑定 |
| AppSettings/FeatureSettings | 功能期望、模式、旧宣告三槽兼容形状等仍存在；与统一绑定不是一份原子事务 |
| R 退休的三绑定 | `stackBinding/sellBinding/discardBinding` 只是 R 旧 schema 读取时校验并丢弃的历史边界；本轮不恢复，也不承诺导入 |

绑定属于同一 Legacy 用户配置根的操作偏好，模式历史也是全局偏好；沿状态、捕获与 pending 动作是进程/交互状态。旧路径不决定 R 新文件名；R 数据自然归属仍按[配置设计](../设计/配置持久化与用户数据布局.md)与 [Legacy 导入边界](../规范/Legacy平替与行为契约规则.md#十八旧版用户数据导入边界)处理。[Z04、Z17、R05]

生产加载会 Normalize：无效 chord 被丢弃，合法未知 ID 可保留但不被运行注册；ID只 trim，不统一大小写。ConfigVersion≤0改为1，**大于1没有未来版本只读保护**；未见未知顶层字段的保留机制。正常读成功后迁移并尝试保存，不是等待用户主动修改才落盘。读失败会尽力留 `.bad-时间`，使用默认并禁止覆盖该原件；不能把这一坏文件保护扩大到未来版本/未知字段。[Z04]

主开关和蓝图的旧格式桥只由 `TickForTesting` 调用，通用修饰映成左侧也是该边界。旧自动挖矿/宣告 parser、字段和说明能找到，不证明生产自动导入仍发生。快捷物品则确实是旧文件保存物品行、新文件保存 slotN 键的双文件结构。[Z04、Z16–Z20、H03]

快捷物品 ID 绑定列表下标，删除条目分支 `RemoveAt(index)` 后 SaveAll，未见同步删除/重排统一 slotN 的步骤。**推断**：删中间行可能让后续物品继承原下标的键，末尾残留键仍在统一表占冲突。应保留为索引身份风险，不声称删条目必然连同正确绑定一起清理；本轮未用真实数据或行为测试复现。[Z11、Z17]

### 5.2 保存失败与假成功边界

解析/策略/冲突拒绝发生在改内存前，旧绑定保持。真正保存时却是先 `TrySetBinding` 改内存，再同步 `SaveAll` 尝试四份配置；统一文件失败只回传 `saveFailed`，未回滚内存，SaveAll 仍刷新绑定签名，所以新键可能已经生效。再提交同一键会因 Changed=false直接返回 true/“未变化”，不重试落盘。[Z04、Z05]

主小窗录入结果可显示保存失败，但“清除”分支忽略返回 bool，以 result.Changed 给“已清除/当前未绑定”；局部框又丢失 message。因此不能写“失败必保旧键与草稿”“显示新键即已保存”或“统一错误文案已解决全部假成功”。本次是源码发现，不冒称已有旧实机报告证明同一症状。[Z10–Z14、Z27]

文件写入有同目录临时文件、WriteThrough/Flush(true)、最多三次替换及50/100/150 ms失败等待；优先 File.Replace，但部分异常回退 File.Copy(overwrite)。既没有四文件事务，也不能概括所有环境均原子保旧。[Z04]

### 5.3 仅静态成本

| 路径 | 能确认的形态；不能外推实际耗时 |
| --- | --- |
| 绑定缓存 | 签名相同复用数组，变化时建注册、字典/数组；不是每Query解析全表 |
| 签名生成 | normalize/parse/排序全表，32位散列；运行缓存信号在 Initialize/SaveAll 刷新。另有主开关小窗显示时，每次 DrawInterfaceLayer 注册 overlay 都直接重算全表签名，即使未改绑。直接改公开字典未刷新不能保证运行缓存失效，无文件监视热重载 [Z04、Z10] |
| 普通查询 | 默认先构造context再找绑定；未绑定也可能付上下文成本。各 binding 重读修饰与主键，各次物理读又查输入/前台；WasDown读写分别锁，没有同Tick共享采样 |
| 主开关 | 活跃时最多遍历63项，有事件早退；成功应用可能直接在Tick同步 SaveAll，含四文件序列化、替换与失败等待 |
| 快捷物品 | 遍历用户行集合，成功入队后break；未见固定行数上限。功能关闭会早退，但不等于所有共享输入成本为零 |
| 宣告 | prefix构造输入并Query后才判断 FeatureEnabled，关闭不代表不查询 |
| 生命周期/日志 | WasDown只有测试Reset清空的明确入口；不能默认退世界清零。普通按住多为idle，主开关事件/异常有记录；没有据此证明日志/I/O零成本 |

这些事实见 [Z04、Z05、Z16–Z21]。本轮没有基准、探针、扫描器、耗时测量或FPS结论，不以静态重复查询定性为实机性能根因。

### 7.1 真实功能与公共职责

首轮仅群系显示、自动堆叠、自动出售、自动丢弃，默认全空，包含补齐群系行键盘入口；保留现有开关、名单、提示和其它数据。四项不是容量上限。未来功能通过稳定功能/动作 ID、显示名、适用上下文和正常命令注册；页序、下标、译名与 UI 对象不是身份。

公共层负责绑定、一次输入识别、归属/冲突与分派；功能继续负责实际状态、可用性/故障、资源、过程、失败和多人权威。快捷键以当前状态走原设置语义，关闭的功能仍可由键开启；不直接改背包箱子、不复制功能状态、不制造新取得资格、不改卖＞扔＞存和收藏/钱币保护或在途收尾。

分派现在就能向一次动作请求发命令，以隔离测试中的真实测试消费者验证；不新增生产空菜单。本轮不实现宣告、挖矿、蓝图、快捷物品等业务，也不做宏、连招、录放、定时重复或完整按住调度。以后动作沿用同一规则，不保留普通键当修饰、强制三键等专属例外。

### 7.2 键鼠、组合与主键沿

- **零至三个修饰键＋恰好一个主键**，总数最多四个不同物理键。修饰仅 `LCtrl/RCtrl/LShift/RShift/LAlt/RAlt`，左右身份和显示/保存顺序稳定；左右同类可并用、各占数量。重复 token、纯修饰、两个主键、超限拒绝；字母和鼠标不能作修饰。
- 主键为宿主可可靠识别的非修饰键盘键或鼠标按钮。实际检查字母、数字行、OEM/标点、空格/Tab/Enter/Backspace/Delete、导航、小键盘/运算键、F 键和可获取扩展键；不能只扩 parser 白名单。加号、Num+ 等身份与组合分隔符须无歧义往返。
- 鼠标至少明确左、右、中键按下与标准两侧键。更多按钮按实际输入路径区分；驱动映射键盘就录为所报告键盘键，不虚构 Mouse1–12。纵横滚轮不参与绑定、候选变化或触发，保留正常滚动与 Notes 的 Ctrl/Shift＋滚轮。
- Esc 在录入中取消；Backspace 是可尝试主键，清除只用按钮。F5 固定保留，尝试录入给具体占用原因；其它 F 键不整组禁用。Win 不是修饰；锁定键按物理按下处理，不能将 toggle 状态当 held。布局、NumLock、两处 Enter、媒体/侧键等无法可靠区分时明确限制，不保存永远不能触发的值。
- 精确匹配**修饰集合**：`K`、`LCtrl+K`、`LCtrl+LShift+K` 可分别绑定，第三种只中第三种；RCtrl 不替 LCtrl，额外 Alt 不匹配。额外普通 W 移动不导致失配。
- 触发以**主键新的按下沿**为准：先按修饰再按主键；主键保持时增减修饰不补发其它命令，须真实释放主键后再按。不同主键的独立新沿可同帧请求，不靠查询顺序、全局早退或固定毫秒防抖选赢家。

可识别、允许绑定、已实机验证分开报告。特殊硬件缺失不阻塞已实现键集，也不能静默缩为旧单修饰/仅键盘。原生读取限于现有共享输入 owner，不注册全局热键、部署驱动/后台服务或在失焦时记录其它窗口输入；系统保留组合或宿主收不到的键不保证拦截。

### 7.3 共享输入与场景让路

复用 HostInputState 的真实前台/重新激活保护，正确阶段一次采样、消费者共用同一版本；先维护全部有关主键的物理沿再判断归属/派发。非有效前台不派发；唯一录入会话优先；文本、IME 与界面手势交对应 owner；其余允许游玩场景才匹配。四项保留现有 F5/地图等让路，不为未来预建几十种模式。

原版/Notes 复制粘贴、方向等仍为局部编辑操作，不进入可配置绑定表。游玩时可绑定 `LCtrl+C`，原版重合按下节提醒；进入 Notes、聊天、改名、告示牌及其它实际文本/IME 时交编辑器，不能全局禁 C 或只检查 Notes。

物理 held、允许执行、被消费分开；blocked 不可合成“已松手”。阻挡期间的按下、录入完成键和激活点击不得补发；不可见/切页/失焦/退出世界/owner 接管时结束未提交捕获，重开不残留。已发生功能/网络操作正常收尾，不随快捷键窗口关闭清空。

### 7.4 只在设置时核查原版冲突

提交时读取玩家**当时实际使用**的原版可改键配置，以及目标版本适用固定 F 键/其它入口，按与目标同时可生效的场景判断，不靠默认键表或安装缓存。原版若忽略修饰，组合的主键或修饰键重合仍可产生提醒；互斥文本操作不构成游玩冲突。固定规则按真实调用核对，不臆造用途或整段拉黑。

**所有者在 #51 实机反馈后的决定：与原版按键重合只提醒，允许直接保存；与决明其它动作的绑定冲突才拒绝。** 提醒显示原版来源及相关动作/按键，说明可能同时执行，不增加确认步骤。同一目标同值可幂等成功，不与自身冲突，提交仍读取当前原版值。读取失败显示未能核对的提醒，仍允许保存；不能冒称无冲突，也不改原版设置或停用插件。可靠保存成功才显示已保存并生效，真实存储失败照常保留旧绑定；原版提醒不掩盖保存失败。

决明内部同时可生效目标的同组合拒绝；精确可区分的 K/LCtrl+K 不机械判重复，关闭功能仍占开关键。固定 F5/局部编辑按场景解释，不进入可重绑列表。UI/加载/运行注册使用同一语法；手改自身文件产生非法/重复 ID 或组合时保护原件、解释并限制受影响项，不按列表顺序选赢家或双派发。

**成功后原版再改键：不监听、不周期扫描、不加事件订阅或线程，不主动提醒、自动停用或修改任一方；启动加载也不重新审查原版并停用。用户再次编辑/提交决明绑定才重新核查。** 只承诺设置时检查，后来重叠由用户重新设置解决，不强吞后来原版动作。自身配置语法/重复/注册完整性检查照常进行，不构成原版监控。

### 7.5 一个公共录入小窗

四个真实功能行末尾 keyboard 双击同一小窗，显示当前绑定、说明/结果、开始录入、清除、关闭；不建集中页或常驻大表单，不开放未实现样板行。靠近操作行并夹入视口，沿用 R 面板/按钮/字体、选中和提示。物品已有提示/添加/开关/名单布局不被破坏。

最长四键和具体冲突以真实字形换行、合理安排空间，不能无限缩字；正文、按钮、裁切、命中共用几何。开始前显示旧有效值；开始后提示“先按修饰键，再按一个主键”，排除启动点击与预先按住主键，启动鼠标先真实释放。预先按住的合法修饰可用于之后新主键；纯修饰显示进度、不提交。

新主键自动形成候选、校验并尝试保存，不多层确认；同时多个新主键给无效结果，不按目录顺序选。超限、冲突、不支持、保存失败、取消、清除、成功全部可见；结束录入保留结果小窗。关闭/切页/失焦清未提交候选与输入尾部；另一目标打开先取消旧未提交录入，不改旧有效绑定。

关闭/取消录入/清除等明确控件优先于鼠标候选，点击不能录成 MouseLeft。录入鼠标不穿透世界、背包、名单或页面按钮，也不把所有窗口点击都吞成主键；滚轮仍由合法 UI 处理但不形成候选。录入产生的按下与释放不运行新旧绑定，新绑定须经真实释放/再按。Esc 只取消本次录入，不重写整个 F5/Notes 的 Esc；清除只移除绑定，不关闭功能。

### 7.6 唯一绑定数据与失败语义

同一安装下按用户动作 ID 保存一份统一绑定文档，位于既有 `JueMingRData/config`；精确文件名/schema 在有限实现设计确定。不分散到四项功能文件、不修改原版键位、不恢复退休字段或导入 Legacy。草稿、held、消费、窗口、在途回调不落盘。

复用异步保存与原件保护，由唯一 owner 区分当前有效、候选/正在保存和结果。有效候选提交后，**可靠成功才替换有效绑定**；明确失败保留旧有效值并显示原因，可重新录入。替换已发生但结果未知/外部冲突按既有保护处理，不谎称回滚或反复写默认。必要完成语义在正确职责最小补齐，UI/Draw 不写盘。

回调绑定目标/revision，不让旧窗口结果覆盖新目标/候选；明确提交可以安全收尾，取消未提交不等于撤回磁盘操作。缺文件空绑定；损坏、未知版本/字段/键/动作、重复分别处理，保护原件并提供有限错误。暂缺模块项保留而不派发，不因注册变化删其它用户数据。

以后功能提供稳定 ID、名称、上下文/可用性、正常命令并接公共 UI；动作与开关不另建解析/采样/存储。隔离测试证明页面重排不串键、新动作不需改公共层功能名 switch。热路径不重复 parse/排序/签名或读原版配置；无有效绑定且未录入短路业务，不跳过 F5/焦点职责；单项更改不 SaveAll、不重写无关文件，不逐键日志、不每功能线程，缓存有明确容量/失效/退出。

### 7.7 验证与开发候选交付

先接群系真实端到端，再接三项自动化，本批四项必须完整。新任务完成有限实现设计、测试先行、关键注释和独立只读审查；不能停在框架/parser。验证真实 Host/UI/命令与隔离文件，覆盖主键沿/精确修饰、鼠标控件优先、不做原版后续监控、语法/加载一致、保存未知/失败/旧回调、动作扩展、字体布局及相关 F5/Notes/物品安全回归。测试在初始化/线程前隔离数据，不读日常私人内容，不启动游戏/服务器。

执行相称 Debug/Release、架构/行为/存储/宿主/安装恢复检查。RDP 设备创建前环境不可用的图形项可明确待补，真实绘制异常/输入安全错误不能豁免。适用检查和审查完成后，从受审干净候选按单工作区顺序构建比较、生成包含既有功能的开发包并直接安全安装到所有者确认目录；保护数据、备份与恢复材料，不启动游戏，保留安装供测试。实现 Issue OPEN、PR Draft，等待所有者实际游戏键鼠/IME/显示反馈，不自动合并、发布或 Tag。


### 7.8 R 开发候选的使用与边界

在 F5 的“信息 → 群系显示”和“物品 → 自动堆叠／自动出售／自动丢弃”四行末尾，双击键盘图标打开同一个小窗。四项默认未绑定；开始录入后先按修饰键，再按一个主键，自动核查并可靠保存。关闭小窗及 F5 主界面，松开录入键后再按新组合使用。它们调用原有开关设置命令，不改名单、丢弃提示、物品取得资格、处理顺序或多人权威。

六个修饰键按 `LCtrl、RCtrl、LShift、RShift、LAlt、RAlt` 显示，最多选三个不同物理键；键盘主键覆盖普通字母、数字、OEM/标点、空白/编辑/导航、数字区运算、F1–F24、锁定键及 XNA 可报告的扩展键。Esc 用于取消录入，F5 保留且有提示；Backspace 可以录入。鼠标明确支持左、右、中按下和两侧键；滚轮继续原有滚动，不作绑定。原版重合只提醒并允许保存，决明内部重复绑定仍拒绝；媒体键/侧键是否送达取决于设备与系统。当前不能区分两个 Enter，不承诺 Win 组合、更多独立鼠标键或全部 NumLock/键盘布局/特殊硬件已经验证。

文本编辑的固定操作不进绑定表；Notes、聊天、改名、告示牌和 IME 等拥有输入时，快捷键让路。原版冲突仅提交时核对并提醒；保存后、后改原版键位及下次启动均不主动重查或停用。再次编辑时才重新检查。精确修饰与主键新沿、独立同帧动作及非开关命令使用同一公共分派。

绑定独立保存在 `JueMingRData/config/hotkeys.json`，安装不生成默认绑定，不导入 Legacy 字段。可靠保存成功前仍用旧表；普通明确失败允许重新录入，未知提交或外部冲突保护原件并提示。清除只改当前绑定，关闭窗口不撤回已经提交的保存。未来消费者通过稳定动作 ID、名称、上下文与真实命令注册，四项不是容量上限，接入方式见[实现设计](../设计/统一快捷键实现设计.md#后续动作接入)。
