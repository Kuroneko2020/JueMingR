## 2. 首次进入世界提示

### 2.1 触发、状态和用户所见

`Automation/Information/FirstWorldLoadPromptService.cs:12–96` 每次被 Runtime 分派时先检查在世界内且不在主菜单。已确认的非零角色/世界运行 token 组合可快速返回；这里允许负 token，条件是 `!= 0`，不能误写成“正数 ID”。完整持久身份仍来自 `InformationWorldContextProvider` 的 `PlayerRecordKey`。同一个持久角色换世界或换对象 token，只更新进程内准入，不再读写一次性标记。

首次标记报告成功后，服务记住当前角色与运行 token；只有 `firstVisit=true` 才显示文字。依赖返回失败时不准入，下一 Tick 再试；完整身份未知时不造匿名记录。退出世界重置准入。`ResetAdmissionState` 只重置准入，不清除已经开始计时的提示文本；不能据此声称提示所有状态都在离世界时归零。

显示内容固定为 `按f5打开配置窗口`，不是可配置的任务或操作清单。阅读时间 3 秒，随后 0.5 秒淡出，基于 UTC 期限。`UI/FirstWorldLoadPromptOverlay.cs:11–100` 在角色头顶居中绘制，约在角色上方 44 像素并带小幅上移；黄色文字与阴影、字号倍率 1.05，绘制经过界面生命周期门。它不消费鼠标键盘，不会替玩家打开 F5，也不证明极端分辨率或 UI 缩放下实际呈现已经验收。

### 2.2 自然身份、文件与失败反例

`Records/PlayerWorldBehaviorStore.cs:239–274` 用原角色键加固定世界键 `player-first-load`、世界显示名 `all-worlds` 建立标记。这是**角色级跨世界一次性**，不是角色×每个世界第一次，也不是每次安装或每次版本升级。

文件名按 UTF-8 的 `playerKey + "\n" + worldKey` 做 SHA-256，再加 `.json`（585–607）；放在既有 `data/behavior` 目录。文件 Version 为 1，包含身份、创建/更新时间和行为记录形状。常驻缓存按文件名保存。原件不存在才令 `isFirstVisit=true`；已有但损坏的文件不会自动变成“首次”。加载异常返回缓存中的空形状并记录日志；这不等于当前 R 的坏文件保护与停写合同。

一个关键反例：`SaveLocked`（437–465）会捕获写入异常并吞下，而 `TryMarkPlayerFirstLoad` 最后仍返回 true。调用者得到的“成功”并不保证标记已落盘。因此当次可以显示并准入，下一进程仍可能再次显示。另一个细节是 `TouchIdentity` 先设置 `LastUpdatedUtc`，随后 `string.IsNullOrWhiteSpace(file.LastUpdatedUtc)` 已不成立；对于已存在文件，这个条件不能补救之前加载失败。不能用服务层“失败会重试”的测试证明真实磁盘失败会正确传播。

保存使用临时文件、WriteThrough、`Flush(true)`，现有目标尝试 `File.Replace`；文件不存在时 Move，竞态下只在目标确实消失时再 Move（467–490）。有这些操作仍不能弥补上层吞掉失败的结果语义。

### 2.3 频率、多人及 R 候选

稳定已准入状态只比较 token；角色相同而世界 token 变化时仍避免存储；没有已知 token 时可能反复解析完整上下文。首次失败重试发生于 Runtime Tick，没有在此另设退避；错误日志有节流。提示不写世界或 NPC，也不发送网络；持久记录是本机侧，可靠身份/SSC 等要沿 R 现有准入，不推断“所有多人拓扑都支持”。

既有静态测试 `tests/JueMingZ.Tests/Program.WpDr01FirstWorldLoadPromptTests.cs` 覆盖准入缓存、依赖失败重试、token 与持久键分离、退出/未知 token，使用替代依赖；本轮未运行。这些测试提供用例，不是保存失败、真实渲染或用户接受的证明。

**候选产品问题**：一次性范围选安装/角色/版本哪一种；是否提供“再次查看入门”入口；存储失败时是否允许显示并明确保留重试。实现应由已有 UI 与可靠配置/记录机制带出窄标记，不需要新引导框架。

## 3. 导出诊断

### 3.1 实际按钮链和输出集合

杂项页 `UI/Legacy/LegacyMainWindow.Misc.cs:427–444` 有明确“导出”按钮。F5 只开关主窗口；它本身不是导出操作。`Input/LegacyUiActionService.GeneralDiagnostics.cs:119–159` 在按钮命令中获取完整快照，使用 FPS 记录器的 BeginExport/EndExport 括号，随后调用 `DiagnosticPackageExporter.ExportNow`，记录结果、路径与包含文件数。已读链确认日志/命令记录反馈；没有据此声称存在单独的成功弹窗或自动打开文件管理器。

`Diagnostics/DiagnosticPackageExporter.cs:61–126` 的完整输出集合如下，条件存在的文件允许缺席：

| ZIP 路径/来源 | 条件与含义 |
| --- | --- |
| `manifest.json` | 导出 UTC、运行版本、testRunId、捕获方式和条目路径；不是用户游戏存档 |
| `diagnostics/runtime-snapshot.json` | 当次完整运行快照；没有 snapshot 则直接返回 snapshotUnavailable |
| `diagnostics/recent-buffer.jsonl` | 近期内存缓冲快照 |
| `diagnostics/fps-trend.jsonl` | 旧 FPS 趋势快照；存在此格式不授权 R 恢复旧常驻记录器 |
| `diagnostics/feature-catalog.json` | 既有功能目录文件存在时复制；Implemented 标识不是当前功能验收 |
| `diagnostics/<ActionEventsPath 文件名>` | 既有动作事件文件存在时复制 |
| `diagnostics/<PerformanceEventsPath 文件名>` | 既有卡顿事件文件存在时复制 |
| `logs/<日志文件名>` | 当日本地日期的 `jueming-z-yyyyMMdd*.log`；无当日日志时选最近修改的最多 3 个通用日志 |

默认目录为 Documents 下的 `My Games/Terraria/JueMing-Z/diagnostic-packages`。命名使用 UTC 时间；同名尝试后缀 1–999，仍冲突再用 GUID；最终 CreateNew 创建，避免无条件覆盖已有 ZIP（228–248）。ZIP 关闭后还会调用 `DiagnosticSnapshotWriter.WriteFullSnapshotNow` 写平时的完整快照文件，故“导出”不只产生一个新 ZIP。

### 3.2 成本、隐私与失败

已读按钮链同步取快照、序列化、建 ZIP、复制文件并写完整快照，没有在这条链中看到后台 worker。日志复制以共享读写打开；所有当日日志没有数量上限，备用分支的“最多 3 个”不能说成总体上限，也没有统一字节上限。开销取决于快照、缓冲与日志大小；这是静态工作量风险，未测 FPS 或耗时。

缺失文件可以跳过；顶层异常返回 `exportFailed` 和错误详情。没有成功清理半成品 ZIP 的完整事务保证，也没有“IncludedFileCount=预期数量才成功”的合同。格式完整性、失败回显和导出线程策略都应在后续具体任务中明确。

导出没有自动上传。完整快照和日志可能带角色/世界名字、路径及诊断文本；不能把这些输出宣称已经脱敏。玩家指南应告诉用户在哪里拿文件、哪些内容可能包含身份信息、怎样只分享这次相关证据，而不是让用户手工解释 JSON。

静态参考测试 `Program.DiagnosticCleanupRegressionTests.cs:97–205` 在隔离临时目录生成替代数据、核对 ZIP 核心条目与数量；它不是完整实机日志体积、图形卡顿或隐私审查，本轮未运行。

### 3.3 R 关系

R 的现行规范已经区分产品必要信息、短期调查观察与自动工作量回归。本候选应优先导出现有、必要、可解释的信息，按需采集并有实际安装退出边界。不能因 Z 的 ZIP 里有 FPS 数据，提前建设全量常驻采样、统一性能平台或把旧日志开销一起迁入。

参照 [性能治理规则](../../规范/性能治理规则.md#观察能力分类与安装退出)、[工程治理规则](../../规范/工程治理规则.md#观察能力的任务审查与交付责任)；本篇只提出按需导出的候选，不修改这些规则。

## 4. 旅行菜单：真实功能与高影响边界

### 4.1 默认、入口和作用域

`Config/AppSettings.cs:349,438–442,908` 默认关闭 `MiscTravelMenuEnabled`，别名为 `WorldAutomationTravelMenuEnabled`。`TravelMenuService.cs:16` 的 `FeatureSuspended=false`，不能因为存在 Suspended 常量/旧消息就认定当前功能已停用。

F5 杂项页写着“单机临时开启原版旅行菜单”。点击进入 `Input/LegacyUiActionService.WorldAutomationHandlers.cs:29–54` → `SetEnabledFromUi(enabled, enabled)`；成功、Enabled 且确实 Opened 时关闭 F5。统一功能快捷键 `Input/FeatureToggleHotkeyService.cs:551–552` 却只切配置位，不走 EnableFromUi。没有活动会话/恢复标记时，Runtime 会把这种孤立开启视为 stale config 并关回去；两种入口的操作语义并不等价。

启用链（Service:571–652）要求保存保护 Hook 已安装，然后捕获角色文件路径、世界文件路径、原 `Main.GameMode`、世界 GameMode、角色 difficulty 及相关对象；写活动恢复标记，打开背包，在 `uiOpen.ToggleCreativeMenu` 作用域临时切成 Journey，再请求原版菜单，最后恢复作用域。返回 `enabledMenuOpenUnverified` 时会话仍算启用，但菜单是否真正打开未证实。启用没有要求另外两组 Hook 的每个成员都存在。

`TravelMenuCompat.cs:27–103` 读取 netMode 存入 context，但在已读 Service、Context、Compat 启用与恢复链没有使用它做单人拒绝。UI handler 会识别 `multiplayerBlocked` 结果名，不证明服务实际会返回这个结果。**单人标签与实际强制边界不一致**；这不构成多人可用声明。

### 4.2 全部实际附加效果

| 机制 | 实际行为、成员与边界 |
| --- | --- |
| 临时 Journey 状态 | 对 Main、世界文件、当前玩家及不同的角色文件 Player 引用应用 GameMode/difficulty=3，结束作用域恢复捕获值；不是只显示一个原版窗口（Compat:218–460） |
| 作用域 Hook | `Player.ToggleCreativeMenu`、`Main.UpdateCreativeGameModeOverride`、`Player.Hurt`、`Player.ResetEffects`、`Player.GrabItems(int)`、`Player.GetItemGrabRange(Item)`、`NPC.ScaleStats`、`NPC.SpawnNPC`、`NPC.Spawner.SlimeRainSpawns(Player)`、`CreativePowers.DifficultySliderPower.Load`；Hurt 另要求 godmode power 开启（ScopedJourneyHookInstaller:118–148；Service:1150–1154） |
| 创意 UI | CreativeUI.Update/Draw 作用域、`PlayerInput.IgnoreMouseInterface` getter 绕行、鼠标释放脉冲和世界用物品保护；部分 native Journey UI 也可走输入作用域，不等于 Z 虚拟研究会在原生 Journey 全局开启 |
| 虚拟研究列表 | 在 Z 活动会话、作用域计数>0、保存保护不活动、开关开、创意菜单开时拦截三方法：`ForEachItemWithResearchProgress`、`TryGetSacrificeNumbers`、`IsFullyResearched`。按当前 ItemID.Count 枚举、应用 research override 去重、保留有正数解锁上限的 ID；展示全部为已研究，并让数量等于上限（Callbacks:109–210；Compat:1352–1490） |
| 缓存和退路 | 可研究 ID 数组第一次完整构造后进程缓存；单项 cap 查询仍反射调用原版。拦截条件不满足或反射失败回原方法；这不是把所有研究计数永久写进 tracker 的实现 |
| 自动化暂停 | 活动会话+开关开+创意菜单开+背包开时，Runtime 的旅行门先清动作队列，然后从总分派提前返回；包括其后的恢复、钓鱼、战斗等。关闭某个后续业务不是唯一暂停原因 |
| 背包恢复 | 启用时只有原来关闭的背包由会话强制打开；结束尝试还原该状态。恢复失败清理内部捕获不代表界面必然恢复 |

虚拟研究只改查询结果，不意味着菜单生成物品、创意力量或世界效果都可撤回。恢复 difficulty/GameMode 不会自动撤销玩家在菜单里造成的物品和游戏变化。完整原版创意力量效果不在本轮被执行；如果决定保留，应按允许的实际效果分别建立合同，不能用“临时”一词承诺没有长期后果。

### 4.3 保存、退出和失败路径

保存保护（Service:500–569、`Hooks/TravelMenuSaveGuardHookCallbacks.cs`）在保存前尝试回到原模式，维护嵌套 depth，保存后递减。Prefix 返回 void，恢复失败也不取消原版保存。因此它是一次恢复尝试，**不是已经证明能阻断错误模式落盘的保护**。

作用域安装使用 Prefix/Postfix（`TravelMenuScopedJourneyHookInstaller.cs:63–85`），已读安装点未提供 Finalizer。源码可证明正常后置恢复路径，不能据此保证原版方法抛异常后同样恢复。Runtime 下次 Tick 也会检查/修复与原状态不匹配，但这仍不是故障时刻的保存原子性。

Runtime Tick（Service:361–498）验证会话身份、状态与开关；退出/换上下文/关闭走清理。遇孤立 active 标记尝试恢复，然后调用 MarkRestored，即使当次 restore=false 也会走标记路径；这是一个与“恢复成功才销账”不同的反例。正常 StopActiveSession（666–761）只在恢复成功时 MarkRestored，但 forceDisableConfig 会在恢复失败时清活动上下文和深度，留下标记供后续恢复。离世界（762–782）关闭配置、还原背包、清内存会话，**刻意保留恢复标记**。

### 4.4 数据身份与持久化

`TravelMenuStateStore.cs` 的 `travel-menu-state.json`（以及 `.bak`）保存 Version=1 和 Markers：Active、PlayerPath、WorldPath、PlayerName、WorldName、OriginalPlayerDifficulty、OriginalWorldGameMode、OriginalMainGameMode、CreatedUtc、LastSeenUtc、LastRestoreUtc、LastMessage。身份按角色路径+世界路径 Trim 后 OrdinalIgnoreCase 比较，不是世界 GUID/可靠运行代次；移动文件、云路径或同路径重建的区分需要重新决定。

Load（203–248）进程内只读一次，主文件缺失/坏时尝试备份并保存恢复内容；两者坏则空形状。Save（276–342）临时文件 WriteThrough/Flush，再替换和备份；`File.Replace` 失败会 Copy(overwrite)+Delete，不能统一称为原子替换。保存异常吞下，UpsertActiveMarker 没有成功回执，故启用链可能在恢复标记未可靠落盘时继续。没有读到历史 marker 自动裁剪的有限集合合同。

### 4.5 R 候选结论

这是完整、独立的高影响候选组。先决定是否保留旅行能力、是否包含全研究/无限复制/创意力量、单人强制边界和恢复承诺；普通内部反射选择或 Hook 组织由后续实现者负责。身份、保存与异常恢复缺口是具体技术证据，不能把它们变成要求用户为全部技术方案签字。

若保留，不把旧 `TravelMenuService` 搬成新全局 Runtime，不沿用“UI 标签=权限门”或“写标记调用返回=持久成功”。R 的输入、可靠文件与受控操作需要分别承接具体职责。此候选不影响其它剩余功能先开发。

## 5. 开发者入口与世界生成明细

### 5.1 共享开关和实际输入

`Config/AppSettings.cs:444–456` 中两项 Diagnostics 别名 getter 固定 true，setter 也强制 true；不是两个可关闭的偏好。`Compat/WorldGenDebugCompat.cs:92–179` 启动后查找 `Terraria.Testing.DebugOptions` 等准确类型的静态 Boolean `enableDebugCommands`，必要时再搜索 Terraria 程序集类型；设 true 后读回，缺失/类型不符/异常报告并降级。它缓存字段，每 2 秒保持启用（197–244），没有保留并在关闭时恢复旧值的合同。

生成世界明细行（Misc.cs:387–402）只提示“世界生成读条界面按F5开启”；点击后文本换成“暂时关不掉”，不是切换原版字段的动作。开发者菜单行（405–424）第一次点“开启”只置确认态，再点显示风险提示的按钮才请求原版 `/hh`。旧 debugOn/debugOff/blocked payload 被明确处理为 NotApplicable（GeneralDiagnostics.cs:30–117），不能误列成现存开关模式。

`Compat/DebugCommandsCompat.cs:32–110` 查 `ChatManager.DebugCommands` 的 `Process(byte,string)`，playerIndex 夹到 0–255 后直接传 `/hh`，返回 null/true 视为请求成功；缺类型/方法或异常失败。这是直接进入原版处理器的帮助命令，不是自动向服务器广播的普通聊天消息，也不证明其列出的所有调试命令安全或受支持。按钮没有在此链限定 netMode。

### 5.2 候选范围与证据缺口

如只要世界生成进度明细，应先找到并验证窄的原版读取/展示入口，不能默认常驻开启整个 debug 模式。如果要真正的开发者命令帮助与控制，它应独立标识实验性质、权限及退出条件。原版具体 worldgen F5 窗口的布局/权限与所有 `/hh` 子命令不是本篇已经逐一验证的事实；此缺口只影响该实验候选，不阻塞地图、背包等正常能力。

## 8. 后续开发讨论可直接使用的边界

1. **小型产品帮助组**：首次提示、再次查看帮助、真实功能说明及关于/反馈路由。前置为已存在的 F5、身份/可靠文件；不依赖全部功能迁移。
2. **按需诊断交付组**：先决定玩家能导出什么、失败如何看、怎样分享；实现复用已有必要事实。不开常驻全量观察平台。
3. **旅行能力独立候选组**：明确允许的游戏效果、单人边界与保存恢复承诺后才进入实现。它不阻塞普通功能组。
4. **原版调试/生成明细独立候选组**：分别决定只读进度和开发者能力，补当前原版窄入口证据后实施。旧 alias 恒 true 不是 R 的默认值。

未完成的是这些产品决定、明确列出的原版窄入口证据与未来实机验证；本篇完成了现存入口、关键操作/持久化边界及跨功能关系的源码调查，不把缺口藏在“后续注意”里。
