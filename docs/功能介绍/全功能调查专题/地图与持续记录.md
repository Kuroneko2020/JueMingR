## 2. 共用身份与记录边界

### 2.1 Legacy 玩家—世界身份的实际优先级

`PlayerWorldIdentityResolver` 从当前玩家文件、世界文件和 Main 字段取事实，然后生成哈希身份。

玩家身份优先级：

1. 玩家文件路径及云存档属性得到的路径 hash；
2. 没有有效路径时退回规范化的玩家显示名；
3. 两者均不可用则失败，不写 unknown 玩家桶。

世界身份优先级：

1. 有效 `UniqueId`；
2. `MapFileName`；
3. 有世界 ID 且有世界路径 hash；
4. 仅世界路径 hash；
5. 世界 ID 加显示名；
6. 仅显示名；
7. 均不可用则失败。

`pairId` 由玩家 ID 和世界 ID 再组合 hash 得到。解析结果同时保留来源种类、显示名、世界尺寸等信息。显示名 fallback 是明确存在的兼容分支，不能因此宣称所有同名、改名、移动或云存档场景都能可靠区分。

共享身份目录与特征记录分开：身份文件维护玩家、世界及 pair 的观察信息；特征记录位于 `player-worlds/<pairId>/` 下，包括 `death-summary.json`、`deaths.jsonl`、`playtime.json`、`exploration-summary.json`、`footprints.json`、`map-markers.json`。

运行时身份缓存并非“不再读取任何原版事实”。它仍先解析当前身份，再比较签名；身份未变时主要避免重复维护身份文件，身份文件维护间隔为 1800 runtime tick。只读解析入口不写身份文件。证据：M-ID。

### 2.2 不能把相同 pair 解释成相同业务语义

- 标记是用户主动创建、命名、删除的资产。
- 揭示统计是可重新计算的摘要，包含扫描游标及上次完整结果。
- 足迹是持续追加和按时间裁剪的路线历史。
- 死亡历史是离散死亡事件。
- 世界天数是原版昼夜时钟变化累计。

它们可以共用自然归属，不能共用一个状态 owner，也不能因为都调用 JSON 工具就推断失败恢复相同。后文分别记录三类数据的读失败、写失败及生命周期分支。

R 现有基础区分稳定数据归属与当前 runtime 会话代次。自然归属适合选择数据文件；会话代次适合使旧 UI 手势、异步结果和缓存失效，两者不能互相替代。R 的 `HostDeathRecords`、`ItemSessionProbe` 及机械存储基础提供候选复用点，但本轮不决定旧数据导入，不让 R 编译期或运行时引用 Z。证据：M-R。

## 3. 自定义地图标记（附录 4）

### 3.1 用户结果、默认值与完整图标集合

地图标记默认关闭。开启后在全屏地图右键选择图标，左键确认建立一个记录；开启状态也控制自有标记的全屏地图绘制。F5 列表可读取和管理已有标记，编辑列表并不要求展示开关为开。

当前冻结 Z 的数字边界：

| 项目 | 当前规则 |
| --- | --- |
| 每玩家—世界 pair 最大标记数 | 120 |
| 缓存最大标记数 | 120 |
| 地图绘制最大标记数 | 120 |
| F5 每页 | 10 条 |
| 名字存储上限 | 10 个 .NET 字符串文本单位，即 UTF-16 code unit |
| 默认名字 | 本地时间 `yyMMddHHmm` |
| 默认图标 | 火把，物品 ID 8 |

完整图标白名单：

| ID | 图标 |
| --- | --- |
| 8 | 火把 |
| 48 | 宝箱 |
| 50 | 魔镜 |
| 224 | 床 |
| 171 | 标牌 |
| 393 | 指南针 |
| 966 | 篝火 |

历史落星图标 ID 75 在读取/规范化时映射为床 ID 224；其它不在白名单的 ID 回退为火把。选择器使用固定的八项集合，不临时扫描全部物品类型。图标所用物品只是视觉来源，不要求玩家持有或消耗相应物品。证据：M01。

### 3.2 右键创建的完整分支

真实链为：runtime 交互检查 → 大地图鼠标坐标转换 → 保存待确认位置 → 选择器显示 → 左键选择入队 → 再次检查资格/身份 → `PlayerWorldMapMarkerStore.AddMarkerForPair` 保存。

1. 功能关闭、没有全屏地图或交互资格不满足时，不创建。
2. F5 可见、文本框正在输入、游戏输入不可用、聊天、箱子或 NPC 对话等会阻止创建，并关闭当前待选状态。
3. 右键触发既检查原版按下边沿，也处理物理按下变化，避免同一按住状态反复弹出或取消。
4. 首次右键把当前 tile 和屏幕位置、屏幕尺寸、世界尺寸及坐标来源冻结为 pending placement。
5. 图标选择器围绕右键位置布局，并夹到屏幕范围；八图标横向排列，悬停显示图标名称。
6. 打开选择器及右键取消时，会启用“等待本次右键真实释放”门。这个门还消费对应释放帧，防止同一次点击的残留脉冲再次开关选择器。
7. 选择器打开后，再次新的右键取消；关闭地图会丢弃尚未确认的选择。
8. 左键选图标先记录待提交选择，再由交互服务完成写入，绘制代码不直接保存。
9. 成功创建后关闭选择器；保存失败保留待选状态，可继续选择或取消。容量已满、身份不可用或读取/写入失败没有被伪装成成功。
10. 一次图标提交是本轮处理的终点，避免同 tick 又处理另一轮右键开关。

pending placement 冻结了坐标和视图事实，但其字段没有保存创建时的 pair/session token；真正提交时重新解析当前身份。因此能确认“关闭地图/显式资格变化会取消”，不能进一步宣称所有身份变化都由 pending pair 校验保护。未来 R 需结合已有会话代次明确处理这类待提交手势。

创建失败主要进入状态、诊断和日志；源码存在失败结果不等于玩家一定得到醒目的错误面板。证据：M02、M05。

### 3.3 命名、删除、分页和跳转

#### 名称

双击名字进入文本输入。点击已聚焦的名称区或确认按钮会保存草稿；成功后清理输入焦点，失败保留草稿。普通一次点击未聚焦名字不直接改名。

通用输入草稿上限为 48 个文本单位，去掉 CR/LF，Tab 变为空格；真正进入标记存储时再 `Trim`，截取前 10 个 UTF-16 单位。这里不是 10 个用户感知字符，代理对、组合字符可能受截断影响。空名字允许保存；地图悬停为空时使用默认文本。

标记 ID 是 GUID，改名不改变 ID。当前 UI 没有直接替换已有标记图标的编辑按钮；图标是在创建时选择，不能把全名单展示当成已有图标编辑能力。

#### 删除与分页

每行有删除按钮，直接删除当前 pair 中对应 ID；没有二次确认或撤销链。操作失败时旧文件由存储失败保护保留。

上一页/下一页根据当前条数夹紧页码。翻页清理当前名称输入草稿，不自动保存未确认修改。空列表不画标记行；读取失败在列表表现可能与空列表接近，不能把“没有行”一概解释为从未创建过。

#### 跳转地图视图

跳转先尝试提交当前名称草稿，但并不把改名成功作为继续跳转的前提。然后：

- 读取对应标记坐标；
- 打开全屏地图；
- 将地图视图中心定位到目标，并夹到有效世界范围；
- 写入默认跳转缩放 2；
- 清除原版地图平移状态；
- 关闭 F5，释放 UI 捕获；
- 消费按钮产生的左键触发，防止它继续落到地图。

它不改变玩家位置，不调用传送，不发起服务器位移，也不消耗药水。

同一行可见的“导航”“传送”“智驾”是明确不可用占位；即使直接进入对应 handler，也只有未实现结果，没有游戏操作。传送相关提示中出现药水并不等于已有药水消耗链。证据：M03、M04。

### 3.4 地图坐标、绘制与悬停

鼠标坐标转换优先级：

1. 最近一次全屏地图绘制记录的鼠标 tile；
2. 最近一次绘制变换与当前鼠标屏幕坐标组合；
3. 用当前地图视图中心、缩放和屏幕尺寸构造后备变换。

旧变换会检查视图位置、缩放、屏幕尺寸兼容性；诊断记录 `TransformAgeUpdates`，但没有仅因年龄过大就拒绝该变换的统一门。不能把“记录了年龄”写成“已实现过期时间校验”。

转换结果取 tile 整数并夹进世界范围。地图图标按 tile 中心，即 `tile + 0.5`，交给原版地图绘制 context；这与足迹中本来已经是玩家中心的小数 tile 不同。

自有 map layer 仅在全屏地图和开关启用时绘制；读取当前 pair 标记，限制绘制数量，对离屏图标做判断。悬停使用名字，空名回退默认说明。物品贴图获取有失败路径，不能假定所有资源读取均成功。图层不是导航线，也不改变原版地图揭示内容。

与 R 死亡点、原版图标以及足迹控制条的组合排序见第 6 节；单个 layer 可以显示 hover，不证明全部重叠情况下的最终 hover owner 已统一。证据：M06、M07。

### 3.5 文件格式、缓存、失败与大数据

每 pair 的 `map-markers.json` schema 1：

- 顶层：`SchemaVersion`、`PairId`、`WorldSizeX`、`WorldSizeY`、`Markers`、`LastUpdatedUtc`。
- 单标记：`MarkerId`、`TileX`、`TileY`、`IconItemId`、`Name`、`CreatedUtc`、`UpdatedUtc`、`SortOrder`。

当前读取/规范化行为：

- 缺文件按空集合处理。
- 非空 PairId 不匹配或 JSON 读取失败，返回失败。
- 缺失 marker ID 会生成新 GUID。
- 名字、图标使用前述规范化规则。
- 负坐标归零；存储规范化没有按世界右/下界重新限制所有历史坐标。
- 没有对重复 marker ID 做统一拒绝。
- 没有未知更高 schema 必须只读隔离的严格分支。
- 数量只保留调用允许的前若干条，当前常用上限为 120。

增加、改名、删除都先读当前文件，再保存整份标记集合。常规坏 JSON/PairId 不匹配会阻止这些修改，而不是把失败读成空集合继续覆盖。保存通过临时文件完整写入，再替换目标；失败返回失败，清理临时文件，避免用未完成内容替换旧文件。

但历史超容量文件存在另一条路径：读取只保留前 120 条；在这个截断结果上改名或删除再整份保存，会把未读入的尾部记录排除在新文件之外。因而“新增拒绝超过 120”并不同时保证“旧 256 条文件的后 136 条一直安全保留”。

缓存有效期为 500 ms。它在判定有效命中前检查 `File.Exists`/文件长度/修改时间，返回结果还会复制标记；到期会重新读 JSON，即使文件最终没有变化。地图 Draw 调用的缓存读取可以触发这些磁盘工作，所以不能写成“Draw 永不碰磁盘”或“稳定显示零工作量”。

展示关闭只关闭创建/绘制，不删除文件；F5 列表仍可以读取管理已有数据。数字 120 限制显示/存储规模，但不证明某个实机帧率结果。证据：M05、M-ST。

### 3.6 历史 256 与当前 120 的证据并存

早期更新记录 `0.701-地图标记数据底座-2606150108.md` 写过每 pair 256、缓存 512。后续 `0.734-地图标记分页与上限-2606160940.md` 明确记录按用户要求改为上限 120、每页 10；当前冻结源码常量与后者一致。

这是有时间顺序和变更记录的阶段差异，不是应把历史文字倒改成 120。报告同时保留：

- 历史阶段事实：曾有 256/512；
- 当前冻结源码事实：120/120、每页 10；
- 具体兼容后果：旧超容量文件进入当前截断读取及整份重写的风险。

R 没有继承这些数字、图标选集或 UTF-16 名字长度的已接受合同。候选组“地图标注与地图视图操作”应将完整创建/取消、列表编辑、容量和分页、视图定位、数据失败反馈与公共地图输入一起讨论。导航/传送/智驾继续保留占位分类，不自动列入恢复承诺。证据：M01、M-H、M-R。

## 4. 揭示区域统计（附录 5）

### 4.1 用户得到什么

Legacy 的“揭示区域”统计当前玩家本地地图中 `Main.Map.IsRevealed(x,y)` 返回真的格子数量，占当前世界全部格子数量的比例。它读取已有地图揭示状态，不揭开地图，不修改地图，不记录玩家路线，也不能由比例还原路线。

这是 F5“地图加强”中的固定信息项，登记默认启用，没有普通功能开关。初始控制状态是“性能”模式、“扫描中”。用户点击百分比打开详情，在详情中切换模式、停止或开始扫描。

两种模式的完整参数如下；这些是冻结 Z 实现参数，不是 R 已接受预算。

| 参数 | 性能模式 | 快速模式 |
| --- | --- | --- |
| 单批最多读取格子 | 512 | 4096 |
| 单批时间预算 | 0.35 ms | 3 ms |
| 通常扫描间隔 | 30 个 runtime tick | 1 个 runtime tick |
| 因时间预算耗尽而退避 | 未完成且没有读取失败时，下一批间隔改为 90 tick | 不增加退避 |
| 扫描完成后自动重扫 | 无 | 无 |

时间检查发生在一次成功读取之后，因此预算不是强制抢占的实时上限。模式名大小写不敏感地识别 `Fast`，其它输入归为 `Performance`。证据：E01、E02。

### 4.2 从触发到结果的完整链

`JueMingZRuntime` 每轮进入揭示统计阶段；服务先检查世界资格和扫描到期时间，再解析当前玩家—世界身份、读取地图尺寸，最后推进扫描。

1. **没有世界、主菜单、身份不可用或地图尺寸不可用**：尝试保存当前进度，清除当前 pair 和内存文件；用户明确暂停的控制状态继续保留，其它情况恢复为等待扫描。
2. **进入新 pair**：尝试保存旧 pair，然后加载新 pair 的摘要。该切换并不检查旧 pair 保存是否成功，详见失败边界。
3. **世界尺寸改变**：重建统计摘要并从头扫描，不保留旧尺寸的已发布计数；如果用户此前暂停，仍保持暂停。
4. **未完成扫描**：从持久化 `NextTileIndex` 继续；线性下标转换为 `x = index % width`、`y = index / width`，逐行覆盖整个世界。
5. **单格读取失败**：停止本批，不跨过失败坐标；此前本批已读成功的进度保留，下批仍从失败坐标尝试。
6. **完成扫描**：写入完成时间，将工作计数作为正式已揭示计数，进入 `IdleComplete`。之后不会因地图继续揭示而自动重扫。
7. **停止扫描**：清除手动刷新请求，进入 `PausedByUser`，尝试保存，保留当前扫描游标。
8. **开始扫描**：
   - 尚未完成：继续原游标，不从头清零。
   - 已完成：手动重新扫描整个世界；保留上次完整计数和完成时间，直至新扫描完成。
9. **切换模式**：只改变后续预算；不重置进度，不自动开始已暂停的扫描，也不立即清空既有到期时间。

模式和暂停状态是进程内共享控制状态，不写入每 pair 的摘要文件。同一进程换世界会沿用模式和用户暂停状态；重新启动进程恢复默认控制状态，再根据文件是否完成决定继续扫描或保持完成空闲。证据：E02、E03。

### 4.3 百分比、详情与新旧结果

首次扫描没有任何完整结果时，页面百分比随本次已经扫描到的揭示格子增长；分母仍为整个世界的格子数。因此首次扫描中的低比例不代表已经完成全世界统计。

已有完整结果后再次扫描，页面继续显示上次完整计数；本轮工作计数独立累计，直到扫描完成才整体替换。详情可区分“扫描中/已停止”的进度，但主行百分比本身没有“旧值”或“部分结果”后缀。

详情完整反馈规则：

| 条件 | 显示 |
| --- | --- |
| 身份不可用 | `已揭示 -- / --`、`当前玩家-世界身份不可用` |
| 地图不可用状态 | 已知计数，以及`当前地图不可用` |
| 读取失败标志存在 | 已知计数，以及`exploration-summary.json 读取失败` |
| 总格子数不大于 0 | `等待地图扫描` |
| 未完成且用户暂停 | `已停止 已扫描数量 / 总数量` |
| 未完成且未暂停 | `扫描中 已扫描数量 / 总数量` |
| 已完成 | `上次统计 yyyy-MM-dd HH:mm:ss`，转换为本地时间；没有有效完成时间则为`尚未记录` |

主行在身份不可用或 `ReadFailed` 时显示 `--`，正常按两位小数显示百分比。模式按钮始终可点；“开始扫描”需要身份已解析且未被识别为地图不可用。详情有独立关闭按钮，关闭详情不暂停统计。

详情依赖传入的状态结果；服务加载坏文件后转为新内存摘要时，并不持续向 UI 发布原来的 `ReadFailed` 标志。因此“UI 有读取失败文案”不等于所有实际读取失败都会保持可见。证据：E03、E04、E05。

### 4.4 状态归属、文件与失败边界

唯一扫描状态由 `PlayerWorldExplorationService` 持有，包括当前 pair、内存摘要、脏标志、扫描/保存到期时间、模式、控制状态及手动刷新请求。UI 读取结果快照并提交命令，不拥有扫描游标。

每 pair 文件为 `exploration-summary.json`，schema 1 字段完整集合：

- 身份与范围：`SchemaVersion`、`PairId`、`WorldWidth`、`WorldHeight`、`TotalTileCount`。
- 数量与游标：`RevealedTileCount`、`WorkingRevealedTileCount`、`ScannedTileCount`、`NextTileIndex`、`ScanComplete`。
- 时间与状态：`LastCompletedScanUtc`、`LastScanUtc`、`LastScannedTileBudget`、`LastResetReason`、`LastWriteSucceeded`、`LastWriteStatus`、`LastWriteMessage`、`LastUpdatedUtc`、`ScanSemantics`。

运行服务优先提供当前 pair 的内存结果；磁盘缓存仅在没有对应内存文件时读取。磁盘缓存检查文件存在、修改时间等属性，并使用 500 ms 有效期。服务规范化会强制写回 schema 1、当前 pair、当前统计语义并限制计数范围；没有“未知更高 schema 拒绝写入”的分支。

保存使用共用 JSON 原子替换工具，但业务层有以下不同情况：

- **扫描中普通保存失败**：保留当前脏内存；后续扫描进入到期保存分支时可再次尝试。
- **完成或用户暂停时保存失败**：保留脏内存，但完成/暂停分支会提前返回，不靠这些空转自动周期重试。后续显式保存、恢复扫描或生命周期切换才可能再次触发保存。
- **退出世界、身份/地图不可用**：`FlushAndPause` 无论保存成功与否都会清除内存文件和脏标志，失败待存进度可能丢失。
- **切换 pair**：保存旧 pair 后直接加载新 pair，同样可能丢失旧 pair 的失败待存进度。
- **初次读取坏 JSON、读取失败或非空 PairId 不匹配**：`LoadFile` 创建可继续扫描的新摘要，记录 reset reason；不是保持坏文件只读隔离。后续保存可覆盖原文件。
- **地图逐格读取失败**：与文件读取失败不同；当前游标保留并重试该坐标，失败结果进入诊断。

因此，机械层“临时文件＋替换”只能说明一次文件替换的方式，不能证明业务层所有旧数据和失败待存状态均被保护。证据：E02、E03、E05、M-ST。

### 4.5 工作量、操作权限与 R 候选

扫描读取发生在 runtime，不在地图绘制阶段。完成后没有格子扫描，但仍按所选模式的间隔检查身份、地图和状态。用户暂停后 `_nextScanTick` 被置为 0，暂停分支又不推进到期时间，因而可以每个 runtime tick 重走身份、尺寸、锁和诊断分支；“暂停后不读格子”不能写成“暂停零工作量”。

每次完整扫描的规模是世界宽度乘高度。分片期间地图仍可能发生变化，因此结果是分时读取组成的统计，不是某个瞬间冻结的全图快照。快速模式只改变完成速度和每批工作量，不提高原始地图数据的新鲜度保证。

这一链没有物品、钱币、世界写入、玩家位移或服务器请求。登记为本地辅助、多人待验证；本地地图读数不等于全队地图揭示情况，本轮没有验证多人地图同步规则。

R 当前没有揭示统计实现。候选开发组可以单独为“地图揭示统计”，复用已接受的身份、会话失效、结果发布与 F5 基础，保留独立扫描状态 owner。未来需要讨论的产品边界包括首次部分值与旧完整值的文案、手动刷新、控制状态是否持久化、失败隔离和规模预算；本调查不选择 R 默认值，也不把 Legacy 参数升级为合同。读取 `Main.Map` 的线程安全尚未在 1.4.5.8 原始类型上验证，不能直接推导为可以交给后台线程扫描。

## 5. 足迹记录、地图路线与回放（附录 6）

### 5.1 三种状态必须分开

| 用户或系统状态 | 是否继续采样/追加 | 是否画路线 | 时间轴行为 |
| --- | --- | --- | --- |
| F5 足迹展示关闭，默认状态 | 正常世界 tick 中继续记录和保存 | 不画；发布显示关闭状态 | 控制条隐藏，再打开重新进入最新端、暂停、1x |
| 展示开启但未开全屏地图 | 继续记录 | 不画全屏地图路线 | 控制条隐藏 |
| 大地图中暂停历史回放 | 继续记录 | 画到历史游标为止 | 历史游标与显示时间轴末端尽量保持；保留窗口裁剪时仍会夹紧 |
| 大地图中暂停在最新端 | 继续记录 | 随新发布记录显示最新路线 | 游标跟随最新端 |
| 播放历史 | 继续记录 | 随回放游标逐步增加 | 播放到最新端自动暂停 |
| 玩家死亡/幽灵、离开世界、身份或位置不可用 | 该期间不正常追加位置点；尝试保存并断段 | 由显示与发布状态决定 | 恢复有效采样后另起一段 |
| 仅 F5、聊天、箱子、背包或地图 UI 打开 | 服务没有这些 UI 排除条件 | 由展示条件决定 | 不构成记录暂停命令 |

Legacy 没有独立用户“停止记录”按钮。F5 行只控制 `MapFootprintsDisplayEnabled`，默认 `false`。控制条的“暂停”只暂停回放游标。也没有在本专题实际 UI 链中找到用户清空足迹、删某一段、导出路线或设置保留期的入口。

真实装配顺序为：世界状态读取 → 足迹录制 → 足迹渲染缓存 → 揭示统计；录制方法没有接收展示开关。F5 等 UI 不应被写成“自动停止记录”的条件。证据：F01、F02、F07。

### 5.2 采样、点合并与全部断段条件

录制默认每 **6 个 runtime tick** 到期一次。时间轴使用累计观察到的 runtime tick，常量以 60 tick/s 换算；不是原版昼夜时间，不是现实日历时间，也不纳入离线时间。

位置优先使用有效且不是近零空值的玩家中心坐标，否则退回玩家 `Position`；像素除以 16 转为可带小数的 tile 坐标。负坐标被夹到 0，非有限值拒绝。实际采样没有把坐标夹到世界右/下边界。玩家必须存在、active，并且不是 dead 或 ghost。

距离以下均为“本次位置相对**最后已存储点**”，不是相对上一次观察样本：

| 条件，按实际优先级 | 结果 |
| --- | --- |
| 距离 `> 160` tile | 异常跳跃，另起一段；恰好 160 不进入此分支 |
| 距离 `<= 2` tile | 不新增点，将 tick 间隔追加到最后点的 `DurationTicks` |
| 距离 `>= 4` tile | 新增普通点 |
| 距离在 `(2,4)`，且方向显著改变 | 新增方向点 |
| 距离在 `(2,4)`，未达到方向变化条件 | 不新增点，也不追加最后点 duration；仍推进文件和当前段的时间轴末端 |

方向变化条件为：相对最后点的距离至少 1.5 tile、有前一个有效方向、当前单位方向与前方向的点积 `< 0.5`。但 `<= 2` 的驻留合并先执行，因此实际能新增方向点的距离仍必须 `> 2`。方向仅在新增点时更新；没有既有方向时不会凭空形成方向点。

断段/重新播种的完整条件：

1. 初次加载当前 pair，或者恢复采样时没有 `_lastSample`。
2. 玩家—世界 pair 改变；先处理旧 pair 待存数据，再在新 pair 既有时间轴末端另起一段。
3. 离开世界或主菜单。
4. 身份不可用。
5. 玩家不存在、不 active、死亡或幽灵。
6. 位置不可用。
7. 与前一样本的 runtime tick 间隔 `> 600`；恰好 600 不进入该分支。
8. UTC 间隔同时满足 `> 30 秒` 且 `> max(30 秒, tickGap / 60 × 3)`；负 UTC 差按 0 处理。
9. 相对最后存储点的距离 `> 160 tile`。
10. 当前文件找不到最后点。

新段有新 GUID、断段原因和一个起始点，起始点 `Flags = 1`；因小于 4 tile 的方向变化新增的点使用 `Flags = 2`。新段时间起点等于既有时间轴末端，断段跨越的长 tick/现实间隔不计入路线时间，也不跨段连线。

一个容易误读的例外：`tickGap <= 0` 虽返回名为 `runtimeTickBackwards` 的诊断，但实现只是替换最后样本并安排下一次采样，**没有建立新段，也没有推进时间轴**。不能把诊断名字列成已经实现的断段动作。

文件记录了世界尺寸，但已存在的正尺寸不会因本次样本尺寸变化而重置路线。这与揭示统计“尺寸变化重扫”不同。证据：F02、F03。

### 5.3 文件、数量与保留窗口

每 pair 文件为 `footprints.json`，schema 1：

- 文件：`SchemaVersion`、`PairId`、`WorldSizeX`、`WorldSizeY`、`TimelineStartTicks`、`TimelineEndTicks`、`MaxRetainedTicks`、`Segments`、`LastUpdatedUtc`。
- 段：`SegmentId`、`StartTicks`、`EndTicks`、`BreakReason`、`Points`。
- 点：`TileX`、`TileY`、`StartTicks`、`DurationTicks`、`Flags`。

默认保留 `43,200,000 tick`，按 60 tick/s 是累计观察时间 **200 小时**。文件中已有的正 `MaxRetainedTicks` 被保留，不强制上限为 200 小时；只有不大于 0 时回到默认值。没有对应用户设置入口。

保留裁剪以 `TimelineEndTicks - MaxRetainedTicks` 为截止点：

- `StartTicks + DurationTicks < 截止点` 的点删除。
- duration 跨越截止点的点保留原坐标，将起点改为截止点并缩短 duration。
- 没有剩余点的段删除。
- 保留窗口不做真实轨迹插值来制造一个新空间交点。
- 这是时间保留规则，不是点数或段数上限。反复断段可以增加段和起始点而不推进相应长间隔，因此不能由 200 小时推导固定数量上限。

数量语义也必须区分：

- `SegmentCount`：当前保留的段数。
- `PointCount`：当前保留各段的点数总和。
- 诊断 `BreakCount = max(0, SegmentCount - 1)`：不是一生累计断段事件数；裁剪后会减少。
- 单点段占段数和点数，但无法组成路线线段。
- render cache 的候选线数、当帧绘制线数与存储点数不是同一种数量。
- F5 足迹行只有开/关，播放条只有播放/暂停、进度条和倍率；上述数量及保留小时主要进入诊断快照，没有独立用户数量面板。证据：F01、F03、F04、F12。

### 5.4 保存与失败恢复的实际强弱

普通保存间隔为 1800 runtime tick。新段播种会重新安排下一次保存，因此连续频繁断段可以不断后移周期保存时点。离开世界、资格失效、换 pair 和显式 flush 也会触发保存。

与揭示统计相比，足迹对“已有有效待存内存”有更强保护：

- 生命周期中断时先尝试保存；存在脏数据且失败，保留当前 pair、文件和脏标志，只清除最后采样与方向状态，等待恢复。
- 切换 pair 时，旧 pair 有脏数据且保存失败，就拒绝接纳新 pair 样本，避免把旧待存数据直接换掉。
- 普通周期写失败保留脏内存，不向后推进成功保存到期时间。
- 正常扫描中的失败会在后续到期采样再试；世界退出/资格失效/换 pair 的失败分支可能每 runtime tick 再试，因为没有独立失败退避。

但是初次读取失败保护不同：

`PlayerWorldFootprintStore.ReadForPair` 能报告坏 JSON、读取失败或 PairId 不匹配；`PlayerWorldFootprintService.LoadPairLocked` 没有检查这些成功/失败标志，直接用返回结果构造当前文件。失败结果中的空数据随后可被播种并保存，从而覆盖原坏文件。不能把“换 pair 写失败保留内存”的保护推广为“初次历史读取失败也不会覆盖”。

另有一个静态可推导的尾部时间差：

1. 正常采样在距离 `(2,4)` 且没有方向点时，会推进文件/段 `EndTicks`，但不改变最后点起始时间或 duration。
2. 保存的 `NormalizeFileForPair` 总会调用 `TrimSegmentToCutoff`；即使截止点为 0，该方法也按剩余点的 `StartTicks + DurationTicks` 重算段末端。
3. 因此尚未形成新点或驻留 duration 的尾部观察 tick，在保存文件里可能被缩短。内存文件并不会被保存后的规范化副本替换，重载前后可能有差异。

例如，仅有 `StartTicks=0、DurationTicks=0` 的起点，下一样本在 3 tile、没有前方向，内存时间轴可推进至 6；保存规范化仍可把该段末端重算为 0。这是源码路径反例，未运行测试验证，不把它写成实机复现结论。

所有保存均经共用 JSON 工具同步序列化整份规范化文件，不是增量追加日志。文件规范化会替换 schema、生成缺失段 ID、将非法坐标或负时间归零；没有更高 schema 只读隔离链。证据：F02、F03、F04、M-ST。

### 5.5 回放时间轴的完整规则

每次显示控制条或切换 pair，回放状态重置为：

- 暂停；
- 1x；
- 游标位于最新端；
- 不在拖动；
- 显示时间轴末端等于数据最新端。

允许倍率完整集合：**1x、10x、60x、300x、1800x**。切倍率只改倍率，不自动开始播放。

播放根据现实 UTC 两次推进调用的间隔，计算
`floor(间隔秒数 × 60 × 倍率)`
并推进路线 tick，最后夹到保留起点和数据最新端。播放到最新端自动暂停。位于最新端点击“播放”不会倒回开头；后续到最新端仍会自动停。

点击或拖动轨道会暂停播放，并把横坐标线性映射到显示时间范围。拖出条外仍继续处理已拥有的拖动；释放时做最后一次定位，然后释放拖动状态。

后台追加的处理：

- **最新端**：游标和时间轴末端跟随新数据。
- **历史暂停**：历史游标保持；显示时间轴末端冻结，避免后台追加把同一个历史位置挤向左侧。
- **历史播放中**：显示末端随最新数据更新。
- **保留窗口裁剪**：旧游标仍会被夹到当前可用时间范围；冻结不意味着可以回看已经删除的数据。
- **关闭地图或关闭展示后重开**：重新进入最新端、暂停、1x，不恢复上次历史游标。

控制条在大地图底部居中、自适应屏幕宽度，最大宽度 980；小屏使用较低高度。实际绘制只有播放/暂停按钮、绿色进度条与滑块、倍率按钮；没有数值时间戳、当前点坐标、段列表或数量文本。证据：F07、F08。

### 5.6 全部鼠标输入与原版交接

播放条的输入 owner 与录制状态分离。它使用自身记录的物理按下变化，而不是每帧重复把“仍按住”当成新点击。

- 左键从条内按下，播放条获得该次左键手势；点击空白条面也会消费，不触发其它按钮动作。
- 轨道拖动期间，即使鼠标移出条外，仍拥有该手势。
- 已拥有手势的释放帧仍阻止原版接收该释放，之后交还原版。
- 左键从条外按下再移入，不会凭移入自动取得该次左键手势。
- 鼠标悬停条面、正在拖动或处理拥有的释放帧时，消费右键、中键、Mouse4、Mouse5；该范围有滚轮时消费滚轮。
- 拥有左键时清除原版全屏地图平移状态，避免原版继续拖图。
- 条外普通地图操作不改变播放状态。
- Update prefix 先处理一次；原版 PlayerInput 映射完成后还会再次抑制，防止映射过程重新写回已消费的输入。
- 全局自动化输入门关闭时，左键仅信任 Terraria 进程内读取，禁用 OS 按下状态作为点击后备；这不等于整个控制条被禁用。
- 鼠标坐标按 UI 缩放/平移转换，并使用上次实际绘制的全屏 UI 尺寸进行输入命中，处理 Update 与 post-map draw 尺寸不一致的情况。

控制条资格判断只检查全屏地图和展示开关，没有直接检查 F5 是否可见。和 F5、地图标记选择器、其它同位置覆盖层同时出现时的最终交互优先级，仍需要联合验证；不能由单个条面的抑制测试推导所有覆盖层互不冲突。证据：F08、F09、N01。

### 5.7 绿色路线如何生成、限额如何降级

路线投影为：

`screen = (tilePosition - MapPosition) × MapScale + MapOffset`

渲染借用 `MapOverlayDrawContext` 的位置、偏移、缩放与透明度；使用绿色 `(48,255,96,220)` 乘地图透明度，1 像素厚度，以 `MagicPixel` 的单像素源区画线。足迹层本身不修改悬停文本。证据：F10。

限额分为三层：

1. **持久化层**：按时间裁剪，不受下面显示数字限制。
2. **发布候选层**：最多 200,000 条缓存线。
3. **当帧绘制层**：最多 20,000 条线，并进行屏幕裁剪及默认 1.5 像素的小步合并。

候选构建遍历保留的段和点，过滤非有限/负位置，按段时间排序发布描述。超限时：

- 当段数超过预算，按确定性的时间分布挑选段；预算仅 1 时优先最新段，其它情况覆盖早晚范围，并确保真正按时间最新的段被考虑。
- 段数可容纳时，先为每段分配至少一条，再给最新段保留一定额度，其余按额外线数比例分配，舍入余量偏向较新的段。
- 段内按锚点采样形成线。
- 当单额度的首尾弦退化为零而段内存在路线时，候选层选择该段最长的真实相邻边作为代表。

**限额后的线可能连接原始非相邻点。** `CanInterpolate=false` 仅阻止在粗线中间按时间假装移动，它不禁止将两个采样锚点连成一条完整轮廓弦。

**与本轮指令的明确区别**：附录 A 第 6 项要求“不直连被省略的非相邻位置”。上面记录的是冻结 Legacy 的反例，不能作为 R 默认继承的规则。后续候选必须保留这一用户约束；降低绘制数量时不能让省略轨迹被误呈现为真实直线路径。

当帧进一步限制数量时，也可能把多个候选线合并为“首候选起点到后候选起点/末端”的直线；只有 1 条额度时可以直接连接该段已选范围的首尾。因此：

- “断段之间不连线”可以成立。
- “每条画出的线都是原始相邻位置之间的真实走线”不成立。
- 一条折线路径在粗略轮廓中可能出现斜穿地形的直线；这种直线不能当成玩家曾按该直线行走的证据。
- 小于像素阈值的连贯小步还会通过累计锚点合并，避免整段因每步过小而完全消失。
- 多于当帧预算的可见段只能按确定性的时间排名选取，状态为 `readySegmentLimited`；不是保证每段可见。
- 对非正常重叠时间数据，精确检查当前活动诊断候选的数量上限为 128，超出会发布 `readyDiagnosticsLimited` 等状态；不能继续声称所有诊断数量均为逐条精确值。

回放的部分线插值只允许真正相邻、时间正向且未被重排改写时间边界的来源线。粗线在其结束时间到达前不会进行同样的部分插值。证据：F05、F06、F10。

### 5.8 稳定帧与持续追加的成本不同

| 情况 | 源码可确认的工作 |
| --- | --- |
| 展示稳定关闭 | render cache 首次切换发布空状态；后续走早退门。录制仍继续 |
| 展示开启且不在全屏地图 |录制与 render cache 仍可推进；实际足迹地图层不绘制 |
| 展示开启，缓存刷新到期 | 每 6 tick 解析身份；优先读当前内存，否则磁盘缓存 |
| 数据签名未变 | render cache 可避免重建发布，但**检查签名前已经取得并复制内存全史** |
| 数据追加、驻留 duration 改变、保留裁剪等 | 生成新签名，重建候选并发布新快照 |
| 发布快照、视图、游标都稳定 | Draw 复用已缓存的投影几何、选择和命令，不读源文件、不重新遍历全史、不重新排序；仍发出已有绘制命令 |
| 仅回放游标改变 | 复用投影几何；通过索引/二分和受限活动检查重新选择，必要时只投影部分线端点 |
| 平移、缩放、屏幕范围或发布快照改变 | 几何缓存失效，重新处理最多 200,000 条候选 |
| 时间轴已经超过保留期 | 录制每次裁剪检查遍历全部段和点，并构造候选保留副本；即使最后发现没有实际删除，也发生遍历与分配 |
| 保存到期 | 同步规范化、复制及序列化整份路线 |
| 生命周期/换 pair 保存连续失败 | 保留待存数据，但缺少独立失败退避，可能高频重试整份保存 |

这里“稳定”必须同时限定发布快照、视图和游标。**暂停回放本身不等于稳定快照。** 原地不动也会每 6 tick 合并 duration 并推进 `TimelineEndTicks`，录制签名包括这个末端；正常后台追加因此可以持续发布新快照，令下一次绘制重建几何。

这一设计确实避免了每个 Draw 直接读 JSON 和全史重排，但不能据此得出整个足迹功能在历史暂停时没有全史复制，或新记录只做增量几何更新。本轮没有运行大历史规模测试，没有实机 CPU、GC、磁盘或 FPS 结论。证据：F02、F03、F05、F06、F11。

### 5.9 R 候选组合

R 当前尚无足迹录制、路线数据格式、地图路线或时间轴播放实现。

候选组为“路线记录与回放”，应覆盖用户完整结果：记录资格、断段与时间含义、保留、展示、最新端/历史暂停、播放/拖动、地图输入交接、错误反馈。不能只迁移绿色线并把后台数据责任留空，也不能把 `DisplayEnabled` 自动改解释为录制开关。

可复用 R 已接受的玩家—世界身份、会话代次、公共输入消费、数据根目录和受控存储基础；但路线的高容量历史不能直接套用“偏好只保留最新值”的合并写语义。地图投影可和现有死亡点共享明确的当前地图几何观察，死亡点自身的图标锚点补偿不能套给路线。

Legacy 中的 6/1800 tick、200 小时、200,000/20,000 条、各距离阈值以及“展示关闭仍记录”，都需要在该组产品讨论时明确取舍。现阶段只记录事实和依赖，不自动建立 R 预算或实现授权。

## 6. 与死亡点、蓝图及原版地图的关系

### 6.1 身份可以共享，业务时间和文件不能混用

| 两端 | 已确认关系 | R 候选约束 |
| --- | --- | --- |
| 标记 ↔ 足迹 ↔ 揭示统计 | Legacy 使用同一玩家—世界 pair 归属，但分别保存用户资产、持续路线、可重算摘要 | 共享身份入口，不合并业务 owner |

| 能力 | 数据位置 | 实际绘制/转换 |

R 现有死亡点走另一条已接受链：对原版 `MapIconOverlay.Draw` 做 postfix，在原版绘制后画自有点；自有点命中时清除原版 text，由独立 post-fullscreen tooltip 显示选中的死亡事件。它还识别并避免重复绘制原版最后死亡点。未来新增标记不应无约定地再次清空 text 或重复打开 tooltip 批次。

Terraria 1.4.5.8 已有的原版地图操作包括：

- 原版地图视图位置和缩放、拖动状态。
- 两次左键相隔 `< 0.5 秒` 且屏幕位置距离 `< 2` 时触发地图 ping。
- `TriggerPing` 本地添加 ping；`netMode == 1` 时向服务器发送 NetPing 消息。
- 原版地图玩家交互还存在虫洞传送及消耗药水的实际动作链。

因此控制条或地图视图跳转按钮如果漏出左键释放，影响可能包括拖图、ping 或原版玩家图标动作；不仅是自身按钮重复点击。足迹条现有的 prefix＋原版映射后抑制、释放帧保留和 pan 清理都有具体保护对象。新功能应接入 R 当前公共输入消费基础，再检查和死亡点悬停、F5、选择器的整体排序；不能直接复制各自独立读取鼠标的 Legacy 模式而宣称互不影响。证据：N01、Z-LAYER、R03、F09。

## 7. 事实分层、缺口与返回范围

### 7.1 可以作为本轮已确认事实

- 冻结 Z 的地图标记是实际可追踪的独立能力；“大地图加强”总入口仍有未实现占位。导航、传送、智驾不因有按钮或提示就成为已实现能力。
- 冻结 Z 标记上限为 120、每页 10；早期 256 是有独立历史文档的旧阶段事实，后续更新记录明确变更为 120。保留双方来源，不倒改历史。
- 揭示统计只读地图，具有两模式、停止续扫和完成后的手动刷新；首次部分值和之后保留上次完整值是两套显示路径。
- 足迹展示、录制和回放暂停互相独立；展示默认关闭但正常 runtime 世界 tick 中继续录制。
- 足迹跨段不连线，段内显示降级可以连接非相邻锚点；粗线不是精确走线路径。
- 稳定发布/视图/游标的 Draw 复用不等于整个录制与发布链没有全史复制。
- 三类数据的读取失败、保存失败和生命周期保护并不相同，不能由共用原子写工具统一宣称“数据不会丢”。
- R 已接受的死亡点与身份/输入/存储基础是候选依赖；R 当前尚没有本专题这三项剩余能力的生产实现。

1. **原版谓词**：未新提取 1.4.5.8 `WorldMap.IsRevealed`，不把旧源码注释里的 Light 阈值当作本轮原版证明。
