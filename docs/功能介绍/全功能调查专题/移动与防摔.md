## 1. 结论与完整入口

四项主开关都默认关闭。连续冲刺保存的非关闭模式默认 `HoldDirection`；防摔十二项界面策略默认允许，但主开关仍关闭。F5 移动页实际有模拟连跳、连续冲刺、传送修正、智能防摔，防摔另有模态配置浮层，均可接功能开关键。没有玩家可调“防摔百分比”“无敌模式”“冲刺速度”的实际入口。

| 功能 | 真实能力 | 不应沿用的过度结论 |
| --- | --- | --- |
| 连续冲刺 | 按方向或双击保持，冷却就绪后向原版冲刺入口补脉冲；部分情况下还补写基于装备识别的 dashType | 不能说只写两枚输入位，也不能说同时按左右必然阻挡 |
| 模拟连跳 | 按住跳跃时在原版可用地面/空中机会补“释放→按下”；下+跳让路 | 不增加新跳跃次数；成功送脉冲不证明实际跳起 |
| 传送修正 | 真实使用 1326/5335 时，原目标受阻才在附近搜索可用目标并临时改鼠标 | 不直接传送玩家；“空位”不等于避开液体、敌人或所有伤害 |
| 智能防摔 | 预测坠落，按固定优先级使用能力、临时装备/雨伞、抓钩或传送杖，并处理部分恢复 | 不是绝对免摔；并非完全没有能力字段写入；未实现致死兜底，缓冲方块方案已废弃 |

默认与界面证据：`Config/AppSettings.cs:974–997`、`Config/MovementContinuousDashModes.cs`、`UI/Legacy/LegacyMainWindow.Movement.cs:24–137`、`Automation/Movement/MovementSafeLandingOptionCatalog.cs:9–40`。旧 [Legacy 移动与增益](../Legacy移动与增益.md) 是历史资料；其“左右同时按阻挡”和简单输入描述不能覆盖本篇下列源码反例。本轮不改写旧合同的身份。

## 2. 连续冲刺

### 2.1 模式、方向和资格全集

三项实际 UI 状态是关闭、按住方向键冲刺、双击并按住冲刺。内部 `Normalize` 只有 DoubleTapAndHold 保留，其它值归 HoldDirection；Off 是 UI 状态，不是归一化后独立执行策略。

`MovementContinuousDashService.cs:18–33,231–408` 维护左右物理控制状态、最近按下 Tick、双击武装方向：

- HoldDirection：当前方向保持就可考虑冲刺，不要求先双击。
- DoubleTapAndHold：同方向第二次按下距离前次不超过 18 Tick 才武装；反方向新按下撤销原方向武装并作为新一次起点。
- 同时按左右：较晚按下的一侧胜；同 Tick 时优先当前朝向，只要该方向仍按着，否则右侧。不是一概拒绝。
- 已武装方向有最多 2 Tick 的无方向短间隙宽容；超过则解除，并清双击起点。文本焦点、不可操控、离世界、关闭会清相应状态。

原版 `dashDelay == 0` 才就绪；负值也不是就绪。玩家必须可控、有能力、请求方向仍按住。能力完整定义见 `Compat/TerrariaDashCompat.cs:392–579`：

| 来源 | 资格和顺序 |
| --- | --- |
| 骑乘中 | `MountID.Sets.CanDash[mountType]` 可读且 true；不允许用角色饰品能力绕过不支持冲刺的坐骑 |
| 非骑乘已有能力 | 当前 `dashType > 0` 优先 |
| 饰品回退 | armor 3–9 中解锁可用槽升序；Tabi 或 MasterNinjaGear → type1；EoCShield → type2。先遇到者胜，不按强度另排序 |
| 盔甲回退 | 三件完整 SolarFlareHelmet/Breastplate/Leggings → type3；三件 CrystalNinjaHelmet/Chestplate/Leggings → type5 |
| 坐骑类型辅助值 | Chillet、ChilletIgnis 对应回退值6；真正骑乘许可仍取 CanDash，不是只支持这两种 |

当前 .8 `MountID.Sets.CanDash` 全集为 56 Bat、57 RollerSkates、58 RollerSkatesGreen、59 RollerSkatesWhite、60 RollerSkatesPink、61 Pixie、62 Chillet、63 ChilletIgnis、64 TrustyChillet、65 TrustyChilletIgnis。该表是当前原版许可，尚不证明每种坐骑的实际冲刺手势在 Z 均成功。

### 2.2 请求、实际写入和恢复

Runtime 每 Tick 分派。服务检查 Legacy 文本和原版文字焦点、有效世界、玩家能力、同来源任务、已有 queued pulse；若 UseItem/BridgeItemUse/BridgeUseItemPulse 通道忙则让路。没有要求整个队列为空。Low 独占 Dash 请求排队超时 200 ms、执行 250 ms（Service:47–231）。

`Actions/Executors/DashActionExecutor.cs` 在执行时重读当前能力/方向/冷却。Hook 已安装时，把请求交给 DashMovement 前置，期限为当前游戏 Tick+3 和 UTC+250ms；到期清除。这里返回 Succeeded/Queued 表示**脉冲已经预约**，不是原版冲刺已经移动。Hook 不可用时直接在 Runtime Tick 补一次，明确返回 AttemptedButUnverified，需要实机确认时序。

真正应用（`TerrariaDashCompat.cs:291–389`）会再次确认本机玩家、方向仍按住、可冲刺，调用方向改变出口，写 `releaseDash=true, controlDash=true`。若当前 dashType 缺失但已识别非坐骑装备回退，会**写回 `player.dashType`**；这个行为超出“只补输入”描述。代码没有直接写 velocity/position，也不主动清 dashDelay。

正常 DashMovement 后置将 `controlDash=false, releaseDash=true`，不是逐位恢复最初值；Runtime fallback 在下一个可读游戏 Tick 清同样两位。关闭也重置 pulse。恢复失败留诊断，不保证输入已经归还。双击武装、queued pulse、反射字段缓存均为静态进程状态，不落盘为继续冲刺任务；设置与绑定由 Z 全局配置保存。

**多人与失败边界**：业务没有独立服务端确认；原版运动链不等于所有拓扑已验证。R 应保留原版能力/冷却、统一输入许可和明确脉冲 owner，重新决定是否允许补写 dashType；不照搬各处反射缓存或与钓鱼配装的槽位解锁 helper 形成领域依赖。

## 3. 模拟连跳

### 3.1 完整触发规则

`Automation/Movement/MovementSimulatedJumpService.cs:18–199,233–337` 要求有效世界、本地可控玩家、真实 `controlJump` 保持，且没有原版或 Legacy 文本焦点。`controlDown=true` 直接让原版下+跳穿平台；背包、箱子或 F5 非文字区域本身没有在该业务层统一禁用。外层 Runtime 的游戏输入门仍独立存在，不能把业务中未列 UI 条件理解为失焦也会执行。

可用机会为：地面/滑墙，或处于空中窗口且至少一种原版能力可用。地面判据是 `abs(velocityY)<0.001` 或 sliding；空中窗口为非地面、jump 剩余<=0、`velocityY*gravDir > -1`。不是精确的地面碰撞证明。

| 能力 | 实际资格 |
| --- | --- |
| 二段/多段跳 | 反射所有 Boolean 字段名以 `canJumpAgain` 或 `CanJumpAgain` 开头，至少一个为 true；当前 .8 为 Cloud、Sandstorm、Blizzard、Fart、Sail、Unicorn、Santank、WallOfFleshGoat、Basilisk 九项 |
| 火箭靴 | CanUseBootFlyingAbilities、rocketBoots>0、rocketTime>0、rocketDelay<=0、canRocket；连跳另要求当前 rocketRelease=false。两个许可读取失败存在乐观 true 回退，不能称所有未知都关闭 |
| 飞毯 | 可控、空中窗口、carpet 且 canCarpet 或 carpetTime>0 |
| 翅膀 | wingsLogic>0、wingTime>0 |
| 已骑乘飞行坐骑 | active，CanFly 可确认 true，且空中窗口；CanFly 可由实例属性、flightTimeMax>0 或 usesHover 等事实确定 |

若地面机会已发过一次释放，保持地面时不会不停重发；空中同一机会也只发一次，离开该窗口才重新武装。进入地面会清空中机会，离地会清地面机会。请求入队后即记录已释放及 Tick+2 冷却，不以最终实际跳起才记账。触发原因文本依次 ground、airJump、rocketBoots、wings、mount、aerial；飞毯可落在最后的 aerial，不能因此认为未支持飞毯。

### 3.2 两阶段输入与成功口径

Low 独占 Jump 请求排队和执行均150ms，同源任务或 UseItem/Bridge 通道忙则让路。`Compat/MovementSimulatedJumpPulseCompat.cs:125–169` 在两个 Player.Update 前置阶段先 prime release，再 press；必要时处理 rocket release。它不新增 `canJumpAgain_*`，不修改速度/位置/落差。执行成功主要指输入状态写入完成；能力在执行间变化、原版拒绝或时序不同都可能导致未跳。

关闭会取消排队 pulse 并清机会状态。`Hooks/MovementSafeLandingPlayerUpdateHookCallbacks.cs` 对本地玩家执行，先防摔 pulse、后连跳 pulse；两个功能并非拥有完全独立的跳跃输入。不能仅靠它们来自不同 Feature 就允许同时改同一组位。

反射可用性按进程缓存，已解析为空也不会每 Tick 重扫。开启成本包括输入/能力读取及有界反射字段循环；无跳跃保持时可提前退出。关闭稳态 Runtime 跳过业务，但已安装 Hook 仍需入口检查。没有本次 FPS、按键延迟或多人实测。

## 4. 传送目标修正

### 4.1 完整工具、坐标与候选选择

工具全集只有 1326 RodofDiscord 与 5335 RodOfHarmony。`Hooks/TeleportRodHookCallbacks.cs:18–66` 挂原版用杖函数前后；服务先定位 item 参数、核类型、主开关、本机玩家、itemAnimation>0、ItemTimeIsZero（否则读 itemTime<=0）、世界可用及无文字输入。关闭仍走 Hook 的早期参数/类型/配置判断，不能称无 Hook 成本。

`Compat/TerrariaTeleportRodCompat.cs:117–206,273–327` 按原版重力方向将屏幕鼠标变成玩家左上角目标，再用 `LimitPointToPlayerReachableArea` 限制。原目标已通过检查就不修正；否则在该受限原点周围半径208像素（13格）、8像素步长的圆内枚举候选。循环 dy 从负到正、dx 从负到正；取平方距离严格更小者，等距保留先遇到者，因此相同距离存在上/左扫描顺序偏好。候选统计数包含距离剪枝前计数，不等于真实原版碰撞调用数。

每个有效候选必须满足：有限坐标；世界边界留50像素；再次限制后坐标不变；原版 AnyWallOfTypeOnLine(...,350) 不阻挡；目标左上格墙87在世纪之花前的地下或 Remix 条件不阻挡；玩家实际宽高的 SolidCollision 为 false。任何必要兼容读取失败拒绝该候选。未额外检查熔岩、敌人、陷阱、平台下方安全落点或之后摔落，故“safe”在此是**原版传送几何资格**，不能译成绝对安全地点。

找到候选后反变换到鼠标坐标，只有能捕获还原状态才覆盖；原版运行后恢复鼠标。找不到时保持原版原目标继续，让原版自行处理；不是取消玩家动作或强行穿墙。安装是 Prefix/Postfix，不能把后置注释“always”当作原版抛异常时也可靠 finally 的证明；需后续核对实际 patch 的异常恢复合同。

### 4.2 当前原版操作与代价

当前 .8 `Player.ItemCheck_UseTeleportRod:45859–45918` 先应用 itemTime，再检查边界、350线、墙87/进度及 SolidCollision；通过才 Teleport 并 SendData(65)。使用1326且已有 chaosState 会扣 `statLifeMax2/7`，可能死亡，并重置生命恢复；随后加 Buff88 持续360Tick。5335无此混乱分支。

因此修正失败仍可能消耗原版使用时机；修正成功不表示没有混乱扣血。Z 没有直接 Teleport/扣血/加Buff，也没有提供网络 ACK。半径内最多扫描固定二维候选集合，每候选涉及限制、线检测和碰撞，实际成本受环境/首次命中距离影响；它不是每 Tick 全世界扫描，也未实测时延。

## 5. 智能防摔：配置和策略全貌

### 5.1 十二项界面与遗留字段

实际配置项全集：二段跳、火箭靴、飞毯、翅膀、马掌、雨伞、抓钩、飞行坐骑、精灵腿、减伤坐骑、传送杖、重力球。全部默认允许；抓钩提示明确不保证稳定。`gravity_globe` 读取旧 GravityGlobe 或 GravityPotion 任一 true，设置时同时写两字段，不能把历史 GravityPotion 字段当成真实喝药策略。

缓冲方块虽还留有默认字段、旧模型及方法，策略目录已移除，旧 builder 标为废弃。名为 `Strategies/BlockPlacementStrategy.cs` 的当前内容实际是 **TeleportRodStrategy**。羽落、耐力、铁皮等旧字段/致死缓解占位不是当前可执行策略；`NotImplementedStrategy` 的 priority6 始终不是 candidate，不能按名字承诺致死兜底。

### 5.2 危险判定、原版事实与预测

`MovementSafeLandingCompat.Analysis.cs` 先读取能力、速度、重力、角色尺寸、fallStart、extraFall。最低下落速度6.25；危险高度候选为估计落差>=22+max(0,extraFall)，fallStart未知时需要速度>=10.5。速度足够严重并不直接绕过后面的已知落差条件。预测找到落点后，impactTicks=距离/下落速度，且须0–18Tick才进入危险态。

“已经安全”依序包括 creativeGodMode；非石化且 noFallDmg；slowFall；wet/honeyWet/shimmering；webbed；非石化且已抓钩；非石化且有效槽穿翅膀；非石化且当前翼飞行状态；非石化且坐骑 fallDamage<=0.001。这里是在避免摔落伤害的意义下判安全，不表示液体、敌怪或其它伤害无害。

投影落点还会识别液体（含熔岩，仅标为不产生摔伤）、蛛网51/697、云189/196/460/717/718/719、粉史莱姆371、气球446/447/448、便便666、Tile19且style49的云平台。这是完整的固定特殊表；其它实体表面按原版 solid/platform 与 frame/slope/halfbrick 规则探测。

落点探测距离为 `min(768,max(128,(int)(fallingSpeed*24)+96))` 像素，从8像素起每16像素粗查，命中区间再细分到4像素；考虑横向速度预测、角色宽度、平台/斜坡/半砖和碰撞。它不是完整物理仿真，静态预测不可替代真实复杂地形/高速/反重力的测试。证据：`MovementSafeLandingCompat.cs:19–40`；`Analysis.cs:35–236`；`AnalysisHelpers.cs:88–159,244–395,727–852`；`LandingProbe.cs` 的实际表面选择与当前原版碰撞调用。

### 5.5 触发窗口、排队和一次下落保护

窗口同时检查预计 Tick 与距离，不能只满足其一。常规主动窗口为：二段3.5Tick且动态24–40像素；火箭4.5/56；飞毯3/32；重力4.5/56；坐骑6/96；传送6/96。临时换装提前窗口依次为二段10.5Tick/最多112像素、火箭6.5/176、飞毯6/144、重力11.5/160、坐骑8/224；被动装备5/72，雨伞3.5/32。二段动态距离为 `ceil(max(speed*8/60*16+6,16))+ceil(speed*3.5)`，夹到24–40；换装另加7Tick速度提前量再限112。

抓钩策略不只使用通用12Tick窗口。令 `v=max(下落速度,6.25)`，`d` 为玩家中心至目标距离，`s` 为钩速，`q` 为指向重力方向的单位向量分量，则相对追赶速度为 `s*max(0,q)-v`。q<=0、钩的向下速度<=0.25或相对速度<=0.25判太慢；所需提前距离为 `16+ceil(v*(2+玩家半高/相对速度+1))`。预计撞击 Tick 小于 `2+d/s+1+1` 判太晚；撞击距离大于提前距离或撞击 Tick>20判太早。2、1、1分别为输入、抓住确认、安全余量。太晚/太慢而有传送候选则让行，无传送后备则低置信最后一试。`GrappleActivationHardCapPixels=480` **仅声明、没有实际引用，不能当有效上限**。

抓钩目标取实际预测表面：无表面证据则取落点横坐标和落点格顶+4；无横移的普通/半砖目标横坐标夹在格内3..13，斜坡2..14；有横移则朝前脚外侧加 `clamp(abs(vx)*2.5,8,24)` 像素。顺坡移动改用投影中心向运动方向偏10像素（再按角色宽度限制）；斜面Y按坡型1/3为格顶+localX，2/4为格顶+16-localX，最后沿重力方向深入4像素。以上是 Z 几何启发式，不保证原版钩能附着。证据：`SafeLanding/Strategies/GrappleStrategy.cs:14–22,133–340,343–500`。

新救援 High；已装输入/抓钩通常450ms，临时装备/传送650ms；恢复装备 Normal，排队2秒、执行3秒。普通主动冷却4Tick，传送12Tick，其余45Tick。一次下落的重复救援保护在分析不可用、不再危险、已经安全、原已知落点消失、落点任一轴变化>128像素、或玩家横移>192且落点横移>32像素时清除；持续>180Tick也清除。传送陈旧检查另对落点/传送目标任一轴>128、玩家横移>192分别拒绝，缺少相应元数据则无法作该项比较。executor 开始和提交 ItemUseBridge 前重做危险分析；但通用 Bridge 的“使用有变化”仍不等于已到达安全点。证据：`MovementSafeLandingService.DescentGuard.cs:118–189,227–303,331–379`。

## 6. 防摔的真实写入、结果与恢复

### 6.1 临时装备不是只发原版输入

`Compat/MovementSafeLandingEquipmentCompat.Apply.cs:10–136` 在执行时比较源/目标签名，然后直接交换两个容器的 **Item 对象**。签名只比较 type、stack、prefix，空物品互相视为相同；虽然保存 Name，不参与比较，也没有对象 generation、角色/世界身份字段。用户换成同签名的另一件物品不能仅靠此签名识别。

写目标后写源采用短路表达式；第二次写失败时可能已有第一处变化，此分支没有完整回滚，也未生成成功后的恢复记录。目标读回失败同样可能发生在已经交换之后。只有后续选槽失败分支尝试把两侧写回，而其恢复调用结果没有完整验证。因此不能把 `applySkipped` 当作未写入。

换装后调用 `ApplyEquipFunctional`，二段跳调用 `RefreshDoubleJumps`；还会在符合空中条件时给火箭 `rocketTime=20`、给飞毯 `carpet=true/canCarpet=true/carpetTime=20`、给重力球 `gravControl2=true`（FunctionalRefresh.cs:18–206；Compat主文件:17–18）。这不是直接改 fallStart/velocity，但确实是主动能力字段写入。新版是否保留这样的临时能力补充必须明确，不能仅按“原版输入辅助”批准。

换装结果、能力读回、触发结果分别记录。被动装备“已换上”不证明最终无伤落地；主动策略要再次检查能力，等待3Tick settle、必要时15Tick重试。UI 文案不能把记录数归零等同于安全完成。

### 6.2 装备恢复、手动改变与关闭

临时装备至少保持6Tick，满足落地/滑墙检查后还须稳定18Tick；纯雨伞稳定3Tick。落地要求下降速度<=1并且实际零速附近（abs<=0.05）的2像素碰撞探针，或滑墙；刚救援后上升不立即脱掉。恢复请求间隔30Tick。

恢复时目标槽必须仍匹配救援物品签名；不匹配记 userChangedManagedSlot，放弃该记录，不覆盖玩家新物品。若原目标非空，原物品必须仍在记录的暂存槽并匹配，否则记 originalMovedByUser，停止对该记录恢复。原目标为空时先找原来源空槽，再找背包0–49空槽；无空间保留 pendingRestoreNoSpace，继续穿救援物并要求后续处理。鼠标浮动物品非空阻挡换装及恢复，恢复记录继续保留。

这些保护是签名/槽层级，不能夸大为唯一物品身份。恢复的两次写入也不是跨槽原子事务；当前没有独立网络完成票据。`Store.cs` 的字典是进程内 request→plan/result，名字 Store 不表示落盘恢复日志。

关闭主开关后仍有 residual state 就继续 Tick 清理；离世界/主菜单/本机玩家不可读时保留待清理而等待，**不是立刻穿回原装备**。已读临时装备模型/恢复入口只保存槽和签名，未绑定可靠角色×世界/Session generation，恢复时重新获取当前本机玩家；这是需要后续核实并消除的跨会话恢复风险，不能自动假设“换人会清完”。未证明已经发生串角色恢复。

### 6.3 重力、坐骑与传送的专门边界

重力恢复实际 `Recovery.GravityRestore.cs:11–134` 一旦 pending、可控且仍有重力球，就每3Tick尝试回原重力；没有按策略目录中的文字等待稳定落地，诊断 reason 是 immediateGravityRestore。超过600Tick会标记 manual required 并清 pending，不是成功恢复。

坐骑恢复不只等落地：下降速度>1.25，预计撞击<=4Tick，或距离<=clamp(ceil(speed*4),48,128)时可以提前取消骑乘；否则按实际落地稳定检查，重试间隔6Tick。已自行下坐骑则清债务。这里只核当前是否骑乘，不能据此保证玩家手动改骑另一只坐骑时绝不误取消。

传送优先5335再1326，同种低槽；搜索范围是 `IsSupportedItemUseSlot` 支持的背包/热栏槽，不是银行。UseHotbarItem executor 明确把 originalSlot 交给 Bridge 还原，区别于提炼的 UseSelectedItem 默认行为。防摔传送目标按预测落点格上方/反重力下方一格中心生成。传送修正开关是另一项：开启时同一原版调用可再修正鼠标，关闭时防摔仍可发起原版传送；二者不是彼此必开的前置条件。

混沌杖仍执行原版 chaosState 扣血风险。策略候选没有以“用后不会死”为完整证明；故“防摔”可能选择具有其它代价的手段，需要产品合同决定是否允许，以及给出什么可见反馈。抓钩/坐骑/跳跃输入完成、临时装备换上、传送 ItemCheck 有变化，分别都不能单独证明最终救援成功。

## 7. 生命周期、持久化、多人和成本

持久数据只有全局四开关、冲刺模式、防摔选项与快捷键偏好；临时武装、冷却、装备搬动记录、重力/坐骑恢复、鼠标/输入覆盖均为进程内状态。没有崩溃后自动恢复装备的可靠文件合同，不能把人物存档保存出的临时装备状态当作插件恢复记录。

Z 的总分派顺序为防摔→冲刺→连跳（RuntimeAutomationDispatcher:574–600）；Player.Update 前置为防摔 pulse→连跳 pulse。输入通道虽避免部分并发，并没有把所有“有冲突的最后写入”统一为带会话代次的 owner。文字输入、失焦、死亡、切角色/世界、原版能力消失和用户主动换槽应各有具体验证；关闭开关不能撤销已发出的传送/抓钩/装备保存。

原版传送有消息65，普通运动依原版同步；临时装备路径直接写本机容器并刷新能力，所读链没有独立等待服务器承认的事务。目录 `SupportedByOriginalAction` 不能替代此差异，更不能证明 Host & Play、普通客机、SSC 或独立服务器均已验收。

| 状态 | 真实工作量边界 |
| --- | --- |
| 全关闭且无恢复债务 | Runtime scheduler 跳业务主体；已安装 Dash/Player.Update/Teleport Hook 仍作入口检查；传送 Hook 可读参数后才检查开关 |
| 普通开启但无危险 | 输入样本/能力缓存按帧懒读；防摔 cheap precheck 能避开完整落点/装备扫描，便宜跳过诊断按30Tick更新 |
| 危险/开动作 | 下落碰撞与表面探针、背包/社交装备扫描、策略结果/诊断分配、输入桥和反射/直接调用；不能把这些都算成恒定一次读取 |
| 状态改变 | 新玩家/世界/Tile表、输入模式/名单、装备变化使部分缓存失效；不同缓存的生命周期并不完全相同 |
| 失败与长期债务 | 无恢复空间或不可控会持续重试/保留；重力600Tick放弃；反射失败有缓存或节流；既不等于无限每帧重建，也不等于完全无成本 |

本轮没有测帧率、耗时、GC 或输入延迟。后续自动工作量断言应覆盖关闭无债务、关闭有债务、静止、危险但无候选、重复同一次下落、UI阻挡以及恢复失败；实机验证集中于真实动作与恢复，不要求玩家分析内部 JSON。

## 借用、部分失败与相邻保护

B02和C03统一本篇与钓鱼配装/捕捉的借用语义，沿已有输入与物品保护入口；允许哪些防摔策略、是否临时换装是产品取舍。冲刺写能力字段不是纯输入，传送几何可达不保证安全，范围说明不能隐去代价。

两槽第二写失败时第一写可能已发生（§6相关Apply证据），`applySkipped`不等于无副作用；未开始/部分执行/完整写入/恢复待定必须分开。重力、坐骑和装备归还都核当前 owner、原会话及玩家新操作，不能每Tick全恢复。稳定借用不重复交换，真实落地/手动接管/物品更换/世界变化及时结束或作废，未知不得伪报获救。
