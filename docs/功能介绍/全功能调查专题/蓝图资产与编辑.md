# 蓝图资产与编辑

## 1. 范围、版本和结论边界

本专题调查蓝图创建、模板库、世界实例、预览、显示与层级、移动、区域修改、镜像和八类同类替换。实际施工、背包扣料、施工轮次及后处理执行属于另一个施工专题；本篇会明确两端交接的位置。

以下 `Z` 证据均固定在 `Kuroneko2020/JueMingZ@6ac6356c0c564f43284590c168855e96c50e13f7`；未特别注明的源码路径均相对该仓库。`R` 生产基线为 `Kuroneko2020/JueMingR@df8a029873176276d0f620d32b0ac02ae9ea7744`。后续调查文档提交不等于生产实现变化。调查为静态只读查证，仅整理调查文档；没有构建、执行产品测试、启动游戏或修改生产文件。

本轮用户要求保留三种不同对象：

1. **模板资产**：可保存、命名、删除、导入和导出的蓝图内容。
2. **世界实例**：某个玩家—世界身份下，带位置、显示状态、层级、擦除区域及施工记录的模板快照。
3. **真实世界建筑**：通过施工能力实际产生的方块、墙、家具等。

模板“放置”先建立世界实例。移动、镜像、移除实例或修改其区域，不因此搬动、镜像或拆除真实建筑。模板删除与实例移除也不是同一个操作。

`Features/Catalog/BlueprintFeatureRegistrar.cs` 仍把总蓝图项登记为 `Implemented(false)`、`Placeholder`，并含有较旧的待实现描述；但实际 F5、输入、资产库、实例和投影代码已存在。登记元数据不能单独证明“没有蓝图功能”，同样不能证明整条功能链已完成或经过实机验收。

## 2. 入口、创建选区和只读采集

### 2.1 玩家实际可见入口

F5 蓝图主页有三项设置：

- “快捷入口”：手持指定物品时显示快捷操作栏；实际提示为“手持凝胶显示快捷开始栏”。
- “自动放置”：是否允许施工端自动放置。
- “同类替换”：总开关和分类设置弹窗。

主页还有七项动作：创建蓝图、保存蓝图、移动已放置蓝图、修改已放置蓝图区域、镜像已放置蓝图、蓝图库、已放置蓝图列表。各动作有独立快捷键设置；创建、移动、修改区域、镜像按钮会随活动状态变成退出或取消。没有实例时，相应编辑按钮禁用。

默认手持物品 ID 为 `23`，即凝胶；配置值有效范围为 `1–9999`，不合法时恢复 `23`。快捷入口、自动放置、替换总开关和八个替换子开关默认全部关闭。动作入口并非必须先打开“快捷入口”；它们由各自的统一快捷键绑定和输入门控决定。

旧的直接打开蓝图页命令 `OpenEntryHotkey` 返回 `directEntryHotkeyDisabled`。不能把历史默认 `N` 键当作当前运行时仍生效的入口。运行时使用统一快捷键绑定；旧设置桥接存在于测试路径，不能据此扩大当前产品行为。

### 2.2 选区不是“后一个矩形替换前一个矩形”

创建使用内存中的格点集合，可以多次拖框。每次矩形提交逐格切换状态：

- 原来已选中的格子被取消选择；
- 未选中、可读取的格子被加入；
- 不可读取的格子跳过；
- 因此可以追加不相连区域，也可以通过重叠拖框从原选区中扣去一部分。

单次矩形的包含端点面积不得超过 `16,384` 格；已选择集合最多 `16,384` 格。超过单次矩形上限会拒绝整次拖框。接近全局集合上限时，代码按 `Y→X` 顺序逐格处理，已有格子仍可被取消，新增格子只在尚有容量时加入；这不是预先计算整个切换结果后一次性提交的事务。

这里的可选判断允许“能读取但没有建筑内容”的空气格参与选区。叠层采集时会跳过没有可保存内容的格子；全选空气最终提示“选区内啥也没有喔”。因此，选区边界可以影响模板尺寸和锚点，但空气不是拆除指令，也不会产生“清空这里”的世界操作。

“退出创建”保留已经选择的格子，停止当前拖框和活动输入；再次开始创建可以继续。 “清空选区”清除格点并保持创建状态。通用取消和切入若干其他模式会清掉选择；不能把所有退出、取消、清空写成同一种行为。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintCreationMaskState.cs:12、47–145、149–250、311–367、421–449`，`BeginCreate / ExitCreate / Cancel / FinishCreate / HandlePointer / ToggleDragRect`；`src/JueMingZ/UI/BlueprintCreationOverlay.cs:333–365`，传入的逐格函数返回读取是否成功；`src/JueMingZ/Automation/Blueprint/BlueprintCaptureService.cs:124–255、258–292`。

### 2.3 输入所有权与创建生命周期

进入创建后 F5 窗口隐藏，让玩家在世界上拖选。左键按下和释放边缘来自物理按键状态，而不是被 UI 消费后的世界左键值，避免一次 UI 消费被误认成鼠标释放。

F5 窗口命中、指针被其他 UI 占有，或原版的地图全屏、背包、聊天、NPC 对话、主菜单、世界未就绪等状态，会阻止世界选区输入。活动拖框遇到 UI 占有会中止本次拖框并保留已选格子；在世界外释放也取消本次拖框。活动创建会消费相应世界左键，防止同一次点击同时执行原版使用物品。

保存先把选区标记为待采集，再同步只读采集并写模板库。采集或保存失败时，入口停留在 `CreatedPendingSave`，保留选择和失败消息。保存成功后清空选择，并返回工具待命；“保存后使用”路径则尝试进入摆放预览。若资产已经保存成功但预览启动失败，结果会说明“已保存，但摆放预览启动失败”，不能把这次操作笼统当作资产未保存。

证据：`src/JueMingZ/UI/BlueprintCreationOverlay.cs:267–387、405–444`，`UpdateInputGuard / ShouldBlockCreationForPointerOwnership / IsVanillaUiBlockingWorldSelection`；`src/JueMingZ/Input/LegacyUiActionService.Blueprint.cs:158–203`；`src/JueMingZ/Automation/Blueprint/BlueprintEntryState.cs:184–273、341–393`。

### 2.4 采集保存哪些内容

采集以只读世界格子读取器构造模板，没有借采集临时覆盖 `Main.tile` 或调用世界施工来“试摆”。保存的格层包括：

- 普通方块及其内容 ID、样式、帧、斜坡、半砖、失活状态；
- 多格家具对象及其对象组、原点、宽高和子格坐标；
- 墙；
- 红、蓝、绿、黄电线，按颜色位保存并统计用线量；
- 致动器；
- 方块或墙的涂料及涂层信息，附在相应层上。

模板还保存材料提示和能力缺失标记。液体只记录“未采集”能力标记，不形成可恢复的液体内容。文字牌文本、容器内部物品、展示或装备类实体负载也没有被资产采集；外观帧可被保留，不等于内部数据被恢复。

具体外部负载提醒所覆盖的原版 tile 类型：

- 文字：`55、85`；
- 容器：`21、88、441、467、468`；
- 装备/展示负载：`128、269、334、395、470、475、698`。

这些是采集缺失标记，不应被误写成所有镜像或外观一律失败的总开关；镜像还会按其自己的对象和帧证据作判断。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintCaptureService.cs:295–429、452–528、543–570、1126–1264`，`BuildCell / BuildObjectExpansionCell / TryAddTileLayer / BuildExternalStateNote / BuildWireMask / AddMaterial`；`src/JueMingZ/Automation/Blueprint/BlueprintModels.cs:273–347`。

### 2.5 触碰家具子格时，补齐的是整件家具

若选中格属于可识别的多格家具，采集根据原版对象数据和边界把该对象全部子格加入采集请求。补齐出来的格子只采集该家具对象层，不顺带采集那些格子里未选中的墙、电线或致动器。

对象身份和完整性需要进一步核对：

- 家具边界必须包含最初触碰的子格；
- 单件对象面积不能超过 `16,384`；
- 不同对象的扩展范围冲突会使请求构建失败；
- 扩展后再次核对各子格的读取状态和对象身份；
- 某件对象不完整时，抑制该对象层、移除只为补齐它而产生的请求，并留下缺失标记；
- 原来明确选中的格子，其余墙、电线等层仍可保存；只有全部内容都无法保存时才成为空内容失败。

`16,384` 选区格点上限和单件家具面积上限都不能冒充最终采集请求总数上限：多个对象补齐后的请求并集没有在该构造流程中再套同一个总数上限。

模板尺寸按全部采集请求范围计算，再把格子转换成相对坐标。锚点位于范围中心，使用向下取整的 `(尺寸−1)/2`。普通方块按格计材料，多格对象通过类型、样式和对象原点去重，只计一件本体材料。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintCaptureService.cs:124–255、365–449、618–799、841–945`，`TryBuildCaptureCellRequests / ValidateObjectExpansionRequests / TryCreateObjectExpansionSignature / TryAddObjectExpansionRequest`。

## 3. 模板资产、格式、目录和蓝图库

### 3.1 资产身份和存储范围

资产根目录为 `ConfigService.ConfigDirectory/blueprints`：

| 内容 | 路径或标识 |
|---|---|
| 全局模板库 | `templates.json` |
| 导入默认目录 | `imports/` |
| 导出默认目录 | `exports/` |
| 玩家—世界实例文件 | `worlds/<trim 后 WorldPairKey 的 SHA-256>.json` |
| 新模板身份 | `template-<GUID N>` |
| 新实例身份 | `instance-<GUID N>` |
| 当前 schema | `1` |
| 单模板导出类型 | `JueMingZ.Blueprint.Template` |

模板库不是按世界保存；实例文件以玩家—世界配对身份隔离，同时保存 `WorldKey`。世界文件名是配对键的哈希，不是显示名称。

模板包含独立 ID、名称、创建与更新时间、尺寸、锚点、`FormatVersion`、能力缺失标记、格层集合和材料表。世界实例另有独立 ID、名称、模板身份快照、位置、隐藏状态、层级、材料浮窗显示状态、擦除遮罩、完整模板快照、自动施工进度和完成层记录。

实例拥有模板的深拷贝。以后重命名或删除库模板不会反向改写已保存实例；编辑实例也不能写回模板库。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintStoragePaths.cs`，`GetDefaultRootDirectory / BuildLibraryPath / BuildWorldInstancesPath / BuildDefaultExportPath / BuildImportDirectory`；`src/JueMingZ/Automation/Blueprint/BlueprintModels.cs:7–153、419–528`；`src/JueMingZ/Automation/Blueprint/BlueprintWorldInstanceStore.cs:68–123`，尤其 `106–109` 的快照所有权。

### 3.2 格式保护不能只概括为“支持 schema 1”

外层导入文件检查 `SchemaVersion > 0 && <= 1`、精确匹配 `SchemaKind`，并要求有模板对象；未知外层版本或错误类型被拒绝。成功导入时会清空输入模板 ID 和时间，作为新模板创建，重新分配身份并处理重名。

但冻结实现还有以下边界：

- 直接加载本地 `templates.json` 时，没有同样的顶层 schema 拒绝分支；
- 世界实例加载核对非空文件 `WorldPairKey` 是否匹配当前请求键，但没有同样的顶层 schema 版本检查；
- 模板 `FormatVersion <= 0` 被置为 `1`，正数则保留，包括大于当前版本的数值；
- 资产归一化会丢弃无效或重复模板 ID、空层，规范数字和名称，并补对象组信息；没有在这一层完整拒绝未知层类型、重复格坐标或超出尺寸的坐标。

因此可以说“导入外壳有版本和类型保护”，不能说“所有资产字段都做了严格版本迁移和结构验证”。R 候选需要把导入外壳、模板格式、对象数据和本地库损坏分别列为合同，不能直接继承成一个统一安全结论。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintTemplateLibraryStore.cs:33–48、224–259、340–470`，`TryLoad / ImportTemplate / NormalizeCreateTemplate / NormalizeTemplates / NormalizeCells / NormalizeLayers`；`src/JueMingZ/Automation/Blueprint/BlueprintWorldInstanceStore.cs:32–65、161–218`。

### 3.3 蓝图库完整操作

蓝图库按每页 `6` 张卡片分页。卡片包含模板缩略预览、名称、内容摘要、能力缺失提示及“放置／导出／删除／材料”。

- **命名**：双击名称进入文本框；编辑时原“放置”位置显示“保存”。保存空名失败。库层把名称去除首尾空白、把换行变为空格并限制为 `80` 个 UTF-16 单元；实际通用 UI 文本输入上限是 `48`，两个限制不是同一个数。
- **重名**：按不区分大小写查重，尝试名称后追加数字，极端情况下追加 GUID 片段。不能把重名理解成覆盖已有模板。
- **删除**：第一次点击变成“确认”，再次点击同一模板才删除。删除的是库资产，不删除已经保存的实例或真实建筑。
- **材料**：展开的是模板自身保存的材料清单；它不是当前背包可用量，也不是某实例按遮罩、重叠和世界完成状态计算出的剩余施工量。
- **放置**：选择模板并进入摆放预览，关闭库窗口；此时尚未创建世界实例，更没有施工。
- **分页／返回／导入／其他操作**：会按各自路径处理文本焦点；不能把未提交的编辑文本当作已经改名。

模板缩略绘制存在显示限额，不是资产内容截断；后续规模条目将与实例投影绘制分别说明。

证据：`src/JueMingZ/UI/Legacy/BlueprintLibraryUiState.cs:111–201、224–310、445–534、572–652、785–812`；`src/JueMingZ/UI/Legacy/LegacyMainWindow.Blueprint.cs:1258–1374`，`DrawBlueprintTemplateCard`；`src/JueMingZ/Input/LegacyUiActionService.Blueprint.cs:834–980`；`src/JueMingZ/UI/Legacy/LegacyTextInput.cs:8`；`src/JueMingZ/Automation/Blueprint/BlueprintTemplateLibraryStore.cs:119–185、554–615`。

### 3.4 导入导出和文件选择失败

实际 UI 使用 Windows 文件对话框，导入只选一个文件，要求文件和路径存在；导出默认 JSON 扩展名并由保存对话框询问覆盖。UI 默认建议文件名是 `JM-<本地日期 yyMMdd>0000.json`，不同于存储 API 在没有指定路径时使用的“清理后的名称—ID.json”。

导入或导出取消只记录取消状态，不算写入成功。UI 线程状态不符合文件对话框条件时返回 `dialogUnavailable`，其他对话框异常返回 `dialogFailed`。存储 API 的无路径导入另有约束：`imports` 目录顶层必须恰好有一个 `.json` 文件；零个和多个分别失败，不能猜选其中一个。UI 的明确路径导入不依赖这个单文件目录规则。

导出包含一个模板快照及版本、类型、导出 UTC 时间。导入产生新资产身份，即使源文件来自自己刚导出的模板，也不是按旧 ID 自动覆盖库中原资产。

证据：`src/JueMingZ/UI/Legacy/BlueprintFileDialogService.cs:1–121`；`src/JueMingZ/UI/Legacy/BlueprintLibraryUiState.cs:314–441`；`src/JueMingZ/Automation/Blueprint/BlueprintTemplateLibraryStore.cs:188–319`；`src/JueMingZ/Automation/Blueprint/BlueprintStoragePaths.cs`，`BuildDefaultExportFileName / BuildDefaultExportPath`。

### 3.5 保存与缓存的真实失败语义

所有这些 JSON 文件通过同目录临时文件写入，使用 `WriteThrough`、`Flush(true)`，再以文件移动或 `File.Replace` 提交；没有先删除旧文件再复制的常规提交路径。I/O 异常最多尝试四次，间隔 `15、30、45 ms`，属于同步调用上的最多 `90 ms` 重试等待，另加序列化和磁盘时间。失败后清理临时文件，返回失败；不能因此保证断电、任意文件系统或外部并发编辑下绝不损坏。

模板保存操作会加载、克隆、归一化并重写整个模板列表；这不是只追加一个增量记录。模板库 UI 使用进程内加载缓存：首次加载后 `_loaded=true`，包括读取失败的情形；正常创建、导入、改名、删除等会触发刷新，存储根目录变化也会使缓存失效。没有在这个 UI 状态实现里看到文件监视器或每帧重新读取模板库。外部手工改文件不等于界面马上自动更新。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintJsonSafeFileStore.cs:15–101、130–186`，`TryRead / TryWrite / CommitTempFile / RetryIo`；`src/JueMingZ/Automation/Blueprint/BlueprintTemplateLibraryStore.cs:62–82、322–337`；`src/JueMingZ/UI/Legacy/BlueprintLibraryUiState.cs:844–900`。

本段已完整返回第 1–3 节。尚未返回的是世界实例管理、移动／区域修改／镜像、八类替换、投影与材料缓存、施工交接及 R 复用候选。


## 4. 摆放预览与世界实例

### 4.1 “放置”先定位实例，不直接施工

蓝图库的“放置”把模板深拷贝到预览状态。鼠标所在世界格对齐模板锚点，实例原点为“鼠标格坐标减锚点”。该公式没有把整个模板范围自动夹在世界边界内。

进入预览时必须先释放触发入口的左键，再接受下一次新的左键按下，避免点击库按钮的同一次按压直接确认位置。UI 占有、鼠标不在有效世界格时不会确认；物理按键和被消费后的世界按键分别处理。

确认时：

1. 强制刷新当前位置的预览对照；
2. 解析当前玩家—世界身份；
3. 读取该身份的实例文件；
4. 选择现有最大层级加一；
5. 用预览模板快照创建新实例并保存；
6. 保存成功才退出预览、通知已放置列表。

没有身份、读取失败或保存失败时保持预览并报告原因。预览有冲突、不可读格或内容超出世界范围，并不是这里拒绝建立实例的条件；施工可行性另由投影和施工端处理。`IsUsableTemplate` 在该层检查的是非空模板 ID 和正数宽高，没有要求至少一格内容。因此，“采集不能创建纯空气模板”不能扩大为“所有外来模板都绝不可能形成空实例”。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintPlacementPreviewState.cs:176–220、310–382、489–544、774–786、804–829`；`src/JueMingZ/UI/BlueprintPlacementPreviewOverlay.cs:301–324`。

### 4.2 世界实例拥有独立快照

实例创建后默认显示，材料窗口字段默认为 `true`，但 `MaterialWindowVisible` 在冻结源码中仅有模型、克隆和初始赋值使用，不能据此声称它控制了实际卡片材料弹窗。实际弹窗展开项由 UI 状态单独拥有。

实例文件载入时：

- 空配对身份被拒绝；
- 文件不存在表示当前没有实例；
- 文件内非空配对键与请求键不一致时拒绝；
- 实例身份无效时生成新 ID，重复 ID 保留第一项；
- 实例所属配对键、世界键按文件上下文归一化；
- 层级不小于零；
- 擦除坐标和完成层记录分别去重；
- 最终按层级、实例 ID 排序。

模板快照、擦除遮罩和完成记录都保存在实例文件。移除实例会删除这些实例数据；保留模板并不等于保留该实例的施工记录。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintWorldInstanceStore.cs:32–65、68–158、161–315`；`src/JueMingZ/Automation/Blueprint/BlueprintModels.cs:464–545`；全仓 `MaterialWindowVisible` 引用仅落于这两个文件。

### 4.3 已放置列表的实际 UI 与服务能力

列表每页 `5` 个实例，支持分页和返回。当前卡片实际按钮是：

- **取消放置**：第一次点击进入确认，按钮变成“确认”；再次点击才移除实例。
- **显示／隐藏**：立即反转实例的 `Hidden`，保存成功后刷新投影和材料。
- **材料**：打开该实例模板快照中的静态材料清单，可关闭和滚动。

列表上方另有当前有效投影的总材料对照面板。卡片材料清单与这个动态总量不能混为一项。

层级存在真实数据和服务方法：`MoveLayer` 将实例与相邻项交换并重编号，到顶或到底返回无变化；输入分派有 `layer-up / layer-down` 命令分支。但冻结 UI 目录中没有生成这两个命令的按钮调用。故应记录为“层级规则和命令已实现，当前真实列表缺少上下移入口”，不能沿用历史简介直接写成“玩家可在卡片调整层级”。

手持快捷栏的“清空放置”则有实际入口，直接调用 `ClearAllCurrentWorld`，没有逐实例移除的二次确认过程。它清空当前玩家—世界实例文件中的列表，保留库模板和 Terraria 世界建筑，并取消相应编辑状态。

证据：`src/JueMingZ/UI/Legacy/BlueprintPlacedInstanceUiState.cs:106、180–193、218–403`；`src/JueMingZ/UI/Legacy/LegacyMainWindow.Blueprint.Placed.cs:135–200、259–388`；`src/JueMingZ/Input/LegacyUiActionService.Blueprint.cs:481–514、1056–1065`；`src/JueMingZ/Automation/Blueprint/BlueprintHandheldActionBarState.cs:70–81、578–651`。

### 4.4 实例保存成功与显示刷新成功是两个结果

显示、移除、层级等编辑先写实例文件，再刷新投影和材料。投影或材料刷新抛错时只限频记录日志，已经保存的实例变更不会回滚。不能把界面暂未刷新推断成保存失败，也不能把文件保存成功表述成所有后续界面都已收敛。

实例列表 UI 首次加载后使用缓存；进入世界的低频生命周期、打开列表及明确实例变更是刷新边界。绘制和命中测试使用缓存摘要，不负责重新载入实例文件。

证据：`src/JueMingZ/UI/Legacy/BlueprintPlacedInstanceUiState.cs:126–176、671–819`；`src/JueMingZ/Automation/Blueprint/BlueprintWorldInstanceLifecycleService.cs:64–142`。

## 5. 移动与区域修改

### 5.1 移动是两阶段提交

开始移动要求当前身份可解析、实例文件可读取且至少有可见实例。第一下左键选择鼠标命中的最高层可见实例，第二下左键才提交新位置：

- 命中必须是实例的实际内容格，不能只是模板矩形包围盒；
- 已被擦除的格子不参与命中；
- 隐藏实例不参与；
- 重叠时层级大的优先，同层级按实例 ID 的序数比较选较大者；
- 抓取点相对实例原点的偏移会保留，不强行改成中心抓取。

选中后构造一份浮动投影；鼠标换格只平移这份浮动层坐标，并更新墙显示策略。原实例位置直到第二次点击且保存成功之前都不改变。取消只清掉浮动状态，原实例仍在旧位置。浮动投影把其内容标为 `Missing`，不是每次鼠标移动都重新做完整世界可行性判定。

提交前重新读实例文件，复核目标仍存在、可见且没有受保护的施工记录；随后只更新原点和时间。层级、擦除相对坐标、模板资产和真实建筑不随移动改变。保存失败保留移动活动状态和失败提示。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintPlacedInstanceTransformState.cs:178–267、336–512、617–705、722–844`。

### 5.2 哪些进度会禁止移动和镜像

判断使用实例持久记录：

- `AutoPlacementProgressState` 去空白后只要不是空串或不区分大小写的 `idle`，即视为有自动施工进度；
- `CompletedLayers.Count > 0` 也会阻止移动和镜像。

这里不是“每次重新扫世界，判断建筑目前是否还在”。已完成建筑后来被挖走，也不会因此自动解除编辑保护。

更重要的是，完成记录可能来自投影对照发现世界中已有相符内容，并不必须由自动施工亲手放置产生。故“我没开过自动放置”不足以推出“该实例一定还能移动或镜像”。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintPlacedInstanceTransformState.cs:413–475、515–614`；`src/JueMingZ/Automation/Blueprint/BlueprintProjectionService.cs:819–906`。

### 5.3 区域修改实际是追加排除遮罩

“修改已放置蓝图区域”进入修剪模式：

- 当前只有一个可修改的可见实例时，直接锁定它，可从周围空气开始拖框；
- 多个实例时，首次按下要命中可见实例内容，按最高层规则选择；
- 一旦已有目标，后续拖框继续修改该目标，不自动跨到旁边实例；
- 指定目标已不存在或隐藏时失败；
- UI 占有会终止本次拖框；世界外释放取消本次拖框；
- 每个拖框包含端点面积最多 `16,384` 格。

释放后，遍历目标实例模板中落在矩形内的内容格，把相对坐标加入 `EraseMask`。重复擦除不会重复添加。它是“追加排除”，不是像创建选区那样再次拖过即可恢复；没有在这条路径中实现反向取消已存遮罩。

遮罩以格坐标排除该格的全部蓝图层，没有在 `AddEraseMaskCells` 里把触及的家具自动扩展成整件遮罩。模板本身和世界实物保持原状，后续投影／对象完整性规则再处理剩余对象。区域修改也没有移动和镜像的完成进度阻止分支，不能把两者的限制互相套用。

每次拖框释放即单独保存。此后的“取消修改”是结束当前编辑，不能撤销此前已经保存的多次拖框。若保存失败，文件没有获得本次遮罩；状态中的本次计数已经先被计算，不能把这个计数本身当成可靠落盘证据。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintEraseRegionState.cs:112、153–364、435–611、649–705`，`BeginErase / HandlePointer / ApplyEraseRectangleLocked / AddEraseMaskCells / ResolveTargetForPointerLocked`。

### 5.4 区域修改与投影刷新的静态缺口

成功擦除后，`BlueprintEraseRegionOverlay` 调用 `BlueprintEntryState.MarkEraseApplied` 更新入口模式和消息；在这条链中未见移动、镜像或列表变更所用的 `NotifyInstancesChanged`、投影强制刷新或材料强制刷新。

因此冻结实现可能已经把遮罩保存到文件，而缓存投影继续显示旧内容，直到打开列表、进入世界或施工端等下一个解析入口刷新。这里是静态调用链的差异，未执行游戏复现，不能升级成已确认的实机症状。R 候选应把“实例变更可靠提交后统一使投影和材料失效”列入保护要求。

证据：`src/JueMingZ/UI/BlueprintEraseRegionOverlay.cs:268–287`；`src/JueMingZ/Automation/Blueprint/BlueprintEntryState.cs:478–500`；对照 `src/JueMingZ/Automation/Blueprint/BlueprintPlacedInstanceTransformState.cs:963–989`、`src/JueMingZ/UI/Legacy/BlueprintPlacedInstanceUiState.cs:753–781`。

## 6. 水平镜像与家具完整性

### 6.1 可见实例镜像与预览镜像要分开

实际主页和手持栏的“镜像”进入世界实例选择状态，点击目标后尝试水平镜像并保存该实例副本；它不是在库模板上原地保存新版本。目标选择和进度保护与移动共用规则。

预览状态另有 `MirrorHorizontal` 方法和命令路径，可以只替换内存预览副本。旧底部状态栏方法中也画有“水平镜像／取消摆放”按钮，但该状态栏方法在冻结源码中只有定义，没有当前页面调用。该预览镜像路径应标为内部能力存在、当前实际 UI 未证明可达，不与玩家可点击的实例镜像混写。

实例镜像只替换 `TemplateSnapshot` 并更新时间；原点、层级保持。冻结实现没有同步水平翻转实例 `EraseMask`。所以已有修剪遮罩的实例镜像后，遮罩仍排除旧的相对坐标，而不是跟随被镜像内容一起翻转。此区别需要在 R 合同中明确处理，不能靠“整件镜像”四字隐去。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintPlacedInstanceTransformState.cs:515–586`；`src/JueMingZ/Automation/Blueprint/BlueprintPlacementPreviewState.cs:269–307`；`src/JueMingZ/UI/Legacy/LegacyMainWindow.Blueprint.cs:1047–1140`，`DrawBlueprintStatusBar`；实际主页入口见同文件 `277–293`。

### 6.2 镜像规则和拒绝分支

普通格横坐标变为 `Width−1−X`，锚点也沿同一公式翻转。普通方块斜坡按 `1↔2、3↔4` 互换，`0` 不变；其他斜坡值拒绝。半砖、涂料、涂层、失活等值保留。墙、电线、致动器和独立 `paintCoating` 层复制到镜像位置；未知层类型拒绝。

家具不能简单逐格翻转旧帧：

1. 用 `TileObjectData` 解析源帧、尺寸、方向、子格位置和基础帧网格。
2. 按对象原点、内容类型和帧样式收集完整对象组，检查每个子格恰好存在。
3. 核对已有对象元数据与帧推导一致。
4. 找到相反方向的合法 alternate，并证明目标形状与原对象相同。
5. 计算整件家具的新原点和每个目标子格帧，重建对象组元数据。
6. 把整件材料需求重新挂到目标 `(0,0)` 代表子格，其他子格的需求量为零。
7. 重新检查目标对象完整性。

任何子格缺失、重复、元数据不一致、目标重叠或越界、方向或帧无法证明，都会使整张镜像操作失败，不输出半张成功模板。失败时原模板或实例不被替换。

绳索是无方向的特例；平台即使属于 `Object` 层，也要镜像锤击斜坡，并处理已证明的锤形帧对。火把和开关还根据镜像后的模板支撑关系，按下方、左方、右方、背景墙的优先顺序重建挂靠方向；没有支撑上下文时拒绝。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintMirrorService.cs:208–418、625–869、975–1352、1550–1741`。

### 6.3 保存的样式身份与帧方向偏移不是同一字段

当前生产镜像调用 `BlueprintObjectFrameMirrorTransform`，不是较旧的 proof-only resolver。转换保留真实存储的 `Style`，另用基础网格的帧样式和方向偏移计算目标帧。

`StyleLineSkip > 1` 的对象按原帧样式加目标方向行偏移重建；普通重复方向对象则先在方向周期内匹配，再补回周期基数。不能把关门的实际 `Style=36/72` 消掉，也不能把方向偏移误当下一种家具样式。

`LegacyMainWindow.Blueprint.cs` 仍有“不能翻转时清零回退”的旧注释和可视合同字符串，但实际 `MirrorService` 明确拒绝无法证明的对象帧。正式行为以这条实际调用链为准，同时保留旧注释冲突证据，不能倒改历史描述。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintMirrorService.cs:842–869`；`src/JueMingZ/Automation/Blueprint/BlueprintObjectFrameMirrorTransform.cs:29–207、278–350、409–494`；冲突注释在 `src/JueMingZ/UI/Legacy/LegacyMainWindow.Blueprint.cs:97–98`。

### 6.4 镜像没有最终施工，不等于实现完全不碰世界内存

模板采集本身只读，但镜像纹理重算存在不同实现：

- 在 `Main.tile` 中选固定起点 `(6,6)`；
- 临时范围为模板宽高各加两格边框，即 `(Width+4)×(Height+4)`；
- 备份原 `Tile` 引用，把整块临时区替换为空格；
- 写入镜像后的方块、平台、挂靠对象和所需墙支撑；
- 调用 `WorldGen.TileFrame(..., true, false)`；
- 读回帧以及平台锤形状态；
- 在 `finally` 中恢复已备份的原 `Tile` 引用。

游戏格数组未就绪或临时范围放不下时跳过重算；内部异常返回零并恢复已备份格子，不必然使整次镜像失败。故只可说“意图是不保留临时世界修改”，不能仅凭 `finally` 推导所有原版副作用、多人同步或性能已经安全实测。临时成本还取决于包围矩形面积，不只是实际非空格数量：稀疏而跨度很大的模板仍可能产生大的备份数组与逐格初始化。

R 候选应保持预览／资产编辑与真实世界操作的清晰边界；是否允许这种临时借用 `Main.tile` 的实现，不能从 Legacy 行为自动继承。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintMirrorService.cs:421–440、1798–2005`，`RebuildTileTextureFrames / TryGetTileFrameRebuildArea`。

## 7. 八类替换：完整集合、实际界面与材料选择规则

本节及后续 Z 证据均固定于 `6ac6356c0c564f43284590c168855e96c50e13f7`。以下路径是 Z 仓库相对路径；`BlueprintReplacementRuleService` 等短类名用于说明职责，不构成 R 必须沿用的实现。

### 7.1 玩家实际能配置的内容

蓝图主页面有“替换”配置入口、总开关和总开关的快捷键设置。配置浮层列出八个独立勾选项：

| 界面类别 | 实际分类集合 | 需要保留的区别 |
|---|---|---|
| 火把 | Tile 类型 `4` | 不是所有发光家具 |
| 平台 | Tile 类型 `19` | 普通 `Tile` 层唯一可以进入替换分类的类别 |
| 工作台 | Tile 类型 `18` | 不扩展为所有制作站 |
| 椅子 | Tile 类型 `15` | 不扩展为床、沙发或所有座位 |
| 门 | 关闭的门，Tile 类型 `10` | 开门类型 `11` 不在本分类集合 |
| 桌子 | Tile 类型 `14`、`469` | 同一类别包含这两个明确的原版类型 |
| 箱子 | Tile 类型 `21`、`467` | 不表示复制箱内物品；也不包括捕获时识别的所有容器类型 |
| 告示牌 | Tile 类型 `55` | 不自动包括类型 `85` 或所有带文字的物体 |

除平台外，目标必须是 `Object` 层。墙、电线、制动器以及未列出的家具类别不会因总开关开启而获得替换资格。类别来自实际 Tile 类型分类，不按玩家看到的名称模糊匹配。

总开关和八个分类开关默认均关闭。总开关关闭时，分类选择本身仍可保存；再次开启总开关才恢复它们的效力。配置浮层有关闭按钮和八项复选框，按宽度安排列数。实际输入处理会写入配置；不能把它描述成只修改当前浮层的临时选择。

证据：`src/JueMingZ/UI/Legacy/LegacyMainWindow.Blueprint.cs`，类别文案及门的限定说明，95–108；替换配置行与浮层绘制，762–998。`src/JueMingZ/UI/Legacy/LegacyMainWindow.Input.Blueprint.cs`，替换输入分派与设置保存，630–751。`src/JueMingZ/Config/AppSettings.cs`，859–870。`src/JueMingZ/Automation/Blueprint/BlueprintReplacementRuleService.cs`，类型常量，86–95；`TryClassifyLayerCategory` / `TryClassifyTileCategory`，433–485。

### 7.2 获得替换资格的全部必要条件

一层要进入替换逻辑，必须同时满足：

1. 替换总开关已开；
2. 所属的八类之一已开；
3. 层种类、Tile 类型符合上表；
4. `PaintId == 0`；
5. `CoatingFlags == 0`；
6. `Slope == 0`；
7. 不是半砖；
8. 不是失活状态。

因此，开启“同类替换”不会授权抹掉原蓝图的染色、涂层、斜坡、半砖或失活差异。某件家具通常属于八类之一，也不代表它的所有状态都可以替换。

证据：`BlueprintReplacementRuleService.cs`，`CanReplaceLayer`，403–430。

### 7.3 候选集合的来源与顺序

候选物品来自原版放置目录中 `IsBaseItemPlacement` 为真的描述项，即普通物品自身的放置能力。灵活放置魔杖选项、为特殊物体补充的稳定映射项，不会仅因为也能产生相同 Tile 而自动进入这份替换候选集合。

候选按物品 ID 去重、升序排列。实际选择是确定的顺序选择，不是随机选择，也没有“最接近颜色”“同一套家具优先”或玩家自定义优先级。分类候选缓存首次成功建立后复用；原版目录尚未就绪时不把失败当成永久初始化成功，后续请求仍可能再次检查。

证据：`BlueprintReplacementRuleService.cs`，`GetCandidateItemIdsForCategory` 及候选初始化，497–580。`src/JueMingZ/Automation/Blueprint/BlueprintVanillaPlacementDescriptor.cs`，`IsBaseItemPlacement`，78–81。

这里的“完整八类集合”可以从固定源码完整列出；每类究竟包含多少个可用物品，取决于成功建立的原版放置目录。本轮没有运行原版或导出该目录，因此不以猜测的物品 ID 清单代替运行时目录。

### 7.4 材料选择不是“开启后立即全部换成别的材料”

原材料足够时优先使用原材料。只有当前待处理需求的原材料不足，且该层满足替换资格，才遍历同类候选：

- 跳过无效物品和原材料自身；
- 找到第一个能够独立满足这一项完整 `MaterialStack` 的候选；
- 记录原材料、实际选择材料、替换是否发生及类别；
- 没有候选足够时，保留原材料需求并报告不足或无法选择。

不会把同一项需求拆成“原材料一部分、候选 A 一部分、候选 B 一部分”来凑数。不同需求项可以分别选择不同候选。

动态材料清单还维护 `plannedUse`：前面需求已经预留的材料，会从后面的可用数量中扣除，避免同一批材料在多项需求中被重复当作足够。实际施工的选择入口接收主背包可用量；材料清单入口可以接收主背包与虚空袋合计。这是两种不同用途的可用量，不能从清单的“数量足够”直接推导“施工现在可执行”。

证据：`BlueprintReplacementRuleService.cs`，`TryChooseMaterialForAutoPlacement`，158–208；`ChooseMaterialForMaterialList`，210–278。施工与清单容器范围见第 8 节和第 11 节的交接边界。

### 7.5 已有世界物体能否算完成，与背包是否缺原材料是两件事

投影判定还会询问世界中的现有物体是否可作为同类替代完成目标：

- 目标层本身必须具有替换资格；
- 世界物体处于激活状态；
- 世界物体与目标归入同一替换类别；
- 染色、涂层、斜坡、半砖、失活等受保护状态相符。

这一判定不要求先证明玩家背包缺少原材料。因此，开关开启后，世界中已经存在的合格同类物体可以使目标判为满足；这与“需要建造时，原材料优先、原材料不足才选替代材料”并不矛盾。

完整显式多格物体还要经过对象级判定。归一化对象处理要求所有相关待完成层都满足对应判据，再给出整个对象的完成结果，不能只因某一格是同类物体就把整个家具当作完成。旧资产缺少完整对象元数据时不会因此自动升级成有完整身份保证的对象。

证据：`BlueprintReplacementRuleService.cs`，世界替代判定，291–380。`src/JueMingZ/Automation/Blueprint/BlueprintProjectionNormalizedBodyResolver.cs`，`ApplyWorldCompletion` 及完整对象替代判定，137–310。

### 7.6 R 候选应保留的产品区别

可考虑保留“八类独立开关、总开关、原材料优先、明确候选集合、状态差异不被替换抹去、清单不重复预留”的用户能力。以下不能未经正式契约决定就默默改变：

- 将“门”扩大到开门状态或所有可开关物体；
- 将工作台扩大为所有制作站；
- 将箱子替换误解为复制容器内容；
- 将替换分类当成通用家具等价关系；
- 把“已有世界对象可满足目标”绑定到背包缺料；
- 把可显示的虚空袋数量当作所有施工路径都能消费的数量。

这些是候选保护项，不表示 R 已有蓝图或替换功能。


## 8. 材料、投影和预览：口径、完成记录与缓存边界

### 8.1 三种容易混淆的“材料清单”

| 界面或数据 | 数据来源 | 实际含义 |
|---|---|---|
| 模板库的材料信息 | 模板保存的 `Materials` | 捕获、保存时的静态模板材料 |
| 已放置实例卡片打开的材料浮层 | 实例自己的 `TemplateSnapshot` | 该实例模板副本的静态材料；不是重新扫描世界所得的剩余量 |
| 已放置列表顶部的材料对照面板 | `BlueprintMaterialService` 的缓存快照 | 当前世界有效投影中仍缺失的材料及背包对照 |

库模板、实例副本、当前世界剩余需求是三种对象。改库模板不会自动重写已经放置的实例快照；替换规则选择的当前材料也不会自动改写库模板原始材料。

顶部动态面板的绘制和布局直接取 `GetCachedSnapshotForDraw`，不在该绘制入口读取世界或背包。当前快照不可用时显示“材料对照待刷新”；无缺失材料时显示对应空态。面板按快照生成材料行，不能把卡片的静态材料浮层当成这个动态面板的另一种显示方式。

证据：`src/JueMingZ/UI/Legacy/LegacyMainWindow.Blueprint.Placed.cs`，`DrawBlueprintPlacedMaterialPanel`，56–132；实例材料浮层及 `BuildTemplateMaterialLines(instance.TemplateSnapshot)`，259–388。`src/JueMingZ/UI/Legacy/BlueprintLibraryUiState.cs`，模板材料文本构造相关入口。模板与实例分离的模型和保存规则见第 3、4 节。

### 8.2 动态材料统计究竟数哪些层

动态统计以投影结果中的有效层为输入：

- `Fulfilled`：当前观察已经满足，跳过；
- `Completed`：已有持久化完成承诺，跳过；
- `Conflict`：目标位置存在不相容内容，跳过并另计冲突；
- `Unavailable`：无法可靠判定，跳过并另计不可用；
- `Missing`：才进入材料需求计算；
- 被更高实例相同覆盖组遮盖的层不作为有效待建层重复计数。

因此，“动态材料缺口为零”可能表示目标已经满足，也可能存在冲突、不可用层，或者缺失层没有可统计的物品映射。不能把它单独作为“蓝图已经完整建好”的证明。

对已经存在本体但仍缺染色、涂层等后处理的层，材料统计先询问后处理计划器，使用该步骤的材料需求；不能始终按重新建造本体来收取材料。未能得到后处理需求时，才使用层上的 `MaterialItemId` 和 `MaterialStack`；无有效材料信息的缺失层另计，不凭空创造材料映射。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintMaterialService.cs`，`BuildMaterialSnapshot`，623–767；`TryCreatePostProcessMaterialRequirementLayer`，945–994。

### 8.3 背包范围、延迟读取与读取失败

材料对照读取主背包索引 `0–57`，以及可访问的虚空袋容器。只累计本次需求和替换候选涉及的物品 ID。虚空袋读取入口本身没有再要求“玩家当前打开虚空袋界面”。

- 本地玩家或主背包读取失败：对照失败，保留已解析的需求，不把可用量伪装成已成功读取。
- 虚空袋读取失败：仍可成功返回主背包统计，并用 `readWithoutVoidBag` 区分。
- 没有可统计需求：直接成功返回空材料列表，不需要读取背包。
- 普通材料快照解析可以只解析需求，返回 `inventoryDeferred`；实际背包读取由材料窗口、已放置列表、自动摆放等显式刷新入口请求。
- “未读取背包”的零可用量与“成功读取后确实没有材料”有不同状态，不能在 R 文案中混为一谈。

统计按选定材料汇总需求、主背包量、虚空袋量、总可用量和缺口；同批材料分配要扣除前项已经计划使用的数量。替换选择规则见第 7 节。

证据：`BlueprintMaterialService.cs`，背包读取器及 `MainInventorySlotLimit = 58`，250–348；快照与强制刷新入口，355–453；延迟和失败分支，717–766；`BuildItems`，770–852。

施工执行侧的已验证交接范围是主背包 `0–49`。清单显示主背包 `0–57` 和虚空袋，不等于所有这些数量都能被当次施工消费。这一差别必须在施工专题合稿时保留。

### 8.4 原版放置目录如何提供材料身份

材料映射不是“拿 Tile ID 当 Item ID”。`BlueprintVanillaPlacementCatalog` 建立原版放置描述目录，索引物品、材料、Tile 与样式、墙等关系：

1. 等待原版物品数量、`ContentSamples.ItemsByType`、派生放置详情和灵活魔杖所需元数据就绪；
2. 对同一个就绪状态令牌最多尝试建立两次；
3. 遍历原版物品，记录普通物品的 Tile、墙和样式放置能力；
4. 将灵活放置魔杖的“使用物品”和“消耗材料”分开记录，并保留选项信息；
5. 加入少数明确的稳定补充映射；
6. 成功后缓存目录及查询索引，普通查询复用。

灵活魔杖会产生“手里拿的工具”和“需要的材料”不同的描述。缺少可靠目录时，应报告未就绪或无法映射，不能把工具 ID、材料 ID、Tile ID 混成同一个标识。

显式写在资产里的材料身份也受到保护：资产已给出材料或放置身份而与解析结果不符时，不允许为了让查询成功就悄悄替换它。只有原信息确实缺失，且当前 Tile／样式能得到唯一可靠映射时，才有受控回退。完整显式多格对象的归一化还要求完整对象元数据和可证明的代表格；旧格式或残缺对象不会直接获得同等保证。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintVanillaPlacementCatalog.cs`，缓存与查询，15–93；`TryInitialize`，146–247；索引构造，249–309；就绪条件，564–597；物品扫描、魔杖与补充映射，600–790。`src/JueMingZ/Automation/Blueprint/BlueprintPlacementIdentityNormalizer.cs`，显式材料／身份约束，541–618。`src/JueMingZ/Automation/Blueprint/BlueprintProjectionNormalizedBodyResolver.cs`，完整对象归一化入口，41–134。

本轮确认的是固定源码中的映射机制和失败规则，没有运行全物品目录。不能据此声称已逐一验收 Terraria 1.4.5.8 的全部家具、全部样式或全部魔杖选项。

### 8.5 投影状态及重叠规则

投影首先按实例层级处理可见实例，将相同世界坐标、相同覆盖组的内容归并；更高层覆盖较低层。不同覆盖组仍可共存，例如墙与前景内容。隐藏实例不参与该轮有效投影；区域擦除掩码剔除对应相对位置的层。覆盖不会删除低层实例文件中的原内容。

有效层再根据世界观察和持久化完成记录分类：

| 状态 | 主要含义 | 对绘制和材料的影响 |
|---|---|---|
| `Missing` | 世界尚缺目标本体或必要后处理 | 显示缺失投影；能够映射时计入材料 |
| `Conflict` | 已有不相容内容阻碍目标 | 冲突色显示；不当作普通缺料 |
| `Unavailable` | 世界读取、对象证明等条件不足 | 不可用状态；不猜完成或需求 |
| `Fulfilled` | 本次观察满足目标 | 不再绘制缺失投影；非电线层可能随后保存完成记录 |
| `Completed` | 已有对应持久化完成记录 | 按完成承诺处理；普通层不因之后被拆除而自动变回缺失 |
| `Covered`／覆盖计数 | 被高层同覆盖组内容压住 | 不重复作为当前有效层执行或计料 |

世界坐标读取在一轮投影中有缓存，包括读取失败结果，避免同一格的多个层反复读取。显式多格物体中任一待完成部分冲突或不可判定，会通过对象策略影响同组未完成部分；已经满足或已经完成的成员不因此任意降级。旧式缺少完整对象身份的资产走受限兼容判定。

普通 Tile／家具本体相同但染色、涂层、形状或失活状态仍需处理时，可以是 `Missing` 加“本体已存在”的后处理信息，不必一概判成占位冲突。墙、电线、制动器各有独立规则。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintProjectionService.cs`，状态常量，12–17；`BuildProjectionSnapshot`，650–816；普通层、墙、电线和制动器判定，1421–1658；多格对象结果传播，1752–1953。

### 8.6 “只读快照”不等于绝无文件写入

这是实际链中的重要边界：

- `GetReadOnlySnapshotForInternalConsumer` 返回供内部消费者共享的投影快照；
- 它仍会进入 `ResolveSnapshotLocked`；
- 刷新时发现非电线层已由世界满足，会调用 `PersistCompletedProgressIfNeeded`；
- 该方法将完成层加入实例的 `CompletedLayers`，更新实例时间，保存整个当前世界实例文件；
- 保存成功后，当次待发布快照同步收敛为 `Completed`，并使材料缓存变脏；
- 保存失败不把未保存的完成详情发布成已持久化完成；保留本轮观察意义上的满足结果，并记录保存失败。

所以这里的“只读”主要约束消费者不要修改共享返回对象，不是对底层磁盘副作用的承诺。进入材料查询或显式刷新，也可能经这一链完成持久化。

这种持久化会影响编辑：实例只要有完成进度，移动、镜像就可能被其进度保护拒绝，即使玩家没有亲自开启过自动摆放。世界中本来就存在满足蓝图的内容，也能触发这条完成记录链。

电线被明确排除：电线完成是当前目标颜色与当前世界颜色的实时差额，不保存新的普通完成承诺，旧的电线完成记录也不用于遮蔽后续缺失颜色。已有额外颜色不等于必须拆除它们；需要补的是目标所缺颜色。

证据：`BlueprintProjectionService.cs`，共享／克隆入口，348–427；`ResolveSnapshotLocked`，593–647；`PersistCompletedProgressIfNeeded`，819–906；当次快照收敛，909–941；电线历史完成排除，776 附近；`ClassifyWire`，1613–1658。编辑进度保护见第 5 节。

### 8.7 缓存在哪里生效，哪些入口仍有全量工作

**投影解析缓存。** 名义有效期为 250 毫秒，但非强制解析的命中检查发生在当前身份解析、世界实例文件读取、实例列表建立和签名计算之后。它可以省掉命中后的世界投影重建，不能据此声称“250 毫秒内没有文件读取或实例遍历”。强制刷新跳过这一命中复用。

签名包括当前玩家／世界键、文件修订、世界读取器就绪状态、替换设置、实例 ID／层级／隐藏／位置／更新时间、擦除掩码和完成键，以及模板身份、更新时间、格数等。它没有逐字节哈希全部模板格内容。投影构建计时也从这些前置读取之后才开始，诊断中的构建耗时不能代替完整调用成本。

**绘制缓存。** 已放置投影的世界绘制直接取 `GetCachedSnapshotForDraw`，不会通过这个入口重新读全世界实例文件。墙层和前景层有各自合适的绘制入口；前景投影按绘制通道遍历有效层，再做视口裁剪。当前源码没有在这一世界投影绘制链设置“只画前 N 层”的统一数量上限。

**材料缓存。** 材料也有 250 毫秒缓存，但签名仍在命中检查前构造；普通读取、显式背包刷新、绘制缓存读取是不同入口，不能只看一个函数名推断全部调用成本。

**未确认预览。** 浮动模板预览使用模板签名和放置原点缓存。鼠标原点未变时可以复用旧预览层；世界内容或替换设置并不是该预览签名的全部输入，因此静止时可能不立即反映世界变化，确认放置会强制刷新。`GetSnapshot` 会复制模板和预览层，世界绘制／输入读取此接口时仍有与模板规模相关的复制成本。

**移动中的浮动实例。** 原点未变时复用；原点变化时逐层平移并更新墙表现。这与重新捕获真实世界、正式确认保存是不同步骤。

证据：`BlueprintProjectionService.cs`，336、348–427、593–647、2124–2160。`src/JueMingZ/UI/BlueprintProjectionOverlay.cs`，15–32、147–225、302–331。`src/JueMingZ/UI/BlueprintProjectionWallWorldOverlay.cs`，11–55。`BlueprintMaterialService.cs`，355–453、579–620、867–894。`src/JueMingZ/Automation/Blueprint/BlueprintPlacementPreviewState.cs`，561–630。`src/JueMingZ/Automation/Blueprint/BlueprintWorldInstanceTransformState.cs`，722–754。

### 8.8 预览图片不是资产内容本身；特殊家具还有图形资源生命周期

库缩略图最多抽取 768 个格，按整个格列表的下标范围均匀抽样，不是仅显示前 768 格。抽样仅限制缩略图绘制，不截断保存或实例投影内容。

缺失投影优先使用原版纹理与明确的家具绘制规则。人体模型等特殊家具还有专门的图像合成路径：人体模型生成 `48×64` 的离屏目标，缓存键包含内容、外观签名和版本；屏幕位置、相机、缩放、透明度不进入该外观缓存键。缓存上限为 16 项，按近期使用淘汰并释放资源。

缓存命中仍验证图形设备和代际是否匹配，只有缺失或失效才分配目标；世界进入、离开、世界名变化和运行时退出有失效／释放路径。正在合成目标时遇到重入失效，会延后释放，避免边绘制边销毁。这个局部缓存的生命周期保护不能外推为所有蓝图编辑状态都具备相同的会话保护。

人体模型图像路径有分配失败、设备失效、绘制异常等明确退路。未能绘出某种家具，不应静默改写模板对象或假装真实世界已经放置。

证据：`src/JueMingZ/UI/Legacy/LegacyMainWindow.Blueprint.cs`，缩略图采样，1603–1650。`src/JueMingZ/UI/BlueprintProjectionGhostRenderer.cs`，绘制入口和特殊对象分派，32–66、236–368。`src/JueMingZ/UI/BlueprintDisplayDollRenderTargetDesign.cs`，8–52。`src/JueMingZ/UI/BlueprintDisplayDollRenderTargetCache.cs`，世界／退出通知，34–86；缓存命中与创建，311–455；淘汰和延后释放，1026–1115。`src/JueMingZ/Runtime/JueMingZRuntime.cs`，生命周期调用，202 附近、746 附近。

本节说明的是固定实现形态与成本来源，没有运行像素比对、性能测试或游戏实机，不能据此补发“视觉完全一致”或“稳定帧率已经通过”的验收结论。

### 9.2 快捷键、手持快捷栏与世界鼠标的边界

七个动作使用统一快捷键系统；新配置默认只提供地图快捷宣告绑定，没有蓝图动作默认绑定。因此不能把旧文档中的 `N` 当成当前新配置的默认蓝图入口。

动作快捷键按以下顺序处理：创建、保存、移动、区域修改、镜像、库、已放置列表。同一轮命中第一个已触发动作后返回。统一系统报告被 UI 或环境阻挡时，蓝图分派保留阻挡结果，不绕开输入保护。F5 的动作快捷键字段要求双击才进入录制；录制取消／清空属于快捷键编辑语义，不能误称为世界蓝图操作的通用取消键。

手持快捷栏出现还需要：

- 快捷入口开关开启；
- 已在世界内且世界可读；
- 游戏 UI 状态和原版菜单读取可用，菜单未阻挡；
- 没有打开全屏地图或 F5；
- 没有聊天或 NPC 对话；
- 选中物品槽、物品类型有效，且类型等于配置的蓝图工具物品；

默认工具物品为凝胶；工具物品校正范围及默认值见第 1 节。手持栏自身的 UI 隐藏判定没有直接检查背包开启状态；世界选区和放置输入另有背包阻挡。两者不能合并成一条“只要开背包，所有蓝图 UI 都隐藏”的规则。

创建中或已退出但保留待保存选区时，手持栏优先显示保存、退出创建及有选区时的清空；否则显示创建、蓝图库。有实例时增加列表、清空放置、移动、区域修改、镜像。活动编辑即使暂时没有实例摘要，也保留相应取消按钮。窄屏使用紧凑布局，位置在屏幕下方居中并受屏幕边界约束。

### 9.3 关闭显示、退出模式、停止施工不是同一个开关

关闭 F5 只结束或隐藏 F5 的交互表面，不自动删除模板和实例。隐藏实例是实例文件中的持久化显示选择，会令该实例不参与有效投影；“取消放置”则移除实例记录。二者都不等于拆除真实世界中已经存在的建筑。

关闭手持快捷入口只让手持栏失效，并清理该栏的临时鼠标状态；其关闭边沿用同一个令牌让各入口只清理一次，稳定关闭后走轻量分支。它不是“删除全部蓝图状态”，也不是自动放置开关。

自动放置有独立开关；关闭它不能据此推断库、创建选区、实例投影、材料显示和世界实例生命周期也全部停止。当前生命周期调度仍在只读显示调度通道每 10 个调度 tick 检查一次，自动放置调度则是另外的入口。调度通道被命名为 `ReadOnlyDisplay`，也不会抹去第 8.6 节已经确认的完成记录保存副作用。

证据：`BlueprintHandheldActionBarState.cs`，`ObserveFeatureGate`，470–495。`src/JueMingZ/Runtime/RuntimeAutomationDispatcher.cs`，78–86、401–420。实例隐藏／删除及其保存语义见第 4 节。

### 9.4 世界身份更新与活动编辑状态没有统一为一个生命周期所有者

世界实例生命周期服务读取当前角色×世界键和世界键：

- 未进入世界、主菜单或身份不可靠时，清除它自身保存的“上次观察身份”；
- 身份未变时直接返回；
- 身份变化时刷新实例 UI 和投影；
- 刷新异常有 10 秒日志节流；
- 它在刷新前已经更新“上次观察身份”，因此本服务不会仅因一次刷新失败就在下一次相同身份检查中自动重试。

该服务本身没有取消创建选区、未确认模板预览、移动、镜像或擦除模式，也没有在无世界分支直接清空所有这些缓存。

各活动状态的身份方式不同：

- 未确认模板预览在确认时取得当前角色×世界身份；
- 移动／镜像在开始时保存角色×世界键，后续按保存的键读取和保存目标实例；
- 区域擦除的指针／应用流程重新解析当前世界，并寻找它的目标；
- 创建选区主要保存坐标掩码，没有统一会话代际令牌。

这是已核到的状态所有权差异。它表明不能从某个局部刷新器推导“所有活动编辑在换人、换世界或重连时必然同时取消”。本轮没有运行游戏复现跨世界编辑，因此不把它写成已经发生的数据损坏；R 候选应明确由谁终止旧会话编辑、释放输入、丢弃旧结果并禁止旧手势跨会话提交。

证据：`src/JueMingZ/Automation/Blueprint/BlueprintWorldInstanceLifecycleService.cs`，`TickCore`、当前身份解析与重置，60–161。`src/JueMingZ/Automation/Blueprint/BlueprintPlacedInstanceTransformState.cs`，336–388、399–586。`src/JueMingZ/Automation/Blueprint/BlueprintPlacementPreviewState.cs`，489–544。`src/JueMingZ/Automation/Blueprint/BlueprintEraseRegionState.cs`，153–364、435–523。`src/JueMingZ/Automation/Blueprint/BlueprintCreationMaskState.cs`，32–145。

人体模型图形缓存另有世界／图形代际保护，见第 8.8 节。应保留这一局部正确机制，同时避免把它外推到别的状态对象。

### 9.5 规模上限与实际成本按路径分别判断

| 场景 | 固定实现中可以确认的工作量／边界 |
|---|---|
| 创建选区 | 单次矩形与已选集合受 16,384 格约束；快照复制并排序选中格 |
| 捕获家具 | 触及多格家具会扩展为完整对象；选择上限不等于最终扩展后全部捕获内容的统一上限 |
| 模板库 | UI 每页六卡，缩略图最多抽样 768 格；资产仍完整保存，库存不是六项上限 |
| 已放置实例列表 | 每页五项，但分页不把实例文件分成五项，也不限制整个世界实例量 |
| 实例文件修改 | 读取、规范化、复制、序列化和提交完整世界实例文档 |
| 投影解析 | 遍历可见实例及其层，建立覆盖映射和世界读取缓存；签名和整文件读取发生在普通缓存命中检查前 |
| 擦除掩码判定 | 投影每层调用线性掩码查询；层数为 L、掩码为 M 时，这部分最坏可随 L×M 增长，不能因为另有 `BuildEraseMaskSet` 就认为本处使用集合查询 |
| 稳定已放置绘制 | 使用缓存，但仍分绘制通道遍历投影层后裁剪；未核到统一层数绘制限额 |
| 未确认预览 | 快照复制完整模板和预览层；鼠标原点变化时重建或移动对应层 |
| 镜像 | 家具证明、对象变换之外，原版帧重建还依赖模板外接矩形面积；稀疏但跨度大的选区不能只按非空格数估算 |
| 原版材料目录 | 首次成功建立需要完整物品目录扫描；成功后复用；同一就绪令牌最多两次建立尝试 |
| 特殊人体模型图像 | 缓存最多 16 项；命中复用，失效／缺失才合成，淘汰释放 |
| 普通文件提交失败 | 同步提交最多四次；三次退避分别为 15、30、45 毫秒，尚不包括实际 I/O 和序列化时间 |

擦除查询的具体反例：`BlueprintProjectionService` 在层循环内调用 `BlueprintEraseRegionState.IsCellErased`，后者逐项比较掩码坐标。虽然同类文件也提供构造 HashSet 的工具，不能用别的调用点的集合行为覆盖这里的线性查询事实。

证据：`BlueprintCreationMaskState.cs`，12、32–44、311–367。`BlueprintProjectionService.cs`，693–729。`BlueprintEraseRegionState.cs`，822–854。`src/JueMingZ/Automation/Blueprint/BlueprintJsonSafeFileStore.cs`，15–101、130–191。其余成本入口见第 2、4、6、8 节对应证据。

这些是静态工作量与阻塞位置判断，不是 FPS 根因、帧率损失数字或优化收益证明。

### 9.6 失败后应该保护什么，固定实现还留下哪些差异

已经确认的保护包括：保存前保留原资产、先写临时文件再替换、保存失败不把实例移动／镜像当作成功、取消尚未提交的预览不写真实建筑、未知家具镜像不作逐格猜翻、显式材料身份不被隐式重映射。

仍需单列的差异包括：

1. **未知格式保护不完整。** 导入封套会校验格式与版本；本地库／实例顶层版本和模板内部正版本没有同等的完整拒绝规则。不能把导入封套检查描述成整个资产体系已经有安全迁移机制。
2. **本地保存没有 R 当前存储的预期文件身份防覆盖协议。** 采用临时文件替换并不自动解决外部同时编辑后的旧快照覆盖。
3. **刷新失败可能保留旧显示。** 库首次加载失败会缓存已尝试状态；世界生命周期失败也不会在同身份的下一 tick 自动重试，需要对应刷新入口。
4. **区域擦除保存后的刷新链不完整。** 该路径已保存掩码并更新入口通知，但没有核到与移动／镜像／实例列表操作同等的实例变更通知和投影、材料显式刷新；自动放置关闭时，显示可能等待其他刷新事件。此项为静态链缺口，未做实机复现。
5. **镜像与擦除掩码的关系未统一。** 镜像替换实例模板快照，原 `EraseMask` 坐标未同步镜像；应并列说明固定行为和 R 待定产品规则，不能默认它代表“擦掉的形状随整体镜像”。
6. **镜像不完全是纯内存资产计算。** 固定帧重建暂时替换 `Main.tile` 的一片区域并在 `finally` 恢复原引用；它没有最终施工，但仍接触实时世界数组。不能把这条链作为 R 的“预览绝不接触世界写入口”证明。
7. **预览与正式投影判定并非完全同链。** 未确认预览没有经过正式实例投影的完整对象身份归一化入口；确认前后视觉与完成状态需要专门验证，不能仅因两者都叫投影就视为相同。
8. **当前 UI 的能力可达性小于后台方法集合。** 独立材料窗口、预览镜像、层级命令等必须按第 9.1 节标明。

以上均为移植前必须理解的差异，不是本轮批准修改 Z 或直接实现 R 的清单。


## 10. R 现有实物、可复用边界与跨功能关系

本节 R 生产证据固定于 `df8a029873176276d0f620d32b0ac02ae9ea7744`。后续仅文档提交不改变这一生产基线。

### 10.1 R 现在有什么，尚没有什么

R 目前没有蓝图资产、模板库、实例、投影、镜像或自动施工领域实现。F5 页签列表中出现“蓝图”不代表该页已经恢复对应功能。现有正式资料也明确：`blueprints/templates/`、`blueprints/instances/` 是未来用户数据布局建议，实例归属、模板快照和进度语义以后由具体功能合同确定；不是已经实施的 schema，更不授权自动读取、覆盖或迁移 Legacy 资产。

证据：R `src/JueMingR.TerrariaHost/F5/F5Layout.cs:57`；当前 `src` 蓝图引用定向核对；`docs/功能介绍/Legacy蓝图.md:3–26`；`docs/设计/配置持久化与用户数据布局.md:226–243`。

可以复用的是以下现有机制，而不是一套已经存在的蓝图业务：

| R 实物 | 已有保证 | 蓝图仍需负责的内容 |
|---|---|---|
| `SingleFeatureRuntime` | 会话边沿通知；身份对象变化先结束旧会话；新会话递增 `Generation`；观察失败关闭相关能力 | 模板与实例的持久身份、编辑状态取消、完成记录语义、迟到保存结果是否仍可发布 |
| `HostInputState` | 一个原版输入采样周期；失焦隔离；恢复后等待真实按键及五鼠标键全部释放；已消费尾帧不补发 | 世界选区、拖动、选择实例、预览确认等新手势及其所有权 |
| `F5Interaction` | 同一布局代际内按下与释放命中同一元素才触发；关闭后释放尾帧仍消费 | 蓝图库卡片、对象预览、删除确认、导入导出反馈等新业务视图 |

### 10.3 推荐开发分组与内部顺序

**候选分组：将附录 24–26 作为“蓝图资产与编辑”完整领域推进，附录 27–28 单列实际施工。** 同组内部可以分成可验收的步骤：

1. **资产与捕获。** 先确定稳定归属、格式保护、完整对象和只读采集；完成保存、命名、删除、导入导出，以及取消／失败不破坏原资产。
2. **实例与世界预览。** 模板副本、位置确认、显示／隐藏、移除、有效层覆盖、冲突／不可读表达和材料需求；确认放置只提交实例数据。
3. **编辑与替换。** 移动、整件镜像、区域修改、八类替换；明确完成进度保护、掩码与镜像的关系，以及全部实际 UI。
4. **交给施工领域。** 使用同一目标身份、材料与对象规则，另行证明工具、距离、原版动作、请求权威、实际成功和部分进度。

这样分组的理由是：资产、实例、镜像、区域掩码和投影需要同一对象语义；实际施工还会争用玩家工具、选槽、物品消耗和原版动作阶段，具有不同确认与失败边界。不能只为减少分组数量，把“预览已经画出来”当成“施工能力已经完成”。

上述顺序是调查建议，没有修改 R 架构、创建任何接口或冻结未来 schema。



## 11. 与实际施工的精确交接，以及操作／多人边界

### 11.1 附录 24–26 到 27–28 的交接

资产和编辑侧提供的是“目标是什么、当前观察缺什么、有哪些材料”的数据，不提供已经施工成功的结论。冻结 Z 的实际接点如下：

1. 自动放置关闭时，候选解析在取得投影前返回。
2. 开启后，读取 `BlueprintProjectionService.GetReadOnlySnapshotForInternalConsumer`，取得世界身份、有效层和投影签名。
3. 再调用 `BlueprintMaterialService.ForceRefreshReadOnlyForAutoPlacement`；投影不可用、材料解析失败或库存未成功读取时停止生成正常候选。
4. `BuildCandidates` 根据层、工具能力、材料和替换规则形成施工候选，再按施工侧顺序排列。
5. 某些施工要求精确材料：电线计划、需要消耗材料的后处理、特殊 `ItemUse` 放置能力不会直接走普通八类替换。
6. 锤子、刮漆器、致动魔杖等工具本身不作为一次性消耗材料；其候选保留工具信息，材料 ID／数量可为零。
7. 完整对象本体规划接收选中的材料 ID 和 `ReplacementApplied`，并生成实际放置几何／身份信息，不能只给一个任意子格坐标。
8. 候选随后交给施工领域验证、执行和确认；请求发出不等于世界已满足。

候选中明确传递的关键信息包括：

- 实例 ID、目标层、相对坐标与世界坐标；
- 内容、样式、帧、染色、涂层、斜坡、半砖和失活目标；
- 原材料、所选材料、数量、可用量、替换标志及类别；
- `MaterialExecutionScope = "mainInventory0-49"`；
- 实际使用物品、能力类型、放置描述键、灵活魔杖选项；
- 工具槽、工具物品及相应工具状态；
- 完整对象组、尺寸、子格、对象状态；
- 目标对象左上角、实际鼠标 Tile 坐标、放置 alternate、归一化身份和预检结果。

材料清单可以显示虚空袋；候选为空且只存在虚空袋贡献时，施工侧明确提示当前只能从主背包 `0–49` 使用材料。这里核到的是候选与交接协议，实际选槽、使用、消耗、服务器回执和成功确认由“蓝图实际施工”专题继续查到最终出口。

证据：Z `src/JueMingZ/Automation/Blueprint/BlueprintAutoPlacementService.cs`，关闭与投影／材料入口，877–940；精确材料、工具和替换分支，1250–1338；候选字段，1370–1431；请求元数据构造，2665–2734。替换选择与对象目录的完整规则见第 7、8 节。

### 11.2 特殊默认本体不能在资产侧被提前压平

模板可以保留捕获到的对象状态、frame/style 等证据；施工侧是否只能恢复同物品默认本体，是另一条能力规则。两者不能通过“捕获时直接抹掉差异”来假装一致。

正式 Legacy 参考列出的开门、运行中的计时器、触发态开关、Monolith 效果、Cannon 角度等，涉及默认本体与临时状态的区别。完整对象归一化和材料匹配也不能因它们属于一个功能家族就合并为同一个物品需求。当前资产专题确认到目录、精确身份和对象归一化接点；每种特殊本体的实际施工规则归附录 27–28，不在这里用摘要替代那份完整白名单。

证据：R `docs/功能介绍/Legacy蓝图.md:15–21` 的参考边界；Z `src/JueMingZ/Automation/Blueprint/BlueprintPlacementIdentityNormalizer.cs:541–618`、`BlueprintProjectionNormalizedBodyResolver.cs:41–310`，以及上一节的施工候选交接。

### 11.3 本专题实际修改和消耗

- 捕获读取客户端当前能取得的世界 Tile 和对象元数据，保存新的本地模板；不因此消耗建筑材料。
- 预览确认、实例显示／隐藏、移除、移动、镜像、区域修改操作本地实例数据；不是拆方块、挖墙或清线命令。
- 修改库名称、删除、导入、导出操作本地用户资产；不复制箱内物品、文字或展示实体装备。
- 动态投影刷新可保存非电线完成记录，因此不应笼统称整个展示／查询链“无持久化副作用”。
- 镜像帧重建存在第 6、9 节说明的临时 `Main.tile` 写入，是资产操作中必须单独列出的原版副作用边界。
- 原材料不足、冲突、不可读、身份不足、保存失败都有各自失败语义；不能通过自动删除世界内容或绕过进度保护把它们变成成功。

### 11.4 多人结论应分层，而不是直接标“不支持”

固定 Catalog 将蓝图主项标为 `Multiplayer.Unknown`、`Implemented(false)`，但生产中确有本专题所述的真实子链。这个元数据既不能证明“毫无蓝图功能”，也不能证明多人可用。

本地模板库管理与服务器建造权威是不同问题。普通客户端能读到的世界数据、区块是否已加载、当前世界身份是否可靠、服务器是否接受之后的实际建造，都要分别判断：

- Z 捕获读 Tile 的链为 `BlueprintTerrariaWorldTileReader.TryReadTile` → `TerrariaTileReadCompat.TryGetTile` → `TerrariaMainCompat.TryGetTile`。
- 最后一个方法检查 `Main.tile`、坐标范围和非空 Tile；这条链没有看到 R `WorldTileObservation` 那样对普通客户端 `sectionManager.TileLoaded(x,y)` 的明确检查。
- 因此不能仅凭 Tile 非空就把所有远处数据当作已经可靠加载的完整客户端世界；这是定向多人验证点，不是本轮已经复现的坏存档。
- 本地资产保存成功，不是服务器建造成功；服务器拒绝、延迟、权限或 SSC 规则也不能靠本地完成字段猜测。
- 镜像暂存世界数组后恢复，不足以证明原版帧函数没有其它状态、随机流或网络副作用；本轮虽已定向提取 Terraria 1.4.5.8 WorldGen 类型，但尚未完整核定该帧函数的全部副作用，也未执行它。

证据：Z `src/JueMingZ/Features/Catalog/BlueprintFeatureRegistrar.cs:8–21`；`src/JueMingZ/Automation/Blueprint/BlueprintCaptureService.cs:1126–1225`；`src/JueMingZ/Compat/TerrariaTileReadCompat.cs:9–18`；`src/JueMingZ/Compat/TerrariaMainCompat.cs:622–632`。R 对照为 `src/JueMingR.TerrariaHost/World/WorldTileObservation.cs:66–72`。

后续多人目标仍应分别覆盖单人、Host & Play 的本地客户端、连接他人或独立服务器的普通客户端；特殊服务端规则单列。当前静态调查没有给这些拓扑补发验收结果。

### 12.2 “取消保护原实例”的精确提交边界

附录 26 的取消要求需要按实际提交时机解释：

- **移动**：第一次选择实例后形成浮动预览，第二次确认前原位置不变；取消清理活动状态和浮动预览。
- **实例镜像**：开始后等待点击目标；目标点击进入镜像并保存，不具有与移动相同的“选中后再点一次确认位置”阶段。取消待选择状态不改原实例；已经保存的镜像不是可由随后“取消”撤销的临时预览。
- **区域修改**：每次有效拖选释放就保存擦除掩码；取消结束模式，不撤销此前已经保存的拖选。
- **未确认模板预览**：尚未确认时只是预览；确认成功才创建实例。真实 UI 的专用取消按钮可达性按第 9.1 节区分。

证据：Z `src/JueMingZ/Automation/Blueprint/BlueprintPlacedInstanceTransformState.cs`，`Cancel` / `HandlePointer`，188–267；选择／镜像与移动提交，399–586。`src/JueMingZ/Automation/Blueprint/BlueprintEraseRegionState.cs:435–523`。`src/JueMingZ/Automation/Blueprint/BlueprintPlacementPreviewState.cs:489–544`。

因此，R 不能只沿用同名“取消”按钮，就宣称所有编辑都拥有相同的事务撤销语义。是否为区域修改增加确认前草稿、镜像增加提交前预览，应由正式产品合同明确；本轮没有替所有者作出决定。
