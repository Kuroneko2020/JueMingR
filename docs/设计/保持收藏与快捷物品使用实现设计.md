# 保持收藏与快捷物品使用实现设计

本设计对应 [G05 #91](https://github.com/Kuroneko2020/JueMingR/issues/91) 已获所有者接受的本阶段实现，包含分装新堆不自动收藏与鼠标快捷手势归属修订，随本次合并进入 `main` 生效；行为范围见[行为合同](../功能介绍/保持收藏与快捷物品使用行为合同.md)。实际状态、接受范围、构建与安装证据留在 Issue，源码接受不表示最新修订已经安装。现有六项目、net472/x86/C# 7.3、锁定 Terraria 1.4.5.8 与依赖方向不变。

## 职责与选择

收藏意图和快捷使用分属两个业务 owner；Host 只持有原版对象、真实因果作用域和精确 Hook。Platform 只扩展公共动态动作和真实相交物品资源的窄所有权，不认识具体魔镜/电话。UI 使用原 F5 控件、背包图标选择网格和唯一绑定小窗，装配只接线。

采用有据操作边界加有限随身观察；拒绝旧版全局 type/prefix/name 收藏记忆。采用原版真实选槽使用；拒绝固定临时槽搬物与完整快照回滚。采用冻结核心动作加受控动态快照；拒绝解除核心冻结或第二套键轮询。这些选择直接处理串意图、恢复抢人工选择及动态注册失效风险。

## 收藏身份与原版语义

运行关系绑定唯一 Runtime Session 代次、原版实物引用及有据转移代次。引用变化只有实际原版完整转移、交换克隆、合栈、合法变形等边界才能交接；值相等不能授权交接。观察用于确认当前成员/退休，不能从前后总量猜转移。只在主包 0—49 及可靠中转的合法收藏语义下写必要 favorite 并回读，不写 stack/type。

按所有者追加要求，主动拆分出的新堆不继承原堆收藏。`PickupItemIntoMouse` 每次实际转移一件，原来源多于一件时不 Link，连续右键也不把原意图传给鼠标新堆；原来源只剩一件时属于完整转移/合入，仍传递。鼠标多件向空装备槽克隆一件同样不 Link，不能为此清装备共享字段；最后一件走引用交换。原余量和接收端已有的独立收藏保持，左键正常合堆继续按任一有效输入取 OR。

锁定原版 `ItemSlot.ToggleFavorited(Item)` 是主动收藏/取消边界；`ToggleLoadoutShare` 是不同语义。`canFavoriteAt` 只包括 0/1/2/32；装备 8—12 使用共享语义。`MouseItemSwap` 与 `SwapClearFavorite` 在不保留标记的上下文清标，因此装备期间保存独立收藏意图而不补共享字段。原版切组 `EquipmentLoadout.Swap` 交换 Item 引用；只交接已知实物的当前组关系，不全扫描其它组。

原版排序跳过收藏栈并搬实际对象；合法派生只在对应操作作用域领取。嵌套动作只由最近有效作用域提交，异常不推定成功；已取消代次比旧继承更新，晚到关联不能重新补回。离保持域、真正销毁或新会话清旧资格；不可读不伪造空库存。稳定观察复用有限槽结构，记忆容量随现存对象/有限中转而变，不用任意寿命淘汰正常持有物。

收藏恢复先于受影响自动操作的最终资格复核，仍由现有 ItemHostObservation 正常确认 favorite 变化。既有取得意图可以失效，不能因此新建取得意图或清除未知占用。

## 动态快捷键与两个文件

核心注册仍在 Freeze 前完成。公共注册表新增仅能替换本 owner 命名域的动态快照；校验身份、容量和核心冲突后一次发布，带 revision。Bindings 在真实 revision 变化时重编译有效表和主键索引；分派持有稳定快照，并在调用每项前核对该动作仍属当前代次。旧 action 引用不能悬挂执行，修改不能使枚举失效。无变更稳态不重编译。

条目稳定 ID 不承载位置/译名/type。领域配置最多 192 条，完整基线 28 个核心动作加两开关仍在注册表 256 总量内；实际准入也读取公共剩余容量。绑定文件另有 256 行和 65536 字节门，未知动作占容量，失败明确反馈。删除使用真正移除记录的公共保存命令，不把空串行无限累积；只清本条身份，保留其它功能与合法未知记录。

领域配置用既有 DocumentWorker 和 AtomicFileDocument，可靠 Saved 才发布新条目快照。添加先保存领域，再注册空绑定动作；键保存失败留下可见未绑定条目。删除/禁用在接受命令时阻止新使用，已开始的原版动作安全收尾；只有领域删除可靠成功才退休 action 并清其绑定。保存失败或停用的持久条目保留公共冲突占位并禁止修改其绑定，不能让另一动作抢走原键。清键失败只留不可执行孤儿及准确反馈，多个失败身份分别保留供显式重试。领域失败不假报删除；旧对象保持停用等待明确用户后续操作，不因旧 worker 完成自动执行。两个总开关分别标记本次明确修改范围；另一开关保存成功不得解除此前失败开关的暂停，只有对原开关的显式操作才能恢复。启动不依赖两文件到达顺序，只有已载入有效领域条目可注册，其绑定才可能执行。未知提交保护相应文件，不使所有无关快捷键永久停止。

UI 捕获持有 action ID 和编辑代次，目标退休时关闭录入/草稿；已接受机械写入仍由 worker 收口。所有新回调核对当前条目代次与会话。按键与条目可用性分别判断，总开关关闭仍可切开；一次公共分派收齐后，实际使用再次复核最新启用状态，避免同更新总开关关闭后仍执行。

## 真实使用与归还

公共分派把本次命中的不可变 `HotkeyChord` 传给条目请求；不从稍后可能改变的绑定表重查。`HostInputState` 用既有冻结样本认领主键/修饰的按住尾段，独立于物品操作寿命，忙或缺提供者仍消费已认领的原版使用贡献。仅检查原版 Keyboard profile 的 MouseLeft、MouseRight、SmartSelect 三项，保留未认领来源；消费只能扣除本帧实际映射，不能重新激活失焦/模态已清掉的动作。尾段不进全量 SuppressHeld，不吞 WASD 或独立输入；主键和修饰各自可靠释放后退休，失焦合成空态不算释放。

固定 `.8` 的 `Main.mouseLeft/right` 是映射后的 UseItem/UseTile，不是原始物理按钮；`Player.controlTorch/controlUseTile` 在分派时仍可能属于上一帧。准入因此检查扣除快捷贡献后的本帧 Triggers。原版 KeyboardInput 对按住键用 CopyKeyState，LatestInputMode 又跨 Reset 保留，不能据该字段猜本帧手柄来源。现有 HostInputHooks 增加一个精确 `KeyConfiguration.Processkey` postfix，只观察原版实际手柄映射贡献；不读取设备、不改原版设备字典、不另起分派。原版 UI 的直接输入分支保留。已存在且仍驱动攻击的修饰键不被新组合抢走。

没有尾段时不扫描键鼠来源；功能关闭且无尾段时不观察手柄来源。启用结果由输入分派后的 Runtime Poll 发布，观察门在下一帧原版映射前已就绪，不能将发布随意移到映射与分派之间。启用时也只有原版本就正在映射的手柄 token 才记录三项动作贡献；闲置无新扫描。尾段只存固定键位集合和三项动作事实，不排队、不超时重试；测试计数 `SourceChecks` 仅 DEBUG。原版来源证据定向提取到忽略目录 `.local/g05/mouse-source`，身份与下文固定 EXE 一致。真实入口回归从公共绑定保存和 Shell 分派开始，保留缓存键盘顺序、五键映射、真实 ItemCheck、原版归位和客机序列化，最终断言效果次数、原物数量、选择及输入，而非仅 Active=false。

`.8 Player.selectedItem` 是 `selectedItemState.Selected` 只读投影；必须使用当前原版 Select/Update/Override 语义，不照旧写字段。一次请求有独立操作代次，携带条目版本、会话、真实提供者成员和原始选择。优先主包直接选择，不搬物，无位置副本可被错误写入存档。

镜子/电话等效果在 ItemCheck 的 useTime 中段发生，第一次 ItemCheck 返回不代表完成；持续阶段仍需保持真实来源。原版数字/滚轮明确选择是人工接管，WASD/跳跃/修饰并非接管。合成使用位只在证明需要的实际阶段存在，结束释放本功能自己的位，不清物理输入，不把旧值写回原版后续映射。异常清理和正常清理共用代次核验，旧 A 不能退休/恢复新 B。

结果分开记录：是否开始真实使用、是否已发生变形/消耗等观察、选择是否归还或由玩家接管、输入是否释放、是否仍有实际位置责任。未知效果不重试。暂停按模拟阶段等待，不以现实超时重放；关闭/UI/失焦继续清理，死亡/保存退出/会话离开在原版边界前退休，绝不回填旧库存。

## 紧凑界面与工作量

#93 的 UI 追加修订只改变呈现：QuickItemPanel 直接接前一完整块的 Height，复用公共 Row 的尾部间距；不构建 Message／保存状态文本或保留空热区。设置、绑定、真实能力和编辑内容仍能使布局失效，普通错误说明不作为几何代次。错误经两个名称现有 Hint 入口按需读取；卡片、选择器、清键重试按钮保留真实用途。

QuickItemSettings 将文件、两个开关、已存在条目及单个未保存草稿的错误分开持有，可靠的对应操作才退休错误；失败条目数受现有条目上限约束。新增失败的草稿没有持久条目可编辑，重新添加会产生新 ID，因此可靠的新条目保存可替代该单槽错误，无关开关或已有条目编辑不能清除它。Host 对注册失败按设置 Revision 去重，绑定清理按退休 ID 保留原因，启动重试不先清错误。已退休条目的使用错误在可靠发布时清除。TakeFeedback 接到现有 F5 本地提醒链，成功与普通保存不生成通知，后台稳定路径不反复枚举错误集合。

所有者另行明确允许 QuickItemUse 仅替换反馈分类调用：Success、NotExecuted、Error 不由中文文本推断；原选择、使用、归位、输入、准入和调用时序不变。操作异常按条目及操作 ID 去重并保留；同次操作后续成功不能抹掉异常，新操作成功才退休该条旧错。原版接管的未执行保持静默，必要主动请求失败仅沿现有出口反馈，不建立通知平台。

主列表按所有者补充要求采用决明 Z 的小物品图标加当前键位栏，随宽度排一至三列；无绑定显示“+”，双击仍打开同一个公共绑定窗。物品图标点击更换、悬停小叉删除；名称和当前操作放悬停。添加/更换使用自动丢弃同款图标网格与 ItemPickerInput，单选立即保存。打开时只读取主包 0—49 一次，去重并展开合法形态；不扫描箱子、不为此准备全物品目录/配方。模式、兼容策略、启停放在编辑处，兼容顺序只在悬停说明。选择器首次定位后，滚动不会不断被拉回。

同一 Items 页面拥有滚动/裁剪/手势；稳定列表不重读背包、不重建布局。只有可见图标加载纹理，Draw 不读文件或准备目录。收藏观察及界面工作量计数仅 DEBUG 编译，Release 不包含其属性和递增；不引入常驻计时采样、日志或新 worker。

正常首个 ItemCheck 结束不能立即填入返回槽：原版连发武器会读取 HasBufferedChange，这样会吞掉末发。本轮用真实发射/耗弹差分得到反例后改由原版动画、channel/reuse 完成自然归位；新 B 边沿到来前可退休已真实完成的 A。使用首帧结束后同帧退出仍须归还本帧合成 controlUseItem，不能以 checkedItem=true 当输入已释放；后续映射帧不再改写。旧 token 的 finalizer 先校验，再释放鼠标、选择或占用。

## 实施与验证依据

以下为本阶段开发与首轮完整交付的实施、验证依据；追加修订的适用检查与实际执行范围以任务 Issue 的原始回执为准，不表示完整流水在每次修订或最终化提交上重跑。

1. 先在既有 ArchitectureTests 增加动态动作晚注册、删除时分派、已保存绑定重新接入、孤儿不执行、旧保存回调和容量反例；用实际公共实现得到 RED，窄扩展后验证 GREEN。
