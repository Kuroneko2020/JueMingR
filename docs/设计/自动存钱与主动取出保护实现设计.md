# 自动存钱与主动取出保护实现设计

对应 [行为合同](../功能介绍/自动存钱与主动取出保护行为合同.md) 与 [#93](https://github.com/Kuroneko2020/JueMingR/issues/93)。起点为已交还的 main `9368ffdf826ff582756ec6824e1f861c517579a8`；G05 PR #92 已合并。本文记录本轮设计，不冒充实施或实机结论。

## 职责与操作

Features/CoinDeposit 拥有受检币值规则、会话内意图及代次、结果和独立偏好。TerrariaHost/CoinDeposit 拥有银行入口见证、有限内容观察、真实取出 Hook 和唯一写入口。Items 只扩展实际钱包交集所有权及保护查询，不删除旧非币排除；UI、快捷键只提交设置。

每次提交绑定会话、偏好/保护代次、本地 Player、真实 inventory/账户/数组/成员引用和当前有效入口。原版实际源币写域与已有出售、存放、丢弃、使用占用交叉检查；其中出售本来占完整 58 槽。任一可被 MoveCoins 移动的钱币受手动、弹药或原版锁保护时，先于银行查询等待，写前再次拒绝整次调用，不能临时收藏、裁剪或隐藏它。共享手动事实经原始物理释放的窄入口退休，不依赖非币取得机会触发整包观察。

本功能可用性同时要求自己的取出 Hook 与共享 Items 安装/材料保护能力就绪；共享保护安装失败时，观察、提交、开关和状态统一反映不可用。普通物品自动处理偏好关闭不等于保护能力缺失，不因此禁用存钱。

`CoinSnapshot` 仅在实际尝试时捕获钱包59槽、四银行身份/数组/成员/属性和鼠标；金额域为钱包前58槽与目标银行，另外三银行用于证明无隐藏写入/别名，不把其它银行余额当转移成果。固定 `.8` 的重建成员必须匹配本次操作前生成的真实原版四币模板或 plain Air；未触碰成员保持原引用和全字段。币值按 checked long，收藏币仍在金额域。临时读取/别名拒绝不制造交易故障；原版已进入后不能证明包络或守恒则 Unconfirmed，不回填、不换账户重放。

首存依照 [#93 已批准的限定澄清](https://github.com/Kuroneko2020/JueMingR/issues/93#issuecomment-5725175285)：只有存钱罐原无币、原版正常返回0，且逐槽证明除原合法空槽变成独立plain Air之外全域不变，才考虑补充步骤。以操作后真实对象重新捕获全部包络，然后释放原版许可；新许可前再次逐槽核对这份操作后证据，避免释放期间的等值替换悄然重新绑定请求。选择最高币种最先槽位和目标首个合法空槽，再复核会话/代次/入口及保护并取得新许可。先准备替代空对象，受控步骤仅将源整栈引用移至目标、将源置为新的独立plain Air；写后核对两端金额、精确引用和全部属性，其它槽严格不变。不克隆币堆，不写回原版调用前的空对象。失败只有在精确证明当前仍是本次独占写入时才可恢复本次确切两槽并验证；否则保留未知边界并停止。

按所有者截图追加的界面窄修：正常关闭由开关选中态表达，正常保存完成后不保留重复提示行；三项功能悬停只说明用途。配置进行中、失败、取出保护及未知结果仍直接显示，具体解除条件沿已有悬停入口提供；不新建文案过滤或帮助平台。

提交前先完成真实因果取出观察；请求即使在同更新提前生成，也要在唯一写入口再次核验代次。正常操作不执行用户输入或网络回调，有限同步确认后发布结果。任何可能部分写入的不可确认结果保留本操作边界，禁止换目标重放。取出意图不占用通用 Items 所有权，不阻止手动花钱。

取出作用域只在外层原版调用内存活。已证实源减少但到账/临时身份不可读时仅留下 Pending 意图，不持有旧 Item 等待以后钱包上涨。Pending 与 Protected 使用相同范围退出、显式重开及明确新会话结束边界，但不冒充已经到账；暂时 null 世界/连接不新建会话，正身份变化才退休旧状态。自动交易 Faulted 与意图分开，开关不能清除。

未确认自动交易额外保存本次真实来源槽位的固定 bitmask。临时身份失败导致 Runtime 重新开始时，在所有 Feature Update 前仅恢复同一原版玩家/会话的共享冲突范围；不恢复旧 token、Item 引用、写许可或事务。明确新玩家/世界/连接或退出会话才退休该事实，防止故障标志仍在而共享出售已解除保护。

## 观察与性能

关闭/会话/输入廉价门在先。无可存钱币且无保护时不查银行。有限钱包观察使用固定数组事实，不创建全功能快照或字符串签名。

保护阶段优先验证已知入口见证，只证明至少存在一个；不读容量。见证失效后的零结论必须同一游戏线程完整覆盖原版有关范围，跨帧扫描不得假装原子空集。普通发现每个有工作更新最多读取128个投射物/tile位置，完整固定范围为1000+79×79；普通移动不每跨一格就丢弃进度，传送或资格/对象改变重新开始，完成后仍过滤当前有效入口。

先尝试不依赖钱包资格的非虚空见证；即便缓存同时有虚空入口，只要非虚空见证仍成立就不读钱包。仅依赖虚空见证或需要证明完整空集时，读取有限钱包确认闭合袋资格。

增量发现不能证明提交瞬间的原版先后顺序；实际新工作在同一线程重新完成有序查询，并作窄身份核验，最多每60个允许更新进行一次实际尝试。钱包/可能目标的固定内容事实每6个允许更新复核；静止新家具、投射物、容量和网络本地变化缺少统一低成本事件，故保留这条有界校验。无币无保护没有范围/容量查询；稳定已完成无币停下。无进展缓存绑定钱包、该账户内容及意图版本，等值Item重建和同账户更换入口不重新尝试；容量、新币等变化恢复工作。保护无见证且查询失败时60更新后再作完整可靠查询，不能把失败当零。两端快照/全属性校验只属于有限真实操作，不在稳定Tick运行。

计数位于 DEBUG 的 Host、Range、Transfer 和取出入口，Release 不带这些常驻字段。`WalletReads`/`CapacityReads` 是固定事实观察涉及的槽数，`TileReads`/`ProjectileReads` 为实际发现位置，`CompleteQueries` 为原子范围查询，`NativeCalls`/`Snapshots`/`Scopes` 为实际操作次数；不能将这些计数换算FPS或视为全部CPU/GC成本。门禁将正确性与关闭、无币、保护、满双账户/入口改变、真实变化及持续拾币工作量成对验证。

## 验证入口与边界

- 纯规则与文件：ArchitectureTests `--coin-deposit`，同时纳入全量入口；`CoinDepositChecks` 与 `CoinSettingsChecks` 验证意图、币值、共享占用、可靠偏好及真实文件冲突/未来格式。
- `.8` 真实适配：NativeWorldTextProbe `CoinDepositCpu`，实际先跑G05完整夹具再跑 `NativeCoin*` 的取出、全属性/Partial、范围差分、身份/Pending、CoinGun、普通客户端序列化、隔离加密保存重载、工作量、UI及写后异常。没有替身成功的MoveCoins。
- 原资源图形：`CoinDepositVisual`；正规包装入口 `scripts/test-world-object-text.ps1` 支持显式完整diff `-WorkloadBaseline`，内容目录必须匹配固定原版。CPU布局与实际绘图分别记录。
- 构建/选组：`scripts/build.ps1 -Configuration Debug -WorkloadBaseline <起点main>` 自动选取 `coin-deposit-host` 与共享消费者，实际单文件差异路由检查覆盖 Items/来源/Input/worker/G05；Phase0S 安装恢复隔离检查将 `coin-deposit.json` 作为不透明用户数据。

首存专项须用真实原版入口验证规范化后成功，以及已转移、非空等值替换、槽内容改变、账户/数组变化、新保护/占用、异常/读回失败均不误入首存；满账户和无进展不循环。只有完整实现和门禁通过后才生成候选。结果、固定SHA、独立审查、双包和实际安装身份只在 #93/PR 记录。

## 实施与验证顺序

1. 先写会话/保护/旧请求拒绝、受检金额、首存选择、共享占用和偏好失败的预期失败用例，再实现纯规则。
2. 实现 Host 取出因果、范围见证和唯一提交；通过同身份真实原版验证四币、四银行、五取出源、99/100、满/部分、非币/收藏/别名/异常与两端最终状态。
3. 接入公共输入/F5、独立偏好和完整 profile；检查 G01–G05 共存、真实钱币枪材料、隔离原版保存重载和普通客户端实际序列化。
4. 正规构建自动选组涵盖本功能与共享消费者；测关闭、无币、保护、满/完成无变化、真变化和长期边界。图形验证正常及极端布局。
5. 固定干净实现，另派未参与设计的独立只读审查；修复具体发现并定向复审。相同固定 SHA 在同一工作区连续两次干净构建/完整打包，对全部声明产物、PDB、payload、ZIP 做逐文件比较。
6. 仅在包门禁通过且游戏未运行、目标和原安装归属明确时安全安装。保留原文件/回执和玩家数据，记录源码/完整包/实际安装三方身份。停止待用户实测与外审。

不得把模型测试、隔离 NativeProbe、序列化截获或图形预览称作真实联机、物理输入、FPS 或产品接受。
