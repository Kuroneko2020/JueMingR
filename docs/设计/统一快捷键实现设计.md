# 统一快捷键实现设计

本设计实施已接受的[统一快捷键功能行为合同](../功能介绍/统一快捷键功能行为合同.md)第 7 节。需求由 #49 / PR #50 收口，实施由 [#51](https://github.com/Kuroneko2020/JueMingR/issues/51) 授权。本文记录实现选择，不将开发候选或自动测试称为实机验收。

## 职责与数据流

现有 Platform 增加不依赖 Terraria 的 `Hotkeys` 公共能力：不可变组合、统一物理沿、稳定动作注册、绑定文档和保存协调。TerrariaHost 负责一次实际 XNA 输入适配、原版设置时冲突、四个动作注册和 F5 内唯一小窗；已有 Features 继续拥有业务状态。没有新生产项目、依赖、全局键盘服务或第二套焦点检查。

每 Tick：`HostInputState.BeginUpdate` 保护录制与尾段的旧缓存 → `AfterMapping` 在原版缩放/导航之前消费录制、尾段与可见小窗鼠标占用 → `AfterKeyboardRefresh` 冻结真实键鼠样本并维护全部边沿 → F5/Notes/Items 与小窗裁决占用 → 对仍获许可的新主键沿分派。F5Shell 在该映射出口仅用当前 MouseInfo 与已有小窗几何提供占用裁决，不重新读设备或推进边沿；所有消费者只读同一份样本；被阻止的按下仍记入物理状态，不能在编辑结束后补发。失焦合成空态不作为真实释放。

注册由稳定 ID、显示名、适用上下文、可执行条件和命令组成。首轮 ID 为 `biome-display.toggle`、`items.auto-stack.toggle`、`items.auto-sell.toggle`、`items.auto-discard.toggle`。群系复用 `HostPreferences.SetBiomeEnabled`；物品复用 `HostItems.Change`，只变对应开关。资格不依赖开关已经开启。公共分派执行动作委托，不内置 bool 或界面顺序；隔离测试通过同一出口执行非开关动作。

## 按键与触发

规范形式为零至三个不同的 `LeftControl/RightControl/LeftShift/RightShift/LeftAlt/RightAlt`，加一个主键。保存使用上述无歧义 XNA token，显示单独使用 `LCtrl/RCtrl/LShift/RShift/LAlt/RAlt`；顺序固定用于展示与保存；六位修饰掩码精确相等，不将额外普通按住键算作修饰。主键已有按住时增删修饰不会产生新沿。每 Tick 可执行不同主键的新沿；同组合且适用上下文重叠的不同动作不能同时生效。

输入使用已锁定 1.4.5.8 的 XNA KeyboardState 与 PlayerInput.MouseInfo。主键目录覆盖该接口可报告的普通字母、数字、导航、OEM、数字区、F1–F24、锁定键及可报告扩展键，并区别系统/IME 状态伪键。鼠标为 Mouse1–Mouse5；滚轮不进入目录或边沿，继续交给现有滚动。Esc 为录制取消，F5 为界面保留；Back 为可绑定 Backspace。Win 不作修饰，按住 Win 时不产生候选/玩法命令。

当前接口没有扫描码和 extended-bit，不能区分主区 Enter 与数字区 Enter；数字区受系统实际报告和 NumLock 影响。锁定键只看按下高位，不把锁定状态当作持续按住。媒体键等能否被硬件/系统交给游戏另属实机边界，不能由枚举或夹具证明。布局字符名称不作为持久身份，OEM 按接口键身份显示。系统保留组合可能不抵达进程，不能保证捕获。

## 原版冲突与编辑所有权

仅候选形成与最终提交时读取当前 `PlayerInput.CurrentProfile.InputModes[Keyboard].KeyStatus`；原版匹配忽略额外修饰，故组合的主键和每个修饰 token 都要检查。读取失败拒绝这次设置，保留旧值。按实际 .8 条件处理 Tab+Alt / Steam Shift 例外、可编辑游玩动作及固定入口：F7/F8/F10/F11、Shift+F9、Enter/Alt+Enter、开启原版调试命令时的数字区。F1–F4 等可改映射不写死保留，裸 F9 不因 Shift+F9 被拒绝。

文本、IME、物品选择器、UI 鼠标手势与玩法互斥；Ctrl+C/X/V、Ctrl/Shift+Insert、Shift+Delete 等不设全局禁键。捕获不接管 Notes 或其他编辑器的 IME token。游戏内地图/相机等模态入口与 F5 现有门一致。保存之后没有原版变化监听、定时读取、启动重检、自动禁用或按键日志；用户后来改原版造成重叠时允许原版原有行为，界面只作一次清楚说明。

## 唯一小窗

四行末尾键盘图案携带稳定动作 ID；同入口两次有效点击在 500 ms / 6 逻辑像素内打开唯一小窗。图案与普通开关命令分开，未接入占位图标维持无动作。小窗贴近入口并夹在可用视口，复用当前 UiSurface、UiTextMetrics、F5ControlRenderer、F5IconAtlas 的资源和生命周期。真实字体测量换行，同一冻结几何供绘制与命中；内容/字体变化才重建布局，不将动态错误文案放进固定文案无限缓存。

显示当前组合、录制说明、当前状态和开始录入/清除/关闭。显式控件先裁决，点击控件不会成为 Mouse1 候选；开始时屏蔽激活点击及预按主键直到真实释放，预按修饰允许配合随后新主键。纯修饰只显示进度；同 Tick 多个新主键明确拒绝。候选成功、失败、Esc 取消后小窗保留；关闭、切页、失焦或不可展示结束录制，提交中的可靠写入继续完成。捕获和结束尾段消费键鼠动作直到真实释放，不穿透世界或页面。滚轮不录入，仍走原有滚动路径。

## 独立持久化与失败恢复

唯一文件为 `JueMingRData/config/hotkeys.json`，format `JueMingR.Hotkeys`、version 1、bindings 数组，每项为 `action` 稳定 ID 和 `binding` 规范键名字符串；空串代表未绑定。缺文件默认全未绑定，不因启动或安装写默认文件；不读取或导入旧快捷键/物品退休字段。

`HotkeyBindings` 仅游戏线程修改有效表，复用现有 `DocumentWorker<HotkeyDocument>` 与 AtomicFileDocument 的恢复保护策略。后台线程只处理不可变候选与字节；可靠 Saved 才替换有效表。每次提交有 command ID、动作 ID 与弹窗 epoch，旧完成只能激活其已提交文档，不能改写新目标的草稿/提示。忙时不覆盖接受槽；关窗不取消已接受写入。

结构损坏、未知字段/版本保护原文件不覆盖；合法未知动作保留但不分派。非法组合、重复动作或已注册动作之间的组合冲突禁用受影响条目并保护文档，不能按枚举顺序任选赢家。加载仅做自身语法/注册与内部冲突验证，不访问原版键位。提交前普通明确失败保留旧有效值，允许重新录入后保存；外部冲突或原有恢复材料则继续写保护；替换后结果不明也保留旧有效值并保护写入，提示磁盘状态待恢复核对，不能声称已回滚。进程退出有界排空已接受写入，沿用既有存储恢复材料。

## 后续动作接入

在现有 Host 组合位置向同一 HotkeyRegistry 注册稳定动作 ID、用户名称、当前适用上下文、可执行条件与真实命令委托，然后将获准功能行的 HotkeyTarget 指向该 ID。所有注册在 HotkeyBindings 创建并冻结注册表前完成；不使用页码、索引或译名作身份，不让每个功能再建采样器/文件/录入小窗。示意 `new HotkeyAction("feature.request", "功能动作", HotkeyContext.SinglePlayer, CanRequest, Request)` 中 Request 可以提交一次动作，业务仍由功能 owner 验证并执行；这只是接入说明，不注册新生产功能。

不可执行/故障条件放在 CanRequest，开关当前为 false 本身不是禁止切换的理由。UI 与快捷键调用相同设置/命令出口，不复制状态；Feature 继续处理多人权威、持续行为与在途结果。新增真实消费者时必须覆盖从入口保存到物理新沿及实际命令的反例，不只检查 registry 中存在一项。文件最多 256 条；合法未知动作占用文档条目但不参与分派，满容量显式拒绝新条目而不抛出 UI 异常。

## 成本与核验位置

高频阶段只采固定 261 个键鼠位、推进一次边沿并查主键索引；没有按注册项重复读键/前台、运行解析或原版配置扫描。全未绑定直接退出分派。保存后重新编译表，最多 256 条的内部冲突比较只在文档载入/可靠保存成功时执行。小窗以内容、字体和视口变化重建几何，稳定帧不拼全表签名或重新换行；后台 I/O 沿用一份文档的一名 worker，不为每功能建线程。以上是源码成本形态和隔离检查，未测实际 FPS，不能作性能收益声明。
## 实施顺序与验证

1. 先写组合/精确修饰/主键沿/非开关注册的失败测试，看到 RED 后实现公共内核；再覆盖真实原子文件与忙/失败/未知提交、未知字段/动作和重复绑定。
2. 接共享物理样本及实际原版配置适配，先打通群系真实控件至命令与文件，再通过同一接口接三项物品开关。
3. 用生产 HostInputState、F5Shell、小窗、实际命令出口的夹具验证顺序与所有权；验证 Notes/物品相邻输入、真实字体长组合/错误换行及资源切换。夹具不冒充真实 IME、实体键盘或游戏验收。
4. 必要联合回归与独立完整审查，修复后窄复核；固定 clean SHA 在同一工作区连续 Release 构建，对声明产物 hash/MVID 和同 profile 包比较，不建 worktree。
5. 复用安装/恢复链生成 UnifiedHotkeys 候选，核验精确目标、旧回执和新包，只替换自有载荷，保留用户数据；安装后不启动游戏，保留安装等待实机反馈。

图形环境若在设备创建前明确失败，记录原因与未执行项，不通过缩减行为期待伪造绿色结果。功能/输入/资源真实失败必须修复。当前验证结果、提交、包、回执及独立审查见任务 Issue，不在本文维护动态进度。
