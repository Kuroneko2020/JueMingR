# 宝箱牌子与墓碑显示实现设计

状态：所有者已授权实施；实现、验证、安装和体验接受分别记录在 [Issue #63](https://github.com/Kuroneko2020/JueMingR/issues/63)。前置需求 [PR #62](https://github.com/Kuroneko2020/JueMingR/pull/62) 已合并。本文是本次有限实现设计，不改变路线图或长期治理。

行为依据：[功能行为合同第 7 节](../功能介绍/宝箱牌子与墓碑显示功能行为合同.md#7-已确认的新版首轮合同)。正式合同优先于本设计的内部选择；历史 V0 仅作证据。

## 责任与数据流

- `Features/WorldObjectText` 拥有三个显示模式、对象几何规则、候选选择、开过位置语义及空间索引；不引用 Terraria 或 Notes。
- `Platform/WorldObjectText` 只承载同步只读值和窄观察端口。游戏原始 tile/chest/sign 事实始终属于原版。
- `TerrariaHost/WorldObjectText` 读取当前 `.8` 原版字段，观察本地成功开箱，准备原版文字和图标，按既有世界层画已准备结果。共享世界读取只共享字段和当前 tick 缓存；金属探测门只适用于需要它的消费者。
- `Features/Text` 提取现有 Notes 的有限 Unicode 边界规则，保持 Notes 行为；世界标签以有界游标逐段消费，不能先建立整个长字符串的边界数组。
- 开过记录 owner 把无游戏对象的位置 DTO 交给一个进程级领域 I/O 调度器。调度器以线程池上的单个在途操作顺序复用 `AtomicFileDocument`，负责所有 pair 的读、合并、序列化和安全提交；空闲不占专用线程，不能每功能、每 pair 开线程。普通配置继续沿现有 PreferenceDocument 的机械语义。
- 一份 `world-object-text.json` 保存三个功能的配置，复用既有 `PreferenceDocument` 机械语义。F5 与快捷键都调用同一模式命令；StyleTarget 复用既有颜色/字号弹窗。

## 对象、发现与选择

只读 resolver 从任一组成格的 frame 推回左上角，验证完整 4/6 格，且同类型、合法样式和精确局部 frame。容器 21/441 为 2×2、52 样式，467/468 为 2×2、38 样式，88 为 3×2、65 样式。21/441 使用 `chestType`、467/468 使用 `chestType2`，467 的 style 4 按原版 ChestUI 使用 Item 3988（死人宝箱）；88 使用 `dresserType`。常春藤是 style 10。牌子使用当前 tileSign 且排除 85，当前固定版本覆盖 55/425/573；85 为墓碑。名字优先当前已知非空自定义名，缺信息才用明确通用后备，不把坐标记录当作名称缓存。

发现按当前视口及文字边距渐进扫描，保留可继续的行游标；小幅连续移动不中断进度，大幅跳转撤销旧视口。候选在完整验证后按“当前可见优先、到玩家中心的距离、稳定坐标”比较，最大输出 240/40/40。K 只限制最终输出；更晚发现的更近物体必须替换较远物体，不能扫描先到先得。保留额外候选用于空文案、布局失败或裁剪后的有界补位。尺寸、颜色和移动只使对应投影失效。

当前内部工作上限：每 update 扫描最多 4,096 个视口 tile，同时至多尝试 256 次新对象完整解析；复核现有 N≤384（272/56/56）个对象；Opened 查询至多 256 个原始桶/坐标访问，重复或越界也消耗额度；每对象至多 6 格读。相同 tick 的原始格事实共享容量 65,536 的读穿缓存。至多 8 个冷/脏排版工作各消费 512 源 UTF-16 单位，合计 4,096；单标签源消费上限 65,536，单可见单元上限 1,024。达到文字护栏不继续全文扫描。原版 FindChest 已有坐标字典，直接复用，不建立 C 名称索引；长前导空白自定义名共享每 update 512 字符的检查额度，暖命中只比较引用/状态。牌墓共享 S 表游标，每 update 512 槽；32,000 槽完整周期至多 63 次有效更新（已索引的当前候选每次直接复核文本）。不得以统一 elapsed-time 计时器取代可解释工作上限。

选择用固定最大堆及坐标索引，玩家移动原地重排 N，不为每个被拒候选创建对象。空正文拒绝缓存按坐标/字符串引用最多 512 条，样式/字体/语言/视口排版语义变化后失效；裁剪资格按当前投影单独检查，不记成永久正文拒绝。准备缓存最多 512，逐条淘汰，未再访问的条目最多保留 120 次有效准备更新后每次退役 8 条；取消未完成任务同时撤下缓存，重新出现可重新排队。颜色只更新继承颜色片段；窗口 tile 舍入不作为排版宽度，因此小幅移动不重解析。

三项关闭时不做标签发现、文字、绘制；Always 未取得原版 `accOreFinder` 时先撤销需求再退出；Opened 且已知 H=0 时不做名称表和区域扫描。Opened 使用 64×64 tile 桶查询邻近已打开坐标，桶只因新记录/加载发生变化；不因相机每帧移动重建 H，也不因颜色/字号重新索引。

## 文字与绘制

默认宝箱橙色 FFA500、牌子 E6C16A、墓碑 FF5555，独立字号 70%，70 的默认不改变既有实体 90%。字号范围 50–180、步长 10。牌子/墓碑 Lines 默认 3、范围 1–10；Characters 默认 80、范围 1–1200。All 有最多 10 个实际排版行的护栏，省略号占护栏空间；Characters 按可见完整字符单位计数，颜色标记不计、图标计 1、换行不计，内部空行保留。

有界 lexer 只接受经过验证的原版常见颜色、物品标签，其余按字面显示。一个解析结果供截断、测量和绘制复用；颜色片段之间的组合字符不能被拆开，图标不可分。CRLF 规范为一个换行。基础换行宽度约 460×字号并受视口约束。逐完整单元测量/累积，禁止递增前缀的二次复杂度；长输入未消费部分不用扫描才能判定已经到达显示护栏。

原版 `ChatManager.ParseMessage` 用于已验证标签；缓存 `PositionedSnippet`，Draw 只调用接受该缓存的重载。禁止 Draw 调用 string/未布局 snippet 重载。图标资源取得与布局在游戏线程限额准备；原版 `UniqueDraw` 涉及 `inventoryScale`，外侧 `finally` 恢复。关闭 hover/click 行为。继续借用既有世界 SpriteBatch，禁止每标签 Begin/End 或创建纹理。

## 开过位置与持久化

观察独立于三个显示模式。正常本地玩家、有效会话、背包开启、非负世界 chest 索引、chestX/Y 对应当前 Chest 坐标、完整真实容器才形成事实；拒绝银行、hover、拒绝开箱、其他玩家和 `World.AutomaticOperation`。保持打开同一箱子只比较标量；新坐标才改变 revision，重复坐标不重复写，尚待提交的事实仍归提交 owner 管。

持久 pair 以已载入 `ActivePlayerFileData.Player` 与 `Main.LocalPlayer` 同一对象为前提，角色以 FileData.Path 加 local/cloud 存储域定位；世界以非空 WorldFileData.UniqueId 定位。普通客户端还要求当前连接正常入世，避免握手期旧 GUID。路径/GUID 只在 pair 变化时生成存储键，不逐帧哈希；不读取私人角色文件、显示名、服务器地址、保存时间或完整存档。角色真实文件位置是当前原版可取得的身份，不是角色 UUID：手动把不同角色替换到同一路径无法区分；本地/云移动会形成不同归属，首轮不自动迁移。

身份不足只影响该会话的持久资格，给有限提示，继续记录局部位置，不落到公共 unknown 文件。身份晚到只合并同一 session 的新事实。读取完成后按 pair 与 session/revision 合并，并把加载期间新开的位置保留；旧回调不能写进新世界。离世已接受提交由原 pair 完成，不换绑。

文件为 `JueMingRData/records/opened-containers/<pair-key>.json`，只含 format/version、pair 校验标识及去重左上角位置；不存物品/名称/时间线。单文件有合理容量上限，超限保护原文件并明确降级。后台执行解析、索引构建、合并及序列化；当前查询读已发布索引和本会话增量。Missing、损坏、未来 schema、读取失败、写失败、提交未确认分开，复用原子存储的保护/备份，不因坏文件写空替代。有限去重反馈，无逐开箱成功聊天。

## 分步实施与验证

1. 固定需求与 `.8` 原版证据，写精确路径清单，建立 Draft PR。
2. 先建立能证明三条旧缺陷的测试，再实现完整物体/排序选择/设置命令。继续覆盖 off/gate、未知格、边缘组成格、替换与连续移动。
3. 实现有限文字游标、原版标签准备与有界排版，检查 Unicode、未知标记、图标和冷暖路径。接入 F5/统一快捷键及原版世界层。
4. 实现独立观察和 pair 记录，真实隔离文件测试加载期间增量、旧回调、重复坐标、坏文件/未来版本/失败保护与实际消费者。
5. 跑相邻回归和有限性能场景，图形项准确区分设备前不可用与实际绘制失败；测试设施不得混入发布文件。
6. 固定干净提交，独立只读审查完整 diff；按现有完整 Profile 同工作区顺序重复构建/ZIP 比对，安全预检和安装。保留实现 Draft/Issue OPEN，提供少量中文体验卡，等待所有者亲自体验。

测试报告分别列 T（视口 tile）、C（世界 chest 槽位）、H（历史坐标）、N（附近候选）、K（输出）、S（sign 槽位，当前 32,000）与 L（源文本单位），报告典型/尾部工作和可测分配，不推导 FPS 根因或收益。
