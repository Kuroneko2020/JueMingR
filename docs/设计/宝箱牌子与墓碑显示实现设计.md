# 宝箱牌子与墓碑显示实现设计

状态：所有者已授权实施；实现、验证、安装和体验接受分别记录在 [Issue #63](https://github.com/Kuroneko2020/JueMingR/issues/63)。前置需求 [PR #62](https://github.com/Kuroneko2020/JueMingR/pull/62) 已合并。本文是本次有限实现设计，不改变路线图或长期治理。

行为依据：[功能行为合同第 7 节](../功能介绍/宝箱牌子与墓碑显示功能行为合同.md#7-已确认的新版首轮合同)。正式合同优先于本设计的内部选择；历史 V0 仅作证据。

## 责任与数据流

- `Features/WorldObjectText` 拥有三个显示模式、对象几何规则、候选选择、开过位置语义及空间索引；不引用 Terraria 或 Notes。
- `Platform/WorldObjectText` 只承载同步只读值和窄观察端口。游戏原始 tile/chest/sign 事实始终属于原版。
- `TerrariaHost/WorldObjectText` 读取当前 `.8` 原版字段，观察本地成功开箱，准备原版文字和图标，按既有世界层画已准备结果。共享世界读取只共享字段和当前 tick 缓存；金属探测门只适用于需要它的消费者。
- `Features/Text` 提取现有 Notes 的有限 Unicode 边界规则，保持 Notes 行为；世界标签以有界游标逐段消费，不能先建立整个长字符串的边界数组。
- 开过记录 owner 把无游戏对象的位置 DTO 交给一个进程级领域 I/O 调度器。调度器以线程池上的单个在途操作顺序复用 `AtomicFileDocument`，负责所有 pair 的读、合并、序列化和安全提交；空闲不占专用线程，不能每功能、每 pair 开线程。普通配置继续沿现有 PreferenceDocument 的机械语义。
- 一份 `world-object-text.json` 保存三个功能的配置，复用既有 `PreferenceDocument` 机械语义。F5 与快捷键都调用同一模式命令；StyleTarget 复用既有颜色/字号弹窗。

## 对象、发现与选择

本轮同任务窄修登记见 [#63 稳定态维护修订](https://github.com/Kuroneko2020/JueMingR/issues/63#issuecomment-5652450115)。仅处理同值 Offer 的重复维护/排序；新增 DEBUG 计数只用于有限对照与回归，不进入 Release。写入沿本文现有路径清单，另含 `WorldObjectSelection.cs` 与 `ObjectRulesChecks.cs`；证据留 `.local/world-object-text-implementation/stable-selection/`，新包留 `outputs/world-object-text/<候选>/`。不改变已接受的功能、视觉和刷新边界。

只读 resolver 从任一组成格的 frame 推回左上角，验证完整 4/6 格，且同类型、合法样式和精确局部 frame。容器 21/441 为 2×2、52 样式，467/468 为 2×2、38 样式，88 为 3×2、65 样式。21/441 使用 `chestType`、467/468 使用 `chestType2`，467 的 style 4 按原版 ChestUI 使用 Item 3988（死人宝箱）；88 使用 `dresserType`。常春藤是 style 10。牌子使用当前 tileSign 且排除 85，当前固定版本覆盖 55/425/573；85 为墓碑。名字优先当前已知非空自定义名，缺信息才用明确通用后备，不把坐标记录当作名称缓存。

发现按当前视口及文字边距渐进扫描，保留可继续的行游标；小幅连续移动不中断进度，大幅跳转撤销旧视口。候选在完整验证后按“当前可见优先、到玩家中心的距离、稳定坐标”比较，最大输出 240/40/40。K 只限制最终输出；更晚发现的更近物体必须替换较远物体，不能扫描先到先得。保留额外候选用于空文案、布局失败或裁剪后的有界补位。尺寸、颜色和移动只使对应投影失效。

当前内部工作上限：每 update 扫描最多 4,096 个视口 tile，同时至多尝试 256 次新对象完整解析；复核已就绪 N≤384（272/56/56）和至多 8 个待准备对象；Opened 查询至多 256 个原始桶/坐标访问，重复或越界也消耗额度；每对象至多 6 格读。相同 tick 的原始格事实共享容量 65,536 的读穿缓存。至多 8 个冷/脏排版工作各消费 512 源 UTF-16 单位，合计 4,096；单标签源消费上限 65,536，单可见单元上限 1,024。达到文字护栏不继续全文扫描。原版 FindChest 已有坐标字典，直接复用，不建立 C 名称索引；长前导空白自定义名共享每 update 512 字符的检查额度，暖命中只比较引用/状态。牌墓共享 S 表游标，每 update 512 槽；32,000 槽完整周期至多 63 次有效更新（已索引的当前候选每次直接复核文本）。不得以统一 elapsed-time 计时器取代可解释工作上限。

只有排版完成且有当前可见墨迹的对象进入上述已就绪名单；8 个待准备槽与 Top-K 分开。槽满时暂停原扫描/历史游标，完成或拒绝后继续原进度，两种发现有工作时轮换优先次序。不能将未知正文先当合格近物塞进 Top-K，再用有限拒绝缓存补救；600 个近处长空白彩色标签超过拒绝缓存后，旧方案会循环重试而饿死远处有效牌子。当前真实原版夹具在 3,200 次更新内完成该反例；它也表明极端连续长空白会推迟后方首次显示，不能承诺所有对象立即出现。普通短名字最多每更新准备 8 件，240 件约需 30 次准备更新，另加附近发现/首次牌表索引的推进时间；移动不无故清空这些进度。

选择用固定最大堆及坐标索引，玩家移动原地重排 N，不为每个被拒候选创建对象。空正文拒绝缓存按坐标/字符串引用最多 512 条，样式/字体/语言/视口排版语义变化后失效；裁剪资格按当前投影单独检查，不记成永久正文拒绝。准备缓存最多 512，逐条淘汰，未再访问的条目最多保留 120 次有效准备更新后每次退役 8 条；取消未完成任务同时撤下缓存，重新出现可重新排队。颜色只更新继承颜色片段；窗口 tile 舍入不作为排版宽度，因此小幅移动不重解析。

稳定态复核与排序失效分开：`WorldObjectSelection.Offer` 对同 key 的 `Kind/TileX/TileY/Type/Style/Width` 六字段完全相同直接返回，保留此前尚未消费的 dirty。`SetView` 已重算现有节点排名；类型/样式即使比较器相等也属于真实载荷变化，沿既有堆修复和有序副本刷新。Discovery 的完整性、资格及取文循环不变，名字/正文不在几何值里，不用几何相同跳过内容更新。未开启种类原有空 Clear/空排序不在本次非空重复维护修复范围。

本轮窄反例先在旧行为上失败：100 次完整 `Discovery.Update` 稳定复核仍有 300 次排序、2,000 次 Repair；另有重复 `CopyTo/Ordered` 反例。修后两者不再增加同值维护；玩家/视口变化后的有效 dirty、同址 21→467/Style10→88/3宽→牌墓、二次有效输出、梳妆台旧原点变内部格、文字独立变化均有执行回归。`NativeWorldChecks.RunSelectionCpu` 读取实际 `.8` tile/chest/sign、真正 Features DLL 和当前 Host 观察/准备源码，使用完整 300 件输入的独立最近名单判定，核对前240条实际待绘包及当前载荷/snippets；另外加载独立构建 Host，经 `UpdateRuntime` 执行 100 次稳定更新，Sort/Repair 均为0。CPU固定字形度量只证明排版/失效与准备消费，不代表原资源外观或绘制已重验。

有限对照入口为 `scripts/test-world-object-text.ps1 -Scope SelectionCpuCosts`，本轮关联非图形回归为 `-Scope SelectionCpuChecks`；默认 `Full` 保持原入口。两次同一主工作区执行，基于 `f16551e` 加等价 DEBUG 计数/测试夹具，前后 `FiniteCostChecks.cs` 和 Discovery 的文件 SHA-256 相同；修复前后的实际源码输入与 build-record 随各自输出保存，不能称为未修改的 f16551e 二进制测量。420 件物体，N=272/56/56，先240次预热，再60次确认成员、顺序、正文和冷准备稳定；随后600次 Update+Prepare。移动场景600次，在第300次增加一件箱子，不禁止必要的第二次排序。

## 文字与绘制

所有者在体验 `9728456` 后要求前 10 字、前 2 行及文字底边贴近物体顶部，并强调梳妆台尺寸不同；这是后续显示偏好，见 [#63 的调整记录](https://github.com/Kuroneko2020/JueMingR/issues/63#issuecomment-5650366560)。新数量只作为未保存配置的初值，旧合法数量原样读取，不作迁移。

默认宝箱橙色 FFA500、牌子 E6C16A、墓碑 FF5555，独立字号 70%，70 的默认不改变既有实体 90%。字号范围 50–180、步长 10。牌子/墓碑 Lines 默认 2、范围 1–10；Characters 默认 10、范围 1–1200。All 有最多 10 个实际排版行的护栏，省略号占护栏空间；Characters 按可见完整字符单位计数，颜色标记不计、图标计 1、换行不计，内部空行保留。

有界 lexer 只接受经过验证的原版常见颜色、物品标签，其余按字面显示。一个解析结果供截断、测量和绘制复用；颜色片段之间的组合字符不能被拆开，图标不可分。CRLF 规范为一个换行。基础换行宽度约 460×字号并受视口约束。逐完整单元测量/累积，禁止递增前缀的二次复杂度；长输入未消费部分不用扫描才能判定已经到达显示护栏。

原版 `ChatManager.ParseMessage` 用于已验证标签；缓存 `PositionedSnippet`，Draw 只调用接受该缓存的重载。禁止 Draw 调用 string/未布局 snippet 重载。图标资源取得与布局在游戏线程限额准备；原版 `UniqueDraw` 涉及 `inventoryScale`，外侧 `finally` 恢复。关闭 hover/click 行为。继续借用既有世界 SpriteBatch，禁止每标签 Begin/End 或创建纹理。

颜色仅以安全常量标签建立原版片段，再用 `CopyMorph` 放入已校验字面内容，避免原版正则把彩色正文内反斜杠当转义破坏。每行独立保留实际墨迹范围，内部空行影响行距但不替完全屏外正文占绘制名额；省略时整单元退回并同步可见字符计数。完整 Unicode 单位不被截断不等于原版字体拥有所有字形：原资源预览中部分 emoji 显示为原版后备星号，未新增字体或承诺 emoji 字形覆盖。

开启状态即使当前候选为零，也先比较字体/语言身份，再作空名单早退：旧字体下超宽的完整单元可能已进入拒绝缓存，新字体必须能恢复其资格。全部关闭仍在字体/布局工作前退出。该零候选恢复路径有宽字形度量反例与换回原 XNB 字体后的真实绘制检查，不依赖切模式或移动来偶然解锁。

贴边定位保留完整物体横向几何：2×2 箱子中心偏移16，3×2 梳妆台偏移24。正文在有界准备阶段复用 `UiTextMetrics` 的原版字形矩形和 Padding.Y，缓存每行上下边界；描边向下1.5不乘字号。Draw与可见资格使用相同底边，内部空行保留行距、尾空行不抬高可见文字，截断退回和省略号同步修订边界。度量类及其尺寸值从已有F5文件机械提取，F5/Notes度量语义不变；Draw不增加测量、纹理读取或资源创建。

原版物品片段保留原生占位；数量文字另按ItemStack字体与自身描边并入底边。`.8` 的私有 `_item` 字段仅在冷准备读取一次，借用原版已经钳制数量的Item，字段缺失走现有准备失败，不重复解析标签或创建第二件Item；缓存同时观察ItemStack字体身份。context14的数量底边为 `(17 + 字形OffsetY + Height) × UniqueDraw占位高度 / 32`。物品特效仍由原版拥有，该边界不承诺裁出所有动态特效或纹理的透明像素。

`bbfc3bf` 新增 `NativeTextAnchorChecks` 的实际ReLogic CPU回调覆盖字形Padding、50/70/180字号、尾空行/内部空行、省略号回退、屏边、2×2/3×2中心及原版Item数量边界；该历史候选图形因设备创建 `DeviceLostException` 延期。

所有者随后反馈首次进档有“绘制层不可用”但显示正常，并要求按新截图继续下调（[#63](https://github.com/Kuroneko2020/JueMingR/issues/63#issuecomment-5651318540)）。根因分开处理：

- 首次 Update 的一次 Runtime 交接可能先于原版 `SetupDrawInterfaceLayers` 完成。此前 bool 的 false 混淆“尚未建立”和“确实失败”；当前由原版层安装入口拥有 `Pending/Ready/Unavailable`，交接时空列表保持 Pending，只有完整 setup 失败才发布 Unavailable。三个世界绘制消费者同步接收状态；显名/附近目标只对确认失败提示、保留选择，恢复结束去重阶段。没有固定等待时间或永久吞掉故障。`NativeLayerReadinessChecks` 用独立构建的 Host、真实原版层类型和隔离已保存配置复现旧两句误提示，并覆盖新三态、重复反馈、失败/恢复/再失败。
- 格矩形顶并非物体可见顶。原版闭合箱子常有6像素顶端透明区、墙牌6像素、梳妆台0；墓碑原版绘制还下移2像素。`NativeWorldObjectBounds` 在 Host 保存当前 `.8` 已支持样式的有限可见边界表，正常取可见顶，倒重力取原可见底（箱子下排18高，通常底为34，不能统一减32）。正文及片段整体再下移1.5世界像素，普通正文底贴边，黑描边可搭在边缘上；梳妆台因此下移约2像素。字号不改变此偏移，zoom由现有世界层统一处理，屏边早退也包含下移后的描边。

本次实际图形环境可用，`NativeTextAnchorChecks` 用原 XNB 纹理读回的可见边界作独立 oracle，覆盖8组类型/样式、3字号和7种正文、墙牌/墓碑/换行/图标/倒重力；测试逐物体隔离像素，避免大字号长箱名污染邻居采样，同时保留组合预览。`ProbeGraphics.Scene` 同步真实箱子下排高度、墓碑偏移和梳妆台37样式换行。本次CPU、原资源GPU、Host组合和有限成本检查通过；这些不是实机FPS或多人、资源包与所有者视觉接受结论。固定表针对原版闭合帧，不逐帧追踪开盖/机关动画或替换资源；当前21/441仍只支持原有52样式，并非 `.8` 名称表全部54样式，本次不扩容。

上段绑定 `773411e` 的几何验证。所有者随后确认箱子和梳妆台位置正确，但所见告示牌仍不对，墓碑尚未看（[#63](https://github.com/Kuroneko2020/JueMingR/issues/63#issuecomment-5651850159)）。用同文“药水/食物/材料”的实际原资源预览复现：style1吊挂的全alpha顶是吊链，而牌面在下方，旧oracle同样把吊链当作顶而遗漏了问题。当前告示牌以**牌面**为贴边对象，剔除竖直吊链/支柱；容器、墓碑、共享排版与首次进档提示代码均不改变。

三种牌的 `.8` 安装样式依次为0落地、1吊挂、2左附、3右附、4壁挂（此前把2笼统叫墙挂不精确）。55/425牌面上下边界为 `{0,10,6,6,6}` / `{22,32,28,28,28}`；573为 `{4,14,6,6,8}` / `{22,32,30,30,26}`，下边界exclusive。55/425吊件占y0..9、牌面y10..31；落地牌y22起为支柱。573落地牌面保留y4..21的破损碎片，吊挂时同一板体下移10；y0..3、y22起的支柱及吊挂y0..13的吊绳不作板面。不是按宽度阈值裁掉细小碎片，也不是给所有牌子统一再加一个偏移。

回归先由已知牌面边界产生CPU红，再覆盖原文字、三字号、三类牌×五种安装方式×正常/反重力的实际GPU墨迹。`NativeSignAnchorChecks` 使用默认70字号、125% zoom；oracle从独立确认的原资源牌面ROI中读alpha，不读取生产表，保留整个物体的组合预览。既有全Native名字、记录、名额、热键/组合及有限成本检查继续通过；源码和测试通过不等于所有者对牌子、墓碑或多人已验收。

## 开过位置与持久化

观察独立于三个显示模式。正常本地玩家、有效会话、背包开启、非负世界 chest 索引、chestX/Y 对应当前 Chest 坐标、完整真实容器才形成事实；拒绝银行、hover、拒绝开箱、其他玩家和 `World.AutomaticOperation`。保持打开同一箱子只比较标量；新坐标才改变 revision，重复坐标不重复写，尚待提交的事实仍归提交 owner 管。

持久 pair 以已载入 `ActivePlayerFileData.Player` 与 `Main.LocalPlayer` 同一对象为前提，角色以 FileData.Path 加 local/cloud 存储域定位；世界以非空 WorldFileData.UniqueId 定位。普通客户端还要求当前连接正常入世，避免握手期旧 GUID。路径/GUID 只在 pair 变化时生成存储键，不逐帧哈希；不读取私人角色文件、显示名、服务器地址、保存时间或完整存档。角色真实文件位置是当前原版可取得的身份，不是角色 UUID：手动把不同角色替换到同一路径无法区分；本地/云移动会形成不同归属，首轮不自动迁移。

身份不足只影响该会话的持久资格，给有限提示，继续记录局部位置，不落到公共 unknown 文件。身份晚到只合并同一 session 的新事实。读取完成后按 pair 与 session/revision 合并，并把加载期间新开的位置保留；旧回调不能写进新世界。离世已接受提交由原 pair 完成，不换绑。

文件为 `JueMingRData/records/opened-containers/<pair-key>.json`，只含 format/version、pair 校验标识及去重左上角位置；不存物品/名称/时间线。单文件有合理容量上限，超限保护原文件并明确降级。后台执行解析、索引构建、合并及序列化；当前查询读已发布索引和本会话增量。Missing、损坏、未来 schema、读取失败、写失败、提交未确认分开，复用原子存储的保护/备份，不因坏文件写空替代。有限去重反馈，无逐开箱成功聊天。

正常写入采用 150 ms 合并窗口，连续新事实最多等待 1,000 ms 后提交；明确可重试失败仅追加 250/500 ms 两次退避，随后等待自然新机会，不永久忙轮询。被冻结并等待合并的会话索引必须随重试批次转交，成功后只退役本次实际覆盖的索引，不能因重试列表已有坐标而丢掉失败状态或永久占满 8 段额度。错误反馈按 pair 的原因转换去重，另一 pair 保存成功不消费旧 pair 的未领失败；同一容量阻塞阶段只发一次，正常重新准入才结束该阶段。原子提交未确认保持保护，不能直接重发或覆盖；退出只有有限等待，不保证强制终止/断电前未提交事实。
