# 笔记功能实现设计

本轮实现已获所有者在实际使用场景中的接受，随 [PR #43](https://github.com/Kuroneko2020/JueMingR/pull/43) 合并进入 `main`；固定接受对象与未覆盖范围见[接受边界](../功能介绍/笔记功能行为合同.md#已接受实现与验证边界)。

本文解释[笔记合同](../功能介绍/笔记功能行为合同.md) Q1～Q7 的实现职责和验证边界；动态进展见 [Issue #42](https://github.com/Kuroneko2020/JueMingR/issues/42)。沿用现有六个生产项目、一个晚期 Harmony 上下文和宿主线程，不建立第二运行内核。不导入 Legacy 数据；本轮兼容此前 R 候选的 schema 1 笔记。

## 内容、草稿和操作

本轮验收修订依据 #42 的所有者追加合同：在现有职责内增加编辑选区及每篇当前悬挂的阅读区域/字号偏好，替代首轮固定区域和无选区限制。样式由 F5 和 Notes 共用窄绘制能力；笔记排版、命令、确认和草稿仍归笔记。新增 UI 首次接入即复用当前样式，具体维护与接受边界见 F5 设计；不建立主题引擎。

编辑选区由 `NoteEditor` 的 anchor/caret 表达，两端始终位于完整字符边界。方向扩展只改选区，普通左右先收起到对应端；点击和视觉行导航沿同一行表定位。输入/粘贴/删除先构造并验证完整替换候选，再一次改变 Text/revision/边界和选区，失败保持原文本及选区。IME 预览不写入 Text，未确认前原选区保留，确认字符只调用同一替换事务；取消组合不删除原内容。剪切先复制选区成功后才删除，无选区不复制/剪切整篇。Host 拥有一次拖选捕获及有限边缘滚动，停止/隐藏/失焦立即结束捕获，不把释放尾部转给其它动作。

保存入口取当前编辑、Dirty/待确认组合与提交状态；取消编辑仅编辑存在时可见，提交期间结束编辑不表示撤回磁盘请求。删除完成按 command ID 与目标匹配，只有该目标可靠删除后才清除对应确认；旧完成不得清除另一个目标。取消编辑不清除尚未解决的存储异常。

`Features/Notes` 的不可变 `Notebook` 是同一数据根的唯一已提交事实：有序 `Note` 集合，每篇有稳定 GUID、标题、正文及悬挂位置/背景不透明度。数组顺序就是创建顺序；重名合法，重命名不换身份。新建、更新、删除、悬挂/取消、背景和拖动落点都是明确命令，成功持久提交后才替换事实。F5 和便签共同投影此快照，便签只读已保存正文。

`NotesWorkspace` 拥有当前编辑字段、草稿、删除确认和保存前置动作；`NoteEditor` 拥有文本、字素边界、光标与编辑 revision。会话草稿不是第二份已提交正文。一次仅一个字段，单击其它字段不切换；双击另一字段、内容空白、新建/悬挂/删除、切页、主动关闭先提交。点击“保存”及标题 Enter 在可靠成功后结束当前编辑并回到预览；正文 Enter 换行，Esc 取消。失败保留草稿并阻止后续动作。

后台完成结果含命令 ID。已提交结果总要更新事实，即使 UI 已隐藏；后续 UI 动作还须匹配编辑对象/revision 和交互 epoch。失焦、强制隐藏、取消使后续动作失效，不自动重放。保存进行时不接收第二条领域命令，但编辑可以继续；迟到成功只推进该次提交的基线，不能覆盖新草稿。新的 IME 预览、候选或尚未配对的代理项不增加文本 revision，但会使同一编辑的旧保存后续动作失效；保存入口及标题 Enter 在组字完成后仍有未决输入时暂不结束编辑。删除确认离页/关闭/隐藏时清除，同次失败可留确认重试。

## 存储和失败恢复

唯一正式文件为 `<已验证 Terraria.exe 目录>/JueMingRData/notes/notes.json`，UTF-8 无 BOM JSON，当前写入 schema 2、兼容读取 schema 1，根字段 `schema`、`notes`。schema 2 每篇完整包含 `id/title/body/pinned/x/y/opacity/readingWidth/fontPercent`；位置是独立屏幕像素坐标，背景不透明度整数 0～100。没有外部正文文件，合法空集合必须是完整的 `notes: []`，不存在部分索引/正文事务。

读取严格区分正式文件不存在、合法空集合、缺字段/重复字段或 ID/坏格式、未知 schema、未知字段、超限、I/O 和另一写入者。正式文件不存在但精确 `.bak`、`.tmp` 或 `.schema1-original` 存在时视为需恢复，拒绝默认空写入；不扫描目录、不猜最新版本。未知或未可靠读取的原件不能自动重写。正文不做容错降空或静默截断。

现有配置 `PreferenceDocument` 只表达内存偏好、覆盖合并和失败后仅本次有效，不能承载笔记保存前置。机械文件核心从 `FilePreferenceStorage` 提取到 `AtomicFileDocument`，原配置保留 64 KiB 及原行为。笔记使用明确文档上限和恢复材料保护；复用已有 opaque byte storage port，不给每篇创建存储实例。

一个 `DocumentWorker<T>` 负责一个一致性单元的读取、编码和串行 I/O。最多一个已接受命令（含未领取结果）；无覆盖槽、不合并不同操作、不常驻每篇线程。游戏线程只提交不可变候选并领取结果，Draw/输入不读写、哈希、序列化或等待。普通退出拒绝新命令并在有限预算内尽量排空，worker 的 finally 负责释放文件 lease；未实际停止不能清理测试根。尚未提交草稿不承诺跨崩溃恢复。

文件写入使用同目录 `CreateNew .tmp`、完整写入/Flush/readback、初建不覆盖 Move、替换前身份检查及 Replace。成功必须核对正式候选和实际被替换的 `.bak`。只有完整可靠结果才推进内存事实。一个 `.bak` 保留上次实际内容，一个 `.tmp` 保留未确定候选；不清理不属于本次的材料。已知提交前、且自有临时材料可清理的 I/O 失败允许重试；外部变化、提交后不确定性或恢复材料冲突锁定保护，不能用重试轮换掉唯一备份。

稳定 `.lock` 在实例生命周期内排除合作写入者；替换时读句柄禁止普通原位写。Windows delete sharing 无法排除不合作程序原子 rename，故不是任意文件系统 CAS：若实际替换来源不符，正式路径可能已改变，保存必须报冲突并保留真实 `.bak`。此时退出所有同安装游戏，复制整个 notes 目录，检查正式文件/备份/候选，人工选择完整文档后重启；不自动覆盖原件或恢复旧快照。安装、恢复和重置 config 都不删除 notes。


schema 1 只有在整份可靠解码后才允许升级。加载本身不写文件；第一次真实提交前，机械存储把准确原始字节写入同目录 `notes.json.schema1-original` 并 Flush/readback 验证，再执行原有原子提交。该档案不随 `.bak` 轮换，不覆盖不同原件，既有档案冲突或留存失败阻止升级。未知/损坏/缺字段文件不会进入这条路径。程序安装不提前读写转换真实 Notes；回退 DLL 不会降级 schema 2 或自动用旧档案覆盖后来编辑，旧程序可能拒绝新格式，应保留整个目录并使用匹配程序或由人明确选择恢复副本。

阅读调整由 `NotesFeature` 拥有每篇至多一个最新意图，正文仍只来自当前可信 `Saved`。滚轮只改预览意图，不调用编辑保存门，不逐格复制/编码整本，也不丢弃 worker 忙时的最后值。静止 250 ms 或当前未提交批次达到 1 s 后，空闲 worker 合并一次；已进入批次后的新调整重新起算时限。可靠完成只确认对应批次，较晚意图保留；普通内容命令优先，下一阅读批次基于其最新成功结果。失败保留预览及错误，停止自动重试；新调整可重试，成功取消/删除对应悬挂才清理其意图。每次悬挂有仅进程内的身份，旧完成不得让已取消/删除/重挂的偏好复活。

正常退出在 750 ms 总预算内冻结已接受的阅读意图，在进行中命令可靠成功后基于 worker 的最后成功正文尽力保存；此前写入失败时不追加旧快照覆盖。退出不读取活动 Editor 或 Terraria 状态，不写未提交正文草稿；强制结束及超时不承诺未落盘调整恢复。源格式档案、普通备份、最后可信内存和未落盘预览是不同证据。

## 规模与成本

保护上限按单位分开：标题 80 个编辑字素；单篇正文 1,048,576 UTF-16 code units；最多 1,024 篇；schema 1 原件仍限 16 MiB，schema 2 编码文档最多 16 MiB + 64 KiB。额外 64 KiB 只为最多 1,024 篇的新元数据留出兼容余量，避免合法旧上限文件因新增字段无法升级。它们是 x86 进程内完整快照、一次活动排版和整文档提交的资源护栏，不是建议日常写到上限。超限新增/粘贴整次拒绝并说明，读取超限整份保护，绝不截正文。聚合上限在后台编码后检查，输入阶段只做相应字段/字符检查。

另设单个组合字素最多 1,024 UTF-16 单位。原因是“基字符 + 百万个结合标记”仍可能只有一个编辑字素，只数每批几个字素无法约束单次字体度量/绘制。这个资源保护远超过代表性组合 emoji 的规模；不是将正常正文改成短文本。超过时整次拒绝输入、整份保护读入文件，不保存前缀。零宽字形也可能形成超长视觉行，所以视觉行在完整字素边界累计最多 1,024 UTF-16 单位后折行；只改变显示折行，不插入换行或删改保存内容。

提交会编码整份文档，成本随聚合正文增长；未改正文及验证索引共享，位置和透明度操作不重扫正文。普通逐 UTF-16 单位分段的文本使用隐式索引，避免每份快照保存正文四倍大小的整数数组。复杂字素使用已验证索引；活动编辑只重分段变化附近，区域旗帜配对变化延伸至相邻连续段结束；Dirty 在修改或保存完成时更新，不逐帧比较整篇。

长正文布局只保留可见卡片/便签与活动编辑版本；短正文的有界高度缓存保留，防止离屏短卡片每帧重建而饿死可见长文。所有布局共用每次准备最多 8,192 UTF-16 单位与约 2 ms 的推进目标，每个不可分步最多 1,024 单位；时间检查不含 GC/系统停顿等，不能当作硬实时或 FPS 保证。已出现的可见正文优先取得一部分预算，便签轮转起点，完成后无变化不再推进。行表和度量以分块方式共享未改前缀，密集换行正文的尾改也不复制百万行引用。

未排完显示“正在排版”，保留请求的阅读位置，不把临时高度当完整高度反复夹回。未完成行不伪造点击位置；视觉导航可等待同一编辑对象/revision/caret 的行，编辑或切换后旧等待失效。布局最终完成再夹紧真实滚动范围，光标定位只在编辑变化/等待完成时调整，手工阅读滚动取消该次待定位。图形按裁剪后的可见行绘制，旧长文本不进入 F5 固定标签字典。合成短长文、多篇、上限读写与停止测试记录实际工作量和时间，不把 wall-clock 或静态形态称为 FPS 结论。

## 文本和宿主输入

当前目标为加载链验证的 Terraria 1.4.5.8 / ReLogic。定向当前二进制确认原生 `keyCount/keyString/keyInt` 队列由 IME listener 写入；Host 消费已提交字符，组合预览通过 `IImeService.CompositionString` 单独显示。不用 `Main.GetInputText` 的末尾追加、Ctrl+Z 清空和聊天标签删除路径。

文本 lease 在既有输入 Hook 的最小 prefix/postfix 中仲裁。聊天、sign/chest、原版弹层、非自身文本 owner、失焦等优先。仅自身编辑时设 `WritingText`/自有 sentinel/必要 blockInput，处理本帧已采样游戏键；别人接管时不关闭其 IME 或清其队列，但必须归还本功能先前借入的 blockInput。消费后的原始 keyState 不在更新后恢复，避免下一帧早期快捷键重播。普通字段切换也清除旧编辑的延迟导航和半代理项。

`Main.HandleIME` 是当前 .8 的实例方法；停用可能同步触发 FinalizeString，明确保存前先将完成字符写入仍绑定的旧草稿，再冻结提交；明确取消丢弃完成队列。不能先解绑再让尾字串入新字段。跨样本 WM_CHAR 代理对只在同一编辑中合并。组合或候选在本帧/上一帧任一有效时，Enter/Esc 优先交给 IME；确认键按住的尾部不提交/取消编辑。真实 Windows IME 的事件时序仍由实机验收覆盖。

剪贴板用 Windows 原生成功/失败返回的窄适配，单次访问失败立即反馈、不阻塞等待重试；复制成功前不剪切正文。自动测试只用隔离剪贴板替身，不访问真实内容。Ctrl+Z 保持草稿。

net472 的 StringInfo 不能直接保证组合 emoji 的扩展字素边界，见 [Microsoft 说明](https://learn.microsoft.com/en-us/dotnet/core/compatibility/globalization/5.0/uax29-compliant-grapheme-enumeration)。本实现按 [UAX #29](https://unicode.org/reports/tr29/) 的必要规则保守组合代理对、结合标记、变体选择符、emoji 肤色/标签、区域旗帜对、ZWJ 序列、Hangul 和 CRLF；测试中文、组合重音及代表性 emoji。不是宣称通过所有 Unicode 版本或字体塑形测试。边界数组供插入、删除、左右及逐行导航共享；实际字体缺字是显示能力限制，不改变保存的字符。

排版把字素分组和真实字体度量组合成视觉行。绘制、点击、光标、上下/Home/End 共用同一行表；只在编辑/光标/视口变化后保持光标可见，阅读滚轮不被逐帧重置。标题也按完整行和光标呈现，不能只省略尾部。正文直接字面 DrawString，不调用 ChatManager。

## 卡片、便签、坐标和生命周期

#46 本次授权将失焦与正常关闭分开：`HostInputState` 的本帧真实前台许可同时提供给 F5、卡片及便签。失焦立即取消 armed 控件和未完成便签拖动，恢复拖动前投影，不发送 `Position`；重新激活的按住/松开不能执行旧关闭按钮或保存动作。仅释放本功能输入租约并保留会话草稿，已经发出的可靠保存仍按原命令身份接收完成；不清他人的聊天、文本队列或 IME。实现与实机验收状态以 #46 为准。

F5 原窗口状态继续拥有窗口拖动、页滚动及总指针门，笔记卡片负责页面内字段、按钮和独立正文滚动。主动离开经过保存门；强制隐藏释放输入并保留会话草稿。页面内容采用卡片排列，短标题按实际行数收紧，多行标题预览至多两行、编辑至多四行并保留滚动；新增入口常驻，保存仅在当前编辑有修改/待确认组合或提交期间出现，取消编辑仅编辑存在时出现；两段删除不会把悬挂内容先移除再等失败回滚。

悬挂默认区域 280×304 屏幕像素、正文字号 120%，独立于 F5 UI scale。Shift+滚轮每格改变宽度 40，范围 240～560，高度按 304/280 比例取整（261～608）；Ctrl+滚轮每格改变正文 10 个百分点，范围 80%～180%。字号和区域分别调整，工具栏不随正文字号缩小。实际行高同时覆盖当前字形高度、行距和描边；字体或小屏幕需要时临时投影区域，绝不反写用户偏好。默认透明背景，文字和工具保持自身不透明度；悬停显示“按住拖动”、`<`、`>`、`×` 及对应短帮助；拖动把手不另显示帮助。工具栏位于实际窗口内部，主窗口和悬挂窗口共用紧凑控件：常规最低高度 28 像素，保持原文字比例并按实际字形高度加 8、宽度加 10 留边，大字形按需撑开。拖动按钮按文字宽度显示，三个工具靠右，中间空白不响应拖动；正文避开工具栏和独立的底部提示区；提示区按当前字体和宽度固定预留帮助/错误所需高度，悬停与错误出现不改变正文几何或滚动范围。正文滚动到底时末行完整位于提示区上方，绘制和命中共用矩形，不保留窗口外隐形命中条。箭头以 5 增减背景不透明度并在 0～100 夹住，相同值不写；重复已悬挂保持不变，可靠取消后重新悬挂才重置位置、区域、字号和默认透明度。保持悬挂正常退出再启动恢复最后可靠保存的偏好。位置随可用视口投影夹紧，但仅用户真实拖动完成或正常关闭中断时持久化最后有效位置；失焦取消未完成拖动并恢复拖动前显示位置，不因窗口变化偷偷改文档。保存立即拒绝时立即恢复可信位置，异步失败后恢复已保存投影；F5 关闭时也有必要失败提示。

多张便签逆绘制序唯一命中；F5 窗口、文本编辑/IME、拖选及其释放尾部优先。拖动中不调阅读参数；Shift 与 Ctrl 同按只消费滚轮，不调整任何值；单一修饰键在限值处也消费滚轮。鼠标释放尾部和已消费滚轮不恢复给热栏，滚动边界也消费。只有把手能开始拖；页面滚动、正文滚动、便签滚动互不代替。当前视口/缩放变化或输入所有者中断结束拖动，保留最后有效落点。F5 关闭时独立便签资源仍存活；资源不可用/绘制失败立即关闭其输入门，且不 dispose 原版共享纹理字体。
