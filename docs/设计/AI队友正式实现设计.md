# AI 队友正式实现设计

本设计涵盖已授权的首批 S0–S5 及管理界面演进；产品版本由根 Directory.Build.props 承载。用户行为见[功能合同](../功能介绍/AI队友功能行为合同.md)。源码存在、编译和自动检查分别只证明其实际范围；Steam 双机、游戏效果和 FPS 仍由所有者操作确认。

AI 专项开发中有复用价值的中间数据、样本、实验输出和经验可以直接保留到 `references/AI队友`，按现有目录及 [README](../../references/AI队友/README.md) 按需提供发现入口，简要注明来源、版本、用途和已验／未验边界，尤其保留能够支撑后续判断的原始中间数据。不要求复制所有临时日志、逐文件登记或新增永久校验门。该目录持久保留且由 Git 忽略，不成为编译／运行／分发依赖；正式合同、设计和当前任务授权仍由原有权威入口承担。

## 角色、资源与生命周期

每个人物拥有稳定 Guid、创建者关联、行为设置和完整原版人物序列化数据。名字、玩家槽位、世界坐标均不是永久身份。创建者映射绑定真实人物文件记录，改名不产生新档；人物资源跨世界延续。首次创建使用对应难度的原版默认人物，重新加入、复活不发新手物资。

Feature 拥有档案及行为语义；Infrastructure 只在游戏安装根下的 JueMingRData 中读写自有字节；Host 在游戏线程捕获原版人物、执行真实物品操作。后台不得接触 Player/Item/Main。原版序列化中真人鼠标、制作退款和临时界面槽必须在显式队友保存范围分流，不能调用全局 SavePlayer 冒充队友保存。

当前实例绑定人物 Guid、世界会话与 activation generation，独占原生 Player、连接及动作。槽位仅为本次映射；同一档案不能同时激活两具可产出物资的身体。收回停止新动作并捕获一致人物快照，立即退役自身连接和身体；活化保留到该修订成功保存，避免另开身体复制资源。保存失败保留唯一最新内存状态并显示原因，不自动从旧磁盘恢复或重置。

连接失败与主动收回共用停止动作、关闭流和退役槽位的出口，但失败原因独立保留；后台保存完成后仍显示原服务器或本地终止原因。捕获最新身体本身失败时，旧修订已保存不代表本次收尾已保存；保留唯一最新身体及 activation，并由现有重试入口重新捕获。只有本次收尾快照已受理且相应保存完成后才释放 activation，不自动重连。

### 创建草稿与终局

创建由独立 CompanionCreationSession 持有真实主人、世界/session token、未入档的 Player 草稿及原版 UICharacterCreation／UIVirtualKeyboard，放在 Main.InGameUI 的原生模态页面，不由管理窗口关闭动作销毁会话，不改 Main.PendingPlayer 或游戏菜单。构造前后保留世界默认难度；私有发型 helper 与静态 dirty 只在构造及本会话所属 UserInterface.Update／Draw 栈交换并 finally 归还，覆盖按钮派发。原版命名、确认、返回出口按精确实例门控；过期实例和键盘回调不能写普通人物／收藏或重提草稿。真正确认只经 HostCompanions.CreateDraft 防重复、原生初始化一次、Capture 和 manager 入档，试穿装备不复制进资源。接受 Guid 与首次 worker 发布是两个状态，回管理先保留 pending 创建身份，不让旧名单首人覆盖；未保存修订不能激活。取消命名回同一创建页，真正取消回管理；可信输入失效清本轮 native LastDown 而保留草稿，物理尾沿现 HostInputState 中立归还。原版预览仅触及独立草稿，受限外观阶段及私有 RNG／共享 shader 有 finally 收尾；外围按实际视口夹取，内部控件不重建另一套皮肤。明确 Reset 保留难度／外观／声音，重建资源并递增 DataEpoch；恢复行为仅改偏好。

自有档案格式 v3 将 AutoRespawn、手选槽/type/prefix、PermanentlyDead、NativeData、身份及偏好同次原子保存。v1/v2 继续读取，自动复活默认开启、未指定武器；v1 默认非终局，v2 保留终局，不在读取时自动升级。Clone、行为 revise 和 UI 单字段编辑完整保留其他设置。Join、Attach 和 manager.TryReserve 均尊重终局。原版 KillMe 的 DropItems／HardcoreDeathPenalty 继续执行；只在 KillMeForGood 精确命中本 Host 的身体时跳过其读取真人 Main.playerPathName／ActivePlayerFileData 的删除出口，标记该 activation 已到终局。原生 surviveHardcoreDeath 扣除 60 基础生命仍大于零时不进入此出口，保留合法复活。

终局沿同一 CloseActor 停止并退役身体；先发布不可再激活的档案标记，再捕获最终原生资源。捕获失败仍保留 Closing、唯一最新身体及 activation，显式重试只重新捕获，不重新执行死亡／掉落。普通定时保存、行为更新和收回保留终局标记，只有明确破坏性 Reset 可创建新的非终局 DataEpoch。真人及非本 Host 身体仍走原版删除语义。

自动复活沿真实身体的 respawnTimer 与原生 AfterBody／Spawn 出口：关闭不请求原生跳过或自动 Spawn，仍推进原生死亡状态；再次开启继续当前计时，永久终局优先。状态标签按在役真实 timer 转秒显示，暂停不偷减、不改档案 revision。手选只保存本人物有限槽和物品 type/prefix，在显式 Alt 选择、加载后的合法 Spawn／复活转换应用；不每帧强制 Select，不复制库存或自动搜索最佳武器。已知物品提交和真实资源变化后只核该偏好槽，移走／替换／耗尽即退出失效指定。

## 管理窗口与物品事务

管理窗按内容首选尺寸和实际视口夹取，维持同一逻辑布局及左右独立滚动。名单双状态分开：当前选中用四条内侧居中绿色短线，已加入用错位长下划线，死亡／连接中不以资源资格冒充离役。头像按原生头部 DrawData／纹理帧可见边界居中，有限缓存随资源和外观失效，关闭清借用纹理。两侧姓名、人物／生命／魔力头部共享高度与基线，紧凑饰品／时装／装备 tabs 按自然字宽夹在本列；主 tabs 位于标题右侧。装备、背包、钱弹以实际槽外接细线分组和统一边距，空槽复用 Extra54 真实帧（染料1、时装饰品2、生效饰品11），钱弹文字居中。数量和持物草稿使用原生 ItemStack 字体及局部采样，保留完整数字。心星每行10段并沿原版连续框／填充几何，六个原生样式及真实数值不截断。离线卡片用已保存当前值和基础上限，不重演装备／buff。身份、DataEpoch 或真实命中几何改变才退休旧按下；普通状态、数量、倒计时和保存进度局部刷新。设置／保存失败按钮有无改变需要重投影时，只保留同 key/epoch/rect 且仍可用的当前按下，不设置点击冷却。

人物预览由窗口持有自己的 Player 显示副本，按外观变化更新；重建该副本的 selectedItemState，不借真实人物的选择状态。只准备明确视觉字段、染料及受控 CCed 早退前的原生外观阶段，不额外执行真实身体的 Player.Update／PlayerFrame／装备结算，不复制会产生粒子的仿真状态。预览用自己的随机源、原生 socialIgnoreLight 分支和固定姿态，finally 归还临借 RNG／共享 Mount shader。全身绘制使用原生 SpriteDrawBuffer 的 UI 变换，头像使用其要求的 SpriteBatch；两者各按实际原生出口恢复外层绘制状态，并在自己的区域裁切。关闭窗口释放显示副本并停止相关准备。

窗口物品草稿只持有本次触及槽位的身份、基线与预览，真实物品留在原库存；不占 Main.mouseItem 或 slot58。只有光标为空且整条拿取链平衡时，才在游戏线程重验人物／会话／generation、相关槽位、双向原生合法性及实际用物保护，一次替换全部触及槽。Shift 是完整平衡事务。未提交草稿在关闭、切页／切人、失焦、死亡和依赖变化时撤销，已完成事务不回滚。

提交后 HostItems 按真正变化槽退休自动存放取得证据、物品观察和材料准备职责，不清别人的 Store／Use owner。双方装备、染料和特殊装备按各自原生槽 ID 同步；保存或同步失败保留最新真实状态，重试只补捕获／发送，不重做物品转移，也不等待不存在的通用服务器 ACK。稳定无草稿时不扫描交易；活动草稿只验证自己的有限依赖。

快捷丢弃按当前原版有效 Ctrl／Shift 配置，一次点击只选丢弃或 Shift 交接。OwnerTrash 是真实主人 trashItem 标量端点，与数组端点同线程准备、双端重验、短写入提交，不能用临时数组代替。主人与 AI 合法来源都只去真人垃圾桶，收藏／用物／材料及 OwnerOperations.DiscardBlocked 初受理和终提交均保护；已有持物草稿拒绝冲突。旧垃圾被本次替换是明确丢弃语义，原生研究仅提交后真人身份执行一次。主人数组通知和垃圾标量后处理分开；垃圾5走主连接，AI来源5走自身连接，保存／发送失败只补后处理，不重放扣减／旧垃圾销毁。

## 原生执行与输入

原版 Player.Update 循环负责每具身体每游戏步唯一一次物理推进；Host 在该身体实际消费者前合成移动、跳跃、选物、瞄准和用物，返回后读取真实结果。不会从常规 Tick 再调用一遍完整 Update，也不为每名队友重跑 NPC/射弹世界。

队友只借用已确认同步原生消费者所需的角色与鼠标上下文，成对保存恢复，异常也必须恢复。真人及别人的网络队友保持原入口。死亡保存、鼠标物品和地图副作用按当前显式角色分流；原生伤害、耗材、掉落、复活计时继续执行。

真人 session 来源是原版发布的 Main.ActivePlayerFileData.Player。ItemSessionProbe 的活跃资格、token 与死亡记录都共用该来源，不回退到可能临借 AI 的 Main.LocalPlayer；缺活动人物文件按未就绪处理。真人 Player／world／socket／netMode 的真实变化仍换 token 并结束旧会话，普通死亡不换真人。AI Hurt／KillMe scope 只服务原生消费者身份，不能污染公共 runtime 并错误停止 Journey、收回另一 AI；验证须包含死亡后公共 UpdateRuntime，不能只推进 Host/Player。

UpdateBuffs、其后实际 UpdateLuck 与 Update 中独立的到期 DelBuff 分支取得本身体资格；不扩大整个 Player.Update 的本地身份，也不从 Host 再补跑 Buff。原版不递减标志、药水病及冷却回填继续由原消费者执行。每次 activation 持有自己的 MinionRespawner，真实 KillMe 的 CollectMinionsFor 定向收集，合法复活后在窄角色范围执行原生 RestoreMinions。真人静态恢复记录保持原归属；收回、退役和换世界清理对应临时记录。

角色 scope 中全屏地图输入为 false，退出恢复进入前的精确值。AI 连枷因此只响应自己的 channel、死亡和终止条件；真人开图及自己连枷的原生终止仍走真人入口。棱镜 PointInView 使用本帧 RotatedRelativePoint(MountedCenter)，不以随后已移动的射弹 Center 代替原生转向原点。

跟随与攻击分别占移动与用物通道，可并行。UI、重规划、可选预测预算不足不能令全队停步停火。地形或物品变化仅撤销依赖它的动作。原版真正暂停世界仍暂停身体。

新移动规划按真实世界步在可行动角色间独立轮转，同一步重复更新不重选，停火角色仍可取得规划机会；死亡、退役或失效身体不占活体轮次。该选择用于行为决策、导航新轨迹及目标刷新，与瞄准增强的机会选择分开。持续开火不扣留其他角色的移动机会，昂贵多步 walk 找地／drop／jump 的 cache miss 共享该轮转资格；未轮到只延后相关新查询，普通即时前缀、已有合法轨迹、真实 Update 与攻击继续。几何按 TileCollision→推进局部位置→SlopeCollision，保留校正位置／速度／接触，查询 finally 归还八项 Collision scratch；有限已加载非 null 足迹禁止物化未知 Tile。平台／stairFall／起点初速／能力／世界和真实读格依赖绑定成功及已知失败缓存，Unknown不当稳定失败；真实落地退休旧跳跃方向。Debug 有限工作量计数只供隔离测试，普通 Release 不含该采集，不据此签 FPS。

## 网络与共享世界

队伍唯一值是 native Player.team（无队白色及五种原版队伍），离线受控读取最新 NativeData 改队／捕获，在役按 owner/world/profile/activation 改身体并保存；恢复行为默认不改原生队伍。握手8／出生12携带保存值，显式改队通过该 AI 自己连接的原生45发布。最新待发意图绑定 actor、session、activation 和连接，合法同身体死亡换代才受控承接；旧连接／重用槽不能投新 actor。primary 自有45／157回声不覆盖新意图，其他玩家照原版消费。主连接不可发送或自身流已结束时保留／退役相应意图，只有原生出口实际被字节传输接受才清 pending，绝不将返回视为服务器 ACK；有限重试不重做状态变更。

单人直接附着额外原生身体。TCP 使用当前真人连接的实际地址和端口，每人物独立连接；不复制真人 HostToken。接入、密码、独立槽、初始化、就绪、关闭为该连接状态，密码不进入档案和日志。

额外连接在后台仅处理有界字节流，原生解码与 Main 写入在游戏线程。接入与资源回执由该连接消费。地形固定由真人主连接唯一原生解码；按队友所需区域合并原生8请求，已载区块不重复请求，每外层更新最多请求一个新区域。159不会强制重发服务器已标记发送的区块，不能作为换源基线。

初始 23/54 在 49/129 之前各按 NPC 槽保留最后一份原帧，23 另保留真实接收时刻，容量受原生槽数约束。世界身份校验、原生出生及初始枚举完成后，首次 Ready 提交一次到全队观察表并清空缓冲；不等待以后碰巧再发更新，也不改写真人 NPC 表。

来源记录不等于已消费基线：只有实际成功解码进共享观察表的 23 才完成基线，Ready 前因无角色需要而过滤的主流帧不能阻断首次副流基线。主动按兴趣回收观察时撤销此消费标记；已解码的原生 inactive 状态仍是合法基线。54 按同流先前 23 归属，缓冲中的 23 换代清掉旧 54，避免给新身份拼接旧增益。

首次进入或同一在役身体返回已加载地形都需要 NPC 基线。真实远处23在首次解码前被过滤时，只按原生槽记最后实际位置候选，不创建NPC、不伪造revision或NpcBaseline；身体首次进入该候选兴趣区域，也按外到内边沿合并到来源的既有154→8→23/54→49通道。曾消费后因全队离开而退役的观察沿同一通道恢复；不重新 Join/Ready，不假重载地形。仍有另一身体需要时不退休。真实 49 只结束对应有序枚举；移出兴趣而过滤的 NPC、枚举确认缺席的槽也结束该轮恢复，不按旧位置每帧重发全量请求。

真人始终保留原生NPC表及其23/28/162顺序。全队另有一份必要区域的共享NPC观察表，使用原生NPC消息解码，但观察解码不扣真人pending、不重复显示命中文字/生成视觉与出生回调。AI身体NPC接触、用物/近战/直接伤害及所属射弹在各自同步消费者期间切入这份表，正常返回与异常均归还真人表；不改整段Player.Update的真人输入身份。观察表不运行第二个完整NPC.Update/AI、掉落或DOT伤害；必要本地接触/移动阶段允许从默认值与自身历史继续进入下一挥击或起跳，原生增益标志/计时与按玩家槽分列的免疫在真实世界更新阶段全队只推进一次。无在线身体时释放此表及区域来源引用。

23 的观察副本仍由原生方法创建与换代，但仅在当前观察解码的精确槽、且 Main.npc 确为共享观察表时跳过 ResetNPCSlotData。该方法清理的是真人世界射弹 local/static immunity、玩家近战冷却/标签、Portal 冷却与全局 boss 槽索引，不是新 NPC 自身字段。观察 OnSpawn 继续隔离；真人原生出生、换代及其他槽清理照常执行。

## 计算和关闭
