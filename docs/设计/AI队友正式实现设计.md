# AI 队友正式实现设计

本设计对应所有者 2026-11-15 授权的首批 S0–S5，当前产品版本保持 0.1.6。用户行为见[功能合同](../功能介绍/AI队友功能行为合同.md)。源码存在、编译和自动检查分别只证明其实际范围；Steam 双机、游戏效果和 FPS 仍由所有者操作确认。

## 角色、资源与生命周期

每个人物拥有稳定 Guid、创建者关联、行为设置和完整原版人物序列化数据。名字、玩家槽位、世界坐标均不是永久身份。创建者映射绑定真实人物文件记录，改名不产生新档；人物资源跨世界延续。首次创建使用对应难度的原版默认人物，重新加入、复活不发新手物资。

Feature 拥有档案及行为语义；Infrastructure 只在游戏安装根下的 JueMingRData 中读写自有字节；Host 在游戏线程捕获原版人物、执行真实物品操作。后台不得接触 Player/Item/Main。原版序列化中真人鼠标、制作退款和临时界面槽必须在显式队友保存范围分流，不能调用全局 SavePlayer 冒充队友保存。

当前实例绑定人物 Guid、世界会话与 activation generation，独占原生 Player、连接及动作。槽位仅为本次映射；同一档案不能同时激活两具可产出物资的身体。收回停止新动作并捕获一致人物快照，立即退役自身连接和身体；活化保留到该修订成功保存，避免另开身体复制资源。保存失败保留唯一最新内存状态并显示原因，不自动从旧磁盘恢复或重置。

连接失败与主动收回共用停止动作、关闭流和退役槽位的出口，但失败原因独立保留；后台保存完成后仍显示原服务器或本地终止原因。捕获最新身体本身失败时，旧修订已保存不代表本次收尾已保存；保留唯一最新身体及 activation，并由现有重试入口重新捕获。只有本次收尾快照已受理且相应保存完成后才释放 activation，不自动重连。

## 原生执行与输入

原版 Player.Update 循环负责每具身体每游戏步唯一一次物理推进；Host 在该身体实际消费者前合成移动、跳跃、选物、瞄准和用物，返回后读取真实结果。不会从常规 Tick 再调用一遍完整 Update，也不为每名队友重跑 NPC/射弹世界。

队友只借用已确认同步原生消费者所需的角色与鼠标上下文，成对保存恢复，异常也必须恢复。真人及别人的网络队友保持原入口。死亡保存、鼠标物品和地图副作用按当前显式角色分流；原生伤害、耗材、掉落、复活计时继续执行。

UpdateBuffs、其后实际 UpdateLuck 与 Update 中独立的到期 DelBuff 分支取得本身体资格；不扩大整个 Player.Update 的本地身份，也不从 Host 再补跑 Buff。原版不递减标志、药水病及冷却回填继续由原消费者执行。每次 activation 持有自己的 MinionRespawner，真实 KillMe 的 CollectMinionsFor 定向收集，合法复活后在窄角色范围执行原生 RestoreMinions。真人静态恢复记录保持原归属；收回、退役和换世界清理对应临时记录。

角色 scope 中全屏地图输入为 false，退出恢复进入前的精确值。AI 连枷因此只响应自己的 channel、死亡和终止条件；真人开图及自己连枷的原生终止仍走真人入口。棱镜 PointInView 使用本帧 RotatedRelativePoint(MountedCenter)，不以随后已移动的射弹 Center 代替原生转向原点。

跟随与攻击分别占移动与用物通道，可并行。UI、重规划、可选预测预算不足不能令全队停步停火。地形或物品变化仅撤销依赖它的动作。原版真正暂停世界仍暂停身体。

## 网络与共享世界

单人直接附着额外原生身体。TCP 使用当前真人连接的实际地址和端口，每人物独立连接；不复制真人 HostToken。接入、密码、独立槽、初始化、就绪、关闭为该连接状态，密码不进入档案和日志。

额外连接在后台仅处理有界字节流，原生解码与 Main 写入在游戏线程。接入与资源回执由该连接消费。地形固定由真人主连接唯一原生解码；按队友所需区域合并原生8请求，已载区块不重复请求，每外层更新最多请求一个新区域。159不会强制重发服务器已标记发送的区块，不能作为换源基线。

初始 23/54 在 49/129 之前各按 NPC 槽保留最后一份原帧，23 另保留真实接收时刻，容量受原生槽数约束。世界身份校验、原生出生及初始枚举完成后，首次 Ready 提交一次到全队观察表并清空缓冲；不等待以后碰巧再发更新，也不改写真人 NPC 表。

真人始终保留原生NPC表及其23/28/162顺序。全队另有一份必要区域的共享NPC观察表，使用原生NPC消息解码，但观察解码不扣真人pending、不重复显示命中文字/生成视觉与出生回调。AI身体NPC接触、用物/近战/直接伤害及所属射弹在各自同步消费者期间切入这份表，正常返回与异常均归还真人表；不改整段Player.Update的真人输入身份。观察表不运行另一套NPC.AI、掉落或DOT伤害；原生增益标志/计时与按玩家槽分列的免疫在真实世界更新阶段全队只推进一次。无在线身体时释放此表及区域来源引用。

AI观察来源变更只冻结受影响NPC/射弹，154仅提供同流因果屏障，其后仍需真实23/27基线。NPC通过原生8枚举/49终止取得新活体基线，缺席旧槽才退役；Pending连接失效可改选。同身份射弹换源等待新基线；新generation的首个完整27立即接入并退役旧精确key，不丢弃唯一出生包。29由主连接唯一处理，即使换源等待也终结该精确key，迟到同key的27不能复活旧弹。真人原消息不等待这些AI屏障。

真人主流的合法 27 一旦接管该精确 key，后续仅由主流 FIFO 更新该对象，副流迟包不能覆写；该次原生消费不等待 AI 换源 pong。队友射弹实际 Projectile.Update 同步尾只为当前 key/activation 补齐 owner 资格，原 SendData27 经该身体连接输出；netSpam、extraUpdates、netUpdate 清除及终止仍归原生尾，不逐帧补发稳定射弹。

共享观察在原版NPC世界阶段之后全队推进一次：沿原生重力/碰撞和netOffset衰减语义推进必要几何与计时，不运行另一套AI或产生世界结果。新23的AI阶段有自己的观测时刻；已有预测时间线保持该时刻，按真实age消费并复核代次、目标、环境及地形租约，不能把旧AI阶段重标成当前样本。仍有效的结果不会仅因相邻帧没有新23而丢弃。

接收于 T 的未推进原始样本在下一玩家阶段 T+1 可首次捕获，已经被几何推进的同一修订不能冒充新 AI 样本。依赖玩家的预测沿其真实槽位先后和普通连续运动保持必要条件，复杂来源切换等待新一致样本。增强机会每游戏步只选一次最久未获机会的合资格角色，共享既有预算；排除死亡、禁攻击、失效目标及已预测死亡目标。半自动释放帧不剥夺新样本捕获机会，真正出手仍由原生 ItemCheck 决定。

初始人物槽、资源交接与常规差异同步共用一份原生槽ID映射，保留原版offset，按真实inventory、装备、染料、misc、银行、垃圾及配装数组长度枚举；银行协议预留200个ID不代表本体数组有200格。常规输出只发送变化的5/42/50及角色控制/生命，不逐帧全量发送库存。

个人掉落 90 按接收 Actor 和原生 item slot 保存稀疏实例，在该身体的 90 原生解码、稀疏 UpdateItem 及实际 GrabItems/PickupItem 同步消费者范围临借 Main.item 对应槽，拾取视图保持至同步序列化真正读取 Main.item；退出归还共享对象。距离、容量、数量及实例拾取消息遵守原生规则，不收到包就加背包、不强发原版实例不会发送的 21/151。原生世界物品阶段之后，每个实际存在的个人实例每游戏步至多 UpdateItem 一次；同角色 151 只退役自己的实例。共享 21/22/151 仍保持唯一原生消费者，收回、断线、槽复用及换世界清理所属实例。

每Actor还按实际命中保存稀疏NPC预测视图，完整原生Strike同步返回及OnHit/OnKill都在同一目标/root视图中执行，随后归还共享观察对象。原生PushPendingDamage实际对象按发送连接归属，从真人全局队列移出；realLife递归仅登记一次。162只解除该连接对应对象，不代表服务器接受命中，不补扣血。该Actor自己连接的23按原生生命/phase分支减去自己尚未确认的预测，代次变化丢弃旧视图。原生按玩家槽的免疫与当前共享观察同属一个计时出口，不能在私有clone中冻结或重复老化。

纯 Steam 采用专用通道73 + streamId 到房主 GUI 的最小字节桥，房主端每流连当前本地服务器 TCP。73是本产品保留选择，不证明所有第三方均无冲突。桥只接受当前会话成员并只代理本机当前服务器。已知流的队列或发送失败只退役该流；过长包按有界读取消费，避免坏队首逐帧重试。关闭一条流只关闭其 TCP，绝不调用真人 SocialSocket.Close。GUI/专服 Steam 收包归属尚需双机判别，四步为握手、一个独立槽、第二独立流、单流关闭隔离；不能用注入API故障的隔离检查或TCP通过替代。

## 世界坐标、瞄准与交互资格

LoadBody只恢复人物数据，不确定本世界的出生位置。首次进入与复活在原生Spawn完成后，以本角色实际中心重置临时Aim；无目标或禁攻击时跟随当前身体，清除旧目标/旧世界预测状态。合法目标因预算延后时保留仍有效的原解，不能每帧降回身体中心。

actor scope中的mouse仍是原战斗/棱镜瞄准点，tileTarget也保留同一真实原目标格，不把动作搬到脚下或其他安全格。世界交互另有每scope一次O(1)资格：坐标有效、Tile对象存在，且多人时本连接共享世界的sectionManager.TileLoaded为真；缺manager、nonnull但未收块仍未知。只延后该角色该格的PlaceThing/Wiring消费者，原生ItemCheck、计时、已合资格射击、移动、其他射弹/队友与远距自背包不因此停止，不补造Tile或扫描世界。

原生UpdatePlacementPreview属于真人光标的共享UI状态，不属于借用角色用物身份的权限。AI scope不执行该预览，避免CanPlace/Framing把未知足迹或锚点物化；真人预览照旧，真正的已知格PlaceThing动作仍保留原生范围、资源和操作资格。

LaserDrill的AI_075同样直接读取tileTarget。只在其真实pool key/activation归属与当前actor一致时，未知格跳过该原生分支的tile/steering工作块；原生channel退出、冷却及共同position/timeLeft/heldProj/SetDummyItemTime尾继续执行，不复刻尾或手工续命。真人、其他角色/其他射弹不借当前scope被拦截。资格恢复后同一原格继续原生工作。
## 计算和关闭

管理窗由行内入口和独立热键两种来源打开，来源属于UI本身；行内管理按钮的真实release先沿CloseAndSubmitPosition关闭F5和冲突视图，再把同一管理窗切为独立来源，保留输入尾，不通过伪释放打开；独立来源的输入、准备、绘制和收尾不依赖主F5可见性。`companions.manage`只在实际装配Companions的profile注册，默认无绑定，沿现有HotkeyBindings保存/冲突/清除。可执行门尊重其他弹窗、文字与Notes真实指针捕获及释放尾，普通悬挂便签hover不封锁新边缘；不通过全局SuppressHeld吞掉无关移动键。

标题拖动只平移已准备的可见控件和几何，不重建人物/物品单元或重复测字。缩放/屏幕变化撤旧grab再夹紧，失焦取消未提交拖动并归回上次接受位置。位置只在运行内保留，不新增持久化文档或把UI动作写回身体。

适用实体观察与昂贵选路/预测由全队有限工作调度共享；各角色保留自己的目标、动作和预测消费身份。基本控制按游戏步继续，改进型工作可轮转延后。零在线队友时不扫描世界、不生成预测任务、不逐帧落盘。存档变化标脏并合并，收回/退出形成明确保存边界。

原生同步消费者的actor scope持有临时myPlayer、鼠标、tileTarget、地图与嵌套current身份，退出必须在finally归还这些精确旧值；资源变化观察或清理异常仍传播，不能使其跳过恢复。PlayerFinal所能补回的NPC/tile状态不替代该scope自身的完整恢复职责。

## 边界

首批包含正式档案、真实资源、基础跟随/战斗/生存和实际两页管理 UI，不扩展完整 Boss 战术、复杂工作、LLM 或通用协议平台。旧 v5–v15 证据按原身份复用，不签为本轮正式 AI/Steam/全资源链通过。动态步骤、分支、检查和未决项回任务 Issue 与开发包 HANDOFF。
