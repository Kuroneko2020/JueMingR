# AI 队友正式实现设计

本设计涵盖首批 S0–S5、管理界面和跟随战斗与补给。产品版本由根 Directory.Build.props 承载。用户行为见[功能合同](../功能介绍/AI队友功能行为合同.md)。真实候选、验证结果和所有者实测状态由任务记录承载。

AI 专项开发中有复用价值的中间数据、样本、实验输出和经验可以直接保留到 `references/AI队友`，按现有目录及 [README](../../references/AI队友/README.md) 按需提供发现入口，简要注明来源、版本、用途和已验／未验边界，尤其保留能够支撑后续判断的原始中间数据。不要求复制所有临时日志、逐文件登记或新增永久校验门。该目录持久保留且由 Git 忽略，不成为编译／运行／分发依赖；正式合同、设计和当前任务授权仍由原有权威入口承担。

## 角色、资源与生命周期

每个人物拥有稳定 Guid、创建者关联、行为设置和完整原版人物序列化数据。名字、玩家槽位、世界坐标均不是永久身份。创建者映射绑定真实人物文件记录，改名不产生新档；人物资源跨世界延续。首次创建使用对应难度的原版默认人物，重新加入、复活不发新手物资。

Host 以当前原版文件路径和本地／云端类别为档案入口，只在这些标量身份改变时重新派生摘要。离开、失去路径、进入服务端角色或更换主人立即撤销前一名单和管理许可；在途创建、写入与已退役实例的最终捕获仍由原归属和精确 activation 持有。临借队友槽执行原生消费者期间，跳过档案身份刷新。档案读取由后台单一 worker 调度，初读失败及部分成员读取错误都在管理窗显示「重试读取」。部分读取保留已载入成员，并暂停创建直至名单完整。只释放暂不可读文档的读租约，重试合并缺少的成员，保留运行时较新修订和已有提交。正常空名单保持可创建状态。

Feature 拥有档案及行为语义；Infrastructure 只在游戏安装根下的 JueMingRData 中读写自有字节；Host 在游戏线程捕获原版人物、执行真实物品操作。后台不得接触 Player/Item/Main。原版序列化中真人鼠标、制作退款和临时界面槽必须在显式队友保存范围分流，不能调用全局 SavePlayer 冒充队友保存。

当前实例绑定人物 Guid、世界会话与 activation generation，独占原生 Player、连接及动作。槽位仅为本次映射；同一档案不能同时激活两具可产出物资的身体。收回立即停止新动作、退役当前身体并捕获一致人物快照。普通回收关闭连接，硬核终局连接按下方确认规则收尾。活化保留到该修订成功保存，避免另开身体复制资源。离线预览从保存的人物重新加载基础血蓝上限。保存失败保留唯一最新内存状态并显示原因，不自动从旧磁盘恢复或重置。

连接失败与主动收回共用停止动作、关闭流和退役槽位的出口，但失败原因独立保留；后台保存完成后仍显示原服务器或本地终止原因。捕获最新身体本身失败时，旧修订已保存不代表本次收尾已保存；保留唯一最新身体及 activation，并由现有重试入口重新捕获。只有本次收尾快照已受理且相应保存完成后才释放 activation，不自动重连。

加入进度只属于实际等待的 activation。单人同步 Spawn 已完成时不留下“正在加入人物”；多人在真实 Ready 或该 activation 结束时，仅退休仍属于它的同一进度提示，不定时清除错误或其他操作反馈。人物自身的在役、连接、死亡与收回状态继续由 Actor 唯一持有。

### 创建草稿与终局

创建由独立 CompanionCreationSession 持有真实主人、世界/session token、未入档的 Player 草稿及原版 UICharacterCreation／UIVirtualKeyboard，放在 Main.InGameUI 的原生模态页面，不由管理窗口关闭动作销毁会话，不改 Main.PendingPlayer 或游戏菜单。构造前后保留世界默认难度；私有发型 helper 与静态 dirty 只在构造及本会话所属 UserInterface.Update／Draw 栈交换并 finally 归还，覆盖按钮派发。原版命名、确认、返回出口按精确实例门控；过期实例和键盘回调不能写普通人物／收藏或重提草稿。真正确认只经 HostCompanions.CreateDraft 防重复、原生初始化一次、Capture 和 manager 入档，试穿装备不复制进资源。接受 Guid 与首次 worker 发布是两个状态，回管理先保留 pending 创建身份，不让旧名单首人覆盖；未保存修订不能激活。取消命名回同一创建页，真正取消回管理；可信输入失效清本轮 native LastDown 而保留草稿，物理尾沿现 HostInputState 中立归还。原版预览仅触及独立草稿，受限外观阶段及私有 RNG／共享 shader 有 finally 收尾；外围按实际视口夹取，内部控件不重建另一套皮肤。明确 Reset 保留难度／外观／声音，重建资源并递增 DataEpoch；恢复行为仅改偏好。

自有档案格式 v6 将归属、身份、DataEpoch、终局、原生人物流、主要武器和全部行为偏好一起写入同一原子修订。v1 至 v3 按历史字段顺序读取。v1 默认非终局，v2 保留终局，二者默认开启自动复活。v3 的有效手选记录转为一件主要武器，游戏线程用当前物品定义验证武器资格。v4 在原来的位置读取一个共享自动消耗品开关，并将同一个值用于增益和成长，随后按原顺序读取四份类型名单。v5 在同一位置依次读写增益与成长两个布尔值，再读写四份名单和原生人物流。新人物两开关开启、两份许可为空。v6 另存每人物的家具增益，旧档该项关闭。独立护士沿用原有字段，旧档迁移时仅保留过去主动回血和允许护士同时开启的实际待遇，避免升级后意外花钱。读取与同一修订重试保留旧文件字节，下次接受实际变更才写 v6。每个档案深复制武器和许可数组，在役 Actor 按同一 Profile 引用复用只读设置快照。文件仍核对摘要、归属、单调修订并走既有原子写入。

Join、Attach 和 manager.TryReserve 均尊重终局。原版 KillMe 的 DropItems／HardcoreDeathPenalty 继续执行。只在 KillMeForGood 精确命中本 Host 身体时跳过其读取真人 Main.playerPathName／ActivePlayerFileData 的删除出口，标记该 activation 已到终局。原生 surviveHardcoreDeath 扣除 60 基础生命仍大于零时保留合法复活。

锁定客户端先运行 Main.UpdateUIStates，后运行 DoUpdate_HandleInput；本创建页的早期 Update 只登记本输入 epoch 的时间，由原 InputPostfix 在 AfterKeyboardRefresh 后、世界动作消费者前派发一次。许可仍取现有可信焦点和中立释放门，不借上一帧 finalized，也不增加 OS 采样。派发短栈使用原 UI zoom，finally 归还屏幕及当前／上次鼠标坐标；颜色／音调滑条的 Draw 仅借回同帧可信鼠标，文本／IME 保留原出口。真正加号回调晚于该帧 Flush，成功开页也立即取得本帧世界动作归属。派发后只消费世界 trigger、鼠标及热键动作，不清原生文本队列；即使回调关闭页面，本帧和真实释放前的物理尾仍归原模态。跳过采样或失焦不会补派旧点击。

终局沿同一 CloseActor 停止并退役身体；先发布不可再激活的档案标记，再捕获最终原生资源。捕获失败仍保留 Closing、唯一最新身体及 activation，显式重试只重新捕获，不重新执行死亡／掉落。普通定时保存、行为更新和收回保留终局标记，只有明确破坏性 Reset 可创建新的非终局 DataEpoch。真人及非本 Host 身体仍走原版删除语义。

自动复活沿真实身体的 respawnTimer 与原生 AfterBody／Spawn 出口，关闭时继续推进原生计时。关闭期间的状态同时显示实际剩余秒数与设置，归零等待重新开启。终局优先显示。主要武器使用 type、prefix 和槽提示，先匹配原槽，再按确定顺序匹配移动后的同类物品。最新原生资源快照和已移动或移除的偏好一起保存。自动持有、缺弹和缺蓝属于本次运行状态。

## 管理窗口与物品事务

### 配置页的局部组织

配置与背包共用紧凑固定外框。配置顶部保留所选人物、实际状态和复活信息。两列复用 F5RowLayout，同一对功能行推进到两者的最大高度。供给配置打开锚定按钮的紧凑浮窗，药品、成长物用图标网格，增益物品使用候选和已选两栏，各自滚动。授权仍保存具体物品类型。三档饱食在界面合为一组，旧档仅允许部分食物时用黄色短线显示。幸运药水按三个强度分别选择。暂未显示的旧类型继续保留。已选增益用勾叉显示是否有货，悬停查看库存与当前人物的成长完成状态。护士治疗与主动回血分别拥有开关，回血模式只参与药品评分。普通设置成功静默，错误可通过有限提示或对应控件查看。

控件使用现有 InventoryBack／MouseText、ItemsRenderer／F5ControlRenderer 和共同 Input／文字 lease。管理窗小字沿用按 scale 描边及同源度量。头像、人物／宠物及 Point 图像子批次恢复窗口明确建立的 Linear 文本批次。物品和数量保持自己的像素采样。功能行按钮明确写目标值，从当前 Profile 的副本更新对应字段。人物或主页面切换、关闭及 DataEpoch 变化退休旧展开、确认和选择。

逐人物快捷键的动作 ID 由 owner GUID、profile GUID 和设置标识组成。当前归属可调用同一个 SetBehavior，离线偏好和在役偏好均由当前 profile 决定。真实热键派发使用公共 HotkeyStateFeedback，在本人物档案的保存结果确认后重读同一设置，短提示显示名字、实际开关和回血模式。同一设置再次改变时，淘汰旧动作的待确认提示。其他设置或库存的保存可以合并确认当前结果。首次写回失败后，即使重试成功也不补报。普通配置点击保持静默。键盘图标使用公共 F5HotkeyHints.Toggle。自动回血热键关闭时保留上次模式，重开恢复该模式。HotkeyRegistry 动态所有者独立保留已有绑定和当前配置人物的可编辑动作。当前角色缺席时原 hotkeys.json 记录仍随原文档保留。档案普通 Revision 变更只更新快照，实际名单或名字变化才替换受影响的动作。绑键弹层从双击的第一次点击就跟随其真实父窗和锚点。可见期间父窗保留绘制，弹层先消费输入及释放尾。

主要武器草稿由管理窗持有，绑定人物 Guid、世界会话、在役身体、activation 和 DataEpoch。进入时撤回未提交的物品投影、结束右键连点、退休原按下。选择模式的格子仅编辑自己的主要武器草稿，真实物品保持原位。完成时 Host 从真实库存复核槽位及 type/prefix；相同身体的后台保存 Revision 变化不取消草稿或有效按下。轨迹和用物调度在原生占手边界选择当前武器，偏好提交本身不换手。

密码挑战使用紧凑的会话共用弹框和现有 TextEditInput。掩码用于已输入字形和预编辑字形，密码输入禁止复制到剪贴板。取消结束本轮等待请求，失焦保留等待意图。退场交还原有 IME 租约，释放本次草稿及准备阶段引用，保留可信输入尾。普通状态、倒计时和格子内当前武器标记局部更新。真实操作、身份、资源或命中几何变化时，按原窗口规则重排并退休失效按下。拖动尚未松手时变更窗口比例或资源尺寸，先恢复已提交的位置，再在新视口夹取。

### 主动补给与长期许可

每个 Actor 使用自己的偏好快照、用物状态和真实原生身体。血药按现有 RecoveryRules 的快速／智能评分与 PotionRecovery 的实际回复量选择。蓝药根据显式武器的原生魔力费用和当前蓝量判断，并在可消费时重读本次真实结果。血药和蓝药使用默认允许的类型及各自排除集合；成长和增益使用初始为空的显式许可集合。主动恢复及魔力花使用原生快捷消费者和精确来源，既有魔力花允许条件独立于新增主动回蓝设置。

每名队友独立保存家具开关和本次激活的扫描、候选与退避。共享真人家具恢复的七类原版家具、完整物块与缺失效果判定，使用队友当前身体的有效交互范围。只在可确认的实际物块上调用原版交互，制作窗和指针归真人。多人使用队友连接同步增益。护士只有自己的开关和原版可治疗、可支付条件；血药智能门槛只用于物品，没有药品许可的患者同样可以合法就诊。

成长目录包含原版个人生命与魔力、恶魔之心、工匠面包、个人微光永久物品、火把神恩赐和矿车升级包。成长和占手动作在原生 ItemCheck 边界交接，观察真实消耗、成长完成字段和矿车产出。增益使用固定版本可消费目录及现有 Buff 等效组判断，收窄原版 QuickBuff 至一个真实来源。缺少饱食时在允许且可用的食品中按原生三档优先级与时长选择，已有同组饱食时等待。增益和成长独立准入，已有用物依据各自阶段收尾。过期效果或补货后重新执行，长期许可随档案保留。所有生命、永久字段、库存和银行仍由实际原生身体保存。捕获或发送失败只重试尾部。

邻近护士以队友原生身份和该患者实际购物条件计算费用。发现、复验和提交用患者自己的有效装备、旅途状态及原版 Simple 交互区域。个人储存复用该范围，装备写入后随同一人物的原生装备更新重新取得有效范围。共享观察消费同来源、同 NPC 实例的原版住房消息 60，让 ShopHelper 按患者所在地、护士住处／相邻居民和实际折扣定价。队友和主人分别按各自真实库存及四银行计算余额。两边影子账本调用固定原版 TryPurchasing 生成原面额找零计划。仅在护士原生付款边界复核同一患者、护士、距离、费用和两个实际写集，然后单线程一次提交。队友承担自己可支付的部分，主人只承担剩余差额。付款确认后由原生方法治疗同一患者。精确作用域保护真人聊天、购物与成就。玩家当前交接或其它资源操作拥有的相交槽会阻止本次付款。

护士已提交而治疗结果未知时保留人物与 DataEpoch 的会话事实，普通收回重入后不会重扣。同步按真实付款者分别提交 5 号槽位，治疗效果由原生 35，队友生命和增益走该连接的常规同步。Host 外层更新在窗口关闭时也会刷新待同步队列。

### 背包和共同窗口

管理窗按紧凑背包的共同尺寸和实际视口夹取。背包、配置、人物、列表和模式共享外框，背包左右各自滚动。名单双状态分开：当前选中用顶部内侧居中一条绿色短线，已加入用错位长下划线，死亡／连接中不以资源资格冒充离役。头像按原生头部 DrawData／纹理帧可见边界居中，有限缓存随资源和外观失效，关闭清借用纹理。两侧姓名、人物／生命／魔力头部共享高度与基线，人物 header 统一姓名留白、血蓝和深色预览的分区／基线；队友预览左侧以原版 Pvp[1] 六帧及 Pvp[2] 选框呈现两列三行队伍按钮，只调用所选 AI 的 SetTeam。加入／收回是队友预览左侧与框底对齐的普通按钮，文案读当前成员身份，悬停说明实际可用性。两侧展示框都把完整内部留给人物和宠物。配置页在独立人物头部显示真实状态、复活倒计时／自动复活关闭状态，组织见上一节。紧凑饰品／时装／装备 tabs 按自然字宽右对齐、留上／右内边距夹在本列装备模块顶部，与所控制的装备／染料槽共享边框和背景；主 tabs 位于标题右侧。装备、背包、钱弹以实际槽外接细线分组和统一边距，空槽复用 Extra54 真实帧（染料1、时装饰品2、生效饰品11），钱弹文字居中。数量和持物草稿使用原生 ItemStack 字体及局部采样，保留完整数字。心星每行10段；横向条按原版实际中段纹理宽推进，先完整panel再fill，保HP／MP端盖各自负位移、fill内缩、原sourceRect裁剪方向和生命果末段分配。完整负边界纳入统一float锚点／scale及block测高，不能用装饰贴右侧的相似图替代。六个原生样式及真实数值不截断。离线卡片用已保存当前值和基础上限，不重演装备／buff。身份、DataEpoch、实际 activation 或真实命中几何改变退休旧按下；人物框外的按钮捕获当时的加入／收回操作和真实 activation generation，不在松手时反向选择动作。普通状态、数量、倒计时和保存进度局部刷新。设置／保存失败按钮有无改变需要重投影时，只保留同 key/epoch/rect 且仍可用的当前按下，不设置点击冷却。

装备模块与主库存之间两侧使用同一高度、同一行的工具条。左侧四个箱子动作，右侧选择主要武器、排列物品、使用一次和一个按固定顺序循环的储存按钮。武器编辑或一次用物沿原工具行收纳同模式按钮。每个储存名称、选择状态和计数都在首选测量内，极窄时滚轮横移该行。

纯 Steam 采用专用通道73 + streamId 到房主 GUI 的最小字节桥，房主端每流连当前本地服务器 TCP。73是本产品保留选择，不证明所有第三方均无冲突。桥只接受当前会话成员并只代理本机当前服务器。已知流的队列或发送失败只退役该流；过长包按有界读取消费，避免坏队首逐帧重试。关闭一条流只关闭其 TCP，绝不调用真人 SocialSocket.Close。桥接关闭或 Steam 链路失败时，只要房主 TCP 仍接受发送，就继续转交已接收的待确认死亡，沿用同流原版 154 的有界确认。客机失去大厅后仍按自身已收到的回复判断确认状态。GUI/专服 Steam 收包归属尚需双机判别，四步为握手、一个独立槽、第二独立流、单流关闭隔离；不能用注入API故障的隔离检查或TCP通过替代。

## 世界坐标、瞄准与交互资格

LoadBody只恢复人物数据，不确定本世界的出生位置。首次进入与复活在原生Spawn完成后，以本角色实际中心重置临时Aim；无目标或禁攻击时跟随当前身体，清除旧目标/旧世界预测状态。合法目标因预算延后时保留仍有效的原解，不能每帧降回身体中心。

队友目标按自身到敌怪受击框距离排序，保留有限近邻和轮转远邻。策略优先评估最多两件主要武器，对缺少可用组合的情形分批扫描主背包。武器选中使用同一资格规则，原生用物另核本人物弹药来源、魔力费用、物品事务及实际可用条件。保持当前选槽使用换手间距与短时评分余量，实际不可用时选择能执行的备选。魔法计划因缺蓝时尝试当前人物获准的主动补魔，重读实际蓝量，再执行或回退。

`ActorSolution` 接收显式 Player、武器、NPC 和该人物的样本条件，调用真人战斗已使用的 Balanced 代表轨迹或适用的专用 Contact 求解器。真实原生 ItemCheck 使用当前目标和手上武器重新核对。短期结果绑定目标引用和代次、采样修订、姿态、装备／弹药及地形读集。预算未完成保留 Unknown，允许已知地形的保守直接开口。每世界步仅轮到一名队友扩展目标与武器搜索，昂贵组合查询单独限额，实际瞄准增强继续使用既有鲜样本轮转。实际放置、击中、扣费及新建射弹仍由原版执行。

actor scope中的mouse仍是原战斗/棱镜瞄准点，tileTarget也保留同一真实原目标格，不把动作搬到脚下或其他安全格。世界交互另有每scope一次O(1)资格：坐标有效、Tile对象存在，且多人时本连接共享世界的sectionManager.TileLoaded为真；缺manager、nonnull但未收块仍未知。只延后该角色该格的PlaceThing/Wiring消费者，原生ItemCheck、计时、已合资格射击、移动、其他射弹/队友与远距自背包不因此停止，不补造Tile或扫描世界。

原生UpdatePlacementPreview属于真人光标的共享UI状态，不属于借用角色用物身份的权限。AI scope不执行该预览，避免CanPlace/Framing把未知足迹或锚点物化；真人预览照旧，真正的已知格PlaceThing动作仍保留原生范围、资源和操作资格。

## 计算和关闭

管理窗由行内入口和独立热键两种来源打开，来源属于UI本身；行内管理按钮的真实release先沿CloseAndSubmitPosition关闭F5和冲突视图，再把同一管理窗切为独立来源，保留输入尾，不通过伪释放打开；独立来源的输入、准备、绘制和收尾不依赖主F5可见性。`companions.manage`只在实际装配Companions的profile注册，默认无绑定，沿现有HotkeyBindings保存/冲突/清除。可执行门尊重其他弹窗、文字与Notes真实指针捕获及释放尾，普通悬挂便签hover不封锁新边缘。鼠标主键另读原版当前及上一轮 UI 占用，背包打开时将 Ctrl＋左键留给可能随后在 DrawInventory 才命中的原版物品。键盘保持原有可执行门，无关移动键继续交原版。

标题拖动只平移已准备的可见控件和几何，不重建人物/物品单元或重复测字。缩放/屏幕变化撤旧grab再夹紧，失焦取消未提交拖动并归回上次接受位置。位置只在运行内保留，不新增持久化文档或把UI动作写回身体。

适用实体观察与昂贵选路/预测由全队有限工作调度共享；各角色保留自己的目标、动作和预测消费身份。基本控制按游戏步继续，改进型工作可轮转延后。零在线队友时不扫描世界、不生成预测任务、不逐帧落盘。存档变化标脏并合并，收回/退出形成明确保存边界。

原生同步消费者的actor scope持有临时myPlayer、鼠标、tileTarget、地图与嵌套current身份，退出必须在finally归还这些精确旧值；资源变化观察或清理异常仍传播，不能使其跳过恢复。PlayerFinal所能补回的NPC/tile状态不替代该scope自身的完整恢复职责。
