## A. 已接受的配置持久化设计

### 数据根与实际文件

数据根是已经验证的 `Terraria.exe` 所在目录下的 `JueMingRData/`。Host Composition Root 从已验证 `targetAssembly.Location` 取得游戏根；不使用当前工作目录、决明程序集所在的 sidecar、开发仓库或私人硬编码路径。设置不进入 `Terraria.exe.config`，Bootstrap 最早初始化不读取用户设置。

```text
<Terraria.exe 所在目录>/
└─ JueMingRData/
   └─ config/
      ├─ ui.json
      └─ features/
         └─ biome-display.json
```

两份偏好属于这一份游戏安装，在该数据根内跨角色、世界和返回菜单共享；不代表其它游戏副本或电脑自动共享。数据根不可用时不转存 AppData、Documents 或另一目录，不自动提权或修改 ACL；对应文档保留明确的读取或保存失败反馈，尽可能保持本次会话功能可用。

只按真实需要创建上述路径及每份文档同目录的 `.lock`、`.tmp`、`.bak` 辅助文件。启动读取可以创建必要父目录和排他锁文件；缺少正式 JSON 时使用默认值，不仅为补默认值而创建 JSON。第一次真实调整该项偏好才请求首份保存；重复选择相同值不产生请求。

### 两份独立的格式合同

每份文档最多 65,536 bytes，采用 UTF-8 JSON，根必须为对象。各自只读取、写出整数版本 `1`；没有已有旧格式迁移链，也不承诺降级。下面的字段均为必填，缺字段不由反序列化默认值补合法；重复字段、错误类型、错误格式身份、非法整数或越界整数使整份文档无效。

| 文档 | 字段与类型 | 默认值和含义 |
| --- | --- | --- |
| `config/features/biome-display.json` | `format` 必须为字符串 `JueMingR.BiomeDisplay`；`version` 必须为整数 `1`；`enabled` 必须为布尔值 | 缺文件默认 `enabled=true`，保持已接受的默认群系显示行为；它是用户期望开关 |
| `config/ui.json` | `format` 必须为字符串 `JueMingR.Ui`；`version` 必须为整数 `1`；`windowPosition` 必须为 `null`，或仅含必填 `x`、`y` 两个 Int32 整数的对象 | 缺文件默认 `windowPosition=null`，沿用默认居中；非空位置使用 Terraria UI logical 坐标 |

```json
{"format":"JueMingR.BiomeDisplay","version":1,"enabled":true}
```

```json
{"format":"JueMingR.Ui","version":1,"windowPosition":null}
```

UI 示例中的 `null` 可以由合法对象替代，例如 `{"x":40,"y":24}`。合法整数超出当前视口不构成格式损坏；显示时按下节投影。版本为其它整数时明确标记不支持，包括未知较新版本；未知字段拒绝整份文档写回，避免静默丢弃它们。未知字段、损坏和不支持版本保持不同状态，不自动删除原件、迁移、规范化写回或恢复备份。

`ui.json` 与 `biome-display.json` 各自读取、保护和保存；一份损坏不阻止另一份正常使用，不建立两文件原子事务，也不因一份成功就声称所有偏好已保存。

### 期望值、实际功能状态与窗口投影

Settings 的 `PreferenceDocument<T>` 是相应用户期望及 revision 的唯一 owner。群系 Feature 继续拥有实际启停、可用性、故障和 ViewModel；Runtime 区分 `hostAvailable` 与 `userEnabled`，用户保存的 `false` 只表示正常关闭，不能进入宿主故障路径。配置读取和用户命令不能解除已有 Feature 故障锁或自动重试，故障也不能回写为用户选择关闭。UI 的开启、关闭与不可用显示仍取自实际 Feature 状态。

F5 保存的是用户最终选择的位置，当前绘制原点只是该偏好在当前视口内的投影。沿用整数化、窗口边距、Terraria UI logical 坐标域以及极小视口安全关闭；不能混用世界坐标或桌面物理像素。视口、窗口尺寸或 UI scale 变化时重新夹紧显示，自动夹紧不写回偏好，视口恢复后重新投影原偏好。用户主动再次拖动才可以提交新位置。

标题拖动期间不请求逐帧保存。真实松手时提交最后有效位置；正常关闭或退出世界中断拖动时，先取最后一个有效且聚焦的拖动样本，再取消捕获，不保存 Terraria 合成释放中的输入坐标。#46 本次明确调整失焦行为：取消未完成拖动、恢复拖动前的显示位置，不提交新偏好；实施与验收以 #46 为准。拖动最终回到起点时不提交，同值偏好不重复保存。

F5 是否打开、最后页签、滚动、鼠标捕获、按键按下、armed 控件和拖动过程都是瞬时状态，不跨启动保存。位置保存不增加缩放、自由窗口尺寸、UI 美化、快捷键业务或其它尚未接入按钮的配置。

### 读取与保护状态

| 状态 | 当前会话与磁盘处理 |
| --- | --- |
| 正在读取 | 对应偏好尚未就绪，拒绝其修改命令，避免迟到读取覆盖用户操作；另一份已就绪文档独立工作 |
| 文件缺失 | 使用默认值并允许之后的真实修改首次保存；不自动生成默认 JSON |
| 格式、字段、版本均合法 | 恢复期望值；没有真实修改就不写回 |
| JSON、字段或大小无效 | 使用默认值作为本次会话起点，保留问题原件，禁止本进程写回 |
| 版本不支持 | 保留原件并禁止写回，提示使用能读取该版本的程序；不自动降级或恢复旧备份 |
| 存在未知字段 | 保留整份原件并禁止写回，不忽略字段后重新保存 |
| 权限或 I/O 失败 | 明确报告该文档未可靠加载或保存，不伪装为文件缺失，不切换目录 |
| 另一写入者占用或外部变化 | 进入该文档的写保护，保留原件或已识别的冲突恢复材料，停止提交并报告 |

读取完成但受保护后，用户仍可调整本次内存中的偏好；这不解除磁盘保护，也不创建第二套生效配置。失败在本进程中不自动重试，不因下一帧、下一次点击或世界切换解除保护。正常处理方式是退出游戏后处理原因，再重新启动；没有文件热重载。

Host 对启动加载设置总计 2 秒的等待上限，通过原有游戏回调收取不可变完成快照，不在回调中等待文件 I/O。超时的文档使用默认值并进入保护，迟到的读取结果作废，不能覆盖之后的会话选择；后台仍持有其资源直到实际结束。

### 保存、备份和冲突

每个机械存储实例在读取时取得 `<文档名>.lock` 的 `FileShare.None` 句柄，并持有到工作线程退出。相同实现的第二个进程无法同时取得该文档写入权。锁文件释放句柄后不自动删除，避免删除与下一进程取得锁发生竞态；它不是需要每次启动清理的坏文件。

保存按以下顺序进行：

1. 在后台编码候选，并通过同一文档语义解码验证；机械层只处理字节、大小和身份，不认识功能字段。
2. 以 `CreateNew` 在同目录创建 `<文档名>.tmp`，写入完整字节、`Flush(true)` 并核验候选内容。已有临时文件不覆盖、不接管。
3. 首次创建通过不覆盖目标的 `File.Move` 提交；读取后出现同名目标则报告冲突。
4. 替换已有文件时重新检查来源身份，以保持打开的只读句柄阻止普通就地写入，再用 `File.Replace` 提交，同时将实际被替换的字节保留为 `<文档名>.bak`。
5. 核验备份身份及已提交目标的候选身份，均符合预期后才报告该 revision 保存成功。

首次 `Move` 或已有文档 `Replace` 是对应文件的提交点。正式文件不会先被截断再慢慢写入。正常连续保存只保留一份上一有效原件，不累积每次运行的备份；损坏、未来版本或未知字段未获合法读取时不会进入替换，因此不能被默认值覆盖或污染正常备份。备份不自动恢复。

保证限于普通可信的本地环境。替换所需的 delete sharing 意味着不合作程序仍可能在最终核验与替换间执行原子 rename；不能声称已提供任意 rename 的 compare-and-swap。`File.Replace` 保留实际被替换字节，随后的备份身份核验发现不一致时报告冲突并永久停止该实例写入。此时正式路径可能已是本次候选，`.bak` 保留外部被替换内容，不保证它是合法配置，也不把该次报告为保存成功或继续轮转备份。已提交目标又变化时同样停写并报告。

提交前失败时，只尝试清理本实例实际创建的 `.tmp`；不删除预先存在的临时文件。已尝试操作系统提交而结果不明确时，保留那一份候选以供退出后的恢复，不能猜测并清理。I/O、权限或冲突失败均不继续自动保存；文件系统错误、磁盘或硬件故障不构成绝对无数据损失保证。

### 工作线程、退出与用户反馈

两份文档分别拥有一个后台线程和一个容量为 1 的待写槽。每次真实选择替换该槽中的旧待写值，静默 150 ms 后提交；相同值不请求。每份文档顺序写入，旧请求不会在新请求之后落盘；旧 revision 的完成只更新机械文件身份，不能把较新的待保存选择标为已保存。

后台只持有不可变偏好、编码器和机械存储，不持有或访问 Terraria live object。JSON 编解码、目录准备、文件 I/O、哈希及备份核验都在后台；Draw、输入和每 Tick 回调只读取快照或发送窄命令，不轮询文件、不扫描目录。无变化时后台等待信号，不持续写日志或制造保存任务。两个实际消费者共享必要机制，不扩展为未来配置注册中心。

偏好为进程级，返回菜单或切换角色、世界不会销毁它们。首次 Runtime handoff 在既有 Host Composition Root 中装配 `HostPreferences`，Bootstrap 和 Terraria Hook 集合保持原边界。最终退出使用 BCL `AppDomain.ProcessExit` 事件，不新增 Terraria Hook。

正常窗口关闭和退出世界的拖动收尾、失焦的未提交拖动取消均在游戏线程处理；直接关闭游戏时，`ProcessExit` 不访问 F5 Shell 或重新采样拖动，只处理已经接受的保存请求。尚未由游戏线程提交的拖动过程不因此获得退出保存保证。

退出先拒绝新命令，尽可能排空已接受的待写槽；两份文档共用总计 750 ms 的等待预算，不逐份各等待 750 ms。超时取消尚未开始的工作，不能无限阻塞游戏退出。已经开始的原生 I/O 无法安全强制终止；工作线程到实际结束前仍拥有存储和锁。停止返回未完成时，测试和调用方不得释放或删除数据根；突然断电、强制结束只按已提交字节提供恢复依据，未落盘的选择可能丢失。

正常改开关、拖动窗口、自动保存、合法读取和首次缺失均静默。`Pending`、`Saved` 与 revision 继续作为内部正确性状态，但不构造成功/过程提示字符串，不改成成功日志、通知队列或闪烁 UI，也不新增通知设置。

Host 只为真正的读取/保存失败、损坏、未知字段或版本、加载超时、占用和外部冲突复用 `Main.NewText` 给出必要中文提醒，准确说明本次内存选择与磁盘未可靠保存的区别。每份文档各保留一个“已成功交付的异常原因”，生命周期与进程级 Host 一致；同一持续原因不因 revision、重复操作、开关 F5 或切换世界再次提醒，新的原因仍可提醒，两份文档互不吞掉消息。菜单或隐藏 UI 时不领取提醒，显示调用成功后才确认交付；显示失败不消费该原因。此去重不解除原件保护，也不改变 F5 自身故障提醒。

普通用户处理单份异常时，先退出游戏，复制保留问题文件，再只移走该问题 JSON，下次启动恢复该项默认值。未知较新版本优先使用匹配程序，不将它当成坏配置自动回滚。若仍有保存失败，应保留相关 `.tmp`、`.bak` 并报告，不盲目清理整个目录。需要恢复备份时，先明确它的来源与合法性，保留当前原件；本轮没有自动备份恢复按钮。

| 位置 | 职责 |

六个生产项目和依赖方向不变。Platform 增加 `System.Runtime.Serialization` 的 BCL 引用以读取有界 JSON；ArchitectureTests 增加 Infrastructure 引用，使真实文件检查进入现有正式构建入口。这不是新第三方依赖或新生产项目。

自动验证使用每次独立创建的临时根，初始化前明确注入路径；不使用真实用户配置、Documents、角色世界或日常游戏目录。覆盖格式拒绝与文档隔离、故障与期望分离、真实文件保存/备份/冲突、另一进程、合并和停止、视口投影与实际输入消费者。测试必须等工作线程确认结束才清理根；持久化计数和线程/槽边界只支持对应组件结论，不证明整体 FPS、多人或实机体验。

`JueMingRData` 是用户数据，不是程序载荷。安装、更新、恢复和卸载默认保留它；重置配置不删除其它用户内容。沿用验证包严格的未知文件和清单所有权门，不通过放松 sidecar 检查接纳用户数据。隔离安装恢复测试分别证明安装前已有和安装后产生的用户目录、配置及无关文件均保留原字节。

沿用 [可重复构建入口](可重复构建与项目骨架.md)，新 profile 为 `Phase0VSettings`，包 ID 为 `phase0v-settings-<FULL_SHA>`，ZIP 为 `JueMingR-Phase0V-Settings-<FULL_SHA>.zip`，附独立的[配置保存测试卡](../../scripts/phase0s/Phase0V-Settings-Owner-Test-Card.zh-CN.md)。测试包来自 clean commit，记录来源和完整构建身份、长度与 SHA-256，并使用同 profile 核验包字节复现；包内不含真实数据、游戏引用、Legacy 或私人路径。原群系/F5 的验收不替代本次持久化验收；游戏安装及项目所有者亲自实机仍须对应授权。

## A2. 已接受的笔记数据布局

[Issue #42](https://github.com/Kuroneko2020/JueMingR/issues/42) / [笔记实现设计](笔记功能实现设计.md) 使用已验证游戏根下 `JueMingRData/notes/notes.json`。UTF-8 无 BOM；当前写入 schema 2，兼容此前 R schema 1。单份保存有序 ID、标题、正文、悬挂位置/背景与每篇阅读区域/字号；正文不放入 config，不扫描或导入 Legacy。

一个文档后台 owner 串行处理明确命令，包含未领取结果时也只接受一个，不覆盖合并新建/删除。阅读偏好另以每篇一个最新意图有界合并，不提交活动草稿；写入基于最新可靠正文，失败/退出保证见实现设计。机械核心 `AtomicFileDocument` 继续供原配置以 64 KiB 和原偏好策略使用；笔记 schema 1 上限仍为 16 MiB，schema 2 增加 64 KiB 元数据余量，字段与篇数上限不变。

schema 1 整份可靠读取后，第一次真实写入前保留精确原字节到 `notes.json.schema1-original`；该档案不随普通 `.bak` 轮换，不覆盖冲突档案。加载与安装不预先升级。`.bak`、`.tmp` 与该原件档案均为恢复材料；正式文件缺失但任一存在时，不建立空白替代。未知字段、较新 schema、部分/损坏文件与外部变化整份保护。

提交以正式文件/实际备份核验为准；不确定提交停写并显示最后可信内容。失败时保留完整 notes 目录再判断，不能套用“只移走配置恢复默认”。程序回退不等于数据回退：不为旧 DLL 自动降级或用旧档案覆盖后来的笔记。安装、恢复和重置配置保留整个 `JueMingRData`。固定接受对象、实际安装和验证限制查 #42；本节不将接受扩大到未覆盖场景。
## A3. 物品自动处理的独立配置

[#46](https://github.com/Kuroneko2020/JueMingR/issues/46) 的开发候选在同一已验证游戏数据根下使用 `config/features/item-automation.json`；它与已接受的群系、UI、笔记文档分别加载、保护和保存，不修改它们的 schema 或数据。产品实机接受仍由该任务的固定候选证据决定。

UTF-8 无 BOM，`format` 为 `JueMingR.ItemAutomation`，当前写入 `version=3`。业务字段为 `stackEnabled/sellEnabled/discardEnabled`、`sellTypes/discardTypes`，展示偏好为布尔 `discardFeedbackEnabled`。首次三项关闭、出售 `[2337,2338,2339]`、丢弃 `[]`、提示开启。所有者在 #46 本次修正中撤除三项绑定，改用页面控制；新设置和写入不含绑定字段。严格读取合法已知 version 1/2 时保留原业务字段并将新增提示设为 true；version 3 必须完整包含合法提示字段，不将缺失或坏数据作为旧格式补齐。

合法已知 version 1 的 `stackBinding/sellBinding/discardBinding` 只在严格解码边界校验 Int32 存储形状并丢弃，非零值不会注册或执行按键。完整读取后，首次真实保存前由既有 `AtomicFileDocument` 精确保留源字节到 `item-automation.json.schema1-original`，档案不随 `.bak` 轮换。原件档案冲突、临时文件、外部变化等均拒绝覆盖；正式文件缺失但有 `.bak`、`.tmp` 或该档案时不创建默认替代。读取和程序安装不自动升级，不直接编辑真实用户 JSON。

合法 version 2 第一次真实保存为 version 3 时仍走既有原子替换，`.bak` 精确保留被替换的 version 2；普通后续保存继续轮换上一原件，不新增永久旧格式档案。提示切换与其它偏好共用同一保存 owner；配置相等包含提示，业务相等仅比较三开关和两名单，所以改变提示不清理来源资格或重置业务尝试。隔离文件迁移与重启检查不等于真实安装或用户配置已迁移。

文档上限64 KiB，名单按当前目标物品集合校验、按 type 去重并排币。不可变值按内容相等，不保存来源、槽号、会话、网络请求或错误历史。缺失使用默认但不自动创建；损坏、未知字段、较新版本、重复非法结构、并发冲突与不可靠 I/O 保留原件并禁止写回。读取受保护后，用户显式修改可在本次内存生效并提示未可靠保存。继续复用 `PreferenceDocument` 与 `AtomicFileDocument` 的独立工作线程、合并保存、锁与原子替换，不在绘制/输入回调等待文件操作。

## A4. 统一快捷键的独立文档

[#51](https://github.com/Kuroneko2020/JueMingR/issues/51) 开发候选落实 `JueMingRData/config/hotkeys.json`；目标已接受，实现待所有者实机接受。首轮四项均默认未绑定；安装不创建该 JSON，首次实际设置才保存，不改已有 UI、群系、物品开关/名单或提示文件，不读取退休的 Legacy 热键字段。

格式为 `format: JueMingR.Hotkeys`、`version: 1`、`bindings` 数组；条目用稳定 `action` ID 和无歧义 `binding` token 字符串，空串表示未绑定。同一游戏安装共享这一文档，不按页面/角色/世界另建镜像。组合语法、显示与设备限制由[实现设计](统一快捷键实现设计.md)和[行为合同](../功能介绍/统一快捷键功能行为合同.md#78-r-开发候选的使用与边界)唯一规定。

HotkeyBindings 持有有效表和提交结果，复用 DocumentWorker 与 AtomicFileDocument。只有可靠 Saved 才换有效绑定；接受槽忙时拒绝覆盖，关闭窗口仍让已提交的操作安全收尾。普通明确失败可重录；替换后未知、外部变化或既存恢复材料保护原件，不假称磁盘回滚。结构损坏、未知字段/版本不覆盖；合法未知动作保留但不分派；非法或重复动作及同场景重复组合禁用相关项，不按行顺序挑赢家。必要锁、临时与备份仍沿机械文档同目录约定，安装/恢复保持用户数据。

原版键位只在编辑候选/最终提交时核查，不进入自己的文件；启动加载不重新审查原版。用户后来改原版造成重叠时不会自动提示或禁用。测试在初始化 worker 前隔离数据根，包含真实文件、未知提交和外部冲突；任何测试结果均不把用户配置或游戏实际验收当作自动检查的一部分。
## B. 后续数据分区建议

本部分保存项目所有者要求保留的方向讨论。除 A 中两个配置文档、A2 已接受的笔记、A3 物品候选及各自必要辅助文件外，以下目录与文件尚未实施，不构成交付门，也不授权全部未来功能。

外层优先按功能或数据职责分区，内部再按全局、角色、世界、角色×世界等自然归属细分。下树是逻辑建议，未来具体文件名、schema、身份算法和存储格式由相应功能任务决定。

```text
JueMingRData/
├─ config/
│  ├─ settings.json
│  ├─ ui.json
│  ├─ hotkeys.json
│  └─ features/
├─ notes/
├─ blueprints/
│  ├─ templates/
│  └─ instances/
├─ footprints/
├─ markers/
├─ records/
│  ├─ deaths/
│  ├─ playtime/
│  └─ exploration/
├─ identities/
│  ├─ players/
│  ├─ worlds/
│  └─ player-worlds/
├─ behavior/
├─ travel/
├─ backups/
├─ exports/
└─ logs/
```

| 职责与建议位置 | 要保留的语义与待决定边界 |
| --- | --- |
| 全局配置/UI：`config/settings.json`、`config/ui.json` | 保存用户选择，不汇集全部功能字段或运行状态 |
| 功能配置、名单和预设：`config/features/` | 按稳定功能职责组织；简单名单可在功能文件内，真正独立且复杂的多份预设以后再考虑子目录 |
| 快捷键：`config/hotkeys.json` | 已在 A4 落实为 #51 开发候选；统一绑定语义，待实机接受，不由各功能保存镜像 |
| 笔记：`notes/` | 已在 A2 落实为本轮获接受的单份完整文档；首轮没有时间字段或旧导入，具体格式与恢复以笔记设计为准 |
| 蓝图：`blueprints/templates/`、`blueprints/instances/` | 分开可复用模板和绑定具体世界的实例；实例的世界或角色×世界归属、模板快照和进度以后确认；保存进度不授权重启后盲目重放放置动作 |
| 身份与关联：`identities/players/`、`worlds/`、`player-worlds/` | 保存角色、世界与关联，不复制原版角色或整个世界存档；显示名不是唯一身份，路径及其哈希不能未经证明作为永久身份。各功能引用同一可靠识别结果，不各自猜测；身份不明不自动合并、不写共用 `unknown` 桶；多人服务器与世界身份由对应任务明确 |
| 足迹：`footprints/` | 按角色×世界隔离的长期路径记录，与小型配置分开，避免混合频繁整份重写 |
| 地图标记：`markers/` | 单独保存用户创建的标记；世界共享或角色×世界私有由功能合同决定 |
| 历史记录：`records/deaths/`、`playtime/`、`exploration/` | 死亡、游玩时间、探索分别组织；分清原始事实和派生摘要，不让两套统计独立累加 |
| 行为记忆：`behavior/` | 例如某角色在某世界打开过的箱子，是事实记录，不能作为全局共享偏好 |
| 特殊恢复状态：`travel/` | 旅行菜单等由具体功能规定有效期、身份与恢复条件，不按普通设置在启动时无条件应用 |
| 备份、导出、日志：`backups/`、`exports/`、`logs/` | 与用户内容分开；备份和日志有保留边界，导出由用户主动触发，不制造每次运行的全量归档；本轮文档同目录 `.bak` 不因此迁入未来 `backups/` |

同一事实只有一个主要存储位置，不能因目录增多而重复保存。Session 状态、鼠标捕获、执行队列和可重建缓存默认不持久化。重置配置不删除笔记、蓝图、足迹或历史；清理日志或缓存不删除用户内容与身份关联。安装、更新、恢复和卸载默认保留用户数据。

Legacy 原件继续只读，不自动导入、移动、覆盖或删除；后续按 ADR-0009 逐功能评估价值、语义和风险，不承诺全量旧格式兼容。功能真正开始时，同一任务更新本节对应建议，将其细化为正式功能合同或明确替代，不能让旧建议一直冒充当前实现。
