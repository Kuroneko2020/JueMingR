# 高频路径修复与工作量回归

本设计对应 [Issue #67](https://github.com/Kuroneko2020/JueMingR/issues/67)。所有者已正式接受候选 `df7de7f0cbdc948853ec21aac60f6c7ee3d4cb43` 的三个高频路径修复、本地自动工作量回归及维护责任；自 [PR #68](https://github.com/Kuroneko2020/JueMingR/pull/68) 合并进入 `main` 起纳入正式基线。复用 [#65 调查报告](https://github.com/Kuroneko2020/JueMingR/issues/65#issuecomment-5653239652)，不开展全仓重调查。保持六个生产项目、唯一领域状态 owner、net472/x86 与锁定原版引用，不增加依赖、性能平台或服务器端合并权限门。

接受及对应验证、独立审查、完整包与安装身份见 [#67 集中交付证据](https://github.com/Kuroneko2020/JueMingR/issues/67#issuecomment-5654414857)和该任务的接受收口记录。文档最终化与主线合并不改写原安装来源或回执，也不把原候选检查记为新 SHA 的重新执行。接受不扩大为全部实机、Windows/IME、显示/材质组合、多人或 FPS 验证通过；实际未覆盖项继续保留。

## 三个修复责任

- **Notes**：`NotesPresentation` 识别内容/编辑、资源/尺寸、光标和页面投影变化；`NotesCards` 在原稳定 ID 映射中保留卡片和控件，把结构/局部布局与可见正文推进、光标定位分开。主滚动允许遍历可见性，但不重建每篇相同控件/标识；正文内部滚动不替代主滚动。真实高度变化仍更新必要排布，长文共用预算并最终完成。复用控件后，按下时必须保存独立的命中几何/文字与代次，滚动/窗口/布局变化使旧点击失效，不能拿同一可变控件与自己比较。
- **样式**：`StylePopup.Close` 取消一次并退休旧 Editor，捕获和释放尾缘仍独立收尾；`StyleEditor.PreviewHsl` 在完整草稿状态同值时保持稳定。Hue 记忆、首次真实 HSL 动作、HEX 半草稿和错误清除均有语义，不仅比较 RGB。有效释放、六位 HEX、目标独立的异步保存不变。
- **开过记录**：`OpenedPositionStore` 保留唯一待重试批次，由 worker 独占合并，gate 内只交接引用/配额/有限状态；不让游戏线程处理整批，也不在锁外并发改 Pending。保留在途新增、去重、Deferred 冻结段实际占用、overlay 退役、有限重试、未知提交保护及 Stop 边界。重复已准入事实可用现有 Accepted/Current/最多8个冻结索引判断，游戏线程不查询正在合并的可变批次。

## 回归性质与独立判定

先在旧实现取得直接失败，再修复并保留相邻行为反例：Notes 少量/多篇、冷排版后光标/选区/主滚动/正文滚动及真高度/字体/宽度变化；样式通过真实 F5 壳层关闭和真实滑杆输入验证同值、真移动/释放、Hue/HEX/失焦/切目标；记录以受控事件停在实际失败批次整理阶段，前台真实读取/登记先完成，再释放后台，且最终数据/配额正确。超时只防死等，不以微秒阈值判性能。现有 #64 稳定排序、移动与同 key 载荷回归继续有效。

计量挂在真实工作位置或观察对象身份，少量条件编译挂点仅用于检测产物；缺挂点、无匹配组、错误运行时、缺依赖或二进制身份不符不能假绿。普通 Release 不含测试挂点或禁用开关控制的常驻诊断。工作量减少必须和正确性同时成立，不外推实际 FPS。

## 本地自动入口设计

`build.ps1` 是正规构建与检查门；完整开发包沿既有 `build-phase0s-validation-package.ps1` 的 Release/RequireClean 链继承。薄 `test-workload-regressions.ps1` 只消费明确构建根，不调用 build 或现有会自行 build 的整套脚本；原慢图形/计时入口保持独立。复用现有 ArchitectureTests、Phase0SFixtureTerraria 的 Notes/样式/输入组、NativeWorldTextProbe 的真实 Host 组合，不新增测试框架。

普通 Debug 使用本次产物；Release 的工作量观察使用同源码 Debug 产物，核对已有构建记录的输入身份与输出哈希后可复用，但所选检查本次重新执行。不匹配才顺序构建所需 Debug，普通 Release 仍独立验证和打包。检测 EXE/依赖与普通载荷分目录，构建与检查前后核对源码输入，结果写入既有构建记录而非新台账。

核心为便宜的幂等/局部失效/排序/并发不变量；相关 Host 按完整基线 diff 加暂存、未暂存和非忽略新文件选择，删除/重命名检查两端。Notes、共用样式、记录、公共文件/worker、F5/输入/字体、世界观察分别带上实际代表消费者；测试/脚本/项目规则变化保守选全部确定性 CPU 组。纯无行为文档不触发慢图形或时间测量；未知路径或基线不可得至少核心并明确风险判断缺口，不能返回零项通过。

检查失败须让正常入口非零退出，阻止成功构建记录和后续包/ZIP发布为成功。通过旧实现失败或隔离最小故障实际验证退出码传播，不以脚本文本存在某命令为证据。本地入口约束不是不可绕过的 GitHub 权限保证。

## 维护与交付

新增或实质修改高频能力由对应模块/测试维护者补少量可执行的关闭、稳定、局部变化、规模/异常恢复场景；公共修改带上消费者。判定、阈值、跳过或路由变化在当前 PR 单独说明并独立审查，不以新实现自己的结果作为唯一正确答案。低价值检查可在说明原因并保留替代覆盖后删除/替换，不建立永久性能数字总账。

最终候选须有红后绿、正规入口和路由实跑、适用 Debug/Release/Host/存储与代表预览、独立增量审查及干净固定包身份。安全安装保留全部用户内容/偏好/历史与恢复材料，不读写真实 JSON、不自动开功能或启动游戏。图形设备创建前的已分类环境限制如实保留，真实失败不能借此豁免。

## 自动入口与维护位置

在仓库根运行：

```powershell
powershell -NoProfile -File scripts/build.ps1 -Configuration Debug
powershell -NoProfile -File scripts/build.ps1 -Configuration Release -RequireClean
powershell -NoProfile -File scripts/build-phase0s-validation-package.ps1 -Profile WorldObjectText -OutputDirectory <全新目录>
```

比较基线默认 `merge-base HEAD origin/main`，可用 `-WorkloadBaseline <commit>` 明确指定审查起点。独立重跑 `scripts/test-workload-regressions.ps1 -Baseline <commit>` 只接受匹配的 Debug 构建；不自动从头构建。它编译/运行两个小型既存 Host 夹具，普通载荷与夹具 DLL 位于不同目录。

| 触发 | 自动组与代表 |
| --- | --- |
| 所有正规构建，包括纯文档 | 核心：Notes 卡片/输入、两种样式能力、记录重试并发、#64 排序与真实 Host 世界呈现/关闭 Shell |
| Notes | 核心加焦点输入、快捷键/弹层消费者 |
| 共用样式 | 核心中的颜色-only 和颜色+字号真实输入/保存消费者及已编译 Shell |
| 开过记录 | 核心记录并发；ArchitectureTests 保留格式保护、Deferred、跨 pair、有限退出 |
| 死亡记录、世界天数，以及公共Host/存储路径 | `death-host`：ArchitectureTests `--death-history`、NativeWorldTextProbe `DeathCpu`、真实输入夹具 `death-popup`；包括完整Host、N=128/8192、P=6/K四档、真实地图CPU循环与保存失败/迟到结果 |
| 公共文件/worker | 加 Notes、绑定和普通偏好真实文件/并发代表 |
| F5/输入/布局/运行接入 | 加相关窗口、悬挂/物品输入、信息行及世界观察/投影 |
| 测试、脚本、项目/构建规则 | 保守加全部上述 CPU 组；入口/路由自身变化再执行小型 Git 差异夹具 |
| 未知路径/无比较基线 | 至少核心，然后失败要求补足风险判断 |

`scripts/workload/Workload.Support.ps1` 维护保守路径路由及当前输入指纹；`test-workload-regressions.ps1` 维护组到既有执行模式的映射。指纹包含全部非忽略跟踪/新文件的相对路径与字节，删除记缺失；构建记录 schema 3 仅增补此身份、比较基线、实际组、运行时、结果和检测输出哈希。构建开始/结束核对输入，未完成的记录为 PENDING，失败写 FAILED、失败项与已完成结果；包明确要求同提交 PASS。Release 缺少匹配 Debug 记录/输出时只由 build 编译一次检测变体，不递归调用整个构建入口。

CPU 测试使用无纹理字体或原版 headless 初始化能力，实际闭合的 F5 Shell 输入、异步原子文件与 source-linked UI 控制均保留生产方法；没有游戏循环或真实用户文档。它们不证明 XNB 外观、GPU 命中、实际输入法或多人验收。`scripts/test-phase0s.ps1`、`scripts/test-world-object-text.ps1 -Scope Full` 和原有 `phase0u-visual`/Notes 原资源预览仍是按任务风险单独触发的入口，不嵌入每次核心构建。

Notes 几何次数、记录重试坐标访问回调由相应生产类的 DEBUG 编译段拥有；现有 #64 DEBUG 排序/修复计数继续复用。功能换实现时由该模块实施者更新真实观察点和反例，审查缺探针失败及 Release 缺席；不得以固定零值或改期待来保住绿灯。具体首次捕获、耗时与交付身份查 #67，不在本设计累计执行流水。

死亡组观察实际页读取/原子根写入、稳定结果/行/候选引用、弹窗布局及生产投影/绘制调用位置。稳定2000次相同请求不得重读页或写根；只换原因不得重取K候选；地图N=1040、每档20轮恰做20×K次投影，屏外不补旧点，当前降低数量立即约束旧大结果。有限负对照强制markers缓存每次失效，正规build必须非零；测试结束按原始字节恢复。地图检查仅隔离GPU资源读取和末端draw，不改变业务循环；`DeathVisual`保留原资源预览入口，设备创建前的环境延期不能变成像素或完整地图共存PASS。详细实现/边界查[本批设计](死亡记录世界天数与地图死亡点实现设计.md)，动态证据查#81。
