## 三个修复责任

- **Notes**：`NotesPresentation` 识别内容/编辑、资源/尺寸、光标和页面投影变化；`NotesCards` 在原稳定 ID 映射中保留卡片和控件，把结构/局部布局与可见正文推进、光标定位分开。主滚动允许遍历可见性，但不重建每篇相同控件/标识；正文内部滚动不替代主滚动。真实高度变化仍更新必要排布，长文共用预算并最终完成。复用控件后，按下时必须保存独立的命中几何/文字与代次，滚动/窗口/布局变化使旧点击失效，不能拿同一可变控件与自己比较。
- **样式**：`StylePopup.Close` 取消一次并退休旧 Editor，捕获和释放尾缘仍独立收尾；`StyleEditor.PreviewHsl` 在完整草稿状态同值时保持稳定。Hue 记忆、首次真实 HSL 动作、HEX 半草稿和错误清除均有语义，不仅比较 RGB。有效释放、六位 HEX、目标独立的异步保存不变。
- **开过记录**：`OpenedPositionStore` 保留唯一待重试批次，由 worker 独占合并，gate 内只交接引用/配额/有限状态；不让游戏线程处理整批，也不在锁外并发改 Pending。保留在途新增、去重、Deferred 冻结段实际占用、overlay 退役、有限重试、未知提交保护及 Stop 边界。重复已准入事实可用现有 Accepted/Current/最多8个冻结索引判断，游戏线程不查询正在合并的可变批次。

## 回归性质与独立判定

先在旧实现取得直接失败，再修复并保留相邻行为反例：Notes 少量/多篇、冷排版后光标/选区/主滚动/正文滚动及真高度/字体/宽度变化；样式通过真实 F5 壳层关闭和真实滑杆输入验证同值、真移动/释放、Hue/HEX/失焦/切目标；记录以受控事件停在实际失败批次整理阶段，前台真实读取/登记先完成，再释放后台，且最终数据/配额正确。超时只防死等，不以微秒阈值判性能。现有 #64 稳定排序、移动与同 key 载荷回归继续有效。

计量挂在真实工作位置或观察对象身份，少量条件编译挂点仅用于检测产物；缺挂点、无匹配组、错误运行时、缺依赖或二进制身份不符不能假绿。普通 Release 不含测试挂点或禁用开关控制的常驻诊断。工作量减少必须和正确性同时成立，不外推实际 FPS。

## 本地自动入口设计

`build.ps1` 是正规构建与结构／覆盖门；ArchitectureTests `--structure` 只含结构断言。`CheckCatalog.cs` 将原默认入口的业务、存储、并发及 Biome 断言按唯一检查 ID 登记，`--list-checks` 提供实际清单，`--check <ID> <root>` 执行一项；默认 `<root>` 仍可主动完整执行。多个消费者命中同一 ID 时计划只列一次，独立 profile 的实际 Host 场景分别保留。

薄 runner 只消费已核验 Debug 构建，缺产物不递归构建。实际需要 Host 检查时才编译两个既有夹具，全部数据保持现有隔离。正规 Debug、Release 与完整包共享本地 `artifacts/build/workload-evidence.json`，每个检查保留原执行提交、源码指纹、参数签名、实际产物哈希、时间和 executionId。结果被复用时不重新运行相同检测。

输入身份记录全部非忽略跟踪／新文件及缺失文件的精确字节；行为证据排除 docs 与根说明文档，仍包含生产源码、断言、fixture、脚本、项目及构建配置、固定外部依赖、SDK、x86 Framework 与相关环境选项。每检查使用明确职责投影：现有页面组合、后台两种状态、工具节奏及工具工作量叶子夹具，以及两项 PowerShell 自检，只进入其实际 CPU 消费者的指纹。生产、共享 helper、分派器、项目、选组及构建规则继续作为共同输入。叶子增加共享职责或新消费者时必须同改映射；不能只因同程序集变化使无关叶子证据失效。未知边界先保守验证并补分类，不建立任意语义分析平台，也不宣称所有领域已经支持细粒度复用。页面组合还被 ToolsVisual 使用，图形专项不进入这个 CPU 缓存。

每项保留完整原输入清单和原执行身份，复用时重新计算相关输入投影；本地有界产物快照保存原执行的精确字节，含运行配置与依赖集合。新编译的元数据可不同，但旧执行不冒充新程序集实跑；当前 Debug 与 Release 构建产物各自仍须通过实际哈希及结构门。相同构建的现存夹具变更会失效；跨已证明无关的叶子修改或提交元数据时，核对原快照，现存运行配置和目录集合仍须匹配。重新编译后尚未需要的夹具可以只保留原快照。任何缺失／损坏原快照都重测。不得删除注释、抹 SHA 或改写身份来假定等价。

一次运行在开始、完成及失败保存边界核对输入、依赖和产物；输入变化不给合格记录。旧 schema 缺事实时重新验证，不迁成 PASS。失败或取消先撤销该项旧成功，已证明稳定且完成的其它项可以保留；缺项不能以任意数量 PASS 代替。原执行、复用、未选、失败／延期分别呈现，图形及真实原版链证据不能由 CPU 结果替代。

```powershell
powershell -NoProfile -File scripts/build-phase0s-validation-package.ps1 -Profile ContinuousProcessing -OutputDirectory <全新目录>
```

Related 默认用 `merge-base HEAD origin/main` 的累计变化，加暂存、未暂存、非忽略未跟踪和删除／重命名两端；额外 `WorkloadBaseline` 不能缩掉主线范围。Feedback 只回答显式范围，不得用于打包。Full 保留所有已登记 CPU 组；未知路径或基线缺失先明确失败要求补分类或必要判断，不先浪费一轮再假绿。主线变化要重新计算最终义务；分支名、HEAD^、最近一次 PASS 均不是自动新基线。

`Workload.Support.ps1` 维护有限职责路由；`Workload.Evidence.ps1` 负责实际计划、身份、覆盖和复用判定；`test-workload-regressions.ps1` 执行并记录。原测试／脚本公共入口变化仍保守选较广集成组，不等同任意新路径默认全量。

日志列比较依据、路径／组、所需检查、执行／复用／失效／未选与原耗时。schema 4 build-record 的 coverage 绑定本次候选，复用项仍指原 executionId。打包消费同一判定，核对所需集合、实际 DLL 与依赖，在 staging 提升前再次验证；Feedback、FAILED、PENDING、旧格式、缺项和不匹配一律不可交付。

## G10 钓鱼与配装检查

[#109](https://github.com/Kuroneko2020/JueMingR/issues/109) 的 `NativeFishingObservationChecks` 由既有 `NativeFishingChecks.FullLoop` 调用，随 `FishingCpu` 正式执行；`NativeFishing*` 路由和 SDK 隐式编译已覆盖新文件，不新增 runner。历史“全部消费者关闭”的断言保留，不能替代新“设置开启但未触发”的证据：Auto、Loadout、Equipment、Store 1/2 分别在非鱼竿和持竿场景推进 120 次真实 Player/Projectile/Runtime 更新，分开记录初始化与稳定区间实际 `Observation.Read` 的 `Scans`。需求判断只核已有身份，创建回调只失效，不把扫描迁到另一入口。

同组新增实际延迟/失败首抛、首次入液、停止后再抛、手动接管、显示独立启停/已有漂发现、单次 Current 查询和槽/会话退休；650 次 Host 更新保留一个原版创建的干飞漂，专门拒绝任意飞行超时，该段不声称推进了原版飞行 AI。G09 使用实际借用 token、既有完成边界和原版补抛验证观察暂停/同会话恢复，不代替图形入口的虫网命中。装备归还用例保留真实临时装备和阻挡归还的鼠标物品，核对关闭自动后仅归还责任的 120 次更新无扫描，再经原版更新精确归还。拉抛/切杆、在途产物与存鱼继续由已有用例覆盖；计数结果不是 FPS 或日常实机结论。

后台拉抛及自动存鱼夹具在真实首次入液/Waiting 时注入指定咬钩，不固定等待 150 步后假定仍未咬钩。原版可在该等待段自然拉起；对已返回的漂覆盖 ai[1] 会破坏原生产物，形成错误反例。修正只约束测试预置，原产物、存放和重抛断言保留，不冻结生产 RNG 或改变游戏计时。

G10 本轮修订在同一 `fishing-host` 组增加 `BackgroundCpu` 和 `F5AutomationCpu`，沿真实 Host 装配验证物品、存钱、恢复/服务及提炼的后台和前台 F5 悬停实际结果、陈旧 Draw 状态、暂停/空外层更新及手动所有权。自动钓鱼保留独立 F5 门；工具完整 Player.Update 用例验证采集和借网补抛在 F5 打开时继续。新测试只用隔离角色/世界和网络出口，不能充当日常实机或多人接受。此轮按所有者要求仅运行受影响检查，不打包/安装或执行全量审计。

`fishing-host` 选择 Features/Host 的 Fishing、ArchitectureTests/Fishing、NativeFishing 与 NativePlayerRename；已有 `NativeFishingBorrow` 仍先归 G09 tools-host。tools/shared/storage 的真实提供者变化带上 fishing，直接使用的 Text 与 NotesClipboard 同样保留消费关系；局部 Fishing 不反向扩成 shared。正常 runner 在本组执行 `--fishing`、`FishingCpu`、`BackgroundCpu` 与 `F5AutomationCpu` 各一次，并执行公共短提示检查；实际 Git 单文件、混合、重命名/删除及 dispatcher 参数、失败退出由 routing-contract 核对。接受状态见 [#107](https://github.com/Kuroneko2020/JueMingR/issues/107)。

CPU 断言覆盖全部关闭且无归还尾部时零 projectile、水体、装备来源与规则读取；稳定布局不重建/不查询水域，稳定装备不重新规划/交换，成堆渔具及来源变化恢复规划。目录的 `RuleChecks` 只计谓词调用；`ShapeReads`/`VersionReads` 另计周期规则形状、物品项和条件读取，不能以谓词缓存命中推导零目录开销。每 30 个模拟更新复核水域，实际 TileReads 在读取处计量；真实环境变化后候选失效。0/1/3 无输入外层回调不增加钓鱼动作或消耗模拟机会。

同入口还检查共享存放优先序、真正零入包溢出、部分容量及有限成员退役，原版客户端序列化与 `MessageBuffer.GetData` 的关闭/F5、重复、超时晚包及未知责任；临时装备实际拆分/交换、共享投影、较晚意图、死亡及隔离保存边界；单人改名实际 Rename/SavePlayer、本地只读校验和测试专属重载、云服务边界替身，以及真实字符队列的编辑确认/取消。夹具没有服务器或真实云账户，不把这些结果写成多人/跨设备同步通过。

`NativeFishingOutcomeChecks` 另经真实水、蜂蜜和熔岩碰撞及原版条件构造，执行消饵/保留、断线、两种随机多堆鱼及敌对/友好 NPC 产物，每次观察到替代鱼漂重新入液即结束本次鱼获窗口。随机数只在三个实际消费方法内暂换独立原版 RNG，原方法正文决定结果；咬钩由夹具提供，不据此声称自然等待时间或概率已验证。NPC 保留原版生成与状态，仅隔离成就末端和不参与该断言的纹理初始化；没有推进 NPC 长时 AI。装备检查同时核对完整原版玩家更新后的实际钓鱼加成，不能只以规划分数证明效果。

显式 `FishingVisual` 使用真实 XNB 字体和纹理，在正常、150%、短窗、最小逻辑高度核对主窗及浮层；经真实 F5 完成七个键盘图标双击、公共录入器、可靠保存和真实按键派发。G10→G09 借网→G10 恢复另在该图形入口执行原版虫网命中及捕获链。普通 CPU 构建不隐式运行慢图形。以上轻量计数不写盘、不采样时间；测试 Harmony 观察只在隔离测试进程存在，候选安装中不包含独立探针或详细观察日志。

本轮 #107 将 `NativePageCompositionChecks` 纳入独立 `pages-host` 选组（工具／公共变化仍带上本组），并由现有工作量入口执行 `PageCompositionCpu`：检查两页完整组合、末尾游商位置及稳定布局复用。字体/缩放与真实图形资源点击另用既有 Tools/QuickItems/CoinDeposit/Processing Visual 检查，不将 CPU 布局证据称作实机验收。

## #112 输入事故查证续办的有限证据接线

本轮沿现有runner/Evidence/Support交付子项真实回执与单独稳定性资格，不新增测试流水或依赖平台。正常退出立即持久化的原件保留executionId、命令、实际退出/时间、输出SHA与产物前后身份；全批稳定性尚未核验时不得PASS。下一次入口可核同批锁定输入/产物后取得独立qualification；进行/失败、损坏或缺失latest/资格及未发布.pending拒绝。总coverage未完不能由部分成功升级。当前采用的有限准入身份保存在RUNNING/FAILED、batch与checkpoint根单指针，build在删除Debug前先读；缺损或新候选需要重新审核，不能默认扩大执行。checkpoint存在时保全全部历史归档是本轮保留策略，不是引用精确GC。

固定适用性记录以实际merge-base及附加BASE推导的累计计划核集合，逐原记录自己的输入差异、原ID/源码/命令/归档与当前必要补验关联；Release/包门同样消费。旧完整Strategy加当前rollchoice生命周期补验为QUALIFIED，rollchoice本身只能记该子scope EXECUTED。条件诊断三文件普通OFF依赖真实InputBoundary当前产物证明；未知环境/符号/scope/断言/产物变化、失败或未完成禁止资格。NativeOuterInputBoundary精确走input-boundary组，NpcLifetime走combat并由Strategy-rollchoice真正消费，避免tests通配反向传播无关叶。具体当轮固定范围与结果查#112及历程175；本节不替代逐候选适用性审查或实机接受。
