# 视距解锁实现设计

本设计对应[行为合同](../功能介绍/视距解锁行为合同.md)和 [#124](https://github.com/Kuroneko2020/JueMingR/issues/124)。合同来自本轮明确授权；具体固定候选的运行证据、支持下限和交付身份回到任务记录，不由设计描述推定验证通过。

## 唯一状态与接线

| 位置 | 职责与边界 |
| --- | --- |
| `Features/View/ViewPreferenceCodec` | 只编码 `JueMingR.View` version 1 的 `enabled` 布尔值；拒绝倍率、未知字段、错误类型和版本 |
| `TerrariaHost/View/HostView` | 唯一视距所有者；装配进程级开关文档、加载和保存生命周期，处理原版缩放准入、实际渲染需要与故障 |
| `TerrariaHost/View/ViewZoom`／`ViewRenderPlan`／`ViewOptions` | 单一目标范围、float32/ToEven预测、最终native核对及原选项仅显示夹取 |
| `TerrariaHost/View/ViewTileCache`／`ViewCacheMemory` | 条件性k=z三层缓存；逻辑coverage、按轴容量、old/new峰值准入、原生叶借用和失败资格 |
| `TerrariaHost/View/ViewNativeCoverage` | 足够容量的原生七层仍由Main拥有；早期借用本Draw预测zoom做原coverage，私有批次及异常域同层归还 |
| `TerrariaHost/View/ViewHooks`／`ViewBackgroundScope` | 锁定原版接点、直接绘制和实际光照范围；背景／全屏效果的临时坐标借用在同层恢复 |
| `TerrariaHost/View/ViewNpcCulling` | 只扩大原版DrawNPCs局部粗筛矩形，保留原800世界像素halo与原候选；不更改NPC更新/同步 |
| `TerrariaHost/View/ViewSceneCapture`／`ViewWaterResources` | 原版场景filter物理capture及水面mask/四分之一world波纹buffer的有限生命周期；实际Camera决定覆盖，设备/退出归还 |
| `TerrariaHost/View/ViewLegacyCapacity` | 旧光照额外容量先在独立原版引擎准备，完整后发布精确数组和LightMap；不让活引擎暴露部分数组 |
| `TerrariaHost/View/ViewSectionRequests` | 客机当前实际视口的原版区块请求及有限在途责任；不拥有区块数据或实体同步 |
| `TerrariaHost/F5/ViewControls` | 窄 `IViewControls` 的标准行投影；发送 `SetUnlockEnabled`，不直接访问原版倍率或文件 |
| `F5Layout`／`F5Renderer`／`F5Shell` | 地图 page 2 的共用几何、命中、颜色、提示和命令派发；装配用 `AttachView`，不保存第二份开关 |
| `Phase0SLoadChainHost` | 已有 Composition Root 内装配 HostView 并接入生命周期与原版入口，不建立第二套 Runtime |

`ControlsEnabled` 表示当前是否可以修改开关，`UnlockEnabled` 是当前实际调节许可。标准颜色只读后者：即使关闭后仍处于超范围相机，关闭按钮仍显示红短线。正常布局、颜色和提示读取不发送命令。

`EnableViewUnlock`／`DisableViewUnlock` 是明确命令，位于枚举尾部；`ViewControls.Owns` 只认这两个值，保持 `MapControls` 既有连续命令区间不变。新行放在地图通用功能区、地图标记之前，不进入标记管理、探索详情或足迹回放。公开行不受隐藏资格投影影响。

行名称及说明通过既有 `F5RowDescription`／`F5RowLayout` 传给共同名称提示。没有键盘图标、新绑键注册、滑条、窗口和“打开”命令；这是所有者指定使用原版映射键的接入例外。普通点击静默，错误按原有通道处理，不新增通知系统或 F5 状态行。

## 原版输入与倍率责任

原版 `ViewZoomIn`／`ViewZoomOut` 是唯一缩放动作来源。消费者读取同轮 R 已过滤的映射事实；`HostInputState.AfterMapping` 早于原版缩放消费，而 `CanUseInput` 依赖后来的 finalized，不能直接拿晚阶段许可挡住早阶段消费，也不能提前执行键盘结束采样。

必要的映射阶段只读许可在原输入 owner 就地表达：当前 mapping、真实前台、隔离／重启尾部、文字与录键占用。它不放宽其它消费者，不从 OS 再取按键复活已消费输入。两键同按净变化为零，同次映射只处理一次，按住沿原版节奏连续更新目标。

原版 `Main.GameZoomTarget` 保持目标唯一来源；最终 `RenderZoom`／`GameViewMatrix` 仍属于原版实际相机。输入下限与绘制下限必须同时接受受支持的扩展目标；可见矩形、指点和叠加层使用实际最终矩阵，不能各自从开关或目标倍率猜相机。

关闭不夹紧目标。低于1仅允许每Mapping+.02向1靠近，高于2仅允许−.02向2靠近；向外、两键抵消或无输入均不修改目标。`UnlockEnabled=false` 与 `NeedsExpandedRendering=true` 可以同时成立。开启但仍普通倍率时，不按理论最低倍率分配外围资源。

续办基础目标范围为`.3`—`10`，关闭且已在普通范围时保持原`1`—`2`。原滑条只替换确切`GameZoomTarget−1`显示读取，仍由原版实际按下／rightLock交互写回`1`—`2`；打开或悬停不会写回。`MinimumTarget`还按真实物理长边、原版`ForcedMinimumZoom`及现有512格观察合同（含halo与最终倍率1/128量化余量）提高下限，防止大视口越过现有查询容量。消费者不复制这一产品下限常数；一律读取原版最终矩阵与物理尺寸。

## 坐标、绘制与资源

保持实际物理后缓冲尺寸、UI scale 和全屏地图域。世界可见范围从最终世界矩阵的逆变换获得，物理四角取保守世界 AABB，再按各消费者实际 halo 转成 Tile／光照范围；有限有效性检查阻止零、负、NaN 或无穷进入逆变换。

优先使用原版世界绘制与直接绘制路径，只补真实仍按旧矩形裁切的消费者，不构造第二个世界 Renderer、不长期伪造 `screenWidth`／`screenHeight`。若必要背景内部短时借用原版字段或 batch，正常和异常路径均在同层、同线程恢复准确旧值，其他消费者不得观察伪物理视口。

图格、墙、前背景液体、光照、NPC／玩家／掉落物／弹体及必要全屏效果必须覆盖同一真实视野。已用最终矩阵的 R 世界文字、显名、标记、工具与地图消费者继续各自状态所有权；只修实际受影响接缝。玩家中心候选不再被旧固定 140 格上限截断，仍保留当前距离／碰撞框／模式语义；光标中心半径保持原单位，不扩大武器或交互资格。

图形资源按实际需要和当前设备上限准备、稳定复用，容量或设备／模式改变时才重建；新资源成功后替换并通知真实引用消费者。不得按理论最小倍率预建每个原版 RT，不能每次目标变化重建全部资源，也不能同帧追加 4／6 轮完整光照来掩盖漏区。回普通范围后结束额外责任，退出世界或设备失效时不保留过期快照／GPU 引用。

原版`DoDraw`替换确切目标夹取、直接绘制选择、场景capture资格和必要shimmer填充接点；接点形状不符则回滚本owner安装，不放行半套解锁。Color／White沿原版当前光照范围；Retro／Trippy中仍用未缩放尺寸的容量、处理、清理等接点改用同一实际相机范围。旧光照容量按256世界像素桶增长，稳定倍率不逐帧重建。`ViewBackgroundScope`只在必要原版背景与全屏效果的调用内借用尺寸、位置和batch，finalizer保证异常时还原；不改变真实后缓冲、UI尺寸和其它消费者的坐标域。

`WorldTargetFeature`／`WorldObjectDiscovery`保留预算和容量。相机矩阵代次变化时继续有界、与新视口相交的扫描进度，并以最新可见区重验已发现内容，避免持续缩放不断清零使后段饥饿；真正世界／查询身份变化或不相交时仍清理，未知区仍不可读。世界文字的布局失效与扫描进度分开维护，原先排版拒绝的内容可随新布局重试。玩家中心候选以实际矩阵四角计算范围，移除旧140格历史夹顶；光标中心单位、武器／交互权限和预测模型不变。

普通客机沿原版合法区块请求和实际响应，必要请求必须去重、有上限、可退出本地跟踪；未知 Tile 保留未知。实体仅显示本客户端实际收到的活对象，不改变服务器同步、生成、AI 或退场。假 `netMode` 场景只证明模拟边界，不能写为真实联网。

`ViewSectionRequests.Update`只在实际客机已入场、世界视口需要扩展时工作，跳过全屏地图和fancy UI。可见section由`Main.Camera.ScaledPosition/ScaledSize`加必要tile halo取得；每次更新最多发一个原版`MessageID.RequestSection`（锁定.8为159），固定16槽，同区在途去重。原版服务端`MessageBuffer.GetData`→`NetMessage.SendSection`按世界边界与该连接发送记录处理，客机原版包10 decoder才置loaded；本功能不改loaded位。视口移开只释放本地槽，不撤回TCP；同区300次更新未收或SendData异常使额外请求局部停止并一次反馈，回普通视野／非客机／会话结束清理责任。开关OFF但实际仍宽时继续按真实视口工作。

区块回执不刷新服务端按玩家位置的section活跃时间，也不赋予远处实体更高同步频率。普通实体收包／存活／退场继续由原版维护；本功能既不请求全世界，也不修改服务器、玩家位置或生成／AI范围。

## 偏好生命周期

`config/features/view-unlock.json` 属于当前已验证游戏根下的 `JueMingRData`。文档缺失使用 `false`，不主动生成默认文件；`PreferenceDocument<bool>` 继续拥有偏好与 revision，`AtomicFileDocument` 负责 64 KiB 上限、有界读取、同目录原子替换、备份、锁定和冲突／恢复材料保护。UI 只读快照和发送窄设置命令。

保存只由真实开关变化请求，目标倍率、实际矩阵、Retained 与资源都不编码。坏格式、未来版本、未知字段、加载超时、外部变化和未知提交沿已有保护状态；本次内存选择与磁盘保存可靠性分别报告。进程退出只处理已接受请求并遵守有限等待，不在 Draw、输入或逐帧回调执行磁盘工作。角色／世界切换不另建偏好镜像，不增加倍率恢复服务。

## 续办的实际缓存路线

本节对应`JMR-VIEW-CACHE-RANGE-20261018-v1`，从已交付3ea继续。当前实现没有七层1:1 world缓存；七层仅定向核对原版七对象、分组、background swap/pending及设备/内存模型。Reach1920×1080实测profile下，50%最小4224×2544、30%最小6852×4022的轴尺寸排除该路线，没有调用原InitTargets尝试OOM。原Init失败会改Retro/map并SaveSettings，不能作为可选缓存准入探针。

当前生效路线为Color／White实际wide中的tile、tile2、wall三层k=最终RenderZoom。Reach保守cap2048，HiDef保守cap4096，原版8K反射资格不自动将本cache cap改为8192；不符合时direct。产品从不设置profile；隔离原版SetGraphicsProfile验证与所有者真实profile分别记录。没有实测的物理8K／其它设备不由数学面积推定通过。

`ViewRenderPlan`区分目标、forced、raw与量化render，以及Translation/WorldSize；稳定请求复用同一几何计划，route变化只更新窄不可变投影。早期原版drawToScreen选择读取该计划；缓存仅在62952最终zoom发布之后验证真实尺寸、RenderZoom与Translation，不能把临时叶尺寸传播给Combat、世界文字或区块请求。

三层纹理每轴独立保留足够容量；先创建完整新组，旧组仍活时按old+new理论RGBA8峰值及当前可用虚拟／物理内存准入，另留64MiB局部余量。该余量不是全项目预算、VRAM实测或避免一切驱动失败的保证。P从192按16世界像素档收窄到可容纳的halo，不裁可见区、不使用k<z；当前Reach50%实际P128、30%P192。新组完全准备后才替换，三层成功首填后一次借出Main的三个真实字段，finally只归还仍指向自己的别名。targetSet、原七层其它字段和background pending继续原生所有权；wall叶的ApplyPendingBackgroundTargetSwap只在本缓存逻辑scope内跳过，不能提前消费未拥有的background swap。

逻辑world coverage与物理小RT独立保存，不沿WorldSceneLayerTarget.UpdateContent从纹理尺寸反推世界范围。首填／coverage／失效及原renderCount3决定三层刷新；Main的renderNow在62806先清，而本缓存晚于最终zoom，故早route接点按本Draw快照该请求，由Prepare消费一次。退出、异常、菜单和未缓存分支清除该快照，不能沿用上一Draw。快照或原group3已使内容失效时，先清每层valid；即使该帧因分数相位走Direct，dirty也保留到对应叶成功Fill，不能因回到旧相位复用dirty前样本。没有新增每Draw计数器代替原Color光照组时钟。

k=z存储的是最终输出点样本。Coverage足够仍不能复用分数输出相位变化后的图像；连续移动／调整时可保留旧组并correct direct，稳定一个native Draw间隔后再准备。回到已有正确相位的有效样本可直接复用。这样不为移动每帧支付整组Fill再Composite，真实内容变化仍按原组／renderNow更新。按影响实测静止、移动和连续目标变化，不能把静止收益外推完整游戏FPS。

原叶使用唯一k矩阵和实际native transform的采样相位，反重力采用负Y叶、匹配CullClockwise与复合FlipVertically，不能假设30%投影高度恰好1080：原版rounded camera世界高3638乘38/128为1080.03125。TileBatch保留原point，叶内SpriteBatch沿原direct LinearClamp；复合这张输出密度纹理时用PointClamp，避免第二次线性过滤使alpha边缘变模糊。缓存帧在最终准备后、首个世界Begin前借出稳定自有world SpriteBatch，原共享实例必须没有打开的Begin或pending，否则该帧不用cache。正常世界及filter完成后、原DebugVisualizer／UI前归还共享引用；异常由同次DoDraw finalizer归还。点复制只额外提交该自有caller，保存其完整状态并重开，Point复制另用自有SpriteBatch。动态tile entities仍沿原PostDrawTiles的最终Main.Transform，不进入静态层。

原生覆盖scope与每个Fill保存并在同层恢复screenWidth/Height、screenPosition、Zoom、P、drawToScreen、RT绑定、Main两个共享batch引用和自有XNA租约。使用稳定自有TileBatch/SpriteBatch；原版RenderTiles等会吞部分异常，因此在实际TileBatch queue resize／End叶记录首异常，外层即使原body正常返回也不得发布valid。失败退休自己的损坏队列，不用End假装丢弃；独立释放TileBatch内私有SpriteBatch，继续必要清理并保留首异常。未知异常传播，已知可选OOM清组并记住device/mode/物理尺寸/目标capacity资格，后续同资格direct且不重试；倍率、光照、地图和用户设置不改。只有必要direct资源失败才进入既有一次反馈／普通安全状态。点复制的首异常可能被原WallsTilesNPCs两层catch遮蔽，须在其结束接缝或DoDraw finalizer保留首异常；caller.End本身也在try内。失败退休本帧自有caller／copy队列，不把原版End重试成功当归还条件。只减掉仍由这些实例持有的Begin贡献；Immediate的End先减租约、后Flush，故仅在该独占Immediate仍存在时减它，保留进入后新开的外来Deferred租约及pending，不全局置零或回写过期入口计数。本轮owned scope首异常还需在外层原Main.Draw无finally的guard接缝归还进入值和计时间隔，否则后续Draw调用会被短路。仅匹配该精确首异常，不改变其它原版异常；后续验证必须观测fpsCount实际递增，不能只数调用次数。

### 新增owned入口的失败传递与归还

| 入口 | 首异常与归还责任 |
|---|---|
| Native原生组早覆盖借用 | scope保存真实root域、七字段／swap身份与pending、RT及共享batch；叶端记录被原版吞掉的首异常，未完成内容作无效。私有坏队列退休，完整归还后将首异常交同一DoDraw。申请批次前的已知OOM可同帧直接绘制；叶已部分发布则放弃本帧。 |
| 三层Fill | 每层有效性只在原叶完成后发布；私有队列与XNA entry lease、root字段/RT同层归还。已知申请／Fill OOM由可选cache owner记住资格，同帧改Direct；未知异常原对象传出。 |
| 三层Composite／world borrow | 首次caller.End即在try和完整owner内；caller与copy均为稳定自有实例，共享原实例保留。正常在原版UI前归还引用；单次或持续End失败都退休自有队列并只归还其Begin贡献，外来queue／租约不改。首异常穿过原版catch；OOM放弃本帧，未知IO原对象传播。 |
| scene／water准备 | scene三RT为physical；Direct mask、Native液体层及wave域按本帧route选择。自身scope先归还borrow／坏队列／租约，未知异常原样传出；必要Direct资源OOM仍走原ViewRenderFailure。 |
| Main.Draw外层 | 只认上述owned入口的精确首异常；归还进入时guard、RT与计时间隔。逐层保存并恢复prior exception marker／RT snapshot；被原版true guard拒绝的嵌套Draw不清外层owner、不执行另一次DoDraw。未标记的原生异常保持原对象和原版行为，不作全局异常恢复。 |

已知可选缓存的中途OOM以内部`ViewOptionalCacheFailure`携带原始OOM对象为InnerException，由同次DoDraw finalizer完成归还后消费。当前部分提交帧被放弃，不把液体alpha／queued step当可重试事务；已失败资格下下一次真实Draw为Direct，目标、Lighting/map、设置及开关保持，控制异常不得外泄到普通Game.Run。必要Direct也失败才触发原来的安全普通状态／一次反馈。未知IO不走该控制类型，仍准确传播；原始OOM保留在内部异常链并由有限专项观察，不新增常驻诊断或文件日志。
Native额外批次以实际语义普通计划为退出接点：在原RenderToTargets前确认不再Expanded时释放私有TileBatch、其内SpriteBatch及额外SpriteBatch，并解除设备订阅。OFF-Retained或仍Expanded的Native／Direct切换保持稳定复用；不由该owner清原版七层或wave pair。退出的首异常也进入同一owned guard归还责任。

## 水、scene与三层route
