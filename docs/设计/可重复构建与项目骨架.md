# 可重复构建与项目骨架

- 状态：有效
- 生效边界：本设计随包含本文件和 ADR-0011 的提交合并进入 `main` 后，成为仓库当前正式构建设计。
- 授权边界：只覆盖可重复构建输入、六项目骨架、最小 operation contract 和有限架构检查；不授权加载链、安装器、用户功能或发布。
- 对应任务：[Phase 0-R Issue #23](https://github.com/Kuroneko2020/JueMingR/issues/23)
- 决策依据：[ADR-0011：可重复构建与项目骨架](../决策/ADR-0011-可重复构建与项目骨架.md)
- 上位架构：[总体架构与状态所有权](总体架构与状态所有权.md)

## 1. 目的与证据边界

本设计为后续实现提供一个可编译、可复现且能由普通 Agent 逐文件理解的最小起点。它只证明当前源码能在锁定工具链和固定合法引用下构建，并能检查当前批准的物理边界。

构建、ArchitectureTests 或字节复现通过，不证明 JueMingR 已加载、运行、兼容 Terraria、具备多人或性能质量，也不构成玩家验收。动态执行记录由 PR 和 Issue 承载，不写入本设计。

## 2. 锁定输入

- .NET SDK 固定为 `10.0.203`，使用 SDK 内置 MSBuild；
- 所有项目使用 `net472`、C# `7.3` 和 `x86`；
- 不使用 `PackageReference` 或第三方测试框架；
- `Terraria.exe` 来自用户合法 Terraria 1.4.5.8 安装；
- `ReLogic.dll` 从该 `Terraria.exe` 的固定嵌入资源提取；
- `Microsoft.Xna.Framework.Game.dll`、`Microsoft.Xna.Framework.dll` 与 `Microsoft.Xna.Framework.Graphics.dll` 来自本机 XNA Framework 4.0 Refresh；其中后两项由 Phase 0-T 的类型安全 UI 绘制编译 RED 证明为必需；
- 五项文件只作为本地编译引用，按 baseline 核验后放入被 Git 忽略的 `external/TerrariaRefs/`；
- 五项引用均为 `Private=false`，不得进入 Git、构建输出或分发包。

baseline 只记录可公开的身份、SHA-256 和来源类别，不记录私人安装路径。它不是运行兼容声明。

## 3. 项目边界

六个生产项目及依赖方向固定为：

- `JueMingR.Bootstrap`：无项目引用；
- `JueMingR.Platform`：无项目引用；
- `JueMingR.Features` → `JueMingR.Platform`；
- `JueMingR.Infrastructure` → `JueMingR.Platform`；
- `JueMingR.TerrariaHost` → `JueMingR.Platform`、`JueMingR.Features`、`JueMingR.Infrastructure`；
- `JueMingR.Setup`：无项目引用。

非生产项目 `JueMingR.ArchitectureTests` 引用 `JueMingR.Platform`、`JueMingR.Features` 与 `JueMingR.Infrastructure`，用于核验公开合同、纯 Feature 行为和隔离目录中的真实持久化读写。只有 `JueMingR.TerrariaHost` 可以直接引用 Terraria、ReLogic 和 XNA。

[配置持久化任务](https://github.com/Kuroneko2020/JueMingR/issues/34)按其[具体设计与接受边界](配置持久化与用户数据布局.md)增加 Platform 的 `System.Runtime.Serialization` BCL 引用及上述测试引用；六个生产项目和它们的 ProjectReference 方向不变，没有新增第三方依赖。

Phase 0-T 只增加已批准群系纵向切片所需的最小 Runtime/Session、Feature、Host Composition Root 与唯一绘制入口；不得据此扩张为 Coordinator、队列、Feature registry 或通用 UI 框架。

## 4. 最小 operation contract

- `IGameOperationRequest` 是无成员的 typed request marker；
- `GameOperationOutcome` 只包含拒绝、成功、部分完成、失败、取消、超时和未确认七个终态；
- `GameOperationResult` 是只暴露构造器和只读 `Outcome` 的 immutable result。

该 operation contract 本身不提供执行器、调度器、重试、线程、业务目标或 Terraria 类型；Phase 0-T 的最小单 Feature Runtime 由独立、宿主无关的合同承载。

## 5. 三个固定脚本

`prepare-terraria-references.ps1` 只接受 Terraria 与三个 XNA 显式源文件和 `VerifyOnly`，只写固定引用目录。它校验源文件、用简单 staging 准备五项引用，并允许无写入的幂等复跑。

`build.ps1` 只接受 Debug/Release 和 `RequireClean`，在固定配置目录构建 solution、运行 ArchitectureTests、拒绝游戏与 Legacy 文件进入声明输出，并写简单 build record。

`verify-reproducible-build.ps1` 的既存实现仍要求 clean commit，在系统 TEMP 创建两个 GUID detached worktree，以相同显式源独立准备和 Release 构建，比较声明 DLL、EXE、PDB 的集合、长度和 SHA-256；可选择一种群系、F5 基础或配置持久化候选包并比较两个工作树各自产物。它仍会创建/移除工作树，**没有改造成单工作区脚本**。依本次所有者明确决定，该入口退出当前自动/默认执行路由，不在本次整理任务运行或重写；下节及 ADR-0013 的长期替代关系已获接受，随本次合并进入 `main` 生效。

### 单工作区重复构建一致性

本小节依据 [ADR-0013（Accepted）](../决策/ADR-0013-单工作区操作偏好与项目知识分层.md)，执行方式已获所有者接受，随本次合并进入 `main` 成为长期规则，其余有效构建设计不变。[Issue #34](https://github.com/Kuroneko2020/JueMingR/issues/34) 已记录所有者授权的同工作区替代证据；它不改变本节证据层级，也不要求纯文档任务重复构建。

获准且确实需要此证据的任务，在当前单一主工作区固定同一个 clean commit、SDK 和全部锁定输入，顺序完成两次干净构建。第一轮完成后先保留声明产物的相对路径、长度、SHA-256 与输出副本，再按已授权的精确构建输出边界清理并进行第二轮；比较完整声明集合与每个文件，不用第二轮覆盖第一轮证据。涉及包字节一致性时，两轮分别用同一 profile 的既有打包入口产生独立输出，比较包内声明集合及 ZIP 长度/哈希。清理只针对确认属于本任务的构建输出，不触及 `references`、用户数据、安装或其它工作树。

结论名称是“同工作区重复构建一致性”，不等同于独立 checkout 或跨环境复现，也不证明游戏功能、多人、性能或用户接受。未来发布若要求更强的独立环境证据，应在对应任务明确解决环境与授权，不能暗中创建工作树或把较弱证据写成已满足更强门。本次仅协调文档，没有修改脚本参数、baseline、自动检查或安装；纯文档最终化沿用[交付偏好](../规范/工程治理规则.md#单工作区与安装交付偏好)。

### 项目所有者测试包入口

复用 `scripts/build-phase0s-validation-package.ps1`，不复制一套持久化打包脚本。`-Profile Phase0VSettings -OutputDirectory <全新目录>` 从 clean commit 构建配置保存测试包；profile 决定唯一包 ID、ZIP 名和对应测试卡，沿用现有 payload、manifest、依赖、许可证及安装恢复工具。输出目录必须尚不存在，仓库内只允许位于 `outputs/` 或 `artifacts/` 下。

配置包 ID 为 `phase0v-settings-<FULL_SHA>`，ZIP 名为 `JueMingR-Phase0V-Settings-<FULL_SHA>.zip`。外部构建记录继续保存构建输入与资产哈希，包内不带 `JueMingRData` 或游戏引用。`scripts/test-phase0s.ps1` 继续运行宿主 fixture 与安装恢复；后者包含安装前已有及安装后产生用户数据的保留检查，不放松未知文件所有权门。配置语义、后台生命周期及真实文件专项检查随 `scripts/build.ps1` 的 ArchitectureTests 执行，不建立独立的隐藏验证入口。

笔记候选 #42 在同一入口增加 `-Profile Phase0WNotes`，ID `phase0w-notes-<FULL_SHA>`、ZIP `JueMingR-Phase0W-Notes-<FULL_SHA>.zip`，附[笔记实机卡](../../scripts/phase0s/Phase0W-Notes-Owner-Test-Card.zh-CN.md)。沿用相同 payload/manifest/安装恢复工具和上述 clean、输出边界、同工作区顺序比较要求，不另建打包系统或发布版本。安装恢复隔离检查对配置和笔记两种 Profile 均验证安装前后用户数据保留。

本功能的 Features JSON 编解码只增加框架自带 `System.Runtime.Serialization` 引用。`ArchitectureTests/Notes` 按内容、编辑、文件、并发职责进入现有 build runner；宿主 fixture 链接实际 Notes 输入/卡片/便签/绘制代码并引用本工作区 Debug 构建的 Platform/Features/Infrastructure DLL，所以先运行 `scripts/build.ps1 -Configuration Debug`，再运行 `scripts/test-phase0s.ps1`。夹具 `notes-input` 可单独运行合成原生队列/IME/剪贴板和无纹理字体度量的调度检查；该分项不替代完整图形与加载链检查。真实图形、输入法和多人证据分别记录，不能用分项成功掩盖其它失败。
#42 已获所有者本次即时授权，因既有显示设备不可用证据可显式执行 `scripts/test-phase0s.ps1 -DeferGraphics -GraphicsDeferralReason <已分类的环境证据与任务授权>`。默认不传参数仍执行完整图形入口；没有原因不能启用延期。该选项只将 Notes 的 XNA 像素/裁切/图形状态段、实际 F5 输入/绘制消费者段列为 DEFERRED，仍执行布局与输入模型、合成 Notes 输入、实际组合设置及反馈、加载链/错误路径、重复进程、TEMP 安装启动与恢复，以及两种 Profile 的安装恢复检查。独立 `phase0u-visual` 保留原图形入口，实际 XNB Notes 八场景预览另列待补，不计入非图形 PASS。

通过其余必要检查及独立审查、安全预检后，本任务可先用原 Phase0WNotes Profile 交付“图形验证待补的开发测试候选”。包绑定实际 clean SHA，重复构建和安装身份/数据保护门不变；真实绘制失败、未知异常不能借此放行。交付说明和实机卡注明延期范围与证据，后续按风险补图形和真实 IME/外观验收，不默认重跑无关检查。此许可不扩大到未来任务或正式发布；操作环境和长期文档生效边界见[操作偏好](../规范/工程治理规则.md#rdp-工作方式与本次图形延期交付)与[测试分层](../规范/测试与审计规则.md#显示环境受限时的验证分层)。

## 6. 有限架构检查

无第三方包的 console runner 保留 Issue #23 指定的直接 XML、反射和 Git 跟踪事实，并增加 Phase 0-T 的公开类型边界、群系纯映射与生命周期检查。既有负向控制仍为错误的 Features→Host、Platform→Terraria 和 Host `Private=true` 三项。

检查器不是安全产品，不抵御 hostile Git config、hostile environment、同权限恶意进程、链接攻击或实现者同时篡改实现与测试，也不证明脚本自身不可篡改。

## 7. 维护规则

- 保持脚本参数和写入根固定，不扩张为通用构建平台；
- 只在当前合同出现真实缺口时增加检查，不主动发明新威胁；
- 游戏引用身份改变时必须通过新的项目所有者决定更新 baseline；
- 新加载链、依赖、项目、功能或发布工作必须进入独立任务；

本设计已获项目所有者接受，并随包含本文件的提交合并进入 `main` 后生效。后续加载链、新依赖、新项目、功能或发布工作仍必须进入独立任务。
