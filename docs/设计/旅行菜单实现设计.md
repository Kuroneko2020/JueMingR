# 旅行菜单实现设计

产品范围见[行为合同](../功能介绍/旅行菜单行为合同.md)，授权、固定候选、独审、执行原件及交付事实见 [#122](https://github.com/Kuroneko2020/JueMingR/issues/122)。原始委托为本地 `references/JMR_JOURNEY_MENU_20261018/00—08`；不改写原件为进度记录。

## 状态与接入

`Features/Journey/JourneyActivation` 只管理本次会话激活/故障，没有 Terraria 类型或持久开关。`TerrariaHost/Journey/JourneySession` 实现既有 `IRuntimeFeature` 和 F5 的 `IJourneyControls`，由完整 ContinuousProcessing 的 `PostfixContext` 组装并加入同一 Runtime。与 Guidance、F5 共用唯一进程级 `HiddenFeatureAccess`，Runtime 仍逐功能更新和局部失败隔离。

`JourneySession` 绑定 Runtime generation、实际本地 Player、PlayerFileData 和 WorldFileData；它们只是本功能持有的原版资源归属，不建立第二套 Session 权威。HIDE、真正单人、完整会话、本地文件及原版依赖在第一次副作用前核验。启用时准备正 cap 研究集合、捕获力量持久子流和少量运行基线，再开放准确资格；原版窗口确认后发布命令成功。启用失败沿同一停止职责撤回。

窗口可见由真实 `CreativeMenu.Enabled && playerInventory && !Blocked` 投影。F5 安全离页先处理已有笔记草稿，成功打开原版窗口后才让出；物理输入尾部沿既有 HostInputState。原版 ToggleMenu 收起时归还研究槽物品，不能用只隐藏窗口的原版 CloseMenu 丢下该槽。

F5 标准行只生成开启、关闭和原 `journey.toggle` 绑键。EnableJourney 始终委托 `SetEnabled(true)`，Active 时由 JourneySession 直接 `Open()`，保持同一 Persistence 引用及已选择力量，不经过 Stop/Activate、不捕获新基线；已经可见时也不反向收窗。底层 `IJourneyControls.Open` 与 JourneySession.Open 保留为此幂等入口；快捷键继续 Toggle。按钮收尾不改变安全离页、失败反馈或成功让出职责。所有者已反馈本批功能实测未发现问题，接受随 PR #123 合并生效；原工程与安装身份仍分别回到 #122。

`JourneyHooks` 只在这 11 个已核方法中替换准确身份读点，每方法必须恰好一处，原 CodeInstruction 的标签/异常块保留。替换帮助函数以当前 owner/对象/Runtime 代次短判定，不全局覆盖 IsJourneyMode，不影响角色死亡身份、匹配、列表或序列化。任何目标、签名或读点不符时撤销本 owner 已安装 patch，旅行不可启用，其它 owner 的 patch 保留。

研究集按原版正 cap 目录及 ContentSamples override 规范化去重，第一次需要构造并复用；未解锁/OFF不枚举目录。开启/关闭只令准确原生无限物品窗口缓存失效一次；它在其它类别下会从当前树移除，故直接读取该已缓存字段，不遍历可见树猜测是否存在。不伪造 tracker 编辑、不每帧刷全表。真实资源/原版 reset 清理该领域缓存。

## 持久视图与真实保存链

人物：Player.SavePlayer 在 Player.IOLock 中经 InternalSavePlayer → ProtectedInvoke → InternalSavePlayerFile，以实际 PlayerFileData.Player 直接 Serialize；没有先克隆。自动保存、退出和快捷改名复用该链。Serialize 写真实 difficulty、真实 tracker，再调用 Manager.SaveToPlayer。文件写入沿原版加密、本地/云提供者和备份行为。

世界：WorldFile.SaveWorld → _SaveWorld 在独立 WorldFile.IOLock 中经 ProtectedInvoke → InternalSaveWorld；SaveWorld_Version2 同步生成完整内存字节，头/flags 写真实 Main.GameMode，SaveCreativePowers 调 Manager.SaveToWorld，之后沿原版文件写入、验证及滚动备份。外层自动/退出可能由 ThreadPool 发起；不是在请求线程临时改字段后猜测 worker 会读到。

`JourneyPowers` 在激活前调用原版 Manager.SaveToWorld/SaveToPlayer 捕获原版自身生成的两段完整小子流，分别 31/16 字节、6/3 个力量记录及终止符。即使非旅行身份，原版仍无条件序列化这些力量，所以只保护身份不够。此处复用原版结构，不重写人物/世界格式、不全量复制存档、不翻全局力量单例给后台读。

`JourneyHooks` 在实际 InternalSavePlayerFile 和 SaveWorld_Version2 入口捕获不可变 SaveView；人物匹配实际文件对象和 Player，世界匹配实际 WorldFileData。线程局部仅作为这次同步序列化的有界嵌套栈，不传播资格、不跨线程猜测归属。对应 Manager.SaveToPlayer/SaveToWorld 写出该次冻结的基线子流；其它数据和原版失败语义原样继续。Finalizer 幂等弹回上一上下文并返回原异常。

关闭先撤资格，恢复当前相同对象的运行力量，再退休 owner 的基线。在途 SaveView 自持旧不可变字节，关闭/换代不能让它套用新世界基线；保存完成即释放，不累积历史角色索引。主线程不等待后台保存，不引入 Player/World 两锁相互等待。没有恢复 JSON、启动扫描或每 Tick 文件 I/O。

另一个交错是保存已在 OFF 时进入串行化，然后才第一次开启能力。它的 SaveView 原本没有借用基线，不能让稍后的力量写出读取新临时值。两个实际串行化入口共享一个仅包住计数/基线捕获发布的短准入门；还有未持有不可变基线的串行化在途时，首次开启在副作用前明确返回“正在保存，请稍后开启旅行菜单”。已经冻结旧基线的保存仍可跨关闭/再启用继续，不拦住安全的A→B代次交错。初步可用性和实际激活之间也在同门重新判定，不能靠一次无锁检查消除竞争。原保存本体、I/O及其Player/World锁都不在此门内；不等待它完成、不阻止关闭，也不在OFF生成力量快照。正常、异常与嵌套的Finalizer分别退出本节点，幂等恢复上一视图及计数。

云的既有保存接口仍保持原样。本候选尚未验证真实云提供者持久结果，因此在启用前拒绝人物或世界任一云路径，不能声称云输出已经通过。

## 关闭、原生旅行与原版 Reset

关闭恢复六个原生世界力量及本地 God/Range/Spawn 的原基线，并取消借用期间尚未提交的滑条目标。风雨滑条只归还控制缓存，不重新执行其即时天气命令；实际环境变化保留。非旅行第一次有效难度按基础 GameMode 取 x1/x2/x3，FTW 的额外级别仍由 Main.Difficulty 原生叠加；不重复计算。

原生旅行组合不启用 R 时资格/研究查询完全走原版。启用增强时捕获已有真实研究和力量，关闭只撤本次增强。Manager.Reset 开始前退休旧 owner，由该原版入口重置全部力量，不能等下一 Tick 再将旧快照写到新世界。ResetDataForNewPlayer 只重置人物力量，故在旧对象仍实际归属时先归还借用的世界力量再退休基线，防止仅人物反序列化/克隆留下临时世界控制。原版自身加载/重置行为由其继续执行；生产不调用 LoadPlayer 做验证。

Full Reset 即将替换全部力量，即使收起旧菜单失败也必须无条件退休旧基线，后续会话结束不能将它再写回。Player-only reset则仍需保留恢复失败的保护责任；两种reset不共用“失败都保留旧基线”的规则。已经进入保存的不可变SaveView不因退休而丢失。

## 输入、共存和成本

F5/Hotkeys 仅发同一 owner 命令并投影状态。动态 `journey.` 注册只在隐藏资格变化时重建；锁定的旧绑定不执行/占键。启用状态不随长期绑定保存。

原版在使用工具时可能令 IgnoreMouseInterface=true。CreativeUI.Update/Draw 的短作用域只向 UserInterface.Update 和 CreativeUI.DrawToggleButton 的准确读点提供局部例外；已验证的 .NET Framework/Harmony 不能包裹闭泛型集合 DrawSelf，因此复制槽使用非泛型 UICreativeItemGrid.DrawSlot，按原版44×44槽、真实grid hover和ActiveInstance鼠标位置补回被压掉的hover。范围仍限本次CreativeUI调用栈及Host焦点/释放准入，不改变全局getter或其它界面。CreativeUI.Update早于本帧映射，失焦/释放隔离时直接拒绝该原版UI新输入，防上帧映射变成新命令。

原版窗口真实鼠标、文本、鼠标物品占用只限制冲突的新操作。Shell 的工具、加工、恢复准入和 Items 的新动作委托在该接缝让路；Runtime、原版映射、观察、已完成回执和归还不总早退、不清全队列。仅 R Active 且窗口关闭时无输入 claim。复制物品由原版实际来源和既有持物保护消费，不能靠“开关仍 true”证明共存。

Shift复制直入包在 ItemSourceHooks 的原版 OverrideLeftClick 精确 context29/cursor7 取得来源；原GetItem前后实际数量与原版返回共同确认，再交现有有限RegisterAcquisitions。普通鼠标复制仍走原生手动持物/后续交接，不把整个库存重标为新物品。源码中的来源分支不改变既有存/卖/扔判定。

旅行有效难度还传播到现有NPC预测。原先 NativeValueSnapshot 不支持 Main 唯一的 nullable float `_gameModeDifficultyOverride`，导致基础GameMode不变时丢失运行倍率；现以编译好的 float? 编码/原生接收读回保留 null/值，并在 NativePredictionAlignment.WorldPremise 纳入原版 Main.Difficulty，倍率变化使旧未来失效。线协议38/实验138绑定新布局，不兼用旧身份；没有改变NPC算法、容量、RNG或恢复策略。窄验证限定实际世界子流捕获/接收与前提变化，不借此宣布全部NPC重新验证。

安装时解析必要元数据与 IL；稳定资格查询只用缓存引用和短条件。首次目录、菜单绘制、原版真实力量及正常保存 I/O 是对应功能工作，OFF不做研究扫描、保存快照、日志或后台排队。组件工作量/耗时与真实高生成率、加速世界的原版负载分别报告，不能外推量化 FPS。
