# 本地短提示与快捷键反馈实现设计

本分支按 [#101](https://github.com/Kuroneko2020/JueMingR/issues/101) 授权实现[行为合同](../功能介绍/本地短提示与快捷键反馈行为合同.md)，不是 main 已生效或实机接受声明。

## 职责与生效点

`HostHotkeys.RegisterSwitch` 只包装显式登记的同步开关，原 `HotkeyAction.Invoke` 与共享物理输入不变。Biome 在 SetFeatureEnabled 后确认，Items / Labels 在 PollPreferences 应用后确认，其余同步域读取既有权威设置。不开第二套状态镜像、不轮询全部 37 项。

QuickItems、CoinDeposit、Recovery、Processing 的原注册入口显式包装异步开关。各设置 owner 新增 AcceptedCommandId、CompletedCommandId、CompletionSucceeded 只读事实；成功 TrySubmit 才更新接受 ID，原 Poll 是唯一完成消费者，加载 ID=0 不产生回执。Coin 的同步 Poll 已完成场景也按同一 ID 处理。

`HotkeyStateFeedback` 捕获命令前有效模式和 Runtime 世代／角色；最多 12 条请求仅在原消费者 Poll 完成之后观察。后续同设置文件命令取消旧关联，不影响另一文件请求；F5 没有反馈请求。失败关闭时暂停为 false 不是成功证据。同步域活动项只检查自身当前状态，异步域还检查 owner 命令 ID。有效结果文本捕获旧关闭模式，不在保存结束后猜测。

## 显示所有权

`LocalShortFeedback` 是游戏线程上的有限显示 owner，通过既有 IRuntimeFeature 会话出口清理。只处理至多四个活动项；每项有稳定 action ID、范围、过期时间和当前状态谓词。显示满不向上游发拒绝。无活动项在读取时钟、字体、池或布局前返回；无 pending 的回执检查同样早退。

`NativePopupText` 共用最窄的原版入池、所有权判定和释放。锁定 .8 原版满池会替换现有槽，因此先确认空槽；同线程检查后调用 NewText。每次分配独立字符串实例作为令牌，并核对当前池数组槽、实例、Advanced/freeAdvanced、name/displayText 的引用身份。对象引用或字符串内容相同不构成所有权。只释放确认属于自己的项，禁止清全池／恢复快照。

快捷键结果失去原生槽后，仅在余下期限使用后备绘制，不再申请新原版项。正常头侧位置按原版 NewText 的半字框偏移、倒重力屏幕投影和游戏矩阵推导。原版自身测量／碰撞／动画成本仍存在，不能宣称完全消除测量。

`LocalShortFeedbackRenderer` 复用 MouseText 与 UiTextMetrics 实际字形边界，按文字、字体实例、字号、视口缓存。F5 GameInterfaceLayer 已打开 UI batch，后备绘制用逆 UI 变换保持物理像素位置；地图走既有 FullscreenMapDrawing.Overlay（其时无 batch），窄 Begin/End 后恢复设备状态。地图 lease 只在活动显示期间持有，结束释放。显示异常在本地边界隔离，不能进入 F5 或业务 FailClosed。

丢弃的格式／命名和完成事实仍在原适配，显示委托只做主动回执优先退让。Onboarding 保留独立状态机、数据和 Draw 确认，仅共用 NativePopupText。

## 验证与交付

首个反例是调用完整 ContinuousProcessing Host 的实际 stack 注册动作后，状态改变但原版文字池没有“自动堆叠 已开启”。新测试不是只调用字符串助手。

- 正规构建／工作量：`scripts/build.ps1`；`NativeShortFeedbackChecks` 由实际工作量入口选中，覆盖 37 项接线、可靠提交、失败／未知、后续 F5、模式、容量、槽复用、清池和生命周期。
- 图形：`scripts/test-world-object-text.ps1 -Scope ShortFeedbackVisual`，真实 .8 EXE + XNB + 隐藏 XNA 设备；检验原版像素、头侧、镜头／缩放／倒重力、有限后备、稳定布局缓存，并实际查看输出。
- 相邻：原 About／Onboarding、Items、QuickItems、CoinDeposit、Recovery、Processing 和共享输入检查保持真实消费者；人工游戏、多人、FPS 与隔离探针分别报告。
- 包：沿 ContinuousProcessing 完整 profile 包含已合并功能，附本任务实测卡；不增加新 profile／版本／依赖。源提交、两轮顺序干净构建、载荷、ZIP、安装 receipt 分别绑定，实际结果仅记 Issue / PR。

实施顺序为反例 → 窄适配和各确认点 → 实际消费者与图形／工作量 → 完整差异独立只读审查与窄修 → 同工作区顺序干净包 → 安全安装 → 所有者实机反馈。具体运行结果不在本稳定设计维护第二份状态表。

原版浮字先于 F5 层提交。当 Update 后、F5 Draw 前的镜头／缩放变化令原生项部分越界时，Draw 只退休该槽，后备延至下一次 Update，避免同帧原生残留加后备两份像素。实际组合两出口的图形反例固定此顺序。移除最后一个活动结果立即释放 map lease；地图 Hook 申请故障在本活动周期只尝试一次，不逐帧重试。
