# 物品自动处理实现设计

本设计落实[已接受合同](../功能介绍/自动存放功能行为合同.md)；任务授权和动态状态在 [#46](https://github.com/Kuroneko2020/JueMingR/issues/46)。代码、自动验证、安装和三种拓扑实机分别给证据，本文件不是完成声明。总体项目依赖及状态所有权继续遵守[总体架构](总体架构与状态所有权.md)。

## 边界与唯一所有者

三项分别称自动堆叠、自动出售、自动丢弃；首次关闭，出售默认 2337/2338/2339，丢弃空。物品领域拥有两名单、三期望状态、有限的取得意图及卖＞扔＞存决策。配置由独立进程级 PreferenceDocument 保存；UI 只提交同一组偏好命令。Host 持有原版对象、因果回调、版本适配和实际操作，不能判断名单或另存期望状态。

沿用并扩展现有 Runtime 的会话生命周期；群系与物品接入同一会话代次，群系仍保留自己已接受的单人能力门。会话身份需要本机 Player 对象、世界身份、连接身份和死亡边沿，不能只看 active bool。代次由唯一 Runtime owner 发放；任何旧结果不得跨代次重新应用。

领域及 Platform 值不包含 Terraria Item/Player、反射句柄、可变原版数组或图形资源。Host 游戏线程产生语义槽观察，再由领域发三个具体 typed 请求；不以字符串分派动作，不建立事件总线或通用工作流。操作协调只记录本任务真实冲突范围，不强制所有请求进全局队列。

## 来源、观察与整栈资格

世界来源绑定实际 Player.PickupItem(WorldItem) 调用；开启来源绑定 ItemSlot.TryOpenContainer 的完整外层调用，依据目标版本 OpenableBag 与实际成功分支。GetItem 设置名、newAndShiny、未知增长均不是来源。

因果作用域内记录非币物品实际进入合法主包的增量，作用域完成后才提交来源；作用域未完成时不执行自动动作。开启原物及钥匙消费不能被自己的观察当作产物。虚空接收、落地产物不算主包接收；落地后真正拾取是新事件。嵌套取得只归一个最近的合法外层作用域，避免双计。

主包合法输入为 0..49、54..57 的有效非币物品；50..53 是币槽，58 是鼠标槽。收藏、鼠标拿持、当前使用、原版手动动作和在途来源逐实际槽保护，不笼统排除快捷栏或弹药栏。名单按 type；存放要求 maxStack>1 并按实际 Item.CanStack 兼容关系分组。指定 .8 的 CanStack 仅比 type/prefix，不能单独替代可堆叠门。

一次可靠取得允许处理兼容组的合格整栈，包括旧数量。成功外层因果结束时，Host 同步取得一份最多58槽观察并批量提交本次实际取得的全部身份；不等待下一轮领域扫描来补齐成员，捕获失败也不凭后来库存追溯。只有这次取得可捕获或重新合并成员，普通观察只能删除成员。关联包含槽、对象实例标识、type/prefix、数量、最大栈及当前保护；任一关联无法可靠延续即取消该成员，不凭槽号或等值物品代入。不能可靠追踪的移动、拆合或未知增长保守取消，后续真正取得仍可重新授权当前合格整栈。

来源机会不是数量额度，也不是永久 type 许可。实际提交的成员在执行中或完成、部分、未知、无适用目标时立即退役；操作结果和真实在途资源继续由原操作 owner 收口。拒绝且未产生副作用可有限等待当前条件变化；同组尚未提交且关联仍可靠的成员保留，下一次判断仍按卖＞扔＞存。没有剩余合格成员即删除机会，收藏同类不续住已完成组。首次未结束取得起600 tick到期，连续真实取得合并当前成员但不延长该次年龄；这个内部期限限制待处理状态，不是物品保护秒数。

按 [#46 修订授权](https://github.com/Kuroneko2020/JueMingR/issues/46#issuecomment-5604119169)，三项先取得同一领域 owner 管理的可靠来源资格；仅开出售或丢弃同样捕获可靠来源，三项全关不登记、重开不追溯。名单修改、启停、开店或无法解释的库存增长不建资格。出售只有当前有效 NPC 商店才参与。处理开始前逐实际候选复核资格与保护，再重判卖＞扔＞存。明确不适用才可选下一动作；执行中、部分副作用、未知结果均不能直接降到下一动作重做同一资源。配置业务相等比较仅三开关与两名单；纯展示偏好改变不清机会、不重置尝试版本。实际验证范围继续以任务证据为准。

Host 注入公共 `HostInputState.CanStartActions`，领域判断和三个宿主动作入口复核同一许可。焦点和输入采样有效性不进入 Session 身份，也不阻断来源记录、既有网络回复和结果收口。原物/钥匙手动保护仅在该许可有效且 `PlayerInput.MouseInfo` 的原始左右键均 Released 时清除；F5/名单消费后的 `Main.mouseLeft/Right` 或失焦合成空样本不能证明真实释放。

## 操作与结果

请求带会话代次、当前观察身份、实际来源槽和类型/前缀/数量/收藏/使用状态。Host 开始前重新核对，旧观察不能直接写游戏。未开始的不适用、拒绝与已开始后的执行中、完成、部分完成、失败、取消、超时、未确认分开。

出售走经核验的原版完整槽位出售路径，核对店和玩家购物状态；保留动态价格、回售调整、零收入和有限回购语义。Player.SellItem 只是收款段，不能独自算完整交易。其容量失败会替换前58槽的备份，故影响范围是整个前58槽加店/回购；不能与任何重叠在途槽并发。收款后异常不得再执行整笔或回写旧整包快照。

只有该同步原版出售已证明拒绝、来源/币值/回购未变，且58槽语义全部一致时，才接纳这次已知备份恢复的新 Item 引用并保留成员 instance；不制造重试 revision。普通观察中出现的等值替换仍产生新 instance 并取消旧成员。此例外不回写库存，不容忍未知副作用，也不把对象等值当通用来源连续性证明。

丢弃走原版垃圾桶分支，保留 Clone、研究附带副作用、替换旧垃圾桶和清源顺序。原垃圾桶可含任何内容；连续成功后只有最后一项可按原版取回。输入槽与共享垃圾桶串行，未知替换停止后续覆盖，不将世界掉物当垃圾桶处理。

丢弃反馈由独立 `ItemDiscardFeedback` 呈现适配器同步处理，不拥有业务结果。提示开启且原版允许物品浮字时，从本次清槽前的原物 Clone 调用 `AffixName()` 捕获当前语言与前缀显示名；原版丢弃完成并由 `FinishDiscard` 收口后，仅 `Completed` 使用 `ConfirmedQuantity` 发出一次“自动丢弃了{数量}个{名称}”。数量不含旧垃圾桶内容。提示关闭不取名、不构造句子；取名、显示异常或原版拒绝显示均不改变业务完成、重试、撤回或补发。手动垃圾桶路径不接入此适配器，读取历史结果不触发显示。

目标 .8 的 `Main.ReforgeItemInReforgeSlot` 使用本机 `Player.Center` 与 `PopupText` 池；本实现只调用同一原版浮字系统的 `NewText(AdvancedPopupRequest, Vector2)`，白字、60帧、初速度 `(0,-7)`，不执行重铸。Advanced 请求直接承载完整句子，`freeAdvanced` 使其不参与普通拾取合并或追加数量；原版 ResetText 清除复用槽的效果状态。遵守原版20条池、`showItemText` 和服务端门，不加聊天、广播、声音、粒子、逐成功日志或跨帧队列。目标方法及程序集身份的原始证据由 #46 本次取证记录追溯；ABI 夹具只能验证接线和载荷，不能代替实际浮字观感。

存放只给原版三参 QuickStackToNearbyChests 传入选择性 SourceInventory；不调用全包、个人银行或 void 路径。原版负责真实世界 Chest、600px 范围、锁/占用、已有兼容栈及同类容器空位、部分容量与顺序。选择性数组归本次 Host 操作所有，不暂时改真实 inventory、favorite 或 maxStack。单人同步结果核对兼容组总量及对应目标；原版来源合并会改变每槽数量，不能将这种合并误认成入箱。

客机复用原版 net5/85，只有一个占用共享 netInv 的未收口批次。发送前排除既有原版库存操作和槽锁；发送不是成功。只有当前会话、本批槽范围、确实应用的来源 net5 及实际余量能领取结果；反向85只是阻挡提示。所有来源回复均领取后按各兼容组判完成/部分/零移动，不能一个槽回复便宣告全批成功。无法确定的异常/超时停止受影响资源的自动重试；不强清原版锁，不根据 unlock 或本地数量下降猜业务成功。

原版没有 R 请求 ID、逐业务提交/回滚协议。服务器已入箱而客机余量回复未达时本地仍有原物。断线后的两个历史可能不可区分；本功能不能承诺跨断线资源守恒。允许的处理是未确认、不重发、不回填、不跨会话重放；不能增加丢物、保存账本、禁止退出或服务器组件来伪造确定结果。生命周期接入 .8 的本机 DropItems/DropCoins 与 SaveAndQuit 边界，在原版动作前结束旧会话，不阻挡原版死亡或保存；世界/角色/连接身份变化也发放新代次。

## 在途原槽保护的必要宿主门

原版网络锁不是所有写槽入口共同遵守的事务锁。已核验 .8 的主包接收 helper、FillAmmo、ConsumeItem 和收竿选饵都有独立路径；手柄也可直接开袋。必须在实际副作用之前保护本批原槽，同时保留其它槽的原版行为。

- 两个主包接收 helper 可按实际目标索引拒绝，原版继续接收其它位置。
- FillAmmo 的合栈和空槽循环均需显式跳过在途索引；返回 Air 会让空槽分支反而覆盖原物，禁止此伪空槽方案。
- PickAmmo_IterateRange 可过滤传入索引序列；不改共享 AmmoSlotOrder 数组。
- 开始使用、QuickBuff、手动 ItemSlot/手柄入口按真实对象和槽保护。仅拒绝末尾 CanConsumeConsumableItem 会形成免费效果，不能采用。
- ConsumeItem、饵料、工具辅助材料需核对实际选料和效果顺序；不能只守 HeldItem，也不能假定所有扣料经 ConsumeItem。
- SortInventory 保留原版 HasLockedInventory 门，同时尊重 R 在原版解锁后仍未确认的有限范围。
- 原版手动出售的58槽备份范围也与在途源冲突，保护实际 SellItem 入口，包含鼠标持物点击商店的分支。
- 自定义货币购买可能备份/恢复全部源数组，在任何自有在途范围存在时等待。普通金币买入只因保护范围中的币槽/空槽拒绝；已经收到 Air 而同批其它槽未收齐，也不能被找零占用。

以上保护作用于本机共享会话的自有未确认范围；闲置早退。方法签名、版本身份与必要 IL 形状全部通过后才允许发送存放请求。匹配失败在 HostItems 内关闭物品能力，保留 F5/Notes，不得以“待实机”放行缺少必要保护的候选。

## UI、名单与保存

所有者在 #46 本次修正中撤除三项快捷键绑定，改用页面明确“开启/关闭”。删除绑定控件、录入、冲突解析、运行切换和业务字段；不保留可绑定键盘占位。F5 固定键、Notes 文本/输入法/阅读修饰键及其它页惰性键盘图案保持原职责。

三行顺序为自动堆叠、自动出售、自动丢弃；出售/丢弃的“添加”与开启/关闭同组，名单紧接对应行。完整行面板、名称内边距、组右对齐、字形宽度、居中、等高等距和选中短线由 `F5RowLayout`、`F5ControlRenderer` 共用于信息页与物品页。信息页的群系命令映射仍在原 owner；公共控件不依赖群系状态。期望开启显示绿色短线，关闭显示红色短线，文字保持普通字色；无商店等不适用条件不改变期望，真实故障另行提示。重复提交已选状态不生成偏好 revision 或写盘。

丢弃行在“添加”前加普通文字按钮“提示 开/提示 关”，默认开，仅该按钮切换偏好；其余三项仍为明确开启/关闭。按钮共用上述布局，不引入单独尺寸或画法。丢弃选择区展开时仍保留提示与开启/关闭，隐藏添加；切换提示保留候选快照和已选草稿，确认/替换合并最新提示偏好。纯展示变化参与配置内容相等与保存，但领域通过 `HasSameAutomationRules` 只比较三开关与两名单，不清来源、唤醒判断节拍或重置尝试版本。

名单为稍扁的47×34 logical 图标卡，候选为47×48卡，间隔4；随可用宽度换行。空名单不占额外区。对应行的“添加”原位展开候选并暂代本名单，后续行按真实高度下移；同一页只展开一处。添加可多选，标题显示模式和已选数量，右侧固定“×/确定”，零选择时确定弱态不可提交。当前展开名单的功能行隐藏“添加”，不绘制也不参与命中，“开启/关闭”保持原位；另一名单仍保留添加入口。确认、取消、Esc等收起选择后恢复“添加”；切换另一添加或其它名单图标放弃旧草稿。本体直接进入该类型的替换选择，标题显示目标名称，无中间编辑层或确定；点候选即提交。名单卡悬停显示右上移除叉号，保留18×18命中区域，优先命中，释放直接移除规则。图标本体、叉号和候选有各自提示，不默认显示 ID，不操作真实背包物品。

候选仅展开时扫描合法主包，HashSet 去重、List 按合法槽首次出现顺序保留非币且不在对应名单中的类型；另一名单和收藏不排除。展开期间不随背包变化刷新或重排；消失的物品仍可按类型确认，新出现类型需关闭重开。一次扫描同时区分“没有有效非币物品”和“全部已配置”。候选顺序与持久名单排序分离；没有 Refresh、槽位/Item引用或第二滚动条。稳定快照、重复添加保留草稿和明确模式反馈属于本次所有者新增体验决定，不能倒写为 Legacy 既有行为。

`ItemSelection` 是唯一临时选择 owner，持有名单、添加/替换目标类型、候选、选中集合及会话/选择代次。确认合并最新偏好，保留最新开关和另一名单；替换重查目标仍存在及候选合法/非重复。命令拒绝保留草稿并解释；内存命令接受和异步磁盘失败分别表达。关闭、Esc、获准离页、F5关闭、失焦和会话结束取消，快照不跨会话。普通滚动、字体/皮肤/尺寸变化只取消旧命中捕获，不清有效选择。功能关闭仍能编辑；未加载、失效会话或真实故障另行禁用。仅对应功能已开启且正在选择时说明名单影响有可靠取得资格的物品去向，不常驻就绪/保存成功/正常处理结果。

`ItemsLayout` 先按完整名单数量计算逻辑高度，再夹紧主滚动并只投影可见卡片；绘制和命中共用该缓存，无递归重排。展开/切换尽量保持对应行位置，仅一次最小调整使标题与首排可用；后续用户滚动不回拉。偏好、选择、可用性、字体/资源、尺寸变化才重建逻辑布局，滚动只更新可见投影，hover 不读取背包或重造页面。固定行和按钮继续复用公共 F5 控件。

名单与候选按钮宽度均为47，保留4间距及左右8内边距；当前522宽内容区每行正好10列。名单34高、候选48高不变。图标使用原有50×34/48×48居中拟合范围，外框变窄不降低图标缩放；图标实际最大46/44宽仍在按钮内。物品底框由ItemsRenderer在按钮范围内四边各内缩2，名单显示43×30、候选43×44；图标继续用完整拟合范围居中，允许在底框边缘略微探出，不按底框裁切或缩放。十列、间距、滚动高度及完整按钮命中保持原样；普通功能按钮不收缩。

选中候选仅在卡内右上角显示小绿对号，无绿框或填色；短左笔与上挑长右笔使用不同粗细，形成轻快笔势，不增加动画。名单移除叉号沿用小尺寸轮廓，两笔略有错落，启用为亮红色、禁用为暗红色，底色保持12×12；18×18命中区域不变。`ItemsRenderer` 的绿对号、移除底色和红叉号借用游戏 `MagicPixel`，按长度缩放的绘制必须显式采样 `(0,0,1,1)`。纹理宽高不是一个像素，不能用整张纹理的缩放代替目标尺寸；替换资源时仍沿用借用生命周期，不释放游戏纹理。

`ItemPickerInput` 保留页内选择时最小文本 token、原 blockInput 租约及 WritingText/真实释放尾部；不包含设置访问或热键命令。不夺取 Notes/聊天/原版文本 owner。主页面控件和公共滚轮仍可使用；按下锁定类型、名单、选择代次和几何，仅同目标合法释放提交。裁切外不可点，叉号优先与本体互斥；删后重排不复用同一手势。Notes BeforeLeave 拒绝离开时仍保留当前草稿。失焦合成空样本不结束真实尾部，字体/资源借用边界不变。
