# 物品自动处理实现设计

本设计落实[已接受合同](../功能介绍/自动存放功能行为合同.md)；任务授权和动态状态在 [#46](https://github.com/Kuroneko2020/JueMingR/issues/46)。代码、自动验证、安装和三种拓扑实机分别给证据，本文件不是完成声明。总体项目依赖及状态所有权继续遵守[总体架构](总体架构与状态所有权.md)。

## 边界与唯一所有者

三项分别称自动堆叠、自动出售、自动丢弃；首次关闭，出售默认 2337/2338/2339，丢弃空。物品领域拥有两名单、三期望状态、有限的取得意图及卖＞扔＞存决策。配置由独立进程级 PreferenceDocument 保存；UI 只提交同一组偏好命令。Host 持有原版对象、因果回调、版本适配和实际操作，不能判断名单或另存期望状态。

沿用并扩展现有 Runtime 的会话生命周期；群系与物品接入同一会话代次，群系仍保留自己已接受的单人能力门。会话身份需要本机 Player 对象、世界身份、连接身份和死亡边沿，不能只看 active bool。代次由唯一 Runtime owner 发放；任何旧结果不得跨代次重新应用。

领域及 Platform 值不包含 Terraria Item/Player、反射句柄、可变原版数组或图形资源。Host 游戏线程产生语义槽观察，再由领域发三个具体 typed 请求；不以字符串分派动作，不建立事件总线或通用工作流。操作协调只记录本任务真实冲突范围，不强制所有请求进全局队列。

## 来源、观察与整栈资格

世界来源绑定实际 Player.PickupItem(WorldItem) 调用；开启来源绑定 ItemSlot.TryOpenContainer 的完整外层调用，依据目标版本 OpenableBag 与实际成功分支。GetItem 设置名、newAndShiny、未知增长均不是来源。

因果作用域内记录非币物品实际进入合法主包的增量，作用域完成后才提交来源；作用域未完成时不执行自动动作。开启原物及钥匙消费不能被自己的观察当作产物。虚空接收、落地产物不算主包接收；落地后真正拾取是新事件。嵌套取得只归一个最近的合法外层作用域，避免双计。

主包合法输入为 0..49、54..57 的有效非币物品；50..53 是币槽，58 是鼠标槽。收藏、鼠标拿持、当前使用、原版手动动作和在途来源逐实际槽保护，不笼统排除快捷栏或弹药栏。名单按 type；存放要求 maxStack>1 并按实际 Item.CanStack 兼容关系分组。指定 .8 的 CanStack 仅比 type/prefix，不能单独替代可堆叠门。

一次可靠取得允许处理执行前当前兼容组的合格整栈，包括旧数量。来源意图不是数量额度，也不是永久 type 许可。每个兼容组在一次处理机会结束、明确无适用目标、取消或有限期限到达后终结；下一次可靠取得才能再次建立该组意图。连续取得只合并重复信号，不能以每次续期建立永久许可。移动、拆合栈不凭旧槽号执行；当前实际观察与请求开始前复核共同确定输入。

卖扔不依赖来源，名单修改及启停可影响已有库存；出售只有当前有效 NPC 商店才参与。处理开始前重判卖＞扔＞存。明确不适用才可选下一动作；执行中、部分副作用、未知结果均不能直接降到下一动作重做同一资源。

## 操作与结果

请求带会话代次、当前观察身份、实际来源槽和类型/前缀/数量/收藏/使用状态。Host 开始前重新核对，旧观察不能直接写游戏。未开始的不适用、拒绝与已开始后的执行中、完成、部分完成、失败、取消、超时、未确认分开。

出售走经核验的原版完整槽位出售路径，核对店和玩家购物状态；保留动态价格、回售调整、零收入和有限回购语义。Player.SellItem 只是收款段，不能独自算完整交易。其容量失败会替换前58槽的备份，故影响范围是整个前58槽加店/回购；不能与任何重叠在途槽并发。收款后异常不得再执行整笔或回写旧整包快照。

丢弃走原版垃圾桶分支，保留 Clone、研究附带副作用、替换旧垃圾桶和清源顺序。原垃圾桶可含任何内容；连续成功后只有最后一项可按原版取回。输入槽与共享垃圾桶串行，未知替换停止后续覆盖，不将世界掉物当垃圾桶处理。

存放只给原版三参 QuickStackToNearbyChests 传入选择性 SourceInventory；不调用全包、个人银行或 void 路径。原版负责真实世界 Chest、600px 范围、锁/占用、已有兼容栈及同类容器空位、部分容量与顺序。选择性数组归本次 Host 操作所有，不暂时改真实 inventory、favorite 或 maxStack。单人同步结果核对兼容组总量及对应目标；原版来源合并会改变每槽数量，不能将这种合并误认成入箱。

客机复用原版 net5/85，只有一个占用共享 netInv 的未收口批次。发送前排除既有原版库存操作和槽锁；发送不是成功。只有当前会话、本批槽范围、确实应用的来源 net5 及实际余量能领取结果；反向85只是阻挡提示。所有来源回复均领取后按各兼容组判完成/部分/零移动，不能一个槽回复便宣告全批成功。无法确定的异常/超时停止受影响资源的自动重试；不强清原版锁，不根据 unlock 或本地数量下降猜业务成功。

原版没有 R 请求 ID、逐业务提交/回滚协议。服务器已入箱而客机余量回复未达时本地仍有原物。断线后的两个历史可能不可区分；本功能不能承诺跨断线资源守恒。允许的处理是未确认、不重发、不回填、不跨会话重放；不能增加丢物、保存账本、禁止退出或服务器组件来伪造确定结果。生命周期接入 .8 的本机 DropItems/DropCoins 与 SaveAndQuit 边界，在原版动作前结束旧会话，不阻挡原版死亡或保存；世界/角色/连接身份变化也发放新代次。

## 在途原槽保护的必要宿主门

原版网络锁不是所有写槽入口共同遵守的事务锁。已核验 .8 的主包接收 helper、FillAmmo、ConsumeItem 和收竿选饵都有独立路径；手柄也可直接开袋。必须在实际副作用之前保护本批原槽，同时保留其它槽的原版行为。

- 两个主包接收 helper 可按实际目标索引拒绝，原版继续接收其它位置。
- FillAmmo 的合栈和空槽循环均需显式跳过在途索引；返回 Air 会让空槽分支反而覆盖原物，禁止此伪空槽方案。
- PickAmmo_IterateRange 可过滤传入索引序列；不改共享 AmmoSlotOrder 数组。
- 开始使用、QuickBuff、手动 ItemSlot/手柄入口按真实对象和槽保护。仅拒绝末尾 CanConsumeConsumableItem 会形成免费效果，不能采用。
- ConsumeItem、饵料、工具辅助材料需核对实际选料和效果顺序；不能只守 HeldItem，也不能假定所有扣料经 ConsumeItem。
- SortInventory 保留原版 HasLockedInventory 门，同时尊重 R 在原版解锁后仍未确认的有限范围。
- 原版手动出售的58槽备份范围也与在途源冲突，保护实际 SellItem 入口，包含鼠标持物点击商店的分支。
- 自定义货币购买可能备份/恢复全部源数组，在任何自有在途范围存在时等待。普通金币买入只因保护范围中的币槽/空槽拒绝；已经收到 Air 而同批其它槽未收齐，也不能被找零占用。

以上保护作用于本机共享会话的自有未确认范围；闲置早退。方法签名、版本身份与必要 IL 形状全部通过后才允许发送存放请求。匹配失败在 HostItems 内关闭物品能力，保留 F5/Notes，不得以“待实机”放行缺少必要保护的候选。

## UI、名单与保存

所有者在 #46 本次修正中撤除三项快捷键绑定，改用页面明确“开启/关闭”。删除绑定控件、录入、冲突解析、运行切换和业务字段；不保留可绑定键盘占位。F5 固定键、Notes 文本/输入法/阅读修饰键及其它页惰性键盘图案保持原职责。

三行顺序为自动堆叠、自动出售、自动丢弃；出售/丢弃的“添加”与开启/关闭同组，名单紧接对应行。完整行面板、名称内边距、组右对齐、字形宽度、居中、等高等距和选中短线由 `F5RowLayout`、`F5ControlRenderer` 共用于信息页与物品页。信息页的群系命令映射仍在原 owner；公共控件不依赖群系状态。期望开启显示绿色短线，关闭显示红色短线，文字保持普通字色；无商店等不适用条件不改变期望，真实故障另行提示。重复提交已选状态不生成偏好 revision 或写盘。

名单使用40 logical 图标卡片、4间隔，按可用宽度多列换行；空名单不占额外内容区。“点选图标可替换或移除；悬停查看名称”提供发现入口。点击卡片打开明确编辑弹层，再选替换或移除；替换选择新类型即提交，移除释放时提交。添加从当前合法主包按 type 去重、排币和已有项，可借收藏物提供类型；批选只是草稿，确定才追加，取消不提交。点击卡片不操作实际背包物品。始终保留“启用后，名单提交会影响已有库存”提示；普通保存成功和每次自动处理结果不常驻，真实故障/未可靠保存保留。

绘制与命中消费同一个生产几何缓存。偏好、可用性、字体/资源、滚动、窗口/弹层尺寸或草稿变化才重建；稳定帧不重造整页。长名单只构造、命中和绘制可见卡片，候选只在打开/刷新时读取有界主包。按住后重排、滚动、切页或失焦取消原目标。Notes `BeforeLeave` 先裁决，拒绝离开保留草稿；接受离开才取消 Items 草稿。

`ItemPickerInput` 只拥有名单/编辑弹层的 `CurrentInputTextTakerOverride`、原 `blockInput` 租约及 `WritingText`/真实释放尾部；没有设置访问、键位注册、组合解析或开关命令。失焦的合成空样本不结束尾部；外来文本 owner 的 token 与键样本保持。过小视口只取消不能显示的弹层并提示，F5/Notes 可继续使用。

配置仍为 `<verified game>/JueMingRData/config/features/item-automation.json`，format `JueMingR.ItemAutomation`，当前写入 version 2，仅三开关和 `sellTypes/discardTypes`。version 1 在严格解码边界识别三个旧 Int32 字段 `stackBinding/sellBinding/discardBinding` 并丢弃，不验证或恢复按键语义。完整可靠读取后仅标记原件；第一次真实保存前精确保留到 `.schema1-original`，后续 `.bak` 轮换不覆盖该原件。加载/安装不自动改写，不存在时不预创建。未知版本/字段、重复非法结构、坏数据、外部冲突和不可靠 I/O 均保护原件；正式文件缺失而恢复材料存在时不创建默认替代。

Host 装配独立 `PreferenceDocument` 与既有 `AtomicFileDocument`，只为该物品文件接入有限旧格式退休。不可变值按内容相等；64 KiB、类型集合/节点界限、去重排币继续适用。不保存来源、槽号、事务或错误历史，不改变 Notes/config 其它格式。受保护文件下明确修改可仅在本次内存生效，并显示未可靠保存；文件工作在独立后台完成。

本次实际查看附件01（当前 R 信息页）、02（历史 Z 物品页）、03（被拒绝候选），前者是控件语言依据，02只作三项/名单结构参考，03定位固定大列和绑定表单偏差。原图保留于忽略任务资料，来源/哈希已在 #46 登记，不进入编译/运行。旧合同“未找到截图”保留为当时事实。本次未取得该材质包原件；动态同候选信息页、默认物品页、较长名单、添加与编辑预览入口已同步，设备创建前 XNA adapters=0 按所有者授权待补，不能称视觉已验证。业务实机、多人及 FPS 仍由所有者实际反馈另证。

## 成本、停止与验证

全关且无在途收口时不做领域背包/容器扫描；无可靠来源不找箱，无商店出售尽早不适用。不为观察开线程、日志或永久历史。开启的三项共用一次最多58槽观察；可靠事件即时标脏，没有可靠事件的库存/收藏/使用变化按6 tick 有界轮询。原版锁、手动动作、使用忙碌与交互锚分别入观察版本，一个条件解除不能被另一个仍忙的条件掩盖。一次最多尝试一个候选；原版等值58槽 clone 更新对象身份但不制造新的业务版本。

取得意图容量受主包槽/当前类型数约束，持久时间有限。一个无目标意图终结不能让别的卖扔等待；只有真实相交范围阻挡。全关/改名单取消未开始意图，已开始的必要接收与错误收口保留有限状态，不丢掉尚未知的真实资源状态。

| 实际所有者 | 状态与界限 | 终止/失效 |
| --- | --- | --- |
| ItemAutomationFeature | 最多128个 type/prefix 来源意图；600 tick 从首次未处理取得起计，重复信号不续期 | 关闭堆叠、会话结束、一次非拒绝操作机会、消失或到期；异常溢出显式停止 |
| ItemHostObservation | 58槽语义快照及当前 Item 引用；商店实例；分别记录临时准入门 | 当前值变化刷新版本，身份变化更新执行复核；会话结束清除 |
| ItemOperationOwnership | 出售58槽，丢弃源槽/垃圾桶，存放所选槽及共享批次；另保留异常开启受影响槽 | 确定结果释放；未知/超时不自动释放或重发；新会话不重放 |
| ItemNearbyStorage | 最多一个客机批次；最多64个已证实零移动的兼容组容量短缓存 | 批次600 tick 后只留有限迟到回复收口；容量120 tick、位置变化、箱更新/手动箱操作或会话结束失效 |
| ItemsPresentation / ItemPickerInput | 当前可见控件、最多主包类型数的候选、临时选择与键盘/鼠标尾部 | 提交/取消/离页/失焦；自己创建的 Rasterizer 释放，借用游戏纹理不释放 |

附近目标遍历仅在实际存放尝试时调用原版范围入口；缓存只来自实际零移动，包括客机完整来源回执的零移动，未知本地箱内容不建立拒绝前检。关闭后的每 tick 收口仅检查有限状态；不继续领域扫描或建立新意图。相关投射物材料保护至多每观察 tick 扫描原版1000投射物数组一次，且仅在当前候选确实涉及饵料、电线或促动器时执行。UI 名单按可见卡片构造/绘制，物品候选只在打开或刷新时读取58槽；动态成本证据和限制在 #46，不将调用数或夹具耗时换算为 FPS。

实际文件按自然职责分为领域偏好/来源选择、Host 观察、三个受控出口、来源 Hook、在途保护、呈现/绘制/名单输入和 Host 装配。没有第二个 Runtime、事件总线、永久数量账本或通用队列；测试分为领域架构检查、独立手写 ABI/操作替身、生产 Host 加载、真实 XNA UI 和安装恢复。

内部顺序：领域失败判据与设计→配置/UI/真实选择性操作首链（及早验证客机）→唯一 owner/出口/冲突结构检查→其余动作与UI→组合/来源/异常/隔离文件/成本→新上下文完整差异审查→clean候选顺序重复构建、包审计和安全安装。所有步骤属于 #46，无额外框架验收任务。

自动验证须独立检查交易币值/回购、垃圾桶允许销毁、转移源与目标或真实槽结果，不能只看调用次数。模拟网络、夹具和局部原版证据不代替三拓扑实机。图形检查只有当前环境证实设备创建前失败才按本次授权延期。保持既有完整入口；关键安全路径未实现或已知不安全时不安装候选。不得运行真实游戏、真实服务端或触碰日常存档作测试。
