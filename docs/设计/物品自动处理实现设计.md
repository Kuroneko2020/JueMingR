# 物品自动处理实现设计

本设计落实[已接受合同](../功能介绍/自动存放功能行为合同.md)；任务授权和动态状态在 [#46](https://github.com/Kuroneko2020/JueMingR/issues/46)。代码、自动验证、安装和三种拓扑实机分别给证据，本文件不是完成声明。总体项目依赖及状态所有权继续遵守[总体架构](总体架构与状态所有权.md)。

## 边界与唯一所有者

三项分别称自动堆叠、自动出售、自动丢弃；首次关闭，出售默认 2337/2338/2339，丢弃空，三键未绑定。物品领域拥有两名单、三期望状态、有限的取得意图及卖＞扔＞存决策。配置由独立进程级 PreferenceDocument 保存；UI 只提交同一组偏好命令。Host 持有原版对象、因果回调、版本适配和实际操作，不能判断名单或另存期望状态。

沿用并扩展现有 Runtime 的会话生命周期；群系与物品接入同一会话代次，群系仍保留自己已接受的单人能力门。会话身份需要本机 Player 对象、世界身份、连接身份和死亡边沿，不能只看 active bool。代次由唯一 Runtime owner 发放；任何旧结果不得跨代次重新应用。

领域及 Platform 值不包含 Terraria Item/Player、反射句柄、可变原版数组或图形资源。Host 游戏线程产生语义槽观察，再由领域发三个具体 typed 请求；不以字符串分派动作，不建立事件总线或通用工作流。操作协调只记录本任务真实冲突范围，不强制所有请求进全局队列。

## 来源、观察与整栈资格

世界来源绑定实际 Player.PickupItem(WorldItem) 调用；开启来源绑定 ItemSlot.TryOpenContainer 的完整外层调用，依据目标版本 OpenableBag 与实际成功分支。GetItem 设置名、newAndShiny、未知增长均不是来源。

因果作用域内记录非币物品实际进入合法主包的增量，作用域完成后才提交来源；作用域未完成时不执行自动动作。开启原物及钥匙消费不能被自己的观察当作产物。虚空接收、落地产物不算主包接收；落地后真正拾取是新事件。嵌套取得只归一个最近的合法外层作用域，避免双计。

主包合法输入为 0..49、54..57 的有效非币物品；50..53 是币槽，58 是鼠标槽。收藏、鼠标拿持、当前使用、原版手动动作和在途来源逐实际槽保护，不笼统排除快捷栏或弹药栏。名单按 type；存放要求 maxStack>1 并按实际 Item.CanStack 兼容关系分组。指定 .8 的 CanStack 仅比 type/prefix，不能单独替代可堆叠门。

一次可靠取得允许处理执行前当前兼容组的合格整栈，包括旧数量。来源意图不是数量额度，也不是永久 type 许可。每个兼容组在一次处理机会结束、明确无适用目标、取消或有限期限到达后终结；下一次可靠取得才能再次建立该组意图。连续取得只合并重复信号，不能以每次续期建立永久许可。移动、拆合栈不凭旧槽号执行；当前实际观察与请求开始前复核共同确定输入。

卖扔不依赖来源，名单修改及启停可影响已有库存；出售只有当前有效 NPC 商店才参与。处理开始前重判卖＞扔＞存。明确不适用才可选下一动作；执行中、部分副作用、未知结果均不能直接降到下一动作重做同一资源。

## 操作与结果

请求带会话代次、当前观察身份、实际来源槽和类型/前缀/数量/收藏/使用状态。Host 开始前重新核对，旧观察不能直接写游戏。未开始的不适用、拒绝与已开始后的执行中、完成、部分完成、失败、取消、超时、未确认分开。

出售走经核验的原版完整槽位出售路径，核对店和玩家购物状态；保留动态价格、回售调整、零收入和有限回购语义。Player.SellItem 只是收款段，不能独自算完整交易。其容量失败会替换前58槽的备份，故影响范围是整个前58槽加店/回购；不能与任何重叠在途槽并发。收款后异常不得再执行整笔或回写旧整包快照。

丢弃走原版垃圾桶分支，保留 Clone、研究附带副作用、替换旧垃圾桶和清源顺序。原垃圾桶可含任何内容；连续成功后只有最后一项可按原版取回。输入槽与共享垃圾桶串行，未知替换停止后续覆盖，不将世界掉物当垃圾桶处理。

存放只给原版三参 QuickStackToNearbyChests 传入选择性 SourceInventory；不调用全包、个人银行或 void 路径。原版负责真实世界 Chest、600px 范围、锁/占用、已有兼容栈及同类容器空位、部分容量与顺序。选择性数组归本次 Host 操作所有，不暂时改真实 inventory、favorite 或 maxStack。单人同步结果核对兼容组总量及对应目标；原版来源合并会改变每槽数量，不能将这种合并误认成入箱。

客机复用原版 net5/85，只有一个占用共享 netInv 的未收口批次。发送前排除既有原版库存操作和槽锁；发送不是成功。只有当前会话、本批槽范围、确实应用的来源 net5 及实际余量能领取结果；反向85只是阻挡提示。所有来源回复均领取后按各兼容组判完成/部分/零移动，不能一个槽回复便宣告全批成功。无法确定的异常/超时停止受影响资源的自动重试；不强清原版锁，不根据 unlock 或本地数量下降猜业务成功。

原版没有 R 请求 ID、逐业务提交/回滚协议。服务器已入箱而客机余量回复未达时本地仍有原物。断线后的两个历史可能不可区分；本功能不能承诺跨断线资源守恒。允许的处理是未确认、不重发、不回填、不跨会话重放；不能静默增加丢物、保存账本、禁止退出或服务器组件来伪造确定结果。具体死亡/保存接线仍须以 .8 实际方法核验，不能从槽锁推断。

## 在途原槽保护的必要宿主门

原版网络锁不是所有写槽入口共同遵守的事务锁。已核验 .8 的主包接收 helper、FillAmmo、ConsumeItem 和收竿选饵都有独立路径；手柄也可直接开袋。必须在实际副作用之前保护本批原槽，同时保留其它槽的原版行为。

- 两个主包接收 helper 可按实际目标索引拒绝，原版继续接收其它位置。
- FillAmmo 的合栈和空槽循环均需显式跳过在途索引；返回 Air 会让空槽分支反而覆盖原物，禁止此伪空槽方案。
- PickAmmo_IterateRange 可过滤传入索引序列；不改共享 AmmoSlotOrder 数组。
- 开始使用、QuickBuff、手动 ItemSlot/手柄入口按真实对象和槽保护。仅拒绝末尾 CanConsumeConsumableItem 会形成免费效果，不能采用。
- ConsumeItem、饵料、工具辅助材料需核对实际选料和效果顺序；不能只守 HeldItem，也不能假定所有扣料经 ConsumeItem。
- SortInventory 已在 SortCoins/SortAmmo 前检查 HasLockedInventory，保留该原版门。
- 原版手动出售的58槽备份范围也与在途源冲突，不能仅拦本领域的自动出售。

以上保护只在本机客机、自有在途范围存在时生效；闲置早退。方法签名、版本身份与必要 IL 形状全部通过后才允许发送存放请求。匹配失败或保护闭包未实现不得启用客机自动堆叠，不得以“待实机”放行完整交付。此处的待实现门不是缩减多人目标。

## UI、名单、键位与保存

物品页按已接受功能行/操作组/名单区布局，只给实际三项控制。独立 Items presentation 复用 F5 布局、UiSurface、当前字体度量、裁切与滚动。绘制和命中使用同一个快照；按下记录目标/几何/代次，释放同目标才提交。名单批选是临时草稿，确定才添加；替换直接选定提交，移除为明确命令，取消/离页/失焦丢弃临时选择，保持真实输入尾部消费。

候选从当前合法主包按类型去重，排币和本名单已有类型；收藏栈允许提供名单类型，执行时仍保护实际收藏栈。提交已启用名单会影响现有库存，界面直接说明，不增加逐件确认。UI 不持有可变真实 Item，不以点击候选卡执行卖扔。

三键通过同一偏好命令切换期望值，F5隐藏不停止后台。键位捕获、聊天/Notes/名单编辑、F5、游戏绑定、失焦由壳层对同一冻结键样本仲裁；被屏蔽仍更新边缘基线，解禁不补触发。绑定明确支持范围、冲突和清除；不能只有图标。Notes 的 BeforeLeave 保存门必须组合，不能被物品页覆盖。

配置文件为 `<verified game>/JueMingRData/config/features/item-automation.json`，format `JueMingR.ItemAutomation`、version 1。保存三开关、sellTypes/discardTypes、三绑定；不保存来源、槽号、事务和错误历史。不可变值实现内容相等，避免绕过 PreferenceDocument revision 或编码自检。名单去重、排币；解码对未知字段、属性、未来版本和不合法值保护原件，不自动重写。最大字节沿用65536，节点数与当前目标类型数有界。

Host 装配独立 PreferenceDocument 与 FilePreferenceStorage。正常缺失不创建文件，默认全关；损坏或读取不可靠仍全关且保留原件。用户显式命令可在内存生效，必须准确提示未可靠保存。合并后台保存，不阻塞 Draw/输入/每项动作；不触及 Notes、UI 或 Legacy 配置。

## 成本、停止与验证

全关且无在途收口时不做领域背包/容器扫描；无可靠来源不找箱，无商店出售尽早不适用。不为观察开线程、日志或永久历史。开启的三项共用一次最多58槽观察；可靠事件即时标脏，没有可靠事件的库存/收藏/使用变化允许有界轮询，具体 cadence 和最坏规模由实际接线测定并登记 #46。

取得意图容量受主包槽/当前类型数约束，持久时间有限。一个无目标意图终结不能让别的卖扔等待；只有真实相交范围阻挡。全关/改名单取消未开始意图，已开始的必要接收与错误收口保留有限状态，不丢掉尚未知的真实资源状态。

内部顺序：领域失败判据与设计→配置/UI/真实选择性操作首链（及早验证客机）→唯一 owner/出口/冲突结构检查→其余动作与UI/键位→组合/来源/异常/隔离文件/成本→新上下文完整差异审查→clean候选顺序重复构建、包审计和安全安装。所有步骤属于 #46，无额外框架验收任务。

自动验证须独立检查交易币值/回购、垃圾桶允许销毁、转移源与目标或真实槽结果，不能只看调用次数。模拟网络、夹具和局部原版证据不代替三拓扑实机。图形检查只有当前环境证实设备创建前失败才按本次授权延期。保持既有完整入口；关键安全路径未实现或已知不安全时不安装候选。不得运行真实游戏、真实服务端或触碰日常存档作测试。
