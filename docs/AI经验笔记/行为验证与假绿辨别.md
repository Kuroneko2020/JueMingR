# 行为验证与假绿辨别

本页保留真正发生过的判定失败；当前要求以[测试与审计规则](../规范/测试与审计规则.md)为准，不迁入旧健康审计、固定轮次或通配命令。本次只整理，没有运行产品测试。

## 实现和测试共享同一错误假设

DisplayDoll 旧测试以实现的 pseudo-world/zoom 公式生成期待，证明了内部自洽，却没有经过真实原版 DrawPlayer 管线；后来把“贴对象底部”设为正确，又与原版脚点证据冲突。正确辨别需要独立原版锚点、原始纹理真实 RGBA、最终绘制几何及有代表性的视觉反馈，各自回答不同问题。合成 RGBA 只能证明像素分析器，游戏截图的屏幕 RGB 不能冒充源 render target RGBA。

“实机探针”若先给生产打开 fullbright/重建纹理，再抓失败，会污染 expected-red，无法证明旧失败还存在。先冻结实际候选、输入与失败样本，确保对照只改变待检因素；生产修复与取证工具各有授权和退出边界。真实 Draw 没有被调用、target 内容丢失或样本来自旧包时，不能用 helper 绿补成实机通过。

来源：旧 `排查复盘/蓝图DisplayDoll坐标旧公式假绿-2607090513.md`、`蓝图DisplayDoll同管线假绿修正-2607091258.md`、`蓝图DisplayDoll离屏纹理真实像素与生命周期假绿-2607100807.md`、`蓝图DisplayDoll实机探针不得污染生产红测试-2607101134.md`、`蓝图DisplayDoll真实像素探针证据边界-2607100951.md`、`蓝图DisplayDoll同管线第二轮假绿治理-2607102303.md`。结论已按[后续原版脚点](蓝图多格物体与镜像.md#原版脚点源图脚点与可见底行不是一个值)及[真实像素](绘制分层与图形资源.md#displaydoll黑像素与空纹理需要不同证据)修正，不保留旧错误 oracle 作为建议。

## 反射与运行输出的身份

Compat 测试一度断言自建 Terraria.Main stub，但运行解析命中真实 Terraria 程序集同名类型；失败反映两套状态不是同一个 owner，不能只改产品写入掩盖。应检查 resolved Type 的程序集和实际被测实例。另有 `--no-build` 读取默认 bin 而实际 x86 构建在另一目录的旧输出案例：命令退出 0 不等于执行了最新候选。

来源：`排查复盘/Compat反射测试程序集命中偏差-2606190208.md`、`蓝图DisplayDoll收口验证命令与PowerShell字符串-260709.md`。后续使用 R 既有构建记录与明确输出路径核对，不复制 Legacy 命令或改其文件。

## 生命周期与隔离也会改变判定

同一游戏 tick 的时间戳可能采于状态创建之前，若测试把它误判为时钟回退，会错误终止合法首观察。历史修正只限定首次锚定窗口，不能容忍接受首观察后的真实回退。写入测试必须在静态初始化/后台入队前确定隔离根；stop 的预算返回不保证线程实际退出，不能立刻删除它仍可能访问的目录。路径过长出现 DirectoryNotFound 也不直接证明业务目录不存在。

来源：`协作方法/同一游戏tick生命周期时间戳与真实帧序列测试-2608261254.md`、`临时测量Owner退役与测试进程隔离-2608280231.md`、`排查复盘/蓝图世界实例测试路径过长-2607072051.md`。

## 用户可用性与性能结论

Catalog 的 Implemented(true/false)、源码存在、审计通过都不是叶级功能可用性的充分证明；旧蓝图和笔记入口元数据尤其不能单独判定缺失或完整。实机清单应让用户执行已准备好的明确动作、观察短文本结果、遇到未就绪安全跳过，不让用户解释 JSON 或给未定义分数。

60 FPS 封顶不证明有余量；原版 F10 整数刷新与 Alt+F7 的 600 帧输出不是零成本常驻测量。一次本地 wall-clock、静态调用数、低频缓存或旧测量退出都不证明 FPS 根因/收益。来源：`排查复盘/实机性能清单不能照抄技术矩阵-2608060250.md`、`Terraria原版参考笔记/UI_Input_notes.md`。当前新增观察能力仍须遵守已接受的[安装退出](../规范/性能治理规则.md#观察能力分类与安装退出)，不是保留探针才能维持验证信心。
