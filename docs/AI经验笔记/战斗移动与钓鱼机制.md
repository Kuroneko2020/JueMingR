# 战斗移动与钓鱼机制

## AI 钓位与原版钓鱼事实

20 格约束的是合法入液入口距离。高窄池的水量仍由原版连通深度计量，按池中心排序或只计算圆内的水量会选错池。抛法经过合法轨迹才进入原版实际释放，实际浮漂入液是报告依据。原生一次收竿可带回多漂，TryStartUse 返回 false 也可能已消费收竿，需核实原版拉漂和实际产物各自的结果。

坐姿由原版家具占用、方位和角色状态提供，稳坐后普通导航的微调会使其起身。钓点冻结，危险结束时回原位。多人按真实 Actor 传递场景和任务资格，主人身边的候选不能替代队友位置。自动配装接受手动新组为基准，自动换装仍可合法选组，借件仍按原来的真实组归还。具体接入与证据边界见[AI 队友钓鱼实现设计](../设计/AI队友钓鱼实现设计.md)。

## 独立人物创建与硬核存档边界

原生人物流已保存 difficulty、七色、hair／skinVariant 和声音；扩展创建输入时应贯通初始化、序列化和 Reset，不能只改界面。Reset 若仅比较 difficulty==3，会把中核／硬核悄悄变经典。创建草稿不能预领物资，确认后才一次初始化；发型创建集合与世界理发师解锁集合不同，不借切 Main.gameMenu 获取名单。

临借 Main.myPlayer 只处理原生消费者身份，不迁移 Main.ActivePlayerFileData／playerPathName 的存档归属。硬核 KillMeForGood 仍读取后两者并删除文件，所以 AI 必须在真正终局出口按精确身体分流；不能把全局路径换成假文件，也不能只按 difficulty==2 封所有复活。surviveHardcoreDeath 扣除 60 基础生命仍大于零的原生例外没有进入终局。永久死亡需由自有档案与资源同一提交表达，普通 dead／respawnTimer 不承担跨世界身份；捕获失败先阻止重新激活，再保留唯一最终身体重试。具体机制与证据边界见[队友设计](../设计/AI队友正式实现设计.md#创建草稿与终局)及 #184，不外推为实机体验。


## 普通客户端对照与必要本地阶段（2026-11-17）

NPC23不是完整快照。必须以同包序列、同可用历史、同玩家/地形输入、同消费阶段下的普通原版客户端作观察端基准；服务器源对象证明发布来源，不自动提供新receiver未收到的隐藏历史。前轮Armed终态“源21/首次14、Hurt986”FAIL原件不改，但新普通receiver首次也为14，实际contact输入同14；旧期待缺少接收端基准，不能继续指导把首次强写21。手选serializer非单射仍只证明手选域，不证明普通客户端必然不可恢复。

真正额外缺口是本地第一轮结束后不再入下一轮。必要本地阶段可以在原版近身、目标/地形条件下重新挥击，当前TargetClosest和碰撞后的sprite方向同属扩展攻击框来源；不是只老化一份已接受动作。源端用真正server mode、connected/state10/broadcast/实际活跃section运行原生发送条件，实际NPC包全部FIFO喂plain/product，数量按原件记录，不人为停发或丢包。plain对照临借第三表并隔离产品Hook owner/current，原生decode/Update/contact不执行产品Prepare、Reset保护或静态矩阵owner；finally归还表、Hook及全局slot状态。

690/AI126也会在普通客户端本地再次起跳、减速、穿墙和更新ai2/ai3。先区分首次decode的defaults与下一local action，不从server已穿墙直接要求首包镜像，也不因这一历史差全面封攻击。AI126内使用的gravity须在action前建立，随后公共重力/碰撞尾只一次。359首个非零ai3包尚未做客户端尺度应用；仅local action按原生公式改尺寸和位置，并保留实例当前形态，重复同form23不还原defaults后再移一次，新gen则从原生defaults开始。

首次远处23被filter并不等于该槽永远未知：可保留有界slot/真实point候选，供同一Actor首次进入已载区域时触发现有合并154/8基线lane；候选不是body/revision/NpcBaseline。实际原生8/23/54/49后才建立观察，缺席/过滤完成有终止，不按旧位置逐帧全量请求。旧已建立离返与免疫证据保原身份。原 fresh 通用 Fighter unstuck 失败（普通 Y915.075、共享 Y920）已由当前共用脱困机制修复，原件不改。关键是先捕获动作入口 vx==0 且未受击，再依 oldPosition、反向移动、justHit 和玩家交叠推进 ai3；Armed 动作随后才阻尼速度并更新挥击。支撑/头顶、前方地形和 sprite 朝向成立后才使用先前资格起跳，不能见动作后 vx==0 或 raw ai3==1 就跳。实际 native Strike 产生的 justHit 只消费一次，重力碰撞仍各一次。fresh 长跳46步内没有第二个落地挥击不是运动失败：此段严格比较几何/速度/clock和动作后真实 contact；连续近身窗口独立要求第二次挥击与换侧扩框 Hurt。两目的不能混用聚合断言，也不能强落地/停包造第二轮；完整 critter/完整 Fighter 策略仍不代签。
只抑制观察副本的全局 Reset 还不够：原生射弹在 Inner hook 前先读 local/static 和玩家 melee cooldown，85 的真实 -1 会跨槽换代挡新敌。必须用独立 server 出生并恢复 client 旧 externals 取证，避免 source Spawn 提前清掉待测旧状态。静态冷却不是每 Actor 私有资源；同代真人与全部 AI 必须共享，仅主/副旧新代并存时隔离，并在主流后来真实 Reset 时接续已命中新代的计时。原生 Matching clear 与真正同代 spawn reset 也须验证，不能只检查数组被置零。
## 共享 NPC 状态、槽清理与已载区兴趣重入（2026-11-16）

23 不传的字段应从原生生产者与最终消费者共同划界，不能只补一个怪名。尺寸会同时改变 Center、basic/ray、碰撞与接触；dontTakeDamage/immortal 在近战、射弹私有视图建立之前已有资格门；Solenian 的反射必须与倍率一起恢复，服务器对已错误发出的 28 不会补做反射。Summoner 防御还参与客户端穿甲补偿，原生光环的 100% 穿甲先加进 28，再由服务器减防；服务器重新 Strike 并不能补回少加的量。测试应读真实 DamageVar 结果再核严格补偿与服务器生命等式，不能把基础 40 误当随机后的固定 40。

持久形态以 decoder 的真实 defaults/difficulty/netID 为基数，重复 23 不重乘。461/417 已变形包带的是变形后 top-left，不能再照抄服务器保中心/底边移动；378 则先同步 timer10，下一动作才展开并止动、免伤。King Slime 的非零 SyncAnchor 必须在尺寸准备后用同一原帧锚点修正一次。物品 slime 的 full-health 位引用形态后的 lifeMax，数值受伤生命不能再乘。Antlion 的尾前支持点逆算另受 x86 扩展精度影响：值类型 Store 先落实 single，再要求正向加原速度精确回到收到的位置；这不是给预测加 epsilon。

样本当前字段与下一行动产生的属性不能混用。AI87 的合法 2→4 出版仍 noGravity=false、KB=scaled(.2)，下一次 4 行动才 true/KB0；raw4/ai1=0 也可能是长期稳定阶段。公共 Motion.Step 在下一行动置 true 不证明当前样本也应归一 true，严格 SameSample 不是 hint。当前阶段与首次来源的未决应留在任务中，不能用“都是飞行”“击退肯定为零”或修改比较容差替代证据。

此类局部来源资格有实际完成条件：首次/换 phase 解码不伪造未来 sample flag，真正共享 NPC 动作完成必要纯字段/KB/几何后才开放该 NPC 的 AI 出伤与预测；其他目标/角色及此 NPC 的原生接触不暂停。同 phase 新包保已建立本地 phase，不能每包重置而永久饥饿；缺地形/必要目标不因时钟流逝自动就绪。generation/netID/来源和兴趣生命周期撤销资格，raw tick/revision 与已经推进样本的 Fresh 门仍保持。它区别当前本地可消费状态与服务器隐藏历史字面镜像，不能代替直接 contact damage 本身的来源恢复。

realLife 还要带可消费根身份。用同源完成枚举校验头/前节/身体及代次，缺依赖合并原有 154/8，不盲读 ai3 或真人 wofNPCIndex。身体换头代次后，在下一物理步前也必须阻止旧绑定出伤；root 私有死亡只影响该 Actor 的兄弟段。Worm 的原生 CannotSpawnInSlot0 是真实入口条件，不能硬令普通 worm 出生在 0 来造证人；本轮合法的零根证人改用原生允许的 113/114，并保持真实 OnSpawn→AI28→23→8→命中/服务器链。Ogre/Deerclops 接触帧是实际攻击矩形输入，可从合法同步计时维护必要窗口，不必运行完整攻击 AI/FindFrame。

单换 Main.npc 数组不足以隔离原生创建。NewNPCInstanceInSlot 的 ResetNPCSlotData 清的是全局射弹免疫、所有玩家近战 CD/标签、Portal 冷却和 boss 索引；必须在精确观察解码槽内挡该全局副作用，真正原生出生仍执行。测试要先让原生人类攻击建立 immunity/tag；全局索引还应验证不同类型的二级包，避免同类型 OnSpawn 把错误清除又写回而掩盖缺陷。源 NPC 的正常出生同样会清这些全局行，冷夹具须 finally 归还，不能污染后续叶。

地形已载与 NPC 基线是不同事实。同 Actor 合法退出再返回同 section，要以真实 native Player.Update 保持站位、让更近普通朋友维持静止 NPC 的原生 target，证明无自然 23 时仍由产品主动恢复。按全队兴趣边沿合并请求；真实 49 对过滤移出/缺席也结束该轮，不能凭旧位置每帧请求。源与测试期待稳定后集中独审，原 FAIL、优化 Release 身份和未验证的 Steam/实机/FPS 边界留原任务，不用窄组件 PASS 外推全 NPC 策略。

## 附着弹首段、实际出手与家族生命周期（2026-11-25）

附着弹旧模型知道何时下坠，却只用未来不同时刻的直线方向试投。首个擦边接触可能比第一个可靠中心方向更早通过，全部失败时真人和 AI 都会退回当前中心。应先依据到达时刻反解下坠或弯曲的出手方向，再对整数光标映射、真实出生和地形重放。首段代表可达足以供普通手部消费，伤害、附着、免疫和派生沿各自机制验证。卡牌模式 3 还要读原版同 owner 的残留槽，包括非活动卡牌。真召回继续使用家族模型，槽已全返回时观察原版重置后的一次真实新生。

旧 Release 的骨头标枪反例通过原版 ItemCheck 真实出生，在 650px 慢移场景没有消费提前量，也没有正命中。此类检查要逐发绑实际借入点、弹体出生、目标真实位置和原版伤害，同时检验近距离纵移的中心余量。真人 6ms 与双队友共享 2ms 应各自计量，已有发射和有效解都要给分母。旧错误来自已存在的首段缺口，最初何时诱发用户现场的大范围失准仍未查明。见[附着弹实现](../设计/战斗辅助实现设计.md#附着弹首段与召回1840163-候选)。

## 导航地形、移动目标与动作回执（2026-11-24）

Terraria 1.4.6.1 的源码基线 `9288e52` 中，跨层规划可以在接替动作尚未就绪时撤掉在走的动作，直接行走又会被主人的高度门拒绝，连在一起产生空输入。反向也要查。朝主人的斜向路径受侧墙阻挡时，队友上方可能仍能起飞。主人已经落地或横向较远时，队友仍可能具备有用的本地下降入口。定位这类故障时，同时核对最终二维目标、当前段实际入口和接替是否可执行。旧动作是否该制动取决于它下一步会不会错过入口或破坏可控接触。检查输入后还要读取原生位移、离开支撑、落地与恢复。进展沿实际身体的当前段度量，主人的移动和动作序号变化都不能充作身体进展。真实失败仅限制同条件的请求。用户行为和验证状态分别回[现行合同](../功能介绍/AI队友功能行为合同.md)及 [#184](https://github.com/Kuroneko2020/JueMingR/issues/184)。

移动目标的实际控制按同一具原版身体的更新读取。图上的高落点遇到净空或接入失败后，同方向的低落点仍可能可走。查询保留未展开的高度与支撑入口，当前动作在真实位置接入；绕隔墙时直线距离虽短，沿眼前原版地面直追仍可能撞回墙面。该情况下沿有效出口推进，遇到真实阻挡再换入口。

动作序号对应真实原版输入与观察结果。从平台收到 Down 并实际失去源支撑后，即使下落距离很小，装备和地形变化也须从空中的实际姿态继续控制。伤害检查覆盖下一处可生存接触，落地后读取实际生命重新选段。正常可控行走和翼飞随目标变化，取消旧目标的动作不会产生几何失败记录。

Terraria 1.4.6.1 的普通候选 `e8e8b961` 在缺口进近时显露另一种抖动。同一 Walk、主人仍向前且身体速度仍朝前，制动余量门反复发出反向键，下一更新又恢复前进键，原版朝向逐步翻转。复现时同时读按键、朝向、速度和动作序号，单看位移会漏掉。平台边缘也须按身体足迹复核入口。纯平台末端从第一步即满足原版下穿，旧候选却先退 8.12px 到靠近格中心才于第 14 步发出 Down。紧贴实体的单格平台在格中心采样会触到实体，外缘实际脚位仍能原版下穿，旧候选连续 180 步静止。相邻的纯实体台边对照走 `Drop`，实际离岸、落地后继续跟随。原始对照与候选身份由[任务 #184](https://github.com/Kuroneko2020/JueMingR/issues/184)承接。

从平台与实体混合承托的位置开始时，脚位进入目标容差只说明走近了入口。应用首步原版重力复核 Down 的实际离撑条件。只验首次 Down 或首次下降还会漏掉身体在落下途中被原层实体再次接住。第四版隔离原版记录中，队友先移到只由平台承托的位置，第 9 步 Down、第 11 步离撑，第 31 步落到下一层，期间没有回到原层支撑。主人此前已在下层站定，第 36 步才开始走，便于把队友主动下穿与主人横移分开观察。缺口制动同样需要区分缺少支撑和撞墙等原因，只在缺支撑且实际惯性可停时选松键，仍保留门口及有效转向的原版控制。

同一普通候选的平地跟跑原版对照里，克盾在第 130 步已无冷却，原版已允许再次触发，相距 221.39px，安全跑道和收益均成立。更早一次仅因距离不足而沿用了地形检查的十步间隔，直到第 136 步才准备动作。第 137 步已进入冲刺动作，普通跑步当步松键，未发冲刺输入。第 138 步才实际触发，水平速度达 14.5px/更新。核对这一链时，分别观察距离资格、跑道与制动、方向与热键是否同次交付，以及真实原版冲刺回执。

原版克盾的冲量只有在相对当前惯性和真实翼速有帮助时才值得使用。天界星盘的水平悬停可快过克盾起冲，同样的选择器在较慢普通翼上可以让水平冲刺和升力交叠。试验用真实 `dashDelay`、翼量消耗和位置确认各阶段，再以现有物品交接改变能力来源。主动追赶另外记录停止后的真实减速、反向输入和位移。不能只看输入标志或角色曾经靠近。

Steam 1.4.6.1 的连续平台与石地对照把速度、方向和实际位移分开比较。旧平台制动只在短距离尝试原生接触，4.12px/更新越过旧 48px 检查门后便反按。固定状态同时取 4.10、4.12 与 5.25，原版身体跟跑再用独立移动的主人；远距离同侧稳态统计错误反向及朝向变化，避免把周期性的「右右右左」漏作只有两次连续交替。当前制动先识别可证明的平齐平台支撑，再用原生接触检查特殊地面。未证时保留可观察的短步和松键，确认危险时允许主动刹车。真的回头和接近停点分别观察。

核入场资格必须追溯原版的物品、套装、坐骑和单独动作入口。1.4.6.1 普通横冲型为分趾袜／忍者大师装备、克盾、日耀、晶体刺客与四种 Chillet。类型4无原版取得或启动分支。蝙蝠、轮滑与小妖精坐骑允许装备来源参与，普通持续方向加速和高速碰撞由原版坐骑接缝消费。公羊符文沿下降动作交付 Down 和新一拍 Jump，优先检查同帧两段移动和实际落地，避免把普通悬停下键交成下砸。日耀从自然生成的盾取得资格，空冲结束仍可保留盾，第一次实际命中才消费；用原生冷却、位移和真实接触验证各阶段。

准入要验证执行端真的能兑现的输入顺序。原版先处理水平按键和减速，再处理活动冲刺的衰减、回到普通跑速的衔接及后续碰撞。按反方向时身体可能仍向前，在真正反转之前要记前向扫掠。地形图确认的长跑道作为普通行走段交付，临时选中的冲刺须取得实际方向及停距的证明，尤其不能把向主人准备的冲刺套给背向主人去找出口的路段。共享预算耗尽时保留预测步和地形列，正常跟随与准备可以同时推进。已允许继续的冲刺遇到地形变化须在活动中重验；一旦选择刹车，本次不因下一步所需空间变短而重新加速。留档同时观察启动、减速、冷却复用和普通移动恢复。代表来源通过原生探针与用户原世界、联机、实际帧率分别记录。

## 跟随下降与原版悬停（2026-11-22）

临时拒绝只在相同已观察的姿态、速度、资源和相关读格下适用。已结束的搜索仍可能交出可尝试前缀；若入口接不上或原版动作偏离，结果需要回到同一恢复职责。确认实际交付、原版接受和预期接触各发生在不同阶段。接入游标引用带代次的候选，预算和容量压力由同一份共享额度推进。即使前沿没有可回收的闭合叶，执行一个已证出口前缀或处理可替换叶也能给下一段留下空间。

定向 Hoik 需要从模块外用普通身体和原版输入验证。侧碰和斜坡修正可以先把横速清到很低，又在齿位释放出明显的原版位移。慢速阶段按实际接触和进度识别，不统一用大位移或单位时间的距离判断。连接证明记录身体形状、加载后的实际齿序和同一支撑出口。真正到达后才可以沿当前目标继续，连续验收要把门、绳索、平台和 Hoik 之间的换接一起走过。

组合导航迁移后，旧 `DropSafe` 的下平台检查仍然通过，而正式 Follow 用的是另一处 80 像素落点探查。相隔 96 像素的上下层因此能出现在几何测试里，实际队友却不给 Down。旧离岸候选只向前探 4 像素，探完仍有支撑就停止，普通路线又要求离边前能刹停。下降候选现在包括接近与真正离开支撑，在同一个规划候选中按预算逐段检查足迹及落点。下穿的当前 Down 输入、原版 `stairFall` 和新的身体支撑各自来自对应原版阶段。正式复现用加入后的能力观察和真实 `Player.Update`，直接查询几何的旧用例只说明兼容入口的职责。

## 队友移动轮转与网络消费基线（2026-11-16）

原版 SlopeCollision 不替调用方推进 delta：支撑与轨迹须按 TileCollision→局部位置推进→SlopeCollision 保留校正位置和速度，斜平台接触不能只看旧位置的垂直返回。查询会修改八项 Collision scratch，未知 Tile 还可能被原版物化；有限已加载非 null 足迹与 finally 归还缺一不可。stairFall 是跨帧下穿事实，不能因本帧 controlDown 清零便重新把平台当支撑。起跳成功须在请求方向取得位移，绝对位移会误认反向初速的背后落点。此处解释已证机制，不把它称为历史所有卡位的唯一根因。

队友起跳还有输入准入。JumpMovement 先于该帧地面碰撞；一像素支撑可以与仍向下的原生速度同时存在。路线从预计向上的初速出发，只能回答离地后能否通过。首次激活或上次请求未起跳时，`releaseJump` 必须由真实 Player.Update 消费一次 `controlJump=false` 恢复。在同一次更新之前清后重写不会产生释放帧。用保持障碍或高差不变、原生 releaseJump 初始为 false 的场景，通过实际垂直位移和再次落地验证闭环。此源码因果不能识别所有者现场的具体地图或原始触发动作。

1px 几何修正不能绕开全队预算：静止失败的 48 步找地／160 步下穿须绑定实例、起点初速、能力、世界及实际读格依赖缓存，关键格变化才重建；未获规划资格延后该查询，Unknown 不缓存成稳定失败。Debug 隔离 leaf 的实际 Move／build 计数证明相关工作量，不代表 FPS。原始中间数据可按[正式设计的 AI 专项资料规则](../设计/AI队友正式实现设计.md)选择保留。

AI 更新临借 Main.myPlayer 后，Main.LocalPlayer 不能作为真人 session／旅途身份；真实入口是 Main.ActivePlayerFileData.Player，世界及连接也须同源。队伍发布要区分状态变更、字节实际入队与服务端消费：SendData 返回不等于发送或 ACK，过期 actor／连接意图不能投给重用槽。编码捕帧只证明局部路由，实际 TCP 加原生 server／observer 消费才证明其有限接收链；私人垃圾槽按原版 CanRelay 策略，不为观察端自造广播。

## 基础参数、动作前提与冻结用途（2026-10-06）

当前唯一根因/原版分支/消费者/范围/修法/正反例表查[现行设计](../设计/战斗辅助实现设计.md#foundation-motion-design)，完整有限链返修查历程146起，旧基础规则交付查140—145；实际交付与未体验状态查[阶段入口](../计划/辅助瞄准阶段文档.md#1-恢复工作先读)。本节只保留可复用判断，不建立第二张根因表。

共同水平控制不能代支撑、StepUp、障碍和有限近扑的完整动作链；限定共同块入口时，独立前置速度应由原版分支或其不变点证明，不能用动作后最终值回填期待。当前湿态、湿中维持资格与本步接触是不同状态：灭火消费维持lavaWet，微光续buff消费当前接触；几何正确不证明上游纵向参数、液体资格与下一步基础正确。自有效果与共享jump scratch分开，旧湿态逐步携带，派生泳蹼退出后不能冒充独立装备资格。

日志必须变成可失败的门：全场从首个合法需求更新计选中/新鲜发布和最长空白，冻结窗另从动作前开始；预定身份切换在窗口前固定，不能每帧用实测变后的身份重签。正动作窗还须真的出现起跳/跨台阶，错实例代际、同身份旧tick、漏动作/反向和大部分空白均走实际Evaluate出口，合理近似仍能通过。局部原版、真实Source和完整动作前窗口互补，不拿远期Trend额度豁免确定共同规则。

首个冻结完整不证明后续当前发布仍有需要的跨度；只对预声明稳定且无停止边界的窗口，每步同时核真实Count/Stop，缩为2点的后续发布必须在同一Evaluate失败。快照/玩家proof不重复进世界更新分母。工程失败的输出误差0也不代表退出门通过；原EOF失败缺stderr尾应保留未归因，成功重试保真实执行ID，不能把历史复用或首轮成功siblings重签为第二轮新执行。受限local适配、正式原入口、实际ZIP、文件安装和本人体验分别记事实。

## 共享几何与目标标记的复用经验（2026-10-06）

## 战斗观察的隔离与验证陷阱

预设“随机分支前命中”的检查必须按真实计时消费者推导界限。纸飞机初始 ai0 为 -Next(30,80)，含出生当次自增，最早第 50 动作才进入 loop；不能凭“近距离”给一个 25 动作门槛。先输出实际出生／首次正 Strike／预测时间，并用 token、slot、key 绑定首体，区分计时断言错误与真实错路。已有正伤害与逐帧预览仍保原分母，不把末断言失败抹去，也不把后发弹命中算作第一体成功。

同一弹体的伤害框与反射框可能不同：AI29 的扩大框先碰到目标，不代表其原始框已进入反射区域。测试应分别见证原始框重叠、扩大框重叠、真实反射状态与正伤害，不能凭目标挂了反射标志就预设负控。x86 临时表达式可能保留扩展精度；验证实际已存 Single 字段时比较双方存储值，不因两段相同显示文本而随意加容差。主动改变玩家 dead／ghost 的占位负控必须在 finally 归还本次修改，否则下一普通动作的严格资格门会被夹具自身挡住。

路径的完整捕获、条件前推、接受/重用是三种责任。完整复制Mount不能证明骑乘运动已闭合；真实扫帚Hover的微量速度含位置补偿，蜜蜂疲劳改变下一步水平速度，不能固定velocity过关。名字渐变nameOver与调试仇恨线targetSetFrame只参与呈现，精确纳入接受会让真实Draw或外围时钟持续拒收；但会消费AI随机的金色小动物光照不能同样删除。Conditional玩家派生targetRect只能在来源可证时放宽坐标，真实击退/传送仍需自然事件使旧前提失效。

水中本帧位移不等于帧末velocity：液体倍率、裁剪、坡/台阶/传送带和noTileCollide发生于不同阶段。断点按原版已发生的移动阶段核对，显式Teleport及阶段外重定位另保留。测试须冻结一次后完整120步，并另走实际Session与原版Draw；同时记录选择身份、稳定期撤销、输入边沿恢复和真实湿态/接触，不能用shown>0或Mount.Active宣称持续可用。独立NPC冻结夹具的固定玩家也须处于原版640px世界边界内和所声明干地，否则worker的真实BordersMovement会改变追击前提。

性能证据须区分主线程、worker及等待。逐块缺页会串起多轮异步等待；同Prepare已核对的Chunk可复用采集字节，私有Tile可复用存储但必须还原全部字段。不能跨帧复用比较证明或把上次未声明页当已知。有限测量队列满后Count不再增长，离线探针应逐次排出而非用Count差判回包；失败回包旧TotalMs=0表示未带计时，不是失败免费。

当前形状的验证域必须来自原版分派和独立世界范围，同时统计漏画与多画。仅遍历已画线段会让空结果自证；仅用点目标也测不到大受击框的扇形、收缩和距离条件。464的两次旋转不能合成一次角度相加后再取整；火山剑的端点/四角距离也不等价于普通连续胶囊相交。真实曲线虚线须跨分段连续计数，屏外射线按形状裁切，离散点不可连成线。

天然事件要区分生产者阶段与后续普通回调：949在AI内SelfHurt有效，但同帧移动后普通Damage仍会返回矩形，后者不能创建/挪动伤害；502第五次反弹在最终位移前已失活；535的536子体临时伤害与四条装饰线不可合并；闪电Kill会清customHitbox，必须在其自然窗口复制点集。远端未同步的临时字段不能据外观补造确定事实。

完整未来要在推进原版前冻结，关联链要在所有槽位更新后取对照状态：后槽位DOT可回写先槽位的生命，EOW又会在AI阶段解除共享realLife。AI6父Center含浮点半尺寸，AI37父中心使用整数半尺寸。位置近似相同不保证缓存能滚动；目标、朝向、液体、DOT计数和无位移的随机攻击计时要分别核对。生产状态比较保持严格，有限浮点差异重建应记录真实工作量；静止新采样身份可以共享已冻结点数组，不能共享可变工作缓冲。

第一批 #112 的正式语义见[战斗设计](../设计/战斗辅助实现设计.md#第一批观察与共享预测)，最新状态见[阶段入口](../计划/辅助瞄准阶段文档.md)。`Damage_GetHitbox`并非纯getter；须限定原版自然Damage范围。最后extraUpdate可能不再伤害，Kill及644哨兵AI瞬时爆发又不能被普通槽清理抹掉；队友近战/哨兵的owner-only分支需要基于真实本地阶段的独立观察，不能额外执行AI或Damage。本人PvP无队伍时`InOpposingTeam(self)`也可能为真，本人与队友关系必须分开。

原版AI5为量化目标、周期和每轴加速，AI14有同一次更新两遍轴向驱动，不能一律归一化Seek。普通碰撞先用全速度裁剪，再按是否碰撞分别水中减速；窄湿身传感器、出水减半、斜坡/平台与gravity的高度因素会影响下一步。模型只复制标量和局部tile值，不在活对象跑AI后回滚。

隔离`UpdateNPC`夹具仍要显式建立真实前提：solid表、足够低的地面、对应buff清理、照明引擎和target。只看到120步位置一致不能证明“已落地”，要断言确实发生原版接触；复用NPC.SetDefaults也不能假定清掉前场景所有buff。图形同理，MagicPixel资产并非1×1，绘轮廓要明确1像素source；实际截图会揭示只测stroke数量看不到的放大色块。

## G11A 原版阶段与观察边界

共享投射物 Finalizer 不能对所有模块广播收尾：战斗回执的默认工具 token=0 与工具空闲 token=0 相等，会让异常路径访问空 Intent，截断真正战斗 owner 的清理。固定 Harmony 在本次隔离复现中仍向调用方保留最初异常，因此仅断言异常类型会假绿；须在下一次 UpdateRuntime/FinishFrame 前核作用域、输入与使用权。`NativeCombatProjectileChecks` 经真实 Projectile.AI/ToolHooks 观察到工具二次空引用和战斗残留，修复用当次已取得回执分派并拒绝无效工具 token。借出输入前还须发布清理责任，正常 Postfix 与异常 Finalizer 消费一次；不能为了战斗退役而提前清掉工具等待合法归还的状态。技术实现与回归路由见[实现设计](../设计/战斗辅助实现设计.md)，不外推为实机验收。

原版 AutoReuseLogic 必须完整执行，补写 releaseUseItem 也有自身所有权：异常在原版消费之前发生时要撤回自己的补写，正常原版 channel/release 结果不可整批回滚。模拟步决定与 ItemCheck/Projectile 多阶段消费分离；空外层更新不能推进周期。鼠标槽 58 由原版来回克隆，只能在当次合法游戏使用中核身份，不能把拖物 UI 也放行。

光剑的“0 间隔仍稀疏”要区分投出频率和有效飞行：固定 .8 再次按下使用就召回旧剑，仅切槽不召回；回程仍伤害且有转向惯性。动画尾部才释放会把原版冷却放在投出之前，剩下约 3 tick 就进入返回，早松才让飞行覆盖剩余冷却。不能用前飞帧数乘速度估算有效距离，也不能把射数或隔离靶总扣血当成实机 DPS。常驻 NativeCombatReleaseChecks 观察真实起手、投出、轨迹及冷却；原故障在间隔 0 下最远约 52px，100px 飞行断言失败。常规/传奇、0/12/30、原版装备达到动画 3 及松手退役分别验证；通用 CPU 夹具含 24×24 持握绘制盒，不代表完整近战实机。

## G10 原版执行与归还边界

G10 设置开启、鱼漂观察需求、在途/装备归还责任须分开（[#109](https://github.com/Kuroneko2020/JueMingR/issues/109)）。原“全关”早退不能证明“开启未抛”成本；同一步缓存也不能消除每个新模拟步的无用全表扫描。现有原版创建回调可唤醒空观察，已有身份负责保持观察；显示和显式查询独立于 Auto。固定 .8 的 Started 可先于 Shoot，原版 itemTime 会推迟创建，甚至动画结束仍未创建；等待应按真实使用结束/漂身份退休，不能凭短超时丢合法干飞。槽复用需同时核实际槽对象和完整 key，不能只看旧对象 active。借网暂停观察不等于清除 G10 会话，装备归还也不要求扫描鱼漂。

焦点是物理输入资格，不是所有自动业务的执行资格。后台钓鱼需同时贯通 Session.Ready、ToolUse.ActionValid/Pick/Update 与 F5.CanPresent，单改第一层仍会在实际出口取消。G10 最新所有者决定取消纯自动业务默认失焦暂停：使用共享自动准入并贯通存鱼、Items 实际出口、工具及服务，保留真实更新阶段、所有权和回焦隔离。手动保护释放继续走严格前台输入，不能随自动门一起放宽。隔离实际 Player.Update 的用例同时覆盖 mouseInterface 为 false 和 Draw 遗留 true，不因该标志而向全局写 false。

F5 自动增益的同类根因是前台调用普通 CanTargetInput，旧门明确拒绝 State.Visible。G10 最新决定以共享准入取消所有业务的默认 F5 暂停，只给自动钓鱼收竿/重抛/切杆设置独立门；不能继续复制增益单项例外。自动业务识别壳层真实自有鼠标租约，实际文字/指针和物品所有权仍有效。完整消费回归同时测前台 F5 悬停、后台、其它恢复/服务及工具实际结果，并验证自动钓鱼仍暂停。UI 结果隐藏应由呈现层保存期限和已观察来源，不能每帧按业务保留错误重新开始计时，也不能为了隐藏清空诊断事实。

固定 .8 的拉竿许可、实际 ItemCheck 消费、旧鱼漂退休、Give/GetItem 产物和新漂生成是五个不同边界。只读候选不能授权真实咬钩；实际任务鱼例外还取决于今日当前任务及是否完成。每 30 个模拟更新重读水域并核规则形状/版本，稳定条件可以复用谓词结果，却不能把该周期检查说成零目录读取。同语言资源重载也会改变鱼名与关键词结果，不能只比较 GameCulture 引用。

切杆还要跨越第六个边界：原版 Select 原竿仅缓冲，允许切换不等于已切回。原版 Player.Update 前可能有未采样外层 Update；此时提前退役 ToolUse 会把自动临时槽误判为手动换离，并导致装备归还。回归需含非空临时槽、背包 10—49、非零原竿槽、0/1/3 次空外层更新及切杆期间同一装备借用。不要把自动循环误停直接等同于原版永远不兑现缓冲。

全页闪灰可以来自持久化准入而非绘制丢帧：一次设置 Busy 如果作为所有 Part.Enabled 的输入，会把其它按钮一起灰显。保留可靠写入串行门与旧 Value，独立表达视觉可用性；也要测只开窗口/多选这种不保存的点击。新增窗外关闭不能绕过布局代次检查，否则缩放帧会用旧窗矩形丢弃草稿。

F5 自身可见门和原版 mouseInterface 是两道门，后者须识别壳层真实租约，不能写 false 冒充空闲。菜单还会消费映射鼠标触发，允许 F5 装备动作后必须再核物理左右键释放；文字、IME、箱子和其它原版界面仍阻断。没有实际借用的最优组准备态不应产生“已归还”或“未自动切回”提示。

松露虫的 localAI[1]=1/localAI[2]=2673 是召唤标记，不是物品 1。Legacy 的“开始鲨猪／鲨猪啦！”是会话沿文字，后者不是 Boss 成功回执；原版生成与消耗须另走实际收竿消费者验证。R 使用公共头顶短提示呈现，结束会话与自动重抛不能混为一谈。

全部溢出不等于没有钓获：原版已产出物品时，本次边界可捕获符合保护的同类型旧库存；没有旧物就结束，不把后来拾取追认成该次钓获。普通与专用来源共用一次优先序与同一个存放 owner。原版客户端 85 只是请求/阻塞列表，消息 5 分槽真实应用后才结算；关闭功能、F5、超时和重复消息不等于撤销在途事实。

临时配装必须保留真实引用，A→B→C 连续升级按目标最新记录判手动接管，逆序还整条链。来源槽和目标槽的共享意图各有代次；显式较晚收藏/共享优先。正常可堆叠渔具不能整堆进 armor（原版保存省略 stack），应原版拆一件、同源空位落地再交换；自动保存共用的 IOLock 只作非阻塞有限保护。普通水中的旧熔岩钩仍属于先替换的旧钓鱼饰品。

原版 Rename/SavePlayer 可能静默跳过或忽略云 Write false；无异常与 name 已变都不足以说明保存成功。生产只验证实际写出口及完整字节读回，不 LoadPlayer；后者影响全局旅行能力，只能在隔离测试中使用。改名粘贴需在通用单行编辑器之前去 CR/LF、Tab 转一个空格；20 UTF-16 字符的最终限制仍由完整名字命令承担。

正式边界见[行为合同](../功能介绍/钓鱼与配装行为合同.md)与[实现设计](../设计/钓鱼与配装实现设计.md)。原版 CPU/字体纹理/客户端包序列化是不同证据；没有真实服务器、系统 IME、云账户或 FPS 结果就不外推。

## 持续使用、重复使用与松开发射

`autoReuseAllWeapons`、物品 autoReuse、channel 与 `ShootsOnUseRelease` 是不同资格；damage≤0 等情形也不能从“所有武器”名称猜覆盖。原版释放发射武器依赖连贯按住与松开边缘，普通连点插入 release 会破坏它。光剑快切固定 18 个 Phaseblade/Phasesaber 资格比释放发射集合窄，Keybrand 等同集合物品不因此入选。

## 鱼漂身份、过滤条件与版本签名

1.4.5.7 `ProjectileKey` 打包 spawner/index/generation，合法值可能为负；只有 -1 是该合同的 sentinel，不能用 `<0` 全拒或只取 projectile index。观察、显示 fallback 与缓存必须使用相同的完整身份方法，避免复用槽位误认上一鱼漂。
