# 战斗移动与钓鱼机制

Legacy 历史机制整理，主要针对 Terraria 1.4.5.6/.7；R 的后续实现单独标明，其余不表示已迁移或重验。来源相对旧经验根，功能行为见[战斗](../功能介绍/Legacy战斗.md)、[移动增益](../功能介绍/Legacy移动与增益.md)、[钓鱼](../功能介绍/Legacy钓鱼.md)。

## 装备提醒：危险 key 不等于装备状态

固定 Legacy `6ac6356` 每12 tick读取首个Boss/指定事件，仅在危险key变化时扫描裸 `armor[0..9]` 与 `miscEquips[0..4]`。先保存key再查装备会使首次无命中后战斗中换装永久漏检；Reset只清key/扫描期限，未撤销旧text/expiry。真实消费者是独立Game层固定文字，2秒加0.25秒淡出，不是每秒创建CombatText；每次显示另有正常文件日志。完整固定名称、事件优先级、血月并存与失效反例见[三项合同第6节](../功能介绍/稀有生物旅商方向与装备提示行为合同.md#6-装备提示完整固定规则与通知语义)，不能仅据旧注册“1秒”或功能说明宣称实现正确。

调查另查当前锁定原版 .8：有效装备可能来自其它装备组收藏项共享，且受解锁、难度、部位/饰品与冲突条件约束；数组有值不等于生效。该次V0静态知识不构成运行验证。

R #77 的 `EffectiveEquipmentReader` 只读实际 `GetEffectiveArmor`、槽位资格与角色条件，176个ID由当前ItemID/资源独立验证，音乐盒不再匹配本地化名前缀。`EquipmentWarning` 比较Boss类型/具体入侵类型与问题物品类型集合；持续危险仍读取必要有效槽，稳定集合不重发。扩充Boss暂存容量必须保留旧集合，否则相同风险也会被误判为变化。3秒+0.25秒使用独立Stopwatch时钟并及时撤下；源码、自动检查与实测分别见[实现设计](../设计/方向指引装备提示与游商测试实现设计.md)及[#77](https://github.com/Kuroneko2020/JueMingR/issues/77)，不宣称已实机接受或提高FPS。

## 持续使用、重复使用与松开发射

`autoReuseAllWeapons`、物品 autoReuse、channel 与 `ShootsOnUseRelease` 是不同资格；damage≤0 等情形也不能从“所有武器”名称猜覆盖。原版释放发射武器依赖连贯按住与松开边缘，普通连点插入 release 会破坏它。光剑快切固定 18 个 Phaseblade/Phasesaber 资格比释放发射集合窄，Keybrand 等同集合物品不因此入选。

原版 projectile AI 可能在 ItemCheck 之外仍需 held 状态。历史快切经历 press、保持、release、原版消费、真实选槽确认后再等间隔；设置 0 tick 只取消额外等待，不绕过原版动画/物品周期。`changeItem` 或选槽请求不是 selectedItem 立即改变的证明。

来源：`Terraria原版参考笔记/Combat_ItemUse_notes.md`、`Fishing_notes.md`，结合旧功能介绍 `战斗页/光剑快切.md` 的后续修订。查证应覆盖原版 ItemCheck 与 projectile AI 两端，不只用输入 helper 断言。

## 右键链球与自瞄的 release 证据

旧链球连击从物理右键制造虚拟左键 release，不能直接复用依赖物理左键 release 的瞄准缓存。`targetUnavailable:noCachedReleaseAim` 指向当前释放缺少可用缓存，不必然是 selector 找不到怪。目标的 press/release 所有权、有效时间和消费者要一一对应；不能在 release 临时重新找一个目标来伪装已有连续决定。

弹药还可改变 projectile、速度、魔法箭袋/箭术和 extraUpdates，不能只按武器 shoot 字段预测。哥布林工匠 107 与被绑的哥布林 105 不同，特殊可命中功能不应扩张到全部友方 NPC。来源：`排查复盘/链球连击右键虚拟release自瞄失败-2606052309.md`、`Terraria原版参考笔记/Projectile_Aiming_notes.md`、`Combat_ItemUse_notes.md`。

## 鱼漂身份、过滤条件与版本签名

1.4.5.7 `ProjectileKey` 打包 spawner/index/generation，合法值可能为负；只有 -1 是该合同的 sentinel，不能用 `<0` 全拒或只取 projectile index。观察、显示 fallback 与缓存必须使用相同的完整身份方法，避免复用槽位误认上一鱼漂。

过滤要有实际声呐 Buff；没有识别或条件未知保留鱼获，不能擅自跳过。切杆/换装/重抛需等真实槽位与原鱼漂结束，不能拿请求已入队或最近一条被覆盖的结果代替本次动作回执。

版本签名例子：PickTile 在 .6 是三参、.7 是四参；TileDrawing.IsTileDangerous 从 `(Player, Tile, ushort)` 变成含 x/y 的五参，必须传真实世界坐标。来源：`Terraria原版参考笔记/Fishing_notes.md`、`Tile_Visibility_notes.md`、`WorldGen_Blueprint_notes.md`。两套本地树只帮助定位差异；R .8 的 Hook 仍需独立确认。

## R 1.4.5.8：恢复和增益的真实出口

`DebugOptions.ManaV2` 默认开启，`CheckManaPredictWithoutUse` 在缺蓝时仍可返回 true，以允许慢速施法；不能据此断定资源够用。G07 使用无副作用的费用细节与原版截整表达式观察下一次费用，实际补给仍调用 QuickMana，持续 channel 和输入不清零。QuickBuff 的资格方法包含实际使用副作用，按真实提供者过滤必须发生在资格方法前。

手动学习要捕获消费前类型，并在真实效果成功后确认；最后一件已变为空物品，不能事后只读 held type。取消增益限定原版图标路径，自然 DelBuff 不代表人工操作。完整家具使用 TileObjectData 帧与原版范围，自动使用 scope 只抑制制作窗口入口；不能先打开再关闭掩盖闪窗。

G07 隔离原版检查与正式策略见[实现设计](../设计/自动恢复增益与邻近服务实现设计.md)和[行为合同](../功能介绍/自动恢复增益与邻近服务行为合同.md)。这些证据不代表真实游戏、多人与 FPS 验收。

## 防摔根因要先区分原版能力与插件写入

`FallDamage_notes.md` 记录了用户原版对照：飞行后卸下翅膀仍不摔伤，不能仅因现象发生在插件启用时就认定智能防摔/自动回血写了状态。wingsLogic 残留飞行能力与“当前装备仍有翅膀”不是同一个观察；依赖哪个值需看真实调用时序。`Mount_Movement_notes.md` 当时没有已确认机制，本轮不补造坐骑规则。

自动挖矿重力矿列下移丢标记是另一类已记录失败：观察原坐标失效后要在有界邻近范围识别新落点，不能把整列旧坐标当成功，也不授权直接写 Tile 或无限追踪。来源：`排查复盘/自动挖矿重力列下移丢标记-2606090022.md`。这些历史原因只是后续定向查证线索，不形成性能改进或迁移授权。
