# 战斗移动与钓鱼机制

## 基础参数、动作前提与冻结用途（2026-10-06）

当前唯一根因/原版分支/消费者/范围/修法/正反例表查[现行设计](../设计/战斗辅助实现设计.md#foundation-motion-design)，完整有限链返修查历程146起，旧基础规则交付查140—145；实际交付与未体验状态查[阶段入口](../计划/辅助瞄准阶段文档.md#1-恢复工作先读)。本节只保留可复用判断，不建立第二张根因表。

共同水平控制不能代支撑、StepUp、障碍和有限近扑的完整动作链；限定共同块入口时，独立前置速度应由原版分支或其不变点证明，不能用动作后最终值回填期待。当前湿态、湿中维持资格与本步接触是不同状态：灭火消费维持lavaWet，微光续buff消费当前接触；几何正确不证明上游纵向参数、液体资格与下一步基础正确。自有效果与共享jump scratch分开，旧湿态逐步携带，派生泳蹼退出后不能冒充独立装备资格。

日志必须变成可失败的门：全场从首个合法需求更新计选中/新鲜发布和最长空白，冻结窗另从动作前开始；预定身份切换在窗口前固定，不能每帧用实测变后的身份重签。正动作窗还须真的出现起跳/跨台阶，错实例代际、同身份旧tick、漏动作/反向和大部分空白均走实际Evaluate出口，合理近似仍能通过。局部原版、真实Source和完整动作前窗口互补，不拿远期Trend额度豁免确定共同规则。

首个冻结完整不证明后续当前发布仍有需要的跨度；只对预声明稳定且无停止边界的窗口，每步同时核真实Count/Stop，缩为2点的后续发布必须在同一Evaluate失败。快照/玩家proof不重复进世界更新分母。工程失败的输出误差0也不代表退出门通过；原EOF失败缺stderr尾应保留未归因，成功重试保真实执行ID，不能把历史复用或首轮成功siblings重签为第二轮新执行。受限local适配、正式原入口、实际ZIP、文件安装和本人体验分别记事实。

原版一个能力属性不等于正在执行动作：ShouldFloatInWater还要经过实际水线、wet/位移、Down/坐骑和微光分支；干地装备不能抢走普通/快跑模型。观察查询与未来Terrain.Reset/预算分别拥有，不能采样时补写真实Tile，不能把未知必要目标几何吞成自由趋势。合法玩家替代只改变玩家前提，仍核身份/数值与真实挂接成员；离开机制应自动恢复普通路径。

Source提前择人必须消费与首次真实AI同一相位：Health/DOT投影可改变aggressive和首次起跳重选，公共gravity裁剪可改变AI入口，AI内Transform则不能重算本步已选重力。用同一纯值控制判断分责，既不拿旧dead无关编号挡线，也不无条件换本地玩家掩盖真正先读旧目标的分支。有限独立动作趋势未消费玩家时无需额外玩家门；质量标签不能暗示完整原版独立行动。

局部规则A、默认真实Source完整接缝B、动作前冻结与后续实际位置C分别保全。手填正确参数或事后刷新不代Source，selected/published零不能称用途通过；先修夹具入口再验证真实分母。冻结误差按轴和最早相位定位：旧258公共Y正确但X未建有限动作，先验近期门真实失败后才获批准补59001—59034；该96更新新窗零误差不扩成全AI/全部场景精确，也不删除旧RED与远期误差。工程复用保原执行ID与原字节，包再读实际ZIP，文件安装与本人体验继续分列。

## 共享几何与目标标记的复用经验（2026-10-06）

当前机制、职责表与未支持边界查[设计](../设计/战斗辅助实现设计.md#shared-mechanism-marker-design)，授权及交付身份查[阶段入口](../计划/辅助瞄准阶段文档.md#shared-mechanism-marker-20261005)，实际因果与失败原件查历程129—139。

修共同碰撞语义要先列实际查询区域与顺序。body、movement、受击框不能互相代用；独立原版公式/方法作oracle，候选与基线同地形仅证明该采样几何，不能证明采样范围本身正确。Tile→Slope→Conveyor每次都可能重写共享up/down；早期已清Jump与最后Vy责任分开。高速dry每段已有Slope/belt不代表外层末尾可省。原判别RED保留，夹具缺数组、错选主体、纯底色图、被钳UI倍率不作产品修前失败。

追踪对象不等于R选中对象，guardian朝向也不等于Flying速度目标。按原版具体阶段重选并看下一真实消费者，不用aiStyle宽名单全局封锁/放行。多个编号玩家需要哪个时间线必须提前明确；重选B后重复B当前矩形不能标HeldPlayerControls，旧A的无关未来不能挡B。必要效果、观察退路许可与模型质量不是一个bool。整段退路从0最多重算一次，不能拼接半段假设。

直接赋位与健康共享是两种关系：114主体X不代表Y硬贴，397Clamp也不等于贴owner，401缺弹体未来不能伪造。父phase到阈值的本帧仍可能执行home；剩余窗严格按未来动作，恰终点切相位不能预支下一帧玩家几何。看原版if/else归属及动作前状态，而不是仅看动作后phase。测试同列TimeLeft、方向、时钟、完整身份与位置，不只速度数值。

显示独立需求不应启动后台/伪造Cache。标记-only、path-only、dual、both-off用实际选择/Source/Cache/World层核，资源失败既要证明健康路径仍画，也要区分真正共享batch/device故障。GPU图片必须有内容断言；UIScale先缓存真实屏幕再设置，并检查实际矩阵，不只保存文件名。配置旧缺项、复制路径、未知/重复/坏类型原字节保护属于同次交付。

测量保留完整合法分母、原首帧、坏样本、GC与观察成本；30预热/120尾样本的暖态CPU与连续480帧是不同证据。二进制目录会漂移，历史MVID存在不证明匹配最终生产commit；哈希不符撤回同源标签，保留原件，不倒填证据或从不同路线点数推导提速。

## 战斗观察的隔离与验证陷阱

路径的完整捕获、条件前推、接受/重用是三种责任。完整复制Mount不能证明骑乘运动已闭合；真实扫帚Hover的微量速度含位置补偿，蜜蜂疲劳改变下一步水平速度，不能固定velocity过关。名字渐变nameOver与调试仇恨线targetSetFrame只参与呈现，精确纳入接受会让真实Draw或外围时钟持续拒收；但会消费AI随机的金色小动物光照不能同样删除。Conditional玩家派生targetRect只能在来源可证时放宽坐标，真实击退/传送仍需自然事件使旧前提失效。

水中本帧位移不等于帧末velocity：液体倍率、裁剪、坡/台阶/传送带和noTileCollide发生于不同阶段。断点按原版已发生的移动阶段核对，显式Teleport及阶段外重定位另保留。测试须冻结一次后完整120步，并另走实际Session与原版Draw；同时记录选择身份、稳定期撤销、输入边沿恢复和真实湿态/接触，不能用shown>0或Mount.Active宣称持续可用。独立NPC冻结夹具的固定玩家也须处于原版640px世界边界内和所声明干地，否则worker的真实BordersMovement会改变追击前提。

性能证据须区分主线程、worker及等待。逐块缺页会串起多轮异步等待；同Prepare已核对的Chunk可复用采集字节，私有Tile可复用存储但必须还原全部字段。不能跨帧复用比较证明或把上次未声明页当已知。有限测量队列满后Count不再增长，离线探针应逐次排出而非用Count差判回包；失败回包旧TotalMs=0表示未带计时，不是失败免费。

当前形状的验证域必须来自原版分派和独立世界范围，同时统计漏画与多画。仅遍历已画线段会让空结果自证；仅用点目标也测不到大受击框的扇形、收缩和距离条件。464的两次旋转不能合成一次角度相加后再取整；火山剑的端点/四角距离也不等价于普通连续胶囊相交。真实曲线虚线须跨分段连续计数，屏外射线按形状裁切，离散点不可连成线。

天然事件要区分生产者阶段与后续普通回调：949在AI内SelfHurt有效，但同帧移动后普通Damage仍会返回矩形，后者不能创建/挪动伤害；502第五次反弹在最终位移前已失活；535的536子体临时伤害与四条装饰线不可合并；闪电Kill会清customHitbox，必须在其自然窗口复制点集。远端未同步的临时字段不能据外观补造确定事实。

完整未来要在推进原版前冻结，关联链要在所有槽位更新后取对照状态：后槽位DOT可回写先槽位的生命，EOW又会在AI阶段解除共享realLife。AI6父Center含浮点半尺寸，AI37父中心使用整数半尺寸。位置近似相同不保证缓存能滚动；目标、朝向、液体、DOT计数和无位移的随机攻击计时要分别核对。生产状态比较保持严格，有限浮点差异重建应记录真实工作量；静止新采样身份可以共享已冻结点数组，不能共享可变工作缓冲。

第一批 #112 的正式语义见[战斗设计](../设计/战斗辅助实现设计.md#第一批观察与共享预测)，最新状态见[阶段入口](../计划/辅助瞄准阶段文档.md)。`Damage_GetHitbox`并非纯getter；须限定原版自然Damage范围。最后extraUpdate可能不再伤害，Kill及644哨兵AI瞬时爆发又不能被普通槽清理抹掉；队友近战/哨兵的owner-only分支需要基于真实本地阶段的独立观察，不能额外执行AI或Damage。本人PvP无队伍时`InOpposingTeam(self)`也可能为真，本人与队友关系必须分开。

原版AI5为量化目标、周期和每轴加速，AI14有同一次更新两遍轴向驱动，不能一律归一化Seek。普通碰撞先用全速度裁剪，再按是否碰撞分别水中减速；窄湿身传感器、出水减半、斜坡/平台与gravity的高度因素会影响下一步。模型只复制标量和局部tile值，不在活对象跑AI后回滚。

隔离`UpdateNPC`夹具仍要显式建立真实前提：solid表、足够低的地面、对应buff清理、照明引擎和target。只看到120步位置一致不能证明“已落地”，要断言确实发生原版接触；复用NPC.SetDefaults也不能假定清掉前场景所有buff。图形同理，MagicPixel资产并非1×1，绘轮廓要明确1像素source；实际截图会揭示只测stroke数量看不到的放大色块。

## G11A 原版阶段与观察边界

共享投射物 Finalizer 不能对所有模块广播收尾：战斗回执的默认工具 token=0 与工具空闲 token=0 相等，会让异常路径访问空 Intent，截断真正战斗 owner 的清理。固定 Harmony 在本次隔离复现中仍向调用方保留最初异常，因此仅断言异常类型会假绿；须在下一次 UpdateRuntime/FinishFrame 前核作用域、输入与使用权。`NativeCombatProjectileChecks` 经真实 Projectile.AI/ToolHooks 观察到工具二次空引用和战斗残留，修复用当次已取得回执分派并拒绝无效工具 token。借出输入前还须发布清理责任，正常 Postfix 与异常 Finalizer 消费一次；不能为了战斗退役而提前清掉工具等待合法归还的状态。技术实现与回归路由见[实现设计](../设计/战斗辅助实现设计.md)，不外推为实机验收。

原版 AutoReuseLogic 必须完整执行，补写 releaseUseItem 也有自身所有权：异常在原版消费之前发生时要撤回自己的补写，正常原版 channel/release 结果不可整批回滚。模拟步决定与 ItemCheck/Projectile 多阶段消费分离；空外层更新不能推进周期。鼠标槽 58 由原版来回克隆，只能在当次合法游戏使用中核身份，不能把拖物 UI 也放行。

快切 Select 是缓冲申请，真实选中后才开始额外间隔。蓄力投射物也有不同瞄点读取阶段，燧石和冰川之牙不能硬套物品动画 2 的释放门。死亡撤动作资格，但 SessionPlayer 仍可观察 Boss 逃离；统计的本地近期列表与普通客户端的服务器事实不是同一数据源。内存 socket 原版收发闭环不等于真实多人验收。滑块的 Field 必须接实际悬停命中，Escape 取消还须保留键尾，不能只消费鼠标尾。具体原版路径、future provider 阶段及回归入口查[实现设计](../设计/战斗辅助实现设计.md)。

光剑的“0 间隔仍稀疏”要区分投出频率和有效飞行：固定 .8 再次按下使用就召回旧剑，仅切槽不召回；回程仍伤害且有转向惯性。动画尾部才释放会把原版冷却放在投出之前，剩下约 3 tick 就进入返回，早松才让飞行覆盖剩余冷却。不能用前飞帧数乘速度估算有效距离，也不能把射数或隔离靶总扣血当成实机 DPS。常驻 NativeCombatReleaseChecks 观察真实起手、投出、轨迹及冷却；原故障在间隔 0 下最远约 52px，100px 飞行断言失败。常规/传奇、0/12/30、原版装备达到动画 3 及松手退役分别验证；通用 CPU 夹具含 24×24 持握绘制盒，不代表完整近战实机。

## G10 原版执行与归还边界

G10 设置开启、鱼漂观察需求、在途/装备归还责任须分开（[#109](https://github.com/Kuroneko2020/JueMingR/issues/109)）。原“全关”早退不能证明“开启未抛”成本；同一步缓存也不能消除每个新模拟步的无用全表扫描。现有原版创建回调可唤醒空观察，已有身份负责保持观察；显示和显式查询独立于 Auto。固定 .8 的 Started 可先于 Shoot，原版 itemTime 会推迟创建，甚至动画结束仍未创建；等待应按真实使用结束/漂身份退休，不能凭短超时丢合法干飞。槽复用需同时核实际槽对象和完整 key，不能只看旧对象 active。借网暂停观察不等于清除 G10 会话，装备归还也不要求扫描鱼漂。

焦点是物理输入资格，不是所有自动业务的执行资格。后台钓鱼需同时贯通 Session.Ready、ToolUse.ActionValid/Pick/Update 与 F5.CanPresent，单改第一层仍会在实际出口取消。G10 最新所有者决定取消纯自动业务默认失焦暂停：使用共享自动准入并贯通存鱼、Items 实际出口、工具及服务，保留真实更新阶段、所有权和回焦隔离。手动保护释放继续走严格前台输入，不能随自动门一起放宽。隔离实际 Player.Update 的用例同时覆盖 mouseInterface 为 false 和 Draw 遗留 true，不因该标志而向全局写 false。

F5 自动增益的同类根因是前台调用普通 CanTargetInput，旧门明确拒绝 State.Visible。G10 最新决定以共享准入取消所有业务的默认 F5 暂停，只给自动钓鱼收竿/重抛/切杆设置独立门；不能继续复制增益单项例外。自动业务识别壳层真实自有鼠标租约，实际文字/指针和物品所有权仍有效。完整消费回归同时测前台 F5 悬停、后台、其它恢复/服务及工具实际结果，并验证自动钓鱼仍暂停。UI 结果隐藏应由呈现层保存期限和已观察来源，不能每帧按业务保留错误重新开始计时，也不能为了隐藏清空诊断事实。

固定 .8 的拉竿许可、实际 ItemCheck 消费、旧鱼漂退休、Give/GetItem 产物和新漂生成是五个不同边界。只读候选不能授权真实咬钩；实际任务鱼例外还取决于今日当前任务及是否完成。每 30 个模拟更新重读水域并核规则形状/版本，稳定条件可以复用谓词结果，却不能把该周期检查说成零目录读取。同语言资源重载也会改变鱼名与关键词结果，不能只比较 GameCulture 引用。

切杆还要跨越第六个边界：原版 Select 原竿仅缓冲，允许切换不等于已切回。原版 Player.Update 前可能有未采样外层 Update；此时提前退役 ToolUse 会把自动临时槽误判为手动换离，并导致装备归还。回归需含非空临时槽、背包 10—49、非零原竿槽、0/1/3 次空外层更新及切杆期间同一装备借用。不要把自动循环误停直接等同于原版永远不兑现缓冲。

全页闪灰可以来自持久化准入而非绘制丢帧：一次设置 Busy 如果作为所有 Part.Enabled 的输入，会把其它按钮一起灰显。保留可靠写入串行门与旧 Value，独立表达视觉可用性；也要测只开窗口/多选这种不保存的点击。新增窗外关闭不能绕过布局代次检查，否则缩放帧会用旧窗矩形丢弃草稿。

F5 自身可见门和原版 mouseInterface 是两道门，后者须识别壳层真实租约，不能写 false 冒充空闲。菜单还会消费映射鼠标触发，允许 F5 装备动作后必须再核物理左右键释放；文字、IME、箱子和其它原版界面仍阻断。没有实际借用的最优组准备态不应产生“已归还”或“未自动切回”提示。
