## R 世界投影的当前接缝

同批世界图纸定位见[正式合同](../功能介绍/蓝图世界投影行为合同.md)／[实现设计](../设计/蓝图世界投影实现设计.md)。捕获frame-important不等于固定矩形；ObjectId=0的自然内容仍是合法raw快照。绘制保成员raw frame与独立行高／PaddingFix，shape不得被误送“不完整家具”门。半砖要裁源再下移，平台不等于实心三角；植物flip用源X奇偶，局部坐标与Summary源原点不可混用。

## R 世界匹配的对象与失效边界

#138在锁定1.4.5.8上将建筑等价与组内证明分开：元数据的Alternate可能只是点击锚点，也可能携带方向／附着形态；PlacementStyle／RandomVariant也不能按名称全忽略。共享capture decoder先确认真实布局，canonical保建筑种类、样式、方向、结构／附着形态及位置；组内另核全部成员同一实际对象和合法raw布局。闭门逐行独立随机X、PaddingFix、三类selector、随机装饰、灯／机关运行态和自然树片段按真实机制解释，不建家具支持白名单，不把自然ObjectId0统一拒绝。

合法门开闭尤其不能只比源矩形：闭门1×3、开门2×3，左开实际top-left在铰链左一格；canonical位置是铰链列和top，仍须读当前实际六格并保护额外列的变化。一个成员可解释不证明整件完整，raw随机／动画等价也不允许把不同真实组状态的散格拼成同件。具体原版机制及验证入口见[投影设计](../设计/蓝图世界投影实现设计.md#世界匹配与当前完成证明)，原始定位／哈希保本任务证据。

持续运行态必须用真实字段变化验收。`.8`的15tick定时器可以反复切灯raw frame，Main.tileFrame绘制数组不覆盖它。整块反复撤销会拖住同块普通层；改逐对象后，32盏同步切换仍可使各对象来不及同时完成。已完成canonical证明与正在读的raw成员样本须分别管理：只能由完整当前样本产生小型纯值证书，原事务的真实old／new逐成员收口才能延续前者，后者一律取消重取。没有证书、混态、异常和交错writer继续撤资格，不能按方法或家具名称吞掉变化。

同一问题还有首次目标数据的寿命：raw变化不使不可变模板失效，文件请求尚未开始世界采样时反复取消，会让每Update真实ToggleLamp永远取不到首份目标。目标到达后才绑定当前raw资格；开始跨Update采样后真实失效仍丢对应样本。按物理块交付和直接返回一件完整家具曾消除128记录片间空等及anchor往返，但每对象仍独占一次Update：32灯真实采集混合图旧首置需33次源运输，补最后一格只需重核普通层，不能用补齐速度代证首扫。v2用有限运输批与同Update连续消费，保各逻辑对象独立raw资格；局部变化保源和稳定兄弟，批内轮转避开反复失效首项。最终仍在observer同锁逐范围核当前完整证明，替代无条件全图第二遍。

普通轮转与显式优先也必须分别推进。旧优先A同时消耗普通cursor时，四实例会反复选A/B/A/D而跳过C；无priority两实例公平和纯普通65536记录测试都不覆盖它。修法是优先不动普通游标、普通服务转到实际选中实例后继，source admission独立，删除保移位后的后继。新有限工作槽还须验证超过槽数的持续dirty反例：稳定大样本保进度，只有兄弟已消费、唯一项raw反复重启才为待源实例让槽。有限槽的source准入是第二个公平层：容量扫描绕完整圈不能把成功普通准入的后继抹回0，未入槽的移动priority也须有限参与准入。d866首冻只在4槽内安排priority，35份稳定大普通图令后序point身份在516次兄弟服务中0请求；它不同于6份持续dirty让槽。修后普通成功后继与独立交替priority供源，另用70份真实实例证明64次尝试后从未扫尾部接续，不能新设scene数量上限或靠扩大等待。测试私有pending从read迁到work时，故障夹具须同步identity/token观察，测试文件gate必须在using Dispose前放开，避免清理超时盖掉原异常。当前确切红绿、场景和延迟回任务交付记录；不把实现预算、测试规模或60Hz静态换算当产品容量／实测时延。

Moving的候选与原位置restore共享worker身份。致命source失败若只按候选对象引用取消，会恢复Opened但后台已无引用的旧实例，并留下归restore所有的Pending槽。回执应明确实际IdentityRetired；Host按身份释放槽、终止编辑并退休故障restore，普通取消和窗口预算退让保原语义。反例必须让真实reader读到未缓存的坏块，观察另一个模板继续实际采样，不能仅设置Failed／Pending或修改仍被cache遮住的文件。

深色paint还揭示显示验证差异：Sprite tint与原纹理相乘，深绿纹理红通道为零时，CPU传了红色仍可能没有红像素。保原几何／涂料，并在实际冲突层末片段加独立MagicPixel细边，需用相同深绿原XNB和真实WorldLayer.Draw取证；普通石纹或颜色参数断言不能代签。对应原FAIL／修后PNG和源身份回本轮交付记录。

匹配显示不写永久mask，也不改变overlap输入。跨tick覆盖若早先Match成员后来拆掉，必须先撤资格，不能将旧Match与新尾批拼完成；完成后则真正退休这一实例，之后拆世界不复活。对象实际读取依赖必须全进watch/current性，视图revision与Main.tile身份不是内容变化版本。CPU纯值／真实原版消费者、Host事务、GPU、普通包和用户体验各自取证，不相互代签。

## R 材料与真实用物的共同边界

#140 首次材料实现 `4f0cbe9` 同时加入可见 Capture 页 `Prepare→RefreshMaterials→MaterialDraft` 与仅核非空 handle 的请求门。真实 Save 在 Starting 就分配 handle，Sealing 前也已具有 Summary；暖放置目录使半成品能进入只接受 sealed stage 的 worker，读失败随后按同 key 稳定缓存。原 StaticAssembly 等到 Capture helper 完成 DraftReady 后才首次 Prepare，故漏掉这个时间接缝。材料源准入须由 Host 正向核 DraftReady，保目录 demand、正常 Pending、真正 I/O 错误与 accepted Create 的原退休责任；Saving 仅保同完整 key 的已发布值，不为保数字重开源。新增反例必须先暖目录，从真实 Save 的 Starting 起持续运行实际页面 Prepare，不能先封存再看最终状态。正式边界见[采集设计](../设计/蓝图采集实现设计.md#材料声明固定草稿与独立派生读取140-候选)，实际执行结论回任务原件和证据。

同一首次实现还把玩家／库存资格 epoch 用作全范围候选与源证明的失效条件；首项缺料时，持续移动可反复清零游标而饿死后项。正确责任是活动遍历保前进、耗尽时消费相关恢复信号，真实目标／支撑／mask／目录变化仍撤证。不能只删重置而丢补料／走近恢复，也不能让一次普通扣料变成全 scene source 重读；验收要走实际原版 ItemCheck 和真实扣料，不只看 planner 返回对象。这是源码可达机制，所有者未测自动建造前不改称本人实测。

2026-10-27所有者已经反馈自动施工体验；上句只描述旧调查时点。本轮进一步确认首次`4f0cbe9`的单Candidate／逐项重新demand结构仍有跨采样预算缺口，`834c5f8`修复移动重置没有消除它：取走首项后，原read继续到后段而发布更大的ordinal，源到尾又按Candidate为空宣告耗尽，未服务前缀就可能被永久越过。两格移动反例不能覆盖300条跨256预算或共享预算只剩小前缀。施工未处理ordinal须与source采样位置、最终Match进度分离；有限复用原不可变source，不把每次略过都变为整块运输和世界重读。

同轮获准使用的真实保存大图又暴露未交付`d5a68be`源复用方案的另一缺口，不能归到现装`03f0523`或上述旧游标原因。其一个普通源含1648个有效记录，与313个对象范围竞争；原保留只在BeginMaterialSample尝试一次，暂满后长read跨Update出现空槽也不补留；64次范围发现轮转又把大部分机会花在已结束对象上。真实原件518更新仍普通ordinal0、重复逾2万源步骤而没有新起手。300条单普通范围和六个小实例分别覆盖预算、容量，却都没有“大普通源＋同模板大量对象范围”的竞争组合。修复保四槽／1MiB及原预算，对存活read有限重试留同源，先轮转有限活跃源，再做原范围发现；独立夹具须从已知几何产生此混合结构，真实库存扣料及源步骤上界都要核，私有图纸只作隔离补充，不入库或产品。

本轮所有类别的已知拒绝须在新动画之前筛掉。`.8`的CanPlace即使onlyCheck／forcedRandom也会消费RNG并改三个preview缓存；查询副本只能隔离自己的scratch并替换装饰随机，不能暂存／回滚全局RNG。真实消费者仍核所选alternate／style／完整本体。普通实心块（含平台）的Collision.EmptyTile确实查活动玩家与NPC；墙、非实心火把与普通椅子不继承同一门。已有错误世界方块若原版允许，可作其它目标依托，其自身Conflict不变；BuildSupport表示资格观察，不能误删或扩成主动垫块。原版火把可借平台，且正常消费可能先整平一处支撑，不能用metadata家具底锚或一律拒绝坡形替代真实legacy分支。

旧火把例只用了平Stone底托，没有覆盖原Player在放置前主动整平的准备写入。本轮真实trace出现assorted返回允许、原SlopeTile成功后BuildSupport变dirty、同次AllowBuildTileChoice反被旧stamp拒绝，第二次起手才消费；不能以最终能放成功掩盖多挥一次。修复只接受该flight／原生消费代次的真实成功gate和3×3实际预期等值，保普通地形framing语义，仍以整平后原writer拆支撑的晚变化反例检查拒绝。

连续节奏须对照真实原版held input。`.8`的Tile／Wall在itemTime归零且动画仍正时可以再次放置，StartActualUse并非每格消费边界；同一ToolUse租约也须给每目标、每ItemCheck独立代次和消费基线。普通动画等待不等于失败，迟到Finalizer不能作用下一代，未知消费与packet34不能因有后继或低频重核而解除。相关原件与实际本轮结果回同任务交付记录，不从静态机制推导真人、多人或FPS通过。

材料窗拖动冻结的是可容纳字形的局部几何，不是上一串数字的墨迹包围盒。本轮834c5f8初冻把真实汇总70→69的17.3→18字形高变化误当不可容纳，原始GPU检查确认rawLeft仍按住却EndDrag、正文移0.7；修复用固定汇总词汇和数字的真实字形预算稳定普通单行。纯平移后再用两个较大的绝对坐标相减，会出现133.6→133.599976的float损位；判据须验证实际绘制平移、原局部预算和工作量，而不将不同加法次序的位值相等当用户契约。原生产FAIL与oracle数值问题分别保留。

实际页面反例还须满足既有输入阶段：新Shell的matrix默认0，跳过ProcessInput直接AfterUpdate会被F5的可读视口保护正确关闭；复用真实中性映射／ProcessInput后再Prepare，不能强写私有matrix或放宽生产门。封存Normalize将逻辑operation映射到新的physical run，ReadChunk门闩要同时核当前请求逻辑身份和实际物理源，不能假定两个Guid相等。原版UIScale请求值也可能被视口夹紧；100／120%图必须核实际getter、矩阵与缓存视口，文件名不同不证明缩放不同。

## 整件身份不能用“有家具就拒绝”代替

旧复盘明确要求：创建选区碰到可识别家具任一子格，应补齐整件；原选区采全层，扩展出的格只补 object 层，不顺带抓未选 wall/wire。无法证明子格、origin、尺寸或 frame/style/direction 时可以精确拒绝该对象并给原因，不能误伤其它合法内容，更不能默存半件。投影、材料、镜像与候选都需要共享一致的对象身份，而不要求沿用旧字段或类。

## 对象组不变量与子格坐标差异

闭门合法子格的 style offset 曾被误当“整组必须相同”，导致镜像误拒。身份/content/style、origin、尺寸和方向的对象级条件，与每个子格沿样式换行形成的 offset 证明不同。不要为了负例绿而要求所有 frame/offset 相等；应包含真实闭门正例及不可证明对象负例，双次/四次镜像核对往返。

假人六个子格归一化应以 top-left origin 与整件样式为准。历史 .6 raw style 0/1/2/3 表达男女与方向，stored gender 与方向不能混；镜像改变方向不应顺便改性别。TerrariaHelper 只提供 bounds/style/alternate 线索，不构成“它有同一套假人离屏纹理缓存”的证明。

## R 多实例消除与稀疏窗口

本轮明确采用永久session mask，不是普通z-order露底。对象key必须带instanceId；命中一成员只整件消Tile，墙线液体／Actuator保留，masked内容不能继续当覆盖源。Moving排自身并继承旧mask，origin／顺序／全部delta由Host同次提交；worker不确认编辑。原单current、latest全局serial、Cancel后重开整场景会串生命周期，改成模板共享／实例身份与单事务。

原8MiB cache按128+2048×64计费只驻63个满块；65块顺序整窗回访会使64块交集被连续驱逐，真实反例读65块。保持常数不变、先消费命中再miss，配合稳定source core和16格命令段，分别证明IO和构建复用，不能只涨cache或用FPS断言。原目录逐y查询对小viewport有界，但新whole-overlap可传百万空行，必须跳真实块前空gap并重查跨块末行，不能只改viewport遮住。对应红绿与真实源身份回交付记录，组件预算不等于进程峰、FPS或本人体验。

后续双预算接缝揭示另一类闭环：Host接收新window驱逐仍可见resident，下一Draw又重请求；commands超预算后Drop接收者也会循环。每帧4 admission只限速，不收敛。应先用当前永久mask compact immutable DTO（含halo、层及完整对象metadata），再联合raw／replacement命令净增入场；普通先到驻留，拒绝关联稳定需求与真实容量变化，candidate／一个明确point需求有限优先。完成空必须保完成事实，NotLoaded不能当空气选穿；取消／Move restore保旧快照。保存确认同理，图与过滤summary的同key就绪门须共享给按钮和Enter，不能让上帧canSave或任意对象ID数量成为当前证明。当前工程结果与失败仍回原交付记录，不据静态推演声称FPS／OS输入或本人接受。
