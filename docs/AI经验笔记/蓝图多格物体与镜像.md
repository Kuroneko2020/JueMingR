# 蓝图多格物体与镜像

Legacy 行为与历史失败整理；R 尚未实现蓝图。用户能力参考见[Legacy 蓝图](../功能介绍/Legacy蓝图.md)，正式平替合同仍须对应功能任务决定。

## 整件身份不能用“有家具就拒绝”代替

旧复盘明确要求：创建选区碰到可识别家具任一子格，应补齐整件；原选区采全层，扩展出的格只补 object 层，不顺带抓未选 wall/wire。无法证明子格、origin、尺寸或 frame/style/direction 时可以精确拒绝该对象并给原因，不能误伤其它合法内容，更不能默存半件。投影、材料、镜像与候选都需要共享一致的对象身份，而不要求沿用旧字段或类。

来源：`排查复盘/蓝图多格家具保护误伤正常功能-2606301115.md`、旧功能介绍 `蓝图页/蓝图.md` 的多格家具段。旧自动测试未在本轮重跑；后续最小案例包括选中单个合法子格、同件多个子格、真缺格和重叠歧义。

## 对象组不变量与子格坐标差异

闭门合法子格的 style offset 曾被误当“整组必须相同”，导致镜像误拒。身份/content/style、origin、尺寸和方向的对象级条件，与每个子格沿样式换行形成的 offset 证明不同。不要为了负例绿而要求所有 frame/offset 相等；应包含真实闭门正例及不可证明对象负例，双次/四次镜像核对往返。

假人六个子格归一化应以 top-left origin 与整件样式为准。历史 .6 raw style 0/1/2/3 表达男女与方向，stored gender 与方向不能混；镜像改变方向不应顺便改性别。TerrariaHelper 只提供 bounds/style/alternate 线索，不构成“它有同一套假人离屏纹理缓存”的证明。

来源：`排查复盘/蓝图镜像对象组style-offset误作硬不变量-2607050904.md`、`蓝图DisplayDoll-0.1124朝向与镜像输入证明-2607101548.md`。

## 原版脚点、源图脚点与可见底行不是一个值

旧 0.1126 曾用“可见像素贴 object bottom”作正确标准；后续原版 T E Draw 证据纠正：在对应 .6 **空装备站立假人样本**中，原版 standing feet 为 2×3 对象底边减 6，源图可见底行比逻辑脚点多 1，最终可见底行为对象底边减 5。不能把三者都硬设为贴底，也不能将此数值外推所有姿态/装备。

后续查 `references/terraria/1.4.5.6/Terraria/GameContent/Tile_Entities/TEDisplayDoll.cs` 的 Draw 与 DrawPlayer 屏幕位置处理；固定源图锚点与目标锚点时分别证明几何，避免同一错误公式在两边抵消。来源：`Terraria原版参考笔记/DisplayDoll站立脚点与2x3底座关系-2607102045.md`、`排查复盘/蓝图DisplayDoll原版脚点与可见底行不可混同-2607102045.md`。真实像素与资源证据见[绘制主题](绘制分层与图形资源.md)。

## 归一化不能悄悄重解释显式材料

旧测试模板 tile 4/style 0 显式写材料 3104；目录暖起后 fallback 改成 item 8，造成是否提前初始化目录影响结果。即使原始材料看起来不符合真实火把，也不能用“catalog 第一项”覆盖历史显式含义并称修复。应区分可信原始字段、可证明恢复与冲突/未知；保存原件或显式报告，不隐式迁移。

来源：`排查复盘/蓝图归一身份不得覆盖旧模板显式材料-2607120317.md`。后续定向验证目录冷/暖与不同顺序下同一输入一致，检查正例、冲突材料和缺失字段；本轮不修旧代码或制定 R schema。
