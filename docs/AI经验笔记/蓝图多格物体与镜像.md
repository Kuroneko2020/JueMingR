## 正式平台对象与连续施工接缝（#142 修复候选）

- 正式Capture会给1×1平台正ObjectId，原版邻接／坡面改变的FrameX会进入raw RandomVariant；只测ObjectId=0／FrameX=0手工图会漏掉本体Conflict。共享Host语义只对已证明的原版18像素／27槽平台profile规范本体variant，保raw FrameGroup、memberLayout、style及真实shape／涂层。平台不因此获得家具operating-frame witness；坏raw布局和不同FrameY样式继续拒绝或Unknown。ObjectId=0的材料与最终Match也须取得同一已证平台profile，不能用名义recipe.Platform绕过Unknown。
- 描述符按UseItemType只筛普通本体，会让新锤／漆／线操作绕过连续过滤；“完整准备后遇第一异类就退出”会漏掉后面的同源本体。所有lane先解析纯计划再比较当前真实tool／supply／consumer／mode，异类只跳该ordinal；同格锤形重读世界再决定下一锤，不把before-shape当模式分组。
- ToolUse token是一次实际租约，不能同时当批次游标epoch；四份retained是运输缓存，不能当候选全集。偏好ordinal属range，有限batch固定旧成员上界并结清未访问退休份额，普通seed只在公平边界按当前世界重规划。预算暂停／待源不能写成PassComplete，更不能靠空挥保租约或用自己不断产生的dirty重开整轮。

- Smart来源制作与正式智能施工是两种证据。正式省锤须沿自然Player.Update→SmartCursorLookup→ItemCheck→PlaceIt，逐flight／Frame取得准确坐标与二维方向；从slope推出固定X/Y会把上坡漏掉。BorrowAim不能签Lookup回执；同帧解析后才换入的新flight等下一自然解析。原版连续锁按几何段，不等于同料同坡：独立段提交真实neutral，不能改私有lock或伪造release；失败表只在真实neutral／直接路线恢复后有限重开，token／数量／无关dirty不解释恢复。Smart可能改有限邻平台shape，须逐项有当前源／mask／选择与准确目标结果证明；连接FrameX不等于改形许可。平端可先放平、后继再共同成坡，完整Match统一完成，不用后验回滚替代事前授权。初版85be只含下坡窄路，当前证据不支持后来撤销过完整修复。
- 门开闭和左右展开是有限Tile运行态映射。Match正确读两列而动作只刷源hinge，会出现材料零、wing仍未完成；原版paint是单格，不会跟随OpenDoor当刻的复制规则。操作／材料／Match须共用hinge／wing映射，均一闭态去重，不相容闭态保Conflict；原坐标墙／线／致动器独立，映射翼上的实际墙恢复另核。deferred／repeated也用同一重绑出口，不能只修首次候选坐标。
- 已完成的ordinary源片和Draw窗口都可能不驻留。门当前翼格查不到墙上下文不等于图纸明确没选墙；材料视图可无Draw运行，不能靠临时缓存碰巧保住权限。完整≤9格源上下文随原source part运输，含明确空格、同mask资格及全部字节计费。合法密集上下文能超过原retained硬限，必要raw前缀会激活旧“ordinary总是Complete”的隐藏假设：过滤后Cells末尾须接NextOffset，Match和材料跨片累计与dirty订阅不能每片清零，尾片覆盖后的旧游标还须能真实回取早片。传输unit断言和实际Host消费者／完整分母是两种证据。
- 对象bbox／origin相同不代表CanPlace当前chosen同形。共享编码frame→canonical→SamePlacement解释要同时服务预检和晚门；捕获alternate与writer alternate可有合法alias，不能按编号相等代替真实建筑等义。
- UI中的逻辑库存与玩家呈现可以短阶段借用，但不是永久假关包。原DrawInterface混合布局／交互，内部准备从普通关闭库存开始才能借关闭视图；Update／实际ItemSlot／release tail前必须恢复。Hotbar只映射原槽号仍会露出槽内已搬动的Item，需统一标题、hover、Draw与cursor58过渡的准确引用视图。Flexible可把原槽0工具移到材料来源槽；只还原物品视图而保真实新选槽会令标题／额外格读成材料。Using须按本次真实ToolUse／Item反查显示槽并保原版override，不能钉准备前工具。只TryAdoptUse不走真实自动选择的用例漏此传播；反例须让原选另一工具、真实迁移并自动选中后核整套读者。CPU入口／恢复和真实物品链不能证明完整GPU像素。
- 联机GD的17/8无owner、110无坐标；两者单独都不授予临时件来源。唯一单点请求、有序原版成功回包、实际同Tile false→true和精确原生实扣共同建立确认，已观察ABA与引用替换撤权；最终又为true不能重新认领。已知扣料与当前个体可回收资格分别判断，count0不自动成为Unknown。

Legacy 行为与历史失败整理；R 当前选区已接受，真实采集与蓝图库候选见 #134。用户能力参考见[Legacy 蓝图](../功能介绍/Legacy蓝图.md)，正式平替合同仍须对应功能任务决定。

## R 世界投影的当前接缝

同批世界图纸定位见[正式合同](../功能介绍/蓝图世界投影行为合同.md)／[实现设计](../设计/蓝图世界投影实现设计.md)。捕获frame-important不等于固定矩形；ObjectId=0的自然内容仍是合法raw快照。绘制保成员raw frame与独立行高／PaddingFix，shape不得被误送“不完整家具”门。半砖要裁源再下移，平台不等于实心三角；植物flip用源X奇偶，局部坐标与Summary源原点不可混用。

## R 世界匹配的对象与失效边界

连续供料的只读selector与执行记账必须成对设计：把读查询改为不推进端点后，真实原生消费仍须在每个已校验generation结清，再切后继预算。否则同一Item连续合法扣料会在归还时累计超过单次上限，进入Unknown并拖住已经完整Match的实例。正式Capture正ObjectId平台与真实paint的交叉例能区分“没改色”和“改色后收据不能结清”；纯比较器反例和手写ObjectId0不能替代该链。

#138在锁定1.4.5.8上将建筑等价与组内证明分开：元数据的Alternate可能只是点击锚点，也可能携带方向／附着形态；PlacementStyle／RandomVariant也不能按名称全忽略。共享capture decoder先确认真实布局，canonical保建筑种类、样式、方向、结构／附着形态及位置；组内另核全部成员同一实际对象和合法raw布局。闭门逐行独立随机X、PaddingFix、三类selector、随机装饰、灯／机关运行态和自然树片段按真实机制解释，不建家具支持白名单，不把自然ObjectId0统一拒绝。

合法门开闭尤其不能只比源矩形：闭门1×3、开门2×3，左开实际top-left在铰链左一格；canonical位置是铰链列和top，仍须读当前实际六格并保护额外列的变化。一个成员可解释不证明整件完整，raw随机／动画等价也不允许把不同真实组状态的散格拼成同件。具体原版机制及验证入口见[投影设计](../设计/蓝图世界投影实现设计.md#世界匹配与当前完成证明)，原始定位／哈希保本任务证据。

持续运行态必须用真实字段变化验收。`.8`的15tick定时器可以反复切灯raw frame，Main.tileFrame绘制数组不覆盖它。整块反复撤销会拖住同块普通层；改逐对象后，32盏同步切换仍可使各对象来不及同时完成。已完成canonical证明与正在读的raw成员样本须分别管理：只能由完整当前样本产生小型纯值证书，原事务的真实old／new逐成员收口才能延续前者，后者一律取消重取。没有证书、混态、异常和交错writer继续撤资格，不能按方法或家具名称吞掉变化。

同一问题还有首次目标数据的寿命：raw变化不使不可变模板失效，文件请求尚未开始世界采样时反复取消，会让每Update真实ToggleLamp永远取不到首份目标。目标到达后才绑定当前raw资格；开始跨Update采样后真实失效仍丢对应样本。按物理块交付和直接返回一件完整家具曾消除128记录片间空等及anchor往返，但每对象仍独占一次Update：32灯真实采集混合图旧首置需33次源运输，补最后一格只需重核普通层，不能用补齐速度代证首扫。v2用有限运输批与同Update连续消费，保各逻辑对象独立raw资格；局部变化保源和稳定兄弟，批内轮转避开反复失效首项。最终仍在observer同锁逐范围核当前完整证明，替代无条件全图第二遍。

普通轮转与显式优先也必须分别推进。旧优先A同时消耗普通cursor时，四实例会反复选A/B/A/D而跳过C；无priority两实例公平和纯普通65536记录测试都不覆盖它。修法是优先不动普通游标、普通服务转到实际选中实例后继，source admission独立，删除保移位后的后继。新有限工作槽还须验证超过槽数的持续dirty反例：稳定大样本保进度，只有兄弟已消费、唯一项raw反复重启才为待源实例让槽。有限槽的source准入是第二个公平层：容量扫描绕完整圈不能把成功普通准入的后继抹回0，未入槽的移动priority也须有限参与准入。d866首冻只在4槽内安排priority，35份稳定大普通图令后序point身份在516次兄弟服务中0请求；它不同于6份持续dirty让槽。修后普通成功后继与独立交替priority供源，另用70份真实实例证明64次尝试后从未扫尾部接续，不能新设scene数量上限或靠扩大等待。测试私有pending从read迁到work时，故障夹具须同步identity/token观察，测试文件gate必须在using Dispose前放开，避免清理超时盖掉原异常。当前确切红绿、场景和延迟回任务交付记录；不把实现预算、测试规模或60Hz静态换算当产品容量／实测时延。

Moving的候选与原位置restore共享worker身份。致命source失败若只按候选对象引用取消，会恢复Opened但后台已无引用的旧实例，并留下归restore所有的Pending槽。回执应明确实际IdentityRetired；Host按身份释放槽、终止编辑并退休故障restore，普通取消和窗口预算退让保原语义。反例必须让真实reader读到未缓存的坏块，观察另一个模板继续实际采样，不能仅设置Failed／Pending或修改仍被cache遮住的文件。

深色paint还揭示显示验证差异：Sprite tint与原纹理相乘，深绿纹理红通道为零时，CPU传了红色仍可能没有红像素。保原几何／涂料，并在实际冲突层末片段加独立MagicPixel细边，需用相同深绿原XNB和真实WorldLayer.Draw取证；普通石纹或颜色参数断言不能代签。对应原FAIL／修后PNG和源身份回本轮交付记录。

匹配显示不写永久mask，也不改变overlap输入。跨tick覆盖若早先Match成员后来拆掉，必须先撤资格，不能将旧Match与新尾批拼完成；完成后则真正退休这一实例，之后拆世界不复活。对象实际读取依赖必须全进watch/current性，视图revision与Main.tile身份不是内容变化版本。CPU纯值／真实原版消费者、Host事务、GPU、普通包和用户体验各自取证，不相互代签。

## R 材料与真实用物的共同边界

2026-10-28 的精确施工资格不能用“未找到材料 descriptor”倒推仅展示。须绑定锁定原版版本、相关生产者声明覆盖、完整对象 metadata 与具体成员；624 与187/style15的天然本体可证明仅展示，700 与648/style15复制品仍有施工责任。已编译成功 rule 与同精确目标可能相关的未编译声明并存时，也不能提前报材料 Exact；保 Construction/未完整材料，并保独立的完整世界 Match。资格派生统一供给材料、候选、移动与完成分母，raw图纸及永久mask不改，同格墙／线／致动器继续各负其责；未知不是展示。

`d5a68be`首次加入的 ConstructionTargets 只排液体、Refresh 遇空后继即返回false和仅比较前两次消费的测试，分别漏掉天然目标域与跨动画周期的持续节奏。更早`4f0cbe9`顺序候选是背景，不能把新缺口都归到旧游标。沿既有四槽／1MiB与64步预算，复用排序不可变source找附近实际有料目标、重入刚写成的合法依托前缘；同ToolUse token在真实消费机会交接。暂待供源的Pending保持中性并只容纳原自然动画尾，不能续租空挥、改原版timer或另记完成位。墙FillEmptySpace的一次真实消费可写多格，必须记录事件和真实格数，不插0间隔，也不强求两臂事件数相同。

负筛前移还须保失败门的先后：远处同一缺料目标同时记Material和Player，编辑态使eligible变化就会唤醒它，即使玩家朝向、Dirt供给和远世界均未变。真实StableRanges反例的两范围读取各1→2→3，库存分项和源请求均正确；修复只让已具供给的范围登记Player等待，仍保真补料和有料走近恢复。一次Checking点击还要跨首目录publication、首资格回执及首Match建立；这三次初始化不等于该owner退出。真正目录替换、mask／origin／world／identity失效仍撤旧证明和意图。反例应从实际冷目录／实际worker回执开始，不能先预热或再点一次掩盖丢意图。

Fixed只证明提交完成，不证明资格、Match或源已准备。测单Update吞吐前须等待真实资格及同身份work出现，并检查AwaitSourceSupply的返回；不能把false忽略后固定打印ready=true。旧“缺料候选数已增加”也不再是负筛后的可达前提；用超出单片预算但在原世界界内的有限缺料尾，观察真实Material等待与未走完cursor后补料。夹具修正只补对应原消费者及必要顺序前缀，保原聚合FAIL、独立成功与原等待／工作量期待；证据reader未选择整组验收也不证明该失败与任务无关。

#140 首次材料实现 `4f0cbe9` 同时加入可见 Capture 页 `Prepare→RefreshMaterials→MaterialDraft` 与仅核非空 handle 的请求门。真实 Save 在 Starting 就分配 handle，Sealing 前也已具有 Summary；暖放置目录使半成品能进入只接受 sealed stage 的 worker，读失败随后按同 key 稳定缓存。原 StaticAssembly 等到 Capture helper 完成 DraftReady 后才首次 Prepare，故漏掉这个时间接缝。材料源准入须由 Host 正向核 DraftReady，保目录 demand、正常 Pending、真正 I/O 错误与 accepted Create 的原退休责任；Saving 仅保同完整 key 的已发布值，不为保数字重开源。新增反例必须先暖目录，从真实 Save 的 Starting 起持续运行实际页面 Prepare，不能先封存再看最终状态。正式边界见[采集设计](../设计/蓝图采集实现设计.md#材料声明固定草稿与独立派生读取140-候选)，实际执行结论回任务原件和证据。

同一首次实现还把玩家／库存资格 epoch 用作全范围候选与源证明的失效条件；首项缺料时，持续移动可反复清零游标而饿死后项。正确责任是活动遍历保前进、耗尽时消费相关恢复信号，真实目标／支撑／mask／目录变化仍撤证。不能只删重置而丢补料／走近恢复，也不能让一次普通扣料变成全 scene source 重读；验收要走实际原版 ItemCheck 和真实扣料，不只看 planner 返回对象。这是源码可达机制，所有者未测自动建造前不改称本人实测。

## 同材料有限优先与同值原生转向

对象上下文不等于施工层。六类步骤会把平台或多格家具的 `Body` 保留在同格墙候选上，而墙 descriptor 明确用 `TileType=-1`。读 `TileID` 类型表前须先确认 `Placement.Kind==Tile`，不能从 `Body!=null` 推导可索引的前景类型，也不能靠先判空容器回执掩盖错误。重启恢复会重新生成该候选；Feature.Update 异常被运行时失效保护捕获后，蓝图库与凝胶工具栏可因共享可用性门一起关闭，普通启动日志没有错误不等于未发生。回归应保留真实采集对象、同格墙和开启自动建造的组合，并另核实际容器回包等待没有被绕过。

同type不足以授权续用原动作；须同实际slot、Item引用、type及附带依赖槽集合。先保住合法普通fallback，再在同一源步／完整preflight预算内只查现有retained一轮；偏好瞬时target不能占普通单Candidate或推进forward。主动优先成功后，一个只含蓝图描述的让位seed提供有限服务终点；prepared仍可能被前一真实写撤证明，因此必须等Admitted／Refresh实际交接才销账。旧support、flight及消费基线不能随seed保存，来源失效也不能顺带丢掉被让位的其它工作。reach观察与当前来源hint须同口径，不能只观察同type的首堆或总包络。

原方向借用缺口在本轮之前：早期4f0cbe93首次施工／借向、b777d8f加入目标解析提前借向，dca72b66再施方向只用“当前值不同于自写值”更新归还基线；a6ea99ae是在既有解析方法内加入cursor模式借用。原生HorizontalMovement／ChangeDir若选择恰与临时值相同，会同值早退；StartActualUse抓钩也可晚直接写同值，结束遂恢复过时方向。旧左椅／右移与晚右写均与借入左方向不同，且到Scene清空／Use退休之后才验方向，后续原生闲置帧可掩盖首消费帧错误。修复让解析与consumer各自短借向，原生两段转向不跨租期；Lookup异常由同挂点finalizer在Update catch继续移动前归还。新判据在首个真实扣料Player.Update返回立即核方向，并另核家具完整实际方向／样式；组件生命周期不替代原生结果。
