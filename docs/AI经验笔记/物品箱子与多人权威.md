# 物品箱子与多人权威

本页为 Legacy .6/.7 原版笔记及后续功能说明的历史整理；本轮没有执行箱子/多人操作。R 目前无这些能力，实际合同见[技术平台规则](../规范/技术平台与兼容规则.md)与对应未来任务。

## 容器字段不能替代语义分类

旧资料中 `Main.tileContainer` 含 21/467、梳妆台 88、展示类 470/475 等，不都拥有可改名的世界 Chest。普通箱 21/467 为 2×2，梳妆台 88 为 3×2；fake chest 441/468 需进一步辨明行为。世界非负 chest index 与个人银行 -2（猪猪/钱币槽/Chester）、-3（保险箱）、-4（护卫熔炉）、-5（虚空）不同。假人/帽架装备由 tile entity 承担，不是 Chest 名称数据。

原版机制笔记偏重“普通宝箱”能力分类，较晚[宝箱显名功能说明](../功能介绍/Legacy更多信息.md)却明确包含梳妆台与 fake chest 默认名解析。不能用 tileContainer 一刀切，也不能把旧笔记的窄能力建议改成 R 已接受的显示范围；该差异在未来容器功能任务核对真实代码与用户行为。

来源：`Terraria原版参考笔记/Chest_Container_notes.md`、`Inventory_Equipment_notes.md`，以及旧功能介绍 `更多信息页/宝箱显名.md`。

## 拾取来源与同类堆叠

`GetItem(WorldItem, PickupItemFromWorld)` 与共享 Item overload 的用途不同；LootAll 不一定经过 ItemSlot，cursor 从容器拿走后即使关 UI 仍保留来源。数组身份比 context 3/4/32 这类辅助数字更能证明容器归属。`newAndShiny` 会被 UI 清理、可能由非世界来源设置，也可能在钱币/合并栈时不设置，不能当可靠拾取标记。`Item.CanStack` 还检查 type、prefix 和可堆叠性，不只是名称相同。

较晚 Legacy 自动堆叠说明要求选择性 pending transaction，容器取出不得触发重新存回，入队后来源变化也须拒绝旧请求；钱币由自动存钱开启时独占。容器关闭不解除钱币取出保护，观察失败不等于离开银行范围。见[Legacy 物品](../功能介绍/Legacy物品.md)。这些历史状态规则可供行为任务分析，不要求 R 移植旧队列。

## MoveCoins 的零返回与参数签名

`NearbyChests.GetBanksInRangeOf` 的成功且无银行、成功且有银行、读取失败是三态，失败不可释放保护。旧 `ChestUI.MoveCoins` 某些路径会在修改后返回 0，不能凭 raw 0 认为无副作用并执行 fallback。空银行首币历史补救只覆盖能证明的 player.bank，不泛化到其它三银行。

反射 `SetDefaults(int, ItemVariant = ...)` 的可选参数不使它变成一参方法；需要完整签名与正确参数。应在写入前完成解析和恢复条件准备，不能先改钱币再找失败补救。

来源：`Terraria原版参考笔记/Inventory_Equipment_notes.md`、`Chest_Container_notes.md`；后续对相应版本 `Player.cs`、`UI/ChestUI.cs`、`GameContent/NearbyChests.cs` 定向查调用和原始返回路径。

## ABI 与多人证据不可泛化

1.4.5.6 `WorldItem.inner` 是 public field；1.4.5.7 是 public property、private setter。这是编译 ABI 差异，同源码分别编译不证明一个 DLL 跨两版通用。较晚 Legacy 自动堆叠文档明确其当时测试包只面向 .7；R 编译目标 .8 不受这些树替代。

旧 .7 箱内定位提交时请求当前玩家 section 的原版 159 数据同步。请求发出不证明数据已到、周边所有箱子已同步，更不证明服务器权威或多人验收。只读 `Main.chest[].item` 可以报告客户端当前已知结果，不能编造未同步容器；需要核对来源、section、响应时机与拓扑。来源：旧功能介绍 `物品页/自动堆叠.md`、`搜索查询页/箱内物品定位.md`；本地对应原件在 `references/terraria/1.4.5.7/Terraria/`，定向查 `WorldItem` 与消息处理，不执行网络行为。
