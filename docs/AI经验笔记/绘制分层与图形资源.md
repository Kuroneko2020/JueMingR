# 绘制分层与图形资源

## R #55：世界文字的缩放、镜像与代表体

当前 .8 `GameInterfaceLayer` 已拥有 Game 缩放 batch，世界锚点减相机后交给它，不再乘 UI scale。`ZoomMatrix` 不含倒重力镜像；依原版同层标记/战斗文字语义镜像对象锚点而保持字形正立。位置还需跟随 `netOffset/gfxOffY`。宽松扫描余量不等于共享对象的可见代表范围：头部完全在屏外却落在余量内时，不能压掉屏内身体后又在文字层被裁掉。对应 `EntityObservationChecks` 与 `EntityWorldChecks.Logical`；实际 XNA/代表预览本轮因设备创建前 adapter=0 待补，逻辑反例不证明像素外观。

本页分别记录当前 R 字体度量问题与 Legacy 历史失败，不把局部绘制验证外推为 FPS 或实机验收；当前 R 资源职责见[F5 设计](../设计/F5控制界面样板与UI基础.md)。

## R：空格占位矩形不等于可见字形高度

#46 的丢弃提示开关出现整行增高、文字偏上的现象，文本本身没有换行。原版 `Mouse_Text.xnb` 的“提示 开”回调包含 Y=40 的透明 1×1 空格矩形，直接合并所有矩形使高度从 18 变为 41；只测合成字体或两态几何稳定，会漏掉这种原资源差异。应在共用度量里排除受支持 U+0020 的垂直占位，保留水平推进、原生 CR/LF 和其他 fallback，不能靠去空格、固定按钮高度或全跳过 1×1 掩盖根因。

回归入口为 `UiTextMetricsChecks` 的真实 ReLogic CPU 回调边界和 `ItemUiChecks` 的原版 XNB 度量、两态等高及 100%/150% UI scale 绘制预览。原资源预览使用隐藏 XNA fixture，不启动实际游戏；本条不证明真实第三方字体包、FPS 或所有者接受。具体候选与执行结果查 [Issue #46](https://github.com/Kuroneko2020/JueMingR/issues/46)。

## R：新页面共用控件与命中，不能只借用皮肤

Notes/Items 初次接入时，即使借用了 F5 纹理，独立按钮尺寸、字形定位或操作路径仍会造成风格与交互分叉。当前 Notes/F5 共用 `UiSurface` 的表面绘制，Items 与信息页还共用 `F5RowLayout`、`F5ControlRenderer` 的行控件，领域命令仍在 Notes/Items；绘制、命中与裁切使用同一布局。新页面应同时走 `F5LayoutChecks`、领域输入/几何和实际 XNB 预览，不能只比较颜色。内联选择、十列图标、对号/红叉等后续偏好与当时实现缺陷应按 #46 历史分别归因。

`a3740d6` 的 `ItemsRenderer.Fill/Stroke` 修正另一类原资源错误：SpriteBatch 的 scale 缩放源图，null 源矩形会把整张高 MagicPixel 画出；明确取 1×1 源后再按目标长度缩放。`ItemDecorationChecks` 覆盖 1×1、1×1000、32×32 与资源替换；不能从纹理名字猜尺寸。这与上面的空格垂直度量是不同根因。

RDP 的 adapters=0 或设备创建前失败只能说明显示环境不可用，按既有[图形分层规则](../规范/测试与审计规则.md#显示环境受限时的验证分层)保留待补；已进入 Draw 后的断言失败仍需修复。#42 历史延期与 #46 后续执行各绑定其候选，不能用总体正常反馈补造像素/IME/FPS通过。以下各节为 Legacy 历史证据。

## Legacy 显名：层级、文字缓存与可见名额分别核对

旧1.7.448记录为解决文字压住原版UI，把信息层下沉并保留失败回退；它的基准明确是原版`.6`。当前Legacy源码的世界文字走Game层，F5走UI层，悬挂笔记还有自己的坐标域；Notes屏幕位置不能直接当实体标签位置。标签先减相机位置、再由宿主层缩放，裁剪却在该变换前发生。新任务须分别验证世界锚点、屏边和实际层级，不把历史记录当当前`.8`完整支持。

名称/生命值两行经历了−0.10、0.75倍、−0.13和行距补偿；字号变大而间距仍沿用旧值会挤行，单独验证数值公式不能证明中文真实视觉。旧样本0.80/0.67不等于当前默认0.70/0.57。旧外层384项文字度量缓存也没有字体/语言身份，命中时绕过内层字体刷新检查；修一个缓存不能自动证明整条缓存链失效正确。120条标签在距离/屏幕过滤前按索引选取，静态上可能由远处对象占尽可见名额；本轮没有复现实际饥饿或测量FPS。

来源、历史修法和后续验证入口见[显名合同第5–6节](../功能介绍/敌怪动物与NPC显名功能行为合同.md#5-世界绘制生命周期多人和成本)，固定源码Z08/Z10/Z13/Z14、未跟踪历史H01/H03–H06的独立身份见其[来源附录](../功能介绍/敌怪动物与NPC显名功能行为合同.md#10-来源覆盖与缺口)。这些是 Legacy 静态经验与旧记录；R 三项显名已有独立实现与接受边界，见该合同第8节，不以本节代替当前 R 源码。

## Legacy 目标高亮：连通矩形不等于完整多格对象

固定 Legacy `6ac6356` 的五项高亮共用 Main.tile 路径，生命水晶实际回退到 Heart12，魔力水晶639、生命果236、睡眠碎岩龟751；DragonEgg无可解析字段，不能从行名猜成任何蛋或实体。当前原版 `.8` 的 PalworldChilletEgg752、掉落物品和打开产物是不同身份。源码与版本证据见[目标合同的五项身份及附录](../功能介绍/附近目标探测与高亮功能行为合同.md#2-五项身份与来源)。

旧 scanner 只看 active/type，四邻接合组、每组最多64格，不读frame/style/origin；邻件可能合一框、残片可能入选。`4258ef0` 修复在每次绘制前重新检查旧矩形里是否至少还有一个同类active格，解决完整移除仍显示的情形，但不能证明整件存在或矩形已缩小。旧过滤不覆盖缓存，同坐标返回还可再次出现。后续防回归应围绕真实完整对象、消失、重放与当前会话，而不是把64格、60tick和旧数组写成产品义务。

图形结论也须追到最终颜色：renderer虽算正弦pulse，但普通RGB解析A=255，max(A,pulse)恒255，不能凭表达式声称画面会呼吸闪烁。五行未提供styleFeatureId，故有颜色配置字段不等于有调色窗。R现有StyleEditor的RGB草稿可复用，完整StylePopup仍含显名目标/字号；颜色-only须作窄适配，世界文字renderer也不等于已有矩形角标能力。具体[复用边界](../功能介绍/附近目标探测与高亮功能行为合同.md#6-r-复用对照)与[成本/失效](../功能介绍/附近目标探测与高亮功能行为合同.md#4-查询范围完整对象与失效)均为V0，本批尚未实现，没有实机、多人或FPS结论。

## 背景墙应由真实世界层承担遮挡

旧墙 ghost 连续尝试过裁掉前景覆盖格、减淡颜色、移动 UI pass，仍出现墙不完整或盖住人物/家具。后续证据区分了：已放置投影与摆放预览是两个入口；修完前者不代表后者已修。即使墙进入正确 world layer，late overlay 的整格 range 填充仍能再次盖住前景。有效方向是保留完整墙目标/材料数据，让墙在世界背景层绘制，并去掉会重复遮挡的墙模板范围填充；不是剪掉期望墙格来伪装修复。

来源：`排查复盘/蓝图墙ghost生命周期底层修复-2606291136.md`、`蓝图摆放预览墙层漏修-2606291453.md`、`蓝图摆放预览range填充盖前景-2606291732.md`，及该目录较早四篇墙 ghost 复盘。较早口径已被后续失败限定，不继续当正确方案。

## DisplayDoll：黑像素与空纹理需要不同证据

旧 0.1121 实机失败后，0.1123 记录女假人朝右样本中 **728 个非透明像素的 RGB 全为 0**；相同 alpha/形状的 fullbright 对照恢复 RGB，支持该样本源 Lighting 导致黑色。另一个现象是 backbuffer 变化后目标仍未 Dispose、尺寸仍 48×64，却 `IsContentLost=true` 且非透明像素为 0。对象存在、尺寸正确和句柄活着不能证明内容有效。

后续历史修复将中性源颜色与最终 ghost alpha 分开；源图不重复施加阴影/透明度，最终绘制只承担一次透明度。缓存的外观 key 与图形设备/世界 generation 有效性不同；内容丢失或资源重建后旧纹理不得继续算成功。不能靠全局改 `Main.gameMenu` 暂时“变亮”，也不能在正常 Draw 中增加 GPU readback。

来源：`排查复盘/蓝图DisplayDoll-0.1121实机失败事实冻结-2607100926.md`、`蓝图DisplayDoll-0.1123实机像素与content-loss根因确认-2607101506.md`、`蓝图DisplayDoll-0.1125中性离屏颜色职责-2607101713.md`、`蓝图DisplayDoll-0.1127图形资源生命周期职责-2607101846.md`；`Terraria原版参考笔记/RenderTarget内容丢失与重建生命周期-2607101846.md`。0.1132 总复盘记载所有者对位置、方向、透明度、resize/UI scale 的样本反馈，不能反证早期包已正确，也不能外推所有外观组合。

## 图形状态恢复必须覆盖失败分支

离屏绘制借用 render target、viewport、SpriteBatch、screenPosition、shader 等状态时，要明确谁借用、谁恢复、何时失效。一项清理抛异常不应阻止其余恢复；失败生成不能缓存为成功。真实原版 DrawPlayer 会读取自身管线状态，伪世界公式与纯 helper 测试不等于该调用上下文。后续查证应固定身份与场景，先保留失败源图，再用不污染生产的对照辨别；[假绿辨别](行为验证与假绿辨别.md)说明证据边界。

## 完整数据、可见裁剪与滚动各自负责什么

大模板按固定前缀 512/1536/2048 截断，可能让排列较后的屏内内容永不绘制。完整有效模型与按视口裁剪不同，不能把截断模型称为优化且默认无行为损失。特殊实体的代表格 16×16 也不是 sprite bounds，外层和内层裁剪都必须保留仍可见的整件图像；后处理只缺油漆等状态时，主体存在就不再叠一层假人虚影。

UI 标题滚出视口只应跳过标题，不能提前返回整个子菜单；modal 阻挡了滚轮不代表正文能滚，正文要有自己的 viewport、content height 与 offset，标题/关闭按钮固定。来源：`蓝图大模板固定前缀截断-2607011916.md`、`蓝图DisplayDoll外层代表格裁剪与实体bounds不可混同-2607102137.md`、`蓝图后处理主体虚影误叠特殊实体-2607081808.md`、`蓝图子菜单标题滚动早退-2607012117.md`、`蓝图材料弹层只阻断不滚动-2607012337.md`（均在旧 `排查复盘/`）。这些是行为和成本形态证据，不证明 FPS 收益。
