# 绘制分层与图形资源

## R：聊天颜色标签不递归解析物品图标

锁定 Terraria 1.4.5.8 的 `ChatManager.ParseMessage` 采用非递归标签匹配，`ColorTagHandler.Parse` 直接生成文字片段。把 `[i:ID]` 塞进整段 `[c/颜色:正文]` 不会生成图标；应拼接相邻颜色片段和独立物品标签，并避免空颜色片段显示为原文。`ItemTagHandler` 的 s/x 数量会截到物品 maxStack，合并掉落的真实总量应继续保留在正文；只有受信 ID 能生成图标，外部名字仍清洗。

颜色切换标签也占聊天字节预算，不能只计可见名称或原始图标标签。承载物包含多个槽时，应在内层完整槽预算和最终消息预算都保留该开销。图标解析得到 ItemSnippet 不证明实际贴图可见；其 `UniqueDraw` 还会触发原版 LoadItem/ItemSlot.Draw。#89 的 `NativeAnnouncementIconChecks` 分别验证实际解析、数量/名称、恶意标签、超长内容及原版 XNB 像素；不冒充真实联机送达。技术合同见[宣告实现设计](../设计/物品浏览器箱内定位与快捷宣告实现设计.md)。

## 死亡详情与地图：小输出不能掩盖全量准备

冻结 Legacy `6ac6356c0c564f43284590c168855e96c50e13f7` 的详情每页只有 6 条，但 Draw 入口的缓存命中仍 Clone 全 N 条历史，500 ms 到期还会全读/反序列化/排序。地图虽仅留 256 个候选，首次/文件变化仍在 Draw 同步扫描全史、为有效事件构造 tooltip，并反复 RemoveAt(0)；稳定帧还复制候选。两者各有同步锁和文件缓存，不存在能据名称推断的后台读取。死亡/时间观察必须保留，关闭展示后应撤销的是详情/地图准备，不能靠停止记录满足成本计数。

当前原版 `.8` 地图 context 的 mapScale 控位置、全屏 drawScale 实际取 UIScale；复用原生投影不等于图标随地图等比缩放。原版最近死亡点另有 Y 偏移，重复画相同事件可能略错位；旧层后写 hover 还能盖掉原版经过时长。原版 AddLayer 无公开移除，末尾全屏回调在 SpriteBatch.End 后，R 调查基线的世界文字层与 F5 都排除全屏地图，不能声称已有地图接入。层注册/退出、实际批次、资源失效和输入共存须单独窄核验。证据与新版已接受目标见[四项合同的地图与成本](../功能介绍/死亡信息死亡详情世界天数与死亡点常驻行为合同.md#5-死亡点常驻)，四档数量不是旧版能力，需求接受不证明图形实测或 FPS。

## R：正文缓存命中不代表外围准备已经复用

固定 `b64933d` 的 `NotesPresentation.Prepare` 将光标修订、页面滚动和未完成排版都送入完整 `NotesCards.Prepare`。正文布局虽复用，仍重建全部 N 篇的卡片几何、2N 个控件及其 ID 字符串；正文推进预算不覆盖这部分工作。后续修正应在这两个 owner 区分内容/高度变化与光标/可见区变化，保留真实高度改变后的排布、命中一致、拖选和长文最终完成。既有 `NotesHostChecks` 的正文引用稳定断言不能证明卡片控件也稳定。

同一基线的样式窗关闭后仍保留 Editor，壳层重复 Close 会重新取消同一草稿；滑杆同坐标保持也会递增草稿 revision，使副窗布局重建。这里是草稿失效，不是同值配置提交或写盘。后续仅在真正草稿变化时修订，关闭时退休草稿并保留输入尾缘；不能只比较 RGB，灰色 Hue 记忆及未完成 HEX 状态仍有独立语义。既有 `EntityStyleInputChecks` 的空闲 Prepare 缓存断言不覆盖这两条输入路径。

上述为 [Issue #65](https://github.com/Kuroneko2020/JueMingR/issues/65) 在 `b64933d` 的静态机制知识，当时未改变实现，未测量实际耗时或 FPS。历史报告保持原判定。

[Issue #67](https://github.com/Kuroneko2020/JueMingR/issues/67) 的 `ecf3627` 保留稳定卡片/控件，区分局部文本和全本几何失效；必要高度变化仍重排。复用后必须冻结按下时的几何/文字并随投影变化取消旧点击；页面重入即使不重排也要重新公布 ContentHeight。`NotesWorkloadChecks` 与既有 Notes 输入检查共同保护这些边界。`5c38a3d` 在关闭时退休草稿，并仅在已规范化的完整 HSL 同值状态短路；`EntityStyleInputChecks` 和真实已编译 Host 的关闭 Shell 检查覆盖实际调用。草稿 revision 与配置写盘仍是两种责任。上述检查已接入 [工作量入口](../设计/高频路径工作量回归.md)，不证明实际 FPS 改善。

正向资源替换预览的合成字体也须满足正式布局合同。既有配色第四场高度 30 必然挤掉导航下划线安全间距，#67 仅将正向输入改为 26，保留宽度/偏移/150% 场景；`F5LayoutChecks` 继续单独验证超高字体拒绝，不能以预览需要通过为由放松生产拒绝规则。

## R #63：资格准备与显示名额分开

所有者后续要求文字底边贴物体顶部时，不能只删除固定间隔：`LineSpacing × 行数`还包含字体底部留白和尾空行。共享`UiTextMetrics`返回的可见底边是`OffsetY + Height`，不是Height；在已有有界准备中缓存，再让Draw与屏边资格共用，截断退回也要恢复边界。普通箱子与梳妆台中心偏移16/24；物品标签还有独立ItemStack数量字体和描边，新增度量依赖必须进入资源失效判断。

格顶也不等于可见纹理顶：`.8` 闭合箱子常有6像素透明区、墙牌6像素、梳妆台0；字形正文底与黑描边底另差1.5。当前用有限原资源边界表取可见顶并让正文贴边，倒重力需取原可见底，箱子底常34不能照搬格高32。维护表时核原版裁片/绘制偏移与实际XNB alpha；不在Draw读回纹理。图形测试必须拿纹理可见边界而非同一格矩形公式作oracle，长名字还会污染邻居采样区，应逐物体隔离并保留组合预览。细节、表的版本/闭合帧限制、历史GPU延期与本次图形通过见[实现设计](../设计/宝箱牌子与墓碑显示实现设计.md#文字与绘制)；不等于实机接受。

首次Update可能早于原版界面层Setup。可恢复就绪状态不能仅用false表示“尚未建立/已失败”，否则已保存的开启配置在首次进档收到错误提示、随后正常绘制又掩盖时序。由安装入口区分Pending/Ready/Unavailable，只在完整Setup失败后报告；恢复时清去重阶段，之后真故障仍需报告。实际builtHost的`NativeLayerReadinessChecks`覆盖两句旧误提示及新失败恢复，不靠固定等待或不再报错来修。

全alpha边界也可能选错语义对象：告示牌文字应贴牌面，吊链顶不是牌面顶。773411e的检查只取整个物体墨迹，吊挂牌即使留下10世界像素间隔仍可假绿；用所有者原文分别放在style1/2的实际原资源预览才复现差别，斜杠字形与类型传递均不能解释此间隔。当前按已核牌面ROI排除竖直附件，保留破损牌板碎片；默认尺寸的三类牌×五安装方向×双重力独立像素检查和组合预览入口为`NativeSignAnchorChecks`。不要用统一偏移、按行宽阈值削平碎片或镜像整个格高替代牌面边界；精确数据见[设计](../设计/宝箱牌子与墓碑显示实现设计.md#文字与绘制)。用户确认箱子/梳妆台不代表牌墓也已接受。

Top-K 的候选必须已经满足实际正文/墨迹资格。只给近处未知正文预占名额，再加512项拒绝缓存，在600个长空白彩色牌子下仍会循环淘汰重试、饿死后面的有效文字。当前将8个待准备槽与272/56/56就绪候选分开，满时暂停原游标，拒绝缓存只节省工作；历史与tile发现轮换获得冷槽。空行只影响行距，是否完全裁出要按最多10行的实际墨迹边界判断。实际原版 `NativeWorldChecks` 的长空白、屏外墨迹、重新启用冷任务和超过K反例保护此职责，内部预算/极端内容延迟见[设计](../设计/宝箱牌子与墓碑显示实现设计.md)。

原版颜色解析器会处理反斜杠，已验证字面正文不能再次直接塞进标签解析；用安全常量建立颜色片段后 `CopyMorph` 放正文。已布局 `PositionedSnippet` 重载避免 Draw 再解析/排版，但原版四次描边＋一次正文枚举仍在 x86 每块分配240 bytes，不能把缓存命中写成零分配。中立原资源夹具需显式提供 `_uiScaleMatrix`，其默认零矩阵在未运行 `Main.Initialize` 时会让真实 F5 样式窗消失；这属于夹具初始化，不应修改生产渲染兜底。原版字体能正确切分 Unicode 不保证拥有全部 emoji 字形。该候选视觉和成本是隔离证据，实机接受另查 #63。

外层空名单早退也不能绕过资源失效：唯一完整字符单元被旧字体判超宽后，拒绝缓存可能让候选永久为零。若字体身份检查在零候选返回之后，新字体再合适也不能恢复。当前保留全关最早退出，在开启状态先比较资源身份再判空；`EmptyCandidateFontRecovery` 先失败，再证明仅换回原字体即可恢复实际绘制，避免靠切模式清缓存掩盖根因。

## R #55：世界文字的缩放、镜像与代表体

当前 .8 `GameInterfaceLayer` 已拥有 Game 缩放 batch，世界锚点减相机后交给它，不再乘 UI scale。`ZoomMatrix` 不含倒重力镜像；依原版同层标记/战斗文字语义镜像对象锚点而保持字形正立。位置还需跟随 `netOffset/gfxOffY`。宽松扫描余量不等于共享对象的可见代表范围：头部完全在屏外却落在余量内时，不能压掉屏内身体后又在文字层被裁掉。对应 `EntityObservationChecks` 与 `EntityWorldChecks.Logical`；实际 XNA/代表预览本轮因设备创建前 adapter=0 待补，逻辑反例不证明像素外观。

本页分别记录当前 R 字体度量问题与 Legacy 历史失败，不把局部绘制验证外推为 FPS 或实机验收；当前 R 资源职责见[F5 设计](../设计/F5控制界面样板与UI基础.md)。

## R：空格占位矩形不等于可见字形高度

#46 的丢弃提示开关出现整行增高、文字偏上的现象，文本本身没有换行。原版 `Mouse_Text.xnb` 的“提示 开”回调包含 Y=40 的透明 1×1 空格矩形，直接合并所有矩形使高度从 18 变为 41；只测合成字体或两态几何稳定，会漏掉这种原资源差异。应在共用度量里排除受支持 U+0020 的垂直占位，保留水平推进、原生 CR/LF 和其他 fallback，不能靠去空格、固定按钮高度或全跳过 1×1 掩盖根因。

回归入口为 `UiTextMetricsChecks` 的真实 ReLogic CPU 回调边界和 `ItemUiChecks` 的原版 XNB 度量、两态等高及 100%/150% UI scale 绘制预览。原资源预览使用隐藏 XNA fixture，不启动实际游戏；本条不证明真实第三方字体包、FPS 或所有者接受。具体候选与执行结果查 [Issue #46](https://github.com/Kuroneko2020/JueMingR/issues/46)。

## R：新页面共用控件与命中，不能只借用皮肤

#89 首轮物品浏览器把动态说明、输入、状态及换行试探片段送入 `F5Layout.TextSize` 固定文案缓存。同字体/窗口的连续浏览累计达到1024项后抛异常，F5 fail-closed 而独立定位高亮仍存在，表现为无法清除且F5无法重开。修复使用已有 `DynamicTextSize`，由当前页面保留布局；不能扩大上限、随意清固定缓存或取消异常保护掩盖归属错误。反例用同一布局连续160种真实物品说明，再重开/清除；另用真实Host输入链验证定位成功自动关闭→F5重开→清除。入口与执行状态见[实现设计](../设计/物品浏览器箱内定位与快捷宣告实现设计.md)及#89；独立Prepare/Draw截图不能替代这一完整生命周期。

Notes/Items 初次接入时，即使借用了 F5 纹理，独立按钮尺寸、字形定位或操作路径仍会造成风格与交互分叉。当前 Notes/F5 共用 `UiSurface` 的表面绘制，Items 与信息页还共用 `F5RowLayout`、`F5ControlRenderer` 的行控件，领域命令仍在 Notes/Items；绘制、命中与裁切使用同一布局。新页面应同时走 `F5LayoutChecks`、领域输入/几何和实际 XNB 预览，不能只比较颜色。内联选择、十列图标、对号/红叉等后续偏好与当时实现缺陷应按 #46 历史分别归因。

`a3740d6` 的 `ItemsRenderer.Fill/Stroke` 修正另一类原资源错误：SpriteBatch 的 scale 缩放源图，null 源矩形会把整张高 MagicPixel 画出；明确取 1×1 源后再按目标长度缩放。`ItemDecorationChecks` 覆盖 1×1、1×1000、32×32 与资源替换；不能从纹理名字猜尺寸。这与上面的空格垂直度量是不同根因。

RDP 的 adapters=0 或设备创建前失败只能说明显示环境不可用，按既有[图形分层规则](../规范/测试与审计规则.md#显示环境受限时的验证分层)保留待补；已进入 Draw 后的断言失败仍需修复。#42 历史延期与 #46 后续执行各绑定其候选，不能用总体正常反馈补造像素/IME/FPS通过。以下各节为 Legacy 历史证据。

## Legacy 方向：正确角度不等于正确视口

固定 Legacy `6ac6356` 两方向共用Game层，但旅商已用逆ZoomMatrix还原实际视口，稀有仍把未缩放坐标与物理屏幕尺寸比较；不能用旅商修复历史替稀有背书。当前原版 .8 的ZoomMatrix不含Effects镜像，倒重力须另核世界锚点与指向，同时保持字形正立。长名字只钳起点、不约束最终字框也会越界，角度纯函数通过不足以证明可见输出。

方向Draw当前已取target-only快照，不再复制整批NPC；共享文本缓存命中仍可能拼键/加锁/重建布局，不能反写成每帧真实测量。装备提醒则是另一独立自绘文字生命周期，不继承PopupText/CombatText的合并或避让。来源、最终消费者和后续投影反例见[三项合同第7、9、11节](../功能介绍/稀有生物旅商方向与装备提示行为合同.md)，本条没有实机或FPS结论。

## Legacy 显名：层级、文字缓存与可见名额分别核对

旧1.7.448记录为解决文字压住原版UI，把信息层下沉并保留失败回退；它的基准明确是原版`.6`。当前Legacy源码的世界文字走Game层，F5走UI层，悬挂笔记还有自己的坐标域；Notes屏幕位置不能直接当实体标签位置。标签先减相机位置、再由宿主层缩放，裁剪却在该变换前发生。新任务须分别验证世界锚点、屏边和实际层级，不把历史记录当当前`.8`完整支持。

名称/生命值两行经历了−0.10、0.75倍、−0.13和行距补偿；字号变大而间距仍沿用旧值会挤行，单独验证数值公式不能证明中文真实视觉。旧样本0.80/0.67不等于当前默认0.70/0.57。旧外层384项文字度量缓存也没有字体/语言身份，命中时绕过内层字体刷新检查；修一个缓存不能自动证明整条缓存链失效正确。120条标签在距离/屏幕过滤前按索引选取，静态上可能由远处对象占尽可见名额；本轮没有复现实际饥饿或测量FPS。

来源、历史修法和后续验证入口见[显名合同第5–6节](../功能介绍/敌怪动物与NPC显名功能行为合同.md#5-世界绘制生命周期多人和成本)，固定源码Z08/Z10/Z13/Z14、未跟踪历史H01/H03–H06的独立身份见其[来源附录](../功能介绍/敌怪动物与NPC显名功能行为合同.md#10-来源覆盖与缺口)。这些是 Legacy 静态经验与旧记录；R 三项显名已有独立实现与接受边界，见该合同第8节，不以本节代替当前 R 源码。

## Legacy 目标高亮：连通矩形不等于完整多格对象

固定 Legacy `6ac6356` 的五项高亮共用 Main.tile 路径，生命水晶实际回退到 Heart12，魔力水晶639、生命果236、睡眠碎岩龟751；DragonEgg无可解析字段，不能从行名猜成任何蛋或实体。当前原版 `.8` 的 PalworldChilletEgg752、掉落物品和打开产物是不同身份。源码与版本证据见[目标合同的五项身份及附录](../功能介绍/附近目标探测与高亮功能行为合同.md#2-五项身份与来源)。

旧 scanner 只看 active/type，四邻接合组、每组最多64格，不读frame/style/origin；邻件可能合一框、残片可能入选。`4258ef0` 修复在每次绘制前重新检查旧矩形里是否至少还有一个同类active格，解决完整移除仍显示的情形，但不能证明整件存在或矩形已缩小。旧过滤不覆盖缓存，同坐标返回还可再次出现。后续防回归应围绕真实完整对象、消失、重放与当前会话，而不是把64格、60tick和旧数组写成产品义务。

图形结论也须追到最终颜色：renderer虽算正弦pulse，但普通RGB解析A=255，max(A,pulse)恒255，不能凭表达式声称画面会呼吸闪烁。Legacy五行未提供styleFeatureId，故有颜色配置字段不等于有调色窗。R调查基线StyleEditor的RGB草稿可复用，当时完整StylePopup仍含显名目标/字号；世界文字renderer不等于已有目标箭头能力。具体[复用边界](../功能介绍/附近目标探测与高亮功能行为合同.md#6-r-复用对照)与[旧成本/失效](../功能介绍/附近目标探测与高亮功能行为合同.md#4-查询范围完整对象与失效)为V0；本批R实施另见下节，不倒填旧版可用性。

## R：附近发现范围也要覆盖可见箭头

#59沿既有单个Game层接入五项三箭头，窄StyleTarget让三显名保留字号、五目标仅有颜色，继续共用草稿/输入/偏好机械保护。显示几何从完整2×2对象与当前显示边界推导，浮动后重算指向，位置和方向一起倒重力变换，UI缩放不重复作用。共有一份自有箭头纹理和每Draw一次的基础时间计算，无目标/全部裁出不新建资源或推进观察。不同的转圈/浮动周期并不自动错开相邻物体；首包所有目标同相位，实测要求错开后，改由稳定原点/类别派生固定相位系数，与共用时间合成，不按列表下标、发现时刻或每件计时器计算。缩近与放大后不能仍拿旧外接圆留隙要求强迫半径增大；用完整外扩保护裁切，画面判断真实贴图与保守透明边界。[实现设计](../设计/附近目标探测与三箭头实现设计.md)

两个具体反例影响真正可见结果：一是相机亚格移动使floor/ceil附近宽度在相邻整数交替，若按宽度任意变化清游标，后排目标永久饥饿；应以真实屏幕尺寸/缩放revision重启。二是800px视口右侧x=52的睡眠龟，主体虽出屏但环绕时左箭头仍有可见像素；只给2格扫描余量会提前丢标。观察/保留区须覆盖最大绘制外扩（首包88世界像素；后续箭头放大/浮动调整后为92），完整性四格读取和逐件绘制裁切仍分别负责。两项均有先失败后窄修的领域/实际Host适配夹具证据。

缓存每更新清内容、退出清候选和进度，不等于容器容量立即释放；本批保留512×512附近上限内的有界峰值。生命果风摆含原版WindForVisuals，有限静态核验不能给出全状态最大偏移。首包XNA设备数0是在GraphicsDevice创建前失败，当时未生成/查看动画帧；本次实测调整环境可用，实际XNA绘制与选定原版静止图像的多时刻预览已完成并查看。原始纹理尺寸与世界保守显示边界分别承担取图/几何职责，预览不能把36×38边界直接当成38×36龙蛋图像的源矩形。数学、隔离预览和Host通过不升级为实际游戏顺滑、材质、多人与FPS结论。

## R：复核通过不等于排序数据变化

#63 世界文字的 Discovery 在 Update 内先复制已有对象复核，再扫描，最后复制输出；扫描同一多格物体也会重复 Offer。若 Selection 对已有 key 无条件 Repair/dirty，稳定几何会每次触发完整有序副本刷新。修复在唯一选择 owner 比较 `WorldObject` 全部六字段，保留已有 dirty；不能只比较距离/排序器，因为同址类型、样式变更仍要更新输出载荷。正文不在该值中，原取文和排版失效继续负责名称、正文、字体/字号变化。

`ObjectDiscoveryChecks` 的完整 Update 反例、`ObjectRulesChecks` 的有序读取/未消费 dirty 反例，以及 `NativeWorldTextProbe -Scope SelectionCpuChecks` 的真实源→准备包和独立 built Host 组合分别验证这一边界。420 件稳定夹具预热后600次更新的 Sort/Repair 从1800/362018降至0/0，格读取与取文量不变；移动仍保留真实重新排序。计数只在 DEBUG 编译，Release 不含观察字段/调用；CPU固定字形和局部计时不证明 GPU外观、FPS或全部性能问题。具体输入、对照和未验范围见[实现设计](../设计/宝箱牌子与墓碑显示实现设计.md#对象发现与选择)。

## 背景墙应由真实世界层承担遮挡

旧墙 ghost 连续尝试过裁掉前景覆盖格、减淡颜色、移动 UI pass，仍出现墙不完整或盖住人物/家具。后续证据区分了：已放置投影与摆放预览是两个入口；修完前者不代表后者已修。即使墙进入正确 world layer，late overlay 的整格 range 填充仍能再次盖住前景。有效方向是保留完整墙目标/材料数据，让墙在世界背景层绘制，并去掉会重复遮挡的墙模板范围填充；不是剪掉期望墙格来伪装修复。

来源：`排查复盘/蓝图墙ghost生命周期底层修复-2606291136.md`、`蓝图摆放预览墙层漏修-2606291453.md`、`蓝图摆放预览range填充盖前景-2606291732.md`，及该目录较早四篇墙 ghost 复盘。较早口径已被后续失败限定，不继续当正确方案。

## R 连续方向、短通知与字体恢复

#77 将稀有箭头位置和旋转同时放到最终物理视口核验，Game逆变换只负责层输入；近距离还需缩小图形长度，仅把圆心偏移减半仍会让尖端越过目标。小视口的字框可以夹边或移到箭头上方，箭头不能跟着夹成方形轨迹。

装备提示有独立3.25秒寿命，局部占用只读原版PopupText/CombatText的有限池。原版position不是中心：先加未缩放半文字尺寸，再施加旋转/缩放，倒重力镜像顺序也要遵守实际Draw。普通字体主体的几何验证不代表全部逐字符特效/极密文字无重叠。失败测量不能先提交缓存命中键，显式恢复需让相同字体和文本重新度量。

加载链夹具也要遵守资源时序：无纹理CPU字体切到GPU batch后，先经真实Update准备再Draw；图形夹具释放后，后续绘制故障注入必须恢复成套资源，否则既可能假红，也可能因Draw早退根本未注入。源码与有限原资源预览见[实现设计](../设计/方向指引装备提示与游商测试实现设计.md)及[#77](https://github.com/Kuroneko2020/JueMingR/issues/77)，实机、多人与FPS另行区分。

## DisplayDoll：黑像素与空纹理需要不同证据

旧 0.1121 实机失败后，0.1123 记录女假人朝右样本中 **728 个非透明像素的 RGB 全为 0**；相同 alpha/形状的 fullbright 对照恢复 RGB，支持该样本源 Lighting 导致黑色。另一个现象是 backbuffer 变化后目标仍未 Dispose、尺寸仍 48×64，却 `IsContentLost=true` 且非透明像素为 0。对象存在、尺寸正确和句柄活着不能证明内容有效。

后续历史修复将中性源颜色与最终 ghost alpha 分开；源图不重复施加阴影/透明度，最终绘制只承担一次透明度。缓存的外观 key 与图形设备/世界 generation 有效性不同；内容丢失或资源重建后旧纹理不得继续算成功。不能靠全局改 `Main.gameMenu` 暂时“变亮”，也不能在正常 Draw 中增加 GPU readback。

来源：`排查复盘/蓝图DisplayDoll-0.1121实机失败事实冻结-2607100926.md`、`蓝图DisplayDoll-0.1123实机像素与content-loss根因确认-2607101506.md`、`蓝图DisplayDoll-0.1125中性离屏颜色职责-2607101713.md`、`蓝图DisplayDoll-0.1127图形资源生命周期职责-2607101846.md`；`Terraria原版参考笔记/RenderTarget内容丢失与重建生命周期-2607101846.md`。0.1132 总复盘记载所有者对位置、方向、透明度、resize/UI scale 的样本反馈，不能反证早期包已正确，也不能外推所有外观组合。

## 图形状态恢复必须覆盖失败分支

离屏绘制借用 render target、viewport、SpriteBatch、screenPosition、shader 等状态时，要明确谁借用、谁恢复、何时失效。一项清理抛异常不应阻止其余恢复；失败生成不能缓存为成功。真实原版 DrawPlayer 会读取自身管线状态，伪世界公式与纯 helper 测试不等于该调用上下文。后续查证应固定身份与场景，先保留失败源图，再用不污染生产的对照辨别；[假绿辨别](行为验证与假绿辨别.md)说明证据边界。

## 完整数据、可见裁剪与滚动各自负责什么

大模板按固定前缀 512/1536/2048 截断，可能让排列较后的屏内内容永不绘制。完整有效模型与按视口裁剪不同，不能把截断模型称为优化且默认无行为损失。特殊实体的代表格 16×16 也不是 sprite bounds，外层和内层裁剪都必须保留仍可见的整件图像；后处理只缺油漆等状态时，主体存在就不再叠一层假人虚影。

UI 标题滚出视口只应跳过标题，不能提前返回整个子菜单；modal 阻挡了滚轮不代表正文能滚，正文要有自己的 viewport、content height 与 offset，标题/关闭按钮固定。来源：`蓝图大模板固定前缀截断-2607011916.md`、`蓝图DisplayDoll外层代表格裁剪与实体bounds不可混同-2607102137.md`、`蓝图后处理主体虚影误叠特殊实体-2607081808.md`、`蓝图子菜单标题滚动早退-2607012117.md`、`蓝图材料弹层只阻断不滚动-2607012337.md`（均在旧 `排查复盘/`）。这些是行为和成本形态证据，不证明 FPS 收益。

## R：无新输入采样不等于无可呈现内容

#77 实测后的闪烁定位核到原版1.4.5.8：FrameSkip.Off 且无 CameraLock 时，外层Main.Update可能调用了提前返回的DoUpdate，随后仍Draw。R的BeginUpdate正确清掉本次动作采样许可；错误在于Guidance和F5名称说明把CanStartActions/CanUseInput继续当呈现门，因而整段交替隐藏。只读文字改用已有焦点/重激活隔离资格，动作许可仍必须当次完成采样，不能缓存旧true或跳过整个Runtime。

单帧图形和恒定输入夹具抓不到此问题。回归需实际混合“完整采样、只有外层Update、Draw”，同时检查输出连续与无采样禁止动作。图形逐像素比较需冻结该专用夹具的通知时钟，否则慢GPU读回跨过3秒会把正常淡出误报为闪烁；时钟合同另有受控测试。原版UI scale与Game zoom也不可混用，最终字形和四向黑边需一起核对。用户实际跳帧设置仍未知，不能把RDP、1440p或显示器刷新率当已证原因。实现及证据边界见[本批设计](../设计/方向指引装备提示与游商测试实现设计.md)。

## 原版浮字对象复用与双绘制出口

“在头顶上方”只有方向，没有距离约束。#101 初版 `Top-24` 叠加原版半字框与自身上浮，比锁定 .8 重铸 `Center` 起点额外高出45世界像素（42高玩家）。仅断言字框在头上仍会通过。位置回归应与同文字、字体、相机、帧龄下的真实原版重铸浮字比较；分开空池运行避免互相碰撞，不执行重铸业务。倒重力 Draw 的镜像顺序另行核对，不能直接照抄正向偏移；隔离像素检查仍不能替代所有者实际游戏体验。

#101 对锁定 .8 的检查确认：PopupText.NewText 满池会选已有槽，ResetText 复用对象，ClearAll 更换池项；因此仅对象引用或文本内容相同不能证明所有权。窄适配先检查空槽，每次申请分配独立字符串令牌，同时验证数组槽／对象／Advanced语义／name与displayText引用，清理仅触及自己的项。后备显示不抢原版槽、不重放业务。

普通 GameInterfaceLayer 回调已有 UI SpriteBatch，地图 FullscreenMapDrawing.Overlay 没有开放 batch；分别采用逆UI变换借用和短 Begin/End 并恢复设备状态。地图跳过普通F5层，不能只给DrawInterface增加提示就声称全屏地图可见。真实XNB／原版浮字像素与CPU布局证据分开，首次引导仍需原有Draw回执。实现入口见[本地短提示设计](../设计/本地短提示与快捷键反馈实现设计.md)；任务分支未自动取得产品接受。
