# 工具、捕捉与矿脉的原版调用边界

这是 G09 在固定 Terraria 1.4.5.8 上的实现与隔离验证经验，配套知识已随三项能力、各轮修复及性能检查获所有者接受，随 [PR #106](https://github.com/Kuroneko2020/JueMingR/pull/106) 合并进入 `main` 生效。候选、人工体验、后续工程验证与保留安装的不同身份查 [#105](https://github.com/Kuroneko2020/JueMingR/issues/105)。不替代[行为合同](../功能介绍/工具与自动采集行为合同.md)或[实现设计](../设计/工具与自动采集实现设计.md)，不证明真实多人、长期运行或 FPS；本次收口不追加人工复测或重跑产品检查。

- **临时选物不是人工换物。** `.8 SelectedItemState` 是公开值类型。原版 OverrideSelection/自动归还与用户 Select 要区分；QuickItems、Extraction 主动结束时的受控 Select 也不应取消矿脉。真正的人工同槽选择仍代表新意图。入口为 `ToolHooks`、`HostItems.ReturnSelection`，借网保留矿脉的反例在 `NativeToolsChecks`。
- **虫网范围来自挥动帧。** 普通网/金网/防熔岩网不应按库存 24×28 计算，也不能按目标方位凭空改变预测朝向。原版 StartActualUse 后先减动画，捕捉帧是 max-1 至 1。`NetGeometry` 在隔离 Player 上复用有限原版几何；`NativeCaptureChecks` 用实际 XNB 和真正 Player 几何独立核对左右、重力、手套及三网实际 ItemCheck/CatchCritters。
- **免费复种与补种是两个出口。** 再生工具对本批两底座×七品种正常免费复种；液体可让 PlaceAlch 拒绝，留下真实已收空位。暂时虚化或不可读不等于底座被替换。`HerbHarvest` 保留 48/600 有限机会，`NativeHerbChecks` 覆盖无种子即时复种和积水后晚到种子的真实单次消耗。
- **只读“可产生进度”不能试挖。** `PickTile_DetermineDamage` 和 `HasEnoughPickPowerToHurtTile` 会写 hitTile。`MiningEligibility` 仅在严格 37 类型过滤后用原版只读可达分支；低于一次破坏的正伤害仍可绿。新增支持材料须重核原版副作用，不只改数组。
- **正伤害不等于整区轮换能完成。** 原版 HitTile 只有有限累计缓存。30 格低镐力原版回归曾复现每格都打但永不挖掉；保持当前有效目标至消失或受阻才换格。展示架 470/帽架 475 下支撑还需 `CheckTileBreakability`；NPC 101 也可自然锚定魔矿 22，需读取 `FixExploitManEaters.SpotProtected`。单独 `CanKillTile` 与伤害为正不足以判绿。
- **泥沙会在 PickTile 返回前整列变空。** 原版递归 SquareTileFrame 生成下落弹幕，首击后再扫描会漏掉原选区。仅为真实手工重力命中预存候选，成功后接管；已证实腾空的旧选中位置允许落回，未知/未腾空旧格仍排除。`NativeMiningChecks` 对 123/224 运行真实 Projectile.Update、碰撞及 Kill/PlaceTile，检查实际落地 Tile 与选区。
- **借工具不能让原装备被后台处理。** 受控换物暂时失去原版“当前手持”保护，需有限保护原 Item；鱼竿保护还跨越网动画与恢复决定。保护只进自动处理观察，不拦人工拿走。补种保护与 Pending 一样采用保留意图，不能在可靠保存 Busy 期间突然释放。
- **Player.PickTile 不一定是玩家持镐造成。** 宠物弹幕也会借 owner 调用该方法。首挖观察需位于真实 `ItemCheck_UseMiningTools_ActuallyUseMiningTool` 的玩家、实物及坐标作用域；本功能合成后续挖掘不能递归选脉。普通钻头和激光钻头的实际镐击仍在该 Player 链中，StartActualUse 的 toolTime=1 允许首帧正常镐击。
- **钻头 AI 在 ItemCheck 之后读瞄准。** 限定本次使用真正生成的 projectile 对象及完整 key，再为它的 AI 借用提交目标并在 postfix/finalizer 归还；不能按 owner/type 接管已有弹幕。真实矿点和显示朝向应一起测试，不能只测 PickTile 已执行。
- **切网本身就可能结束鱼漂。** 真正 `AI_061_FishingBobber` 检查当前手持鱼竿，无需挥网成功就会 Kill。有效借用前拒绝已主动收回的漂；归还后任何本机漂仍在便零补抛。`FishingBorrow` 的 token 和单调终态隔离晚回调；Started 不等于看到新漂，未知不释放同次重试许可。当前合成协作者测试只是 G10 的接入契约证据。
- **UI 所有权要到达实际消费端。** 新弹层同时接 ClaimsPopupPointer、输入尾部、滚轮、关闭/失焦和提示路由；不能因底页被 BlockPointer 就把弹层自身提示一并关掉。布局/字体变化先撤销按下状态，Draw 消费缓存控件。`NativeToolsUiChecks`、`NativeToolsVisualChecks` 使用实际 Host 与原版资源，不依赖玩家配置。

开发期间的实测反馈纠正了首版的以下错误选择；具体候选身份及执行记录仍查 #105：

- **一次最终成功不足以证明连续节奏。** 原版免费采草可每更新推进一株；首版每株整动画归还，把八株拖成 176／183 更新。`NativeToolCadenceChecks` 用相同可达布局和真实 ItemCheck 对照，修复后两工具手持／借用均与原版八更新相同。30 格矿脉同时覆盖蘑菇爪、铜镐、钻头和复合工具，比较每个效果更新及首次延迟，不改原版计时。
- **静态包络正确不等于动态时机正确。** `NativeCaptureTimingChecks` 的控制轨迹涵盖进入相位、离开、跨身、跳跃、反向、玩家脚本追近、左右和重力；另有真正 NPC.UpdateNPC 平地／障碍运动。参考枚举合法单次启动时机，自动链保留原版命中。受控轨迹不冒充任意 AI 预测，玩家脚本移动不冒充完整玩家碰撞实机。
- **一次 token 的唯一恢复仍可能形成多 token 抖动。** `NativeFishingBorrowChecks.Misses` 使用相位间的受控非线性跳动制造真正漏捕，保留原版 Catch、浮标 AI、借网和补抛；普通／有自动竞争两臂均须有限结束，不能只直接调用 Prepare/NetFinished。离开再入及运动转静止仍可捕，最后实际挥动的运动事实不能被归还时的静止覆盖；未知与人工取消不能当普通 miss。自动让位也须保留尝试记录。
- **Ready 必须是真需求且无调度副作用。** 仅检查三项 Enabled 会让提炼长期空让；把原物借用保护照搬到交接前 Ready，又会让唯一原手持材料永远“不就绪”。最终使用仍全量准入，只在观察交接需求时排除本次归还可解除的那一层保护。持续合法采草竞争夹具维持外部成熟，证明提炼首次接手及随后交回的原版边界；它不用于证明自然生长速度。
- **工作量数要落在真实消费者。** 几何检查累计 ApplyUseStyle/GetMeleeHitbox/纹理帧读取；跨更新相同条件只建三个阶段。Boss 同代次聚合只遍历一次。稳定 512 格对照同时计深层资格和 ReadCurrent，不能只报 Draw 零扫描。还须经过真正 SelectedItemState/ItemCheck 检查全红等待矿区和收完的幼苗田；纯 Runtime 或完全空田会漏掉选择入口的全扫及闭包。空田分批发现后还验证新植物真实收获延迟、移位、失去工具及关闭；完成空矿区保持开关且停止读世界。
- **绑定存在与绑定可发现是两件事。** 原先两个独立图标的注册／双击链正常，所有者进一步明确要求选脉框紧邻“快捷键”。现在按该决定呈现绑定值，行尾保留主开关键及原第二行选区入口；真实 F5 滚轮、录入、保存、新进程重载分别验证。动态绑定文字不得塞入永久固定文案缓存。150% 要先更新真实屏幕尺寸再请求比例，并断言原版没有将比例钳低；截图批次也须使用真实 UI 矩阵。

原版源码的精选位置与身份转查[本地资料说明](../设计/本地参考资料使用说明.md)。永久只读 Legacy 是行为证据，既有缺陷不成为本轮必须恢复的语义。局部测试红/绿、正规构建、独立审查、完整包和实际安装各有不同证明范围。

## 完整玩家更新揭示的执行边界

上述 `NativeFrame` 节奏与动态动物检查仍是窄链证据：真实 NPC AI 不补足玩家侧省略的 `Player.Update` / `ItemCheckWrapped`，直接 `Mining.Select` 也不验证自动首挖。`NativeToolExecutionChecks` 保留完整玩家更新、原版选槽和计时、真实镐击／采收／Catch；实际自动模式由物理首挖后松开进入，鼠标在远处且使用非零相机与缩放。只隔离成就、网络及末端粒子出口；图形模式使用三网真实 XNB、兔子 AI 和实际捕获物。合成 Host 不是日常游戏或多人验收。

- **外层更新不保证有输入样本。** 固定 .8 `Main.Update` 调用的 `DoUpdate` 在部分帧跳设置和不足一个游戏更新的累积时间下，会在 `HandleInput` 前返回；R 的外层 prefix/postfix 仍执行。原 `ToolUse.Update` 用本轮执行准入判断既有租约寿命，导致无样本更新取消连续使用；下一真实帧动画仍走，Catch 却被取消身份挡住，采草／挖矿也等下一整段动画。旧安装候选在该序列下直接复现三项退化。保留意图与批准新消费必须分开，危险、界面和会话撤销仍同时有效；G10 后台修订沿共享自动准入，失焦不再默认取消自动意图，但空外层更新仍不能执行消费者，物理输入与回焦隔离继续有效。
- **同手持工具接管不等于换槽。** 自动首挖之后，松开时若仍在同一工具动画，等待 `CanChangeSelectedItemImmediately` 会额外丢失下一次合法镐击。现有 Sync 接缝在无人工按住、buffer／override／本帧手选且同来源准入有效时，取得普通路径共用的唯一租约；不改槽、不重置计时。新按下立即交回人工，共享物品占用仍能拒绝取得租约。
- **智能光标差异要有实际因果。** 本次完整链同时覆盖开／关，首个分歧在无样本外层更新后的租约取消；`UsingSmartCursorWithContinuity` 的平台连续锁不能推定为再生工具问题。未因此添加鼠标坐标回写、全局抑制、额外 Hook、转向补丁或速度常量。
- **完整更新会真实拾取掉落。** 免费复种的用例应从无种子开始、观察实际再生工具与幼苗结果。不能要求全过程背包永远无种子：完整玩家更新自然捡到本次采收掉落，不代表用了种子后备。

## 修复后检查的有效性

原检查补强从干净 `d4cc715` 修复源码继续；历史问题候选是 `387d4b9`，不能将其漏检直接归给当前实现。此前已建立跨更新三阶段几何、原版连续节奏、动态捕捉与有界矿区/药田工作检查，补强保留并补足实际调用链及反例。各轮执行、负对照和审查记录查 #105，本次文档最终化不改变这些证据的来源或覆盖范围。

- **同 tick 的空间对照不能证明跨 tick 复用。** `NativeCaptureChecks` 保留推进更新的静态候选，并让依赖变化后的网格也持续推进更新，同时核对独立原版结果和重建次数。普通虫网不是 melee，单开手套不改变有效尺度；测试必须分别覆盖无效变化复用和有效尺度失效，不能将错误测试假设写成产品合同。
- **只测 Draw 会漏掉 Update；只有深查数也会漏掉额外读取。** `NativeToolsCacheChecks` 与 `NativeToolsWorkloadChecks` 从真正 Host 挂接 `ReadCurrent`/`CanProgress`，正样本先证明观测有效，再对成员读取、局部 witness 和有界深查分别计预算。不能把必要的成员存在性、执行前复核或有界未知责任当作应全部清零的缺陷。
- **关闭零计数不覆盖开启空闲。** 空药田、幼苗田、没工具、没种子各有不同责任。`NativeToolsCacheChecks` 统计开启空田的实际读取与变化后回稳，`NativeHerbChecks` 计缺种等待的真实背包槽访问并保留晚到种子的真实消耗；`NativeToolCadenceChecks` 在实际自然收完后继续推进原版时序，核对临时用物退休及剩余探索责任。
- **有界不等于必要，调用次数不等于实际工作。** `NativeCaptureWorkloadChecks.Observation` 在真实漏捕/借网/回竿场景里观察 Boss 内部 NPC 槽访问，分别计底层事实和聚合遍历，证明捕捉有效性与钓鱼消费者真正到场。CPU 反例还直接检验生产 `BeginActions` / post-NPC 接线，不能靠测试手动刷新掩盖遗漏。
- **绿灯只表明当前期待成立。** 本轮在忽略目录保留有限错误机制实验：实际恢复重复工作或遗漏失效，要求指定断言红，再精确恢复源码重建验绿；没有用 throw 或伪计数替代领域反例。普通路由和 build 失败门另行验证。它不建立每次提交运行全仓突变测试的义务，也不把上一候选安装改标为本轮提交。

- **输入机会和模拟机会也不等价。** .8 在 HandleInput 后仍可能因暂停／加载／stepper 跳过世界；核对 GameUpdateCount 的唯一普通递增、加载重置与快照恢复后，才将 Tools 有限等待接到世界阶段入口。这里只保留 600／135／300 的原窗口；共享 tick、动作授权和未知保护不变。真实阶段夹具须自己提供入口计数，不能只给新字段命名便称为真实时间。
- **单位置预算不能外推到整队列。** 旧算法在 48 缺种位置一次选择读 2400 槽；相同观察三次 Ready＋Choose 合计 14400。局部七品种位图复用发现后，此缺种组合降至 50；真实候选的保护／数量／位置仍需逐次复核，不能泛称所有种植只读 50 次。缓存失效与未知保护退休是两件事。
- **负对照自身必须存在。** 原版砂类缺支撑会立即转成弹幕；检查过期后拒绝新格前，先证明它是实存稳定方块。多位置补种的花盆也须原版合法承托，否则看到库存减少并不代表幼苗保持存在。旧安装接受、当前自动结果和未验证的多人／长期／FPS范围分别记录。
