# 信息地图与持久状态

本页主要为 Legacy 历史知识；R 当前群系与两份配置说明见[当前功能](../功能介绍/当前群系显示与F5配置.md)。旧记录路径和数值不是 R schema 或性能预算。

## 观察对象决定群系和位置标签含义

`Player.Zone*` 描述那个玩家的本地场景，不能当作远处旅商/NPC 的群系。旧 .6 笔记未发现名为 ZoneAether/Oasis/Spider/Town 的对应字段，存在 ZoneShimmer 也不意味着所有名称可直接猜字段。场景、购物区域和城镇聚类要分别解释。旅商位置标签从 pylon、townCluster、pointBiome 到 unknown 有不同证据强度，低置信的“附近”不能写成确定城镇。

稀有生物方向旧记录限定生命体分析仪能力、hideInfo[11]、客户端活动且 rarity>0 的候选，再按 rarity/距离择一；1300px 与 15 tick 是当时版本的范围/节奏，不是 R 通用值。来源：`Terraria原版参考笔记/Information_Biome_notes.md`、`Map_Direction_Hints_notes.md`。

## 地图跳转、轨迹与可视范围

大地图 `mapFullscreenPos` 是地图中心相关 tile 坐标，实际绘制变换还含缩放、偏移与图标定位；不能拿手写 screen center 公式同时当绘制和命中 oracle。视图跳转改变地图中心，不是传送玩家。用 `MagicPixel` 画细线时须核对原纹理（旧版本 1×1000）与 1×1 源矩形，不能把整张源高误当单位像素。

足迹复盘中，裁剪跳点却不推进待连接起点会产生跨空白放射线；暂停回看时仍用增长的 latest 作分母会把滑块挤向左；旧→新硬截断会饿死新路线。LOD 代表点连成的弦不一定是原始相邻边，不能在弦上插值并声称玩家走过那条路。应保存断段、原始边关系与展示时间轴语义，再对可见裁剪和预算作限定结论。

来源：`Terraria原版参考笔记/Map_UI_notes.md`、`排查复盘/足迹播放与绘制坐标复盘-2606170816.md`及旧功能介绍 `地图加强页/足迹.md`。后者较晚记录了显示关闭仍记录、暂停冻结显示末端、默认最新端等行为，见[功能参考](../功能介绍/Legacy地图与足迹.md)；本轮未复测视觉或 GPU 成本。

## 数据归属不能由 UI 开关或短期 token 推导

Legacy 笔记是全局用户笔记；地图死亡、天数、探索摘要、足迹和标记按玩家-世界 pair 存储。足迹展示开关和死亡点显示开关不控制记录，也不删除历史。世界天数是开始观察后的游戏时钟累计，不是现实游玩时长或世界历史年龄。身份失败不写 unknown 共享桶；进程对象 token 可合法为非零负值，与可持久玩家 key 的验证是不同合同。

首次进入世界提示的历史服务 seam 只证明 marker 返回 false 会重试；旧 store 吞 durable save 异常时，不能把“API 返回成功”解释成磁盘提交已可观察。后台保存应在入队时明确数据根/身份、隔离测试路径，并等实际 worker 生命周期结束，不能 stop 调用返回就删除测试目录。

来源：旧功能介绍 `F5通用/笔记页.md`、`更多信息页/首次进入世界提示.md`、`地图加强页/世界天数.md`、`死亡点常驻.md`；`协作方法/临时测量Owner退役与测试进程隔离-2608280231.md`。后续 R 存储选择仍依[配置设计](../设计/配置持久化与用户数据布局.md)区分现行 A 与未来 B，不把旧目录直接搬入新版。

## 读失败降为空值可能被无关编辑写回

Legacy 笔记专项静态查证发现：正文缺失或读取异常被当作空正文成功加载；编辑标题又把缓存正文一并保存，存在“正文暂时读错 → 只改标题 → 空正文覆盖原文件”的代码路径。读取失败、真实空内容和缺文件必须区别对待，不能因为页面需要一个字符串就消除内容可信度。这里是静态风险链，未运行复现或证明真实用户事故。

同链路还显示，先写正文再写索引的补偿回滚会吞回滚异常并清理备份，不能称为跨文件崩溃安全；store 成功后 cache 忽略刷新失败，又可能让磁盘已更新而界面仍旧。审查用户创作内容时应分别查提交、补偿、重载和展示，不能只看一个返回成功，或只看注入一次写失败后成功回滚的测试。

来源绑定 Legacy `6ac6356c0c564f43284590c168855e96c50e13f7`：`UserNotesStore.TryLoadSnapshot/CommitBodyAndIndex/RollbackCommitted`、`UserNotesUiState.SaveActiveEditor`、`UserNotesCache` 的成功后刷新。准确路径、行段及测试缺口见[笔记候选 NOTE-23～25 与证据 E08/E23/E24](../功能介绍/笔记功能行为合同.md#note-23加载异常孤立文件和未知版本b事故发生-c)。R 的不静默覆盖内容原则已有效；这不授权照搬旧存储、增加通用框架或开始实现。

## R 笔记的完整提交与保护机制

#42 使用单份完整 JSON 消除正文/索引跨文件部分提交，复用机械文件层而保留独立的内容命令语义。`File.Replace` 后核验失败时，正式路径可能已经变化，必须把“提交未确认”传至 worker 和 UI，停写且保留实际 `.bak`，不能按普通未提交失败重试轮换备份。缺正式文件但有精确恢复材料也不应创建空列表覆盖。

`JsonReaderWriterFactory` 把首字段 `__type` 映射成 XML 属性；只查 XElement 子元素的字段白名单会漏掉它。严格未知字段保护需要同时核对属性。树物化前还需按节点与深度拒绝大量极小对象，输出按实际字节限制扩容，不能把流式 reader 的 MaxArrayLength 当作任意 XElement 树的总上界。源码入口为 `NotebookCodec` / `AtomicFileDocument`，反例在 `ArchitectureTests/Notes`，只使用隔离数据。

不可变内容索引也有成本：普通单 UTF-16 单位文本应使用隐式边界，位置操作复用验证结果；否则大文档多个快照会复制大量相同索引。长文排版既要限制单位工作，也要保证可见任务最终得到预算；反复丢弃离屏短预览会造成稳定饥饿。真实范围与资源护栏以[笔记设计](../设计/笔记功能实现设计.md)为准，局部时长不是 FPS 结论。
