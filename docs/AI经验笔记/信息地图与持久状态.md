# 信息地图与持久状态

## R #63：开过事实与异步所有权独立于显示

开过位置不能挂在共享 Draw 或其它显名开关上。当前正常开箱观察只比少量标量，首次实际事实/Opened 才取得身份和加载；持有同箱不每帧构造路径摘要，重复位置不递增保存修订。角色文件定位＋世界 GUID 有明确局限，未知身份只暂存本会话，迟到身份只合并该会话新事实。[实现设计](../设计/宝箱牌子与墓碑显示实现设计.md#开过位置与持久化)

有限列表预算与冻结会话索引预算是不同资源：首次写失败后，即使重试列表已包含全部坐标，仍必须保留失败重试状态及索引所有权；成功提交后退役实际覆盖的段，否则8段限额会逐次泄漏。`OpenedPositionChecks.DeferredRetryRetiresOverlay` 使用真实原子文件和第65位置失败反例；`OpenedFailureChecks` 验证 pair A 失败、B 恢复不能吞掉 A 的未领通知，未来版本/损坏/未确认提交的原件与备份逐字节保留。容量拒绝按一次阻塞阶段提醒，不能每 Poll 重新排队。测试不代表强退前待写事实已保存。

## R #55：普通偏好的内存意图与磁盘结果

颜色/字号确认后先更新当前意图，工作线程合并保存；未释放 HSL、未完整 HEX 仍只是编辑草稿。快照须持续携带底层 `CommitUnconfirmed/IsProtected/Error`，否则一次新的内存选择会抹掉“可能已替换但无法确认”的事实。旧 revision 完成不能将新意图标记为已保存，关窗/切目标也不取消已提交写入。功能模式记忆归设置 owner，快捷键仅调用委托，避免按钮与按键维护两份“上次模式”。对应 `PreferenceConcurrencyChecks`、`EntityPreferenceChecks` 与分别编译的 `EntityHostChecks`；不读取日常用户文件制造证据。

本页分别记录 Legacy 历史知识与 R 笔记/配置的当前保护机制；R 群系与两份配置说明见[当前功能](../功能介绍/当前群系显示与F5配置.md)。旧记录路径和数值不是 R schema 或性能预算。

## R：未知字段也可能藏在 JSON 桥接属性中

.NET JSON reader 会把对象首字段 `__type` 转成 XML 属性。只检查子元素可误收未知格式，再在保存时丢掉字段。Notes 的 `NotebookCodec` 已有属性检查，#46 复盘却发现两份偏好的 `PreferenceJson` 漏了同因保护；现统一在该解码器检查根与全部后代属性，额外属性归 `UnknownFields`，不改配置版本或持久化算法。`PreferenceChecks.BridgeAttributes` 覆盖群系根、UI 根、windowPosition 内部，并用隔离真实文件验证内存仍可选、原件与已有备份保持。Items codec 已有对应检查与回归，不能把同因风险自动认定为每个模块都有缺陷。Notes 专用的节点/大文档限制也不直接套给 64 KiB 配置。

## Legacy 显名：索引缓存、正常命令与显示副作用

旧三个显名确实消费同一对象集合和标签服务，但NPC名字、动物资格、敌怪分段生命是不同规则。标签缓存的索引/类型与12Tick检查、名字缓存的24Tick绝对到期值都没有完整会话身份；同槽同型替换、时间回退或语言改变可能留下旧内容，不能把“每次检查active”当成身份保证。这是源码风险，未证明旧用户已经遇到串名。观察拥有者应表达有效性/新鲜度，业务各自决定内容；未来其它真实观察需求不应依赖某显示开关，亦不授权现在建设全实体平台。

NPC的UI写模式与热键开关是两条命令，只有热键从非关闭转关闭时写“上次模式”；按钮选类型再关不能保证热键恢复类型，首次缺历史还可能拒绝开启。新功能应复用R公共命令与可靠绑定保存，不照搬独立热键服务。样式/开关的SaveAll返回值被忽略，新内存值生效不能称为已存盘。配置面板共用控件也不意味着三份颜色/字号共用状态。

仅开三项之一已足以进入共享Draw的FullRecord、旧箱子键导入与开箱坐标持久化；“显示不改NPC”与“整个调用链无写操作”是两件可分别查证的事。后续本批候选建议去掉这项无关副作用，保留R偏好合并保存和用户内容保护的现有边界。完整因果、未运行测试、来源与验证候选见[显名合同](../功能介绍/敌怪动物与NPC显名功能行为合同.md#2-三条真实调用链与用户操作)第2、4、5、9节及Z04/Z06/Z08/Z09/Z15/Z16；不迁移旧箱子记录业务。

## Legacy 箱子历史与正文缓存：身份和显示开关分责

旧箱子记录的实际消费者使用 FullRecord 生成的角色×世界键，优先原版file data路径，缺失才回退角色名/世界名#数字ID；不可用另一个未调用的identity resolver为其背书。记录入口挂在共享Draw，宝箱关着但其它世界显示开仍可登记/导入，全关反而漏记。新坐标在渲染调用里同步存整份文件，失败可仍返回added，重复同坐标不重试；导入移旧键与写新文件没有事务。[新版已确认合同](../功能介绍/宝箱牌子与墓碑显示功能行为合同.md#73-开过的位置独立观察身份与持久确认)要求独立轻量观察开过坐标、可靠pair/未知身份会话降级、加载合并及后台持久确认；显示不承担导入/保存，旧数据不迁移。旧实际文件链仍见第3.3/5/6节及Z02/Z05/Z07，需求确认不是持久化已实现。

牌子/墓碑候选只用tick缓存，命中复核tile却不重新读正文/世界身份；“坐标仍有效”不保证还是原来的字。布局缓存另按文字/字体/模式缓存，UTF-16截取可切坏字符，最终ChatManager仍可能解析标签。候选、正文布局和实际绘制应分别计成本；旧“只缓存文字、不缓存坐标”说明与代码不符。见同合同第4/5节、Z08–Z10/V8-05；这些是静态缺口，没有运行或性能改善结论。

## 观察对象决定群系和位置标签含义

`Player.Zone*` 描述那个玩家的本地场景，不能当作远处旅商/NPC 的群系。旧 .6 笔记未发现名为 ZoneAether/Oasis/Spider/Town 的对应字段，存在 ZoneShimmer 也不意味着所有名称可直接猜字段。场景、购物区域和城镇聚类要分别解释。旅商位置标签从 pylon、townCluster、pointBiome 到 unknown 有不同证据强度，低置信的“附近”不能写成确定城镇。

稀有生物方向旧记录限定生命体分析仪能力、hideInfo[11]、客户端活动且 rarity>0 的候选，再按 rarity/距离择一；1300px 与 15 tick 是当时版本的范围/节奏，不是 R 通用值。来源：`Terraria原版参考笔记/Information_Biome_notes.md`、`Map_Direction_Hints_notes.md`。

## 地图跳转、轨迹与可视范围

大地图 `mapFullscreenPos` 是地图中心相关 tile 坐标，实际绘制变换还含缩放、偏移与图标定位；不能拿手写 screen center 公式同时当绘制和命中 oracle。视图跳转改变地图中心，不是传送玩家。用 `MagicPixel` 画细线时须核对原纹理（旧版本 1×1000）与 1×1 源矩形，不能把整张源高误当单位像素。

足迹复盘中，裁剪跳点却不推进待连接起点会产生跨空白放射线；暂停回看时仍用增长的 latest 作分母会把滑块挤向左；旧→新硬截断会饿死新路线。LOD 代表点连成的弦不一定是原始相邻边，不能在弦上插值并声称玩家走过那条路。应保存断段、原始边关系与展示时间轴语义，再对可见裁剪和预算作限定结论。

来源：`Terraria原版参考笔记/Map_UI_notes.md`、`排查复盘/足迹播放与绘制坐标复盘-2606170816.md`及旧功能介绍 `地图加强页/足迹.md`。后者较晚记录了显示关闭仍记录、暂停冻结显示末端、默认最新端等行为，见[功能参考](../功能介绍/Legacy地图与足迹.md)；本轮未复测视觉或 GPU 成本。

## 数据归属不能由 UI 开关或短期 token 推导

Legacy 笔记是全局用户笔记；地图死亡、天数、探索摘要、足迹和标记按玩家-世界 pair 存储。足迹展示开关和死亡点显示开关不控制记录，也不删除历史。世界天数是开始观察后的游戏时钟累计，不是现实游玩时长或世界历史年龄。身份失败不写 unknown 共享桶；进程对象 token 可合法为非零负值，与可持久玩家 key 的验证是不同合同。

首次进入世界提示的历史服务 seam 只证明 marker 返回 false 会重试；旧 store 吞 durable save 异常时，不能把“API 返回成功”解释成磁盘提交已可观察。后台保存应在入队时明确数据根/身份、隔离测试路径，并等实际 worker 生命周期结束，不能 stop 调用返回就删除测试目录。

来源：旧功能介绍 `F5通用/笔记页.md`、`更多信息页/首次进入世界提示.md`、`地图加强页/世界天数.md`、`死亡点常驻.md`；`协作方法/临时测量Owner退役与测试进程隔离-2608280231.md`。后续 R 存储选择仍依[配置设计](../设计/配置持久化与用户数据布局.md)区分现行 A 与未来 B，不把旧目录直接搬入新版。

## 读失败降为空值可能被无关编辑写回

Legacy 笔记专项静态查证发现：正文缺失或读取异常被当作空正文成功加载；编辑标题又把缓存正文一并保存，存在“正文暂时读错 → 只改标题 → 空正文覆盖原文件”的代码路径。读取失败、真实空内容和缺文件必须区别对待，不能因为页面需要一个字符串就消除内容可信度。这里是静态风险链，未运行复现或证明真实用户事故。

同链路还显示，先写正文再写索引的补偿回滚会吞回滚异常并清理备份，不能称为跨文件崩溃安全；store 成功后 cache 忽略刷新失败，又可能让磁盘已更新而界面仍旧。审查用户创作内容时应分别查提交、补偿、重载和展示，不能只看一个返回成功，或只看注入一次写失败后成功回滚的测试。

来源绑定 Legacy `6ac6356c0c564f43284590c168855e96c50e13f7`：`UserNotesStore.TryLoadSnapshot/CommitBodyAndIndex/RollbackCommitted`、`UserNotesUiState.SaveActiveEditor`、`UserNotesCache` 的成功后刷新。准确路径、行段及测试缺口见[笔记候选 NOTE-23～25 与证据 E08/E23/E24](../功能介绍/笔记功能行为合同.md#note-23加载异常孤立文件和未知版本b事故发生-c)。R 的不静默覆盖内容原则已有效；这不授权照搬旧存储、增加通用框架或开始实现。

## R 笔记的完整提交与保护机制

保存后退出编辑不能只匹配文本 revision：输入法预览、候选和跨采样的半代理项尚未改变正文，也需要保留当前编辑所有者。`NotesInput` 在输入采样后让 `NotesWorkspace` 取消该编辑的旧后续 UI 动作，磁盘结果仍正常确认；标题规范化也不能改变正在组字的替换选区。`NotesPresentation.Request` 的保存、切页/主动关闭、新建、悬挂等依赖提交动作，在完成 IME 后仍有未决输入时暂不执行；普通 BeginEdit 字段切换继续清旧尾部，明确取消仍可丢弃。#46 的反例显示只保护 FinishEdit 会遗漏 Leave/Create。`NotesHostChecks` 覆盖同一 editor 保留、无导航/提交及低代理后续合成一次；这不等于真实 Windows IME 验收。

#42 使用单份完整 JSON 消除正文/索引跨文件部分提交，复用机械文件层而保留独立的内容命令语义。`File.Replace` 后核验失败时，正式路径可能已经变化，必须把“提交未确认”传至 worker 和 UI，停写且保留实际 `.bak`，不能按普通未提交失败重试轮换备份。缺正式文件但有精确恢复材料也不应创建空列表覆盖。

`JsonReaderWriterFactory` 把首字段 `__type` 映射成 XML 属性；只查 XElement 子元素的字段白名单会漏掉它。严格未知字段保护需要同时核对属性。树物化前还需按节点与深度拒绝大量极小对象，输出按实际字节限制扩容，不能把流式 reader 的 MaxArrayLength 当作任意 XElement 树的总上界。源码入口为 `NotebookCodec` / `AtomicFileDocument`，反例在 `ArchitectureTests/Notes`，只使用隔离数据。

不可变内容索引也有成本：普通单 UTF-16 单位文本应使用隐式边界，位置操作复用验证结果；否则大文档多个快照会复制大量相同索引。长文排版既要限制单位工作，也要保证可见任务最终得到预算；反复丢弃离屏短预览会造成稳定饥饿。真实范围与资源护栏以[笔记设计](../设计/笔记功能实现设计.md)为准，局部时长不是 FPS 结论。

阅读偏好合并的最长等待时间必须属于“尚未提交的这批意图”。如果提交期间的新滚轮继续继承已到期的首次时间，后续每次完成都会立即再写整本，合并会退化。`NotesFeature` 在已提交边界后重新起算新批次；普通正文保存优先，退出末次合并基于 worker 最后可靠成功的正文，而不是 UI 尚未领取的快照。悬挂身份随取消再挂更换，迟到的偏好不能复活旧值。这些反例及进行中的保存成功/失败、取消悬挂、删除后退出在隔离 `NotesConcurrencyChecks` 中覆盖。

旧 R 格式升级的原始材料须在首次替换前保留，且不能随普通 `.bak` 轮换。校验读取字节相同还不够：明确的档案路径若是指向正式文件的符号链接，程序自己的 Replace 就会让它改读新格式。`AtomicFileDocument` 只接受该精确路径上的普通文件，冲突时停写并保留原件；没有扩展成通用文件系统框架。真实满额 schema 1 升级、档案冲突与非普通目录路径在 `NotesRevisionChecks` 中使用合成数据验证，符号链接机制判断不能冒充现场用户目录发现。程序回退与数据回退仍须分别处理，不能自动拿旧正文覆盖后来内容。
