# 输入捕获与坐标域

本页整理 Legacy 历史机制与复盘，不移植其输入架构。当前 R F5 的坐标、失焦和释放合同见[F5 设计](../设计/F5控制界面样板与UI基础.md)与[配置设计](../设计/配置持久化与用户数据布局.md)。

## 可见几何与命中必须回答同一个位置问题

手持栏“画在屏幕底部但点不到”曾有两类不同原因：把 OS client 物理坐标除以 UI scale 后对物理目标命中；以及 prefix 看见旧 Terraria 鼠标，后置 PlayerInput 才刷新到真实位置。同一个错误公式被布局与测试同时使用，可以内部一致却整体错位。

应先明确目标属于 client 物理像素、UI logical 还是 world 域，并从绘制结果独立验证命中。鼠标缓存若跨前置/后置阶段共享一个“本帧有效”槽，会让刷新后的阶段仍读旧值。历史修复按阶段分槽；一次按下沿只可转交一次，后置重新命中同一对象和控件才执行，不能把正文点击升级成工具栏命令。R 并未因此获准新增 replay 框架。

来源：`排查复盘/手持栏可见但点不到输入门禁-2606211332.md`、`手持栏后置命令时序纠偏-2606211414.md`、`蓝图快捷栏UIScale逻辑屏幕误当物理目标-2606220418.md`；`协作方法/蓝图手持栏前后置鼠标读取缓存分槽-2606241055.md`。

## 消费世界点击不是物理松手，也不自动证明 UI 所有权

旧蓝图创建曾把 `LeftConsumed` 混作 hover/drag owner，或将消费后的 false 当成真实 release，造成选区误拦和拖动闪断。消费表示本帧不应再传给世界；是否仍按住、是否在 UI 上、谁持有拖动是不同事实。先确定实际捕获区域与物理边缘，释放只清自己的状态；失焦/关闭时用最后有效样本收尾，不用合成释放坐标保存位置。

同帧 prefix 的失败原因又曾被后置的正常空闲状态覆盖，导出只剩“没问题”。查证要记录触发点、消费点和诊断发布点的顺序，而非增加每帧日志。

来源：`排查复盘/蓝图创建选区被UI所有权误拦-2606221439.md`、`蓝图创建闪烁左键消费语义混淆-2606222308.md`、`蓝图创建诊断被后置输入覆盖-2606221924.md`。

## 原版读取和写入时机

`PlayerInput` 会在前置 Hook 后刷新鼠标；`ItemSlot` hover 可在 Draw 阶段才出现；早期清 MouseText 不一定清掉最终 `DrawPendingMouseText`。`IgnoreMouseInterface` 在旧版本是依赖使用/重用状态的 getter，不能当可写布尔字段。`MouseWorld` 涉及重力翻转；旧 .6 鼠标左右键存在不证明有 mouse4/mouse5 同名字段。IME 已提交文本与组合预览不同，`GetInputText`、WritingText、HandleIME 和输入框锚点需在同一编辑上下文核对。

来源：`Terraria原版参考笔记/UI_Input_notes.md`，查所选版本 `GameInput/PlayerInput.cs`、`UI/ItemSlot.cs`、`Main.cs` 的真实调用顺序。不要拿 UI.Update/Draw 都存在当作当前场景必被调用的证明。

## R 笔记对当前 .8 输入链的核对

来源为 #42 对锁定 Terraria 1.4.5.8 / ReLogic 编译输入的定向检查及 `NotesInput`/隔离 Host 测试，不升级上文 Legacy 证据。`DoUpdate_HandleInput` 内先由 PlayerInput 映射，再刷新 `Main.keyState`，且下一次 Update 的较早快捷键会读前次缓存；已消费原始键不能在 Update 后还原。`WritingText` 在原映射末尾会清零，prefix/postfix 的责任不同。

当前 `Main.HandleIME` / `SetIMEPanelAnchor` 为实例方法。停用 IME 可以先同步 FinalizeString 再返回，因此保存应仍绑定旧草稿领取尾字后才冻结，取消才丢弃；聊天等接管时不清他人队列/IME，却仍须归还自身 blockInput 租约。代理对可能跨 WM_CHAR 样本，半代理和延迟视觉导航要跟编辑对象身份一起失效，不能只比相同的 revision 数字。`.8 DrawIMEPanel` 内向上偏移 32 个 UI 逻辑单位，锚点必须先经过当前坐标换算，再处理这项已核实偏移，不能拿旧 .7 参考猜 API。

阅读调整要在编辑输入消费键盘前冻结同一份 Shift/Ctrl 样本；F5 与 Notes 还须同时检查当前 `MapFull` / `ToggleCameraMode` 请求。只检查后来才改变的地图/拍照状态，会在模式切换当帧仍让便签改偏好、消费滚轮。前置 IME 租约使用前置可用信息，后置仲裁使用刚采样的请求，不能混为同一个时刻。

操作反馈文字没变，不代表操作状态没变。例如编辑期间取消删除，仍须使动作快照失效，否则会残留取消删除按钮。绘制、命中、释放执行共用快照，并绑定按下时的目标、几何与代次。选区则归唯一编辑模型所有，绘制和命中只把原文边界投影到视觉行；一次拖选的释放不能再作为空白保存或另一按钮的释放。

来源为 #42 验收修订的实际接线审查与隔离反例（`NotesRevisionHostChecks`、`F5ConsumerChecks`）；执行状态以任务证据为准。合成输入检查能验证仲裁和失败保稿，不能证明真实 Windows IME 候选窗口、语言包或最终画面。长期行为和真实验收边界见[笔记设计](../设计/笔记功能实现设计.md)与 #42。

## R #46 的真实前台与激活手势核对

定向核对的 Terraria 1.4.5.8 `FocusHelper.UpdateFocus` 使用 `Main.instance.IsActive` 并在 Windows 上合并本应用 `Form.ActiveForm`，没有直接比较 OS 前台窗口；`AllowInputProcessing` 是仅返回字段的小 getter。因此“原版仍允许、实际已切到别的窗口”是应覆盖的反例，不能仅把相同字段再加到 F5 判断里。Windows 的 `GetForegroundWindow` 返回用户当前操作窗口，切换时可能为空；`GetActiveWindow` 属于调用线程，不能替代。来源：[Microsoft 前台窗口说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow)、[线程活动窗口说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getactivewindow)。这些静态事实并未证明所有者现场具体哪个原版值滞后。

本次定向原版顺序确认：较早 F7/F11 等读取前次 `Main.keyState`；`PlayerInput.UpdateInput` 映射完成后，外层 `DoUpdate_HandleInput` 内还有缩放/导航消费，最后才刷新键盘。只在外层 postfix 消费映射会太晚。`Main.GetInputText` 还直接调用 `Keyboard.GetState`；小 getter 可能内联，必须在真实方法入口独立收紧。聊天会在该方法前读取 `inputTextEscape`，所以失焦早期同时清瞬时 Enter/Escape 输出，保留文本、队列和 IME。Notes 自身沿用已接受的直接队列输入及租约，不改为调用 `GetInputText`。

当前实现由 `HostInputState` 唯一拥有每 Update 的输入有效性与激活等待；不以时间冷却代替真聚焦中整组按键/鼠标结束，也不把消费后的合成 Released 作为手动保护归还证据。窗口/便签失焦走未提交拖动取消，与正常关闭保存分离。存放 Session 与在途回执不能因前台切换失效，新动作许可由调用方读取。`HostInputChecks`、`F5InputChecks`、`NotesHostChecks` 与 `F5ConsumerChecks.RunInputOnly` 覆盖这些合成反例；后者实际加载生产 Host 并临时撤掉夹具 getter 补丁模拟内联，核验原版消费者输出。真实切窗、Windows IME、像素、多人和性能仍需对应证据；当前执行状态见 #46。

## 输入 guard 也可能制造连点（Legacy 历史）

历史 TravelMenu guard 在并无插件 UI 所有权时仍作用于原版 Journey 范围，反复把 `releaseUseItem` 设成 true，导致原版 ItemCheck 每次像新点击，传送物品等连续使用。故障表面像自动连点，根因是另一输入门的适用范围。来源 `排查复盘/TravelMenu输入guard导致自动连点失控-2606050720.md` 记录了真实输入/物品周期观察与修复后反馈；本轮未复测。

热键主开关、动作键与观察 Hook 也不可互换：主开关键只改偏好，动作需真实触发链；阻挡期间按下的键仍应更新边缘基线，不能门一开就补出幽灵按下。定向查 `自动化与热键/` 四篇中的触发→观察→请求证据，不继承其自动接力、旧队列或通配审计命令。
