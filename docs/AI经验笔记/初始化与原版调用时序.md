# 初始化与原版调用时序

本页前两节为 R 阶段复盘与隔离反例；后续为 Legacy 历史证据，不声称在 R 重现全部旧故障。R 当前加载行为以[最小加载链](../设计/最小原版加载链验证.md)为准。来源路径相对旧经验根，口径见[索引](索引.md#legacy-首次筛选的历史范围与来源口径)。

## R：安装提交前的回调不是运行故障

#46 阶段复盘在 `9026a3d` 找到：Main.Update 补丁先装、其它 Hook 后装，`Postfix` 却把 `hookCommitted == 0` 当异常，可能提前消耗交接门并破坏启动证据。未提交时必须无副作用早退，提交后再要求上下文完整。`ItemLoadedHostChecks.CheckUncommittedUpdate` 在独立加载的生产 Host 中确定性控制此窗口，随后验证正常唯一交接，不靠 sleep 或运行频率猜测。

## R：局部显示失败与共同运行失败分别收口

群系层插入/绘制失败只能停群系显示；接入 Items 后仍调用共同 `FailRuntimeClosed` 会连带关闭自动化。现由 `Phase0SLoadChainHost.DisableBiomeFeature` 局部关闭，`HandlePostfixFailure` 保留共同失败停止。首个有限原因沿现有证据文件记录；若局部错误早于交接，`PostfixContext` 只暂存一个原因，五条启动记录提交后才追加，不能在成功前缀中间插 ERROR，也不能把所有运行异常叫 APPEND_FAILED。

`ItemLoadedHostChecks` 的 `expect-items` 与 `expect-items-layer-failure` 分别覆盖交接后绘制失败、交接前层失败，均要求自动化真实夹具链继续；启动/故障记录不重复。恢复解析同步允许具体有限错误，仍拒绝未知格式/归属，见 `Invoke-InstallRecoveryTests.ps1`。这是隔离回调与静态边界证据，不证明真实设备故障频率或所有异常恢复。

## 读取元数据不应抢跑原版写入器

旧蓝图为补齐 object group 提前调用 `TileObjectData.Initialize()`，随后原版启动在 `Main.Initialize_AlmostEverything → SetupBaseObject → set_AnchorTop/WriteCheck` 抛 `FieldAccessException`，提示 tile data 已锁定。历史复盘定位：Initialize 写表后锁 `readOnlyData`，提前“暖缓存”会让原版自己的正常初始化无法继续写。

适用结论是等原版生命周期建立表后读取；读不到时报告未就绪/不可证明，不由业务读取路径调用初始化器补救。控制台 fixture 初始化原版表是模拟世界内环境的测试安排，不能推导生产调用许可。以后定向核对对应版本的 `ObjectData/TileObjectData.cs` 中 Initialize、WriteCheck 与 Main 初始化调用顺序，再定位实际最早调用者。

来源：`排查复盘/蓝图TileObjectData启动期抢跑-2607011644.md`。本地原件入口：`references/terraria/1.4.5.6/Terraria/ObjectData/TileObjectData.cs`。1.4.5.8 仍须以 R 锁定程序集和当前设计复核，不把 .6 行号跨版本套用。

## 程序集存在与可以安装 Hook 是不同条件

旧记录 `排查复盘/内嵌Harmony反射Patch泛型约束失败-2606122224.md` 保留了反射 Patch 入口与泛型约束不匹配的失败：找到同名方法不证明参数、实例或类型身份正确。R 的当前正式设计进一步要求精确程序集身份、单一 Harmony 上下文、AssemblyLoad 回调外排队的一次性安装工作项，首个宿主 Hook 到 Runtime 仅交接一次。不能用 Legacy 名称猜测 R 时序，也不能见程序集加载就递归安装。

后续只对任务涉及的方法验证完整签名、实际加载类型与回调边界；来源和调用形态不清楚时保留未知，不为此恢复旧通用反射 Service。

## 调用返回不等于没有副作用或已经完成

- `WorldGen.SpawnTravelNPC()` 返回 void。旧 .7 资料显示它可能先处理商店/公告相关状态，再因住房等条件早退；请求被接受或方法被调用不证明旅商已出现。自然到访的随机与城镇 NPC 条件也不能直接套到显式方法入口。应在合法任务里区分调用后观察到活动 type 368、尝试但未验证与失败。
- 税收官的金额展示只读 `Player.taxMoney` 等上下文；真正领取路径会产生钱币、同步并清除税款，不能为了查询而调用领取处理器。
- 物品百科可读取配方、掉落规则报告、商店数据；`OpenShop`、开匣/开袋、渔夫奖励方法不是无副作用查询。直接微光映射不等于完整分解关系，RecipeGroup 也不能只按 requiredItem 逐项相等判断。

来源：`Terraria原版参考笔记/WorldGen_TravelNPC_notes.md`、`NPC_TaxCollector_notes.md`、`Item_Recipe_Shimmer_notes.md`、`Item_Source_Extension_notes.md`。后续先读对应版本方法体和调用者，再决定 Observation/Operation 边界；不执行第三方程序或原版动作来“看看会不会变”。

## 主菜单生成与世界 Session 的就绪不同

症状：把生成预览只注册为世界内 Feature 会等不到建图；仅看 CurrentController 非空又会在异常后的下一轮预备阶段认领旧对象。锁定 .8 的 WorldGenerator 正常路径先 SetGenerator，再发布 Controller/Progress，异常可留下原版静态；WorldGen 外层 finally 只清生成 flag。应观察准确调用与发布，再在正常/异常尾部退休同次身份。程序集就绪只允许绑定，UI、生成和字体各有自己的就绪，不抢跑原版初始化或改旧静态造就绪。

[#149](https://github.com/Kuroneko2020/JueMingR/issues/149) 在 Host 的可选局部 owner 实施，失配只撤自己 patch，保留核心加载链。源码与原生 CPU/图形入口见[世界生成预览设计](../设计/世界生成预览实现设计.md)；隔离实例证据不等于本人真实启动或全部输入/渲染通过。


## 菜单 UI 更新与输入后菜单处理是不同阶段

R #149 的首批 `1eae636e` 到反馈候选 `8c84f81d` 把 MenuUI.Update 当成输入后的 Main.UpdateMenu，导致横幅已显示但 F5 一直被本帧未完成许可拒绝。方法存在只证明可绑定，Hook 已安装、UI 已显示、生成已发布与输入样本就绪仍是不同条件。外层 BeginUpdate 撤权后，锁定客户端先更新 MenuUI，再刷新原生输入；不能凭方法名字含 Menu 推导先后。横幅只检查页面与生成资格，不能证明 F5 所需输入条件已成立。

选接缝应从实际来源生产顺序追到共享输入写者、资格消费者和最终动作，在条件已成立的最窄回调分派。修复沿生产 InputPostfix 在共享采样和 Shell 后转交，不删除 BeginUpdate 清零、不借旧帧许可、不增加键盘采样。失焦早退可能跳过 HandleInput，必须保持该帧无新动作。来源是客户端1.4.5.8 SHA-256 `960A03BFF6050CF7BE16DFC1A7B19E10FC2C4F8F835A6A3B135A50DD9E6BA2F3`、MVID `2c29f6c3-4bd9-4add-9c58-da159804e083` 的 Main.DoUpdate/UpdateUIStates/DoUpdate_HandleInput 原始 IL；同版本 Server 只作辅助资料。实际入口见[设计](../设计/世界生成预览实现设计.md#输入与线程)、`NativeWorldGenPreviewFrames` 与 [#149 修复记录](https://github.com/Kuroneko2020/JueMingR/issues/149)。

检查通过不代表共享对象持续存在：WorldGen.CreateNewWorld 后台 Task 的 GenerateWorld 正常收尾先隐藏预览，再清静态 Progress/Controller；预览原本未显示时隐藏直接返回。先核身份再二次解引用静态 Controller 有空引用窗口，可能把正常退休错判成可选模块失效。使用同一 token 捕获对象并在动作前有界复核可消除静态重读，最后复核仍不是全流程原子锁。原生构造/激活读点也须核查，并把 token 正常退休前移到同次 GenerateWorld 调用的隐藏请求入口、早于可见性判断；但不可提前释放对原生早期 F5 的调用归属，须保留到同调用 finalizer 再 CAS 清理，否则 debug=true 会在静态清空前重新放行。原生外层已读非空条件也可能过期，入口还要复核捕获身份。否则激活成功后才清静态仍可留下失效页面。专属退休信号只清本次进入态，真实构造/资源错误保留失败语义，不能让正常生命周期变化卸掉后续建图功能。具体接缝和确定交错测试回上述设计与原生专项，不外推竞争的实机频率。

顶层命中数不能代表同步构造全链。锁定 .8 的 UIWorldGenDebug 取 Passes 后同步创建 GenPassElement，其构造立即调用 Index，再经颜色初始化调用 CurrentTargetPass；两者仍会读取共同 Controller getter。只改顶层构造/OnActivate 会漏掉这些读点，须区分立即执行与仅注册的 OnUpdate/Draw/Tooltip 委托。本任务将共同 getter 限于线程本地 Open 作用域统一处理，并在编译构造调用者前安装；域外保留原 getter，域内返回同 token 捕获对象或专属退休信号，避免递归 fallback 和两套规则。A/B 精确子链旧红新绿及真正新生成恢复回 #149，不以顶层 prefix 清空冒充子链窗口。
