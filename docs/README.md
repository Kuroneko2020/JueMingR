# JueMingR 文档入口

本文件只列出当前实际存在的正式文档分类和事实路由。

## 当前正式分类

- [`规范/`](规范/)：长期有效的项目规则。当前入口为 [文档治理规则](规范/文档治理规则.md)、[工程治理规则](规范/工程治理规则.md)、[Legacy 平替与行为契约规则](规范/Legacy平替与行为契约规则.md)、[技术平台与兼容规则](规范/技术平台与兼容规则.md)、[性能治理规则](规范/性能治理规则.md)、[测试与审计规则](规范/测试与审计规则.md) 和 [版本、配置与发布规则](规范/版本配置与发布规则.md)。
- [`设计/`](设计/)：描述当前系统或功能如何组织、模块与接口如何协作，以及状态和生命周期由谁负责。当前入口为 [总体架构与状态所有权](设计/总体架构与状态所有权.md)、[可重复构建与项目骨架](设计/可重复构建与项目骨架.md) 和 [最小原版加载链验证](设计/最小原版加载链验证.md)。
- [`决策/`](决策/)：重要选择及其理由。当前入口为 [ADR-0001：文档体系与受控演进](决策/ADR-0001-文档体系与受控演进.md)、[ADR-0002：Legacy 平替策略与行为契约方法](决策/ADR-0002-Legacy平替策略与行为契约方法.md)、[ADR-0003：原版同进程加载路线与兼容策略](决策/ADR-0003-原版同进程加载路线与兼容策略.md)、[ADR-0004：跨会话连续性与稳定起步路线图](决策/ADR-0004-跨会话连续性与稳定起步路线图.md)、[ADR-0005：性能治理采用风险触发与分层证据](决策/ADR-0005-性能治理采用风险触发与分层证据.md)、[ADR-0006：测试与审计采用分层验证与独立判定](决策/ADR-0006-测试与审计采用分层验证与独立判定.md)、[ADR-0007：版本、配置与发布采用分层身份和显式迁移](决策/ADR-0007-版本配置与发布采用分层身份和显式迁移.md)、[ADR-0008：工程治理采用风险分级与仓库原生流程](决策/ADR-0008-工程治理采用风险分级与仓库原生流程.md)、[ADR-0009：Legacy 用户数据导入按功能评估且不构成平替义务](决策/ADR-0009-Legacy用户数据导入按功能评估且不构成平替义务.md)、[ADR-0010：总体架构与状态所有权](决策/ADR-0010-总体架构与状态所有权.md) 和 [ADR-0011：可重复构建与项目骨架](决策/ADR-0011-可重复构建与项目骨架.md)。
- [`计划/`](计划/)：保存已经批准、在相应活动期内有效的高层计划、阶段目标和退出条件，不保存动态任务状态。当前入口为 [稳定起步路线图](计划/稳定起步路线图.md)。

## 查找事实

- 查长期有效规则：[`规范/`](规范/)
- 查 Legacy 行为恢复、平替、差异验收、数据自然归属及某项旧数据导入是否按功能评估：[Legacy 平替与行为契约规则](规范/Legacy平替与行为契约规则.md)
- 查为什么旧版数据导入不构成完整平替义务：[ADR-0009：Legacy 用户数据导入按功能评估且不构成平替义务](决策/ADR-0009-Legacy用户数据导入按功能评估且不构成平替义务.md)
- 查产品运行平台、游戏版本、Windows、渠道、多人和安装恢复边界：[技术平台与兼容规则](规范/技术平台与兼容规则.md)
- 查性能风险触发、性能证据、功能关闭成本、缓存、测量工具和性能检查边界：[性能治理规则](规范/性能治理规则.md)
- 查验证证据层级、测试判定依据、测试期待修改、mock/stub/fake、Terraria 游戏内实机、flaky、慢检查和审计成本边界：[测试与审计规则](规范/测试与审计规则.md)
- 查源码/构建/产品/schema/兼容/发布身份、版本推进、配置迁移、Tag、Release、发布资产与撤回边界：[版本、配置与发布规则](规范/版本配置与发布规则.md)
- 查文档类型、权威、生命周期和结构演进：[文档治理规则](规范/文档治理规则.md)
- 查任务分级、任务契约、写入白名单、Issue、分支、PR、独立审查、Git 授权、停止条件和长期工具依赖边界：[工程治理规则](规范/工程治理规则.md)
- 查总体架构、模块职责、依赖方向、状态所有权、Runtime/Session 生命周期、游戏观察与操作边界，以及 Feature、UI、持久化和 Diagnostics 的职责：[总体架构与状态所有权](设计/总体架构与状态所有权.md)
- 查为什么采用当前总体架构和为什么建立 `docs/设计/`：[ADR-0010：总体架构与状态所有权](决策/ADR-0010-总体架构与状态所有权.md)
- 查锁定工具链、解决方案、六项目边界、ProjectReference、合法本地游戏编译引用、正式构建入口、构建身份和可重复构建边界：[可重复构建与项目骨架](设计/可重复构建与项目骨架.md)
- 查为什么采用当前精简构建骨架、普通可信开发环境威胁模型，并拒绝旧实验的敌对环境审计：[ADR-0011：可重复构建与项目骨架](决策/ADR-0011-可重复构建与项目骨架.md)
- 查 Terraria 1.4.5.8 的 `Main.Update(GameTime)` 顺序、同步 AppDomainManager/Harmony 验证链、五项事件、Phase 0-S 验证布局与未来发行布局边界、验证包安装恢复和项目所有者实机门：[最小原版加载链验证](设计/最小原版加载链验证.md)
- 查为什么作出重要选择：[`决策/`](决策/)
- 查稳定起步前的大方向、阶段依赖和退出条件：[稳定起步路线图](计划/稳定起步路线图.md)
- 查当前阶段、当前任务和阻塞：[稳定起步总跟踪 Issue](https://github.com/Kuroneko2020/JueMingR/issues/7)
- 查具体任务状态：对应 GitHub Issue
- 查历史代码变化：Git
- 查发布变化：未来的 Release/Changelog
- 查原始日志和临时材料：本地目录；这些材料不属于正式事实源

## 结构边界

未来分类只在出现真实文档职责后，通过专门任务、项目所有者批准和 ADR 增加。当前结构不是永久结构；若事实证明其他组织方式更合适，应受控调整。

普通任务不得自行重组文档目录。当前尚不存在 `验证/`；不得为未来可能的用途预建空目录。
