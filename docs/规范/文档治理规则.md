# 文档治理规则

## 一、目的与适用范围

本规则管理 JueMingR 正式文档的类型、权威、生命周期、Git 边界、命名路由和结构演进。它适用于 `docs/` 下的正式文档以及根目录中的文档入口。

本规则不规定具体功能如何实现，也不是动态项目状态表。功能合同、系统设计、任务状态和验证结论必须由各自的权威载体承担。

## 二、文档类型与生命周期

| 类型 | 职责 | 是否进入 Git | 裁定权 | 更新时机 | 删除、替代或退出当前路由 |
| --- | --- | --- | --- | --- | --- |
| 规范性文档 | 规定当前有效的产品或工程合同 | 是 | 项目所有者最终裁定 | 合同发生变化时 | 由新规范明确替代；旧内容依赖 Git 追溯，不在当前规范中保留版本流水 |
| 描述性设计文档 | 描述当前系统、功能、接口和边界如何工作 | 当前有效且已批准的设计进入 | 项目所有者批准，相关维护者维护 | 设计或实现边界变化时 | 失效后更新、删除或由新设计替代，并退出默认路由 |
| ADR 决策记录 | 记录重要选择、理由、代价和替代关系 | 是 | 项目所有者接受或拒绝 | 作出或替代重要决策时 | 不静默改写原决策；由新的 Accepted ADR 明确替代并互相链接 |
| 实施计划 | 约束已经批准的复杂任务范围和执行方式 | 仅活动期内确有必要时进入 | 项目所有者批准范围，任务执行者维护内容 | 获批范围或实施方法变化时 | 完成后先提炼长期结论，再删除失效计划；默认不归档全量计划 |
| 动态任务状态 | 记录当前进度、阻塞和下一步 | 不进入稳定文档；只进入 GitHub Issues | 项目所有者裁定，获授权执行者按事实维护 Issue | 状态实际变化时 | Issue 关闭后由关闭记录承担历史，不转存为状态文档 |
| 验收与证据摘要 | 保存足以支持限定结论的验证协议或脱敏摘要 | 精选且脱敏的正式摘要可以进入 | 测试维护者裁定其覆盖范围；用户验收只由用户裁定 | 对明确版本、环境或场景形成结论时 | 不再代表当前事实后退出当前路由；原始证据按本地或 CI 保留策略处理 |
| 临时研究材料 | 保存搜索笔记、假设和未整理分析 | 否 | 调查者管理，不具备独立裁定权 | 调查期间按需更新 | 结论提炼为规范、设计、ADR 或证据摘要后删除 |
| 自动生成报告 | 保存工具产生的完整测试、审计或测量输出 | 否 | 工具只产生数据，不具备裁定权；负责人解释其范围 | 每次运行时重新生成 | 到期删除或由本地、CI 工件策略清理，不进入默认路由 |
| 历史材料 | 为少数确有长期人工参考价值的旧材料提供追溯 | 默认不另建；精选例外需单独批准 | 项目所有者决定是否保留；原权威载体仍决定事实含义 | 仅在确认长期参考价值时 | 标明历史且退出默认 Agent 路由；通常依赖 Git、关闭的 Issue、Release 和 ADR |

## 三、唯一事实原则

- 同一动态事实只能有一个权威载体。
- GitHub Issues 是任务动态状态的唯一权威载体。
- 规范、设计、计划和验证文档不得复制 Issue 的当前进度、阻塞或下一步；需要关联时只引用对应 Issue。
- 当前规范和设计只描述现行合同，不保存版本流水。
- 历史信息优先依赖 Git 提交、已关闭 Issue、Release 和必要的 ADR；各载体不得互相复制成第二套历史账本。
- 测试通过、审计通过、文档完成或版本推进都不能自动升级为用户验收或产品完成。

### 同一任务的同步责任（待接受补充）

以下为 [ADR-0012](../决策/ADR-0012-关键注释同次交付与五个底线路由.md) 的候选补充，尚未生效；本文件其余有效规则不变。

- 行为、接口、状态归属或生命周期变化时，由实施者在同一任务同步相关源码注释和设计；关键注释的编码与审查要求见 [工程治理规则](工程治理规则.md#关键注释与同次交付待接受补充)。
- 规则或文档职责变化时，同一任务同步对应规则和实际受影响的路由。
- 进度、阻塞或授权变化时更新对应 Issue，项目级变化更新总跟踪 Issue #7；稳定规则和设计不复制动态流水。
- 审查者检查上述事实与载体是否一致。不要求每次提交更新所有文件，也不以制造更多文档替代维护。

## 四、Git 与本地边界

正式进入 Git 的内容包括：

- 当前有效规范；
- 当前有效设计；
- ADR；
- 活动期内确有必要且已批准的复杂实施计划；
- 脱敏后的精选验收与证据摘要；
- 文档入口和路由。

不进入 Git 的文档工作材料包括：

- Agent 缓存和完整对话；
- 临时分析和未整理研究材料；
- 原始日志、构建输出以及完整测试或审计报告；
- 作为原始证据的 ZIP、NDJSON、截图和录屏；
- 未脱敏的机器信息和个人路径。

原始材料保留在本地目录或 CI 工件中。若其结论需要长期使用，只将足以支持结论且已经脱敏的摘要纳入正式文档。

## 五、命名与路由

- 根目录名 `docs` 保持英文。
- `docs` 下由项目定义的目录和普通文档名使用中文。
- `README.md`、`AGENTS.md`、ADR 编号等工具约定可以保留英文。
- `docs/README.md` 只列出实际存在的正式分类和路由，不把尚未创建的未来目录写成既成结构。
- 普通功能任务不得顺手新增、删除、重命名或重组文档一级目录。

## 六、计划和动态状态

- 简单任务不创建计划文档。
- 复杂任务只有在项目所有者批准后才创建计划文档。
- 计划必须引用对应 Issue，但不得复制 Issue 状态。
- 计划完成后，先把仍然有效的合同、设计决定和验证结论提炼到各自权威文档，再删除失效计划。
- 不建立全量历史计划归档；只有确有长期人工参考价值的材料，才通过单独决定保留。

## 七、验证和证据

- 原始证据留在本地目录或 CI 工件；正式文档只保存足以支持结论的脱敏摘要。
- 本地检查只证明所检查的文件、配置或本地行为；自动测试只证明其断言和运行环境覆盖的范围。
- 实机测试只证明指定机器与场景，多人验证只证明实际覆盖的多人场景，用户验收只来自用户的明确裁定。
- 任一证据都不得被解释为超出其版本、环境、场景和验证层级的结论。

## 八、结构演进

- 新增、删除、合并或重命名 `docs` 一级目录，必须通过专门任务、项目所有者批准和 ADR。
- 当前结构不是永久结构；若未来事实证明其他组织方式更合适，应由新的 ADR 受控调整。
- 不得仅因“未来可能有用”或“保持对称”而创建新目录或空目录。
- 普通文件移动若不改变文档权威、生命周期或一级结构，可以不新增 ADR。
- 结构调整必须在同一提交中更新全部相对链接和 `docs/README.md`；根路由职责变化时同时更新 `AGENTS.md`。
- 不保留层层重定向的占位文件。当前首版结构的决定见 [ADR-0001](../决策/ADR-0001-文档体系与受控演进.md)。

## 九、禁止的失控模式

禁止：

- 建立全局动态状态账本；
- 建立更新记录目录；
- 建立文档更改历史目录；
- 为每个内部步骤创建 Markdown 记录；
- 在稳定文档中累积当前版本流水；
- 让历史计划继续进入默认 Agent 路由或授权当前工作；
- 通过源码字符串锚点或自然语言精确文本检查证明文档治理合规；
- 为管理文档再建立大型审计系统；
- 因未来可能使用或追求目录对称而预建目录。

文档治理不设置死板的行数硬审计，也不要求复杂模板。检查应聚焦可确定的结构、链接、Git 边界和实际事实责任。
