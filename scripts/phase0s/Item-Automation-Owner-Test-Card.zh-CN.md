# 阶段复盘修正后的窄复验

所有者已反馈此前安装的 UI 和功能在本人测试场景正常，细微美化后置。本候选修复共享加载/故障隔离、配置保护、笔记收尾与物品保护/短等待，不要求重做所有旧场景，也不要求人为制造加载异常、坏配置或未知交易。

1. 正常启动，打开 F5，确认物品、信息和笔记可用，既有开关、名单和笔记保持。
2. 用一条临时笔记输入中文/表情，尝试保存、切页和关闭，再返回检查尾字；正常确认候选后动作可完成。明确取消仍可放弃草稿。
3. 用少量无价值物品顺手确认已使用的自动项、头顶提示与普通手动快速堆叠正常。异常分支由隔离反例验证，不必在真实物品上故意复现。

反馈简短动作和现象即可。下面保留原来源/失焦专项卡，供尚未测试的场景按需补验；它不是本次要求全部重跑的清单。实际候选、安装与接受范围查 Issue #46。

## 原来源、失焦输入与丢弃提示专项卡

以下专项覆盖范围不因所有者总体正常反馈自动完成。请自行启动游戏，使用少量无价值物品和自有或朋友同意的环境；不拿重要存档验证未知丢失风险。三项仍使用 F5 → 物品中的明确“开启/关闭”，没有快捷键绑定。

1. **先测失焦。** 分别在 F5 关闭、名单展开、Notes 编辑或拖动时切到其它窗口，在外面点击、松手和滚动。游戏及 R 不应因此操作；回到游戏不应补执行旧点击或保存中断的拖动。重新作出的点击、拖动、滚轮、F5 和中文输入应正常，笔记草稿应保留。
2. **分别只开卖、只开扔、只开存。** 卖/扔先把测试物品加入对应名单；出售时主动打开有效商店，存放时附近放有同类物品的普通箱子。每项先从容器取出物品，应不自动处理；然后测试真正拾取或手动开启产物，应按该项规则处理。开关、开店、改名单、整理、购买和取消收藏本身不产生取得资格。
3. **测 20＋3 和资格结束。** 从容器取出20个同类物品，再合法拾取3个，当前未收藏的兼容整栈23个允许一起处理。该次处理完成后，再从容器取同类物品，应不借用旧资格处理。收藏栈、鼠标拿持和当前使用的物品继续受保护，钱币不作为三项的主动候选。
4. **测手动开启与优先级。** 正常开启可开物品，检查直接入包的非钱币产物；满包落地的产物等真正拾取后再检查。匣子、宝藏袋、牡蛎等沿原版通用分类，缺钥匙或没有相应产物不应凭空触发。三项同开且名单重叠时，有有效商店按出售优先；出售不适用时再丢弃、存放。没有店不能一直挡住其它适用规则。
5. **测丢弃提示与重启。** 丢弃行应有 `[提示 开] [添加] [开启] [关闭]`，提示默认开；成功处理23个木头时应在玩家头顶显示“自动丢弃了23个木头”，以实际数量和当前语言物品名为准。切到“提示 关”只关反馈，丢弃仍工作；手动放垃圾桶不应冒出自动丢弃提示。正常退出重进，提示偏好、原三项开关与两份名单应保留。原版全局关闭拾取浮字时，该提示也遵循原版显示限制。
6. **顺手确认原界面。** 添加仍原位展开稳定多选，展开时只隐藏该行添加；图标本体替换、红叉移除、主滚动条和图标样式保持。切换提示不应丢选择草稿、误改其它开关或立即清理已有库存。

回复“现象＋简短动作＋单人/Host & Play/普通客机”，未测的直接写未测。无需读 JSON、评分或逐个联系专题会话。发现物品去向或数量异常时，先关闭相关自动项并报告。

安装保留 Notes、全部配置和既有恢复材料；新候选保留供复验。需撤除本包程序时，在游戏退出后使用同包 `Restore-Phase0S.ps1 -TerrariaDirectory <游戏目录>`；只撤除匹配的自有载荷，不回退用户数据，也不自动装回旧程序。Agent 不代替你操作游戏，不合并、关闭任务或发布。
