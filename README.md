# JueMingR

决明 R（JueMingR）是面向原版 Terraria 的客户端辅助工具，不依赖 tModLoader，围绕实际游玩需求持续提供、改善和扩展便利功能。

JueMingR 延续 JueMingZ 的使用初衷，在独立工程中吸收旧版有价值的功能、有效交互、游戏机制知识和失败教训，重建可持续维护和发展的实现。完整恢复旧版对用户有意义的能力仍是当前建设的重要目标；同时，可以根据实际需求和所有者明确授权，在恢复期间改进体验、开发新能力。旧版功能清单不构成 R 的最终范围，完整平替也不是产品发展的终点。“独立完整重写”描述的是 R 与 Z 的工程关系。

JueMingZ 永久冻结，仅作只读参考。JueMingR 不在编译或运行时依赖旧项目，也不要求保留其错误行为、内部耦合和技术债。

本段定位澄清是依据所有者已确认方向形成的文档候选，最终接受、正式化与合并生效边界见 [ADR-0015（Proposed）](docs/决策/ADR-0015-产品定位与能力演进边界.md)。恢复任务与已批准改进、新需求的具体边界见 [Legacy 平替与行为契约规则](docs/规范/Legacy平替与行为契约规则.md#一目的与适用范围)；持续演进不授予 Agent 自行增加功能或启动后续任务的权限。

已建立最小项目骨架和可重复构建基线，在 Terraria 1.4.5.8 上完成了最小原版加载链、“群系显示”和可交互的 F5 UI 基础。F5 包含十二个分类入口、窗口拖动、滚动与输入隔离，“群系显示”“笔记”和物品自动处理已接入真实业务；十二个入口不代表十二类旧功能已经迁移。

项目所有者已接受 F5 基础作为后续开发起点，外观可以继续迭代。尚未实现完整 Runtime、完整 Legacy UI 与功能迁移或正式安装器，未形成多人验证或正式发行。基础接受范围见 [F5 UI 基础设计](docs/设计/F5控制界面样板与UI基础.md)，当前阶段与任务见 [稳定起步总跟踪](https://github.com/Kuroneko2020/JueMingR/issues/7)。

[配置持久化合同](docs/设计/配置持久化与用户数据布局.md)规定：在已验证 `Terraria.exe` 同级的 `JueMingRData/config/` 下，用 `ui.json` 保存 F5 主窗口位置，用 `features/biome-display.json` 保存真实群系显示的用户期望开关。同一游戏安装内跨角色和世界共享偏好；没有 AppData/Documents fallback，不自动导入 Legacy 数据。该功能及正常保存静默、必要异常提醒已独立获项目所有者接受，随 [PR #35](https://github.com/Kuroneko2020/JueMingR/pull/35) 合并进入 `main` 后成为当前主线能力；接受仅覆盖本任务与所有者实际测试场景，不扩大为全部环境、分辨率、材质包、多人或 FPS 验收。

`JueMingRData` 属于用户数据，安装恢复和卸载默认保留。配置损坏、版本不支持或外部冲突时保留原件并停止该文档写回；重置单项配置不删除其它用户内容。笔记已按同一游戏安装共享的单份文档落地；蓝图、足迹等未来分区建议及其未实施边界仍保存在上述设计中。

笔记支持多篇卡片、标题/正文编辑、文本选区与局部剪贴板、安全保存和删除确认、多张悬挂正文，以及滚轮阅读、区域/字号调整和正常重启恢复。当前实现已获所有者在实际使用场景中的接受，随 [PR #43](https://github.com/Kuroneko2020/JueMingR/pull/43) 合并进入 `main`；详见[笔记使用与接受边界](docs/功能介绍/笔记功能行为合同.md#已接受实现与验证边界)。图形自动检查的环境延期及多人、性能等未覆盖范围仍保留，不代表全部场景通过或正式发行。

正式文档入口见 [`docs/README.md`](docs/README.md)。Legacy 功能恢复、跨功能复用与组合工作量先查[全功能调查总报告](docs/功能介绍/全功能调查总报告.md)，再按主题读取全部十二篇专题；调查是固定版本证据，现行要求与实施授权仍查已接受合同和任务 Issue。

自动出售、丢弃与堆叠及该候选已有的共享基础局部修正已获所有者接受，随 [PR #47](https://github.com/Kuroneko2020/JueMingR/pull/47) 合并进入 `main`。三项由可靠取得触发，使用 F5 内联名单与明确开关，丢弃头顶提示可单独保存；三项现由下述公共快捷键能力接入，已退休的旧字段不恢复。使用与接受边界见[物品自动处理合同](docs/功能介绍/自动存放功能行为合同.md#r-使用与接受边界)，固定候选、实际安装、验证与反馈见 [Issue #46](https://github.com/Kuroneko2020/JueMingR/issues/46)。特定旧槽位报文跨批次疑点由所有者限定接受并[延期调查 #48](https://github.com/Kuroneko2020/JueMingR/issues/48)，不等于风险已排除或全部多人、异常网络、性能场景通过；本次接受不是正式发行，其余 Legacy 功能仍是后续范围。

统一键鼠快捷键及两轮小窗修订已获所有者本阶段接受，随 [PR #52](https://github.com/Kuroneko2020/JueMingR/pull/52) 合并进入主线。群系显示、自动堆叠、自动出售、自动丢弃四个真实入口共用录入、可靠保存和分派，默认未绑定；支持零至三个左右修饰键加一个键盘或已支持鼠标主键。原版重合只在设置提交时完整检查并提醒，决明内部重复拒绝；小窗紧凑排布，多项提醒可展开查看。使用和接受边界见[统一快捷键合同](docs/功能介绍/统一快捷键功能行为合同.md#78-r-已接受实现的使用与边界)，未来获准动作的接入方式见[实现设计](docs/设计/统一快捷键实现设计.md#后续动作接入)。接受不代表全部设备、Windows/IME、第三方字体材质、多人、极端分辨率或 FPS 已验证，也不是其它 Legacy 业务或正式发布授权。
